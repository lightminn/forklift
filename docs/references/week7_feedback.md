# 7주차 발표 피드백

기록: 2026-10-14 · 발표 자료: <https://lightminn.github.io/forklift-presentations/week-07/>

발표 중 받은 피드백을 주제별로 정리했다. 7주차 발표는 하드웨어(구동 · 엔코더 보드 회로와 PCB)만 다뤘다.
확인이 더 필요한 항목은 맨 아래 [확인 필요](#확인-필요)에 따로 모았다.

## 1. 설계 수준 — 과설계

- 전체적으로 **과설계(over engineering)** 느낌이 있다. 스펙과 사양을 좀 낮춰도 될 것 같다.
  - 발표한 구성: 엔코더 신호를 모두 차동으로 보냄(바퀴는 차동 펄스, 조향 · 승강은 SPI를 STDS 보드에서 LVDS로), RJ50 케이블, 센서 보드마다 LDO, MISO용 3상태 버퍼(발표 3 · 7–10쪽).

## 2. MCU 구성

- **MCU를 2개로 나눠** 역할을 분리하고 핀 개수를 확보하는 방안을 검토한다.
  - 지금은 Nucleo STM32H533RE 하나가 DRV8244 4채널과 엔코더 4개를 모두 맡는다(발표 2쪽).

## 3. 커넥터

- 커넥터는 **표준 커넥터**로 쓴다.
  - 발표에서는 엔코더 보드에 1.27 mm 2×4 핀 헤더, 조향 · 승강 케이블에 RJ50 10핀을 썼고, 2.54 mm와 1.27 mm 중 어느 쪽이 나은지 여쭸다(발표 10 · 11쪽).

## 4. 엔코더 — 평가 보드와 비교

- 엔코더 칩의 **평가 보드(evaluation board)를 찾아서 사고**, 직접 만든 보드와 비교해 본다.
  - 대상: 바퀴용 MT6701 보드, 조향 · 승강용 KTH7801 보드(발표 5 · 6쪽).

## 5. 백업 플랜

- **백업 플랜을 생각하고** 진행한다.
- 센서를 차체에 붙일 수 없는 경우처럼 계획대로 안 될 때 어떻게 할지도 생각해 둔다.
  - 5주차 피드백 2절(엔코더를 구조적으로 달 수 없는 경우가 있을 수 있으니 모터를 꺼내 확인)과 이어지는 항목이다.

## 다음 할 일

| 항목 | 관련 절 |
|---|---|
| 사양을 낮춘 구성 검토(차동 전송 · RJ50 · 보드 수가 꼭 필요한지) | 1 |
| MCU 2개로 역할 분리하는 안과 핀 개수 비교 | 2 |
| 엔코더 · 구동 케이블 커넥터를 표준 커넥터로 다시 고르기 | 3 |
| MT6701 · KTH7801 평가 보드 찾아 구매, 자작 보드와 비교 | 4 |
| 센서 부착이 안 될 때의 대안을 포함한 백업 플랜 정리 | 5 |

## 확인 필요

- "표준 커넥터"가 어떤 규격을 뜻하는지 확인한다. 핀 간격(2.54 mm 같은 흔한 피치)을 말하는 것인지, 특정 계열(JST, Molex, M12 등)을 말하는 것인지.
- MCU 2개로 나눌 때 어떤 기준으로 나누는지(구동과 센서, 왼쪽과 오른쪽 등)는 정해 주지 않았다.
- 사양을 어느 쪽부터 낮출지(차동 전송, RJ50, LDO 등) 구체적인 지적은 없었다.
