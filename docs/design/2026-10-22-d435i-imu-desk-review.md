# D435i 내장 IMU 책상 검토 — 시뮬 자이로 모형의 출처, 실제 사용 경로, G4 측정 항목

작성일: 2026-10-22 · 계기: 자이로 방향 오도메트리 계획(`docs/plans/2026-10-21-gyro-heading-odometry.md`, PR #62 브랜치) 4.9 의 사용자 결정
"V-G2 시뮬 보류, 실차 IMU 측정(G4) 대기" 와 함께 지시된 책상 작업 · 사용자 결정(2026-10-22): **IMU 는 당분간 D435i 내장 IMU 기준으로 개발한다** ·
Isaac 실행 없음(기록 재생·CPU 계산만)

## 0. 결론 — 실측 전 판단 불가

- 시뮬 자이로 모형(`config/gyro_model_spec_typical.yaml`)의 데이터시트 항(잡음 밀도·영점 편향·온도 계수 크기·감도 허용차·분해능)은 D435i 에 들어가는 두 칩
  (BMI055, 그 후속 BMI085) 데이터시트의 **대표값(typ)과 같다**. 두 칩의 자이로 사양표는 같은 값이다. 데이터시트에 없는 항(랜덤워크, 온도 경사의 시간 모양과
  크기, 장착 오차, 스케일 부호)은 가정이다(1 장).
- V-G2 에서 자이로 팔의 보정 전 오도메트리 오차가 조향 팔보다 컸던 것은 **모형의 비관적 가정 탓이 아니다**. 기록 재생으로 모형 항을 하나씩 빼 보면, 오차가 없는
  "완전한" 자이로로도 4.3–18.1 m·0.33–1.32 rad 가 남는다. 남는 오차의 주된 기전은 두 가지다(2 장). ① 정지 편향 갱신 블록 대부분이 **제자리 조향 중**에 받아들여져,
  실제 차체 회전(평균 최대 9.6×10⁻⁴ rad/s)이 편향으로 들어간다. ② 시뮬이 자이로에 넣는 Isaac 차체 각속도를 적분하면 정답 자세의 yaw 보다 순회 끝에서
  0.17–0.21 rad 덜 돈다(시뮬 쪽 불일치 — 실제 자이로에는 없는 오차). 그러므로 V-G2 의 오도메트리 단독 비교는 D435i 자이로 품질의 증거가 아니다.
- D435i 로 충분한지 가를 핵심 값 — 실제 칩(BMI055/BMI085), 편향 안정성·랜덤워크, 켜진 뒤 온도에 따른 편향 변화, 캐리지 장착의 진동·휨, USB 경유 타임스탬프의
  지연·시계 차 — 은 데이터시트와 문서로 정할 수 없다(데이터시트에 편향 안정성·랜덤워크 값이 없다). 그래서 결론은 **"실측 전 판단 불가"** 이고, 판단에 필요한
  측정 목록을 5 장에 둔다. 알고리즘 쪽에서 실측 전에 고칠 수 있는 후보(정지 판정에 조향 정지 조건 등)는 4 장에 적는다.
- 별도 IMU(핀맵 초안의 MU_nCS·MU_INT): **미정 — 장착 위치·모델이 정해지면 재검토한다.**

## 1. 시뮬 자이로 모형과 데이터시트

모형: `config/gyro_model_spec_typical.yaml`(sha256 `9fa678a4…`), 적용 코드 `src/forklift_core/localization/gyro.py` `GyroSampler.sample`
(`measured = (1 + scale)·w_imu + b0 + temperature + walk + white`, 그다음 LSB 로 반올림). 모형 파일 머리말은 근거를 BMX055 데이터시트의 BMG160 계열 자이로로 적었다.
아래는 그 값을 D435i 에 실제로 들어가는 칩의 데이터시트와 다시 대조한 것이다.

|---|---|---|---|---|
| 잡음 밀도 | 0.014 °/s/√Hz | 0.014 °/s/√Hz (rms 0.1 °/s @ BW 47 Hz), typ | 같음 | 데이터시트 typ |

읽기:
- **데이터시트 항은 typ 값이다.** 두 데이터시트 모두 이 항목들에 최대값을 주지 않으므로, 모형이 "최악" 은 아니다.
- **편향 안정성·랜덤워크는 두 데이터시트 어디에도 없다.** 모형의 랜덤워크는 400 s 뒤 1σ 0.01 °/s(≈ 36 °/h)다. 이것이 비관적인지 낙관적인지는 데이터시트로
  정할 수 없고 실측(5 장 2 항)으로만 가른다. 2 차 출처(포럼 등)의 값은 확인하지 못해 쓰지 않았다.
- **온도 항은 상한 없는 선형 경사다.** 실제 켜진 뒤 데움은 포화하는 모양일 것으로 보이나, 크기와 시간 상수는 측정으로만 정한다.
- D400 데이터시트 표 4-23 주 (3) 은 "BMI055 IMU 는 더 이상 공급되지 않으며 BMI085 가 대체했다(PCN #118035-00)" 이다. 표 4-23·4-24 모두 D435i 를 대상
  카메라로 적고 있으므로, **팀 장치의 칩은 실기기로 확인해야 한다.** librealsense 는 장치의 칩 ID 로 BMI055/BMI085/BMI088 을 가려
  `RS2_CAMERA_INFO_IMU_TYPE` 로 알린다(`src/ds/d400/d400-device.cpp` `set_imu_type`). 자이로 사양은 두 칩이 같아 위 대조는 어느 쪽이든 성립한다. 가속도
  샘플률은 다르다(BMI055 62.5·250 Hz, BMI085 100·200 Hz — 표 4-23·4-24; librealsense 는 D400 의 새 BMI 에 400 Hz 도 연다).

## 2. 자이로 팔의 보정 전 오도메트리 오차는 무엇에서 오나 — 기록 재생

V-G2 2·3 차 자이로 조사 여섯 실행(ws1 `test_runs/live/vg2b/gyro_s{0,1,2}`, `vg2c/gyro_s{3,4,5}`)의 기록으로 계산했다. 기록에는 120 Hz 정답 자세, 엔코더 증분,
`drive_command_zero`, 측정 자이로 표본이 있다. 스크립트는 ws1 `test_runs/live/gyro_ablation/` 에 있고 sha256 은 9 장에 둔다.
- **재생 방법(`ablate.py`).** 샘플러와 같은 seed 로 같은 순서의 난수를 다시 뽑아 각 오차 항을 정확히 다시 만든다. b0·온도 부호가 실행 기록과 같음을 확인했다.
  그 항들을 빼서 오차 없는 각속도를 되찾고, 항을 하나씩 뺀 측정값으로 러너의 `heading_step`·자이로 오도메트리를 다시 돌린다.
- **비교 기준.** 노드 시각에서 정답과 비교하고(정렬 없음), 아무것도 빼지 않은 재생은 기록된 오도메트리와 8×10⁻⁵ m 안에서 같다.

|---|---|---|---|---|---|---|
| 2 차 s0 | 11.67 m / 0.91 rad | 15.37 / 1.20 | 12.18 / 0.90 | 12.97 / 1.09 | 15.26 / 1.26 | 18.10 / 1.32 |

| 2 차 s2 | 3.73 / 0.11 | 9.55 / 0.54 | 3.72 / 0.11 | 5.38 / 0.21 | 10.08 / 0.62 | 6.87 / 0.55 |
| 3 차 s3 | 6.48 / 0.25 | 5.03 / 0.23 | 4.58 / 0.18 | 8.05 / 0.44 | 5.09 / 0.23 | 4.29 / 0.33 |
| 3 차 s4 | 13.55 / 1.06 | 10.56 / 0.81 | 15.33 / 1.07 | 15.61 / 1.24 | 12.83 / 1.01 | 12.19 / 0.99 |

(위치 최대 / 방향 최대, 같은 노드 시각에서 보정 전 오도메트리 대 정답)

- **모형 항을 빼도 오차가 줄지 않는다.** 항 하나를 빼면 줄기도 늘기도 한다. 완전한 자이로(모든 항 0)에서도 4.3–18.1 m 가 남는다 — 모형의 비관적 가정은 주원인이 아니다.
- **거리는 맞다.** 정답 방향 증분을 쓰고 엔코더 거리만 남기면(`truth_heading.py`) 위치 최대 0.047–0.074 m 이고, 엔코더 거리는 정답 경로보다 0.21–0.27 % 짧다.
  같은 계산에서 조향 팔 s3·s4 는 0.153·0.039 m, 0.42·0.35 % 짧다. 오차는 모두 방향에서 온다.
- **정지 편향 갱신이 실제 회전을 먹는다**(`bias_check.py`). 받아들여진 정지 블록(바퀴 증분 0 이고 명령 0 인 60 틱)에서 정답 차체 yaw 속도의 블록 평균은 중앙값
  5.7×10⁻⁵(s3)·2.4×10⁻⁴(s5) rad/s, 최대 9.6×10⁻⁴·6.5×10⁻⁴ rad/s 다. 그 블록의 대부분 — s3 18 개 중 16 개, s5 15 개 중 13 개 — 이 조향 관절이 움직이던 때다. 순회는
  leg 마다 제자리에서 조향부터 맞춘다. 조향이 움직이던 블록의 평균 |yaw 속도| 는 2.1×10⁻⁴·3.3×10⁻⁴ rad/s, 조향이 멈춘 블록은 5.6×10⁻⁸ rad/s 다.
  10⁻³ rad/s 의 편향 오차가 다음 갱신까지 400 s 이어지면 0.4 rad 이다.
- **정지 판정에 "조향 정지" 를 더해 보면**(측정 조향이 바뀌지 않은 틱만, `ablate_steer_gate.py`) 받아들여지는 블록이 대부분 2–3 개로 준다(3 차 s4 21 개,
  정체가 길었던 2 차 s1 259 개). 모형 그대로의 오차는 7.4–28.5 m 로 오히려 커진다. 순회의 정지 대부분이 제자리 조향이라 갱신 기회 자체가 없어진다. 완전한
  자이로도 3.3–14.5 m·0.17–1.34 rad 가 남는다 — 다음 항목의 시뮬 쪽 불일치가 함께 있다.
- **시뮬 각속도와 자세의 불일치**(`rate_vs_pose.py`). 샘플러가 쓰는 Isaac 차체 각속도(`robot.get_angular_velocity()`)를 오차 없이 되찾아 적분하면, 정답 자세의 yaw 보다
  순회 끝에서 −0.166·−0.185·−0.197 rad 다(3 차 s3·s5, 2 차 s0). 거의 전부 주행 중에 쌓인다. 정지·조향 중에는 0.015 rad 이하다. 원인은 가르지 않았다
  (보고 각속도의 시점과 접촉 보정 뒤 자세 적분의 차이가 후보). 실제 자이로에는 없는 시뮬 쪽 오차다 — 계획 4 장 1 항이 "온라인 G1 과 V-G0 의 쿼터니언 차분 근사의 차이"
  로 남겨 둔 것의 크기가 이것이다.

| 시계 | 각 IMU 패킷은 **깊이 센서 하드웨어 시계**로 찍힌다 | librealsense `doc/d435i.md` |

| 장착(시뮬) | `carriage_low_measured`: 부모 `/World/Forklift/fork_carriage`, 위치 (0.619, 0, 0.27) m, 앞쪽으로 약 5.7°(0.0998 rad) 숙임 — **승강하면 함께 움직인다** | 3 차 실행 `result.json` `perception_mount` |

캐리지 장착이 주는 영향:
- **시뮬은 차체 각속도만 샘플링한다.** 샘플러에 들어가는 것은 차체 루트의 각속도다. 승강 중 캐리지·마스트의 기울기 변화, 유격, 진동은 시뮬 자이로에 없다.
- **실차에서 섞이는 것.** 승강은 이상적으로는 수직 이동(회전 없음)이다. 마스트 휨·유격·진동은 yaw 축에 섞이고, 정지 판정의 분산 시험(`zupt_k`)도 흔든다.
- **장착 오차의 영향.** 카메라→base_link 회전은 우리 장착 보정이 정하고, 깊이↔IMU 는 도면값이다. 장착 피치 오차 δ 는 yaw 감도 cos δ 와 롤·피치 속도의 새어 듦
  sin δ 를 만든다(시뮬 가정 1°).
- **시계 맞추기.** 정지 판정은 MCU 쪽 엔코더(바퀴 증분)와 Jetson 쪽 D435i 자이로를 같은 시각축에 놓아야 한다. 두 시계의 차와 지연을 맞추는 경로가 필요하다
  (지금 시뮬은 같은 틱이라 지연 0).

## 4. 시뮬 모형·알고리즘에 반영할 차이 (적기만 한다 — Isaac 실행 없음)

| 무엇 | 지금 시뮬 | 실제에 맞추려면 |
|---|---|---|
| 샘플 | 물리 틱(120 Hz)마다, 지연 0 | 200 또는 400 Hz 의 자체 타임스탬프 표본, USB·librealsense·ROS 지연과 하드웨어↔호스트 시계 차·드리프트(실측값) |
| 온도 | 상한 없는 선형 경사 | 실측한 데움 모양(포화형일 것으로 보임)과 크기 |
| 편향 걷기 | 0.0005 °/s/√s 가정 | 정지 장시간 기록의 Allan 분산에서 얻은 값 |
| 스케일·교차축 | +1 % 고정, 교차축 없음 | 실측 감도(축별), 교차축 ±1 % 범위 |
| 칩 | BMI055 대표값 | 실기기 `IMU_TYPE`(BMI085 면 자이로 사양은 같고 가속도 샘플률만 다르다) |
| 장착 | 차체 각속도 + 1° 가정 | 캐리지 움직임·진동 항, 실측 장착 회전 |
| 시뮬 각속도 | Isaac 보고 각속도(자세와 0.17–0.21 rad 어긋남) | 원인을 먼저 가르고, 필요하면 자세 차분 각속도를 쓰거나 이 차를 오차 예산에 넣는다 |
| 정지 편향 갱신(알고리즘) | 바퀴 증분 0 + 명령 0 | 제자리 조향 중 회전을 먹지 않게(조향 정지 조건 또는 조향 중 블록을 버림) — 단 그러면 순회에서 갱신 기회가 거의 없어지므로, 정지·대기 때 갱신하는 운용이나 다른 편향 추정과 함께 정해야 한다. 정할 사항이며 이 문서에서 고치지 않는다 |

## 5. G4(실차 측정) 때 잴 것

1. **장치 확인**: `rs-enumerate-devices` 의 IMU 종류(BMI055/BMI085)·펌웨어 버전·IMU 프로파일, 장치에 IMU 보정이 저장돼 있는지.
2. **정지 장시간 기록(냉간 시작부터)**: 카메라를 켜자마자 정지 상태로 30 분 이상(가능하면 2 h) 400 Hz 자이로를 기록하고, 카메라 온도(장치가 주는 온도 옵션)를 같이
   남긴다 → 켜진 뒤 편향 변화의 모양·크기(온도 항), Allan 분산(각도 랜덤워크·편향 불안정성·편향 걷기).
3. **감도**: 알려진 각도(예: LiDAR 지도나 기준 각도로 확인한 360° × 여러 번, 좌·우)를 돌려 축별 감도 오차를 잰다.
4. **장착**: 카메라→base_link 회전(피치 5.7° 장착의 실제 값), 자이로 축과 차체 yaw 축의 정렬.
5. **시계·지연**: realsense-ros 토픽의 실제 자이로 빈도, header 시각의 시계(하드웨어/global time), Jetson 시계와의 차·드리프트, 표본 생성에서 토픽 수신까지의
   지연. MCU 엔코더 시각과 같은 축에 놓는 방법도 이때 정한다.
6. **차량 위 정지·움직임**: 모터에 전원이 들어간 정지, **제자리 조향**(바퀴 증분 0 일 때 차체 yaw 가 실제로 도는지 — 2 장의 기전이 실차에도 있는지), 승강·하강
   중(캐리지 장착의 진동·기울기), 주행 중 진동 스펙트럼.
7. **기준 궤적 한 번**: 8 자·사각 주행을 LiDAR SLAM 또는 외부 기준과 함께 기록해, 자이로 적분 방향과 기준 방향의 차를 시간에 따라 본다.

## 6. 별도 IMU

핀맵 초안(PR #83 검토)에 MCU 용 IMU 신호(MU_nCS·MU_INT, 품번 미정)가 있다. 장착 위치·모델이 정해지지 않았으므로 **미정 — 정해지면 재검토한다.**

## 7. 해석의 한계

- 2 장의 재생은 V-G2 의 기록과 시뮬 모형 위의 계산이다. 실차 D435i 의 성능을 말하지 않는다.
- "완전한 자이로" 는 샘플러가 쓰던 Isaac 각속도다. 2 장 마지막 항목의 불일치를 포함한다.
- 조향 정지 조건은 한 가지 대안으로만 재 봤다(그 정의·문턱은 고정하지 않았다).
- 곧 바퀴 오도메트리가 관절각 기반으로 바뀐다(T11 세션). 그 뒤 실행과 비교할 때는 엔코더 경로가 다르다.
