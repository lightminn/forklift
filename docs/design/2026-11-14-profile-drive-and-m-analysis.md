# 개루프 프로필 구동과 M1–M3 분석 (G6·G8) — 설계 (2026-11-14)

출처: [도착일 절차서](../plans/2026-11-12-arrival-day-procedure.md) 12 절(G6·G8, 총괄 순서 3번), [C3 기록 진단](../validation/2026-11-13-c3-record-diagnosis.md) 6 절(M1–M3 정본), [텔레옵 기록](2026-11-14-teleop-record-state-markers-clock.md)(G1·G5·G7), [IMU 기록·장착](2026-11-14-imu-record-and-mount.md)(G2·G3), [텔레옵 다리](2026-11-12-teleop-bridge.md). 담당 콘솔 세션.

## 1. 무엇이 필요한가

- M1–M3 는 시행마다 **같은 속도 이력과 q 일정표**가 필요하다. 텔레옵은 손 입력이라 그렇게 못 한다(12.3 표). `bringup.py step` 은 받침대 위 바퀴 속도 계단뿐이다.
- 조건(12.3, G6 칸): 받침대 전용 `commission` 이 아니라 **정상 빌드에서**, S6 의 속도 감시·스캔 허가·정지 조건과 운용자 확인 게이트를 **그대로 유지**하고, 운용자는 손에 든 차단 스위치를 쥔다.
- M2 추가 조건(총괄 2026-11-14): 최대 조향 좌·우, 명령 q 대비 측정 q, 적재·빈차.

## 2. G6 — 일정표가 조이스틱을 대신한다

**방식:** 텔레옵 다리(`tools/teleop_bridge.py`)는 그대로 두고, 콘솔이 보내는 `teleop` 메시지의 `speed_ratio`·`curvature_ratio` 두 값만 일정표가 채운다. `deadman`·seq·요청 토큰·lease·모드는 콘솔이 보낸 그대로다. 그래서 arbiter(모드·무장·lease·명령 나이), `TeleopDrive`(가감속·곡률 변화율·creep·묶음 허가), 바닥 허가(스캔), 안전 속도(엔코더), 운용자 확인 넷, MCU 쪽 정지 조건이 손 텔레옵과 똑같이 걸린다. 일정표는 **손을 대신할 뿐 어떤 관문도 열지 않는다.**

- 다리 인자: `teleop_bridge.py … --profile <파일>` (`--record` 필수). 다리는 들어오는 `teleop` 메시지를 arbiter 에 넘기기 전에 두 비율을 일정표 값으로 바꾼다(`ProfileSource`). 콘솔 화면에 일정표 상태(구간 이름·남은 시간·대기/진행/중단)를 `state.notes` 로 보인다.
- **시작:** 무장(TELEOP, armed) 뒤 운용자가 deadman 을 누르고 있는 상태에서 콘솔의 "일정표 시작" 버튼(새 콘솔 메시지 `profile_start`, 요청 토큰 필요)을 누르면 시작한다. 정지 상태(엔코더 속도 < `stop_speed_mps`)가 아니면 거부한다.
- **중단:** deadman 을 놓으면 차는 지금처럼 멈추고(다리의 기존 동작), 일정표는 **중단**된다(이어 하지 않는다). 무장 해제·모드 변경·lease 만료·오류 정지도 같다. 중단된 시행은 기록에 `void` 로 남고, 새 시행은 정지에서 다시 시작한다.
- **끝:** 마지막 구간 뒤 일정표는 0·0 을 보내고 끝난다(운용자가 deadman 을 놓아도 된다).
- **기록:** 일정표 행 `{"t": "profile", "host_ns", "trial", "seg", "label", "state", "s_m", "speed_ratio", "curvature_ratio", "target_mps", "target_kappa"}` 를 다리 주기마다(G1 기록과 같은 writer). 구간 경계마다 G5 표지 행(`profile:<trial>:<label>:start`)을 자동으로 남긴다.

### 2.1 일정표 파일

YAML. 구간의 목록과 시행 이름:

```yaml
schema: drive_profile/1
name: m2_left_max_fwd
load: empty            # empty | loaded (2.3)
segments:
  - {label: still_pre,  hold_s: 3.0}                         # 정지(속도 0, 곡률은 다음 구간의 첫 값으로 미리)
  - {label: arc,        speed_mps: 0.10, kappa_inv_m: max,  distance_m: 1.5}
  - {label: still_post, hold_s: 3.0}
```

- 구간 종류: `hold_s`(정지, 시간), `distance_m`(주행, 엔코더 거리), 그리고 곡률 모양 `kappa_inv_m`(상수, `max`/`-max` = 텔레옵 곡률 한계), `q_rad`(상수, 기구 관계로 곡률로 바꿈), `s_merge: {offset_m, length_m}`(아래 사인 곡률 합류), `q_step: {from_rad, to_rad, at_m}`.
- **구간 진행은 엔코더 주행 거리로 한다**(시간이 아니라). 재출발 가속 중에도 같은 거리에서 같은 곡률이 되게 하기 위해서다. 조향은 개루프다 — 경로를 따라가려 고치지 않는다. 거리는 다리가 이미 계산하는 엔코더 속도(`SafetySpeed` 의 부호 있는 속도)를 다리 주기마다 적분한다.
- 검사(파일을 읽을 때 거부): 속도 ≤ 텔레옵 명령 상한(빈차 0.132 m/s, 적재는 적재 상한과 더 작은 쪽), |곡률| ≤ 텔레옵 곡률 한계 0.36 /m, 계획 속도에서 곡률 변화율 ≤ 텔레옵 곡률 변화율 0.5 /m/s(그래서 기록된 명령 곡률이 일정표와 같다), 주행 방향 부호(후진은 음의 속도), 총 시간 상한(기본 120 s).
- **사인 곡률 합류(M3):** 길이 L 에서 횡 Δy 만큼 옮기는 S 자를 κ(s) = A·sin(2πs/L), A = 2πΔy/L² 로 만든다. 시작·끝의 곡률과 heading 이 0 이다. 예: Δy 40 mm, L 0.9 m → A 0.310 /m, 0.10 m/s 에서 최대 곡률 변화율 0.217 /m/s(한계 0.5 안). Δy 5·20 mm 와 L 2.1 m 는 더 작다.
- **"최대 조향"(M2 추가 조건)** 은 텔레옵 곡률 한계 0.36 /m(q 0.2333 rad)다. 기구 최대는 0.3665 /m(q 0.2374 rad)로 4 mrad 더 크지만 텔레옵 한계를 넘지 않는다 — 총괄 결정(2026-11-14)으로 텔레옵 한계는 바꾸지 않고, 4 mrad 차이는 측정 결과 문서에 한계로 적는다.

### 2.2 시험(먼저)

- 일정표 읽기·검사: 각 거부 조건, 사인 합류의 A·끝 heading 0, `q_rad` → 곡률, `max`.
- `ProfileSource`: 거리 진행(가짜 엔코더 속도), deadman 놓음 → 중단·void, 무장 해제·lease 만료 → 중단, 끝 → 0·0, 정지 아님 → 시작 거부, 구간 경계 표지.
- 끝-대-끝(텔레옵 다리 시험의 MCU 모형 pty 위): 일정표가 arbiter·`TeleopDrive` 를 거쳐 MCU 의 DRIVE 로 나가고(속도 이력·곡률), 손 텔레옵과 같은 관문이 걸린다(바닥 허가 0 이면 속도 0, 확인 넷이 없으면 거부). 모형 plant 는 합성이라 실제 곡률·지연은 말하지 않는다.

### 2.3 적재 시행 — 총괄 결정 (가): 자율 단계로 미룸

실차 다리는 적재 상태의 텔레옵을 **거부한다**(`real_teleop.enforce_real`: `teleop_refused = "real_loaded"`, 실차 복구는 손으로 — field recovery decision (B)). 그리고 S6 단독 실행의 안전 상태(`bench_safety`)는 언제나 빈차다. 그러므로 M2 의 "적재" 조건은 지금 구조로는 돌릴 수 없다. 선택지:

- (가) 적재 시행은 자율 단계 뒤로 미룬다(경로 추종이 적재 운반을 할 때 같은 측정을 한다).
- (나) G6 일정표에만 예외를 둔다: 운용자 확인에 "적재 고정" 을 더하고, 적재 상한 속도, 포크 높이 고정, 일정표 파일의 `load: loaded` 와 콘솔 확인이 같을 때만 연다. 안전 규칙(실차 적재 텔레옵 거부)을 바꾸는 일이므로 총괄 결정, 필요하면 사용자 결정이다.

**총괄 결정(2026-11-14): (가).** 실차 안전 규칙(적재 텔레옵 거부)은 바꾸지 않는다. 적재 조건은 자율 단계(경로 추종)에서 같은 정의로 잰다. G6 은 `load: loaded` 파일을 거부한다(빈차만).

### 2.4 언제 쓸 수 있나

- 다리의 바닥 허가는 스캔이 있어야 연다(`no_scan` 이면 속도 0). 그래서 실차에서 G6 을 돌리는 것은 **G4(A2M12 스캔을 다리에 연결, bring-up 7b) 뒤**다. G6 코드와 모형 위 시험은 지금 한다.
- 다음 PCB 판(비상정지 입력) 전에는 S6 자체가 열리지 않는다(절차서 0 절).

## 3. G8 — M1–M3 분석

입력: 다리 기록(STATE 원행·주기 행·일정표 행·표지), IMU 기록(G2), 각 장치의 시각 맞춤(G7: MCU, IMU — 같은 `host_boot_id`), 장착 축(G3: `û`, 편향 구간). 위치 참값(G9)은 아직 방법이 정해지지 않았으므로 **함수의 입력**으로 받는다(시작·끝 자세와 그 불확도).

- **공통:** 시행을 일정표 행·표지로 자른다(`void` 시행 제외). MCU 표본과 IMU 표본을 호스트 시각 축에 놓는다(각 fit 의 한계 그대로 — 두 장치의 최소 지연 차는 알 수 없는 상수다). 시행 앞뒤 정지 구간의 자이로 평균으로 편향을 빼고(`imu_mount.bias_between`), `yaw_rate(·, û)` 를 적분해 IMU heading 을 낸다.
- **heading 불확도:** 정지 편향 구간 길이·주행 시간과 자이로 잡음(책상 실측 `2026-10-27-gyro-model-d435i-static.md` 의 값, 장착 상태 실측이 생기면 그것)으로 1σ 를 계산해 함께 낸다. 1 mrad 를 넘으면 그 시행의 heading 판정은 "판정 불가"(C3 6.3).
- **M1:** 오도메트리 heading(실차 `RealOdometry` 를 기록된 STATE 로 다시 돌림) − IMU heading 의 rad/m, 방향·속도별. 끝 횡 오차는 위치 참값이 있을 때만.
- **M2:** 일정 곡률 구간(곡률 변화가 끝난 뒤)의 이득 = 평균 IMU yaw rate ÷ (평균 엔코더 속도 × κ(측정 q)), 그리고 κ(명령 q) 기준으로 따로. 진행 방향·좌우별, 적재·빈차별. 명령 q − 측정 q 의 정상값·분포. 좌·우 이득 비가 실차에서 보이는 비대칭이다(실차는 조향각 센서가 하나라 바퀴별은 못 본다).
- **M3:** q 계단 — 측정 q 가 변하기 시작한 때부터 IMU yaw rate 가 새 정상값의 63 % 에 닿을 때까지의 지연(호스트 축, 두 fit 의 한계와 함께). 합류 — 합류 끝과 0.42 m 뒤의 상대 위치·heading 오차는 위치 참값(G9) 입력이 있을 때 계산하고, heading 만은 IMU 로 낸다.
- 읽는 법(C3 6.5 의 문턱·중앙값·95 % 구간·추가 5 회)은 등록 문서에서 고정한다. G8 은 그 값들을 낼 뿐 판정 문턱을 박지 않는다.
- 시험: 합성 기록(알려진 이득·편향·지연·장착 축)으로 각 값의 복원, `void` 제외, 시각 축의 한계 표시, heading 불확도 계산.
