# D435i IMU 기록기와 장착 회전 (G2·G3) — 설계 (2026-11-14)

출처: [도착일 절차서](../plans/2026-11-12-arrival-day-procedure.md) 12.3 의 G2·G3(총괄 순서 2번), [IMU 책상 검토](2026-10-22-d435i-imu-desk-review.md) 3 절, [텔레옵 기록 설계](2026-11-14-teleop-record-state-markers-clock.md)(G1·G7). 담당 콘솔 세션.

## 1. 무엇이 필요한가

- M1–M3 의 참값 heading 과 M3 의 응답 지연은 D435i 자이로를 차체 yaw rate 로 옮겨 쓴다(12.4). 그러려면 표본마다 **장치 시각과 호스트 수신 시각을 함께** 남겨야 한다 — 수신 시각만 쓰면 USB·librealsense 버퍼 지연이 M3 의 지연에 섞인다.
- 10-23 책상 기록(`record_imu.py`, 저장소 밖)은 장치 `frame_timestamp`(µs, 32 bit 라 4,295 s 마다 되감김), `get_timestamp()`(ms, 시간 영역 미기록), `time.time()`(벽시계)을 남겼다. 호스트 **단조** 시각과 시간 영역이 없다. 형식 시험의 입력으로는 쓰되(4 절), 실차 기록은 이 설계의 도구로 한다.
- 실차에서는 D435i 와 MCU 가 모두 Jetson 에 붙는다. 텔레옵 다리(G1)와 IMU 기록기는 **같은 호스트**에서 돌아야 한다 — 두 기록의 호스트 단조 시각을 같은 축으로 쓰기 위해서다(header 의 `host_boot_id` 가 같아야 한다).

## 2. G2 — `tools/imu_record.py`

```
imu_record.py --out imu.jsonl [--seconds S] [--gyro-hz 400] [--accel-hz 200] [--global-time off|on]
```

- pyrealsense2 로 자이로(기본 400 Hz)·가속도(기본 200 Hz) 원 표본을 받는다. 요청 빈도가 장치에 없으면(가속도 200 Hz 는 모든 D435i 에 있지 않다) 장치의 지원 프로파일을 열거해 가장 가까운 것을 고르고, 실제 값과 대체 사유를 `profile` 행에 쓴다.
- motion correction 은 **끈다**(10-23 과 같게). SDK 는 끈 상태에서도 IMU 축을 깊이 좌표계로 돌리는 정렬은 하지만, 내장 보정(감도·편향)은 켰을 때만 적용한다 — 따라서 기록은 **축 정렬된 원 표본**이다. 내장 보정 계수와 옵션의 지원 여부·설정값·되읽은 값을 `profile` 행에 남긴다. 편향은 G3 의 정지 구간에서 재고, 감도(배율) 오차는 이 기록만으로는 모른다 — M1–M3 의 heading 참값에는 G9 의 벽 정합이 배율을 따로 확인한다. `global_time` 은 기본 **끔**: `get_timestamp()` 가 장치 하드웨어 시계 영역에 머물게 해서, 장치 시각 ↔ 호스트 시각 변환을 G7 로 직접 맞춘다(SDK 의 Theil-Sen 변환에 기대지 않는다). 켜면 그 영역을 그대로 기록한다. 끄는 것만으로 하드웨어 시각이 보장되지는 않는다 — 메타데이터가 없으면 SDK 는 호스트 시각으로 대신한다. 그래서 G7 은 `ts_ms` 가 아니라 메타데이터 `dev_us` 만 쓰고, `dev_us` 가 없거나 32 bit 범위 밖인 표본은 `null` 로 남겨 맞춤에서 빼고 센다. 행마다 `dom` 을 남겨 시간 영역이 바뀌면 보이게 한다.
- 행: `{"t": "imu", "s": "g"|"a", "dev_us": frame_timestamp(메타데이터, 32 bit 원값), "ts_ms": get_timestamp(), "dom": 시간 영역 이름, "host_ns": 콜백에서 읽은 time.monotonic_ns(), "x", "y", "z"}`. 단위: 자이로 rad/s, 가속도 m/s², 축은 SDK 가 내는 깊이 좌표계(x 오른쪽, y 아래, z 앞).
- `host_ns` 는 콜백이 불린 시각이다 — 실제 표본 시각과의 차이(전송·버퍼 지연)는 보장하지 않는다(G7 이 지연 하단 포락선으로 다룬다).
- 기록은 G1 의 `RecordWriter`(유한 큐 + writer 스레드)로 쓴다. 콜백은 시각을 찍고 큐에 넣기만 한다(librealsense 콜백 스레드를 막지 않는다; 큐가 차면 버리고 센다).
- 장치 객체: 옵션을 설정한 그 motion 센서 객체를 직접 `open`·`start` 한다(serial 로 pipeline 을 시작하면 SDK 가 장치 객체를 새로 만들어 설정이 빠질 수 있다). 옵션의 되읽은 값도 그 센서에서 읽는다.
- 순서: **header 제출**(장치 이름·serial·firmware·USB·SDK 버전·요청 빈도·`global_time`·`host_boot_id`·시작 시각) → **SDK 시작** → `profile` 행(실제 빈도·대체 사유·내장 보정·옵션값, 시작해야 알 수 있는 것) → 표본 행·60 s 마다 온도 행(`asic_temperature` 등, 읽히면). SDK 는 `start` 가 돌아오기 전에 콜백을 부를 수 있으므로 **표본이 `profile` 행보다 먼저 올 수 있다** — 읽는 쪽은 header 뒤 어디에서든 `profile` 을 받는다. 종료는 어떤 예외에서도 같다: **SDK 정지(콜백이 끝남; 부분 시작이면 연 것만 닫고, 정지 실패는 기록) → 집계 확정 → writer close → `close_result` 확인**. 장치 정보 읽기 실패도 header 에 사유를 남기고 끝까지 간다. footer: 스트림별 표본 수·`dev_us` 결측·NaN·중복·역행(늦은 표본)·재시작(20 ms 넘게 뒤로)·최대 간격, 관측 빈도, 종료 사유(`seconds`·`interrupt`·`stalled`·`start_failed`·`error`), 버림·쓰기 오류.
- 시작 뒤 2 s 동안 표본이 없으면(장치 분리 등) `stalled` 로 끝낸다. 시작 실패·`stalled`·그 밖의 예외(`error`)·장치 정보나 정지 실패·writer 미종료·쓰기 오류는 표준 오류에 적고 종료 상태 1. 기존 파일은 거부.
- pyrealsense2 는 `import` 를 함수 안에서 한다 — 장치 없는 ws1 시험에서도 모듈이 읽히게.

## 3. G7 연결 — `forklift_core/sensors/imu_record.py`

- `unwrap_u32_us(values) -> list[int]`: 32 bit 되감김 풀기. 표본마다 `v + k·2³²` 중 **바로 앞 표본의 풀린 값에 가장 가까운 것**을 고른다 — 되감김 직전 표본이 늦게 와도(`[M−2, 1, M−1, 2]`) 되감김을 두 번 세지 않는다. 스트림별로 푼다.
- 장치 재시작·긴 공백은 되감김 규칙만으로는 구별되지 않는다. `continuous_segments` 는 장치 시각이 **20 ms 넘게 뒤로 가거나**(재시작; 늦은 표본은 그보다 작다) 인접 표본의 호스트 간격과 장치 간격이 **0.5 s 넘게 어긋나면**(풀 수 없는 공백·지연 급변) 구간을 나눈다. 새 장치 시각이 옛 시각보다 20 ms 안쪽 뒤에 떨어지는 재시작은 여기서 알아낼 수 없다 — 그때 fit 은 그 계단(20 ms 이하)을 떠안는다. 이 기준은 재시작 검출을 보장하지 않는다.
- `imu_stream(rows, stream="g") -> ImuStream`(풀린 `dev_us`, `host_ns`, xyz, `host_boot_id`, `host_clock`, 나온 `dom` 들, `dev_us` 결측 수). header 가 둘 이상의 호스트 부팅을 말하면 거부한다.
- `imu_clock_fits(rows, stream="g") -> list[ClockFit]`: 연속 구간마다 `clock_map.fit_clock(dev_us, host_ns, host_boot=...)`. header 의 `host_clock` 이 `monotonic` 이 아니면(10-23 의 벽시계, 또는 불명) **거부**한다 — `allow_wall=True` 는 형식 회귀 분석 전용이고, 그 결과는 단조 시각 정렬의 증거가 아니다. 같은 함수로 MCU(G1)와 IMU 를 각각 호스트 시각에 맞추면 두 장치의 표본을 같은 축에 놓을 수 있다. 각 fit 의 한계(G7 설계 5 절)는 그대로다 — 두 장치의 최소 지연 차는 알 수 없는 상수로 남고, M3 의 지연 결과는 그 한계와 함께 적는다.

## 4. 10-23 정지 기록으로 하는 형식 시험

- 그 기록의 표본(`chunk_*.npz` 의 행 `(get_timestamp ms, frame_timestamp µs, time.time s, x, y, z)`)을 이 도구의 행 형식으로 바꾸는 변환 함수 `rows_from_static_chunk` 를 둔다(호스트 시각은 `time.time()` 을 ns 로 — 단조가 아님을 header 에 표시).
- ws1 의 분석 잡으로 7,922 s 전체에 `unwrap_u32_us` → `imu_clock_fits(allow_wall=True)` 를 돌려 열 변환·순서·되감김 한 번 넘김·표본 간격(400.8 Hz)을 확인한다. 여기서 나오는 drift 는 **벽시계에 대한 값**이고 잔차는 관측 지연 변동일 뿐이다 — 단조 시각 정렬이나 M3 지연 정확도의 증거로 쓰지 않는다. 결과는 PR 에 적는다(원자료는 ws1 에 있다; 시험에는 넣지 않는다).
- 단위 시험은 그 형식을 흉내 낸 작은 합성 표본(되감김 포함)으로 한다.

## 5. G3 — 장착 회전과 yaw rate

평면 운동을 가정한다: 바닥은 평평하고 차체는 바닥 위에서만 움직인다(바닥 기울기는 G9 의 수평계로 확인). 그러면 차체 yaw rate 는 `ω · û` 이다 — `û` 는 IMU 좌표로 본 차체 위쪽 단위 벡터. 전체 회전 행렬은 M1–M3 에 필요하지 않다.

- 이 차는 **제자리 회전을 못 한다** — 실차 명령 변환(`rear_drive_command`)은 뒤축 기준 유한 곡률만 받고 속도 0 이면 바퀴도 0 이다. 회전축 방향을 재는 데 제자리 회전은 필요 없다: 평면 위 일정 곡률 원호 주행에서도 차체 각속도는 위쪽 축 방향뿐이다.
- `û` 를 두 가지로 따로 잰다(`forklift_core/sensors/imu_mount.py`):
  1. **정지 중력:** 완전 정지 구간의 가속도 평균 방향(가속도계는 위쪽 반력 +g 를 낸다) → `û_g`. 원호 주행 중의 가속도는 구심 가속도가 섞이므로 쓰지 않는다.
  2. **원호 주행:** 같은 곡률로 한쪽 방향 원호를 도는 정상 구간(표지 G5 로 고르거나 |ω| 문턱)의 자이로에서 **앞뒤 정지 구간 편향의 평균을 뺀** 평균 방향 → `û_ω`. 편향을 빼지 않으면 책상 실측 편향이 10°/s 회전축을 약 1.2° 기울인다. 앞뒤 편향의 차이(데움 중 변화)를 함께 내고, 편향을 뺀 평균 회전이 0.05 rad/s 보다 작으면 거부한다. 부호는 운용자가 본 회전 방향(위에서 보아 반시계 = +yaw)으로 정한다.
  - 반시계·시계 두 방향의 `û_ω` 는 둘 다 위쪽을 향하도록 부호를 붙였으므로 그대로 사이 각을 비교한다. `û_g` 와 각 `û_ω` 사이 각도 낸다. 바닥이 평평하고 IMU 가 단단히 붙어 있으면 작다 — 크면(문턱은 등록 때 정함) 평면 가정이나 장착을 의심하고 멈춘다. yaw rate 에는 두 방향 `û_ω` 의 평균을 쓴다.
- 장착 피치 오차 δ 의 몫(감도 cos δ, 롤·피치 속도의 새어 듦 sin δ)은 `û_ω` 를 쓰면 같은 바닥 위에서는 사라지고, 남는 것은 주행 중 차체 롤·피치(가감속·요철)의 새어 듦이다. 기록의 `ω` 에서 `û` 에 수직인 성분의 크기(표본별 크기의 RMS·p95 — 왕복 진동이 상쇄되지 않게 — 와 평균 벡터의 크기)는 **평면 가정이 깨졌는지 보는 진단값**이지 yaw 오차의 크기나 상한이 아니다(기운 차체가 자기 z 축으로만 돌면 수직 성분은 0 이어도 Euler yaw rate 와 다르다). G8·G9 의 heading 불확도 판정을 이것으로 대신하지 않는다.
- **부호 확인:** `û_ω` 자신으로 부호를 확인하면 자기 확인이 된다. 그래서 편향을 뺀 각 방향 원호의 평균 `ω · û_g`(중력으로 잰 위쪽)가 반시계에서 양, 시계에서 음인지 본다. 바퀴 오도메트리의 yaw 부호와도 맞춘다(같은 시각축, G7).
- **승강:** IMU 는 캐리지에 붙어 승강과 함께 움직인다(책상 검토 3 절). M1–M3 는 포크를 가장 낮게 둔 채 하고, `û` 도 그 상태에서 잰다. 승강하면 다시 잰다.
- **차체 위 G3 절차**(도착일 절차서 12 절에 넣을 내용, S6 텔레옵이 열린 뒤): 데움 → 정지 60 s(중력·편향) → 왼쪽 최대 곡률 원호 2 바퀴(S6 속도, 지름 2/κ_max 의 빈 바닥) → 정지 60 s → 오른쪽 최대 곡률 2 바퀴 → 정지 60 s. 원호의 정상 구간은 운용자가 G5 표지로 표시한다. 결과: `û_g`·`û_ω`(두 방향)·세 벡터 사이 각·편향 변화·부호·수직 성분 크기. 책상 실측의 450–960 s 는 데움 **시정수**이지 완료 시간이 아니다 — 최소 대기, 정지 구간 사이 편향 변화 허용치, 넘으면 다시 기다릴지는 측정 전에 시뮬-물성과 등록한다.

## 6. 시험 (먼저 쓴다)

- `imu_record.py`: 가짜 프레임 원천(pyrealsense2 없이)으로 행 형식·header 가 첫 행·`profile` 행(실제 빈도·대체·보정 옵션)·footer 의 스트림 통계·온도 행·기존 파일 거부·콜백이 막지 않음(디스크가 멈춰도)·두 스트림 동시 콜백·큐 포화·Ctrl-C·시작 실패·표본 끊김(`stalled`)·종료 중 콜백·`dev_us` 결측·NaN.
- `unwrap_u32_us`: 되감김 0·1·2 번, 작은 역행, 되감김 직전 표본이 늦게 온 경우.
- `continuous_segments`: 장치 재시작(장치 시각이 크게 뒤로, 호스트 간격이 작아도)·긴 공백에서 나뉨; 재시작 뒤 두 fit.
- `rows_from_static_chunk`: 10-23 형식 합성 표본 → 행, header 의 '호스트 시각이 벽시계' 표시; `imu_clock_fits` 가 그 header 를 거부(`allow_wall` 없이).
- `imu_clock_fits`: 되감김을 넘는 합성 기록에서 drift·포락선(G7 과 같은 기준), 재시작에서 두 fit.
- `imu_mount`: 알려진 장착 회전(피치 5.7° 숙임 등)과 0 아닌·변하는 자이로 편향으로 만든 정지·원호 표본에서 `û_g`·`û_ω` 복원(편향을 빼지 않으면 기울어짐), 두 방향 사이 각, 중력 기준 부호 확인, 수직 성분(왕복 진동 포함), 회전 부족 거부(부호 확인에서도 — 회전 없음을 시계 방향으로 읽지 않는다), NaN·짧은·모양이 틀린 입력 거부.
- `RealSenseSource`: pyrealsense2 대역(가짜 모듈)으로 옵션이 스트림을 여는 같은 센서에 설정·되읽히는지, 가장 가까운 빈도 대체, 프레임 → 행 변환(메타데이터 없음 = `null`), 부분 시작 뒤 정지.

## 7. 범위 밖

- G6·G8·G9·G4 는 따로. IMU 를 실시간 오도메트리에 쓰는 일(자이로 heading 계획)은 이 설계 밖이다(사용자 결정 사항).
- 실기 확인: 노트북에 D435i 를 꽂아 `imu_record.py --seconds 120` 으로 형식·빈도·시간 영역을 확인하는 짧은 실기 시험을 사용자에게 부탁한다(8 절). 이것은 **기록 경로 확인**이고 G3 장착·부호 검증이 아니다. Jetson 에서 텔레옵 다리와 함께 돌 때의 기록 품질은 차체 위에서 따로 본다.

## 8. 사용자에게 부탁할 실기 확인

- 준비물: D435i, USB 3 케이블(10-23 과 같은 것), 노트북(conda base 에 pyrealsense2 2.58 이 있다).
- 명령 한 줄(저장소 루트, 출력은 git 이 무시하는 `data/` 아래라 재부팅에도 남는다): `/home/light/anaconda3/bin/python tools/imu_record.py --out data/imu_check/<날짜>.jsonl --seconds 120` (pyrealsense2 2.58.3 이 conda base 에 있음을 2026-11-14 `import pyrealsense2` 로 확인)
- 시간: 약 3 분(책상 위에 그냥 두고, 마지막 30 초에 손으로 한두 번 천천히 돌려 본다).
- 돌려받을 것: 그 jsonl(수 MB). 확인할 것: 축별 표본 수·빈도, `dev_us` 와 `host_ns` 가 같이 찍히는지, 시간 영역, 회전 구간에서 `û` 추정이 돌아가는지.
