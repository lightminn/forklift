# 실차 안전 감시 최소안 (4e-2, 2026-11-16, 설계 메모)

- 배정(총괄, 2026-11-16): 시뮬은 장면 손상 판정(기울기·미끄럼·금지 접촉)을 참값으로 해서 사실상 안전 감시로 썼다. 실차에는 참값이 없다([이식 계획](../plans/2026-11-11-sim-to-real-bringup.md) 5 절 '참값 없는 실차의 감시 제한', [감사표](2026-11-11-p05-truth-audit.md) 8). 학교 규모로 단순하게, 실차 실행기에서 세 가지를 감시해 넘으면 정지하고 알린다. 임시 문턱은 근거 한 줄과 함께 두고, S8 실측 뒤 다시 정한다.
- 범위: 감시 셋과 그 정지·알림. 실차 진입점 전체(4e-2 의 나머지)는 아니다. run_transport·장애물 층은 건드리지 않는다. Isaac 경로는 이 감시를 쓰지 않는다.
- 조율(콘솔 세션, 2026-11-16): 7b(텔레옵 스캔 원천)는 `real_teleop.py` 를 고치지 않고 `teleop_bridge.py` 는 인자·floor_permit·`_on_state`·`cycle` 앞 한 줄만 고친다. 겹치는 곳은 argparse 몇 줄이라 먼저 머지되는 쪽 뒤에 main 을 병합한다.

## 1. 무엇을 감시하나

| 감시 | 입력(이미 있는 것) | 넘는 조건(임시) | 정지 사유 |
|---|---|---|---|
| 모터 전류 | MCU `STATE.current_ma`(L·R·M·H, IPROPI) | 어느 채널이든 \|전류\| > 3.0 A 가 0.5 s 이어짐(신선한 STATE 만 셈) | `watch_current` |
| 명령 대비 바퀴(바퀴마다) | 직전에 포트에 넣은 DRIVE 의 바퀴별 목표(`RealDrive` 의 left·right rad/s, `_submit` 이 큐에 넣은 것) 와 MCU 가 잰 바퀴 속도(`STATE.wheel_rate_left/right_rad_s`) | 무장 중 어느 바퀴든 \|목표 − 측정\| 이 0.05 m/s 상당(바퀴 반지름으로 rad/s 로 바꿈)을 0.5 s 넘음(신선한 STATE 만 셈). 목표와 측정이 모두 0.03 m/s 상당 아래면 보지 않음 | `watch_wheel` |
| 기울기(판정만, 이번에 브리지에 붙이지 않음) | 가속도 표본(중력 방향)을 넘겨받음 | 무장할 때 잡은 기준 중력 방향에서 8° 넘게 기운 상태가 0.3 s 이어짐. 표본을 받기로 했는데 0.5 s 넘게 없으면 그것도 정지 | `watch_tilt`·`watch_imu_stale` |

- 임시 문턱의 근거(모두 `measured: false, until: S8`):
  - 전류 3.0 A: 정격 45 W/12 V ≈ 3.75 A 의 80 %. 빈 포크·0.2 m/s 저속에서 이보다 큰 전류가 0.5 s 이어지는 것을 **S3 실측 전의 임시 이상 징후**로 본다(막힘이라고 단정하지 않는다). 시동·역전 전류가 0.5 s 안에 가라앉는다는 것은 가정이고, S3 에서 채널별 정상 분포를 잰 뒤 다시 정한다. 펌웨어는 5 A 를 20 ms 넘으면 FAULT 로 래치한다(`board_config.c`, 정지 전류 10 A 아래). 호스트 감시는 그보다 낮은 전류가 오래 이어지는 경우를 맡는다. 승강(H)도 같은 값으로 시작한다. 10 kg 들기의 실제 전류는 모른다.
  - 바퀴 0.05 m/s·0.5 s: 텔레옵 속도 상한 0.2 m/s 의 1/4. 목표는 직전 주기에 넣은 값이라 가감속·방향 전환 중에는 측정과 차이가 난다. 0.5 s 는 가속 제한(0.8 m/s²)으로 0.2 m/s 까지 오르는 시간(0.25 s)의 두 배라 그 차이로는 넘지 않는다고 본다(시험으로 확인). 바퀴마다 보므로 조향 중 한쪽 바퀴만 멈춘 경우도 잡는다. 명령 0 인데 바퀴가 도는 경우(밀려 굴러감)도 잡는다. 바퀴가 헛도는 미끄럼은 엔코더만으로는 안 보인다(IMU 불일치는 후속). 축 속도가 무효면 지금도 `speed_invalid` 로 서므로 이 감시는 따로 다루지 않는다.
  - 기울기 8°: 시험장은 콘크리트 평바닥이라 경사가 없다. 차체가 5° 넘게 기울면 이상이지만, 장착 진동과 가감속에 따른 가속도 겉보기 기울기를 피하려고 8° 와 0.3 s 로 둔다. 가속도만으로 보는 기울기는 가감속 중 흔들리므로, 켜기 전에 장착축·가감속·진동·표본 지연을 S8 에서 확인한다.
- 감시는 **무장 중(armed)** 에만 판정한다. 무장하지 않으면 출력이 꺼져 있다.
- 전류와 바퀴는 **새로 받은 신선한 STATE 에서만** 판정하고 지속 시간을 누적한다(`host.health(now).fresh` 이고 `state_rx_ns` 가 바뀐 경우). STATE 가 신선하지 않으면 지속 시간을 지우고 판정하지 않는다. 그때의 정지는 기존 링크 경로(MCU 만료·`speed_invalid`)가 맡는다.

## 2. 넘으면

- 중재기 정지(`TeleopBridge._stop(now, "watch_…")`)로 바퀴 목표를 0 으로 둔다. 지금 `overspeed`·`loop_slow` 와 같은 길이다. 결과: 큐에 있던 DRIVE 는 버려지고(제어 세대 경계), 중재기 정지는 무장도 푼다(`Arbiter.stop`: STOPPED, disarmed). 그래서 브리지가 MCU 에 DISARM 을 보낸다. 과속 정지와 같다. 펌웨어 FAULT·만료·ESTOP 은 그대로 MCU 래치다. 다시 달리려면 운용자가 다시 무장하고 요청해야 한다. 감시가 따로 래치를 두지는 않는다.
- 같은 주기에 다른 정지가 겹치면 기록의 `stop` 은 먼저 걸린 것이다(`rec.setdefault`). 감시는 속도·loop_slow 판정 뒤에 부르므로 그보다 뒤 순서다. 감시가 넘은 사실은 `stop` 과 별도로 `rec["watch"]` 에 늘 남긴다.
- 콘솔에 사건으로 알린다: `{"t": "event", "kind": "watch_stop", "reason": "watch_current"}` 처럼 kind 는 `watch_stop` 하나, 사유는 reason 에 둔다. 콘솔은 kind 에 "stop" 이 든 사건을 빨간색으로 보이므로 콘솔을 고치지 않아도 된다(콘솔 세션 확인, `console/web/js/main.js`). 알리는 자리는 지금 `loop_slow`·`clock_rate` 를 알리는 Bridge.cycle 의 사건 목록이다.
- 기록 행(`rec`)에 감시 값(채널별 전류 최대, 바퀴 차, 기울기)과 넘은 조건을 남긴다. 넘기 전 '경고'(조건은 맞았지만 시간 미달)는 기록만 하고 알리지 않는다. 원인이 계속되면(예: 막힌 바퀴) 재무장 직후 다시 서므로, 사유별로 넘은 횟수를 세션 동안 세어 기록에 남긴다(콘솔 세션 제안).
- 감시는 펌웨어의 만료·FAULT·ESTOP 을 대신하지 않는다. 그 위에 얹는 호스트 쪽 정지다.

## 3. 구조

- `src/forklift_core/safety/real_watch.py`(새): 순수 판정. `SafetyWatch(config, wheel_radius_m).step(t_s, armed, fresh, new_state, currents_a, wheel_targets_rad_s, wheel_rates_rad_s, accel=None, accel_t_s=None, imu_expected=False)` → 넘은 사유(없으면 None)와 기록용 값(가장 큰 전류 채널, 가장 큰 바퀴 차, 기울기, 지속 중인 조건 `pending`). 시간은 호출하는 쪽이 넘긴다. 무장이 풀리면 지속 시간과 기준 중력을 지운다. 넘은 횟수는 사유별로 `counts` 에 쌓는다.
- `config/real/safety_watch.yaml`(새): 문턱·지속 시간·켬/끔, 값마다 `provenance`.
- `real_teleop.TeleopBridge(safety_watch=…)`: 속도·loop_slow 판정 바로 뒤에 감시를 부르고, 넘으면 `_stop`. 전류와 측정 바퀴 속도는 `self.host.state` 에서, 바퀴 목표는 `_submit` 이 마지막으로 큐에 넣은 `RealDrive.wheel_rates_rad_s`(그 만료가 지나면 0)에서 읽는다. None 이면 감시하지 않는다.
- `tools/teleop_bridge.py`: `Bridge` 가 감시를 기본으로 켠다(`--no-safety-watch` 로 끔, 기록 머리에 설정 파일 해시 `safety_watch`). 감시가 넘으면 `watch_stop` 사건을 보낸다.
- **IMU 는 이번에 브리지에 붙이지 않는다.** 브리지 안에서 RealSense 모션 센서를 열면 M 측정의 `tools/imu_record.py` 와 장치 소유가 겹친다. 기울기 판정은 `SafetyWatch` 에 두고 가속도 표본을 인자로 받게만 한다. 센서를 가진 쪽(실차 자율 진입점, S10 전)이 표본을 넘기는 경계로 연결한다. 그때까지 텔레옵 다리에서는 기울기 감시가 꺼져 있고, 시험 단계는 지금처럼 사람 감시·저속·빈 포크다(이식 계획 5 절).
- 실차 자율 진입점(S10 전)이 생기면 같은 `SafetyWatch` 를 그 루프에서 부른다. Isaac 런처·러너는 이 모듈을 부르지 않는다.

## 4. 시험(먼저)

- 판정: 각 감시가 지속 시간 미만이면 넘지 않고, 이상이면 넘는다. 무장이 풀리면 지속 시간이 지워진다. 0.03 m/s 상당 아래는 보지 않는다. 명령 0 에서 굴러감을 잡는다. 바퀴마다 본다(조향 중 한쪽만 멈춤). 신선하지 않거나 새로 오지 않은 STATE 로는 누적하지 않는다. 가속도를 넘기지 않으면 기울기를 보지 않는다. 표본이 끊기면 `watch_imu_stale`.
- 오탐 경계: 0 → 0.2 m/s 가속(0.8 m/s²)과 감속, 방향 전환, 곡률 최대 조향 중 바깥·안쪽 바퀴 속도 차, 시동 전류가 0.5 s 안에 가라앉는 경우에 넘지 않는다.
- 정지 경로: 감시 정지 뒤 다음 출력이 바퀴 0 DRIVE 이고 DISARM 은 없다. MCU 가 FAULT·STOPPING 이거나 같은 주기에 다른 정지가 걸려도 예외 없이 기록된다(`stop` 은 먼저 걸린 것, `watch` 는 따로).
- 브리지: 가짜 MCU 상태(전류 3.5 A 를 0.6 s)로 `TeleopBridge.cycle` 이 `watch_current` 로 정지하고 콘솔 사건이 나간다. 문턱 아래에서는 정지하지 않는다. 기존 텔레옵 다리 시험이 모두 그대로 통과한다(정상 주행에서 오탐 없음).
- 설정 파일: 값마다 `provenance` 가 있고 `measured: false` 다.

- 들어간 시험: `tests/unit/safety/test_real_watch.py`(판정 19 건: 지속 시간 경계, 시동 전류, 채널·부호, 조향 중 한쪽 바퀴, 차이 나는 바퀴 속도 추종, 명령 0 굴러감, 문턱 아래, 가감속 램프와 한 주기 지연, 무장 해제·신선도·새 STATE, 횟수, 기록 값, 기울기·IMU 끊김), `tests/unit/live/test_teleop_bridge_cycle.py` 끝(정상 텔레옵·조향·후진에서 넘지 않음, 전류 지속 → `watch_current` 정지·DISARM·횟수, 문턱 아래 전류, 한쪽 바퀴 멈춤 → `watch_wheel`, 감시 없으면 기록 없음). 기존 브리지 통합 시험은 감시가 켜진 채로 돈다.

## 5. 남는 것

- 문턱 재조정: S3(전류)·S5(정지)·S8(추종·IMU) 실측 뒤.
- 미끄럼(바퀴는 도는데 차체가 안 감)·적재 확인(카메라)은 이번에 넣지 않는다. IMU 각속도와 엔코더 요속도의 불일치로 미끄럼을 보는 일은 IMU 를 실행기에 늘 붙일 수 있게 된 뒤 따로 정한다.

## 6. 검토

- **Codex 1 회차.** P1 1 건(축 평균 비교는 조향 중 한쪽 바퀴 멈춤을 놓침 → 바퀴마다 목표·측정 비교)과 P2 4 건(신선한 STATE 에서만 누적, 3 A 는 S3 전 임시 이상 징후·시동 전류 시험, 정지 경로의 결과와 사유 순서, IMU 는 브리지에서 열지 않고 표본을 넘겨받는 경계)을 반영했다.
- **Codex 2 회차.** 새 P1/P2 없음. P3 2 건(3 절 입력 설명이 바퀴별 방식과 어긋남, 4 절이 끝난 시험처럼 읽힘)은 구현과 함께 3·4 절을 고쳐 반영했다. 구현 중 2 절의 'DISARM 없음'이 틀린 것을 찾아 고쳤다: `Arbiter.stop` 은 무장도 푼다.
- **Codex 코드 리뷰 1 회차.** P1 없음. P2 1 건(새 STATE 사이 공백도 지속 시간으로 셈 → 판정한 STATE 사이가 0.1 s 를 넘으면 지속을 다시 시작, 시험 추가). P3 은 확인 사항: 부호·단위 일치, 탈출 뒤 꼬리 구간은 직전 큐 DRIVE 기준이라 일관됨(경계 시험은 두지 않음), 실 MCU 의 바퀴 응답 지연·펌웨어 램프에 따른 오탐은 S8 에서 확인.
- **총괄(2026-11-16).** 텔레옵 다리부터 켠 것을 받아들였다. 실차 자율 진입점이 생기면 같은 모듈을 부른다(3 절). 기울기 감시가 텔레옵에서 꺼져 있다는 것을 PR 본문과 실차 점검표 후보에 적는다. 문턱은 임시값이고 S3·S8 실측 뒤 다시 정한다.
