# 상품 기반 지게차 잠정 모델

사용자 요청: 상품페이지의 설명 이미지와 규격을 참고해 시뮬레이션용 지게차를 만든다. 이전 차체 보류 결정에서 이번 상품 기반 잠정 모델 작업만 진행하도록 범위가 구체화됐다. 실물 사양 확정, ROS 작업공간 생성, 기존 코어 구조 전환은 포함하지 않는다.

## 근거와 모델 경계

- 원 판매페이지의 설명 이미지 9개와 대표 사진 5개를 확인했다. DLS 표기, 네 바퀴, 전동 승강 포크, 슬롯 지붕, 경사진 앞 기둥, 측면 문, 뒤 카운터웨이트가 보인다. 판매페이지 고시는 모델명을 상세참조로 남겨두며 숫자 치수는 없다.
- DLS 제조사 카탈로그 PDF 12–13쪽의 DLS08 외형이 일치한다. 13쪽 도면은 146 × 63 × 101cm, 12쪽은 순중량 24kg을 제시한다. 99 × 64 × 52cm는 포장 치수로 모델에 사용하지 않는다.
- 따라서 모델 정체성은 `dls08_provisional`이다. 치수와 순중량은 **대응 후보의 카탈로그 값**, 휠베이스·부품 치수·관절 범위는 **사진 비율 추정**, 질량 분포·마찰·구동 이득은 **시뮬레이션 가정**이다. 실제 SKU 동일성·조향 축·승강 거리·모터 성능은 미확인이다.

## 구현 방식

사진에서 수작업으로 구분한 부품을 SI 단위 기본 도형으로 구성한다. 단일 YAML에 전체 크기와 주요 부품 치수를 두고, 생성기가 같은 부품/관절 트리에서 URDF와 MJCF를 생성한다. 기본 도형은 변환·충돌 검사가 쉽고 실측 후 변경할 수 있다. 사진 텍스처나 재구성된 포토그래메트리 mesh를 정확한 CAD로 제시하지 않는다.

바퀴 회전 4개, 잠정 앞바퀴 조향 2개, 포크 승강 1개를 분리한다. 조향 축은 앞/뒤를 YAML로 바꿀 수 있게 하며 기본 앞 조향은 가정이다. 지붕과 문은 닫힌 고정 외형이다. 포크 틸트·사이드시프트·현가 운동은 근거가 없어 추가하지 않는다. 센서 외부 보정값도 만들지 않는다.

시각 형상과 충돌 형상을 구분한다. 포크 두 갈래의 빈 공간을 보존하며, 차체·지붕·기둥·바퀴를 충돌 형상에 포함한다. MJCF의 자기 충돌은 제외하고 외부 물체 접촉만 검사한다. URDF는 형상·운동학 교환 범위이며 가져오는 엔진에서 접촉 필터·구동기를 별도로 구성해야 한다. 관성은 잠정 질량 분배와 기본 도형의 관성으로 계산하며 실제 전복·적재 한계 예측에는 사용하지 않는다.

MuJoCo는 로컬 모델 검사와 렌더링에만 사용한다. 최종 통합 엔진 선정은 아니다. 미터 단위 URDF도 남겨 ROS 작업공간 없이 다른 도구에 가져갈 수 있게 한다.

## 산출물과 검증

- `sim/models/dls08_provisional/parameters.yaml`: 출처 상태와 주요 수치.
- `tools/build_forklift_model.py`: 모델 생성과 설정 검증.
- 생성된 `forklift.xml`, `forklift.urdf`, `scene.xml`: 모델과 별도 바닥 검사 장면.
- `tools/preview_forklift_model.py`: 다각도 렌더, 승강/조향 자세 미리보기, JSON 결과.
- `tests/simulation/test_forklift_model.py`: 실제 생성기·MuJoCo 로딩·치수·승강 방향·포크 간격·낙하 안정성·가정 변경·설정 오류 검사.
- `docs/references/dls08/`와 검증 기록: 원본 URL/해시, 추정 근거, 실제 실행 결과와 미검증 범위.

기능 시험을 먼저 실패시킨 뒤 구현한다. 실제 렌더를 상품 사진과 대조한다. 관절을 지정 자세로 옮긴 미리보기와 시간 적분 물리 시험을 구분한다. 실물 주행·센서 인식·팔레트 작업 성공을 주장하지 않는다.
