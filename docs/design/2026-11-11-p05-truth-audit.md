  2. SLAM 이 꺼졌을 때 제어 자세·속도를 참값에서 가져오는 경로는 실차 진입점에서 아예 조립하지 않는다.
  3. 실차에서 SLAM 이 꺼지면 무엇으로 대신할지는 후보만 적고, 총괄이 정한다(3절).

  - **CONTROL**: 실행 중 제어·허가·정지 결정이나 추정기에 들어간다. 실차는 측정으로 바꿔야 한다.
  - **FALLBACK**: SLAM 이 꺼졌을 때만 참값을 쓴다. 실차는 이 경로를 조립하지 않는다.
  - **HUMAN**: 미션 전환·판정이다. 실차는 측정이나 운용자 확인이 필요하다.

- 분류는 **호출 지점과 분기 조건 단위**로 한다. 같은 훅이라도 호출이 무조건이고 결과만 조건부로 쓰이면, 실차에서는 호출 자체를 막아야 한다(Codex P2-2).

## 1. 가장 중요한 발견

1. **`truth_speed` 는 SLAM 이 켜져도 참값이다** (rt 10587 `np.dot(velocity[:2], forward)`, velocity = `robot.get_linear_velocity()`). 이것이 SLAM 모드에서도 제어에 들어간다:
   - 장애물 층 허가의 정지 상한 `cap_mps = max(|요청|, |truth_speed|)` (core 1455)
   - 서 있을 때 정지 호의 방향 `1 if truth_speed > 0 else -1` (core 1446)
   - 포켓 검사 상한 (core 1537)
   - 센서 침묵 정지 판정 (core 1590–1598)
   - 일시정지·계획 대기·적재 대기 중 허가 감시 (core 5489·5508, 방향 규칙이 무조건)
   - 저상 감시 상한 (core 6070–6080)
   - 허가 틱을 돌릴지 정하는 문 (rt 10593–10596)
   - 실시간 계획 대기 중 움직임 종료 (rt 10237 → core 7939)

   실차는 이 자리를 측정으로 바꾸되, **세 가지 속도를 나눠야 한다**(Codex P2-1, agy ③).
   - **추종 속도**(추종기 입력): 지금 `StopDetector.tracker_speed()`. 창 평균에 추종기용 크기·부호 보정을 적용한 값이라 실제 운동의 상한이나 방향을 보장하지 않는다(합성 입력에서 최근 0.6 m/s → 0.05 m/s, +0.01 → −0.012 재현). **안전용으로 쓰지 않는다.**
   - **정지 확인**: 정지했는지의 판정(정지 판정기).
   - **안전용 속도 상한**(정지 상한 `cap_mps`·방향):
     - 측정 나이, 측정 오차, 지연 동안 가능한 가속, 미끄럼 조건을 넣은 상한이어야 한다.
     - MCU 바퀴 속도와 바퀴 오도메트리는 같은 엔코더가 원천이라, 둘의 최댓값으로 미끄럼을 메우지 못한다. 미끄럼은 IMU(D435i)·명령 대비 측정 불일치로 따로 본다.
     - 정지 근처에서 부호가 떨리면 방향이 매 틱 뒤집힌다. 방향이 불확실하면 **양방향을 다 검사하거나 정지**한다.
     - 4d 에서 이 상한의 식과 입력을 정하고, 실측(S5·S8)으로 값을 정한다.
2. **캡처가 참 자세의 정지 여부로 받아들여진다** (rt 4613–4624, perception_adapter 442–458 `pose_changed`). SLAM 에서도 그렇고, 캡처 자세의 z 는 SLAM 에서도 참값이다(core 5326–5330).
3. **원거리 인식의 기본 제안기는 Isaac instance segmentation 이다**(oracle). `--recognition-proposals learned` 에서도 주행 프레임은 semantic 이 준비돼야 한다(far_recognition_runtime 294). 이것은 4c·4e-2 몫과 겹친다.
4. **LiDAR 자기·적재물 가림은 prim 경로 이름표로 거른다**(`own_prefixes`, rt 7663–7666·8126–8130). 실차는 기하 가림 마스크가 필요하다(4c-1 `PlanarScan` 의 OWN 과 S7).
5. **live 하역 판정은 기록이 아니다.** done/failed 를 정하고, done 이면 대상 목록을 검증한다(live_runtime 515–531). live `scene_require` 도 `cargo.invalidate` 를 부르고 미션을 끝낸다(rt 9626–9634). 실차에서 '판정 불가' 로 바꾸면 이 상태 변화가 다른 곳(운용자)에서 와야 한다.
6. **도킹 기준 스캔을 참 목적지에서 합성한다**(rt 8786–8839·9472). 실차는 측량한 기준 스캔이 필요하다.
7. `hooks.world` 는 시계(`current_time`)로만, `hooks.stage` 는 경로 그리기로만 쓴다. 시계는 SLAM 제어 자세와 격자 갱신에도 들어가므로(core 7433 등) CLOCK 으로 분류한다. 실차 진입점에는 차량 단조 시계가 필요하다.
8. **EVAL 의 장면 손상 판정은 시뮬에서 사실상 안전 감시였다**(agy ③): 기울기·미끄럼·금지 접촉·겹침을 참값으로 걸러 세션을 끝냈다. 실차에는 이 감시가 없다. 대체 후보는 이렇다: IMU 기울기 한계, 모터 전류 급증(접촉), 명령 대비 바퀴·IMU 불일치(미끄럼), 카메라 적재 확인. 4e-2 에서 정하는 후속 결정 항목이다. 정하기 전에는 실차 단계를 사람 감시·저속·빈 포크로 제한한다(계획 5절의 승강 높이 한계 유보와 같은 조건).
9. **SLAM 은 꺼지는 것보다 '조용히 틀리는' 것이 위험하다**(agy ③). 지금은 참값 `slam_error` 로 보지만 실차에는 없다. 일관성 감시 후보는 이렇다: 스캔 정합 점수, SLAM 보정의 도약(odom 대비), 재위치 확인(`pose_check`·시작 재위치 장치). 3절 A 의 정지 조건에 '무효' 판정으로 넣는다.

## 3. 실차에서 SLAM 이 꺼지거나 무효가 될 때 — 후보(총괄 결정 대상)

**SLAM 부재와 운행 중 무효화를 구별한다**(Codex P2-5).
- 부재: `slam is None`. 처음부터 없거나 프로세스가 끝났다.
- 운행 중 무효화: 응답 나이 초과, 위치 무효(정합 점수·도약 감시, 1절 9), 연속성 상실.
- 어느 쪽이든 정지하고, 대기 중 작업(계획·명령)을 버린다. **복구되어도 이전 미션을 자동으로 재개하지 않는다**(운용자가 재개).

| 후보 | 내용 | 필요한 것 | 단점 |
|---|---|---|---|
| A. 정지만 | 부재·무효면 AUTO·미션을 막고 정지. 텔레옵도 막는다 | 무효 판정 기준 | 위치 추정 문제로 차를 옮길 수 없음 |
| B. 정지 + 저속 텔레옵 | A 에 더해 엔코더 + 자이로 dead-reckoning 으로 저속 텔레옵만 연다 | 신선한 장애물 입력, 오도메트리와 격자의 일관된 프레임, 드리프트 한계, 적재 상태에 맞는 footprint | 오도메트리 표류 |
| C. 제동 중 추정 | 무효가 되면 **즉시 제동을 시작**하고, 정지할 때까지만 dead-reckoning 으로 경로를 따라간 뒤 A 로. 제동 시작을 늦추는 유예가 아니다 | 정지까지의 시간·거리·자세 오차 예산(S5·S8 실측) | 예산을 실측 전에 정할 수 없음 |

- 권고: **A 로 시작하고, B 는 실측 뒤 추가한다.** C 는 S5·S8 실측으로 예산을 정한 뒤 판단한다.
- 어느 쪽이든 '참값으로 대신' 은 없다. FALLBACK 경로는 조립하지 않는다.

### 3a. 총괄 결정(2026-11-11)

1. **자율(AUTO·미션)은 A 다.** SLAM 이 없거나 운행 중 무효가 되면 바로 제동해 정지하고, AUTO 와 미션을 막는다.
   - 복구 뒤에도 자동 재개는 없고, 운용자가 다시 시작한다.
   - 제동에는 자세가 필요 없으므로 C 의 '정지까지 경로 추정' 은 넣지 않는다.
   - 무효 판정은 응답 나이·정합 점수·보정 도약·연속성으로 한다. 문턱값은 4e-2 에서 잠정값을 두고 S8 실측으로 확정한다.
2. **텔레옵은 SLAM 과 상관없이 연다.**
   - 저속 상한을 걸고, 그 상한은 **엔코더로 잰 속도**로 판정한다. dead-reckoning 자세는 쓰지 않는다.
   - 이유: 실차 단계 S6(원격 조종)은 SLAM 을 올리기 전에 하고, F1 차량 측 차단(#360)도 AUTO 를 막을 때 텔레옵은 열어 두는 구조다.
   - 조건: MCU 명령 기한 만료 정지와 MCU 비상정지 입력이 살아 있을 것, 사람이 눈으로 보고 있을 것.
   - 저속 상한값은 `config/real/vehicle.yaml` 에 잠정값으로 두고 S5 정지 거리 실측으로 확정한다.
3. **안전용 속도는 측정값(엔코더)만 쓴다.** `truth_speed` 와 `tracker_speed` 는 안전 판정에 쓰지 않는다. 4d 는 추종용·정지 확인용·안전 상한용 속도를 나눈다.
4. **장면 손상 판정을 대신할 실차 감시**(IMU 기울기, 모터 전류, 명령 대비 바퀴·IMU 불일치, 카메라 적재 확인)는 후속 결정 항목이다. 4e-2 에서 후보와 권고를 올린다. 그때까지 실차 단계는 사람 감시·저속·빈 포크로 둔다(계획 5절).

## 4. fail-closed 장치(4d 에서 만듦, 제안)

- 실차 진입점의 훅 객체는 감사표의 CONTROL·FALLBACK·HUMAN·EVAL 이름을 안다.
  - EVAL 훅은 `None` 을 돌려준다(판정 불가). 그 값을 받는 소비자는 '판정 불가' 를 기록하도록 고친다.
  - CONTROL 훅은 측정 구현으로 바꾼다.
  - HUMAN 훅은 운용자 확인 대기로 바꾼다.
  - FALLBACK 경로는 SLAM 필수 검사로 막는다.
- 표에 없는 참값 이름을 부르면 **전용 위반 예외**(`TruthAccessViolation`)를 낸다(Codex P2-4).
  - 지금 러너는 일반 `RuntimeError` 를 미션 실패로 처리하고 세션을 이어갈 수 있다(rt 11121 근처). `AttributeError` 는 `getattr(..., default)` 에 흡수될 수 있다. 그래서 위반 예외는 그 경로들이 잡지 않게 따로 두고, 세션 종료까지 전달한다.
  - 종료 경로에서 다음을 차례로 한다: 제어 세대 무효화, 대기 DRIVE 폐기, DISARM. 이미 송신된 명령은 만료까지 outstanding 으로 둔다(4a' D4).
  - 조용히 대체값을 쓰지 않는다.
- 합격 시험(계획 2.3, 범위 넓힘 — agy ③):
  - 가짜 실차 포트(참값 없음)로 정상 미션 하나가 끝까지 간다.
  - 예외 경로도 돌린다: 센서 침묵 정지, cusp 정지, 복구(수동), 일시정지·재개, 저상 감시, 계획 대기.
  - EVAL 호출은 '판정 불가' 로 남는다.
  - 표 밖 호출이 세션을 끝내고, **그 뒤 새 비영 명령이 나가지 않는다**.
- Isaac 동치: Isaac 기본 경로는 지금 값·호출 위치·횟수·순서를 그대로 둔다. 새 시계 읽기나 setup 서비스는 더하지 않는다. capture·step 내부는 게이트 사각지대라 직접 비교 시험을 함께 둔다(Codex 확인).

### 4-1. 4d-1 에서 만든 것 (안전 속도와 방향)

- 안전 판단은 `SafetySpeed`(부호 있는 값·상한·가능 방향·유효)를 읽는다. 시뮬은 참값 속도 그대로(`SafetySpeed.exact`), 실차는 엔코더 구현(4e-2). SLAM 꺼짐 분기의 참값 읽기는 실차에서 `TruthAccessViolation`.
- 실차만의 규칙 (Isaac 은 방향 하나·호출 1회 그대로, Codex 84경우 동치 확인):
  - 무효 측정 → 바퀴 묶음(`safety_speed_invalid`). 장애물 스위치·구간 활성 여부와 무관.
  - 주행 검사 = 요청 방향(없으면 측정 가능 방향 전부). 제동 검사 = 측정 가능 방향 중 나머지, 속도 상한으로만. 제동 검사가 상한을 허용하지 않으면 정지하고, 이것도 활성 여부와 무관한 hold.
  - 포켓 구간은 방향이 둘이거나 반대쪽 잔류 운동(상한 > 0)이 있으면 정지(`direction_unsure`) — 포켓 검사는 한 방향만 답하고 그 영역은 층에서 면제되기 때문.
  - 저상 감시는 무효이거나 방향이 둘이고 서 있지 않으면 그 틱 상한 0.
- **4e-2 엔코더 구현에 거는 조건**: 정지가 확인되면 상한 0 을 내야 한다. 정지에서도 상한이 0 보다 크고 방향이 둘이면 포켓 구간이 계속 정지하고 5 초 규칙으로 미션이 끝난다.

## 4a. 이 감사가 기대는 다른 전제(agy ③, 해당 단계에서 다룸)

- **LiDAR 가림 마스크는 적재물·승강 상태에 따라 달라진다.** S7 에서 빈 포크·적재 각 상태로 재고, 상태별 마스크를 쓴다(4c-1 `own_mask_source`).
- **측량 기준 스캔은 환경·하중 침하로 달라질 수 있다.** 도킹 정합 점수의 하한과 실패 시 정지를 4e-2 에서 정한다.
- **실차 시계에는 지터가 있다.** 센서 침묵 판정·정지 예측의 시간 규칙은 계획 2.5 를 따르고, 지연 주입 시험(P0-9)으로 본다.
