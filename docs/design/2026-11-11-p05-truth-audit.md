- 상위 계획: [`docs/plans/2026-11-11-sim-to-real-bringup.md`](../plans/2026-11-11-sim-to-real-bringup.md) 2.3(참값 훅 처리, fail-closed), P0-5.
- 함께 가는 단계: P0-4 4d(참값 분리). 4d 는 이 표를 근거로 Isaac 경로 동작을 바꾸지 않고 참값 읽기를 분리한다(재생 게이트 29/29).
- 총괄 조건(2026-11-11):
  1. 실차 경로에서 참값 훅은 fail-closed 다.
  2. SLAM 이 꺼졌을 때 제어 자세·속도를 참값에서 가져오는 경로는 실차 진입점에서 아예 조립하지 않는다.
  3. 실차에서 SLAM 이 꺼지면 무엇으로 대신할지는 후보만 적고, 총괄이 정한다(3절).
- 줄 번호는 origin/main 297e68d8 기준이다(`core` = `src/forklift_core/mission/core.py`, `rt` = `sim/isaac/run_transport.py`).
- 분류:
  - **CONTROL**: 실행 중 제어·허가·정지 결정이나 추정기에 들어간다. 실차는 측정으로 바꿔야 한다.
  - **FALLBACK**: SLAM 이 꺼졌을 때만 참값을 쓴다. 실차는 이 경로를 조립하지 않는다.
  - **HUMAN**: 미션 전환·판정이다. 실차는 측정이나 운용자 확인이 필요하다.
  - **EVAL**: 평가·장면 손상 판정·기록·진단이다. 실차는 부르지 않고 '판정 불가' 로 기록한다.

## 1. 가장 중요한 발견

1. **`truth_speed` 는 SLAM 이 켜져도 참값이다** (rt 10587 `np.dot(velocity[:2], forward)`, velocity = `robot.get_linear_velocity()`). 이것이 SLAM 모드에서도 제어에 들어간다:
   - 장애물 층 허가의 정지 상한 `cap_mps = max(|요청|, |truth_speed|)` (core 1455)
   - 서 있을 때 정지 호의 방향 `1 if truth_speed > 0 else -1` (core 1446)
   - 포켓 검사 상한 (core 1537)
   - 센서 침묵 정지 판정 (core 1590–1598)
   - 일시정지·계획 대기·적재 대기 중 허가 감시 (core 5489·5508, 방향 규칙이 무조건)
   - 저상 감시 상한 (core 6070–6080)
   - 허가 틱을 돌릴지 정하는 문 (rt 10593–10596)
   - 실시간 계획 대기 중 움직임 종료 (rt 10237 → core 7939)

   실차는 이 자리를 측정 속도로 바꿔야 한다. 후보는 오도메트리 속도(`slam["tracker_speed"]`·`odom_speed`)와 MCU STATE 의 바퀴 속도이고, 어느 쪽을 쓸지와 그 지연·잡음이 정지 상한에 주는 영향은 4d 설계에서 정한다.
2. **캡처가 참 자세의 정지 여부로 받아들여진다** (rt 4613–4624, perception_adapter 442–458 `pose_changed`). SLAM 에서도 그렇고, 캡처 자세의 z 는 SLAM 에서도 참값이다(core 5326–5330).
3. **원거리 인식의 기본 제안기는 Isaac instance segmentation 이다**(oracle). `--recognition-proposals learned` 에서도 주행 프레임은 semantic 이 준비돼야 한다(far_recognition_runtime 294). 이것은 4c·4e-2 몫과 겹친다.
4. **LiDAR 자기·적재물 가림은 prim 경로 이름표로 거른다**(`own_prefixes`, rt 7663–7666·8126–8130). 실차는 기하 가림 마스크가 필요하다(4c-1 `PlanarScan` 의 OWN 과 S7).
5. **live 하역 판정은 기록이 아니다.** done/failed 를 정하고, done 이면 대상 목록을 검증한다(live_runtime 515–531). live `scene_require` 도 `cargo.invalidate` 를 부르고 미션을 끝낸다(rt 9626–9634). 실차에서 '판정 불가' 로 바꾸면 이 상태 변화가 다른 곳(운용자)에서 와야 한다.
6. **도킹 기준 스캔을 참 목적지에서 합성한다**(rt 8786–8839·9472). 실차는 측량한 기준 스캔이 필요하다.
7. `hooks.world` 는 시계(`current_time`)로만, `hooks.stage` 는 경로 그리기로만 쓴다. 자세 참값은 아니지만, 실차 진입점에는 `world.current_time` 대신 차량 시계가 필요하다.

## 2. 분류표 (요약; 전체 줄 목록은 부록)

## 3. 실차에서 SLAM 이 꺼질 때 — 후보(총괄 결정 대상)

| 후보 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 정지만 | SLAM 이 꺼지거나 위치가 무효면 AUTO·미션을 막고 정지. 텔레옵도 막는다 | 가장 단순·보수적 | 위치 추정 문제로 차를 옮길 수 없음 |
| B. 정지 + 저속 텔레옵 | A 에 더해, 엔코더 + 자이로 dead-reckoning 으로 저속 텔레옵만 연다(장애물 층 허가는 그 오도메트리 자세로) | 운용자가 차를 빼낼 수 있음 | 오도메트리 표류. 허가 격자가 그 자세에 의존 |
| C. 짧은 유예 | SLAM 응답이 짧게(예: 수 초) 끊기면 dead-reckoning 으로 지금 경로를 감속 정지까지만 따라간 뒤 A 로 | 잠깐 끊김에 급정지하지 않음 | 유예 길이와 표류 한계를 실측으로 정해야 함 |

- 권고: **A 로 시작하고 B 를 실측 뒤 추가**한다. C 는 S8 의 오도메트리 표류 실측 뒤 판단한다.
- 어느 쪽이든 '참값으로 대신' 은 없다. FALLBACK 경로는 조립하지 않는다.

## 4. fail-closed 장치(4d 에서 만듦, 제안)

- 실차 진입점의 훅 객체는 감사표의 CONTROL·FALLBACK·HUMAN·EVAL 이름을 안다.
  - EVAL 훅은 `None` 을 돌려준다(판정 불가). 그 값을 받는 소비자는 '판정 불가' 를 기록하도록 고친다.
  - CONTROL 훅은 측정 구현으로 바꾼다.
  - HUMAN 훅은 운용자 확인 대기로 바꾼다.
  - FALLBACK 경로는 SLAM 필수 검사로 막는다.
- 표에 없는 참값 이름을 부르면 예외로 세션을 끝낸다. 조용히 대체값을 쓰지 않는다.
- 합격 시험(계획 2.3): 가짜 실차 포트(참값 없음)로 정상 미션 하나가 끝까지 가는지, EVAL 호출이 '판정 불가' 로 남는지, 표 밖 호출이 세션을 끝내는지 본다.
