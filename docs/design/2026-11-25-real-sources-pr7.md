# PR 7 — 실 원천(스캔·IMU·SLAM·깊이)을 실차 실행에 넣기

6판 2026-11-25. 상위 계획: `docs/plans/2026-11-18-real-autonomy-entry.md` 7 행. 조립 모양: `docs/design/2026-11-20-real-hil-6a.md` 10 절(`RunSources` 를 바꿔 끼우기만 하면 되는 조립 하나). 계약 출처: `docs/design/2026-11-19-real-safety-wiring.md`(5a–5d, 8.1), `docs/design/2026-11-19-real-assembly.md` 207(시각은 한 축), `docs/design/2026-11-12-real-scan-obstacle-layer.md`(A2M12 시각 조사), `docs/design/2026-11-14-imu-record-and-mount.md`(D435i IMU).

1판에서 바뀐 것(9 절 자체 검토): 실 보드에서 판정까지 돌리는 '그림자 실행'을 버렸다. 대신 송신을 DISARM 으로만 묶은 **관측 실행**과, 그 기록을 HIL 에 다시 넣는 **재생 실행**으로 나눴다. 운영 REAL 조립 거부는 PR 7 내내 유지한다.

## 0. 무엇을 하고 무엇을 하지 않는가

- **한다**:
  - 실 원천 네 가지를 만든다. A2M12 스캔, D435i 가속, 실차 SLAM, D435i 깊이다. 각각 `RunSources` 의 원천 계약(6a 10 절, 5b·5c-2·5d)을 지키게 한다.
  - 실 보드·실 센서로 원천만 돌려 기록하는 **관측 실행**을 둔다.
  - 그 기록을 HIL(이 프로세스가 만든 pty 모형)에 넣어 판정 경로를 끝까지 도는 **재생 실행**을 둔다.
- **하지 않는다**:
  - 실 MCU 의 운동과 운영 REAL 조립은 열지 않는다. `assembly_refusal` 의 `client_real:pr7_preconditions` 는 그대로다. 운영 조립을 여는 것은 S10 선행 조건과 그때의 결정이다.
  - 실 보드 호스트에 가상 ARM 확인을 넣어 판정을 돌리지 않는다. 그러면 실 보드의 송신 경계가 무너진다(Codex 1 회차 P2-1).

## 1. 두 실행

### 1.1 관측 실행 — `tools/real_observe.py`(새 도구)

목적은 실 하드웨어에서 원천이 계약대로 나오는지 보고, 재생할 기록을 만드는 것이다.

- **보드**: `ReconnectingLink(exclusive=True)` 로 연다(8.1). 잡혀 있으면 쓰기 0·종료 2 다. 이 도구의 송신자는 하나뿐이다.
- **송신 경계**(Codex 1 회차 P1-1, 2 회차 P1): 바이트를 쓰는 곳은 `TtyLink.pump_writes` 하나다. `ReconnectingLink.service()`·`transmit()` 모두 그것을 부른다. 관측 실행은 `TtyLink` 의 관측 전용 하위 클래스(`ObserveTtyLink`)를 쓴다. `ReconnectingLink` 에 링크 생성 함수 인자를 더해 **첫 열기와 모든 재열기**에 같은 클래스가 설치되게 한다.
  - `ObserveTtyLink.pump_writes` 는 호스트에서 꺼낸 프레임을 첫 바이트 전에 검사한다. `kind == "DISARM"` 이고 `data` 가 그 seq 의 정규 인코딩(`encode(Disarm(), seq)`)과 바이트 단위로 같을 때만 쓴다. 그 밖은 쓰지 않고 버리고 센다(호스트에는 쓰지 못한 프레임으로 알림).
  - 독 바이트열(8.1)은 허용된 첫 DISARM 바로 앞에만 나간다. 그래서 열린 fd 에 나갈 수 있는 바이트는 '규정 독 바이트열 + 정규 DISARM' 의 반복뿐이다.
  - 관측 실행에는 미션 코어·아비터·허가 상태기가 없다. ARM 을 요청하는 경로 자체가 없지만, 경계는 그것에 기대지 않는다.
  - **합격 시험**은 경계를 빼면 실패해야 한다. pty 에서 호스트 큐에 금지 프레임만 넣는 경우, 금지·DISARM 이 섞인 경우, 독 바이트열·DISARM 을 쓰다 `EAGAIN` 이 나는 경우, 재연결을 거친 경우를 만든다. 그리고 **수신 원시 바이트**를 '독 바이트열 + 정규 DISARM' 의 반복과 대조한다. 완성된 금지 프레임 수만 세면 금지 프레임 앞부분이 새는 경우를 놓친다. 첫 열기가 잠금 거부면 독 바이트열까지 0 바이트다.
  - 기대값은 정상으로 끝난 **fd 하나당** `POISON + DISARM₁ + DISARM₂ + …` 다. 중간에 끊긴 fd 는 그 열기에서 허용된 바이트열의 접두사까지 대조하고, 새 fd 는 독 바이트열부터 다시 시작한다(Codex 3 회차 P3).
  - 도구가 차의 관성이나 사람이 옮긴 변위까지 막지는 않는다.
- **STATE 지연 상한**(Codex 2 회차 P2-1): 스캔 배치와 7c 의 odom TF 는 STATE 의 시각 상한(`DelayBound`)이 있어야 쓸 수 있다. 그 상한은 이 세션이 보낸 DISARM 두 개의 seq 전이로 서고 2 s 뒤 만료된다. 그래서 관측 실행은 다음을 한다.
  - 시작 때 세션 확인 쌍(DISARM 두 개)을 보낸다.
  - 그 뒤 1 s 마다 DISARM 을 보낸다. 기존 OFF 경로의 갱신 주기와 같다.
  - 재연결·재부팅 뒤에는 확인 쌍을 다시 보낸다.
  - 종료 때 DISARM 을 보내 확인한다.
- **읽는 것**: STATE(오도메트리·모드), 각 실 원천의 출력과 진단(세대, 버림 수, 시계 맞춤 잔차, 수신 지연)을 그대로 기록한다.
- **기록의 완전성**(Codex 3 회차 P2-6): 6a 의 기록 규칙(`record_incomplete`, 종료 행, 쓰기 완료 확인)을 관측 기록에도 둔다. 기록기 큐 넘침, 중간 절단, 쓰기 실패, 원시 프레임 본문 누락이 있으면 그 기록은 재생 판정에 쓸 수 없다. 깊이 배열은 JSON 이 아니라 원시 픽셀 그대로 옆 파일(npz)에 둔다. 지금 `RunRecord` 는 NumPy 배열을 `repr` 로 써서 복원할 수 없다. 7e 에는 기록 전후 깊이 픽셀·단위·보정 식별자가 같은지 보는 왕복 시험을 둔다.
- **층**: 오도메트리 좌표의 **진단용 층**만 계산해 기록한다. 지도 좌표가 아니고, 보정 세대 0 이 지도 자세의 증거도 아니다(Codex P2-2). 계획에 넘기지 않는다.
- **시험 방식**(Codex P3, agy 1):
  - 차를 **손으로 밀어** 움직이는 시험은 엔코더 이력이 유효한 구간에서 스캔 배치를 본다.
  - **들어 옮기는** 시험은 바퀴 계수가 그대로라서, 재위치가 다시 필요해지는 음성 사례로만 쓴다.
  - 텔레옵과 동시에 쓸 수 없다. 실행기 잠금 때문이다. 텔레옵 중 원천을 보려면 텔레옵 기록에 원천을 더하는 일이 따로 필요하고, 이 PR 밖이다.
  - 사람이 LiDAR 평면에 찍히는 것은 기록으로 남긴다. 판정에 쓰지 않는다.

### 1.2 재생 실행 — HIL 위의 실 원천 기록

판정 경로(추종, S10 정지, D5, 관문 기한)는 운동이 허가된 루프에서만 돈다. 그래서 관측 실행의 기록을 HIL 실행의 원천으로 넣는다.

- **경로**: 지금 `--run --hil` 처럼 이 프로세스가 만든 pty 모형만 지원한다. 출력 잠금 실보드로 재생하는 것은 6b 의 전송 계약에 묶고 이 PR 밖이다(Codex 2 회차 P2-2).
- **HIL 확인**: 재생 원천은 `Client.HIL` 이고 기록 머리에 `replayed_from` 을 단다. 6a 원천 규칙 그대로, 생성 때와 **매 호출**마다 전송기의 HIL 확인과 현재 부팅을 본다. HIL 확인을 잃거나 부팅이 바뀌면 대기 중인 응답과 캐시된 깊이 프레임까지 버린다. 기록의 STATE 는 시각 대응 자료로만 쓴다. HIL 비트·부팅·명령 확인은 연결된 모형의 STATE 에서만 받는다.
- **무엇을 재생하나**(Codex 2 회차 P2-5): 원시 입력만 재생한다. 스캔, IMU 표본, 깊이 프레임, 그리고 각각의 세대·취득 구간이다.
  - **SLAM 응답은 재생하지 않는다.** 재생한 스캔을 지금 HIL 실행의 SLAM(7c 의 실 SLAM 원천, slam_toolbox 위치 추정)에 넣는다. 그 SLAM 이 지금 실행의 `seed`·`request_processed` 에 답한다. 기록된 응답에 지금 회차·시도를 붙이면 seed 전 스캔이 확인 증거가 될 수 있기 때문이다.
  - 깊이 프레임의 D5 등록 조건(`mission_gen`·`phase`·`correction`)은 그 프레임 취득 구간 전체의 HIL 이력과 맞아야 한다. 읽는 순간의 값으로 채우지 않는다.
- **지도와 시작**(Codex 2 회차 P2-3): 지금 HIL 조립은 `hil:` 장면을 요구하고, 시작 자세가 0 이 아니면 거부하고, 항등 `processed` 를 먼저 넣는다. 재생 실행은 이것과 따로 초기화한다.
  - 기록이 만들어진 조사 지도 번들을 읽는다.
  - 시작 자세는 기록의 시작 자세를 그대로 쓴다.
  - 항등 보정 없이, 재위치(5c-2)로 시작한다.
  - 합격 사례: x·y·yaw 가 0 이 아닌 조사 시작점에서 실제 재위치 증거가 들어와야 F1 이 열린다.
- **시각 옮기기**(Codex 2 회차 P2-4): 기록과 HIL 의 첫 유효 STATE 의 **호스트 수신 ns 차이** Δ 를 구한다. 그 Δ 를 모든 시각에 똑같이 더한다. 각 표본의 `lo`·`hi`, 소비자에게 처음 도착한 시각, 끊김·복구 사건이다. 코어 초는 그 뒤 HIL 의 `start_ns` 를 빼서 만든다.
  - 원 ROS stamp 와 장치·MCU 카운터는 그대로 둔다.
  - 표본은 옮긴 도착 시각보다 먼저 내지 않는다. 예: 첫 빔 뒤 300 ms 에 도착한 스캔은 재생에서도 300 ms 에 처음 보인다.
  - 세대 순서, 같은 틱 안의 끊김·복구, 진단 전용 표식을 보존한다.
- **한계**: 기록의 차 운동과 HIL 모형의 운동이 다르다. 그래서 재생은 원천 계약(시각·세대·형식)과 판정 경로의 **배관**을 본다. 실 원천 위의 운동 판정이 맞는지는 증명하지 않는다. 그것은 S10 의 몫이다.

## 3. 공통

### 3.1 시각 축과 취득 구간

모든 취득 시각은 호스트 단조 시계 ns 다(조립 설계 207). 원천은 표본마다 **취득 가능 구간** `[lo, hi]` 를 낸다. 쓰는 쪽은 신선도를 `now − lo`(가장 오래됐을 때)로, '정지·세대 경계 뒤' 를 `lo ≥ 경계`로 판정한다(Codex P1-3). 구간을 증명할 상한이 없으면 그 원천은 **진단값만** 낸다. 운영 원천 계약은 만족하지 못한 것으로 둔다.

- 시계 맞춤(`plant/clock_map.fit_clock`)의 잔차는 구간이 아니다. 전달 지연이 일정하면 잔차가 0 이어도 실제 시각은 그만큼 늦다(Codex 재계산: 120 ms 일정 지연에 잔차 0 ns). 그래서 구간의 아래쪽은 '호스트 수신 시각 − 전달 지연 상한'이고, 상한은 벤치 측정값이다(`measured: false` 인 동안 진단).
- 시계 점프: `ScanFeed` 는 이미 시스템 시각 점프를 `clock_jump` 로 거부한다. 시계 짝이 다시 설 때까지(스캔 10 장) 스캔이 없다. 이 시간은 시작·복구 직후 준비 시간에 든다(사실 대조 5). Jetson 의 RTC·NTP 스텝 설정은 벤치에서 기록한다(agy 6).

### 3.2 세대

원천마다 생산자 세대를 둔다. 세대와 표본 ID 를 프레임, 사건, 층 작업, 설치 결과까지 실어 보낸다(Codex P2-5). 소비자는 세대가 다른 것을 버린다.

- 세대가 바뀌는 경우: 수신 공백이 상한을 넘을 때, 소켓·장치 오류, 생산자 재시작(어댑터의 `scan_id` 가 줄어듦 — 지금 `ScanFeed` 는 최댓값을 유지해 못 알아챔), 시계 짝 재수립, D435i 파이프라인·센서 재시작, 장치 시각 되감기(32 비트 µs, 약 4,295 s).
- 지금 코드의 `scan_source_lost` 는 즉시 래치이고 소켓 오류는 `fatal_source` 다(사실 대조 4). 관측 실행은 이를 세대 전환으로 기록한다. 운영 루프의 래치 규칙은 바꾸지 않는다. 운영에서 끊김을 래치 대신 복구로 다룰지는 S10 때 따로 정한다.

### 3.3 읽기 비용과 반환 수

반환 수 상한과 읽기 비용 상한은 다르다(Codex P2-5).

- 지금 코드의 반환 상한은 스캔 4 장(`SCANS_PER_CALL`), SLAM 8 개, IMU 64 개다. 스캔·SLAM 은 넘치면 오래된 것부터 버리고 센다(사실 대조). IMU 는 버리지 않는다. 64 개에 닿으면 지금 루프처럼 `imu_backlog` 를 세운다. 건너뛴 기울기나 공백이 정상 판정으로 이어지지 않게 하기 위해서다(Codex 2 회차 P2-7).
- 실 어댑터는 소켓·큐를 비울 때까지 읽지 않는다. 한 틱에 읽는 양도 상한을 둔다. 밀린 양, 버린 수, 세대 변경을 각각 센다.
- 틱이 밀렸다가 돌아올 때의 회복은 50 Hz 틱이 10 Hz 스캔보다 빠르므로 따라잡는다. 이것을 부하 주입 시험으로 확인한다(agy 5).

## 4. 7a — 관측 실행과 실 스캔 원천

- **배관**: `ros2_dev.sh scan-a2m12`(sllidar_node → `real_scan_adapter` → Unix 데이터그램)를 쓴다.
- **취득 시각**: 고정 커밋 조사(2026-11-12 설계 1.1)에 따르면 노드의 `header.stamp` 는 `grabScanDataHq()` 호출 직전의 시각이다. 버퍼에 머문 스캔은 stamp 보다 더 일찍 취득됐을 수 있다. 그래서 stamp ± `scan_time` 은 취득 구간이 아니다(Codex P1-2).
  - 7a 는 그 설계가 남긴 결정을 내린다. 노드를 작게 고친 사본(커밋 고정)으로 SDK 의 `grabScanDataHqWithTimeStamp` 첫 표본 시각을 프레임에 싣는다. 그 값은 호스트 단조 시계 기준이다.
  - **7a-2 구현**(2026-11-25, Codex 7a-2 1 회차 반영): 고정 커밋 34300099 에 패치 하나(`deploy/ros2/sllidar_patches/0001-sdk-first-sample-stamp.patch`, `Dockerfile.scan` 이 `git apply`)를 댄다.
    - SDK 는 각 스캔 버퍼의 첫 표본 시각 옆에 **같은 버퍼의 마지막 표본 시각**을 둔다(`_scan_last_timestamp_uS`, `grabScanDataHqWithTimeStamps`). 끝 시각은 이전 회전의 길이에서 나오지 않는다(Codex P1-1).
    - 노드는 각 스캔을 원래 `scan` 토픽에 그대로 내고, 같은 스캔을 `scan_sdk`(런처가 `/sensors/lidar/scan_raw_sdk` 로 바꿈)에도 낸다. 이 토픽의 stamp 는 첫 표본의 `CLOCK_MONOTONIC` 값 그대로다. `scan_time` 은 같은 버퍼의 마지막 − 첫 표본이다. ROS 시계를 거치지 않으므로 두 시계를 읽는 사이의 선점이나 `use_sim_time` 이 끼지 않는다(Codex P1-2).
    - 두 시각이 없거나 순서가 틀리거나 0.5 s 를 넘는 스캔은 `scan_sdk` 에 내지 않는다.
    - `scan_sdk` 의 `frame_id` 에는 형식 이름 `@sdk_mono_v1` 이 붙는다. 어댑터는 이 이름이 있어야 받는다. 받은 뒤에는 떼어 센서 frame 으로 되돌린다(Codex 2 회차 P2-3: ROS 메시지에는 시계 종류가 실리지 않으므로 시각 범위만으로는 출처를 알 수 없다).
    - 벤치용 `publish_delay_ms` 파라미터(기본 0)는 **이미 읽은 스캔**을 발행 전에 그만큼 붙잡는다. 같은 스캔이 그만큼 늦게 도착하므로, 나이가 주입량만큼 늘었는지 바로 본다(2 회차 P2-1: 읽기 전 지연은 디코더가 버퍼를 최신 회전으로 바꿔 '스캔 누락'만 보인다).
    - **토픽이 stamp 의 뜻을 정하고, 어댑터가 그것을 확인한다.** `--source raw|sdk` 가 구독 토픽과 머리의 `stamp_kind` 를 함께 정한다. sdk 쪽 검사는 다섯 가지다: 형식 이름, 수신 이하의 단조 시각, 5 s 안, 한 회전 길이, 마지막 표본이 수신 이하. 하나라도 어긋나면 버리고 센다(`not_sdk`). 런처는 `FORKLIFT_SCAN_SOURCE` 를 `raw|sdk` 로만 받는다.
    - 호스트(`ScanFeed`)도 `stamp_kind` 가 `sdk_first_sample` 이 아닌 프레임에 취득 시각이 실려 있으면 `bad_meta` 로 거부한다. `scan_time` 은 float32 로 실려 오므로 µs 로 먼저 반올림해 끝 표본을 정확히 되살린다.
    - 프레임은 `first_beam_mono_ns`·`last_beam_mono_ns` 를 싣는다. `ScanFeed` 는 둘이 순서대로 다 있을 때만 넘긴다. 변환은 끝을 `last_beam_mono_ns` 에서 읽고, 회전 주기나 빔 간격에서 만들지 않는다.
    - 텔레옵 다리는 `call_start` 가 아닌 stamp 의 스캔을 버린다. 다리의 배치는 `stamp − 주기` 라서, 첫 표본 stamp 로는 한 회전 이르게 놓기 때문이다(Codex P2-4).
    - 받아들이는 폭 `lidar.yaml timing.scan_period_s` 는 0.12 s(잠정)다. 10 Hz 한 회전(약 98 ms)에 양 끝 오차를 더해도 들어가야 한다. 0.10 이면 명목 회전이 늘 `scan_too_long` 이다(Codex P2-1, 시험으로 고정). 실 실행의 층은 첫 빔 예산을 이 값에서 읽는다(배선은 7r).
    - 저장소 쪽 버퍼 지연 주입 시험(`tests/unit/sensors/test_sdk_first_sample.py`): 패치의 실제 발행식대로 만든 프레임을 쓴다. SDK 버퍼에서 0·120·300 ms 기다린 스캔에서 원래 토픽은 '취득 시각 없음'이다. 고친 토픽은 기다린 시간이 나이에 그대로 든다.
    - 실기 쪽은 벤치 시간표 1 이다.
  - 버퍼 지연 주입 시험(같은 설계 1.1 의 4)으로 늦은 스캔을 신선하다고 하지 않는지 검증한다. 그 전까지 스캔 시각은 진단값이다.
  - **첫 빔과 끝 빔의 범위를 나눈다**(Codex 2 회차 P2-6). 첫 빔은 `[Flo, Fhi]`, 끝 빔은 `[Elo, Ehi]` 다. 지금 층은 `last_s` 하나를 마감(`last_s + B`)과 '오도메트리 이력이 끝 빔 뒤까지 있는가' 두 곳에 쓴다. 보수적으로 마감은 `Elo + B`, 이력이 덮어야 할 끝은 `Ehi` 로 나눈다. 끝 범위를 증명할 수 없는 스캔은 진단 전용이다.
  - **층에 넣을 수 있는 스캔**(Codex 3 회차 P2-4, 4 회차 P2-1): 두 예산을 모두 지켜야 한다.
    - 자세 오차표: 지금 층은 모든 빔을 첫 빔의 대표 자세 하나에 놓고, 고정된 `dt = 2 × scan_period_s + state_delay_s`(지금 250 ms)로 위치·회전 오차를 셈한다.
    - 정지 모델: 지연 `latency_s + scan_period_s + B` 중 첫 빔부터 층 반영까지의 몫으로 `scan_period_s + B`(지금 200 ms)를 잡는다(`latency_s` 0.30 은 그 위에 더해짐). 그래서 끝 빔 기준 마감만 보면, 첫 빔에서 본 장애물의 반영이 늦는 것을 놓친다.
    - 그래서 `Ehi − Flo ≤ scan_period_s` 인 스캔만 층에 넣고, 나머지는 진단 전용이다. 더 긴 스캔을 허용하려면 그 상한을 정지 지연에 넣는 별도 설계가 필요하다.
    - 반례 시험 둘: 취득 폭이 긴 회전 스캔, 그리고 첫 빔 0 ms·끝 빔 150 ms·설치 230 ms 로 폭 250 ms 검사와 끝 빔 마감은 통과하지만 이 조건에 걸리는 스캔.
  - **스캔 정체는 갈라지기 전에 정하고 양쪽이 각자 지닌다**(Codex 2 회차 P2-6, 3 회차 P2-3; 7c 에서는 실행기 한 곳이 받아 SLAM 으로 넘기는 방식으로 바꿈 — 6.1 의 1): 지금 `scan_id` 는 어댑터가 ROS 를 구독한 뒤 매긴다. 그래서 SLAM 쪽이 한 장을 놓쳐도 대조가 안 된다. 어댑터를 분기점으로 삼는다. 어댑터가 `(생산자 세대, scan_id)` 를 매기고 같은 프레임을 **두 데이터그램 소켓**으로 보낸다. 하나는 층(관측·실행기), 하나는 SLAM 브리지다. 7c 의 브리지는 원시 ROS 토픽을 구독하지 않는다. 받은 데이터그램으로 slam_toolbox 에 `LaserScan` 을 자기가 발행하므로, 어느 `/pose` 가 어느 `(세대, ID)` 에 답했는지 안다. stamp 만으로 대응을 복원하지 않는다. 대응이 불명확한 응답은 보정 적용 전에 버린다. 시험은 세 경우다. 데이터그램(층)만 유실, SLAM 쪽만 유실, 이전 세대와 같은 stamp 재등장. 세 경우 모두 양쪽 ID 집합과 버린 사유가 맞아야 한다.
  - **같은 stamp 의 늦은 응답**(Codex 4 회차 P2-2): 실차 모드는 원 ROS stamp 를 쓴다. 그래서 세대 A 의 스캔과 세대 B 의 스캔이 같은 stamp 를 가지면, 늦게 온 A 의 `/pose` 를 B 의 응답으로 받을 수 있다. 브리지가 발행하는 stamp 는 세션 안에서 **엄격히 증가**해야 한다. 이전에 발행한 stamp 이하인 스캔은 발행하지 않고 버리고 센다. 시계가 거꾸로 가면 SLAM 응답이 끊기고, 기존 신선도 규칙이 출력을 닫는다. 시험 둘(Codex 5 회차 P3): A 와 같은 stamp 인 B 는 발행·대기 0 건이다. 더 큰 stamp 의 C 를 기다리는 동안 늦게 온 A 응답은 보정 적용·재위치 확인 0 건이다.
  - **두 경로의 수신 기록**(Codex 4 회차 P2-3; 6.1 의 1 에서 '공통 입력 한 번 + 분기 뒤 경로별 판정'으로 바뀜): 관측 기록에는 `(생산자 세대, scan_id)` 마다 원시 본문을 한 번 두고, 층 경로·SLAM 경로 각각의 수신 여부와 최초 도착 시각을 둔다. 재생은 그 기록대로 각 경로에 따로 Δ 를 적용해 보낸다. 기록 때 한쪽에만 온 스캔은 재생에서도 그쪽에만 간다. 합격 조건은 한쪽 유실과 두 경로의 지연 차이가 재생 뒤에도 같은 것이다. 원천의 실제 유실과 기록기 자신의 누락도 이것으로 구별한다.
- **변환 계약**: `scan_feed.RealScan` 을 `real_layer.RealScan` 으로 바꾼다.
  - 무효 빔: 드라이버는 거리 0 을 `+inf` 로 내고 `ScanFeed` 는 NaN 으로 바꾼다. 무효 빔은 FREE 를 만들지 않는다. HIL 합성 스캔의 '유효한 무반사(`+inf`)' 규칙을 실 스캔에 쓰지 않는다(Codex P2-6).
  - 장착·마스크·`limit_m`: 한 출처(실측 provenance 가 있는 설정 파일)에서 읽는다. 텔레옵 다리의 `--lidar-mount`·`--lidar-mask` 인자와 같은 값이 되도록, 다리도 그 파일을 읽게 바꾼다. 지금의 `obstacle_layer_real.yaml` 장착값 `[0,0,0]` 은 자리표시자라 운영에 쓸 수 없다.
  - 출처: 실 프레임·재생·합성을 구별하는 표식을 `RealScan` 까지 싣는다.
- **진단용 층 좌표**: 오도메트리 좌표다. 필드 경계(`s10a.bounds`)는 지도 좌표이고 `ObstacleGrid` 가 `map_from_odom` 을 적용하므로 시작 자세를 경계에 다시 더하지 않는다. 원점과 yaw 가 0 이 아닌 시작에서 벽과 경계가 같은 지도 칸에 놓이는 시험을 7c 에 둔다(Codex P2-2).
- **시험**: 기록 scan/1 재생(변환, 무효 빔, 세대, 버림 수), pty 모형 위 관측 실행(ARM·DRIVE 0 건, DISARM 확인), 버퍼 지연 주입(노드 사본이 생기면).

## 5. 7b — 실 IMU 원천

- D435i 는 한 프로세스만 연다. 기존 IMU 설계(2026-11-14 2 절)대로 **motion 센서 객체를 직접** 열고 옵션을 설정한다. 파이프라인으로 열면 설정이 빠질 수 있다(사실 대조 8). 7e 의 깊이는 같은 프로세스가 depth 센서 객체를 따로 연다. 둘 사이의 동기화기 대기는 없다. 깊이 처리가 밀려도 IMU 콜백이 기다리지 않게, 콜백은 표본을 큐에 넣기만 한다.
- `samples(upto_ns, limit)` 은 5b 계약에 생산자 세대와 취득 구간을 더한다(Codex 2 회차 P2-7, 4 회차 P2-4). 표본은 `(gen, lo, hi, accel)` 이다. `_ImuGuard` 와 루프의 배치 소비도 세대를 넘긴다. 감시기도 구간으로 판정한다.
  - 신선도: `now − lo`.
  - 공백: 다음 표본의 `hi` − 이전 표본의 `lo`. 예: `[0, 10]`, `[49, 59]` ms 는 `lo` 끼리 49 ms 지만 가능한 공백은 59 ms 라서 50 ms 한도를 넘는다.
  - READY 경계(Codex 3 회차 P2-5): 구간이 ARMING 쪽에 걸칠 수 있는 표본에는 ARMING 규칙(2° 즉시 정지)을 쓴다.
  - 기울기 지속: 연속 기울기의 가능한 최대 지속시간이 0.3 s 문턱에 닿으면 기울기로 본다. 최소·최대가 문턱을 사이에 두면 정상으로 통과시키지 않는다.
  - 세대가 바뀌면 이전 세대의 기준·지속시간을 새 표본과 잇지 않는다. 무장 중이면 시간 공백이 50 ms 미만이어도 `watch_imu_gap` 으로 고정된다. 무장 전이면 이전 기준을 버리고, 새 세대 표본만으로 기준이 다시 설 때까지 ARM 을 보류한다.
  - 세대 변경은 새 표본이 없어도 전달된다(Codex 5 회차 P2). 원천은 `generation()` 으로 지금 세대를 알리고, 루프는 송신 관문 판정 때 그것을 마지막으로 받은 표본의 세대와 비교한다. 빈 배치여도 세대가 바뀌었으면 위 규칙이 적용된다.
  - 시험: 같은 배치 안 5 ms 간격 두 표본 사이에 생산자만 재시작한 경우, 그리고 이전 표본이 아직 신선한 동안 원천이 재시작을 감지하고 새 표본은 0 건인 경우.
  - 전달 지연 상한이 측정되기 전에는 진단용으로만 낸다.
  - 이것은 5b 의 원천 계약과 `ImuWatch` 를 바꾼다. 합성 원천은 `lo == hi` 로 지금과 같게 동작한다.
- **축**: 5b 의 `level_ref` 는 수평 바닥에서 잰 **IMU 좌표**의 중력 방향이다. 그래서 가속도를 차체 축으로 돌리지 않고 IMU 좌표 그대로 비교한다(Codex P2-7). IMU 는 캐리지에 붙어 승강과 함께 움직이지만 회전은 같다(마스트 기울기 없음 전제, 벤치에서 승강 높이별 `level_ref` 를 한 번 잰다).
- 200 Hz 가속 프로파일이 모든 장치에 있지는 않다. 실제 프로파일을 열 때 읽어 기록하고, 감시의 공백 한도(`gap_max_s` 0.05)와 맞는지 본다.
- 세대: 센서 재시작, USB 재연결, 장치 시각 되감기(3.2).
- 시험: 기록 JSONL 재생(장치 시각·호스트 시각), 되감기, 세대, 취득 구간.
- **7b 구현**(2026-11-25, Codex 7b 1–6 회차 반영):
  - `ImuWatch.add_interval(gen, lo, hi, accel, now)` 와 `note_generation(gen)` 을 더했다. `add` 는 세대 없는 점 표본(`lo == hi`)이라 5b 판정이 그대로다(같은 입력의 판정 열이 같다는 시험). 표본이 같은지·미래인지는 `hi` 로 본다. 기준은 가장 새 표본부터 거꾸로 모으고, 정지 전에 시작했을 수 있는 표본(`lo` < 정지 시작)이나 공백(다음 `hi` − 이전 `lo`)을 만나면 멈춘다. 그 양쪽을 잇지 않는다. 기울기 지속은 서로 다른 기울기 표본이 둘 이상일 때만 성립한다.
  - 감시기가 내준 기준(`ImuBaseline`)은 마지막 표본의 `lo`·순번과 감시기의 세대 변경 횟수를 지닌다. `arm` 은 창에서 빠진 표본이어도 그 `lo` 부터 공백을 잰다. 기준을 받은 뒤 세대가 한 번이라도 바뀌었으면(번호가 되돌아왔어도) 곧바로 `watch_imu_gap` 이다. 기준은 만든 감시기를 이름으로 지니고, 다른 감시기의 기준이나 출처 없는 `(방향, 시각)` 은 세대 없는 원천에서만 받는다.
  - 루프 `_pull_imu` 는 `(stamp, accel)` 과 `(gen, lo, hi, accel)` 을 모두 받는다. 세대를 가진 원천은 점 표본도 `(gen, t, t, accel)` 로 보낸다(2-튜플이 섞이면 세대 변경으로 읽힘). 원천의 `generation()` 은 읽기가 상한에 닿지 않았을 때만 감시기에 알린다. 표본 읽기가 실패해도 묻는다. 세대를 물을 수 없으면(`imu_gen_unknown`) 상한에 닿은 읽기(`imu_backlog`)처럼 ARM 의 기준 고정과 이동 DRIVE 를 보류한다(`wait:imu_generation`). ARM 은 미션의 한 기한 안에서만 기다리고, 기한이 지난 뒤에 기준이 서도 거부한다(`imu_wait_expired`, 틱 시작이 아니라 기준을 고정하기 직전에 읽은 시각으로 판정). 원천이 자기 읽기 비용 상한에서 멈추면(`last_read_capped`: 판정과 무관하게 꺼낸 큐 항목 수) 그것도 상한에 닿은 읽기다. `_ImuGuard` 는 `generation()`·`last_read_capped` 도 같은 `SourceFatal` 규칙으로 감싼다.
  - 실 원천 `sensors/imu_source.ImuSource`(설정 `config/real/imu.yaml`). SDK 콜백은 큐의 잠금 안에서 수신 시각을 찍고 넣기만 한다(시각과 자리 사이에 경계가 끼지 않음). 구간은 `[수신 − 지연 상한, 수신]` 이다. 장치 시각은 연속성과 상한 검사에만 쓴다(시계 맞춤 잔차는 구간이 아니다, 3.1). 지연 상한이 측정되기 전(`delay_bound_s: null`)에는 `operating=True` 를 거부하고, 관측 실행만 잠정값(0.03 s)으로 구간을 기록한다.
  - 상한은 감시의 공백 한도와 맞아야 한다: 무장 중 공백은 다음 `hi` − 이전 `lo` = 수신 간격 + 상한이므로, 200 Hz 에서 상한이 45 ms 를 넘으면 기준이 서지 않는다(`fits_watch`, 시험 45/46 ms). 수신이 고르지 않으면 더 좁아진다.
  - **상한 검사**: 한 장치 시계의 모든 표본 쌍이 `|Δ(수신 − 장치 시각)| ≤ 상한 + 1 ms + 100 ppm × 장치 시각 차` 를 지켜야 한다(이웃 쌍만이 아니라 누적, 실행 최솟값·최댓값 둘로 유지, 정수 연산이라 호스트 가동 시간과 무관). 장치 시계는 수신 공백을 넘어 이어지고(넘침은 원천을 멈춤), 경계 때문에 세지 않은 표본도 이 검사에는 든다(공백 뒤에 쌓인 지연도 잡음). 어기면 상한이 깨진 것이다(3.1): 새 세대를 열고 그 뒤로는 어떤 표본도 내지 않는다(`bound_broken`, 기록에는 남김). 운영에서는 감시가 끊김으로 래치되거나 기준이 서지 않는다.
  - 세대: 가속 표본 없이 0.1 s(수신 공백)는 같은 장치 시계가 이어지는 세대다. 장치 시계가 바뀌는 사건 — `lost()`(장치 분리), 장치 시각이 20 ms 넘게 뒤로 감(재시작), 장치 시각 출처가 바뀜 — 과 큐 넘침(400 개)은 새 세대를 열고 원천을 멈춘다(`stopped`). 7b 는 장치를 다시 열지 않으므로 시계가 바뀐 뒤에 오는 것의 출처를 알 수 없고, 넘침은 버린 프레임의 중복·시계 증거를 함께 잃기 때문이다(그 프레임의 재전송이 새 표본으로 통과할 수 있음). 다시 쓰려면 실행을 새로 시작한다. 수신 공백·넘침·분리는 큐 안의 그 자리에 경계로 남아, 앞의 표본은 옛 세대·뒤의 표본은 새 세대가 된다. 수신 공백은 콜백 쪽의 한 수신 이력(단조 최댓값)에서 정한다(조용한 틱이 보든 다음 표본이 보든 같은 경계 하나). 붙은 경계는 하나로 합치되 그 세대 수는 지닌다(큐의 경계 수 ≤ 표본 수 + 1, 이유 문자열도 하나라 콜백의 잠금 시간이 유한, 공개한 세대 번호는 되돌지 않음). `generation()` 은 큐에 이미 들어온 경계를 바로 센다(앞에 기다리는 표본이 있어도 — 송신 관문이 한 틱 늦지 않게). 경계 뒤 표본은 `lo` ≥ 경계 시각이어야 새 세대에 든다(3.1, `before_boundary`). 경계 시각: 수신 공백은 마지막 수신 + 0.1 s, 넘침은 마지막으로 버린 표본의 수신, 분리는 보고 시각(합친 경계도 기록에는 그 사건 자신의 시각). 분리 보고가 표본 없이 여러 번 오면 경계 하나다. 합친 경계의 원인은 최종 사건, 둘 다 최종이면 큐에서 먼저 온 것이다. 32 비트 장치 시각이 한 바퀴 도는 것은 앞으로 한 걸음일 뿐 세대가 아니다. 구간이 호스트 시각에서 나오기 때문이다(3.2 의 '되감기' 를 이렇게 좁힘).
  - 버리고 세는 것: 수신 시각이 뒤로 감(`not_newer`, 장치 시각보다 먼저 봄), 같은 장치 시각(`dup`, 경계 때문에 세지 않은 첫 사본의 재전송 포함), 작은 뒷걸음(`late`), 장치 시각 없음, 경계 전일 수 있음, 자이로 표본. 장치 시각은 프레임 메타데이터(32 비트)에서 읽고, 없으면 시각 도메인이 `hardware_clock` 인 `get_timestamp()` 를 32 비트로 접지 않은 값 그대로 쓴다(접으면 한 바퀴 점프가 숨는다). 그 값이 32 비트 경계에서 한 번 접히는 것을 보면 그 뒤로는 두 값이 모두 32 비트 안일 때 32 비트 카운터처럼 걸음을 잰다(접힘 직전의 늦은 표본은 작은 뒷걸음, 32 비트 밖의 값은 원값 그대로라 한 바퀴 점프가 숨지 않음). 2026-11-17 Jetson(RSUSB 빌드) 기록은 메타데이터가 전혀 없었다(가속 24,060 개 모두 `dev_us` null).
  - 그 Jetson 기록(120 s, 정지)을 재생하면 상한 20·25·30 ms 에서 모든 가속 표본이 한 세대로 받아지고, 15 ms 이하에서는 상한이 깨진다. 이웃 수신 간격 최대 23.8 ms 였고, 무장 감시의 공백(다음 `hi` − 이전 `lo` > 50 ms)은 30 ms 에서 7 번, 20 ms 에서 0 번이다(시험으로 고정). 측정값이 아니라 정지 기록 한 번의 관찰이다(벤치 2 에서 다시 잼).
  - USB 재연결 뒤 센서를 다시 여는 일은 7b 에 없다. 끊기면 원천이 멈추고, 무장 중이면 감시가 래치되며 무장 전이면 기준이 서지 않는다. 재열거는 벤치 3′ 에서 본다.
  - 관측 실행 `--imu`: 가속 표본마다 원값(수신 ns, 장치 µs, `ts_ms`, 시각 도메인, xyz)과 쓴 장치 시각·판정·세대·구간을 한 행으로, 세대 변경을 `imu_gen` 행으로, 연 프로파일을 `imu_profile` 행으로 남긴다. 프로파일 행에는 실제로 열린 가속 주파수와 감시 공백 한도로 본 적합 여부(`fits_watch`)가 붙는다. 장치 찾기는 실행기 잠금 전에 하지만, 장치 시작(옵션 쓰기 포함)은 잠긴 보드 링크가 실제로 열린 뒤다(링크가 끝내 안 열리면 `imu_not_started`). `--seconds` 는 장치를 시작한 때부터 잰다. 첫 열기에 장치가 없다가 재시도에서 잠금에 막히면 첫 열기와 같이 거부(2, 기록 불완전)다. 장치가 없으면 아무것도 쓰지 않고 거부(2), 시작·프로파일 읽기 실패는 `imu_start_failed`·`imu_profile_failed`(끝 DISARM 은 확인), 표본 0 개는 `no_imu` 다. 장치를 멈춘 뒤 큐에 남은 표본을 끝까지 기록한다. 멈춤이 실패하거나 큐가 넘쳐 원값을 잃으면(`imu_overflow`, `no_imu`·`no_scans` 보다 먼저) 기록은 불완전이다(`.ok` 없음). 원천이 멈췄으면 끝 행과 요약에 그 원인(`imu.stopped`)을 낸다(관측 결과는 그대로, 다시 쓰려면 새 실행). 기록의 원값을 새 원천에 다시 넣으면 같은 행이 나온다(`replay`; 수신 공백은 기록의 `imu_gen` 행 자리와 끝 행의 마지막 세대 조회 시각에서 다시 정해지므로 마지막 표본 뒤의 공백까지 같은 순서로 재현되고, 분리와 큐 넘침은 원값이 아니라 재현 대상 밖). 모형 MCU 위 관측 기록으로 왕복을 시험한다.
  - 관측 실행의 `finish()` 는 끝 DISARM 을 곧바로 보낸다. 그 연결에서 STATE 를 보기 전에 보냈는데 처음 본 STATE 가 이미 그 seq 를 담고 있으면, 단계 변화로 확인할 수 없으므로 그 DISARM 이 다 쓰인 뒤 새 seq 로 한 번 더 보낸다(Codex 7b 1 회차 P1-4, 2 회차).

- **F1 세 경계**(5c-2 289): 아비터 요청, `Context.start_blocked`, AUTO 진입 단언. 지금 실차 `Context` 는 `start_blocked` 를 넘기지 않는다. 예외로 읽는 것은 `declared_epoch` 표식이 아니라, **세션의 마지막 seed** 와 같은 묶음의 **완료된 `declared` 결과**다(6.1 의 7 에서 정함 — 마지막 seed 의 선언이 완료됐으면 다른 세대에서도 막지 않음). 실패한 선언·출처 누락은 막는다. STOP·재무장·lease 교체가 예외를 새로 만들지 않는 시험을 둔다(Codex P2-3).
- 시험: 기록 bag(실스캔 + STATE) 재생으로 응답 계약·늦은 응답 거부·seed 전 스캔 버림·재위치 시작·F1 경계, 0 이 아닌 시작 자세의 층·경계 정렬.

### 6.1 7c+7d 구현 설계(2026-11-25, 7b 머지 뒤 — 11판, Codex 설계 10 회차 수렴 뒤 총괄 수정(`slam` 우회), 사실 대조·agy 반영 — 10 절 끝의 6.1 검토 기록)

위 목록과 4·8 절의 세 가지를 여기서 바꾼다(아래 1·3·5). 바꾼 이유를 각 항에 적고, 4·6·8 절의 해당 문장에 이 절을 가리키는 표시를 남긴다. seed 는 slam_toolbox 인스턴스를 다시 띄워 그 첫 스캔이 `map_start_pose` 를 소비하게 한다(4판). 3판의 `/initialpose` 는 2.8.5 에서 어느 스캔이 소비할지 보장되지 않아 버렸다(3 회차 P1-1). 2 회차가 지적한 재기동의 어려움(첫 스캔 묶기·자식 식별·고정 자세 비교)은 정지 요구, 프로세스 그룹 회수, 인스턴스마다 기존 L4 로 푼다.

**0. 시각 셋**(Codex 설계 1 회차 P1, 2 회차 P2-3)
- 응답은 시각을 셋 지니고, 쓰임을 섞지 않는다.
  - **ROS stamp**(정수 ns, 호스트 단조): 브리지와 slam_toolbox 안에서 TF·`/pose` 대응에만 쓴다. 코어로 넘기지 않는다.
  - **순서 시각** `stamp_s`(코어 상대 초, 첫 빔 추정 시각 − 실행 시작): 지금처럼 `SlamPoseTracker` 가 받는 값이다. 역순 검사(`out_of_order`)와 추적기의 나이 계산이 이것을 쓴다. 선언의 합성 응답도 같은 축이다.
  - **증거 구간** `[Flo, Fhi]`(코어 상대 초): 첫 빔 취득 구간이다.
- 거르기(`_filter_replies`)의 각 사유는 다음 시각으로 판정한다. 기존 사유의 순서는 그대로다(`epoch` → `before_epoch` → `future` → `out_of_order` → `repeated` → `skipped_first`).
  - `before_epoch`·확인 요청 경계(`a["t"]`)·출처(`provenance[3]`)·확인 판정·최종 커밋·신선도(`_fresh_ns`, 나이 = 수용 시각 − `Flo`)에는 `Flo`.
  - `future` 에는 `Fhi`(> 지금이면 거부).
  - `out_of_order` 에는 순서 시각.
  - 합성 원천은 `Flo = Fhi = stamp_s` 라서 지금과 같다(7b 의 `lo == hi` 와 같은 방식).
- 첫 빔 구간은 7a 의 `to_layer_scan` 과 같은 규칙이다(SDK 첫 표본 시각 ± 측정된 오차 상한). **7a-3 전에는 상한이 없으므로 구간이 없다.**
- **진단 모드**(2 회차 P2-8): 구간이 없는 동안에도 원천은 스캔을 브리지에 보낸다. 시각은 SDK 추정점이고, 표식 `interval: unmeasured` 를 단다. 응답은 기록만 하고 루프에 증거로 넘기지 않는다. 그래서 관측 실행 `--slam` 에서 L4·응답 간격·정합 품질을 7a-3 전에도 잰다. 실 기록으로 F1 까지 닿는 합격 사례(1.2)는 측정된 구간이 있어야 하므로 7a-3 뒤다.
- **7a-3 과의 관계**(총괄 확인 요청 한 줄): 7c 의 배관·재생·관측(진단 모드)은 7a-3 없이 성립하지만, 회차·확인 경계와 신선도(첫 빔→수용 0.25 s)는 첫 빔 구간이 있어야 판정되므로 실 SLAM 응답이 루프의 증거가 되는 것은 7a-3 뒤다.

**1. 스캔은 실행기가 브리지로 넘긴다**(4 절의 '두 데이터그램 소켓' 대신).
- **분기 지점은 하나다**: `ScanFeed` 가 받아들인 스캔(메타·시계·세대 검사를 지난 것). 거기서 층 경로와 SLAM 경로가 갈라진다. 기록은 `(feed_gen, producer_gen, scan_id)` 마다 원시 프레임 한 번, 경로별 판정 하나씩이다. 합성 원천의 `subscribers` 처럼 배치 잘라내기 전에 부르지 않는다.
- SLAM 경로의 판정(차례대로, 실패는 이유와 함께 세고 그 스캔은 보내지 않음):
  - **오도메트리**: 운영 경로에서는 첫 빔 구간 `[Flo, Fhi]` **전체**가 같은 부팅의 연속(`continuous`)·`included`(STATE 지연 상한 안) 이력으로 덮여야 하고, ROS 로 내기 전에 검사한다(3 회차 P2-4: 보낸 스캔은 버려도 이후 추정에 남음). 진단 모드는 추정점 하나를 쓴다. 자세는 첫 빔 추정 시각에서 두 항목 사이를 보간한다. 덮지 못하면 한 틱(20 ms) 기다린 뒤 다시 보고, 그래도 없으면 버린다(`slam_no_odom`). 오도메트리 자세는 후륜축 자세라서 `base_from_rear(pose, rear_offset_m)` 로 `odom_from_base` 를 만든다(사실 대조).
  - **빔**: 무효 빔(NaN)과 자기 가림 마스크(`lidar.yaml`)의 빔은 NaN 으로 보낸다. slam_toolbox 2.8.5 의 정합(`ComputeOffsets`)이 무효로 다루는 것은 NaN·Inf 뿐이다. `range_max` 를 넘는 유한값은 정합에 인공 점으로 들어갈 수 있다(2 회차 P2-7). 높이 띠(`limit_m`)는 층 규칙이라 SLAM 에는 쓰지 않는다.
  - **장착**: `lidar.yaml.mount` 는 후륜축 기준이다. 브리지의 정적 TF 는 `base_from_laser = rear_from_base⁻¹ ∘ rear_from_laser` 로 만든다(2 회차 P2-6). 층과 SLAM 이 같은 레이저 자세를 얻는지 비영 오프셋·비영 yaw 로 시험한다. `mount.measured: false` 동안 원천은 진단 모드다.
- 이유:
  - slam_toolbox 는 스캔 시각의 `odom → base_link` TF 가 필요한데, 오도메트리는 실행기에만 있다.
  - 층과 SLAM 이 **같은 받아들인 스캔**을 본다. 정체가 실행기 한 곳에서 정해지고, SLAM 쪽은 스트림 소켓이다.
  - Isaac 의 링크·응답 형식을 그대로 쓴다.
- 어댑터의 여러 소켓 기능(7a-1)은 그대로 둔다. 쓰지 않는다. 4 절의 두 경로 기록·재생 규칙은 '공통 입력 한 번 + 분기 뒤 경로별 판정'으로 바뀐다. 7r 은 공통 입력을 한 번 재생하고 실행기가 다시 가른다.
- **자세 오차**:
  - 고른 자세의 시각 오차는 오도메트리 구간 폭 + 첫 빔 구간 폭이다.
  - 병진 오차는 속도 × 오차다(0.15 m/s 에서 30 ms 면 4.5 mm).
  - 회전 오차는 각속도 × 오차라서 더 크다(0.5 rad/s 에서 30 ms 면 0.86°, 10 m 앞 벽에서 15 cm).
  - 한 바퀴(약 98 ms) 동안의 왜곡 보정(deskew)도 하지 않는다. 그래서 제자리 회전·급회전 중 정합은 벤치 4 에서 따로 본다(agy 5).

**2. 원천 계약(5c-2)을 실 링크에 대응시킨다.**
- **브리지는 세션당 한 번 쓴다**(agy 4): 브리지는 지금처럼 연결을 한 번만 받고, 실행기가 끊기면 끝난다. SLAM 컨테이너는 세션마다 런처가 새로 띄운다. 다시 붙으려는 연결은 거부한다. 실행기는 연결하자마자 `hello` 프레임(아래 '링크의 프레임' — `start_id` 포함)을 보낸다. 그래서 이전 세션의 seed 상태를 이어받을 길이 없다.
- **slam_toolbox 인스턴스는 브리지의 자식이다**(3판의 `/initialpose` 를 버림 — 3 회차 P1-1: 2.8.5 의 `/initialpose` 는 스캔과 따로 받는 구독이라, 어느 스캔이 그 자세를 소비할지 보장되지 않는다). 시작과 seed 마다 브리지가 인스턴스를 새로 띄운다. 그 인스턴스의 첫 처리 스캔이 `map_start_pose` 를 소비한다(2.8.5 시작 경로). 이것이 Isaac 의 위치 추정 시작(L3·L4)과 같은 길이다.
  - **띄우기**: 노드 **실행 파일 자체**를 브리지의 직접 자식으로, 새 프로세스 그룹에서 띄운다. `ros2 launch`·`ros2 run` 은 쓰지 않는다. `ros2 run` 은 띄운 노드보다 먼저 끝나서, 노드가 다른 부모로 넘어간 채 아무도 회수하지 않는 좀비로 남는다(7c-1a 전제 시험, ws1 잡 21220·21221; 직접 띄우면 SIGTERM 0.17 s 에 그룹이 비고 회수됨, 잡 21222). 인자는 번들의 지도·`map_start_pose`·위치 추정 설정이고, 지도 TF 발행은 끈다(`transform_publish_period: 0`). 브리지는 `/pose` 만 쓴다.
    - **인스턴스마다 토픽을 따로 둔다**(4 회차 P1): k 번째 인스턴스는 `/slam_k/scan`·`/slam_k/map`·`/slam_k/pose` 로 바꿔 띄운다. 브리지는 인스턴스마다 구독·발행자를 새로 만들고 옛 것은 없앤다. 콜백은 만들 때의 k 를 지니고, 지금 k 가 아니면 아무것도 바꾸지 않는다. 그래서 실행기가 이미 꺼냈지만 늦게 실행되는 옛 `/map` 콜백도 새 L4 를 바꿀 수 없다.
    - **lifecycle**(4 회차 P2-2): 2.8.5 의 노드는 직접 실행하면 `configure → activate` 전이가 있어야 스캔을 받는다(기존 launch 가 해 주던 일). 브리지가 두 전이의 성공을 확인한다. 그다음 그 인스턴스의 스캔 구독이 그래프에 나타나고 정적 TF 를 낸 뒤에 첫 스캔을 보낸다. 이 기다림도 아래 기한에 든다.
  - **끄기**(2 회차 P2-2): 그룹 전체에 SIGTERM, 기한 뒤 SIGKILL 을 보내고 `waitpid` 로 회수한다. ROS 그래프에서 그 노드 이름이 사라질 때까지 기다린다. 브리지의 구독 큐(`/pose`·`/map`)를 비운 뒤 상태(`awaited`·`stray`·L4)를 초기화한다. 이 순서를 마치기 전에는 새 인스턴스를 띄우지 않는다. 그래서 옛 프로세스의 메시지가 새 인스턴스의 응답이 될 수 없다.
  - **시작 검사 = 기존 L4 그대로**(3 회차 P1-2, P2-1): 인스턴스마다 시작 스캔 7 개(1·5·6·7 번에 `/pose` 를 기다림, 2–4 번은 2.8.5 가 건너뜀 — 기존 `startup_expect`). 7 번 전에 `/map` 이 조사 지도 점유 셀의 95 % 이상을 덮는지(적재 증거), 5–7 번의 끝점 비율과 자세가 `map_start_pose` 근처인지(`localized()`)를 본다. 그래서 seed 마다 지도 적재도 다시 확인된다.
  - **seed 동안 정지와 오도메트리 스냅숏**(4 회차 P2-4): 실행기가 seed 를 접수할 때 같은 부팅의 유효한 `odom_from_base` 스냅숏을 잡고, `start_pose = c ∘ 스냅숏` 을 계산해 `seed{seed_id, epoch, start_pose, 스냅숏, boot}` 로 보낸다. 브리지는 그 `start_pose` 를 `map_start_pose` 로 쓴다.
    - seed 접수부터 시작 검사 끝까지 오도메트리가 스냅숏에서 정지 판정 한도 밖으로 움직이거나 부팅이 바뀌면 그 seed 는 무효다(`seed_moved`). 그래서 시작 자세가 어느 스캔에 쓰이든 같은 자세다.
    - seed 접수 때 대기 칸의 스캔은 버린다. 새 인스턴스에 보내는 첫 스캔부터 `Flo ≥ seed 접수 시각` 과 스냅숏과의 오도메트리 연속을 보내기 전에 검사한다.
  - **기한과 끝 상태**: seed 접수부터 끝 상태 전달까지 한 기한 20 s(잠정)다. **이 기한의 최종 판정은 실행기(원천)가 한다**(9 회차 P2). 브리지는 20 s 가 지나도 스스로 고장을 내거나 연결을 닫지 않는다. 기한이 지난 시작 검사의 `ready`·`not_localized` 는 내지 않고, `cancel` 을 받을 수 있게 소켓을 유지한다. 그래서 실행기가 기한 안에 취소를 정했으면 `cancel` 이 20 s 뒤에 도착해도 정상 취소다. 기존 응답 대기(`reply_timeout_s` 60 s, 워밍업 1 s)는 이 기한에 맞춘다. 1·5·6·7 번 중 어느 `/pose` 라도 기한 안에 없거나, lifecycle 전이 실패, `/map` 적재 실패(`NOT_LOADED`), 끄기·회수 실패는 고장이다(`fatal_source`, 배치 고장이라 운용자가 고칠 수 없음). 정합 실패(`NOT_LOCALIZED`)만 `not_localized` 이고 고장이 아니다.
- `relocalize(epoch)`: 실행기 쪽에서만 한다. 회차를 올리고 대기 칸을 비운다. 인스턴스는 그대로 이어 간다. 응답의 회차 표기는 0 의 규칙(`Flo ≥ 회차 시작`)이다.
- **`seed(epoch, map_from_base, stamp_s)`** 는 막지 않는 요청이다. 호출은 접수만 하고 곧바로 돌아온다(채널 잠금 안에서 기다리지 않음). 원천은 seed 시점의 `odom_from_base`(오도메트리 이력에서 `stamp_s` 의 것)와 목표 자세로 보정 `c = map_from_base ∘ odom_from_base(seed)⁻¹` 를 정한다. 루프의 선언 합성 응답(`_declare_apply`)과 같은 seed 시점의 같은 오도메트리 값이다. 그리고 브리지에 seed 프레임(아래 '링크의 프레임')을 보낸다.
  - 상태: `seeding`(끄기·띄우기·시작 검사) → `ready`, `not_localized`, 또는 `void`(취소). 이 사이의 스캔·응답은 새 회차로 표기하지 않고 요청 번호도 소비하지 않는다. 선언을 완료할 수 있는 끝 상태는 `ready` 와 `not_localized` 뿐이다.
  - **링크의 프레임**(4 회차 P2-5, 5 회차 P3 — 정의는 여기 한 곳): 실차 모드의 링크는 `AsyncSlamLink` 를 고친 실차 전용 링크다(Isaac 링크는 그대로).
    - 보내는 프레임:
      - `hello{session_epoch, map_id, start_id, start_pose, deadline_ns}`(세션 첫 시작);
      - `seed{seed_id, epoch, start_pose, odom_snapshot, boot, deadline_ns}`(운용자 seed), `cancel{seed_id, reason}`(입력 자격이 깨진 seed). `deadline_ns` 는 실행기가 접수한 시각 + 20 s 의 호스트 단조 절대 시각이다. 브리지는 이 시각이 지나면 그 시작 검사의 끝 상태를 내지 않는다(10 회차 P3).
      - 스캔.
    - 받는 프레임:
      - `reply`(보낸 스캔의 응답);
      - `state{id, kind}`. `id` 는 `start_id` 또는 `seed_id` 이고, `kind` 는 `seeding`·`ready_for_scans`(인스턴스 활성·구독 확인)·`ready`·`not_localized{reason}`·`void{reason}` 이다.
    - `state` 는 보내는 칸을 비우지도 다음 스캔을 보내지도 않는다. 예외는 하나뿐이다: 지금 취소 중인 seed 와 `id` 가 같은 `void` 는 그 seed 에 묶인 보내는 칸을 비운다(8 회차 P3).
    - `hello`·`seed` 는 보내는 칸이 빈 뒤에 온전한 프레임으로만 보낸다. 반쯤 보낸 스캔 프레임 사이에 끼우지 않고, 그 응답(또는 1 s 기한)을 기다린다.
    - `hello`·`seed` 를 보낸 뒤에는 그 `id` 의 `state(ready_for_scans)` 전까지 스캔을 보내지 않는다.
    - 가짜 서버 시험에 옛 스캔의 `reply` 와 `state` 가 한 poll 에 오는 경우를 둔다.
  - **세션 첫 시작**(5 회차 P2-3): `hello` → `state(start_id, ready_for_scans)` → 시작 검사(L4) → `state(start_id, ready|not_localized)`. 기한은 seed 와 같은 20 s 다. `start_id` 는 운용자 seed 가 아니라서 F1 의 seed 기록에 들지 않는다. 가짜 서버 시험에 seed 없이 첫 `ready` 까지 가는 경우를 둔다.
  - **seed 하나씩**(5 회차 P2-1): `seeding` 중에 새 선언이 오면, 지금 시도를 건드리기 전에(부작용 없는 접수 판정 `can_seed()`) `seed_in_progress` 로 곧바로 거절한다.
  - **시도만 끝난 seed 와 입력 자격이 깨진 seed 를 나눈다**(6 회차 P2):
    - 시도만 끝난 경우(STOP·lease 상실·`superseded`)에는 seed 의 입력(스냅숏, 같은 부팅의 연속 오도메트리)이 그대로 유효하다. 그 seed 는 끝 상태까지 진행한다. 늦은 끝 상태는 기록만 하고, 이미 끝난 시도를 완료시키지 않는다.
    - 입력 자격이 깨진 경우는 `seed_moved`, 부팅 바뀜(예: 첫 시작 스캔 전 MCU 재부팅), 스냅숏과 이어지는 오도메트리가 끊김이다. 이때 원천은 브리지에 `cancel{seed_id, reason}` 을 보낸다(이유는 원천이 정함 — 7 회차 P3). 브리지는 인스턴스를 2 의 끄기 순서로 끄고 `state(seed_id, void{reason})` 를 낸다. 이것은 고장이 아니다. seed 칸은 풀리고, 인스턴스가 없으니 `processed` 도 없다. 재부팅이 연 새 세대에서 새 선언(seed)을 받을 수 있다.
    - **취소의 순서**(7 회차 P2-1): 취소가 시작되면 원천은 새 스캔을 멈춘다. 이미 쓰기 시작한 프레임만 끝까지 쓴 뒤 `cancel` 을 보낸다(응답은 기다리지 않음). 브리지는 `/pose` 를 기다리는 중에도 소켓을 읽어 `cancel` 을 처리한다. 취소된 seed 의 진행 중 스캔은 `void` 가 정리한다. `void` 를 받으면 원천은 그 seed 에 묶인 보내는 칸을 비운다. 그 뒤에 오는 그 seed 의 `reply`·`ready`(늦은 `/pose` 등)는 버리고 센다. 칸이나 시도를 되살리지 않는다.
    - **취소의 기한**(7 회차 P2-2, 8 회차 P2-1): 취소가 시작되면 그 seed 의 시작 응답 의무(1·5·6·7 번 `/pose`)는 끝난다. 20 s 시작 기한도 더 이상 걸리지 않는다. 기한은 둘로 나뉜다.
      - 취소 결정부터 `cancel` 송신 완료까지 1 s(쓰던 프레임의 나머지 포함). 넘기면 전송 장애다(`fatal_source`, 예: 소켓 역압으로 계속 `EAGAIN`).
      - 송신 완료부터 `void` 까지 5 s(잠정 — 끄기·회수·그래프 정리). 넘기면 자식 회수 실패로 보고 고장(`fatal_source`)이다.
    - **엇갈림**(8 회차 P2-2):
      - **아직 보내지 않은 seed**(seed 프레임이 소켓으로 나가기 전)는 원천 안에서만 취소한다. `cancel` 을 보내지 않는다. 브리지가 모르는 `id` 를 받지 않게 하기 위해서다. 그 seed 는 끝 상태 `void` 로 기록된다.
      - **보내기 시작한 seed** 는 `void` 를 받을 때까지 '취소 중'이다. 그사이 같은 `id` 의 `ready`·`not_localized`(취소 전에 브리지가 이미 보낸 것 포함)는 버리고 센다. 확인도 다음 seed 도 열지 않는다.
      - 브리지는 이미 `ready` 를 보낸 인스턴스여도 `cancel` 을 받으면 끄고 `void` 를 낸다. 시험: 정상인데 늦게 끝난 정리(19.9 s 에 취소, 20.1 s 에 `void`)는 고장이 아니다. 회수가 실제로 실패하면 고장이다.
    - 두 경우 모두 그 seed 는 세션의 마지막 seed 로 F1 기록에 남는다. 그래서 그 뒤 확인이 세대를 닫으면 F1 규칙(7)에 따라 막힌다. 새 seed 가 오면 그것이 마지막 seed 가 된다.
- **선언의 완료 조건**(3 회차 P2-2): 선언 시도는 **그 seed 의 끝 상태가 나오고 그때까지 `seed_moved` 가 없을 때만** 완료된다(5c-2 의 기존 조건 — 합성 보정, 새 층 결과 — 에 더함).
  - **선언의 기한은 확인과 따로다**(4 회차 P2-1): 확인은 지금처럼 접수 뒤 3 s 다. 선언은 seed 기한(20 s) + 끝 상태를 받은 뒤 커밋까지 0.5 s 다. seed 요청 대기·재기동·끝 상태 전달·최종 커밋이 모두 이 안이다. `_attempt_judge`·`_commit_void` 의 기한을 시도 종류별로 나눈다.
  - 끝 상태가 `ready` 이면 보통의 선언이다.
  - `not_localized` 이어도 정지를 지켰다면 선언은 완료되고 세대가 닫힌다. 그래서 텔레옵으로 수동 조작을 할 수 있다. 원천은 `processed` 를 루프에 넘기지 않는다. 세대가 닫혀 다음 선언도 받을 곳이 없다.
    - **수동 전용 래치는 `slam` 우회 하나에 묶는다**(총괄 2026-11-25, 사용자 규칙 real-checks-bypassable: 우회 불가는 멈추는 쪽만이고, 이 래치는 출발을 막는 쪽이다). 새 스위치나 조건 로직은 없다.
      - 그런 선언이 완료되는 순간 루프가 세션 래치 `manual_only = {reason: "not_localized", session_epoch, seed_id, since}` 를 건다. 래치는 세션 끝까지 남는다. MCU 재부팅이 연 세대에서 seed 가 `ready` 가 되어도 남는다.
      - **`slam` 우회가 꺼져 있으면**(기본): 세 경계(미션 요청·`Context`·AUTO 진입)가 막힌다. 그 세션은 **끝까지 수동 전용**이다(4 회차 P2-3). 다시 자율로 쓰려면 차를 바닥 표시로 옮기고 세션을 끝낸 뒤 새 세션을 연다(새 브리지, 바닥 표시 자세로 시작). 재위치 세대를 다시 여는 운용자 명령은 두지 않는다. 콘솔은 '위치 추정 실패 — 자율은 세션을 다시 시작해야 함(실제 SLAM 응답 없이는 `slam` 우회로도 출발 불가)'을 보인다(12 회차 P3-1).
      - **`slam` 우회가 켜져 있으면**: 래치는 기록과 콘솔 표시('우회 중: slam(not_localized)')만 하고 세 경계를 막지 않는다. 출력 상한은 지금 `slam` 우회의 0.06 m/s 그대로다(`_speed_cap`, D5 우회와 같은 자리).
      - 그래서 세 경계는 아비터의 한 방향 `block_start` 가 아니라, 판정할 때마다 같은 틱의 **`F1 start_block ∨ (manual_only ∧ slam 우회 꺼짐)`** 을 읽는다(11 회차 P3-1: 아비터 요청·`Context.start_blocked`·AUTO 진입 단언 셋 다 이 한 식). 우회는 켜고 끌 수 있기 때문이다. 우회 전환은 지금처럼 다음 틱 머리에 적용되고, 무장 중·미션 중에는 접수되지 않는다(기존 규칙). 막힐 때 아비터의 거절 코드는 `operator_placed_start` 다. 운용자 seed 에 대한 F1 차단(7)은 지금처럼 `block_start` 다.
      - 우회로 끝난 실행은 F1·SLAM 검증의 증거로 세지 않는다. 미션마다 결과에 그 미션 동안 적용된 우회 집합을 기록하고, 집계는 그 필드를 읽는다(11 회차 P3-2: 세션 끝 상태로는 중간에 끈 우회를 가릴 수 없음).
      - 위 4 의 경계 때문에, 이 래치를 우회해도 실제 `processed` 가 없는 `not_localized` 세션은 지금 계약으로는 출발하지 못한다(4 의 총괄 판단 항목).
    - **표시**(6 회차 P3-2): 루프는 래치를 `real_status.manual_only` 로 낸다. 콘솔의 안내는 지금 SLAM 상태가 아니라 이 래치와 `slam` 우회 상태를 읽는다. 그래서 MCU 재부팅 뒤 새 seed 가 `ready` 가 되어도 안내가 사라지지 않는다(시험).
- **확인 요청의 접수와 완료**(3 회차 P2-3):
  - 루프는 시도를 만들기 전에(진행 중 시도를 끝내거나 층·이력을 자르기 전에) 원천에 **부작용 없는 접수 판정** `can_confirm()` 을 묻는다. `ready` 가 아니면 곧바로 `slam_not_ready` 로 거절하고 아무것도 바꾸지 않는다.
  - 접수된 강제 요청은 그 회차의 **수용된**(늦지 않은) `processed` 로만 완료된다. 늦어서 버린 응답은 완료가 아니다. 원천은 시도 기한(3 s) 안에서 다음 스캔(`Flo ≥ not_before`)으로 다시 보낸다.
  - `not_localized` 에서도 선언(seed)은 받는다. 상태 알림은 `processed`·`skipped` 응답 경로와 따로 둔다(`state` 메시지). 5c-2 대로 텔레옵은 세대가 닫힌 뒤에 열린다.
- **장애 구분**:
  - 전송 장애(소켓 오류·EOF·프로토콜 위반·`ready` 에서 1 s 무응답)는 지금처럼 `fatal_source` 다.
  - 시작 검사의 고장은 위 '기한과 끝 상태'를 따른다.
- **`map_id`**: 원천은 조립 때 번들을 미리 검증(`load_bundle`)해서 그 `map_id` 를 갖는다. 조립 검사(`slam_map_mismatch`)는 그 값으로 한다. 브리지는 `hello` 의 `map_id` 가 자기 번들과 다르면 거부한다. 인스턴스의 실제 적재는 시작 검사의 `/map` 확인이 본다.
- `request_processed(epoch, attempt, not_before)`: `ready` 에서 `Flo ≥ not_before` 인 그 회차의 다음 스캔을 키프레임 판정 없이 보낸다. 응답에 `attempt` 를 단다.
- 응답의 `map_from_odom` 은 브리지의 `compose(pose, invert(odom_from_base))` 그대로다.

**3. 브리지 실차 모드의 시계: 흐르는 `/clock`, 분리된 ROS 도메인**(6 절의 '/clock 을 내지 않는다'와 8 절의 '실차 모드는 /clock 을 내지 않는다'를 바꿈).
- **ROS 현재 시각 = 현재 호스트 `CLOCK_MONOTONIC`.** 브리지가 ROS 시각과 무관한 타이머(벽시계 100 Hz)로 `/clock` 을 낸다. 실차와 재생 모두 같다. 재생은 **기록의 stamp 에만** Δ 를 더한다(`재생 stamp = 기록 단조 stamp + Δ`). 현재 `/clock` 에는 더하지 않는다(1 회차 P2-5).
- 스캔과 `odom → base_link` TF 는 그 축의 첫 빔 추정 시각으로 찍는다. 정적 TF(`base_link → laser`)는 첫 스캔 전에 낸다. slam_toolbox 는 `use_sim_time:=true` 다.
- 이유: slam_toolbox 의 TF·메시지 거르기는 스캔 stamp 와 ROS 시계가 같은 축이어야 한다. 시스템 시계(`CLOCK_REALTIME`)는 NTP 가 계단처럼 옮길 수 있다(3.1).
- **도메인**:
  - SLAM 컨테이너는 **새로 정하는 별도 `ROS_DOMAIN_ID`** 에서 돈다.
  - 지금의 `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` 도 유지해 외부 네트워크로 발견 패킷이 나가지 않게 한다(agy 10).
  - 도메인 안의 시계 발행자는 브리지 하나다.
  - 떼는 이유는 `/clock` 이 실차의 다른 노드(sllidar·어댑터, 벽시계)에 닿지 않게 하는 것이다.
  - sllidar 의 스캔은 런처가 이미 `/sensors/lidar/scan_raw` 로 바꿔 내므로 `/scan` 이름 충돌은 원래 없다(사실 대조로 고침).
- **stamp 단조**: 비교는 실제로 내는 정수 ns stamp 로 한다. 세션 안의 최댓값은 원천이 지닌다. 그 이하의 스캔은 보내지 않고 센다(4 절 4 회차 P2-2).
- **어긋난 `/pose`**: 지금 브리지는 기다리지 않던 stamp 의 `/pose` 를 받으면 그 연결을 `failed` 로 끝낸다(사실 대조로 바로잡음 — '버리고 센다'가 아님). 실차 모드도 같다. 인스턴스 교체는 2 의 끄기 순서(회수·그래프 확인·큐 비움)를 마친 뒤라 옛 인스턴스의 `/pose` 가 새 인스턴스의 응답이 되지 않는다.
- 시험: TF 가 스캔보다 늦게 오는 경우, 첫 스캔 전 정적 TF, 스캔이 늦어도 시계가 흐름, 늦게 온 스캔이 시계를 되돌리지 않음.

**4. 정지 중 갱신과 늦은 응답.**
- 링크에는 보내는 칸 하나와 대기 칸 하나만 둔다. 대기 칸에는 가장 새 스캔만 남기고, 밀린 옛 스캔은 버리고 센다(`slam_superseded`). 그래서 Jetson 이 밀려도 큐가 쌓이지 않는다(agy 9).
- **보내기 규칙**(2 회차 P2-5): 보내는 칸이 비면 대기 칸의 가장 새 스캔을 곧바로 보낸다. 정지 중에도 기다리지 않는다. 그래서 수용 간격은 `max(한 바퀴, 처리 시간)` 이 된다. 이것이 낼 수 있는 가장 짧은 간격이다. '0.2 s 이하 간격·0.25 s 이하 지연'은 규칙으로 보장하지 않고 벤치 4 에서 잰다. 예측으로 미리 버리지 않는다. 처리가 한 번 늦어도 다음 스캔은 보낸다.
- 위치 추정 모드에서 모든 스캔을 보내는 것이 Isaac 키프레임 규칙(0.5 s·거리)과 다른 동작인지는 실 스택 시험에서 처리 시간·정합 품질로 본다. 매핑 모드에서 모든 스캔이 지도를 망친 것(job 754)은 매핑이라서였다. 위치 추정은 지도를 고치지 않고 버퍼만 굴린다. 그래도 7c-1 의 실 스택 시험에서 두 규칙을 비교해 확인한다.
- **예산이 맞는가**(agy 1):
  - 첫 빔부터 수용까지 0.25 s 에는 한 바퀴(약 98 ms)가 이미 들어 있다. 실행기 전달·Jetson 처리·다음 틱까지가 약 150 ms 안이어야 한다.
  - Isaac 위치 추정의 처리 최대는 0.19 s 였다(`slam_localization_params.py` 머리말). 그래서 **실차에서 이 예산을 못 맞출 가능성이 실제로 있다.**
  - 벤치 4 에서 재고, 못 맞추면 5c-2 의 0.2·0.25·`SLAM_MAX_AGE_S` 0.5 를 함께 다시 정하는 별도 결정으로 올린다. 조용히 늘리지 않는다.
  - 못 맞추는 동안은 신선도가 끊겨(보수 쪽) 텔레옵만 열린다(총괄 승인).
  - **`slam` 우회로 여는 범위는 5c-2 그대로다**(총괄 결정 2026-11-19, 5c-2 6 의 2b·3): 우회 중에는 마지막 적용 보정과 오도메트리로 **계속** 달릴 수 있다(0.06 m/s). 그러나 **출발**(운용자 시작 확인·계획 채택·ARM 전 정지)에는 지금 회차의 실제 `processed` 가 한 번은 신선해야 한다. `_still` 의 SLAM 신선도는 hold 해제(`release_gate`)에도 쓰이므로, 우회해서 빼면 만료된 보정이 적용된다(5c-2 4 회차 P1, Codex 7c 11 회차 P2-2 가 다시 확인).
  - 그래서 신선도가 끊긴 정지 차는 `slam` 우회를 켜도 출발하지 못한다. `not_localized` 세션도 마찬가지다(2: 실제 `processed` 가 없음). 이 경계를 바꾸는 것(출발용 정지와 hold 해제용 신선도를 나누고, 우회 중 추적기 나이 예외를 건너뛰고, 선언 보정과 오도메트리만으로 출발)은 5c-2 계약을 바꾸는 일이다. 총괄 판단으로 올린다(2026-11-25).
- **늦은 응답 거부**: `AsyncSlamLink` 는 poll 때 도착해 있으면 오래 기다린 응답도 받는다. 원천은 넘기기 전에 `수용 시각 − Flo > 0.25 s` 인 응답을 버리고 센다(`slam_late`). 보정에도 신선도에도 쓰지 않는다.

**5. 실차 지도 번들 행**(6 절이 넘긴 '실차 행의 필드').
- `config/slam_map_bundles.yaml` 에 `site:` 행을 더한다. 필드는 다음과 같고, `scene_sha256` 은 없다.
  - `name`, `site_record_sha256`, `survey_report`(경로·sha256), `encoder_model`, `folder`, `map_id`
  - `start_pose`(map ← base_link), `start_relocalizable`, `start_reloc_evidence`
- **조사 보고서가 한 조사로 묶는다**(1 회차 P2-7). 보고서에 들어가는 것:
  - 현장 기록의 sha256(조사 날짜, 배치 사진 경로, 바닥 표시의 줄자 실측과 허용차)
  - 조사 주행의 원자료(관측·텔레옵 기록과 `.ok`)
  - 번들 `map_id`
  - 센서·오도메트리 설정의 해시(`lidar.yaml`, 차체 모델, `encoder_model`)
  - 지도 좌표계에서의 시작 자세
- **등록 명령**은 현장 기록 원본을 받아 직접 해시한다(2 회차 P3). 그 값이 보고서의 해시와 같아야 하고, 그것을 행의 `site_record_sha256` 에 넣는다. 보고서의 `map_id` 는 번들과 같아야 한다. 그래서 A 현장 기록에 B 번들을 붙일 수 없다.
- `start_pose` 는 `map ← base_link` 다. 이것을 후륜축 자세로 바꿔(루프가 시작을 보는 기준점) S10-A 설정의 `start_rear` 와 허용차 밖으로 다르면 등록을 거부한다.
- **조사 검사**(Isaac 의 `world.ok` 대신): 바닥 표시 5 곳에서 차를 세우고 위치 추정 결과를 기록한다. 기준은 지도와 무관하게 정한다.
  - 현장 좌표: 시작 표시를 원점, 시작 방향을 x 축으로 한다.
  - 각 표시는 'T' 모양이다. 차 옆면을 표시의 긴 선에 맞춰 세우면 위치와 방향이 정해진다. 줄자로 각 표시의 x·y 와 방향(가로·세로 대각 거리로 계산한 각)을 잰다.
  - 비교: 각 지점에서 '현장 좌표의 상대 위치·방향(시작 표시 기준)'과 '위치 추정 결과의 상대 위치·방향(시작점 기준)'의 차를 잰다. 관측 최댓값은 보고서의 `site_check.position_max_m`·`yaw_max_rad` 이고, 합격 한도는 미리 정한 `site_check.limits`(Isaac V2′ 와 같은 값에서 시작, 잠정)다. 관측값이 한도를 넘는 보고서는 등록에서 거부한다(3 회차 P3: 관측값과 한도를 같은 이름으로 두면 자기 자신과 비교하게 됨). 레지스트리 행의 `v2` 는 그 관측값이다(벤치 7).
  - Isaac 의 V2′ 는 전 노드를 참값과 비교했다. 실차는 이것이 **다섯 점 표본 검사로 바뀐다**는 점을 기록에 적는다.
- 레지스트리 코드는 행 종류를 나눈다. 기존 `put`·`lookup` 이 `scene_sha256` 을 직접 읽는 경로는 Isaac 행에만 쓴다. 섞인 레지스트리에서 두 종류가 모두 맞게 동작하는지 시험한다. `site:` 행의 조회 키는 `(site_record_sha256, encoder_model)` 이다. `start_relocalizable` 은 처음에 거짓이다.
- 구현(7c-2a): `tools/slam_bundle_registry.py add-site`·`lookup-site`. 같은 `bundles` 목록에 `scene_sha256` 대신 `site_record_sha256` 을 가진 행으로 들어간다(`is_site`). 조사 보고서 형식은 `site_survey/1`(도구 머리말). 시작 자세는 루프가 시작을 보는 것과 같은 후륜축에서 비교하고, 허용차는 실차 루프의 시작 허용차(`START_TOL_M` 0.10 m·`START_TOL_RAD` 5°, 벤치 7 전 잠정)다. S10-A 설정의 `map_id` 도 번들과 같아야 한다. 등록 명령은 번들 파일을 매니페스트와 대조하고(`load_bundle`), 보고서 폴더 아래의 원자료를 나열된 해시와 대조한다. 종류는 파일 헤더로 정하고, 관측 기록은 그 `.ok`(재생이 읽는 완료 규칙 `record_complete`), 텔레옵 기록은 마지막 행의 깨끗한 footer(텔레옵 분석과 같은 규칙)로 완료를 보며, 리허설(합성) 기록은 거부한다. 그리고 라이다 설정·차체 모델의 해시와 차량 보정 식별자(`calibration_id`, 오도메트리)를 읽은 파일과 대조한다. 보고서는 번들 뿌리(`SLAM_BUNDLE_ROOT`) 아래에 있어야 하고 행에는 그 뿌리 기준 상대 경로가 남는다. 행에는 관측값(`v2`)과 함께 그 한도(`site_check_limits`)를 남긴다.

**6. 재위치로 시작.**
- 실차 세션은 시작 때 재위치 세대를 연다(`core.require_relocalization(t, "session_start")`). HIL 의 항등 `processed`(`real_run.py` 655)는 실차 원천에 쓰지 않는다.
- 브리지는 `hello` 의 시작 자세(바닥 표시 `start_rear` → `base_from_rear`, 등록 행의 `start_pose` 와 일치)를 첫 인스턴스의 `map_start_pose` 로 쓰고 시작 검사(기존 L4)를 거친다. 운용자가 '재위치 확인'을 누르면 5c-2 의 확인이 돈다. 시작 검사 실패(`not_localized`)나 확인 실패가 이어지면 선언(7b)으로 시작한다.
- Isaac 의 전역 정합 시작(`StartRelocalizer`·`global_match`)은 7c 에 넣지 않는다. 실차 시작점은 바닥 표시 하나다.
- 구현(7c-2c): 조립(`real_run`)은 실 SLAM 원천(`relocalize` 가 있는 epoch 원천)이면 추적기에 항등 `processed` 를 넣지 않고, 루프를 만든 직후 `core.require_relocalization(0.0, "session_start")` 로 시작 세대를 연다. 합성 SLAM(HIL)은 지금처럼 항등으로 시작한다. 시작 세대가 열린 동안 출발 확인·제출은 거부된다(`relocalize_required`). 운용자가 확인(또는 선언)으로 닫는다. `hello` 의 시작 자세는 지금처럼 S10-A `start_rear` 를 `base_from_rear` 로 바꾼 값이다. 등록 행의 `start_pose` 와의 일치는 등록(7c-2a)이 후륜축 기준 허용차로 이미 보장하고, 등록 행을 읽는 운영 REAL 조립은 7c 뒤에도 거부되므로 런타임에 다시 읽지 않는다. 시작 세대를 확인으로 닫으면 seed 가 없어 F1 은 걸리지 않는다(7c-2b).
  - 방위각을 잘못 놓고 시작하는 것은 운용자 육안 확인과 확인 판정의 거리·각 한도(`START_TOL_M` 0.10, 5°)가 막는다.
  - 비슷한 배치에서의 거짓 수렴은 벤치 7 의 오수렴 시험이 본다(agy 8).

**7. F1 세 경계(7d).**
- **기록**(서버 쪽, 루프 안): 세션 안의 모든 `seed` 를 `(session_epoch, generation, attempt, epoch)` 로 기록한다. 시도가 `declared` 로 닫힌 것도 같은 묶음으로 기록한다. 둘 다 루프가 정하고, 콘솔·SLAM 응답은 만들 수 없다.
- **판정 시점**: 세대가 닫히는 순간(`core.relocalized`), 다음 요청 묶음의 `link.begin()`·`Context` 생성 전이다. seed 직후에는 판정하지 않는다. 판정은 되돌릴 수 없으므로, seed 직후에 하면 정상 선언도 완료 전에 영구 차단된다.
- **막는 조건**(2 회차 P1): **세션의 마지막 seed** 가 그 묶음의 완료된 `declared` 가 아니면 막는다.
  - 브리지는 세션 중 바뀌지 않고, slam_toolbox 인스턴스를 새로 띄우는 것은 seed 뿐이다(2). 그래서 한 번 운용자 seed 가 들어가면 그 뒤의 모든 추정은 마지막 seed 에서 이어진다. 세대가 바뀌어도(MCU 재부팅·hold 한도·현장 복구) 마찬가지다. 세션 시작의 첫 인스턴스는 운용자 seed 가 아니라 등록 행의 바닥 표시 자세다.
  - 예: G1 의 선언 seed 가 `refused` 로 끝나고, 재부팅으로 열린 G2 를 확인이 닫으면 막는다.
  - 마지막 seed 의 선언이 완료됐으면(어느 세대였든) 막지 않는다. 그 추정은 운용자가 인정한 시작점에서 이어진 것이고, 0.06 m/s 상한이 세션 끝까지 걸린다. (`not_localized` 로 완료된 선언은 이 예외와 따로, 2 의 수동 전용 래치가 `slam` 우회가 꺼져 있는 동안 세 경계를 막는다.)
  - 새 세션은 새 브리지라 seed 가 없다.
  - 출처 누락(seed 기록 없이 운용자 자세가 들어온 경로)은 막는다.
  - STOP·lease 만료·재무장은 기록을 새로 만들지 않는다.
- **배선**(실차 경로는 지금 셋 다 비어 있음 — 사실 대조):
  - ① 아비터: 실차 루프가 위 조건에서 `arbiter.block_start(source)` 를 부른다.
  - ② 미션 명령: 실차 루프의 `Context` 에 `start_blocked` 를 넘긴다(지금은 넘기지 않아 기본 False). 값은 2 의 공통식 `F1 start_block ∨ (manual_only ∧ slam 우회 꺼짐)` 이다(12 회차 P3-2).
  - ③ AUTO 진입 단언: 아비터의 기존 단언(`arbiter.py` 871)이 같은 공통식을 읽게 한다(①의 요청 검사도 같은 식).
- **수동 복구 보고는 막지 않는다**(1 회차 P2-6).
  - `START_REFUSED` 의 `recovery` 는 실차에서 **수동 현장 복구 완료 보고**다(`real_loop` 의 `field_recovery_done`). 차를 움직이지 않고 새 재위치 세대를 연다.
  - F1 이 잠근 세션에서 포크를 손으로 빼고 DISARM 을 확인한 뒤 그 보고를 못 하면 세션이 갇힌다.
  - 그래서 실차 경로의 차단 목록은 `recovery` 를 뺀 것이다. 미션 제출·재개·집기 요청과 AUTO 를 막는다. 아비터에 차단 목록을 인자로 주고, Isaac 은 지금 목록 그대로다.
- 해제는 세션 끝뿐이다. 텔레옵은 열려 있다(F1 원래 정책).
- **구현(7c-2b, 총괄 #623 판단 ①·② 반영, Codex 설계 확인)**:
  - 실차 경로의 F1 은 아비터의 한 방향 `start_block` 이 아니라 **루프의 시작 게이트**(`RealLoop._start_gate`, 아비터의 `start_gate`)에 둔다. 요청 검사·AUTO 진입 단언·`Context.start_blocked` 셋이 모두 이 게이트를 읽는다. 게이트의 거부 목록(`START_GATE_REFUSED`)은 `recovery` 를 빼므로 수동 복구 보고가 열려 있고, 세션 중 `f1` 우회를 그 자리에서 읽는다. Isaac 의 `block_start` 경로는 그대로다.
  - 출발 게이트식은 세 경계 모두 `(F1 차단 ∧ f1 우회 꺼짐) ∨ (manual_only ∧ slam 우회 꺼짐)` 이다.
  - 기록은 `seed_log`(seed 마다 `(session_epoch, generation, attempt, epoch, seed_id)`, 원천이 seed 를 받은 직후)다. 선언이 닫힐 때 키 전체가 맞는 행만 완료로 표시하고, 맞는 행이 없으면 `declare_unsourced` 로 막는다. 판정은 `_close_generation` 에서 `core.relocalized` 직후 한 번이다. 막힘은 `f1_block`(마지막 seed 의 식별자 포함)과 `reloc_events` 의 `f1_block` 행으로 남고, 실행 끝 기록에 `seed_log`·`f1_block`·`reloc_events` 가 들어간다.
  - **`f1` 우회**(세션 토글, 다른 우회와 같은 방식): 우회 중 상한 0.06 m/s, 그 사이 돈 임무의 결과에 `bypassed` 와 `excluded_counts: [f1, validation]` 를 남기고, 끝 기록의 `mission_counts` 가 그 임무를 F1·검증 계수의 분자·분모에서 뺀다. 화면 띠는 "우회 중: f1" 이다.
  - **우회하지 않는 것**(판단 ①): 이번 회차의 실제 `processed` 가 신선하지 않은 출발. ARM 프레임을 쓰는 그 순간(`judge` 의 `ns`)에 SLAM 응답 나이를 우회와 무관하게 다시 보고, `SLAM_MAX_AGE_S` 를 넘으면 `arm_slam_stale` 로 거부한다(틱 앞에서 0.497 s 였던 응답이 쓰기 때 0.5 s 를 넘는 경우 — Codex 설계 확인 P1).

**8. 관측 실행 `--slam`**(벤치 4·7 의 기록)
- 관측 실행에 실 SLAM 원천을 붙인다(7a-3 전에는 0 의 진단 모드). 관측 실행에는 루프가 없으므로 STATE 에서 오도메트리 이력을 만든다. **루프와 같은 함수**(`_odom_entry` 의 오도메트리 단계와 구간 규칙)를 공용으로 빼서 쓰고, 복사하지 않는다.
- 기록 항목:
  - 보낸 스캔: 정체, 첫 빔 구간(또는 `unmeasured`), `odom_from_base`
  - SLAM 경로 판정: 버린 이유
  - 응답: 상태, `map_from_odom`, 회차·시도, 수용 시각
  - `seeding`·`ready`·`not_localized` 상태, 늦은 응답 버림
  - 정합 품질: 응답마다 지도 벽에 떨어진 끝점 비율(L4 와 같은 계산). 자동 정지에는 쓰지 않는 진단값이다(agy 7).

- **완료 조건을 셋으로 나눈다**(Codex P2-8).
  - 근접 인식: 실촬영 근거리 검출기의 valid 관측. 지금 0/240(#594)이다.
  - D5 깊이 검사: 새 깊이 프레임에서 정지 가능 공간을 확인하는지. 인식과 별개로 시험한다.
  - 우회 운용: `d5_pocket` 은 운용자가 미션 전에 고르는 5d 우회(검사 영역 면제, 0.06 m/s 상한)다. 실 검사가 실패해서 자동으로 바꾸지 않는다. 우회로 끝난 실행을 D5 검증으로 세지 않는다.

## 8. 7r — 재생 실행

- 관측 실행 기록을 `RunSources` 의 재생 원천으로 읽는다. 스캔, IMU, 깊이 프레임과 각각의 세대·취득 구간을 읽는다. SLAM 응답은 읽지 않는다(1.2: 재생 스캔을 실시간 SLAM 에). 이 프로세스가 만든 pty 의 HIL(`--run --hil`)에서만 만들 수 있다.
- 기록 시각을 HIL 실행 시각으로 옮기는 규칙은 1.2 의 Δ 다.
- **ROS 시계**(Codex 3 회차 P2-1): 실시간 SLAM 은 ROS 시각으로 스캔과 odom TF 를 맞추고, 브리지는 `/pose` 의 stamp 가 정확히 같을 때만 응답을 받는다. 전날 기록의 원 stamp 를 그대로 쓰면 맞지 않는다. 그래서 재생 모드의 브리지는 스캔과 TF 를 옮긴 시각축(기록 단조 stamp + Δ)으로 찍고, `/clock` 은 현재 호스트 단조 시각으로 낸다(6.1 의 3: Δ 는 기록 stamp 에만 더함). 원 stamp 는 대조용 필드로 보존한다. 실차 모드도 같은 시계 방식이다(6.1 의 3 에서 바꿈, 재생 모드는 그 축에 Δ 를 더함). 다른 날의 기록으로 지금 HIL 의 `seed` 뒤 첫 유효 `/pose` 를 받는 시험을 둔다. `/clock` 은 재생의 **현재 시각**이고 계속 흐른다. 스캔과 TF 의 stamp 는 같은 축의 **취득 시각**이다. 기존 브리지는 스캔 stamp 를 `/clock` 에도 쓰는데, 재생 모드는 그렇게 하지 않는다. 그래서 300 ms 늦게 온 스캔이 ROS 시계를 거꾸로 돌리지 않는다. 첫 스캔 전과 스캔이 늦는 동안에도 시계가 흐르는지 시험한다(Codex 4 회차 P3).
- **부팅 경계**(Codex 3 회차 P2-2): HIL 부팅이 바뀌면 메모리 캐시만 비우지 않는다. 새 부팅의 경계를 옮긴 시각축에 두고, `lo` 가 그보다 이른 표본은 파일에 남아 있어도 내지 않는다. HIL 확인을 잃은 동안의 표본, 이전 부팅에서 요청해 늦게 돌아온 SLAM 응답도 내지 않는다. 세 경우 모두 0 건 전달 시험을 둔다.
- 이것으로 판정 경로를 실 원천 모양 위에서 돌린다. 실 보드 호스트에 가상 ARM 을 넣지 않고 판정을 보는 유일한 길이다.
- **합격표를 두 시점으로 나눈다**(Codex 2 회차 P2-8).
  - **7r 시점**: 스캔·IMU 재생과 실시간 SLAM 위에서 실제로 도달한 추종·S10 정지 경로의 기한을 잰다. 이때 D5 는 `d5_pocket` 우회다. 그래서 `_feed_depth()` 가 깊이 원천을 읽지 않는다. 이 측정은 실 검사기가 든 25 ms 예산의 증거가 아니다.
  - **7e 뒤 시점**: 우회를 풀고, 실 프레임으로 만든 `PocketCheck` 호출과 같은 틱의 층 질의가 든 경우를 잰다. 재는 구간은 5d 원문대로 **정상 DRIVE 틱 시작부터 송신 관문 진입까지**다. 5d 340 의 25 ms 판정은 이 시점에 닫는다.
  - Jetson 결과에는 어떤 원천이 실시간이었는지 표시한다. 재생 입력만 쓴 측정과, 실 SLAM·카메라 두 스트림이 함께 돈 30 분 측정을 따로 적는다.
