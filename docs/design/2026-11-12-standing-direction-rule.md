# 벽 앞 탈출 — 서 있는 차의 정지 교착을 운용자 확인으로 푼다 (설계 2판, 2026-11-12)

텔레옵 다리(#459) 설계 2절에 적은 교착의 후속이다. 1판(크기·방향 분리, 정지 때 경계 0)은 Codex 적대 검토가 반박해 철회했다(3절). 총괄 결정(2026-11-12): **B — 운용자 확인 '벽 앞 탈출', 다리 전용**. `SafetySpeed`·코어 4d-1 규칙은 그대로라 시뮬·실차 갈림이 없다. Isaac 운용은 지금 그대로다.

## 1. 문제 (측정값)

다리는 엔코더 속도의 가능 방향을 구간 `signed ± e` 로 정한다. 오차 폭 `e` 에는 가속 여유 `a_w·(Δt/2 + 나이)` 가 들어 있다. 그래서 서 있거나 느릴 때(`|signed| < e`, 지금 약 0.022–0.055 m/s)는 늘 두 방향이다. 코어 4d-1 규칙(`MissionCore._direction_limits`, 다리 `direction_limits` 와 같은 결과)은 요청과 다른 가능 방향을 경계 속도로 검사하고, 허가가 모자라면 정지(hold)한다.

라이브 장애물 층 허가(`config/obstacle_layer_single_a2_team_spec.yaml`)로 재면, 뒤 간격이 1 cm 격자에서 6.5 cm 이하, 5 cm 격자에서 8–17 cm 이하일 때 앞 출발까지 막힌다. 대부분은 허가의 고정 여유(정지 margin 5 cm, envelope 1 cm, 칸 크기)다. 경계 속도의 몫은 0.4–0.9 cm 다. 그래서 경계가 0 이 아니면 아무리 작아도(예: 양자화 폭 0.0005 m/s) 같은 거리에서 막힌다. **경계가 정확히 0 일 때만** 코어 규칙이 요청받지 않은 움직임을 비운다(`if speed.bound_mps > 0.0`).

## 2. 문구 그대로였던 결정의 결과 — 덜컥거림 (1판)

'정지 확인 주기에만 경계 0, 첫 비영 명령 뒤 정상 경계' 로는 막 출발한 저속(`< e`)에서 구간이 다시 0 을 걸쳐 뒤를 검사하고 정지한다. 출발 → 정지 → 0.2 s 정지 확인 → 출발이 되풀이된다.

## 3. 왜 `SafetySpeed`·코어 규칙을 바꾸지 않는가 (같은 안이 다시 나오지 않게)

1판은 크기(경계)와 방향을 나눠, 서 있다가 한 방향으로만 명령하는 동안 반대 방향을 측정이 가리킬 때만 가능 방향에 넣고, 정지 기준점에서는 경계를 0 으로 두자고 했다. Codex 적대 검토(2026-11-12, P1 3)가 반박했다.

1. **명령 부호로 운동 방향을 제한할 수 없다.** 펌웨어 바퀴 제어(`drive.c` 975)는 양·음 듀티를 내고, PI(`pi.c` 24)는 감속 중 음의 적분을 만들어 유지할 수 있다. 지금 이득과 1차 plant 로 목표를 +0.2 → +0.001 rad/s 로 낮추면 외력도 부호 전환도 없이 −0.0004 m/s 로 역회전한다(가속 0.53 m/s² — 전제 A1 안). 제자리 회전처럼 바퀴마다 부호가 다른 명령이나 조향으로 한쪽 목표만 낮아지는 경우에는 차량 단위의 '한 방향' 이 정의되지 않는다.
2. **'그 사이 외력 이동 1 mm < 허가 여유 5 cm' 는 근거가 아니다.** 허가의 `margin_m` 은 정지거리에 **더해** 요구하는 거리이고, 실제 뒤 간격은 1 mm 일 수도 있다. 표본 간격(25 ms)·나이(50 ms)·루프·MCU 반영·물리 제동을 합친 전체 변위, 평균 속도가 끝 순간의 역행을 가리는 것, 바퀴가 잠긴 채 차체가 밀리는 것도 빠졌다.
3. **경계 0 은 `SafetySpeed` 의 뜻을 깬다.** 카운트 정지는 '정확히 0' 이 아니다(±1–2 카운트에서 `signed` 0.00024, `bound` 0.022). `bound < |signed|` 는 계약 위반이고, `signed` 까지 0 으로 두면 측정을 지운다. 코어의 다른 소비자(paused 정지 확인 `core.py` 5620, 저상 감시 6169, cusp 정지 호 6689, 포켓 방향 불확실 정지 1576)의 판단까지 바뀐다.

그래서 안전 판단에 쓰는 속도(`SafetySpeed`)와 4d-1 규칙은 측정 그대로 둔다. 교착은 **사람이 보고 명시적으로 승인한 좁은 예외**로 푼다.

## 4. 벽 앞 탈출 (B)

### 4.1 제안(offer)
- 텔레옵 중(`ready`, 무장, 데드맨 눌림) 운용자가 방향 `d` 를 요청했는데, 출력 방향 검사(다리 설계 8절)가 **요청받지 않은 방향 `−d` 때문에** 정지(hold)를 냈을 때만 생긴다. 요청 방향 `d` 자체의 허가가 모자라서 막힌 경우는 제안하지 않는다.
- 상태 메시지에 `escape_offer = {offer_id, direction: d, blocked: −d, reason}` 를 싣는다. 콘솔은 그것이 있을 때만 '벽 앞 탈출' 버튼을 보인다. 버튼 문구에 '뒤(또는 앞)를 직접 보고 누르세요' 를 적는다.
- 제안은 hold 가 풀리거나 다른 일이 생기면 사라진다(무장 해제·STOP·lease·세대·요청 방향 변경).

### 4.2 승인
- 새 신뢰 요청 `escape_approve {request_id, session_epoch, lease_id, control_gen, arm_gen, offer_id}`(lease 필요, 형식 검사는 `safety/validate.py`).
- 중재기는 처리기를 **주입받을 때만** 받는다(`arbiter.escape`; 없으면 `unsupported` — Isaac 운용은 그대로). 중재기는 TELEOP·무장·latch 없음을 확인하고 다리에 넘긴다. 다리는 지금 유효한 제안의 `offer_id` 일 때만 받는다.
- **승인 한 번에 탈출 한 번.** 같은 제안으로 두 번 시작하지 않는다. 연속 승인은 새 hold(새 제안) 뒤에만 된다.

### 4.3 탈출 중
- 구동 방향은 승인한 `d` 로만 간다. 요청이 반대(`−d`)나 0 이 되면 탈출이 끝난다.
- **요청 방향 `d` 의 허가 검사는 평소대로 전부 적용**한다(묶음 호, 경계 속도). 건너뛰는 것은 `−d` 의 '요청받지 않은 움직임' 검사 하나뿐이다.
- 속도는 0.05 m/s 이하다(명령 상한과 둘 중 작은 것).
- 끝나는 조건(먼저 닿는 것):
  - 정상 끝: 엔코더 이동 거리 0.20 m, 시간 4 s. 끝나면 일반 규칙으로 돌아간다(0 으로 서지는 않음 — 일반 규칙이 다시 판단).
  - **즉시 0 + STOP**:
    - 데드맨을 놓음.
    - 반대 방향 측정 운동: `signed` 가 `−d` 쪽으로 정지 문턱(0.01 m/s)을 넘음. 경계로 보지 않는다.
    - 속도 무효, 중재기 STOP·lease 상실·무장 해제·세대 변경, 요청 방향 반전.
- 기록: 제안·승인·시작·끝(사유, 이동 거리, 시간)을 다리 기록(JSONL)과 상태 메시지(`escape`)에 남긴다. 콘솔 로그에도 남는다.

### 4.4 Isaac·시뮬
바뀌지 않는다. 중재기의 `escape` 처리기는 다리만 주입한다. `SafetySpeed`·코어 규칙은 그대로다. 1판에서 4e-2 에 넣었던 '시뮬 공급자 이전' 항목은 철회했다(총괄 2026-11-12).

## 5. 시험

- 다리 주기(가짜 MCU, 실제 `McuLinkHost`·중재기):
  - 뒤 허가 0 인 벽 앞: 앞 요청 → hold → 제안 → 승인 → 연속 비영으로 0.20 m 이동 → 끝 → 일반 규칙.
  - 요청 방향 자체가 막힌 경우(앞 허가 0): 제안 없음.
  - 같은 제안으로 두 번 승인: 두 번째 거절. 새 hold 뒤 새 제안은 됨.
  - 즉시 0 + STOP: 데드맨 놓음, 반대 방향 측정 운동(카운트 감소), 속도 무효, 운용자 STOP, 요청 반전.
  - 속도 0.05 이하, 시간 4 s 끝.
  - 기록·상태 메시지의 `escape_offer`·`escape`.
- 중재기: `escape` 처리기 없음 → `unsupported`(Isaac 그대로), 형식·lease·세대 검사.
- 콘솔: 제안이 있을 때만 버튼, 누르면 `escape_approve` 송신(`node --test`).
- 종단(MCU 모형): 벽 앞 탈출 한 번.
