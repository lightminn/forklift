# 벽 앞 탈출 — 서 있는 차의 정지 교착을 운용자 확인으로 푼다 (설계 5판, 2026-11-12)

텔레옵 다리(#459) 설계 2절에 적은 교착의 후속이다. 1판(크기·방향 분리, 정지 때 경계 0)은 Codex 적대 검토가 반박해 철회했다(3절). 총괄 결정(2026-11-12): **B — 운용자 확인 '벽 앞 탈출', 다리 전용**. `SafetySpeed`·코어 4d-1 규칙은 그대로라 시뮬·실차 갈림이 없다. Isaac 운용은 지금 그대로다.

## 1. 문제 (측정값)

다리는 엔코더 속도의 가능 방향을 구간 `signed ± e` 로 정한다. 오차 폭 `e` 에는 가속 여유 `a_w·(Δt/2 + 나이)` 가 들어 있다. 그래서 서 있거나 느릴 때(`|signed| < e`, 지금 약 0.022–0.055 m/s)는 늘 두 방향이다. 코어 4d-1 규칙(`MissionCore._direction_limits`, 다리 `direction_limits` 와 같은 결과)은 요청과 다른 가능 방향을 경계 속도로 검사하고, 허가가 모자라면 정지(hold)한다.

라이브 장애물 층 허가(`config/obstacle_layer_single_a2_team_spec.yaml`)로 재면, 뒤 간격이 1 cm 격자에서 6.5 cm 이하, 5 cm 격자에서 8–17 cm 이하일 때 앞 출발까지 막힌다. 대부분은 허가의 고정 여유(정지 margin 5 cm, envelope 1 cm, 칸 크기)다. 경계 속도의 몫은 0.4–0.9 cm 다. 그래서 경계가 0 이 아니면 아무리 작아도(예: 양자화 폭 0.0005 m/s) 같은 거리에서 막힌다. **경계가 정확히 0 일 때만** 코어 규칙이 요청받지 않은 움직임을 비운다(`if speed.bound_mps > 0.0`).

## 2. 문구 그대로였던 결정의 결과 — 덜컥거림 (1판)

'정지 확인 주기에만 경계 0, 첫 비영 명령 뒤 정상 경계' 로는 막 출발한 저속(`< e`)에서 구간이 다시 0 을 걸쳐 뒤를 검사하고 정지한다. 출발 → 정지 → 0.2 s 정지 확인 → 출발이 되풀이된다.

## 3. 왜 `SafetySpeed`·코어 규칙을 바꾸지 않는가 (같은 안이 다시 나오지 않게)

1판은 크기(경계)와 방향을 나눠, 서 있다가 한 방향으로만 명령하는 동안 반대 방향을 측정이 가리킬 때만 가능 방향에 넣고, 정지 기준점에서는 경계를 0 으로 두자고 했다. Codex 적대 검토(2026-11-12, P1 3)가 반박했다.

1. **명령 부호로 운동 방향을 제한할 수 없다.** 펌웨어 바퀴 제어(`drive.c` 975)는 양·음 듀티를 내고, PI(`pi.c` 24)는 감속 중 음의 적분을 만들어 유지할 수 있다. 지금 이득과 1차 plant 로 목표를 +0.2 → +0.001 rad/s 로 낮추면 외력도 부호 전환도 없이 −0.0004 m/s 로 역회전한다(가속 0.53 m/s² — 전제 A1 안). 제자리 회전처럼 바퀴마다 부호가 다른 명령이나 조향으로 한쪽 목표만 낮아지는 경우에는 차량 단위의 '한 방향' 이 정의되지 않는다.
2. **'그 사이 외력 이동 1 mm < 허가 여유 5 cm' 는 근거가 아니다.** 허가의 `margin_m` 은 정지거리에 **더해** 요구하는 거리이고, 실제 뒤 간격은 1 mm 일 수도 있다. 표본 간격(25 ms)·나이(50 ms)·루프·MCU 반영·물리 제동을 합친 전체 변위, 평균 속도가 끝 순간의 역행을 가리는 것, 바퀴가 잠긴 채 차체가 밀리는 것도 빠졌다.
3. **경계 0 은 `SafetySpeed` 의 뜻을 깬다.** 카운트 정지는 '정확히 0' 이 아니다(±1–2 카운트에서 `signed` 0.00024, `bound` 0.022). `bound < |signed|` 는 계약 위반이고, `signed` 까지 0 으로 두면 측정을 지운다. 코어의 다른 소비자(paused 정지 확인 `core.py` 5620, 저상 감시 6169, cusp 정지 호 6689, 포켓 방향 불확실 정지 1576)의 판단까지 바뀐다.

그래서 안전 판단에 쓰는 속도(`SafetySpeed`)와 4d-1 규칙은 측정 그대로 둔다. 교착은 **사람이 보고 명시적으로 승인한 좁은 예외**로 푼다.

## 4. 벽 앞 탈출 (B) — Codex B 검토(P1 2·P2 2) 반영

'다리와 코어가 같은 규칙' 은 이렇게 정리한다: **일반 경로는 같고**(다리의 `direction_limits` 는 코어 4d-1 과 같은 결과를 시험이 고정), **S6 다리에만 명시적 수동 탈출 예외**가 있다. 운용자 확인은 뒤 공간을 사람이 직접 봤다는 근거이며, 검출 전 역행이나 바퀴가 잠긴 채 밀리는 것을 자동으로 보장하지는 않는다 — 그래서 한도가 좁고 사람 감시(S6 조건) 아래에서만 쓴다.

### 4.1 제안(offer)
- 생기는 조건(모두):
  - 텔레옵 `ready`, 무장, 데드맨 눌림, 운용자가 방향 `d` 를 요청.
  - 출력 방향 검사가 **요청받지 않은 방향 `−d` 때문에** 정지(hold)를 냄. 요청 방향 `d` 자체의 허가가 모자란 경우는 제안하지 않는다.
  - **신선한 정지**: 카운트 정지(`counts_still`)와 중재기의 정지 검출.
  - **작용 중인 비영 명령 없음**(`port.older_nonzero_may_act` 거짓, 다리의 마지막 비영 명령 만료).
  - **조향이 직진**: 측정 `q` 의 곡률이 직진 허용오차 안(`steering_control.straight_threshold_rad`, `vehicle.yaml`)이다. 꺾여 있으면 제안하지 않는다(Codex 재검토 P2: 꺾인 채 고정하면 곡선 탈출).
- 상태 메시지에 `escape_offer = {offer_id, direction: d, blocked: −d, reason}` 를 싣는다. `offer_id` 는 정지 사건마다 새로 매긴다. 콘솔은 그것이 있을 때만 '벽 앞 탈출' 버튼을 보인다(문구: 막힌 쪽을 직접 보고 누르세요).
- 정지가 풀리거나, 무장·lease·세대·요청 방향이 바뀌면 제안이 사라진다.

### 4.2 승인
- 새 신뢰 요청 `escape_approve {request_id, session_epoch, lease_id, control_gen, arm_gen, offer_id}`. 요청 장부(중복 방지)를 그대로 쓰고, lease 가 필요하다. 형식 검사는 `safety/validate.py` 에 둔다.
- 중재기는 처리기를 **주입받을 때만** 받는다(`arbiter.escape`; 없으면 `unsupported` — Isaac 운용은 그대로). 중재기는 TELEOP·무장·latch 없음을 확인하고 다리에 넘긴다.
- 다리는 다음을 모두 만족할 때만 받는다. 거절 이유는 기록한다.
  - `offer_id` 가 지금 유효한 제안이다.
  - 세대(`control_gen`·`arm_gen`)가 제안을 만든 때와 같다.
  - 탈출 중이 아니다(탈출 중 재승인으로 예산을 늘리지 않는다).
- **승인 한 번에 탈출 한 번.** 다음 탈출은 새 정지(새 제안) 뒤에만 된다. 반복은 허용하되 매번 운용자가 새로 보고 승인하며, 모두 기록된다.

### 4.3 탈출 중
- **방향 고정, 직선만**(첫 판): 구동은 승인한 `d` 로만 간다. 조향은 승인 순간의 측정 `q`(직진 허용오차 안)로 고정하고, 곡률 요청은 무시한다. 측정 `q` 가 직진 허용오차를 벗어나면 즉시 STOP 이다.
- **요청 방향 `d` 의 허가 검사는 평소대로 전부 적용**한다(묶음 호, 경계 속도, 스캔 신선도·점유·unknown, 적재·포켓·복구 차단). 건너뛰는 것은 `−d` 의 '요청받지 않은 움직임' 검사 하나뿐이다.
- **0.05 m/s** 는 명령 상한이다. 물리 속도는 측정으로 따로 감시한다(아래 바퀴별 속도). `SafetySpeed.bound` 로는 걸지 않는다(정지 상태의 오차 폭이 0.055 까지라 출발을 막는다). 일반 과속 STOP(경계 > 0.2)은 그대로다.
- **예산**:
  - 거리: 바퀴별 **누적 절대 이동**(왕복·회전도 예산에서 빠지지 않음)의 큰 쪽.
  - **끝 시점은 매 주기 측정으로 정한다**(Codex 재검토 P1: 명령 속도와 검증 안 된 감속으로 잡은 고정 0.19 m 는 0.20 m 를 보장하지 않는다). `이동 + v·T + ½·A·T² + (v + A·T)² / (2·b_min) ≥ 0.20 m` 이면 끝낸다(가속 항: Codex 4판 재검토 P2 — 정지가 효과를 내기 전 `T` 동안 더 빨라질 수 있다).
    - `v = max_w(|v_w| + e_w)` — 바퀴마다 부호 없는 측정 속도에 그 바퀴 오차 폭을 더한 것의 최댓값(`SafetySpeed.bound_mps` 와 같다; 부호 있는 값으로 하면 후진에서 음수가 된다 — 4판 재검토 P2).
    - `A`: 바퀴 가속 상한(전제 A1, `a_axle × (1 + κ_max·track/2)`).
    - `T`: 표본 나이와 지연 상한, 루프 한 주기, 명령 마감의 합.
    - `b_min`: 탈출 정지 경로의 보수적 감속 하한, **잠정 0.3 m/s²**(측정 아님, S5 의 정지 실측으로 정함 — 계획 잠정값 표).
  - 0.20 m 는 증명된 물리 한계가 아니라 운용 한도다. 그 안전 근거는 사람 감시(S6 조건)다. 정지가 확인될 때까지의 이동은 기록하고 시험이 확인한다.
  - 시간: 4 s.
  - **DRIVE 마감은 탈출 마감(시작 + 4 s)과 다리 설계 6절의 마감 중 이른 것**이다.
- **정상 끝**(거리·시간·허가): 대기 DRIVE 를 버리고, 0 DRIVE(조향 유지)를 내고, 승인을 폐기한다. 다음 주기부터 일반 규칙이다. 허가 끝은 요청 방향 `d` 의 허가가 출력을 못 받치거나 중재기 자체의 목표가 0 이 된 경우다(제안 때는 0 이 아니었다).
  - **일반 규칙으로 넘김**(구현 때 확인): 끝난 순간 차가 아직 `d` 쪽으로 구르고 있으면 측정 방향이 `d` 하나뿐이다(`|signed| > e`). 그러면 `−d` 는 측정상 가능 방향이 아니어서 일반 규칙이 요청을 정상 상한으로 그대로 몰고 간다. 0.20 m 는 **예외 구간의 한도**이고, 넘긴 뒤의 주행은 일반 규칙의 안전 근거(측정 경계)로 판단한다. 운용자가 끝에서 손을 떼면 탈출 자신의 정지 경로만 남는다(시험: 관성 모형 네 경우 최종 이동 12–15 cm). 서서 다시 막히면 새 제안이다.
- **즉시 0 + STOP**(대기 DRIVE 폐기, DISARM, 중재기 STOP):
  - 데드맨을 놓음, 요청 방향이 바뀌거나 0 이 됨.
  - **바퀴별 역행 — 카운트로**: 바퀴마다 탈출 시작 뒤 `d` 쪽 진행(카운트 × `d`)의 지금까지 최댓값을 들고, 지금 값이 그 최댓값보다 **3 카운트**(약 7 µm) 넘게 뒤로 가면 STOP 이다. 속도 문턱으로는 보지 않는다(Codex 재검토 P1: −0.01 m/s 문턱 아래의 −0.005 m/s 지속 역행이 4 s 에 20 mm). 3 카운트는 양자화(±1)와 계수 흔들림의 허용량이다. 양바퀴가 서로 반대로 돌아 평균이 0 인 경우도 잡는다.
  - **예상 밖 회전**: `|yaw_rate| > 0.02 rad/s`(조향을 직진 허용오차 안에 묶은 직선 탈출이므로).
  - **바퀴별 과속**: 어느 바퀴든 `|v_w| > 0.05 + 0.02 m/s`.
  - 속도 무효, 운용자 STOP·lease 상실·무장 해제·세대 변경·재연결.
- 기록: 제안·승인(또는 거절과 사유)·시작·끝(사유, 바퀴별 누적 거리, 시간)을 다리 기록(JSONL, 주기 기록의 `escape_events`)과 상태 메시지(`escape`)에 남긴다. 콘솔에는 차량 이벤트(`event`, 종류 `escape_<단계>`, STOP 으로 끝나면 `escape_stop`)로 가서 로그에 남는다(Codex 구현 검토 P2-2).
  - **끝 뒤 이동**(Codex 구현 검토 P2-3): 끝 결정 뒤에도 바퀴별 누적 절대 이동을 이어 세어, 정지(`settled`), 일반 규칙이 다시 구동(`handed_over`), 부팅 변경(`settle_lost`), 5 s(`settle_timeout`) 중 먼저 온 것에 시작부터의 총 이동을 기록한다. 왕복은 둘 다 센다(MCU 모형에서는 0 명령 뒤 바퀴 PI 의 음 적분으로 뒤로 기어 가는 것도 들어간다).
  - 조향 이탈은 최신 판독만이 아니라 주기 사이의 모든 STATE 에서 본다(Codex 구현 검토 P2-1).

### 4.4 Isaac·시뮬
바뀌지 않는다. 중재기의 `escape` 처리기는 다리만 주입한다. `SafetySpeed`·코어 규칙은 그대로다. 1판에서 4e-2 에 넣었던 '시뮬 공급자 이전' 항목은 철회했다(총괄 2026-11-12).

### 4.5 C 를 택하지 않은 이유 (Codex)
'반대 방향은 최대 변위만큼만 비었는지 본다' 는 자동 허가가 된다. 그러려면 다음을 먼저 입증해야 한다.
- 지연 동안의 가속을 포함한 변위 상한(`U·T + ½·A·T² + (U + A·T)²/(2b)`)과, 루프가 늦어질 때의 지연 상한.
- 보장된 제동 감속.
- 바퀴 잠김 밀림과 회전까지 덮는 도달 영역.

또 지금 허가 API(시작 자세 검사, margin·step 포함)로는 '작은 속도' 를 넣는 방식이 그 거리 검사가 되지 않는다. 실익(격자에서 실제로 얼마나 풀리는지)도 먼저 측정해야 한다.

## 5. 시험

- 다리 주기(가짜 MCU, 실제 `McuLinkHost`·중재기):
  - 제안 조건: 신선한 정지가 아니거나 작용 중인 비영 명령이 있으면 제안 없음, 출력 부호가 승인 방향과 다르면 시작 안 함.
  - 승인 묶음: 세대가 바뀐 승인 거절, 탈출 중 재승인 거절.
  - 바퀴별 역행(양바퀴 반대 회전, 평균 0), 예상 밖 회전, 바퀴별 과속 → 즉시 STOP.
  - 정상 끝: 대기 DRIVE 폐기·0 DRIVE·승인 폐기, DRIVE 마감 ≤ 탈출 마감, 측정 끝 시점 식, 정지 확인까지의 최종 이동 ≤ 0.20 m(모형).
  - 끝 식의 `v`: 후진 탈출(부호 음)과 바퀴별 오차 폭이 다른 판독에서 `max_w(|v_w| + e_w)` 를 쓴다(5판).
  - 지연 중 가속: 판독 시점에 가속 중인 모형(전제 A1 의 가속), 늦게 효과를 내는 정지(`T` 전체), 명령 만료로 끝나는 경로 각각에서 최종 이동 ≤ 0.20 m(5판).
  - 끝에서 계속 누르면 일반 규칙으로 넘어감(측정 방향 `d` 하나일 때만 구동).
  - 문턱 아래 지속 역행(바퀴당 10 ms 마다 −21 카운트)도 STOP, 꺾인 조향에서는 제안 없음, 탈출 중 조향 이탈 STOP.
  - 조향 고정(곡률 요청 무시).
  - 뒤 허가 0 인 벽 앞: 앞 요청 → hold → 제안 → 승인 → 연속 비영으로 이동 → 측정 끝 시점에서 끝 → 일반 규칙.
  - 요청 방향 자체가 막힌 경우(앞 허가 0): 제안 없음.
  - 같은 제안으로 두 번 승인: 두 번째 거절. 새 hold 뒤 새 제안은 됨.
  - 즉시 0 + STOP: 데드맨 놓음, 반대 방향 측정 운동(카운트 감소), 속도 무효, 운용자 STOP, 요청 반전.
  - 속도 0.05 이하, 시간 4 s 끝.
  - 기록·상태 메시지의 `escape_offer`·`escape`.
- 중재기: `escape` 처리기 없음 → `unsupported`(Isaac 그대로), 형식·lease·세대 검사.
- 콘솔: 제안이 있을 때만 버튼, 누르면 `escape_approve` 송신(`node --test`).
- 종단(MCU 모형): 벽 앞 탈출 한 번.
