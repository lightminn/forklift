# WeAct H743 모터 출력 경로 (잠금 게이트 뒤)

작성일: 2026-11-12 · 상태: **설계 초안, 실기 없음** · 관련: [보드 설계](2026-11-12-weact-h743-board-firmware.md) 2.2·3.6·9절, [코어 설계](2026-10-22-mcu-firmware-core.md) 4절(출력 매핑·정지 출력), [실차 이식 계획](../plans/2026-11-11-sim-to-real-bringup.md) 3.4·5절 S3, 총괄 배정 2026-11-12

## 1. 목적과 경계

- S3(축별 개루프)에 필요한 출력 코드 — TIM1 PWM, nSLEEP 깨우기, DRVOFF·PH 구동 — 를 미리 만들어 둔다. **코드를 머지하는 것은 출력을 켜는 것이 아니다.** 출력이 열린 ELF 를 만들어 차량에 쓰는 것은 IPROPI 보호를 확인한 뒤의 **사용자 결정**(총괄 Q6)이다. 이 문장을 빌드 거부 메시지에도 그대로 적는다.
- 기본 빌드는 바뀌지 않는다: `FW_MOTOR_OUTPUT=0`, `motor_out_locked.c`, TIM1 오브젝트 없음, `STATE.flags` bit6.

## 2. 구성 게이트

| 조건 | 결과 |
|---|---|
| `FW_MOTOR_OUTPUT=1` 이고 `FW_IPROPI_PROTECTION_RECORD` 없음 | 구성 거부(메시지: 출력은 IPROPI 보호 확인 뒤 사용자 결정, 코드 빌드는 그 결정이 아님) |
| 기록이 펌웨어 소스의 git 저장소에 **커밋되어 있지 않음**(추적 안 됨), 또는 작업 트리·인덱스에서 수정됨 | 구성 거부(총괄 조건 1) |
| 기록에 표지 줄이 없음: `IPROPI protection record: confirmed-by=<확인자>; date=<YYYY-MM-DD>; evidence=<보호 회로 실측 값이 있는 위치>` | 구성 거부 |
| `FW_BUILD` 가 `normal`(비상정지 핀 없음 — Q3 로 어차피 ARM 거부)·`hil`·`FW_TEST_IWDG_STALL` 과 함께 | 구성 거부. 지금 허용되는 출력 열린 조합은 `commission` 뿐 |
| 위를 모두 통과 | `motor_out_tim1.c` 를 컴파일. 빌드 정체·USB 제품 문자열이 `forklift-mcu commission OPEN <git> rec=<기록 HEAD blob sha256 앞 8자>` 이고, 코어 설정 `outputs_locked=false`(bit6 꺼짐). 실차 실행기는 이 보드를 시운전 빌드로 거부한다(`commission_build`) |

- **기록 검사 계약**(Codex P2-6): 경로는 펌웨어 소스가 든 git 저장소 안의 상대 경로이고, 작업 트리의 그것은 **일반 파일**(심볼릭 링크 거부 — 커밋된 링크는 대상 문자열만 저장하므로 밖의 미커밋 파일을 가리킬 수 있다)이다. `HEAD` 에 그 경로의 blob 이 있어야 하고(`git cat-file -e HEAD:<경로>` — 인덱스에만 있는 "추적됨"은 커밋이 아니다), 인덱스가 `HEAD` 와 같고(`git diff --cached --quiet HEAD -- <경로>`) 작업 트리 파일의 바이트가 `HEAD` blob 과 같아야 한다(`git hash-object --no-filters <경로>` = `git rev-parse HEAD:<경로>`) — `git diff HEAD` 하나로는 HEAD=A·인덱스=B·작업 파일=A 를 놓치고(Codex 2라운드), `git diff` 는 assume-unchanged·skip-worktree 표시가 붙은 파일을 건너뛴다(Codex 코드 검토). 표지 검사와 해시는 **`HEAD` blob 의 바이트**(`git show HEAD:<경로>`)로 한다. 이 검사를 구성 단계와 **매 빌드**(빌드 정체처럼 항상 도는 대상)에서 되풀이한다 — 구성 뒤 기록을 고치거나 지우고 같은 빌드 디렉터리를 다시 쓰면 빌드가 실패한다.
- **그 기록을 쓰고 커밋하는 것 자체가 사용자 결정(Q6)이다. 에이전트는 이 기록을 만들지도, 대신 커밋하지도 않는다.** 이것은 작업 규칙이다 — 표지·커밋·해시는 작성자가 사람인지 인증하지 않는다(Codex). 내용(보호 회로, 핀 전압 실측, 결정 날짜)은 사람이 쓴다. 펌웨어 빌드는 커밋 여부·표지 줄 형식·해시만 본다 — 내용의 진위를 판정하지 않는다.
- 시험은 저장소 밖 임시 git 저장소에 펌웨어를 복사하고 가짜 기록을 커밋해 구성 단계를 돌린다(커밋됨 → 구성, 추적 안 됨·수정됨·표지 없음 → 거부).
- TIM1 이름은 `motor_out_tim1.c` 한 파일에서만 쓴다. 다른 보드 소스는 출력 빌드에서도 `lock_guard.h` 의 poison 을 받는다.

## 3. 출력

- **모드**: DRV8244 PH/EN(코어가 `CONFIG3.S_MODE=00b` 를 강제). EN/IN1 = PWM, PH/IN2 = 방향(SLVSG24C 표 8-4). 채널 L/R/M/H:

  | 채널 | EN/IN1 (TIM1, AF1) | PH/IN2 | DRVOFF |
  |---|---|---|---|
  | L | PE9 CH1 | PE2 | PD9 |
  | R | PE11 CH2 | PE6 | PD10 |
  | M | PE13 CH3 | PE4 | PD13 |
  | H | PE14 CH4 | PE5 | PD14 |

- **핀이 출력을 정한다는 전제**(SLVSG24C 8.3.2.4·8.6.1.5): DRV8244S 는 `SPI_IN` 레지스터 비트를 핀과 AND/OR 로 묶을 수 있지만, 그 결합은 `SPI_IN` 이 **풀렸을 때만** 쓰인다. `SPI_IN_LOCK` 리셋값은 01b(잠김)이고 푸는 값은 10b 뿐이다. 코어는 COMMAND 를 쓸 때마다 01b 를 유지한다(`drv8244.c` 3–4행) — 그래서 DRVOFF·EN·PH 는 핀만으로 정해지고, `CONFIG4.DRVOFF_SEL=1`(리셋값, 코어 설정 0x04)의 AND 결합은 적용되지 않는다. 이 전제를 호스트 시험으로 고정한다(코어가 내는 COMMAND 프레임의 bit 4–3 이 10b 가 아님). `S_MODE` 리셋값도 00b(PH/EN)이고, 코어가 초기화 때 다시 쓰고 읽어 확인한다.
- **PWM**: TIM1 커널 200 MHz, PSC 0, ARR 9,999 → **20 kHz**(DRV8244 최대 25 kHz, SLVSG24C 1절), 가장자리 정렬 PWM 모드 1, 비교값 = round(|duty| × 10,000). **비교·자동 재적재 미리 적재를 켠다**(`OCxPE=1`, `ARPE=1`) — RM0433 Rev 7 PWM 모드 절: 미리 적재를 켜야 하고 카운터 시작 전 `UG` 로 모든 레지스터를 초기화한다(Codex P2-1). 새 비교값은 다음 갱신 사건(UEV, 50 µs 안)에 반영된다. 데드타임 0 — 드라이버가 자동으로 넣는다(SLVSG24C 8.3.2). `BDTR`: `OSSI=OSSR=1`, `OISx=0`, `MOE=1` 은 시작 때 한 번, `AOE=0`.
- **디버거 정지**: `DBGMCU APB2FZ1.DBG_TIM1=1` — 코어가 멈추면 TIM1 이 서고 출력이 꺼진다(RM0433 DBGMCU, "outputs are disabled"). EN 이 idle(low)로 가므로 DRVOFF low 인 채널은 제동, high 인 채널은 차단. IWDG 는 멈추지 않아 약 50 ms 뒤 리셋된다(보드 설계 3.5) — 단 **DBGMCU 레지스터는 시스템 리셋으로 지워지지 않으므로**(RM0433 Rev 7 DBGMCU 절, 전원 리셋만) 지난 디버그 세션이 `DBG_IWDG1`(APB4FZ1 bit 18)을 켜 두었을 수 있다. 그래서 `iwdg_start` 가 **모든 빌드에서** 이 비트를 지우고 다시 읽어 확인하며, 지워지지 않으면 부팅 실패로 본다(Codex P2-4). 리셋 전에 디버거가 다시 진행시키면 TIM1 은 마지막 비교값으로 출력을 다시 낸다(재무장 래치 없음). 코어는 시간 공백 자체로는 세우지 않는다 — 만료는 명령 마감 초과로만 판정한다(`drive.c` 589행) — 그래서 유효기간 150 ms 명령 직후 10 ms 정지했다 재개하면 남은 유효기간 동안 출력이 이어진다(Codex 2라운드). **받침대 전용 잔여 위험**이며 디버거 정지·재개는 받침대(바퀴 띄움)에서만 한다.
- **채널 갱신 순서**(매 주기, `write_outputs`):
  - `drvoff`: **DRVOFF high 먼저**, 그다음 비교값 0.
  - 구동, 같은 방향: 새 비교값(다음 UEV 에 반영), DRVOFF low 는 마지막.
  - **방향 전환**(Codex P2-1, 2라운드): 먼저 비교값 0 만 쓰고 PH 는 그대로 둔다(그 채널은 제동 쪽 — EN low). PH 는 **그 0 뒤에 갱신 사건이 있었다고 확인된 뒤의 호출**에서만 바꾸고 새 비교값을 쓴다. "다음 호출"은 증거가 아니다 — 처리 중 다음 TIM6 갱신이 대기하면 반환 직후 다시 들어온다. 그래서 TIM1 자신의 `UIF` 로 판정한다: 호출 첫머리에 읽고, 호출의 모든 쓰기가 끝난 뒤 지운다(rc_w0). 첫머리에 `UIF` 가 서 있으면 지난 호출 끝 — 그 호출의 모든 0 쓰기 뒤 — 이후 갱신이 있었다는 뜻이다. 지운 뒤와 0 쓰기 사이에 끼는 갱신은 지워져 잃을 뿐이다(안전 쪽, 한 번 더 기다림). 0 이 아닌 비교값을 다시 쓰면 그 채널의 확인은 무효가 된다. 방향을 바꾼 채널은 최소 한 호출 동안 출력이 0 이다(코어의 바퀴 듀티는 방향이 바뀌면 어차피 0 부터 다시 오른다).
  - **차단에서 나올 때**(구현 시험에서 찾음): 차단 때 쓴 0 이 아직 활성이 아니면(갱신 미확인) DRVOFF 를 내리는 순간 옛 비교값이 옛 방향으로 다시 구동한다. 그래서 차단된 채널은 그 0 이 확인될 때까지 차단으로 남는다.
  - `duty = 0`, `drvoff = false` 는 EN low 상시 → 제동(OUT1=OUT2=H). 코어의 `safe_brake` 채널 정지 상태다.
- **nSLEEP**: `board_hal_init` 이 드라이버를 깨운다(S2 와 같음). 결함 처리기는 내린다. 깨운 뒤 SPI 까지 1 ms(`driver_wake_us`, tREADY 최대 1 ms, SLVSG24C 7.5)를 코어가 기다리고, 드라이버 설정 확인(`drivers_ready`) 전에는 코어가 모든 채널을 차단(DRVOFF high)으로 둔다. nSLEEP 은 네 드라이버가 공유한다(회로도 MTR_SLEEP) — 한 축만 시운전해도 넷이 깨어나고, 다른 축은 코어가 듀티 0·정지 출력으로 둔다.
- **시작 순서**: `motor_out_safe_init`(시작 코드 다음 첫 단계)이 레벨을 먼저 쓰고 MODER 를 바꾼다(지금과 같음 — 출력으로 바뀌는 순간 안전 레벨). TIM1 은 `board_hal_init` 에서 비교값 0·`MOE=1`·카운터 시작까지 마친 뒤 PE9/11/13/14 를 GPIO low 에서 AF1 로 바꾼다 — 바뀌는 순간 TIM1 출력은 이미 0 이다.
- **디버거 정지 때 제동**(agy): DRVOFF low 채널은 EN low 로 제동(두 하이사이드 켬, 슬로 디케이 — 전류는 브리지 안에서 돌고 VM 으로 돌아가지 않음)이 최대 약 50 ms(IWDG) 걸린 뒤 리셋으로 SLEEP(코스트). 디버거 정지는 받침대(바퀴 띄움)에서만 쓴다.

## 4. 차단 경로와 보장 방법

| 경로 | 무엇이 끊나 | 보장 |
|---|---|---|
| IWDG 리셋 | 하드웨어 주장(4.1) — 소프트웨어 시험으로 증명하지 않는다 | 근거 4.1, 실측 S5 `fw_iwdg_stall` |
| NMI·HardFault·예상 밖 IRQ | `motor_out_force_safe`: DRVOFF high → TIM1 `MOE=0`·비교값 0 → nSLEEP low. 레지스터 쓰기만 | 레지스터 모형: 어느 구동 상태에서 불러도 전 채널 차단 |
| 명령 만료·`DISARM`·nFAULT·비상정지 | 코어가 그 채널의 정지 출력(차단 또는 제동)을 낸다 | 레지스터 모형 + 코어: 사건 주기에 그 채널 상태가 설정된 정지 상태 |
| 시운전 상한 | 코어가 0.15 넘는 듀티를 거부하고(이전 명령 유지) 시간 상한 뒤 정지 | 레지스터 모형 + 코어: 비교값 ≤ 1,500, 상한 뒤 정지 상태 |

### 4.1 IWDG 리셋 때 출력이 꺼진다는 근거 (하드웨어 주장, 총괄 조건 3)

- MCU 쪽: 리셋 동안과 직후 대부분의 GPIO 는 아날로그 모드다(RM0433 Rev 7 11.3.1). 예외인 디버그 핀(PA13–15, PB3, PB4)은 모터 핀이 아니다. 모터 핀 PB0·PD9/10/13/14·PE2/4/5/6/9/11/13/14 는 떠 있고, 새 펌웨어의 `motor_out_safe_init`(시작 코드 다음 첫 단계)이 다시 잡을 때까지 그렇다. 떠 있는 FT 핀의 누설은 최대 ±250 nA(DS12110 Rev 7 I/O 정적 특성).
- 드라이버 쪽(DRV8244S, SLVSG24C 7.5.2): nSLEEP 내부 풀다운 100–400 kΩ, EN/IN1·PH/IN2 내부 풀다운 200–500 kΩ, DRVOFF 내부 풀업(내부 VDD 로) 200–550 kΩ. 메인보드 회로도 V1.0 1쪽에는 이 네 선에 외부 저항이 없다(nFAULT·nSCS 에만 2.2 kΩ 풀업).
- 계산: nSLEEP 은 네 드라이버가 한 선(MTR_SLEEP)을 공유해 풀다운 넷이 병렬(25–100 kΩ)이고, 최악 누설 250 nA × 400 kΩ(하나만 있다고 봐도) = 0.10 V < VIL 0.65 V → **SLEEP, 출력 Hi-Z**(표 8-4 첫 줄 — DRVOFF·EN·PH 와 무관). EN·PH: 250 nA × 500 kΩ = 0.125 V < VIL 0.7 V. DRVOFF 는 풀업이 이기면 high(두 번째 층)지만, 풀업 전압(S 변형의 내부 VDD)이 데이터시트에 없어 이 층의 여유는 계산하지 않는다 — **차단은 nSLEEP 하나로 성립**한다.
- **주장의 범위**(Codex P2-3): 위 계산은 정상 전원에서 핀이 떠 있을 때 **최종적으로 SLEEP 으로 수렴**한다는 것까지다. 리셋 직전 nSLEEP 은 high 이므로, Hi-Z 로 바뀐 뒤 공유 선의 용량이 풀다운으로 방전되고 DRV8244 의 nSLEEP 슬립 필터(5–20 µs, SLVSG24C 7.5.1)를 지나야 SLEEP 이 된다. 그 사이 EN·PH·DRVOFF 도 각자의 RC 로 바뀌므로 PH 가 먼저 바뀌는 순간적인 반대 방향 구동을 계산으로 배제하지 않는다 — **리셋에서 차단까지의 시간과 그 사이 모터 단자 파형은 S5 실측 항목**이다.
- 남는 위험: 리셋이 오기까지(주기 정지 → IWDG 만료 47.6–53.8 ms) 출력은 마지막 상태를 유지한다. 전원 레일 순서·Jetson 쪽 역전원은 이 주장 밖이다.
- **S5 실측**(총괄 결정 2026-11-12 (A) — stall 빌드의 출력 잠금 조건은 그대로):
  - ① 잠금 stall 빌드(`fw_iwdg_stall.elf`): '주기 정지 → 리셋' 시간. STATE 공백의 길이와 다음 부팅의 `reset_cause = iwdg`(`bringup.py record --markers` → `analyze --kind iwdg`).
  - ② 보호 기록이 있는 출력 열린 시운전 빌드: 받침대·최저 듀티로 바퀴 하나를 돌리는 중 WeAct 의 NRST 버튼을 누른다. '리셋 → 차단' 과도 — MTR_SLEEP·DRVOFF·EN·PH 핀 전압, 모터 단자 전압, 모터 전류(전류 프로브 또는 션트)를 오실로스코프(2채널 이상)로 잰다. 모든 리셋 원인에서 핀이 아날로그로 가는 것은 같다(RM0433 11.3.1).
  - 한계: IWDG 리셋과 NRST 버튼 리셋은 리셋 펄스 길이가 다르다. ①과 ②를 합쳐도 이 차이는 남는다.
  - 오실로스코프가 없으면 ②를 미루고 ①만 한다(도착일 절차서의 분기).
  - 핀 전압이 위 계산과 다르면 S5 를 멈추고 질문으로 올린다.

### 4.2 레지스터 모형

- 레지스터 모형: `motor_out_tim1.c` 를 호스트에서 가짜 장치 헤더(같은 레지스터 이름의 구조체, 전역 인스턴스)로 컴파일한다. 레지스터 쓰기는 모두 한 매크로(`MO_WR(reg, v)`)를 거치고, 호스트 빌드에서는 쓰기마다 해석기를 돌려 **중간 상태까지** 검사한다(Codex P2-2).
- 해석기(RM0433 TIM1 출력 제어 기준): 핀마다 MODER(아날로그·입력 = 떠 있음 → DRV 내부 풀, 출력 = ODR, AF = TIM1 채널). TIM1 채널 출력은 `MOE`·`CCxE`·`CCxP`·`OSSI/OSSR`·`OISx` 로 정하고, 활성일 때 레벨은 OCxM(PWM 모드 1 만 허용 — 다른 값이면 시험 실패)과 **활성(shadow) 비교값**·`CNT`·`CEN` 으로 낸다. `CEN=0` 은 차단이 아니다 — `CNT < 활성 CCR` 이면 EN 은 상시 high 다(Codex 반례 `CEN=0, CNT=0, CCR=1500, MOE=1, CCxE=1` 은 100 % 구동으로 해석돼야 한다). 미리 적재 값은 모형의 UEV(주기 사이에 시뮬레이션)에서만 활성으로 옮긴다. 결과는 채널마다 표 8-4 의 `SLEEP·STANDBY·BRAKE·FWD(d)·REV(d)`.
- 쓰기마다의 불변식: (a) 시험이 그 순간 허용한 방향 밖으로 구동하지 않는다 — 방향 전환 시험은 전환 전에는 옛 방향만, 전환 뒤에는 새 방향만 허용한다. (b) **PH 를 바꾸는 쓰기의 순간 그 채널은 구동 중이 아니다**(EN low 또는 꺼짐, Codex 2라운드 — (a) 만으로는 두 방향을 다 허용하는 구간에서 잘못된 구현이 통과한다). (c) 차단 사건에서 그 채널에 대한 첫 쓰기는 DRVOFF high 다(쓰기 기록).
- 갱신 사건 주입: 모형은 호출 사이에 갱신이 없는 경우(같은 호출을 연달아)와, 호출 안의 k 번째 쓰기 직후 갱신이 끼는 경우(k = 1…40 전수)를 돌린다.
- 시운전 듀티: 0.15 를 넘는 COMMISSION 은 잘리지 않고 **거부**된다(`BAD_VALUE`, `drive.c` 768행) — 기존 유효 명령과 마감이 유지된다(Codex P3-7). 시험은 "거부, 이전 듀티 유지, 비교값 ≤ 1,500"을 본다.
- 하드웨어로만 증명되는 것: 실제 PWM 파형·주파수, 리셋 때 핀 전압, 정지 시간·거리(S5).

## 5. 넣지 않는 것

- TIM1 브레이크 입력(BKIN, 비상정지 배선 전), PWM 중앙 동기 ADC 표본, 전류 조절. 출력이 열린 `normal` 빌드(비상정지 입력 배선 뒤 별도).
