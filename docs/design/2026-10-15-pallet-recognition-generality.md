## 1. 배경과 사용자 결정

리보틱스와의 회사 미팅에서 회사가 현장에서 실제로 겪는 인식 어려움으로 다음을 들었다 — 색이 다른 팔레트, 비규격 팔레트, 일부 파손 팔레트, 복잡한 배경, 옆·위·앞뒤로 여러 개 놓인 팔레트.
지금 검출기(`src/forklift_core/perception/pocket_detector.py`)는 형상 prior 를 아는 **단일 팔레트 depth 기하 기준선**이라 이 목록 밖이다. 2026-10-15 Codex 교차검증에서 확인한 한계는 다음과 같다.

| 한계 | 근거 |
|---|---|
| 형상 prior(YAML)를 명시 주입해야 하고 개구 폭·블록 폭 허용 범위가 그 값에 묶인다 | `pocket_detector.py` `_opening_candidates` 486행, `config/pallet_prior_*.yaml` |
| 높이 대역이 바닥(z=0) 기준이고 팔레트 높이 + 0.10 m 위 점을 버린다 → 위층 팔레트는 후보가 못 된다. 단독 팔레트를 한 층 올린 CPU 확인에서 두 형상 모두 `no_opening_pattern` | `pocket_detector.py:327–336`, `:404`, `:669` |
| "블록–개구–블록–개구–블록 + 개구별 상판" 패턴 전부가 관문이다 → 상판 결손·가림이면 거부 | `pocket_detector.py:516–600`, `:792–806` |
| 최고 점수 하나를 먼저 고른 뒤 상판 검사를 하고, 떨어지면 차순위를 보지 않는다. 나란히 놓인 두 팔레트에서 "포켓 + 팔레트 사이 틈" 가짜 쌍이 최고 점수가 되어, 통과할 진짜 쌍이 있는데도 `invalid` 가 나는 것을 Codex 가 EPAL 6·T11 × 0.6 모두 CPU 합성 depth 로 재현했다(바깥 포켓 부분 가림 조건; 가림 없는 나란히 배치는 정상) | `pocket_detector.py:776–806` |
| 정상 EPAL 6 와 `grounded`(바닥판 없이 블록이 바닥까지 내려온 구조물)를 중심 x = 3 m 에 각각 두면 **둘 다 `valid` 이고 포켓 좌표도 같다** → depth 기하만으로는 B(팔레트 닮은 구조물)를 가를 수 없다 | Codex CPU 확인(2026-10-15), ADR 0003 §3.2·부록 B-8 |

사용자 결정(2026-10-15, 같은 대화):

1. 첫 하위 과제는 **여러 팔레트 분리·대상 선택 + 복잡한 배경 오검출**이고, **비규격도 이번에 포함**한다.
2. **일부 파손 팔레트는 거부하지 않고 완벽한 팔레트처럼 안정적으로 집는다.** 대상 파손은 **상판 일부 결손·깨짐, 블록 일부 파손**이다(하판 결손·구조 손상은 제외).
3. **대상 선택 = 작업 지시 + 자율 보완.** 작업 지시(콘솔·임무)가 대략 위치를 주면 그 근처 후보를 고르고, 지시가 없으면 접근 가능한 가장 가까운 팔레트를, 애매하면 콘솔에서 고르게 한다.
4. **적층은 층별 인식 + 지시된 층 집기**지만 **단계를 나눈다** — 이번 설계는 층별 후보 출력까지, 적층 집기는 바로 다음 설계다.
5. **성공은 Isaac 사례별 장면 + 지표로 보인다**(지금 검출기 대비). 실물은 팔레트·센서가 준비되면 같은 지표로 잰다.
6. 방법은 **학습 기반 인스턴스 분할 + 인스턴스별 depth 기하 맞춤**이다(사용자 질문 "YOLO 커스텀?"에 대한 답으로 제시, 최종 모델 선택은 §6).

## 2. 범위

| 포함 | 제외 (다음 설계 또는 별도 과제) |
|---|---|
| 바닥 위 팔레트의 인식 → 대상 선택 → 접근 → 삽입 → 들기 → 운반, 사례 S1–S3·S5–S7 | 적층 집기(위층 정렬·승강 계획·D5 높이 확장·근접 추적 층 구별·임무의 `top_one`/`whole_stack`) — **다음 설계** |
| 적층(S4)의 **층별 후보 출력**과 층 높이 추정 정확도 | 비규격 + 파손 조합의 위치 확정(원리적으로 모호 — 재관측·콘솔 확인으로 넘긴다) |
| 알려진 형상 EPAL 6·T11 × 0.6 (형상별로 따로 합격) | 하판 결손·블록 통째 결손·판 부러짐에 의한 처짐(구조 손상) |
| 비규격: 매개변수형 진입면 모델로 인식·포크 끼움 검사·바닥 집기 | 재질 때문에 생기는 depth 품질 문제(검정·광택 플라스틱·젖은 표면) — 실센서 측정이 필요한 과제 D |
| 색·조명·배경 겉모습 변화(학습 데이터 무작위화로) | 실물 데이터 수집·실물 평가(준비되면 같은 지표로) |
| 학습 모델의 Jetson 실행 가능성 측정(지연 기록) | 다중 지게차·FMS 연동 |

**바꾸지 않는 것.** 센서 구성(마스트 D435i + RPLIDAR A2M12 — 규격 변경 금지 결정), `PocketObservation` 을 삽입 제어기 입력 타입으로 두는 계약(ADR 0003 1-a), ADR 0004 D6 의 음성 모집단 분리와 dev/eval 규칙, 삽입 깊이 규칙(ADR 0004 D3).

## 3. 성공 기준

### 3.1 문턱은 작업에서 유도한다

포크 실측(`sim/models/dls08_measured/README.md`): 날 폭 55 mm, 두께 25 mm, 길이 0.36 m, 승강 0.28 m. 형상 치수는 `config/pallet_geometry_*.yaml`.

| 형상 | 개구 폭 | 개구 높이 | 날 한쪽 가로 여유 (개구 − 55)/2 | 세로 여유 (개구 높이 − 25)/2 |
|---|---|---|---|---|
| EPAL 6 | (0.800 − 0.100 − 0.145 − 0.100)/2 = 227.5 mm | 78 mm | 86.25 mm | 26.5 mm |
| T11 × 0.6 | (0.660 − 3 × 0.080)/2 = 210 mm | 45 mm | 77.5 mm | 10 mm |

- **가로 위치 p95 ≤ 20 mm** — 작은 쪽 가로 여유 77.5 mm 중 인식 몫. 나머지는 주행 추종·yaw 에 의한 끝 이동·모델 오차 몫이다(기존 M2 목표와 같다).
- **yaw p95 ≤ 2°** — 삽입 0.30 m 끝에서 0.30 × tan 2° = 10.5 mm.
- **높이(z) p95 ≤ 세로 여유의 절반** — EPAL 6 13 mm, T11 × 0.6 5 mm. 바닥 팔레트는 포크 최저 위치가 높이를 정하므로 **S4(층)·S7(비규격 높이)에만 판정**하고 나머지는 기록한다. 비규격은 관측한 개구 높이로 같은 식을 쓴다.
- **위험 오위치** — `valid` 로 나간 후보의 포켓 가로 오차가 **40 mm**(작은 가로 여유의 약 절반)를 넘으면 별도로 센다. 이것이 0 이어야 한다는 것이 아래 상한 판정의 대상이다. (ADR 0003 이 지적한 "p95 만 보고 최대 오차를 안 보는" 판정 구멍을 막는다.)

### 3.2 학습 모델이 들어가므로 통계 상한으로 판정한다

학습 모델은 해석적 보장이 없고, 숫자는 **시험한 장면 모집단에서의 통계**다. 그래서 비율 지표는 관측값이 아니라 **단측 95 % Clopper–Pearson 상한**으로 판정하고, 장면 수를 그 상한에서 역산한다(ADR 0004 D6 와 같은 방식).
실패 0건으로 상한 p 를 보이는 데 필요한 장면 수: 5 % → 59, 10 % → 29, 15 % → 19, 20 % → 14. 실패 1건을 허용하면 5 % → 93, 10 % → 46, 15 % → 30 (`scipy.stats.beta.ppf(0.95, k+1, n−k)`, 2026-10-15 계산).
Isaac 에서 낸 숫자는 **Isaac 무작위화가 덮은 범위에서만** 성립한다. 실물 성능 주장에는 실물 eval 이 따로 필요하다.

### 3.3 지표와 합격선 (개발 전에 고정, dev 결과를 보고 고치지 않는다)

**인식 단계** — 정지 렌더 장면, eval 분할. 알려진 형상(EPAL 6, T11 × 0.6)은 형상별로, S7 은 비규격 모집단 하나로 판정한다:

| 지표 | 정의 | 합격선 |
|---|---|---|
| 놓침률 | 정답 인스턴스(진입 가능한 면이 보이는 것) 중 위치 조건(가로 ≤ 0.20 m, \|yaw\| ≤ 0.35 rad — 기존 대응 문턱)을 만족하는 `valid` 후보가 없는 비율 | **알려진 형상별 S1–S6 통합 상한 ≤ 5 %**, 사례·형상별 상한 ≤ 15 %, S7 비규격 모집단 상한 ≤ 15 % |
| 위험 오위치율 | `valid` 후보 중 가로 오차 > 40 mm 인 비율 | 형상별 통합 상한 ≤ 5 % |
| 포켓 오차 | 대응된 `valid` 후보의 가로·yaw·z 오차 p95 | §3.1 의 값. **S5(파손)·S7(비규격)도 같은 값** |
| 대상 선택 오류 | 작업 지시가 있는 장면에서 지시와 다른 인스턴스·층을 고르거나, 애매한데 콘솔 확인 없이 고른 비율 | 상한 ≤ 5 % (형상 통합) |
| 음성 오검출 | 음성 모집단(N)에서 `valid` 후보를 하나라도 낸 장면 비율 | 상한 ≤ 10 % (§13 결정 필요) |
| 포크 끼움 판정 | S7 에서 끼움 가능/불가 판정이 정답과 다른 비율 | 상한 ≤ 5 % |
| 처리 지연 | 장면당 전체 인식 시간(ws1 기준) + Jetson 측정값 | 기록만(합격선 아님) |

사례별 장면 수는 위 상한에서 정한다. 사례별 상한 15 % 를 실패 0건으로 보이려면 사례·형상당 eval 19, 통합 5 % 는 형상당 eval 59 이상이다. 사례당 eval 19 × 6 사례(S1–S6) = 114 ≥ 59 이므로 형상 통합 조건은 사례별 수로 충족되고, 114 장면이면 실패 1건까지(5 % 상한에 실패 1건은 93 장면, 2건은 124 장면 필요) 통합 합격선 안이다. ADR 0004 D6 의 분할 관행(eval = ⌈0.3 × 총⌉ — 총 44 → eval 14, 총 94 → eval 29)을 따르면 사례·형상당 총 61 장면(dev 42, eval 19), S7 은 비규격 모집단 총 61, 음성 N 은 총 94(eval 29).

**임무 단계** — Isaac 운반 임무(인식 → 선택 → 접근 → 삽입 → 들기 → 운반 → 내리기), 바닥 사례:

| 사례 | 합격선 |
|---|---|
| S1·S2·S3·S5·S6 각 형상, S7 | 사례당 20회 중 19회 이상 성공(로드맵 A–D 와 같은 기준). 이 기준의 실패율 상한은 21.6 % 로 약하다는 것을 결과에 같이 적는다 |
| S5 파손 | 위 기준 + 들기·운반 중 팔레트 기울기·미끄러짐이 정상 팔레트 실행의 최대값을 넘지 않을 것(실행 기록의 팔레트 자세로 판정) |

**기준선.** 같은 장면·같은 임무에 지금 검출기 결과를 함께 낸다.

## 4. 구조

```text
RGB-D 프레임 ──┬─> [제안기] 인스턴스 마스크 목록 (학습 모델 / 기하 제안 / 정답 마스크)
               │
               └─> [인스턴스 기하 맞춤] 마스크마다: 진입면 평면 → 받침면 높이 → 형상 가설 경쟁
                                     → PocketCandidate (자세·포켓·층·형상·증거 범위·상태)
                                                │
          작업 지시(대략 위치·허용 오차·층) ──> [대상 선택] → 선택된 PocketObservation
                                                │            / "콘솔 확인 요청" / "대상 없음"

                                                ▼
                    [근접 추적] 이 팔레트의 관측된 형상(손상 지도 포함)을 템플릿으로 인계
                                                │
                                                ▼
                       [포크 끼움 검사] · [D5 포켓 확인] · 삽입 제어(기존)
```

## 5. 장면 생성과 정답

### 5.1 사례 조리법 (CPU, 시드 결정적)

| 사례 | 구성 | 무작위 축 |
|---|---|---|
| S1 단독 | 기존 접근 자세 분포 | 거리 1.1–4 m, 상대 yaw ±30°, 측방 ±1 m |

### 5.2 손상 연산 (S5)

알려진 형상의 상자 모델(`pallet_boxes`)에 적용하고, 정답 파일에 연산과 매개변수를 남긴다.

| 연산 | 매개변수 범위 |
|---|---|
| 상판 결손 | 상판 7장 중 1–2장 제거(포켓 위 판 포함) |
| 상판 깨짐 | 판 하나를 길이 방향 20–60 % 지점에서 잘라 한쪽 조각 제거 |
| 블록 모서리 파손 | 블록 하나의 진입면 쪽 모서리를 깊이·폭 10–40 mm 깎음(블록 부피의 30 % 이하) |
| 블록 쪼개짐 | 블록 하나를 세로로 갈라 5–15 mm 틈 |

손상은 팔레트의 질량·접촉 모델에도 똑같이 반영한다(렌더와 물리가 같은 상자 목록에서 나온다).

### 5.3 렌더와 정답

- **렌더:** Isaac 5.1(ws1, Slurm `compute`, `--gres=shard:N`)에서 RGB, `distance_to_image_plane` depth, Replicator `instance_segmentation` 을 같은 프레임으로 받는다. 지금 데이터 계약(`scene_dataset.py` — TF `received_tf_static`, depth uint16 mm `optical_axis_z`)을 지키고, 다중 인스턴스 정답을 담는 **스키마 판 2** 를 추가한다(판 1 은 그대로 읽는다).
- **정답(인스턴스마다):** 인스턴스 ID, 형상(알려진 형상 이름 또는 매개변수), 층 번호와 받침면 높이, 진입 가능한 면 목록(정사각 T11 은 네 면 — ADR 0003 §3.3 의 등가 진입면), 면마다 포켓 중심·폭·높이, 손상 연산, 포크 끼움 정답(현재 포크 간격 기준), 화면 노출 비율.
- **작업 지시(장면마다):** 대상 인스턴스와 그에 대한 대략 위치(지도 좌표 + 허용 반경), 층. 일부 장면은 지시 없음, 일부는 일부러 애매한 지시(허용 반경 안에 둘).
- **분할:** 평가 장면은 사례·형상마다 dev/eval 70/30. **학습 데이터는 별도 시드 대역과 별도 조리법(무작위화가 더 강함 — 재질·색·조명·방해물·카메라 자세)** 으로 만들고 평가 장면과 시드·배치가 겹치지 않음을 생성기가 검사한다. 방법 선택(학습 대 기하, 모델 크기, 입력 채널)은 dev 에서만 하고, eval 은 최종 파이프라인에 한 번 돌린다.

## 7. 인스턴스 기하 맞춤

### 7.1 매개변수형 진입면 모델

진입면을 위에서부터 **상부 덱 띠 / 개구·블록 열 / 하부 덱 띠**의 세 층으로, 개구·블록 열을 좌우 배치로 표현한다: 블록(또는 스트링거 끝) 수 m ∈ {3, 4}, 블록 폭 wᵢ, 개구 폭 oⱼ, 개구 높이 h, 상·하부 덱 두께, 전체 폭 W. 알려진 형상은 `PalletGeometry` 값 ± 공차의 좁은 범위로, 비규격은 §5.1 의 넓은 범위로 둔다. 2방향 스트링거형은 진입면이 블록형과 같은 배치(m = 3)로 보이므로 같은 모델을 쓰고, 옆면에서 개구가 안 보이는 것을 형상 속성으로 둔다.
지금 `PalletGeometry` 는 블록 3개를 고정 튜플로 갖는다(`pallet_geometry.py:29`). 매개변수형 모델은 이를 대체하지 않고 **변환해 받는다**(알려진 형상 → 좁은 범위).

### 7.2 증거 소유권

- 한 인스턴스의 증거는 **그 인스턴스 마스크 안의 점**(경계 2 px 안쪽으로 깎음)과, 마스크 뒤로 이어지는 광선 검사용 depth 뿐이다. 같은 평면이라는 이유로 이웃 팔레트의 블록·상판을 가져오지 않는다 — 지금 `supports` 가 평면 전체 열을 더하는 것(`pocket_detector.py:516`)이 나란히 배치 결함의 한 원인이다.
- 맞닿은 팔레트가 마스크 하나로 합쳐져 오면, 맞춤 단계에서 **"하나" 대 "둘로 나눔" 가설을 경쟁**시킨다(폭이 모델 범위의 두 배에 가까우면 분할 가설을 만든다).

### 7.3 받침면 높이와 층

바닥(z = 0) 대신 **인스턴스마다 받침면 높이 z_s** 를 추정한다 — 마스크 바로 아래의 수평면(바닥 또는 아래 팔레트 상판)을 찾고, 없으면 하부 덱 띠의 아래 경계로 정한다. 모든 높이 대역(블록 띠, 상·하부 증거, 광선 검사, 출력 z)을 z_s 기준으로 해석한다. 층 번호는 같은 수평 위치에서 z_s 순서로 매긴다.

### 7.4 가설 경쟁과 부분 증거

1. 진입면 평면을 강건 적합한다(지금처럼 수직 재적합, 잔차 기록).
2. 받침면 z_s 를 정한다(§7.3).
3. 형상 가설마다(알려진 형상 각 진입면 + 비규격 매개변수형) 모델을 평면 좌표 (ℓ, z − z_s) 에 맞춘다 — 관측된 부재(블록 열, 덱 띠)의 **위치와 모델 부재 위치의 일치**로 점수를 매기고, **관측되지 않은 부재는 감점하지 않는다**(없는 것과 안 보이는 것을 구별하지 않음). 반대로 **모델상 빈 곳(개구)에 점이 있으면 감점**한다 — 포켓이 막힌 것은 D5 의 일이지만, 개구 자리에 면이 있다는 것은 그 가설이 틀렸다는 증거이기 때문이다.
4. 자세와 포켓 위치가 결정되려면 남은 증거가 **가로 위치, yaw, 높이를 각각 구속**해야 한다. 기준: 가로는 서로 다른 두 부재의 좌우 경계, yaw 는 평면 법선(면 점 수·폭 하한), 높이는 덱 띠 하나 이상과 z_s. 알려진 형상이면 블록 하나가 깨지거나 상판이 빠져도 나머지 부재가 이 조건을 채운다. **비규격은 두 개구의 양쪽 경계가 실제로 보여야** 한다(prior 가 빈 곳을 메워 주지 않으므로).
5. 가설 간 점수 차가 작으면(정사각 T11 의 진입면, 알려진 형상 대 비규격) 후보를 `ambiguous` 로 두고 둘 다 싣는다.

출력 포켓 높이·폭은 **관측값**으로 내고, prior 에서 채운 값이면 그 사실을 필드로 표시한다(지금은 prior 값이 측정값처럼 나간다 — `pocket_detector.py:669`).

### 7.5 B(팔레트 닮은 구조물)를 가르는 것

기하만으로는 `grounded` 와 팔레트를 못 가른다(§1). 그래서 판단은 둘로 나눈다.

| 판단 | 증거 |
|---|---|
| 이것이 팔레트인가 | 학습 제안기의 인스턴스 점수(겉모습 — 하부 덱 판이 보이는가, 나뭇결·재질, 주변 문맥), 기하 가설 점수, 여러 시점의 일치 |
| 포크를 넣을 수 있는가 | 기하 맞춤의 포켓 + D5 의 관측된 빈 공간 + 포크 끼움 검사 |

부재 결손을 허용할수록(파손 대응) 랙·크레이트와 겹치는 형상이 생긴다. 이것은 **원칙으로 없앨 수 없는 절충**이므로 S5 놓침률과 N 오검출률을 같은 dev 곡선 위에서 보고 운용점을 정한다. 증거가 부족하면 거부하지 않고 **재관측(다른 시점) → 그래도 애매하면 콘솔 확인**으로 넘긴다.

## 8. 후보, 대상 선택, 후보 추적

**`PocketCandidate`** (ADR 0003 1-a 의 구현): 후보 ID, 출처(learned/geometric/oracle), 인스턴스 마스크 참조, 형상 가설(이름 또는 매개변수)과 대안 가설, 진입면, 받침면 높이·층 번호, 자세(x, y, z, yaw), 포켓 두 개(중심·폭·높이, 각 값이 관측인지 prior 인지), 부재별 증거 범위(관측/미관측/모순), 정규화된 점수, 상태(`fitted` / `ambiguous` / `unfit`)와 사유, 포크 끼움 결과. 후보 수 상한은 프레임당 8(제안기 상한과 같게). `PocketCandidate` 는 `PocketObservation` 의 불변식(`non-valid 는 기하를 생략`)을 쓰지 않는다.

**대상 선택** (`select_target(candidates, instruction, reachability)`):

1. 작업 지시가 있으면: 지시 위치에서 허용 반경 안이고 지시 층과 같은 `fitted` 후보. 하나면 선택, 둘 이상이면 **콘솔 확인 요청**, 없으면 "대상 없음 — 재관측".
2. 지시가 없으면: `fitted` 후보 중 경로 계획기가 접근 가능하다고 답한 것 가운데 가장 가까운 것. 1·2위 거리 차가 0.3 m 미만이면 콘솔 확인 요청.
3. 선택 결과는 `PocketObservation`(valid)으로 바꿔 기존 삽입 경로에 넘긴다. 사람이 콘솔에서 고른 후보도 포크 끼움 검사·D5 를 통과해야 한다(ADR 0003 1-b ⓒ).

**후보 추적:** 접근 중 프레임마다 후보를 이전 후보와 연결한다(주행 기록으로 옮긴 자세의 가로·yaw·**높이** 차이와 형상 가설 일치). 선택된 대상이 사라지면 **다른 후보로 자동 대체하지 않고** 재관측한다(Codex P1 — 근접 추적기가 높이를 비교하지 않아 층이 바뀌어도 받아들이는 문제와 같은 종류).

## 9. 근접 추적, 포크 끼움, D5 와의 연결 (바닥 사례)

- **근접 추적 인계:** 지금 roof 추적은 "멀쩡한 빈 판재 팔레트"의 뒤끝·판 간격 패턴을 쓰고(`roof_tracking.py:182`, `:280`, `:421`), 근접 front 추적은 명목 개구 폭·간격을 검사한다(`near_field_tracking.py:408`). 상판 결손은 이번 범위의 파손이므로, 인계 시 **이 팔레트에서 실제로 관측된 부재 배치(빠진 판·깎인 블록 포함)를 템플릿으로 넘기고**, roof 패턴 일치를 "관측된 판 위치와의 일치"로, 개구 검사를 관측 치수로 바꾼다. 관측된 판이 너무 적어 roof 추적 조건(판 경계 수 하한)을 못 채우면 front 경로만으로 간다.
- **높이 비교 추가:** 근접 추적의 연결 검사에 높이를 넣는다(`near_field_tracking.py:366` 은 XY·yaw 만 본다). 바닥 사례에서도 위·아래로 다른 물체가 겹칠 수 있다.
- **포크 끼움 검사:** 후보마다 `check_fork_fit`(`pallet_geometry.py:195`)을 관측 치수로 돌린다. 실차 포크 간격은 수동 조절(0.055–0.38 m)이므로, 안 맞으면 집지 않고 **"포크 간격 조정 필요(권장 간격 x m)"를 콘솔에 알린다.** 이 판정은 거부가 아니라 작업 전제 미충족이다.
- **D5:** 바닥 사례는 지금 D5 범위(바닥 기준 0.03–0.17 m 띠, `pocket_check_v11.py:40`) 안이다. 비규격·파손 팔레트에서는 명목 상자 대신 **관측된 형상**을 D5 에 넘긴다. 포켓 안에 걸린 부러진 판은 지금처럼 접촉 전에 멈추고, 콘솔에 사유를 알린다(팔레트 거부가 아니라 충돌 회피).
- **D5 와 근접 추적 동시 사용:** 이 브랜치의 실행기는 두 기능의 동시 사용을 거부한다(`run_transport.py:2483`, D5 v11 대기). 임무 평가는 **그 시점에 통합된 기본 경로**로 하고 어느 경로였는지 결과에 적는다. D5 v11 통합은 메인 지게차 SW 작업의 몫이며 이 설계의 선행 조건이 아니다.

## 10. 상태와 오류 처리

- 인식 결과 상태: 후보 목록(0개 가능), 후보마다 `fitted`/`ambiguous`/`unfit`. 대상 선택 결과: `selected` / `ask_operator`(사유: 지시 범위에 둘 이상, 1·2위 근접, 가설 애매) / `none`(사유: 지시 범위에 없음, 접근 가능한 후보 없음, 포크 끼움 불가).
- 학습 제안기 예외·시간 초과는 기하 제안기로 넘어가고 출처에 남긴다. 기하 맞춤 예외는 그 후보만 `unfit(exception:<type>)` 으로 바꾼다(지금 검출기의 예외 처리와 같은 원칙).
- **파손은 거부 사유가 아니다.** "상판 증거 부족"은 더 이상 `invalid` 사유가 아니라 증거 범위 필드다.

## 11. 시험 계획

- **단위(CPU, 광선 추적 합성):** 매개변수형 모델 범위·변환, 증거 소유권(맞닿은 두 팔레트 — 이웃 점을 쓰지 않음), 받침면 높이(바닥 / 아래 팔레트 위), 부분 증거(블록 하나 깎임, 상판 두 장 빠짐에서 자세가 문턱 안), 비규격 개구 미관측 시 `ambiguous`, 가설 경쟁(T11 진입면, 알려진 형상 대 비규격), 선택 규칙의 모든 분기, 후보 추적의 층 변경 거부.
- **고정 반례(지금 재현된 것):** Codex 의 나란히 배치 가짜 쌍 두 장면(T11 간격 210 mm, EPAL 6 yaw 0.13 rad·간격 220 mm)을 회귀 시험으로 고정한다 — 새 경로에서 진짜 쌍이 선택되어야 한다. 정상 EPAL 6 대 `grounded` 쌍은 기하 단독으로 못 가른다는 사실 자체를 시험으로 남긴다(학습 제안기 없이 둘 다 `fitted` 가 나오는 것이 기대값).
- **평가기:** 인스턴스 대응(헝가리안, 등가 진입면), 상한 계산, 사례별·형상별 집계, 위험 오위치.
- **Isaac:** 장면 렌더 계약(스키마 판 2 로더 통과, 마스크와 depth 정렬), 손상 연산이 렌더·물리에 같게 들어갔는지, 임무 묶음.
- pytest 는 ws1(`~/bin/forklift-ws1-pytest`)에서 돌린다.

## 12. 단계 (계획으로 넘길 묶음)

1. **데이터·정답·평가기:** 사례 조리법, 손상 연산, Isaac 렌더(스키마 판 2), 다중 인스턴스 평가기, 지금 검출기 기준선 수치(dev).
2. **(병행) 기하 코어:** 매개변수형 모델, 증거 소유권, 받침면 높이, 가설 경쟁, `PocketCandidate`, 대상 선택, 후보 추적. **정답 마스크(oracle 제안)로 먼저 평가**해 맞춤 품질을 분할 품질과 떼어 본다.
3. **(병행) 학습 제안기:** 학습 데이터 대역 생성, 모델 학습, ONNX, dev 에서 학습 대 기하 제안 비교(S6·N 오검출과 S5 놓침의 절충 곡선).
4. **근접 추적·포크 끼움·D5 연결과 임무 평가**(바닥 사례).
5. **eval 한 번**과 결과 기록(`docs/validation/`), 회사용 사례별 영상.
6. 다음 설계: 적층 집기.

## 14. 위험

- **Sim2Real:** 상자 조합 팔레트 모델과 Isaac 재질은 실물 겉모습과 다르다. 무작위화·LOCO 로 줄이지만 실물 성능은 실물 eval 전까지 주장하지 않는다.
- **파손 허용과 오검출의 절충**(§7.5)은 측정으로만 운용점을 정할 수 있다.
- **임무 평가의 실행기 경로**가 D5 v11 통합 시점에 따라 달라진다(§9).
- 비규격 포크 끼움은 포크 간격이 수동이라 자율 집기 범위가 실제로는 **현재 간격에 맞는 형상**으로 한정된다.
