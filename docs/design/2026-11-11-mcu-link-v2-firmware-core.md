# MCU 펌웨어 코어 mcu-link/2 대응 설계

작성일: 2026-11-11 · 상태: **설계, 실기기 없음** · 관련: [코어 설계(v1)](2026-10-22-mcu-firmware-core.md), [링크 계약 mcu-link/2](../interfaces/2026-10-22-mcu-link-contract.md), [실차 이식 계획](../plans/2026-11-11-sim-to-real-bringup.md) 3.3·3.4

## 1. 목적과 범위

실차 이식 계획 3.3(엔코더 고장 검출·듀티 변화율 제한)과 3.4(시운전 빌드)가 요구하는 코어 변경을, 콘솔(계약 주인)과 합의한 mcu-link/2 계약에 맞춰 `firmware/core/` 에 넣는다. 보드 HAL(WeAct H743)은 이 PR 밖이다(별도 설계 문서와 PR).

| 이번에 한다 | 이번에 하지 않는다 |
|---|---|
| `link`: version 2, `COMMISSION`(0x05), `STATE` 끝 `reset_cause` | 보드 HAL·툴체인·클록·USB |
| `drive`: 엔코더 결함 7비트(17–23), 시운전 경로와 `commission_time_limit`(24), `wrong_build`(14)·`estop_unwired`(15), `STATE.flags` bit4–7, 바퀴 듀티 변화율 제한 | 문턱 값의 실측(S3·S4). 보드 설정에는 '실측 대기' 꼬리표를 단 임시값만 |
| `pi`: 출력 범위를 매 주기 받는 조건부 적분(변화율 제한과 적분 포화 방지) | 승강 원점(안 A) — 계획 3.5 결정 뒤 version 3 |
| `app`: `reset_cause` 전달 | HIL 모형 자체(보드 PR 5) |

## 2. 빌드 정체성은 설정의 상수다

`drive_config` 에 네 값을 더한다. 보드 빌드가 컴파일 시점 매크로로 `const` 설정에 넣고, 어떤 링크 메시지도 바꾸지 못한다(총괄 결정 Q3 개정 조건 1).

| 필드 | 뜻 | `STATE.flags` |
|---|---|---|
| `commission_build` | `FW_COMMISSION`: `COMMISSION` 만 받고 `DRIVE` 는 `wrong_build` | bit4 |
| `hil_plant` | `FW_HIL_PLANT`: 입력 스냅숏을 MCU 안 모형이 채움 | bit5 |
| `outputs_locked` | 보드가 모터 출력을 내지 않는 빌드(`FW_MOTOR_OUTPUT` 꺼짐, 또는 HIL) | bit6 |
| `estop_wired` | 비상정지 입력 핀이 있음. 거짓이면 bit7 `estop_unwired` | bit7 = !estop_wired |

- 설정 검증: `hil_plant` 이면 `outputs_locked` 여야 한다. `commission_build` 와 `hil_plant` 는 함께 둘 수 없다(시운전은 실제 출력이 목적이다. 출력이 잠긴 시운전 빌드는 허용한다 — 모터 없이 시운전 도구 경로를 시험할 때).
- 코어는 `outputs_locked` 일 때도 듀티를 그대로 계산하고 `STATE.duty_e4` 에 싣는다(계약 3.3: 계산값, 물리 출력은 0). **출력을 실제로 막는 것은 보드다**: 잠긴 빌드는 TIM1 PWM 을 초기화하지 않고 DRVOFF 를 high, EN 을 low 로 고정한다(보드 설계 문서, 링커 맵·시험으로 확인). 코어 설정의 `outputs_locked` 는 그 사실을 알리고 ARM 판정에 쓰는 값일 뿐이다.

### 2.1 비상정지 핀이 없을 때의 ARM (총괄 결정 Q3, 2026-11-11 개정)

`ARM` 검사 순서에서 `estop_active` 다음, `sensor_invalid` 앞에 둔다:

```
estop_wired == false && outputs_locked == false && commission_build == false  ->  estop_unwired (15)
```

- 거부는 '출력이 열린 정상 빌드 + 핀 미지정' 하나뿐이다.
- `FW_COMMISSION` 빌드는 핀이 없어도 ARM 을 받는다. 이때 시험 조건은 계획 5절 S2–S4 대로 **바퀴를 띄운 받침대, 사람이 주 전원 차단을 손에 쥔 상태**다(총괄 결정 Q3).
- 출력 잠금 빌드(HIL, `FW_MOTOR_OUTPUT` 꺼짐)도 받는다. 바퀴가 물리적으로 돌 수 없고, P0-8·P0-9 를 비상정지 핀이 없는 코어 보드만으로 해야 하기 때문이다(Q3 개정).

## 3. `COMMISSION` 경로

계약 3.4 를 따른다. 코어 쪽에서 정할 것만 적는다.

- **`wrong_build` 는 형식 검사보다 먼저다.** 정상 빌드의 `COMMISSION`, 시운전 빌드의 `DRIVE` 는 내용과 무관하게 `wrong_build`. 프레임의 version·길이·CRC 검사는 그보다 앞(링크 층)이다.
- 형식(`bad_value`): `axis ≤ 3`, `|duty_e4| ≤ commission_duty_max × 10000`(자르지 않음), `valid_after_echo_ms ≥ 1`.
- 그 뒤 `boot_id` → 모드 → `arm_gen` → 마감 → `seq` → `zero_first` 는 `DRIVE` 와 같은 함수와 같은 상태(`last_drive_seq`, `zero_seen`)를 쓴다. 시운전 빌드에는 `DRIVE` 가 들어오지 않으므로 둘이 섞이지 않는다.
- 조향·승강 축(M·H) 명령은 그 축의 절대각이 유효해야 받는다(아니면 `sensor_invalid`). 3.1 절 참조.
- 받아들이면: `cm_axis`, `cm_duty = duty_e4 / 10000`(제어 좌표 — `duty_sign` 적용 전), 마감은 `DRIVE` 식. **축이 바뀌면** 이전 축은 그 주기부터 정지 상태로 가고 적용 듀티 이력도 0 이 된다(다시 고를 때 변화율 제한을 건너뛰지 않게).
- **출력**(`ARMED`): 지정 축만 `cm_duty`(바퀴 축이면 4절 변화율 제한), 나머지 셋은 `DISARMED` 와 같은 채널별 정지 상태(`drvoff = !safe_brake`, 듀티 0). 폐루프(PI)는 돌지 않는다.
- **`STOPPING`**(만료·시간 상한): **고르지 않은 축까지 네 축 모두** 듀티를 그 주기에 바로 0, DRVOFF low(출력 켬)로 두고 `stop_grace_ms` 뒤 `DISARMED`. 그 채널의 드라이버 결함이나 드라이버 미준비면 끊는다. 감소 쪽은 변화율 제한이 없다(4절). 듀티 0·DRVOFF low 는 DRV8244 PH/EN 모드의 전기 제동이다. 정상 빌드의 `STOPPING`(속도 0 PI)과 다르다 — 시운전에는 폐루프 게인이 아직 없기 때문이다. 이 차이를 계약 4절에 적어 달라고 콘솔에 요청한다.
- **시간 상한은 실제 출력으로 잰다**: `drive_finish` 가 정한 적용 듀티 가운데 하나라도 0 이 아닌 주기가 이어지는 동안 시계가 돈다(`cm_on_since` = 그런 주기가 시작된 시각). 네 채널 적용 듀티가 모두 0 인 주기가 한 번 지나야 시계가 지워진다. 그래서 같은 주기에 `0 → 비영` 명령을 받거나 듀티를 계단식으로 바꿔도 시계가 지워지지 않는다. `ARM`·`DISARM` 의 제어 초기화도 시계를 지우지 않는다 — 한 주기에 `DISARM → ARM → COMMISSION(0) → COMMISSION(비영)` 을 받아도 실제 출력에 0 인 주기가 없으면 시계는 이어진다. `ARMED` 에서 `time − cm_on_since > commission_time_ms` 이면 마감 처리와 같은 자리(메시지 처리 전)에서 `STOPPING` 으로 가고 `commission_time_limit`(24)을 켠다. 이 비트는 `command_timeout` 처럼 래치지만 **결함 모드로 가지 않고** 다음 `ARM` 에서 지운다(계약 3.4). 상한으로 들어간 `STOPPING` 은 `DISARM` 으로 줄일 수 없다: `stop_grace_ms` 가 끝날 때까지 `ARM` 을 `stopping` 으로 거부한다. 같은 주기에 `DISARM → ARM → COMMISSION` 을 받아도 0 출력이 `stop_grace_ms` 동안 이어진다(Codex PR 리뷰 P1). 명령 마감과 시간 상한은 모드를 바꾸기 전에 따로 판정한다 — 같은 주기에 둘 다 넘어도 상한 비트와 재무장 보류가 걸린다(Codex PR 재리뷰 P1). 최종 출력 단계도 상한을 넘긴 시운전 듀티를 내지 않고, 그 자리에서 보류를 다시 건다.

### 3.1 시운전 빌드의 결함 판정 (S3 가 하는 일에 맞춤)

S3 는 `duty_sign`·엔코더 극성·조향과 승강의 기구 범위를 **처음 찾는** 단계다. 그래서 시운전 빌드는 다음만 정상 빌드와 다르게 판정한다.

| 판정 | 정상 빌드 | 시운전 빌드 |
|---|---|---|
| `encoder_stuck`·`encoder_polarity` | 결함 래치(`FAULT`) | 비트만 래치(다음 `ARM` 에서 지움), 모드는 그대로. 개루프 듀티라 측정이 틀려도 출력이 커지지 않는다(상한 `commission_duty_max`·`commission_time_ms`) |
| 조향·승강 절대각 무효·범위 밖 | `ARM` 거부, 출력 중이면 결함 | **지정 축만** 본다: `COMMISSION` 이 M·H 를 고르면 그 축이 유효해야 받고, 그 축이 출력 중 무효·범위 밖이 되면 결함. 고르지 않은 축은 비트만 표시(`ARM` 도 막지 않음) |
| 전류 측정 무효·과전류·nFAULT·비상정지·gap·jump·주기 지연 | 결함 | 같다 |

- 이유: 승강 측정 방식(계획 3.5)이 정해지지 않아 승강 KTH 가 없거나 범위가 보정되지 않은 채로 바퀴 시운전을 해야 한다. 전류 측정과 nFAULT 는 과전류 보호이므로 그대로 둔다.
- 조향 축의 기구 범위 보호는 S2 에서 정한 범위(`steer.min_joint`·`max_joint`)에 기댄다. 범위가 아직 없으면 시운전 빌드 설정의 범위를 보수적으로 둔다(보드 설정, '실측 대기').

## 4. 바퀴 듀티 변화율 제한

- 설정 `wheel_duty_slew_per_s`(> 0). 바퀴 두 채널의 **적용 듀티의 크기가 커지는 쪽**만 주기마다 `wheel_duty_slew_per_s × dt` 안에서 바뀐다(제어 좌표, `duty_sign` 전). 크기가 줄어드는 쪽(0 쪽)은 제한하지 않는다. 부호가 바뀌면 0 을 지난 뒤 다시 0 부터 오른다. 조향·승강에는 적용하지 않는다(계획 3.3 은 바퀴 기동 전류가 대상).
  - 이유: 기동 돌입 전류와 역전 전류는 크기가 커지는 쪽에서 생긴다. 줄이는 쪽까지 묶으면 `STOPPING` 이 반대 방향 제동 듀티에 늦게 닿아 정지 시간 예산(계획 3.4, S5)을 먹는다. 급감속 때의 회생 전압은 DRV8244 전류 제한과 S3 측정(계획 R2)으로 본다.
- PI 와의 결합: `pi_step_range(lo, hi)` 로 범위는 `prev ≥ 0` 이면 `[−step, prev + step]`, `prev ≤ 0` 이면 `[prev − step, step]`(부호가 바뀌면 0 에서 `step` 만큼만), 그리고 `[−out_max, out_max]` 와의 교집합. 조건부 적분은 이 범위에서 오차 방향으로 포화했을 때 멈춘다(적분이 제한 뒤에 쌓이지 않음). 이것이 오버슈트가 없다는 보장은 아니다 — 변화율 제한 자체의 지연이 있다. 기존 `pi_step` 은 범위 `[−out_max, out_max]` 로 같은 함수를 부른다(동작 불변).
- 무장할 때, 출력이 꺼지는 모드로 갈 때, 시운전 축이 바뀔 때 이전 듀티를 0 으로 둔다.
- **안전 쪽 동작은 변화율 제한을 받지 않는다**: `DISARM`, 결함, 비상정지, `STOPPING` 이 끝나 정지 상태로 갈 때는 출력이 바로 채널별 정지 상태가 된다.
- PI·변화율 제한의 `dt` 는 설정 주기(`period_us`)다. 주기 흔들림이 `overrun` 문턱 아래인 동안의 차이는 받아들인다(설계 v1 과 같음).

## 5. 엔코더 고장 검출 (계획 3.3, 계약 비트 17–23)

모두 뒤 바퀴 L·R 에만. 문턱은 설정값이고 기본값이 없다(CONTRIBUTING 6절). 보드 설정의 값은 S3·S4 실측 전 임시값이며 '실측 대기' 꼬리표를 단다. 아래 `Δt_s = Δt_us × 10⁻⁶`, `cpr` = 바퀴 한 바퀴의 4체배 카운트(`wheel_enc_config.counts_per_rev`, 모터 축 카운트 × 감속비).

| 결함 | 판정 | 언제 | 그 표본 |
|---|---|---|---|
| `encoder_gap`(17) | 이번 읽기와 직전 읽기의 HAL 시각 차 > `enc_gap_max_us`. 초기화 뒤 첫 주기는 결함으로 보지 않는다(차분은 버림) | 모든 모드 | 차분 버림 |
| `encoder_jump_x`(22·23) | `|Δcount| > enc_jump_rad_s × max(Δt_s, period/2) × cpr / 2π + 1` (`Δcount` 는 32비트 부호 정수로 넓혀 절댓값) | 모든 모드 | 차분 버림 |
| `encoder_stuck_x`(18·19) | `|u| ≥ enc_stuck_duty` 인 주기가 이어지는 동안, **마지막 진행 시각**(기준 카운트에서 `enc_stuck_counts` 이상 움직일 때마다 기준과 시각을 새로 잡음)부터 `enc_stuck_ms` 가 지남 | 출력이 실제로 걸리는 동안 | 정상 |
| `encoder_polarity_x`(20·21) | `|u| ≥ enc_polarity_duty` 이고 `u · ω < 0` 인 주기가 이어지는 구간에서 ⓐ 또는 ⓑ: ⓐ 상승 — 속도 창의 가장 오래된 표본이 구간 시작 이후가 된 시점(창이 구간 안의 표본으로만 채워진 때)의 `|ω|` 를 기준으로, 그 뒤 `enc_polarity_ms` 안에 `|ω|` 가 `enc_polarity_rise_rad_s` 이상 커짐 ⓑ 지속 — 구간이 `enc_polarity_persist_ms` 를 넘김 | 출력이 실제로 걸리는 동안 | 정상 |

- **"출력이 실제로 걸리는 동안"** = `ARMED`·`STOPPING` 이고 (`outputs_locked` 가 아니거나 `hil_plant`). 출력이 잠긴 비 HIL 빌드에서는 계산 듀티가 있어도 바퀴가 안 도는 것이 정상이라 stuck·polarity 를 보지 않는다. HIL 은 모형이 계산 듀티로 돌므로 본다. gap·jump 는 잠금과 무관하게 본다.
- **결함 처리**: 정상 빌드에서 넷 다 래치하는 결함이다. 결함 모드로 가고 `CLEAR_FAULTS` 로만 지운다. 출력이 꺼진 모드에서 gap·jump 가 생겨도 래치한다 — 오도메트리 카운트가 끊겼다는 뜻이라 호스트가 알아야 한다. 시운전 빌드의 stuck·polarity 는 3.1 절.
- **차분을 버린다** = 누적 카운트는 그대로 두고, 16비트 기준값·읽기 시각을 새 표본으로 옮기며, **속도 이력을 지금 표본 하나로 다시 시작**한다(속도 0, 다음 정상 차분부터 계산). 잃은 구간이 '이동 0' 으로 속도 창에 남지 않게 한다. 호스트는 비트 17·22·23 이 켜져 있는 동안 그 바퀴의 오도메트리 연속성이 끊긴 것으로 본다(콘솔 쪽 처리, 계약에 문장 요청).
- **stuck·polarity 의 `u`** 는 직전 `drive_finish` 가 정한 그 바퀴의 적용 듀티(제어 좌표, 변화율 제한 뒤)다. `ω` 는 `wheel_enc` 의 속도(같은 좌표). 계획 3.3 의 "`duty_sign` 적용 전 제어 좌표에서 비교" 가 이것이다.
- **polarity ⓐ 의 기준을 창 한 개 뒤에 잡는 이유**: `ω` 는 창 평균이라 구간 시작 직후에는 앞선 가속 이력 때문에 실제로 감속 중이어도 커져 보일 수 있다(Codex 반례: 20 ms 창에서 2 → 1.99 rad/s 감속 중 추정 1 → 1.75). 창이 한 번 다 바뀐 뒤를 기준으로 삼는다. 설정 주기 × 창 길이로 기다리면 실제 주기가 느릴 때(예: 1 ms 설정, 1.9 ms 실제, overrun 아님) 창이 다 바뀌지 않으므로, 표본 시각으로 판정한다(Codex 2라운드). ⓑ 는 역극성 정속(상승이 없음)을 잡는다. `enc_polarity_persist_ms` 는 정상 감속·역전에 걸리는 시간보다 길어야 한다(S4 실측으로 정함).
- **gap 상한과 16비트 차분의 유일성**: 설정 검증이 `enc_gap_max_us × 10⁻⁶ × enc_phys_max_rad_s × cpr / 2π ≤ 16,383`(16비트 반쪽의 절반, 여유 2 배)을 요구한다. `enc_phys_max_rad_s` 는 바퀴가 물리적으로 낼 수 있는 최대 각속도(무부하 최대 듀티, S3 실측, 그 전에는 보수적 추정)로, 명령 상한이나 jump 문턱과 다르다. 허용 공백 안에서 실제 차분이 접히지 않는다는 전제를 설정으로 강제한다.
- **jump 의 `+1` 과 `Δt` 하한**: 한 카운트 떨림, 그리고 밀린 주기 뒤 바로 온 주기(`Δt` 가 아주 짧음)에서 오검출하지 않게 한다. 한 번의 불가능한 증분은 잡음이든 배선이든 결함으로 본다(여러 번 기다리지 않음).
- **gap 의 첫 주기 예외**: `fw_app_init` 이 첫 입력을 읽은 뒤 첫 주기까지는 USB 열거 등으로 늦을 수 있어 결함으로 보지 않는다. 그래도 그 차분은 접혔을 수 있으므로(예: 327,680 cpr, 8 rad/s, 100 ms → +41,721 이 −23,815 로 접힘) 버리고 기준만 옮긴다.
- 판정 순서: `read_sensors` 안에서 gap·jump 를 먼저 보고(차분을 더하기 전), `judge_driving_faults` 에서 stuck·polarity 를 본다. 출력이 걸리지 않는 동안에는 stuck·polarity 구간을 지운다.
- 백래시: 모터 축 엔코더라 기어 백래시 안에서는 바퀴가 걸려도 모터가 돈다. stuck 은 '엔코더 신호가 멈춤'을 잡는 것이지 '바퀴가 멈춤'을 잡지 않는다. 역전 직후 백래시 구간의 순간 가속은 polarity ⓐ 의 창 지연·문턱으로 견딘다. 둘 다 S4 실측(바퀴 고정 왕복, 받침대 최대 속도 역전)으로 확인한다.

## 6. `reset_cause`

`fw_app_init`·`drive_init` 이 인자로 받아(0–4 밖이면 초기화 실패) 모든 `STATE` 에 싣는다. 값은 보드가 RCC 리셋 플래그에서 정한다: IWDG → 소프트웨어 → BOR·POR → 핀 순으로 판정한 뒤 플래그를 지운다(리셋 핀 플래그는 다른 리셋에도 함께 켜진다). 보드 설계 문서에 적는다. 호스트 빌드 MCU 모형(`firmware/tools/mcu_model.c`)은 0 을 준다.

## 7. 계약 쪽에 요청할 것

- 3.4 받는 순서 맨 앞(프레임 검사 뒤)에 `wrong_build`, 3.2 `ARM` 순서의 `estop_active` 다음에 `estop_unwired`.
- 3.4: 시간 상한은 실제 적용 출력이 이어진 시간이고, 네 축 적용 듀티가 모두 0 인 주기가 지나야 시계가 지워진다. 시운전 `STOPPING` 은 듀티 0(전기 제동)이며 정상 빌드의 속도 0 제어와 다르다(4절에도).
- 시운전 빌드에서 stuck·polarity 는 비트만(다음 `ARM` 에서 지움), 고르지 않은 조향·승강 축의 무효·범위 밖은 표시만. M·H 를 고른 `COMMISSION` 은 그 축이 무효면 `sensor_invalid`. 3.2 `CLEAR_FAULTS` 의 센서 조건도 시운전 빌드에서는 전류 측정만이다(`ARM` 과 같음).
- 비트 17·22·23 이 켜져 있는 동안 그 바퀴 카운트 연속성이 끊겼다는 문장. 호스트는 세션 중 `boot_id` 가 바뀌면 `reset_cause` 가 0 이어도 브라운아웃일 수 있다고 본다.

## 8. 시험 (먼저 쓴다)

- `link`: 고정 벡터 7개(계약 6절)와 바이트 일치, `COMMISSION` 왕복, version 1 프레임은 `rx_errors`, 길이 다른 `STATE`(71 바이트) 거부.
- `pi`: `pi_step_range` 의 범위 포화와 적분 정지, 데드밴드 출력이 범위 안으로 잘림, `pi_step` 결과 불변.
- `drive`:
  - 빌드 비트: 네 설정 조합의 `flags` bit4–7, 설정 검증(HIL 인데 잠기지 않음, 시운전+HIL, gap 상한 × 물리 최대 속도가 16비트 반쪽 절반 초과, polarity 지속 시간이 상승 시간보다 짧음).
  - `estop_unwired`: 정상·열림·핀 없음 → 15, 잠김 → 허용, 시운전 → 허용, 핀 있음 → 허용.
  - `COMMISSION`: 정상 빌드 → 14, 시운전 빌드의 `DRIVE` → 14, axis 4·duty 초과 → 1, zero_first, stale_seq, 마감 만료 → 그 주기 듀티 0 출력 켬 → `DISARMED`, 지정 축만 출력·나머지 정지 상태, `duty_sign` 적용, 축 전환 시 이전 축 즉시 정지·이력 0, 시간 상한 → `STOPPING`·비트 24·결함 모드 아님·다음 ARM 에서 지워짐, **같은 주기 `0 → 비영` 이나 계단식 변경은 시계를 지우지 못함**, 적용 듀티가 모두 0 인 주기 뒤에는 다시 시작, 승강 KTH 무효여도 바퀴 시운전 ARM·명령 가능, M 축 명령은 조향 무효면 13.
  - 변화율 제한: 크기 증가는 주기당 상한 이하, 감소는 즉시, 부호 전환은 0 을 거쳐 상한으로, 적분이 제한 뒤에 쌓이지 않음, `DISARM`·결함은 즉시 정지 상태, 정상 빌드 최대 듀티에서 만료 → `STOPPING` 첫 주기에 반대 방향 제동 듀티가 나옴.
  - 엔코더:
    - gap: 한 번의 긴 공백 → 17·누적 카운트 유지·속도 이력 초기화, `DISARMED` 에서도 래치, 초기화 뒤 첫 주기는 예외.
    - jump: 문턱 넘는 한 번 → 22/23, 짧은 `Δt` 주기는 오검출 없음.
    - stuck: 듀티 유지 + 카운터 고정 → 정해진 시간 안 18/19; **정상 주행 뒤 듀티 유지 중 카운터 정지** → 18/19; 문턱 아래 듀티는 안 걸림; 출력 잠금 비 HIL 은 안 걸림, HIL 은 걸림.
    - polarity: A/B 바꿈 가속 → ⓐ 20/21; 역극성 정속 → ⓑ 20/21; 가속 직후 정상 제동·양방향 역전·변화율 제한 중 문턱 진입은 안 걸림.
    - 시운전 빌드: stuck·polarity 는 비트만, 모드 그대로, 다음 ARM 에서 지워짐.
    - `CLEAR_FAULTS` 로 해제.
- `app`: `reset_cause` 가 `STATE` 에 실림, 잘못된 값이면 init 실패.
