# S1–S6 bring-up 호스트 도구 ① — STATE 기록·바퀴 CPR·계단 응답·안전 시나리오 (설계 2판, 2026-11-12)

총괄이 순서를 바꿨다(2026-11-11): 4e-1b 보다 먼저 S1–S6 최소 bring-up 경로를 만든다. 범위는 계획 `docs/plans/2026-11-11-sim-to-real-bringup.md` 5절이다.

이 문서는 그 묶음의 PR ① 이다.
- 대상: S2 의 STATE 기록·바퀴 CPR(감속비) 실측, S4 의 계단 응답 기록, S5 의 안전 시나리오 기록.
- 계약: mcu-link/2(`docs/interfaces/2026-10-22-mcu-link-contract.md`).
- 2판은 Codex 1차 상의(P1 3·P2 5)를 반영했다(7절).

## 1. 원칙
- **도구는 실행기가 아니다**(계약 3.3 빌드 비트 규칙). 연결은 빌드와 무관하게 하고, 빌드 비트·결함·`reset_cause` 를 기록하고 표시한다. 구동은 3절 조건을 지킬 때만 한다.
- **도구가 내는 것은 소프트웨어 근거다.** `STATE` 의 모드·`duty_e4`·`current_ma`·카운트는 MCU 가 계산하거나 읽은 값이다. 그래서 물리 출력의 정지(DRVOFF·상전압)도, 차체 이동도 증명하지 않는다.
  - S5 의 세 측정(계획 3.4: 출력 반응, 바퀴 정지 시간, 정지 거리)의 합격 판정은 **외부 측정값**으로만 한다.
  - 외부 측정 수단은 다음과 같다. 출력 반응은 DRVOFF·상전압의 오실로스코프, 정지 거리는 바닥 기준선 실측이다.
  - 도구는 외부 측정값을 입력받아 기록·문턱 비교를 하거나, 없으면 그 항목을 `측정 불가`로 남긴다.
- 링크는 기존 `McuLinkHost`(P0-7)와 `tools/real_mcu_link.py` 를 쓴다. 자동 `ARM`·`CLEAR_FAULTS`·재시도는 없다.
- **모든 `STATE` 표본을 보존한다.** `host.state` 를 주기적으로 읽으면 한 번에 받은 여러 `STATE` 중 마지막만 남는다. 그래서 받은 바이트를 도구의 `LinkDecoder` 에도 넣어 모든 표본을 받은 시각과 함께 기록한다.
- 시각은 섞지 않는다(계약 4절).
  - MCU 동역학(계단 응답·카운트 정착)은 `mcu_time_us` 간격으로 잰다.
  - 호스트 사건(송신 완료·사건 표시)은 호스트 단조 시각으로 잰다.
  - 표본 누락은 `seq` 만으로 판단하지 않는다(MCU 가 송신 실패 때 `seq` 를 올리지 않는다). `mcu_time_us` 간격도 함께 본다.

## 2. 명령 (`tools/bringup.py`, 하위 명령)

| 명령 | 단계 | 하는 일 | 구동 |
|---|---|---|---|
| `record` | 공통 | 모든 `STATE` 와 링크 사건(재연결·디코드 오류·`boot_id` 변경·모드 변화)을 JSONL 로 남긴다. 화면에는 1 Hz 요약을 낸다. **사건 표시**: 운용자가 키를 누른 호스트 시각을 기록한다(IWDG 강제·비상정지·주 전원처럼 사람이 일으키는 사건의 시작점 후보). | 없음 |
| `cpr` | S2 | 운용자가 바퀴를 손으로 N 바퀴 돌린다. 바퀴별 방향과 N 은 운용자 입력이다. 그동안 같은 부팅 안에서 부호 있는 모듈러 차분을 더해 **바퀴 1 회전당 카운트(유효 CPR)** 를 낸다. 모터 엔코더의 4,096 counts/rev 를 운용자가 확인했다고 표시하면 `G = CPR ÷ 4096` 도 낸다. 결과는 설정에 바로 쓰지 않고, 붙일 조각과 근거를 출력한다. | 없음 |
| `step` | S4 | 무장 → `ready` → 계단 → 0 → 정리(3절). 지표는 4절이다. | 있음 |
| `scenario` | S5 | `tx_cut`(호스트→MCU 송신만 끊고 수신은 유지), `disarm`, `expiry`(구동 명령을 더 보내지 않음)를 일으킨다. 소프트웨어 시각열을 기록하고, 외부 측정 입력을 받는다(4절). | 있음 |
| `analyze` | S5 | `record` 파일과 사건 표시로 소프트웨어 시각열을 다시 계산한다. 외부 측정값을 함께 받는다. | 없음 |

- `tx_cut` 은 MCU 의 만료 정지 경로를 시험한다. 지금 코어는 전송로 단절을 따로 알지 못하고 명령 마감으로 선다. 그래서 MCU 쪽에서는 `expiry` 와 같은 경로다. 실제 케이블을 뽑는 시험은 정지 `STATE` 를 잃으므로 `record` + 외부 측정으로 따로 한다.
- 수동 사건의 시작 시각:
  - IWDG: 제어 주기가 멈춘 순간이다. 사건 표시와 마지막 `STATE` 의 받은 시각이 그 구간을 둘러싼다. 순간 자체는 외부 측정이다.
  - 주 전원 차단: 그 뒤 `STATE` 가 없다. 도구는 마지막 표본까지만 기록하고, 나머지는 외부 측정이다.

## 3. 구동 명령의 안전 조건 (`step`·`scenario`)
- **빌드**: 시운전 빌드는 `DRIVE` 를 받지 않으므로 거부한다. 실기에서 `outputs_locked` 면 출력이 나가지 않으니 중단한다. 모형·HIL 은 시험용 `--allow-locked` 로 허용한다. `estop_unwired` 는 정상 빌드가 `ARM` 을 거부하므로 그대로 실패로 기록한다.
- **무장**:
  - 운용자가 요청한 뒤 I/O 를 계속 돌려 `McuLinkHost.ready`(`arm_pending → zero_pending → ready`, 0 `DRIVE` 포함)까지 기다린 다음 계단을 시작한다. `authorized` 나 `ARMED` 만으로 시작하지 않는다.
  - 무장 실패 뒤 자동 재시도는 없다.
  - **권한 철회의 구분**: `McuLinkHost` 는 정상적인 `STOPPING` 진입에서도 권한을 철회한다. 그래서 사건(`tx_cut`·`expiry`·`disarm`)을 일으킨 뒤 예상한 `STOPPING → DISARMED` 는 시험의 일부로 보고 관측을 계속한다. 정리용 `DISARM` 으로 감속을 끊지 않는다.
  - 다음은 '중단'으로 기록한다: 사건 전의 권한 철회, 예상 밖 결함, 부팅 변경, 관측 실패(`STATE` 가 끊김).
- **다른 축**: 바퀴 시험의 `DRIVE` 는 조향 목표를 시험 시작 때 측정한 조향각으로 유지하고, `lift_hold=True` 로 보낸다(조향 기본값 0 을 보내면 다른 축이 움직인다).
- **크기·시간**:
  - 바퀴 목표 상한은 `wheel_rate_limit`, 그리고 0.2 m/s 에 해당하는 각속도(`0.2 ÷ wheel_radius`; 반지름 실측 전이면 `cpr` 결과와 측정 반지름이 있을 때까지 1.0 rad/s) 중 작은 값이다. 영 크기 계단은 거부한다.
  - 계단 하나는 최대 3 s 다. 모든 명령의 `expires_ns` 는 시험 전체의 고정 종료 시각을 넘지 않는다. 비영 명령은 그 단계 끝을 50 ms(`HANDOVER_S`)보다 더 넘지 않는다. 다음 단계의 첫 명령이 도착하기 전에 MCU 가 멈추지 않게 하는 이음 시간이다. 그래서 도구가 예외로 멈춰도 비영 명령은 그 이상 이어지지 않는다.
- **정리 절차**(정상 종료·예외·Ctrl-C):
  1. 비영 목표 갱신을 멈춘다.
  2. 대기 명령을 버린다(`drop_drives`).
  3. 제한 시간(기본 1 s) 동안 I/O 를 돌리며 `DISARM` 을 보내고, `STATE` 의 `DISARMED` 를 확인한다.
  4. 확인하지 못하면 '정리 실패'로 기록한다.
  - 링크가 끊겼으면 송신도 확인도 할 수 없다는 점을 기록에 남긴다.
  - `expiry`·`tx_cut` 시험 도중 정리용 `DISARM` 이 끼어들면 그 시험은 '중단'이다.
- **운용자 확인**: 무장 전에 할 일과 시험 형태를 보인다. `--yes` 없이는 입력을 기다린다.
  - 받침대(바퀴 띄움)가 기본이다.
  - 바닥 시험(`--floor`, S5 의 바닥 측정)은 `outputs_locked`·`estop_unwired` 가 꺼져 있고, 주 전원 스위치를 바깥에서 잡을 수 있음을 운용자가 확인해야 한다(계획 5절 S5 선행).

## 4. 계산
- **CPR·G**:
  - 같은 `boot_id` 안에서만 더한다. 32 비트 부호 있는 모듈러 차분을 쓰고, 표본 사이 이동은 반범위(2³¹) 미만이어야 한다.
  - 다음은 결과를 무효로 한다: 부팅 변경, 시각 역순, `encoder_gap`·`encoder_jump_*` 가 켜진 구간(MCU 가 그 차분을 버림, 계약 3.3 호스트 해석).
  - `STATE` 누락만으로는 무효가 아니다. 누적 카운트라서다.
  - 바퀴별 CPR, 두 바퀴의 차이, 운용자가 입력한 N·방향과 부호의 일치를 함께 낸다.
- **계단 응답**:
  - 측정 각속도를 초기값(계단 직전)과 목표의 차이로 정규화한다. 역방향 계단도 같은 식이다.
  - 10 %·90 % 통과 시각(상승 시간), 최대 초과(오버슈트 %), ±5 % 띠에 0.2 s 이상 머문 첫 시각(정착)을 낸다.
  - 문턱 통과가 누락 구간 안이면 시각을 구간으로 낸다. 3 s 안에 정착하지 않으면 '미정착'이다.
  - 입력 지연은 따로 낸다. 송신 프레임의 쓰기 완료 호스트 시각부터 `last_rx_seq` 가 그 `seq` 가 된 첫 `STATE` 의 받은 시각까지의 구간이다.
- **S5 소프트웨어 시각열**:
  - 사건 시작: `tx_cut` 은 마지막으로 쓰기를 마친 프레임의 완료 시각이고, 그 프레임의 `seq`·echo·`valid_after_echo_ms` 를 남긴다. `cap_ms` 만으로 '남은 시간이 최대였다'고 증명하지 않는다.
  - **최악 조건 `tx_cut`**(계획 3.4·S5 필수 사례):
    - 비영 구동으로 바퀴가 도는 것을 `STATE` 로 확인한다.
    - 방금 받은 새 `STATE` 의 echo 로 **최대 유효시간**(`cap_ms`)의 `DRIVE` 를 만들어 마지막으로 보낸다.
    - 그 쓰기가 끝나자마자 TX 를 막고, 수신은 유지해 그 `DRIVE` 가 수락됐는지(`last_rx_seq`) 확인한다.
    - echo·유효시간·쓰기 완료 시각·수락 관측을 기록한다.
    - 이 조건 중 하나라도 채우지 못하면 그 실행은 '최악 조건 시험 미충족'으로 남긴다. 짧은 유효시간의 결과로 대신하지 않는다. `disarm` 은 `DISARM` 쓰기 완료 시각, `expiry` 는 마지막 `DRIVE` 쓰기 완료 시각이다.
  - MCU 모드 전이(`STOPPING`·`DISARMED`)가 처음 보인 `STATE` 의 받은 시각.
  - `duty_e4` 가 모두 0 이 된 첫 `STATE`: 소프트웨어 출력의 보조 근거이고, 물리 정지가 아니다.
  - **카운트 정착**: 두 바퀴 카운트 변화가 허용량(기본 2 카운트) 이하로 0.3 s(MCU 시각) 이상 유지되기 시작한 시각. 관측 끝까지 정착하지 않으면 '미확정'이다. 부팅 변경·엔코더 결함·관측 단절은 정착으로 치지 않는다.
  - **구름 추정 거리**: `카운트 ÷ CPR × 2πr`(받침대에서는 바퀴 둘레 이동량). 이것은 차체 이동이 아니다(백래시·미끄럼·바퀴 잠김 중 미끄러짐). 바닥 정지 거리는 외부 측정값만 판정에 쓴다.
  - 외부 측정 입력 항목: 출력 반응(ms), 바퀴 정지 시간(ms), 정지 거리(mm). 각각 값 또는 `측정 불가`이고, 문턱(계획 3.4)과 비교한 결과를 낸다.

## 5. 시험
- 단위:
  - CPR(모듈러 차분·부팅 변경·결함 구간 무효)
  - 계단 지표(정규화·역방향·누락 구간·미정착·영 계단 거부)
  - 카운트 정착(허용량·유지 시간·미확정)
  - 안전 조건(빌드·크기·시간·`expires_ns` 상한·`ready` 전 시작 금지·조향 유지·`lift_hold`)
  - 정리 절차(예외·Ctrl-C 에서 `drop_drives` → `DISARM` → 확인, 실패 기록, 시험 중단 표시)
- 종단(mcu_model, pty) — **검증 범위는 프레임·무장·만료·재무장 금지·기록·계산 경로**다.
  - 모형의 바퀴는 합성 1 차 동역학이다. 전류 입력은 0 이고 watchdog 은 빈 함수다. 그래서 물리 제동·전류 응답·IWDG·정지 거리는 검증하지 않는다.
  - `record` 는 모든 `STATE` 를 기록한다.
  - `step` 은 무장 → `ready` → 계단 → 정리가 끝나고 지표가 나온다.
  - `scenario tx_cut`(최악 조건 포함)·`expiry`·`disarm` 에서 사건 뒤의 정상 `STOPPING → DISARMED` 가 중단으로 처리되지 않고, 정리용 `DISARM` 이 끼어들지 않는지 확인한다.
  - `scenario tx_cut` 은 호스트 송신만 막는다(`--silent-at-ms` 는 양방향을 숨겨 정지 관측이 안 되므로 쓰지 않는다). 모형이 `STOPPING`·`DISARMED` 로 가고 카운트가 정착하는 시각이 기록된다.
  - `cpr` 은 모형에 구동과 독립인 **알려진 엔코더 궤적 주입 옵션**(`--hand-turn L|R:N:seconds`)을 더해 확인한다. 이 시험이 확인하는 것은 계산이지 보정값이 아니다. 모형과 도구가 같은 헤더의 CPR 을 쓰므로, 잘못된 보정값도 함께 통과할 수 있다.

  - `finally DISARM` 이 송신을 보장하지 않음 → 정리 절차(3절).
  - 속도 문턱 정지 판정 → 카운트 정착·구름 추정 거리와 바닥 외부 측정을 나눔(4절).
  - `link_drop` → `tx_cut`(송신만 차단), 시작 시각 정의(2·4절).
