## 2. 한 틱 (계약 1 절의 순서)

한 틱은 **한 갈래만** 출력한다. 우선순위는 ① 긴급 DISARM → ② S10 일회성 제어 정지 → ③ 명시적 출력 대기 → ④ 정상 AUTO DRIVE 다(Codex P1-3).

**허가 상태별로 낼 수 있는 프레임**(Codex 2 회차 P1-1):
- `OFF`(준비 중 포함): 미션 DRIVE 없음.
- `ARMING`: 그 ARM 과 호스트가 직접 넣는 확인용 0 DRIVE 만. 루프는 아무 DRIVE 도 내지 않고, 세대도 바꾸지 않는다(`control_stop` 금지 — 확인용 0 DRIVE 를 지움).
- `READY`/`DRIVING`: ③·④.
- DISARM 은 상태와 무관하게, lease·무장·측정 조건이 실패해도 송신을 시도한다.

### 2.1 머리
1. 링크 수신. 새 STATE(같은 부팅·증가하는 MCU 시각으로 중복 제거)마다 한 번씩 다음을 갱신한다:
   - `RealOdometry.update`, `SafetySpeed`, 정지 증거(새 표본 정지).
   - `OutputBook`(2.6)의 확인.
   - 중재기 `observe(feedback)` — 새 표본일 때만 준다. 틱마다 같은 피드백을 다시 주어 정지 표본을 늘리지 않는다.
2. `host.tick` → `permit.tick` → **`OutputBook` 게시**(Codex 3 회차 P1-1): 수신·만료·큐 상태를 반영한 확인값과 방향별 잔류 상한을 코어 상태(2.5 의 1 과 같은 세 값)에 넣는다. `Link.begin` 과 코어 제어보다 먼저다.
3. 감시(3절): 시작 간격, 과속, `SafetyWatch`(부팅·MCU 시각으로 중복 제거, 바퀴 비교는 그 STATE 가 확인한 목표로), 엔코더 유효성. trip 이면 ①.
4. `link.gate` 로 STOP·연결·만료를 처리한다(첫 쓰기 직전의 같은 경계에서 다시 — 2.5 의 5).
   - 실차에서는 콘솔 `disarm` 도 ①로 잇는다. AUTO 에서는 중재기 `armed` 가 이미 꺼져 있어 `_on_disarm` 이 아무것도 바꾸지 않기 때문이다.
   - 중재기가 `STOPPED` 거나 lease 를 잃었으면 ①.
5. `session.tick_start`: `link.begin` → `collect_end` → `commands.apply` → `collect_end`. `Context.submit_refusal` 은 `cargo.submit_refusal()` 로 채운다(Isaac 처럼).
   - **정지 판단의 공급**(Codex 2 회차 P2-3, 3 회차 P2-2): 실차에서는 중재기 설정 `external_stop=True` 로 증거 공급자 `stop_evidence(now) -> (fresh, standing)` 를 쓴다. 기본은 끄고, 끄면 지금 경로를 그대로 지난다.
   - 증거는 `Link.begin` 이 부르는 **한 번의** `observe()` 안에서 받는다(필드를 밖에서 덮지 않음). 무효·만료면 그 자리에서 정지 확인을 내린다. 그 밖의 처리(만료·preempt·승강·조향 피드백)는 그대로 돈다.
   - 증거는 고유 표본 누적·`OutputBook` 해소·확인 출력에서 나온다. 같은 표본을 여러 틱 쥐는 것과 실제 표본 공백을 구분한다. 기본 경로와 외부 증거 경로를 각각 시험한다.
6. 예외(수신·SLAM·훅·중재)는 모두 ①로 간다.

### 2.2 SLAM·층·깊이·준비
1. `core.slam_replies` → 제어 자세 → 층의 설치된 스냅숏(PR 5 전에는 가짜) 순서다.
2. `slam["stop_now"]` 는 세 조건의 곱이다: 새 표본 정지, `port.outstanding()` 해소, SLAM 신선. `still_since` 는 그 구간의 시작이다.
3. **hold 해제의 허용**(Codex 2 회차 P2-1): 머리의 수거는 2.2 보다 먼저 돌므로 직전 틱의 `stop_now` 를 믿지 않는다.
   - 최초 수거는 `end_reset(t, release_allowed=…)` 에 그 순간 직접 확인한 값을 넘긴다: 마지막 처리 위치의 신선도 ∧ 정지 증거 ∧ 현재 자세의 유효성(hold 이동 한도 안) ∧ 오도메트리 연속. 코어의 작은 변경으로, 기본 None 은 지금과 같다.
   - 위치 증거가 만료됐으면 해제를 미룬다. hold 한도 초과처럼 새 응답만으로 풀리지 않는 경우는 해제하지 않고 재위치 확인으로 넘긴다. 어느 쪽이든 종료 기록과 복구 잠금은 남는다(Codex 3 회차 P2-1).
   - 미뤄진 해제(`end_release_due`)는 무장과 무관한 정지 상태 경로에서, 같은 직접 확인을 거쳐 `release_gate` 로 시도한다.
4. **D5 깊이 공급**(Isaac 러너 6195–6235 와 같은 일):
   - 검사가 있으면 깊이 원천의 새 프레임마다 다음을 확인한다: 취득 시각이 지금 이전이고 마지막보다 뒤인지, 미션 세대·단계·적용 보정이 같은지.
   - 나이 한도는 둘이다(Codex 3 회차 P2-4): 알려진 시작의 첫 프레임은 0.5 s, 후속 프레임은 검사기 자신의 한도(`frame_max_age_s`, 픽셀 지연 포함 0.2 s).
   - 취득 시각을 **연속 계측 구간**(표본 공백 없음)이 덮어야 한다. 그 구간에서 자세·속도·yaw rate·승강을 보간하고 `add_frame(...)` 을 부른다.
   - `await_still_frame` 은 검사기가 **실제 새 프레임으로 채택**(`add_frame` 반환의 `new`)했고, 그 취득 시각이 현재 대기가 시작된 뒤이자 정지 구간 안이며, 검사기의 나이 조건까지 통과했을 때만 푼다(Codex 2 회차 P2-5, 3 회차 P2-4). 시험은 대기 플래그를 직접 지우지 않고 이 경계를 가짜 입력으로 통과한다.
   - PR 7 전에는 원천이 없다. 4c 시험은 가짜 깊이와 가짜 방향 증거로 이 경로를 통과하고, 실제 엔코더 모델의 `direction_unsure` 차단은 따로 시험한다.
5. **준비**:
   - 처음 `accepted` 를 본 틱에 `freeze_submit` 을 한 번 한다. 운용자 시작 확인은 이때 소비하고 그 미션·lease 에 귀속한다.
   - `status in (accepted, preparing) and not job_pending()` 이면 그 `FrozenSubmit` 으로 `known_request` 를 부른다. 보정 변경으로 답을 버린 뒤의 재요청도 같다.
   - **제출 거부는 ACK 에 반영한다**(Codex 3 회차 P2-5): 제출 단계 조건을 `Context.submit_refusal` 로 `commands.apply` 에 넘긴다. 조건은 화물 잠금, `auto_ready_refusal(stage="submit")`, 운용자 시작 확인 없음이다. 그래서 거부된 제출은 ACK·계획 요청·ARM 이 모두 없다. 운용자 확인은 통과한 제출에만 귀속한다.
   - 요청과 채택은 같은 판정을 새 SLAM 자세·설치된 스냅숏으로 다시 한다.
   - lease·링크·움직임·등록 revision 이 바뀌면 준비를 끝낸다.

### 2.3 채택·무장 분기 (Codex P1-2)
0. 허가가 `OFF` 인 동안 `accepted`/`preparing` 이면 `release_gate` 뒤 `job_hold` 를 한 번 부른다(무장 전 계획 답을 채택하는 자리; Codex 2 회차 P2-4). 추종·도착은 부르지 않고, 출력은 없다(2 절 머리).
1. `job_hold` 가 채택한 틱(`adopted_id == mission_id`, `running`, `approach`)이 오면 같은 미션·lease·중재기 세대를 다시 확인한다.
2. ARM 직전 검사(4b 6절)를 거쳐 `permit.adopted()` 를 한 번 부르고 `commands.begin_wait` 로 들어간다.
3. **무장 대기 분기**(`ARMING`):
   - 추종·도착·포켓 채택·승강 램프를 부르지 않는다.
   - 층·SLAM·링크·감시는 계속한다. 루프의 출력은 없다(호스트의 확인용 0 DRIVE 만 나감).
   - 채택 틱은 ARM 요청으로 끝난다.
   - `READY` 가 되면 `end_wait`. 첫 허가 틱의 후보는 확인된 바퀴 0 과 신선한 실측 조향·승강에서 만든다.
4. 그 뒤 매 틱 2.2 다음에 `auto_ready_refusal(stage="drive")` 를 판정한다.
   - `wait:` 사유는 ③으로 간다.
   - 그 밖의 사유는 ①이다.
   - 최종 제출(2.5)에서 다시 판정한다.

### 2.5 출력 조립과 제출
1. `assemble_command` 는 **조향 배열의 복사본**으로 부르고, `try/finally` 로 그 직후(다른 코어 호출 전) 출력 필드를 되돌린다(Codex 2 회차 P1-4).
   - `state["applied_command"]`·`slam["applied_speed"]` 에는 현재 유효한 **확인값**만 넣는다.
   - `state["command_speed"]` 에는 slew 의 시작값(확인값)을 넣는다.
   - `state["outstanding_motion"]` 에는 아직 작동할 수 있는 **방향별 상한** `{+1: v, -1: v}` 을 넣는다.
   - 코어의 실차 방향 검사(`_direction_limits` 실차 갈래)는 이것을 읽는다. **요청과 같은 방향도** `max(요청, 실측 상한, 그 방향의 확인·미확인 상한)` 으로 층과 D5 를 검사한다(Codex 3 회차 P1-1). 허용치가 그 방향의 잔류 상한보다 낮으면 실차 갈래는 그 틱을 출력 대기(③)로 보낸다. 작은 코어 변경이고, Isaac 갈래와 훅 호출은 그대로다.
   - 조립 중 예외도 같은 `finally` 로 되돌린다.
2. `cargo.observe` → `observe_motion`(오도메트리) → `safety_state` → `session.tick_end`(중재).
4. **제출**(하나의 송신자). 새 단조 시각으로 STOP·lease·중재기 세대·MCU 권한·만료를 다시 읽고 한 갈래를 고른다:
   - **①**: `permit.latch`(4b 의 순서).
   - **②**: 아래 4절.
   - **③ 대기 프레임**:
     - 진입하는 틱에 옛 큐와 후보를 버린다(`control_stop` 한 번 — 세대 변경). 정지 목표(조향·승강)는 그때의 유효한 실측으로 잡아 **그 대기에만 속한 값**으로 저장한다(포트의 일반 의도와 수명을 공유하지 않음; Codex 2 회차 P2-2).
     - 이어지는 대기 틱은 같은 세대로 같은 목표의 바퀴 0 프레임(포트 `hold_frame`)을 다시 낸다. 매 갱신은 새 기한의 결정으로 검증한다. 미송신 hold 는 최신 한 건만 남기고, 대기가 끝나면 버린다.
     - 실측 승강을 매 틱 목표로 삼지 않는다(처짐을 따라 내려가지 않게). 목표가 실측과 벌어지면 그 프레임은 움직일 수 있는 명령으로 센다. `keep` 은 쓰지 않는다.
     - 대기 사유: `wait:snapshot_installing`, 계획 대기, 현재 틱 30 ms 초과(3 절). 무장 대기는 대기 프레임이 아니다(2 절 머리).
     - 코어가 내는 정지(포켓 정지 프레임 대기 등)는 ④의 정상 출력이지만, 그때도 바퀴 0 과 명시적 승강 `target` 을 보장한다.
   - **④ 정상 AUTO DRIVE**:
     - 중재 출력이 `source=auto` 이고 `permit.drive_allowed()` 면 낸다.
     - 후륜축 명령 상한(S10 `max_speed_mps`)을 여기서 강제한다.
     - `OutputBook` 의 '아직 작동할 수 있는 방향'과 반대인 후보는 그 영향이 해소될 때까지 0 으로 둔다(방향 전환 보류).
   - 출력 직전 예외는 ①이다.
5. **송신**(4c `--run` 은 가짜 전송기만).
   - **실차 전용 송신 경계**(Codex 2 회차 P1-2, 3 회차 P1-2): 실차 `RealChannels`(`Channels` 의 하위 클래스)는 긴급 사건(STOP·DISARM 요청·연결 끊김)을 받을 때 같은 잠금 안에서 `emergency_serial` 을 올린다. 메시지 처리와 ACK 는 잠금 밖이다(`link.gate`).
   - 송신은 그 짧은 잠금 안에서 처리한 뒤 새 긴급 사건이 없음(`emergency_serial` 이 처리 때와 같음)을 확인하고, **첫 논블로킹 쓰기 한 번만** 시도한다. 사건이 있거나 `EAGAIN` 이면 다음 쓰기 전에 다시 판정한다. S10 의 예상 종료 전이도 이 경계에서만 인정한다.
   - 첫 바이트 직전에 프레임 종류별로 다시 검사한다:
     - 움직임 프레임: STOP 래치·lease·중재기 세대·MCU 권한·만료.
     - DISARM: 검사 없이 쓴다.
   - 실패한 움직임 프레임은 쓰지 않고 버리고, 부분 송신은 만료까지 추적한다.
   - 쓰기 완료 시각(첫 바이트 직전이 아님)을 `permit.written`·`OutputBook` 에 알린다.
   - **S10 정지 프레임의 예외**(Codex 2 회차 P1-2):
     - 예외는 정지 프레임의 정확한 seq·부팅·무장 세대·포트 세대·원래 lease 에 묶인다. 허용하는 것은 **예상한 종료 전이 하나**뿐이다 — `FINAL` 을 본 `Arbiter.resolve` 의 `AUTO → PAUSED` 한 번.
     - 그 전이에서는 그 프레임을 큐에 보존한다. 루프는 `STOP_PENDING` 동안 중재기 세대 동기화로 `port.new_control_generation()` 을 부르지 않는다.
     - 그 밖의 경계·STOP·DISARM·lease 상실은 예외를 거둔다. 아직 쓰지 않은 정지 프레임은 버리고 즉시 DISARM 이다.

### 2.6 출력 기록 `OutputBook` (계약 1.6, Codex P1-4, 2 회차 P1-4)
- 낸 프레임마다 기록한다: seq, 부팅, 권한 epoch, 포트 제어 세대, 만료, 후륜축 속도·곡률·조향·승강 목표, `movable`, 쓰기 완료 시각.
- 세 가지를 따로 둔다:
  - **확인된 목표**: 그 seq 를 알린 같은 부팅·무장 세대의 STATE 가 확인한 것.
  - **아직 작동할 수 있는 것**: 해소되지 않은 `movable` 프레임의 방향별 최대 속도와 승강 이동.
  - **후보**: 이 틱의 조립 결과.
- 코어에 넘기는 값은 2.5 의 1 대로 셋으로 나눈다: `applied_command`·`applied_speed` = 확인값, `command_speed` = slew 시작값(확인값), `outstanding_motion` = 방향별 상한. 방향 전환 보류는 실차 `permission`(코어)과 최종 제출 검사(2.5 ④) 두 곳에서 본다.
- 정지 완료는 두 조건이다: 옛 명령 해소(또는 미제출 폐기), 그 뒤 같은 부팅의 고유한 신선 표본.

## 3. 감시 (잠정, Jetson 실측 뒤 확정; Codex P2-5)

- **주기**:
  - 시작 간격은 머리에서 본다: 연속 3 회 > 30 ms, 또는 한 번 > 60 ms 면 ①.
  - 현재 틱 경과와 측정 나이는 **첫 쓰기 전에** 본다(Codex 2 회차 P2-6):
    - 60 ms 초과·측정 만료는 ①.
    - 30 ms 초과는 아직 쓰지 않은 정상 후보만 버리고 ③으로 바꾼다.
    - S10 정지·DISARM 은 대기로 바꾸지 않는다.
  - 텔레옵 `loop_slow`(1 초 안 40 ms 세 번)와는 다른 규칙이다.
- **과속**: 둘로 나눈다.
  - 명령과 무관한 **바퀴별 절대 상한**: S10 상한을 바퀴 각속도로 바꾼 값 × 1.5. 넘으면 ①.
  - 확인된 목표 대비 **편차 감시**: 감속·전송 지연(0.15 s)만큼의 여유를 준다. 넘으면 ①.
  - 후륜축 명령 상한은 2.5 ④가 따로 강제한다.
- **`SafetyWatch`**: 텔레옵 다리와 같은 설정이다. 입력 `armed` 는 `permit.armed` 다.
- **세션 시작**: 두 DISARM 세션 확인(4b), 시계율·지연은 DISARM 응답으로 확인한다. 지연 확인용 DISARM 은 S10 정지 확인 중에는 내지 않는다.

## 4. 세션 수명주기·S10 (Codex P1-5, P2-3)

- **`collect_end`**: `commands.apply` 앞뒤와 제어 단계 뒤에 부른다. 같은 미션 id 는 한 번만 수거한다.
- **수거(`end_mission`) 순서**:
  1. 승강 목표를 유효한 실측 위치로 한다(`ms.lift_command`).
  2. `abandon_jobs`.
  3. `close_open`.
  4. `terminate`/`note_end`.
  5. `take_clock`.
  6. `end_reset`.
  7. 결과 기록.
- **허가 종료와 수거를 나눈다**: `permit.mission_ended` 는 권한만 끝내고 수거는 세션이 한다(서로 다시 부르지 않음). 준비 중 STOP·lease 상실도 같은 길이다.
- **S10**(②):
  1. 긴급 사유가 없으면 `port.control_stop` 으로 정지 프레임을 한 번 낸다(바퀴 0·실측 조향·승강 `target` = 실측). 이어 `permit.control_stop(seq)`.
  2. 수거는 한 번이고, 배달 판정이 없다. 이것이 연 현장 복구 잠금과 중재기 세대 변경은 그 프레임을 지우지 않는다(2.5 송신 예외).
  3. 확인 조건: 쓰기 완료 뒤 받은 같은 부팅·무장 세대 STATE 가 정확한 seq 와 `COMMAND_FRESH` 를 보이고, 100 ms 안이어야 한다.
  4. **실패 판정은 보수적으로**(Codex 2 회차 P1-3):
     - 포트 결과가 `queued` 가 아니거나 송신자가 그 seq 를 버리면(첫 바이트 전 만료 포함) 즉시 DISARM 이다.
     - `STOP_PENDING` 중 같은 부팅·권한의 신선한 STATE 가 `reject_reason != NONE` 이면, seq 를 귀속할 수 없어도 즉시 DISARM 이다. 같은 사유가 반복돼도 마찬가지다(사건이 아니라 STATE 로 본다).
     - 기한은 둘이다: 큐 체류(쓰기 완료까지) 40 ms, 쓰기 완료 뒤 확인 100 ms.
  5. `DISARMED` 를 확인하면 중재기를 `stop("s10_stopped")` 로 `STOPPED`, 허가를 `LATCHED` 로 맞춘다(재무장은 `STOPPED` 에서만).
  6. `s10_lifted` 와 정지 확인 결과를 따로 기록한다.
  7. **DISARM 확인**(Codex 3 회차 P2-3): 100 ms 마다 다시 보내고, 500 ms 를 종료 시한으로 둔다.
     - 시한이 지나면 중재기를 `STOPPED` 로 보내고 '미확인'을 기록한다. 확인 조건이 찰 때까지 재무장과 현장 복구 완료를 막는다.
     - `STOPPED` 상태 자체를 매 틱 새 래치 사건으로 다루지 않는다. 기다리는 DISARM seq 는 재시도 때만 바뀐다.

## 5. 장치 차단 (Codex P2-6)

`tools/real_autonomy.py --run` 은 4c 에서 내부 가짜 MCU 전송기만 만든다. 장치 인자는 운영 전송기를 열기 전에 거부한다. 최종 송신 경계 시험은 `ARM` 과 네 가지 DRIVE 가 모두 0 건인지 본다: 일반 DRIVE, ARM 뒤 확인용 0 DRIVE, 대기 프레임, S10 정지 프레임(Codex 2 회차 P3).

## 6. 시험 (계약 4 절 + 4b 11 절, Codex P2-7)

- **순서·분기**:
  - AST 부분 순서는 두 루프의 공통 부분 순서와 호출의 분기 소속을 검사한다.
  - Isaac 전용 분기에는 Isaac 기대값을, 실차 지원 밖 상태에는 래치 뒤 제출 0 회를 요구한다.
- **동작**:
  - `set_rear` 뒤 같은 호출 안의 새 자세 읽기.
  - `paused` + wait 에서 감시가 한 번.
  - 보정 변경 뒤 재요청.
  - 만료 SLAM 에서 수거가 한 번이고 해제가 미뤄짐.
- **송신**:
  - 정상 틱의 최종 제출 1 회와 seq.
  - 중재와 제출 사이 STOP → 0 회.
  - 큐에 든 뒤·첫 바이트 전 STOP → 폐기.
  - 부분 송신 → 만료까지 추적.
  - 콘솔 DISARM(AUTO 중) → 즉시 DISARM.
  - 출력 직전 예외 → ①.
- **미확인 DRIVE**: 확인된 0 → 전진 송신(완전·부분) → 확인 지연 중 반대 방향이나 취소 → 방향 전환·정지 완료 보류. STOP·거부 뒤 다음 틱이 후보를 적용값으로 읽지 않는다.
- **무장**: `ZERO_SEEN` 전 미션 DRIVE 0 건, 루프의 세대 변경 0 회.
- **대기 프레임**:
  - 스냅숏 설치·계획 대기·현재 틱 30 ms 초과에서 같은 세대·같은 목표로 반복된다. 미송신 hold 는 최신 한 건이고, 대기가 끝나면 버려진다.
  - 첫·중간·삽입 전 깊이 대기는 ④의 정상 정지다.
  - 정상 승강 목표는 덮이지 않는다.
- **S10 통합**: 실제 호스트 큐와 만료·부분 쓰기를 흉내 내는 가짜 MCU 로 다음을 본다.
  - 알려진 시작 → 접근 → 가짜 깊이 → 삽입 → 들림 확인.
  - 확인 틱과 다음 틱의 최종 바퀴 0, `extract` 전이 없음, 장애물 기억 보존, `carrying/confirmed`.
  - 정확한 정지 seq → DISARM → `STOPPED`/`LATCHED`.
  - 현장 복구와 새 세대 재위치까지의 잠금.
  - 유지 DRIVE 거절 → 즉시 DISARM. 같은 거절 사유 반복 → DISARM. 첫 바이트 전 만료 → DISARM. 확인 유실 → 100 ms 뒤 DISARM.
  - 정상 종료 전이(`AUTO → PAUSED`)에는 정지 프레임이 남는다. 그 직후 새 STOP·DISARM 이 오면 예외가 거둬져 DISARM 이다.
- **수거·해제**: 직전 틱 `stop_now=True` → 현재 틱 SLAM 만료와 STOP → 수거 한 번(해제 없음) → 새 처리 위치 도착 뒤 해제 한 번.
- **정지 판단**: 같은 표본을 여러 틱 쥐어도 정지 표본이 늘지 않음. 실제 표본 공백에서는 정지가 풀림.
- **출력 복원**: 조립 중 예외 → 확인값으로 복원. 양방향 미확인 상태 → 두 방향 모두 검사. 같은 방향 감속 중 확인 지연 → 층·D5 가 잔류 상한으로 검사하고, 허용치가 그보다 낮으면 대기.
- **송신 경계**: `gate()` 반환 직후·첫 바이트 전에 STOP 주입 → 그 프레임은 쓰이지 않음.
- **해제**: hold 한도 초과로 정지 → 해제 없음·재위치 요구, 종료 기록·잠금은 남음.
- **DISARM 확인**: 쓴 DISARM 을 MCU 가 못 받음 → 재시도 → 500 ms 뒤 `STOPPED`·미확인 기록, 재무장·복구 완료 거부.
- **D5 후속**: 0.3 s 된 정지 프레임은 대기를 풀지 못함.
- **제출 거부**: 확인 없음·만료된 시작 증거 → ACK·계획 요청·ARM 0.
- **lease 상실** → STOPPED·래치, 재무장 전 재개 없음.
- **장치 차단**(5절).
- **틱 훅 표**: S10-A 경로 전체를 `fail_closed_hooks` 로 돌린다. 이름과 반환형이 표와 같아야 한다(조사 결과: 매 틱 이름이 읽히는 필수 훅 — `slam_rear`·`cusp_holds`·`cusp_monitor`·`cusp_standing`·`cusp_heading_motion`·`loaded`·`signed_speed`·`plan_transport_leg`·`plan_return_leg`·`plan_observation_leg`·`steering_position`·`dump_tracking`·`path_stats`, 그리고 실차에서 반드시 있어야 하는 `safety_speed`).
- **기록**(Codex P3): 틱 시작 간격, 제어 계산 경과, 첫 바이트·쓰기 완료, MCU 확인을 구분한다.
