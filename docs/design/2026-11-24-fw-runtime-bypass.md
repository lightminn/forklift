# 펌웨어 보호의 런타임 우회 (mcu-link/4)

작성일: 2026-11-24 · 상태: **기각 — [S 안](2026-11-25-bench-commission-limits.md) 채택(총괄 2026-11-25).** 4판까지의 검토 기록과, 우회와 무관하게 드러난 기존 링크 빈틈(실기 `TtyLink`·`h743_link_check` 가 열 때 0x00 하나만 씀, 보드 USB 재연결 구분자 하나, ARM 취소·수락 증명)을 남기려고 보존한다. 구현하지 않는다

## 1. 범위: bring-up 도구의 벤치 시험

| 보호 | 있는 곳 | 우회 | 빌드 |
|---|---|---|---|
| 엔코더 정체·극성에서 멈춤 | **도구**(`early_stop`, 시나리오 판정). MCU 는 시운전 빌드에서 이미 래치만 한다 | 도구 `--bypass enc_stuck,enc_polarity` | 시운전 |
| L·R 시운전 듀티 상한(빌드 0.15) | MCU(`commission_check`)와 도구(`COMMISSION_DUTY_MAX`, `send_duty`) | ARM 비트 `commission_limits` + 도구 인자 | 시운전 |
| L·R 시운전 시간 상한(빌드 2 s) | MCU(`commission_over_limit`)와 도구(`COMMISSION_HOLD_MAX_S` 1.5, `LIMIT_MAX_S` 3) | 같음 | 시운전 |
| 조향·승강 측정이 무효면 ARM 거부 | MCU(`sensors_valid`) | ARM 비트 `steer_off`·`lift_off`: 그 축 출력을 끄고 무장 | 정상 |

- **쓰는 곳은 `tools/bringup.py` 하나다**(`commission`, `step`, `scenario`).
- **실행기(텔레옵 브리지·자율·HIL)는 MCU 우회를 보내지 않는다.** PR ① 의 적용 대조로, 0 이 아닌 적용 우회를 보고하는 `STATE` 를 받으면 권한을 철회하고 `DISARM` 한다. 2판의 PR ③(텔레옵 브리지·콘솔)은 뺀다(9 절).
  - 자율은 모든 비트를 거부한다.
  - 축 끄기는 거치 전용이라 텔레옵 바닥 경로와 맞지 않는다.
  - 텔레옵에서 축 끄기를 쓰면 `encoder_speed`·`_arm_blocker`·콘솔 직렬화가 NaN 측정에 걸린다(Codex 2 차 P2-3·P2-4).
  - 콘솔의 '검사별 켬/우회'(사용자 11-19)는 호스트 검사이고, 5c 에서 이미 된다.
- **정상 빌드의 엔코더 정체·극성은 우회하지 않는다**(1판 비트 철회, Codex 1 차 P1-3·P2-3, agy 2).
  - 정상 빌드의 바퀴는 엔코더 폐루프 PI 다. 링크가 끊긴 `STOPPING`(300 ms)도 같은 PI 로 세운다(`enter_stopping` 은 적분기를 지우지 않는다, `drive.c` 506·567·978).
  - 텔레옵 `encoder_speed`·`counts_still`, AUTO `rearm_refusal` 이 그 비트로 다음 ARM 을 막는다.
  - 엔코더 없는 바퀴는 어차피 정상 빌드로 몰 수 없다. 개루프 바퀴 시험은 시운전 빌드와 도구 우회로 한다.
- **정상·시운전 빌드의 런타임 전환은 범위 밖이다.** 빌드 구분은 단위가 다른 명령을 섞지 않으려는 계약(3.4)이다.

## 2. 우회 단위와 무장의 소비

- **이번 무장 한 번**:
  - 우회는 `ARM` 에 실린다. 그 `ARM` 이 받아들여진 무장 구간에만 적용되고, 무장 구간이 끝나면 MCU 가 지운다.
  - 남는 것은 RAM 상태뿐이고 비휘발성 저장은 없다.
  - 도구의 "세션 우회"는 그 실행의 모든 `ARM` 에 같은 비트를 싣는 것이다.
- **한 번만 받아들여지는 ARM**(Codex 1 차 P1-1):
  - v4 `ARM` 은 호스트가 본 `STATE` 의 `arm_gen` 을 싣는다. MCU 는 `ARM.arm_gen == d->arm_gen` 일 때만 받고, 받으면 세대를 올린다(0xFFFF 다음 1, 지금 규칙).
  - 이미 받아들여진 `ARM` 은 다시 받아들여지지 않는다(9 `arm_gen_mismatch`).
- **ARM 의 취소 — 완료는 MCU 가 정한다**(Codex 2·3 차 P1-1). MCU 에 취소 토큰을 두지 않는다. 대신 취소를 이렇게 정의한다.
  - 호스트의 취소(`cancel_arm`, 실행 끝, 오류)는 **'취소 요청·해제 미확인'** 일 뿐이다.
  - **취소 완료는 그 뒤 호스트가 다 쓴 `DISARM` 의 seq 를 `last_rx_seq` 로 보고하는, 같은 부팅의 신선한 `DISARMED`(또는 `FAULT`·`ESTOP`) `STATE` 를 받았을 때다.**
    - 이미 구분자까지 나간 `ARM` 은 폐기열로 회수되지 않는다. 그런 `ARM` 이 먼저 받아들여져도, 같은 스트림의 뒤 `DISARM` 이 해제한다.
    - 그 사이(1 틱)에는 정상 빌드의 PI 가 돌 수 있다. 우회 중이어도 무장 절차와 보호는 그대로다.
  - bring-up 도구는 취소 완료를 확인할 때까지 기다린다. 지금 `CommissionSession.cleanup` 이 `DISARMED` 를 기다리는 것과 같다.
  - 확인하지 못한 채 끝나면 결과에 `disarm_unconfirmed` 를 남기고, 터미널에 '상태 미확인 — 주 전원 확인'을 띄운다.
  - **선행 조건**(실기에서 우회를 켜기 전):
    - (가) 같은 장치에 쓰는 프로세스는 하나다. 실행기 잠금 PR(`feat/executor-lock`, 보류) 전까지는 운용 규칙이다.
    - (나) 모든 쓰기 경로가 열 때 폐기열을 쓴다(4 절). `h743_link_check.py` 158 의 직접 `0x00` 도 포함한다.
- **우회한 무장의 수락 증명**(Codex 2·3 차 P1-2). 요청 우회가 0 이 아닐 때 호스트는 아래로만 단계를 넘긴다. 우회 0 인 지금 경로의 동작은 바꾸지 않는다(회귀 범위를 줄임). 실행기는 대신 0 아닌 적용 우회를 거부한다(5.1).
  - **미결은 하나**: `ARM` 을 다 쓴 뒤에는 그 수락이나 거절이 확정될 때까지 다른 구동 프레임을 쓰지 않는다. zero 도 같다.
  - **ARMED 로 넘김**: 다음이 모두 맞는 `STATE` 를 받아야 한다.
    - **이 연결에서** `ARM` 을 다 쓴 뒤에 읽었다.
    - 같은 `boot_id`, `arm_gen` = 보낸 값 + 1(0xFFFF → 1), `last_rx_seq` = **그 `ARM` 의 seq**, `ZERO_SEEN` = 0 이다.
    - 적용 우회·한계가 기대값(5.1)과 같다.
    - 그 뒤에야 zero 를 쓴다.
  - **READY 로 넘김**: `last_rx_seq` = **그 zero 의 seq** 이고 `ZERO_SEEN` = 1 이며, 적용값이 같아야 한다.
  - **재연결**: 이전 연결의 `STATE` 를 근거로 쓰지 않는다. 폐기열을 쓴 뒤 새로 읽은 `STATE` 부터 센다.
  - **철회**: ZERO 대기·READY 의 **모든** 신선한 ARMED `STATE` 에서 적용값이 기대값과 다르면 철회한다. 권한 철회, 대기 출력 폐기, `DISARM` 순서다. 일괄 수신이면 중간 `STATE` 도 본다.
- **시운전 한계는 출력 구간에 묶는다**(Codex 1 차 P1-2, 2 차 확인):
  - 시간 상한은 실제 적용 출력이 연속해서 0 이 아닌 구간(`cm_on`)으로 잰다.
  - **적용 한계는 `cm_on` 이 거짓일 때만 바뀐다.** `cm_on` 이 참인 동안, 정규화한 실효 한계(0 을 빌드 값으로 바꾼 정수 쌍, 5.1)가 적용 한계와 **다른** `ARM` 은 11 `stopping` 으로 거부한다. 같으면 받고, 시계는 이어진다.
  - **`STATE.bypass` 의 비트 0 은 받아들인 `ARM` 의 마스크를 그대로 따른다**(Codex 3 차 P2-2). 새 `ARM` 을 받으면 마스크는 그 `ARM` 의 것으로 원자적으로 바뀐다. 숫자 한계와 연속 출력 시계는 위 규칙대로 보존된다. 그래서 같은 숫자 한계로 비트 0 → 1, 1 → 0 이 모두 가능하고, 호스트 기대 비트는 늘 요청 비트다.
  - **축 변경도 출력 구간에 묶는다**(Codex 3 차 P1-3).
    - `cm_on` 이 참인 동안 지금 축과 다른 축을 고른 `COMMISSION` 은 11 `stopping` 으로 거부한다. 지금 코드는 받아들이고 이전 바퀴 듀티만 0 으로 둔다(`drive.c` 793).
    - 그래서 한 출력 구간의 축은 하나로 정해지고, 상한도 구간 시작 때의 축으로 정해진다(L·R 은 적용 한계, M·H 는 빌드 2 s).
    - 이것으로 L → H 전환 틱에 상한이 바뀌는 경우 자체가 없어진다.
    - 도구는 축을 바꾸기 전에 0 을 보내고, 출력이 모두 0 인 `STATE` 를 확인한다.
  - 빌드 값으로 되돌리는 조건: **무장 구간 밖이고 그 주기의 실제 출력이 모두 0**. 하강 에지가 아니라 조건이다(이미 0 인 채 `DISARM` 한 경우도 되돌린다, Codex 2 차).
  - 상한을 실제로 넘겼으면 지금 규칙(비트 24, `stop_grace_ms` 재무장 보류)이 그대로 산다. `DISARM`·결함·`CLEAR_FAULTS` 가 보류를 줄이지 못한다.

## 3. ARM 비트 (`ARM.bypass`, u8)

| 비트 | 이름 | 받는 빌드 | 뜻 |
|---|---|---|---|
| 0 | `commission_limits` | 시운전 | `ARM.cm_duty_max_e4`·`ARM.cm_time_ms` 를 이 무장의 **L·R 출력** 한계로 쓴다(3.1) |
| 1 | `steer_off` | 정상 | 조향 측정과 무관하게 무장한다. M 채널을 끈다(3.2) |
| 2 | `lift_off` | 정상 | 승강(H)에 같은 규칙을 적용한다 |
| 3–7 | 예약 | — | `bad_value` |

### 3.1 시운전 한계 (`commission_limits`)

| 필드 | 형 | 의미 |
|---|---|---|
| `cm_duty_max_e4` | u16 | L·R 의 \|듀티\| 상한 ×10000. 0 이면 빌드 값 |
| `cm_time_ms` | u32 | **L·R 을 고른 동안의** 연속 비영 출력 시간 상한. 0 이면 빌드 값 |

- **M·H 는 우회와 무관하게 빌드 한계를 쓴다**(Codex 1 차 P1-5, 2 차 P1-3).
  - 듀티는 0.15, 시간은 빌드 상한 2 s 다. 축 변경이 출력 구간 사이에서만 되므로(2 절) 구간마다 상한 하나가 정해진다.
  - 도구의 0.2 s 는 그 아래의 이동 한계다.
  - 조향·승강 시운전이 길게 필요해지면 slew 를 더하면서 다시 본다(총괄).
- **형식**:
  - 비트 0 이 꺼져 있으면 두 필드 모두 0 이어야 한다(아니면 `bad_value`).
  - 켜져 있으면 각 값은 0 이거나 1 ≤ 값 ≤ 천장이다. 넘으면 `bad_value` 이고 잘라서 받지 않는다.
- **비교는 정수 e4 로 한다**: `|duty_e4| ≤ limit_e4`. 지금의 `float × 10000` 은 경계에서 틀린다(binary32 7 → 6.9999995).
- **보드 천장**(새 `drive_config` 필드, 빌드 상수):
  - `commission_duty_ceiling_e4` = 10000.
  - `commission_time_ceiling_ms` = 2 147 483 이다. 검증기 ms 상한이고 약 35.8 분이다. 총괄 결정: 사용자가 무제한을 원했다.
  - 검증: `빌드 값 ≤ 천장`, `듀티 천장 ≤ 10000`, `시간 천장 ≤ 검증기 ms 상한`.
- 남는 위험: 10 절 R1–R3.

### 3.2 축 끄기 (`steer_off`·`lift_off`, 정상 빌드, 거치 전용)

승강 측정 방식이 정해지지 않았다(계획 3.5). 그래서 지금 정상 빌드는 S4 바퀴 거치 시험도 무장할 수 없다. 센서만 건너뛰면 PI 가 무효 위치로 돌기 때문에, 우회의 뜻은 **그 축 출력을 끄는 것**이다.

- **ARM**: `sensors_valid` 가 끈 축은 보지 않는다. 전류 측정과 끄지 않은 축은 본다.
- **무장 구간(`ARMED`·`STOPPING`)의 끈 축**:
  - `duty = 0` 과 `channel_safe_drvoff` 를 함께 둔다. 지금 보드는 `safe_brake=false` 라 끊김(코스트)이다. `safe_brake=true` 채널이면 DRVOFF low·듀티 0(전기 제동)이다.
  - 목표·slew·PI 를 갱신하지 않는다. `DRIVE` 의 그 축 목표는 형식(유한)만 보고 무시하며, `limited` 를 켜지 않는다.
  - `driving_sensor_bits` 에서 그 축의 무효·범위 비트를 뺀다(조향 6·13, 승강 7·14). `sensor_bits` 는 그대로라 `STATE` 에 늘 보인다.
  - 같은 틱의 다른 결함(과전류·전류 무효·드라이버)은 그대로 결함이다.
- **`CLEAR_FAULTS` 는 두 빌드 모두 전류 측정 유효만 요구한다**(agy 1, Codex 1·2 차: 타당).
  - 모드·`boot_id`·비상정지 검사와 DRVOFF 를 세운 드라이버 재초기화는 그대로다. CLEAR 만으로 출력이 열리지 않는다.
  - 재초기화 뒤 `DISARMED` 에서 `ARM` 이 측정을 다시 본다.
- **거치 확인**(Codex 2 차 P1-4, agy 3):
  - 끈 축은 코스트다. 바닥이면 조향이 반력에 꺾일 수 있고, 승강이 자체 고정이 아니면 포크가 내려올 수 있다.
  - 도구는 축 끄기 비트가 있으면 `--wheels-lifted`(바퀴가 바닥에 닿지 않음)를 요구하고, `lift_off` 면 `--forks-lowest`(포크가 기계적 최하단)도 요구한다.
  - 둘 다 `--yes` 와 무관하게 실행마다 따로 입력해 확인받는다.
  - `scenario --floor` 와는 함께 쓸 수 없다.
- **호스트의 목표 값**:
  - 끈 축에는 유한한 무시용 목표를 보낸다. 조향은 0.0, 승강은 `lift_hold` 플래그다.
  - 끈 축의 NaN 측정은 ARMED 판정·목표·정지 증거에 쓰지 않는다. 끄지 않은 축의 검사는 그대로다.
  - 무시용 목표 0 을 실측 조향으로 쓰지 않는다.

## 4. 계약 변경 (mcu-link/4)

- **`version` = 4.** 3 이하는 버린다. 호스트 디코더는 버전이 다른 프레임을 따로 세어 '링크 버전 불일치(보드 이미지를 확인)'를 띄운다(agy 8).
- **`ARM` payload 12 → 21 바이트 `<IQHBHI>`**: `boot_id`, `echo_mcu_time_us`, `arm_gen`, `bypass`, `cm_duty_max_e4`, `cm_time_ms`.
- **ARM 받아들이는 순서**(처음 걸린 이유 하나):
  1. 프레임·길이 검사 뒤, 정의된 다른 빌드 비트 → 14 `wrong_build`.
  2. 형식(예약 비트만 있으면 여기, 비트 0 과 한계 필드, 천장) → 1 `bad_value`.
  3. `boot_id` → 8.
  4. echo → 10.
  5. `arm_gen` → 9.
  6. 모드(지금 순서).
  7. 시운전 재무장 보류 → 11.
  8. 열린 출력 구간 중 실효 한계 변경 → 11.
  9. 비상정지 → 4.
  10. `estop_unwired` → 15.
  11. 측정(끈 축 제외) → 13.
  - 어떤 거부도 적용 우회·한계·시계·보류·래치를 바꾸지 않는다. `ARM_CLEARS` 는 모두 통과한 뒤에만 적용된다.
- **`STATE` payload 84 → 91**, 끝에 붙인다:

  | 필드 | 형 | 의미 |
  |---|---|---|
  | `bypass` | u8 | 마지막으로 받아들인 `ARM` 의 마스크. 비트 1·2 는 무장 구간(`ARMED`·`STOPPING`) 동안만 보고하고, 비트 0 은 적용 한계가 빌드 값으로 돌아갈 때(2 절)까지 보고한다 |
  | `cm_duty_max_e4` | u16 | 적용 중인 L·R 듀티 상한(정규화한 값). 정상 빌드는 0 |
  | `cm_time_ms` | u32 | 적용 중인 L·R 시간 상한(정규화한 값). 정상 빌드는 0 |

- **크기**: body 97, COBS 98, 구분자 포함 99. `LINK_BODY_MAX` 97, `LINK_WIRE_MAX` 100.
- **폐기열**(Codex 1 차 P2-5, 2 차 P2-2):
  - 공통 상수 `LINK_POISON_LEN` = **99**(0 이 아닌 바이트, 0x01)이고 뒤에 0x00 을 붙인다. 99 가 두 디코더의 COBS 최대(98)를 넘으므로 이전 부분 프레임은 넘침으로 버려진다.
  - **호스트 → MCU**:
    - `LoopTtyTransport`(지금 96)와 실기 `TtyLink` 는 열 때와 부분 쓰기를 버릴 때 쓴다. `TtyLink` 는 지금 열 때 0x00 하나만 쓴다(`tools/real_mcu_link.py` 142). 부분 쓰기를 버린다는 것은 권한 철회 뒤 `_cur` 의 나머지를 잇지 않는 것이다.
    - `tools/h743_link_check.py` 의 직접 `0x00`(158)도 폐기열로 바꾼다.
  - **MCU → 호스트**:
    - C 모형(지금 96)과 보드 USB 재연결(`link_cfg.h` 99 의 구분자 하나, `link_usb.c` 의 재동기)이 폐기열을 쓴다. UART7 은 열림 개념이 없어 바꾸지 않는다.

  - **오류 계수 기준점**: 폐기열은 받는 쪽 `rx_errors` 를 일부러 올린다. 그래서 `rx_errors` 증가로 판정하는 도구(`first_boot.py` 106 등)는 **동기화가 끝난 뒤**(폐기열을 쓰고 그 뒤 첫 `STATE`)를 기준점으로 잡는다.
  - 시험에 남은 96 리터럴(`test_mcu_model_hil_options.py` 173 등)도 상수로 바꾼다.
- **함께 고칠 계약 문구**:
  - 1 절 version·body 상한.
  - 2 절 `ARM` 의 `arm_gen`. 세대(0 → 1, 0xFFFF → 1)와 프레임 `seq`(0xFFFF → 0)는 다른 순환이다.
  - 3 절 표.

  - 3.4 빌드 고정 한계 → 무장별 한계, M·H 는 빌드 한계.

  - 5 절 전송량(9.9 kB/s, 460 800 bps 의 21 %).
  - 6 절 벡터.
  - 7 절 v4.
  - 계약 주인 줄은 "총괄 배정으로 콘솔 세션이 v4 작성"으로 바꾼다.

## 5. 호스트·도구

### 5.1 공통 (PR ①)

- **메시지**: `messages.Arm(boot_id, echo, arm_gen, bypass=0, cm_duty_max_e4=0, cm_time_ms=0)`, `Bypass`(IntFlag), `McuState.bypass·cm_duty_max_e4·cm_time_ms`.
- **기록**:
  - 헤더에 링크 버전을 적는다.
  - v3 기록은 새 필드를 "당시 미보고"(None)로 읽는다. v4 헤더의 기록에서 필드가 빠졌으면 손상으로 본다(Codex 2 차 P2-7).
- **`McuLinkHost(fw_bypass=FwBypass())`**: 기본은 우회 0 이다. 모든 `ARM` 에 우회와 그 `STATE` 의 `arm_gen` 을 싣는다. 2 절의 수락 증명을 한다.
- **기대값 정규화**(Codex 2 차 P2-1):
  - 요청 원본과 기대 적용값을 따로 둔다.
  - 기대 비트 = 요청 비트.
  - 기대 한계 = 요청 0 을 같은 부팅의 무장 전 `STATE` 가 보고한 빌드 한계로 바꾼 정수 쌍이다. 시운전 빌드의 DISARMED `STATE` 는 빌드 값을 보고한다.
- **`rearm_hold_check.py`**: `request_arm` 을 거치지 않으므로 새 `Arm` 을 우회 0·`arm_gen` 으로 직접 만든다.
- **`build_policy.fw_bypass_refusal(client, purpose, bits)`**:
  - `Client.BRINGUP` 의 `commission` 은 비트 0 을, `step`·`scenario` 는 비트 1·2 를 받는다.
  - 그 밖은 모든 비트를 거부한다.
- **실행기의 0 아닌 적용 우회**(Codex 3 차 P2-4). 실행기는 적용 우회가 0 이 아닌 `STATE` 를 받으면 권한을 바로 철회하고 무장하지 않는다. `DISARM` 은 모드에 따라 다르다.
  - `ARMED` 면 바로 보낸다(다른 송신자가 무장시킨 것, 2 절 (가) 위반).
  - `STOPPING` 이면 보내지 않고 그 정지가 끝나 `DISARMED` 가 되기를 기다린다. 정상 빌드의 `STOPPING` 은 PI 정지이고, 이 보드는 `safe_brake=false` 라 `DISARM` 이 정지를 코스트로 끊기 때문이다. 우회 비트는 무장 구간 끝에 MCU 가 지운다.
  - 로컬 권한이 없는 새 실행기도 같다.
- **시험 모형**: 텔레옵 시험 모형(`test_teleop_bridge_cycle.py`)의 `gen += 1` 과 지연 ARM 재생성을 새 세대·수락 규칙에 맞춘다(Codex 2 차).

### 5.2 bring-up 도구 (PR ②)

- **인자**:
  - `commission`: `--bypass enc_stuck,enc_polarity,commission_limits` 에 `--cm-duty-max D`, `--cm-time-s T`(생략 = 빌드 값).
    - L·R 을 고르고 `commission_limits` 가 있으면 `--wheels-lifted` 도 요구한다(Codex 3 차 P2-5). 기존 시운전 설계의 받침대 전제를 따른다.
  - `step`·`scenario`: `--bypass steer_off,lift_off` 에 `--wheels-lifted`, `--forks-lowest`.
  - `record` 는 `ARM` 을 보내지 않으므로 받지 않는다.
- **도구 한계**:
  - 우회가 없으면 지금 값이다.
  - L·R 듀티 한계는 정규화한 D 이고, 인자 검사와 `send_duty` 가 같은 값을 쓴다.
  - 유지 한계는 `T − 0.5 s` 다. T 를 생략하면 빌드 값으로 계산한다. 이 값이 `COMMISSION_HOLD_MIN_S` 보다 짧으면 거부한다.
  - 시간 상한 시나리오는 `--limit-s` 를 T 와 같게 강제하고, 3 s 상한을 천장까지 늘린다.
  - M·H 는 0.15·0.2 s 그대로다.
- **엔코더 우회(도구 전용)**:
  - 고른 종류의 비트만 `early_stop` 과 시나리오 정지에서 뺀다. 극성만 우회하면 정체는 그대로 멈춘다.
  - M·H 위치 창도 그대로다.
- **삼각파 프로파일**(Codex 2 차 P2-6):
  - 11-24 진단 브랜치의 `--profile-tri LO HI PERIOD CYCLES`(4fc69237)를 정식으로 옮긴다.
  - **부호**(Codex 3 차 P1-4): 진단 코드는 `abs(duty) == HI` 만 보고 모든 조각을 양수로 보냈다. 결과 계산은 부호 있는 `duty` 를 써서 방향 판정과 어긋났다. 정식에서는 `--duty` 의 부호를 모든 조각과 기록에 똑같이 붙이고, \|duty\| = HI 를 요구한다.
  - **마감표**: 조각 수는 `PERIOD / 0.1` 이 정수일 때만 받는다(아니면 거부). 조각 k 의 끝은 시작 시각 + (k + 1) × 0.1 s 인 **절대 마감**이다. 11-24 의 30 s 프로파일은 루프 부가시간 때문에 실제 비영 출력이 31.44–31.46 s 였다.
  - **T 검사**: T 는 '마감표의 마지막 비영 조각 끝 + 그 명령의 유효기간(60 ms) + 인계'보다 커야 한다. 아니면 거부한다. ARM 예산도 같은 마감표에 정리 시간을 더해 잡는다.
- **긴 실행의 seq 순환**(Codex 2 차 P2-5):
  - 100 Hz 면 약 655 s 에 seq 가 한 바퀴 돈다. 그래서 수락·구동 구간 판정은 seq 집합이 아니라 (seq, 쓰기 순번, 쓰기 시각)으로 한다.
  - `STATE.last_rx_seq` 를 쓰기에 대응시키는 근거(Codex 3 차 P2-3):
    - 같은 연결·부팅·무장 세대 안이어야 한다.
    - 쓰기를 완료한 시각이 그 `STATE` 를 읽은 시각보다 앞서야 한다.
    - 명령 echo 가 그 `STATE` 의 `mcu_time_us` 이하여야 한다.
    - 같은 seq 의 이전 쓰기와는 seq 한 바퀴(65 536 프레임) 넘게 떨어져야 한다.
  - 후보가 둘 이상이면 그 구동 구간은 **판정 불가**이고, 이유를 남긴다.
- **확인·기록·판정 표식**(agy 5·7, Codex 2 차 P2-7):
  - `--bypass` 가 있으면 `--yes` 가 있어도 "우회 요청: …" 을 따로 입력해 확인받는다.
  - 터미널 표시(Codex 3 차 P2-5):
    - 요청 때 '우회 요청'.
    - MCU 가 적용값을 보고하면 '우회 중(MCU): …'.
    - 도구 전용 우회는 '우회 중(도구): …'.
    - 취소 완료 때 '해제 확인'.
    - 확인하지 못하고 끝나거나 연결이 끊기면 '상태 미확인'.
  - 실행 헤더에 링크 버전, MCU 요청 우회, 도구 전용 우회를 적는다. 매 `STATE` 행에는 적용 우회를 적는다.
  - 결과 JSON 과 `analyze` 에 `bypassed: {mcu: [...], tool: [...]}`, `not_for_gate: true` 를 넣는다.
  - **판정 진입점**(`analyze`, `m_entry`, `kth`, `clock`, `tools/h743_first_boot.py`)은 실행 경계마다 헤더**와 그 구간의 모든 `STATE` 행**을 읽는다. 결과 행 없이 끝난 수동 `record` 구간도 포함한다(Codex 3 차 P2-6). 우회가 있는 실행은 `--allow-bypassed` 없이는 판정을 거부하고, 있으면 `not_for_gate` 로 표시한다. 합성 기록의 `refuse_or_mark` 와 같은 방식이다.
  - 수동 `record` 가 요청 없이 0 아닌 적용 우회를 관측하면 그 기록도 표식을 단다.
- **수용 시험(pty 모형)**:
  - 모형 plant 에 **바퀴 계수 고정** 옵션을 두어, 엔코더 없는 바퀴처럼 `stuck` 이 실제로 켜지게 한다.
  - 수용 조건(9 절): 도구가 고른 비트만 무시하고 끝까지 돌며, 마지막 0 과 정리가 정상이다.
  - KTH 무효 주입은 축 끄기 시험용이다.

  - **R3**(Codex 2 차 정정):
    - `enc_phys_max_rad_s`(15)는 설정 검증에서 허용 표본 간격 동안 16 비트 계수 차분이 접히지 않는지 계산하는 값이다. 런타임 판정이 아니다.

    - 보드는 1 ms 마다 판정하고 `STATE` 는 10 ms 마다 나간다. 그래서 `STATE` 기록으로는 결함이 난 틱의 원시 차분과 간격을 되살릴 수 없다(Codex 3 차 P3). 필요해지면 별도 진단 계측으로 하고, 이 설계 밖이다.
