## 1. `--run` 벽시계 실행

`tools/real_autonomy.py --run` 은 지금 무엇도 열지 않고 거부한다. 6a 는 **HIL 경로만** 연다:

- `--run --hil <pty 경로>`: 호스트 클라이언트 `Client.HIL`. 첫 STATE 의 build bits 가 `connect_refusal(flags, Client.HIL)` 를 통과해야 한다 — HIL 보드(`HIL_PLANT`)가 아니면 `not_hil_board` 로 출력 없이 끝낸다. 저장소의 MCU 모형(`firmware/tools/mcu_model.c`)에 `--hil-plant 1`(build bit `HIL_PLANT`)을 더한다 — 모형의 plant 는 지금도 코어가 낸 출력을 따른다.
- `--run --device <경로>`(실 MCU): 지금처럼 아무것도 열기 전에 거부하되 사유를 `device_refused:s10_preconditions` 로 바꾼다(4c 장치 차단 유지).
- **루프**: 50 Hz, 다음 시작 = 첫 시작 + k × 20 ms 로 잠든다(밀린 틱은 건너뛰고 다음 경계로 — 4c 의 `loop_slow`·시작 간격 규칙이 그대로 판정). 시각은 `time.monotonic_ns`.
- **원천**: HIL 에서는 합성 원천을 쓴다 — 스캔(모형 오도메트리 자세에서 설정의 장면을 광선 투사, rig 와 같은 방식), SLAM(회차 계약을 지키는 원천, 보정은 항등), IMU(정지 중 중력 + 잡음), 깊이 없음(`d5_pocket` 우회로만 S10-A 가 끝까지 감 — 실 깊이 경로는 PR 7). **합성 원천은 `Client.HIL` 이고 HIL 보드가 확인된 실행에서만 만든다** — 그 밖에서 만들려 하면 `forklift_core.live.synthetic.SyntheticRefused`(텔레옵 다리의 리허설 표식과 같은 모듈). 기록 머리에 `synthetic` 표식.
- **운동 허가**: `real_loop.motion_allowed(transport)` 는 지금 `transport.fake_mcu is True` 만 본다. 6a 는 루프용 TTY 전송기가 **HIL 보드를 확인한 뒤에만** `hil_plant = True` 를 세우고, `motion_allowed` 가 `fake_mcu is True or hil_plant is True` 를 본다. 실 MCU(`Client.REAL`)는 그대로 DISARM 만.
- **콘솔**: 텔레옵 다리처럼 `console.live.server.LiveServer` 를 띄우고 `RealChannels`·중재기(`real_requests=True`)를 묶는다. 묶음 함수는 `tools/real_autonomy.py` 안에 두고 텔레옵 다리 코드는 건드리지 않는다(보드 확인 날 동결 경로).

## 2. 루프용 TTY 전송기

새 `tools/real_loop_transport.py` 의 `LoopTtyTransport` — 4c 루프의 전송기 계약(`FakeTransport` 가 지키는 것)을 실 TTY 위에서 지킨다. 텔레옵 다리의 `real_mcu_link.TtyLink` 는 바꾸지 않고 `open_raw`·`DELIMITER` 만 가져다 쓴다.

- `receive(host, now_ns, limit)`: 읽을 수 있는 바이트를 호스트에 넘김(`TtyLink.read_available` 와 같은 규칙, 장치 상실은 `host.disconnected`).
- `transmit(host, now_ns, gate)`: 반쯤 쓴 프레임이 있으면 **이어 쓰기 전에** `gate(frame, finish)` 를 다시 지나고, 거부되면 그 반쪽을 3 절대로 폐기한다. 그다음 호스트 큐에서 프레임마다 `gate(frame, write)` — `write` 는 그 자리에서 `os.write` 를 부른다(비블로킹). 첫 바이트도 못 쓰면(`EAGAIN`) `host.unsent` 로 돌려준다. 끝까지 쓴 프레임만 `(kind, seq, written_ns)` 로 낸다. `partial_frame`·`partial_since_ns` 는 루프의 막힌 쓰기 판정이 읽는다(4c 그대로).
- **쓰기 시작 지연 계약**(PR 5 7.1 6): `gate` 의 마지막 시계 읽기(`min(ns, 결정 + W)` 판정)에서 `os.write` 호출까지는 `send_boundary` 의 잠금 안 비교뿐이다. `os.write` 는 커널 버퍼에 복사하고 돌아오며, 줄 위로 나가는 시각은 장치에 달려 있다(USB CDC, 460800 bps 의 40 바이트 프레임 ≈ 0.9 ms). 그 상한은 7 절 '보드 날 확인'.

## 3. 반쪽 프레임 폐기

반쯤 쓴 프레임을 버리고 링크를 다시 열면, 새 열기의 구분자 `0x00` 이 MCU 수신 버퍼의 반쪽을 닫는다. 대부분은 길이·CRC 가 맞지 않아 버려진다. **본문이 다 나가고 끝 구분자만 못 나간 반쪽**은 그 구분자로 온전한 프레임이 되어 늦게 작동할 수 있다(PR 5 설계의 '0x00 이 반쪽을 완성' 경우). 그래서 루프용 전송기는 반쪽을 버린 뒤의 첫 쓰기를 **`0xFF 0x00`**(독 바이트 + 구분자)로 한다: COBS 에서 그룹 경계의 `0xFF` 는 254 바이트를 요구하므로 바로 오는 구분자로 디코드가 실패하고, 그룹 중간이면 본문에 한 바이트가 더해져 CRC·길이 검사에서 버려진다. 반쪽이 없던 열기는 지금처럼 `0x00` 하나.

- 독 바이트 쓰기가 막히면(`EAGAIN`) 링크를 닫고 다시 열고, 열린 뒤 첫 쓰기를 다시 `0xFF 0x00` 으로 한다(반쪽 표식은 열기 사이에 유지).
- MCU 쪽은 깨진 프레임 하나를 수신 오류로 센다(기존 동작). 시험: 모형과 Python 디코더 둘 다에서 '끝 구분자만 빠진 반쪽 + `0xFF 0x00`' 이 프레임으로 받아들여지지 않음.

## 4. S10 정지 프레임의 `authority_changed`

송신 관문은 루프 프레임이 결정된 때의 권한(lease id, 제어 세대)과 지금이 다르면 `authority_changed` 경보로 거절한다(→ ①, DISARM). S10 의 제어 정지 프레임(`kind == "stop"`, 속도 0, 승강 유지)이 한 틱 늦게 쓰이는 사이 권한이 바뀌면 이 경보로 DISARM 이 되어, S10 이 의도한 '승강 유지 정지' 대신 DISARM 정지가 된다.

- 결정: **움직이지 않는 프레임**(`movable == False` — S10 정지, 대기 프레임의 0)은 권한 결박 검사를 건너뛴다. 다른 검사(허가 상태, STOPPED, 측정 신선도, lease 만료 등)는 그대로다. 움직이는 프레임은 지금처럼 거절한다. 근거: 권한 결박은 다른 권한 아래 결정된 **운동**이 나가지 않게 하는 것이고, 정지는 어느 권한에서도 허용되는 쪽이다.

## 5. 예외 틱의 콘솔 정산

틱 안의 예외로 비상에 빠지면 `_assemble_and_arbitrate` 의 `session.tick_end()` 에 닿지 않아, 그 틱 머리에서 받은 명령(`tick_start` 의 기록)의 답이 다음 틱에 `invalid` 로 정산된다. 6a 는 `cycle()` 의 예외 처리에서 그 틱의 `tick_start` 가 돌았고 `tick_end` 가 돌지 않았으면 **한 번** `session.tick_end(now, records, safety, (0.0, 0.0), None)` 을 부른다 — 후보는 0, 안전 상태는 `core.safety_state(t)`(그것도 실패하면 `None` 이 아닌 최소 상태 `{"real_exception": 사유}`). 이 호출의 예외는 삼키고 기록한다.

## 6. HIL 통합 시험 (`realtime`, ws1)

`mcu_model --hil-plant 1` 을 pty 너머에 두고 `LoopTtyTransport` + `RealLoop` 을 벽시계로 돌린다(`tests/integration/`, `mcu_model` 고정물 — `realtime` 표시로 ws1 의 한 프로세스 단계에서 돈다).

- S10-A 한 번(`d5_pocket` 우회, 합성 스캔·SLAM): `s10_lifted` 로 끝나고 모형의 오도메트리가 STATE 를 거쳐 루프에 닫힘.
- **정지 주입**(계획: 각 주입은 비영 명령이 수락된 상태에서 시작, 입력 나이 상한 안에 정지, 기록으로 정지 시한 판정):
  - 링크 송신 끊기(전송기 쓰기만 멈춤, STATE 는 계속): 모형이 명령 만료(`cap_ms` 150 ms) 뒤 멈춤 — 기록의 마지막 비영 DRIVE 쓰기에서 모형의 바퀴 0 까지 ≤ 150 ms + `stop_grace_ms`.
  - 스캔 원천 멈춤: 층 watchdog 이 `layer_overdue` → `overdue_end`(1.0 s) 안에 `layer_latency_exceeded` 래치.
  - SLAM 원천 멈춤: 준비 판정 `slam:stale` 로 출력 대기(0.5 s), 그 뒤 계속 없으면 래치 사유대로.
  - STATE 지연(모형 `--silent-at-ms`): `measurement_stale` 경보 → DISARM.
- 실 MCU 경로(`--device`)는 여전히 거부됨(시험), 합성 원천은 `Client.REAL` 에서 `SyntheticRefused`(시험).

## 7. 보드 날 확인 (6a 를 막지 않음)

| 항목 | 기준 | 어디서 |
|---|---|---|
| 실 검사기·층 질의를 넣은 틱이 송신 관문에 닿는 시각 | 틱 시작 + 25 ms 안(PR 5 7.3) | Jetson |

## 8. 시험 (단위)

- `LoopTtyTransport`: pty 쌍으로 — 이어 쓰기 전 gate 재통과·거부 시 폐기와 재개방; `EAGAIN` 첫 바이트 → `host.unsent`; 끝까지 쓴 프레임만 보고; 반쪽 뒤 첫 쓰기 `0xFF 0x00`, 반쪽 없는 열기 `0x00`.
- 디코더: 끝 구분자만 빠진 반쪽 + `0xFF 0x00` 이 프레임이 아님(Python `FrameDecoder`, 모형은 통합 시험).
- `motion_allowed`: `hil_plant` 는 HIL 확인 뒤에만, 실 장치는 거부.
- 4 절: 한 틱 늦은 S10 정지 프레임이 권한 변경 뒤에도 쓰이고 DISARM 이 아님; 움직이는 프레임은 여전히 `authority_changed`.
- 5 절: 틱 안 예외에서 그 틱의 제출 답이 정산됨(다음 틱 `invalid` 아님).
- `--run`: 실 장치 거부 사유, HIL 이 아닌 보드 거부, 합성 원천 거부.
