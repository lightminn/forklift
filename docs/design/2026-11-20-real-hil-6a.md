## 1. `--run` 벽시계 실행

`tools/real_autonomy.py --run` 은 지금 무엇도 열지 않고 거부한다. 6a 는 **HIL 경로만** 연다:

- `--run --hil --hil-model <mcu_model 실행 파일> [--hil-model-arg …]`: 호스트 클라이언트 `Client.HIL`. **실행기가 pty 를 직접 만들고 모형을 자식으로 띄운다**(6 회차 P1-1: 이미 있는 pty 를 받으면 그 전에 연 다른 송신자가 점유 전에 구분자를 쓰고 닫을 수 있고, 사후 fd 검사는 그 쓰기를 못 봄 — Codex 재현). 순서: `os.openpty()` → slave fd 에 곧바로 `TIOCEXCL` → `/proc/*/fd` 에서 같은 slave(`st_rdev`)를 연 다른 fd 가 있으면 `device_shared:<pid>` 로 그 pty 를 버리고 거부 → **마스터 쪽 입력을 모두 읽어 버림**(점유 전에 누가 slave 에 쓴 바이트는 모형이 보기 전에 사라짐) → 모형을 `--link-fd <마스터>`(`pass_fds`)·`--hil-plant 1` 로 띄움 → 실행기의 마스터 사본 닫기 → 3 절의 독 바이트열 → 루프 시작. slave 경로는 어디에도 알리지 않는다. 모형(`firmware/tools/mcu_model.c`)의 `--hil-plant 1` 은 build bit `HIL_PLANT` 와 `OUTPUTS_LOCKED` 를 **함께** 세운다(코어가 잠금 없는 `hil_plant` 설정을 거부함, `drive.c` 설정 검증; `--commission-build 1` 과 같이 주면 모형이 기동을 거부). 모형의 plant 는 지금도 코어가 낸 출력을 따른다(1 회차 P2-4). **재개방은 없다**: 장치 상실(`EIO`·`ENXIO`·`EBADF`, 모형 종료)이면 `device_lost` 로 실행을 끝낸다(남은 반쪽이 있었으면 사유에 `stream_tainted`) — 다시 하려면 새 실행(새 모형·pty).
- **HIL 확인의 수명**(1 회차 P1-3, 3 회차 P1-2): 전송기의 `hil_plant` 는 **지금 열린 fd 와 그 위의 부팅**에 묶인다 — 그 fd 에서 받은 STATE 의 build bits 에 **`HIL_PLANT` 와 `OUTPUTS_LOCKED` 가 둘 다** 서 있고 `COMMISSION_BUILD` 가 없으며 부팅 id 를 기록했을 때 참이 된다(전송기의 자체 판정 — 호스트의 `connect_refusal(…, Client.HIL)` 은 `HIL_PLANT` 만 보므로 그것에 기대지 않음; `build_policy` 는 텔레옵 경로라 바꾸지 않음). **이후 STATE 마다 다시 보고**, 같은 부팅이라도 어느 비트가 빠지면 곧바로 거짓. 부팅 id 가 바뀌면 곧바로 거짓이 되고 그 새 부팅의 STATE 가 위 조건을 보일 때 다시 참이 된다. 장치 상실은 실행 종료다(재개방 없음). **같은 fd 위의 재동기화**(3 절)는 fd·부팅이 그대로이므로 `hil_plant` 를 바꾸지 않고 호스트 수신 디코더도 비우지 않는다(연속 스트림; 6 회차 P2-2). 호스트(`McuLinkHost`)는 바꾸지 않는다. 합성 원천은 **매 틱 `transport.hil_plant` 가 참일 때만** 표본을 낸다(거짓인 동안 아무것도 내지 않음 — 원천 객체가 남아 있어도 미검증 상대에 데이터가 가지 않음). 루프의 `_transmit` 은 운동 허가(`motion_allowed`)를 `_cut_stuck_write`(재동기화할 수 있음) **뒤에** 읽는다(지금은 앞).
- `--run --device <경로>`(실 MCU): 지금처럼 아무것도 열기 전에 거부하되 사유를 `device_refused:s10_preconditions` 로 바꾼다(4c 장치 차단 유지).
- **루프**(1 회차 P2-2): 50 Hz, 잠들 때는 예약 시각(첫 시작 + k × 20 ms, 밀린 경계는 건너뜀)을 쓰고, `cycle()` 에는 **깨어난 직후의 `time.monotonic_ns()`** 를 넘긴다 — 4c 의 시작 간격 판정은 실제 시작 간격을 본다. 그래서 21–25 ms 틱이 이어지면 경계를 하나씩 건너뛰어 실제 간격이 약 40 ms 가 되고, 세 번째 연속 초과에서 `loop_slow` 다(의도한 고장 판정). 송신 관문 25 ms 기준과 50 Hz 운용 기준은 따로 잰다(7 절).
- **원천**: HIL 에서는 합성 원천을 쓴다 — 스캔(모형 오도메트리 자세에서 설정의 장면을 광선 투사, rig 와 같은 방식), SLAM(회차 계약을 지키는 원천, 보정은 항등), IMU(정지 중 중력 + 잡음), 깊이 없음(`d5_pocket` 우회로만 S10-A 가 끝까지 감 — 실 깊이 경로는 PR 7). **합성 원천은 `Client.HIL` 이고 HIL 보드가 확인된 실행에서만 만든다** — 그 밖에서 만들려 하면 `forklift_core.live.synthetic.SyntheticRefused`(텔레옵 다리의 리허설 표식과 같은 모듈). 기록 머리에 `synthetic` 표식.
- **운동 허가**: `real_loop.motion_allowed(transport)` 는 지금 `transport.fake_mcu is True` 만 본다. 6a 는 루프용 TTY 전송기가 **HIL 보드를 확인한 뒤에만** `hil_plant = True` 를 세우고, `motion_allowed` 가 `fake_mcu is True or hil_plant is True` 를 본다. 실 MCU(`Client.REAL`)는 그대로 DISARM 만.
- **콘솔**: 텔레옵 다리처럼 `console.live.server.LiveServer` 를 띄우고 `RealChannels`·중재기(`real_requests=True`)를 묶는다. 묶음 함수는 `tools/real_autonomy.py` 안에 두고 텔레옵 다리 코드는 건드리지 않는다(보드 확인 날 동결 경로).

## 2. 루프용 TTY 전송기

새 `tools/real_loop_transport.py` 의 `LoopTtyTransport` — 4c 루프의 전송기 계약(`FakeTransport` 가 지키는 것)을 실 TTY 위에서 지킨다. 텔레옵 다리의 `real_mcu_link.TtyLink` 는 바꾸지 않고 `open_raw`·`DELIMITER` 만 가져다 쓴다.

- `receive(host, now_ns, limit)`: 한 틱에 **최대 4096 바이트**만 읽어 호스트에 넘긴다(2 회차 P2-2: `TtyLink.read_available` 처럼 빌 때까지 읽으면 계속 읽히는 스트림이 감시와 DISARM 을 늦춤). 남은 바이트는 커널 버퍼에 두고 다음 틱에 읽는다. 호스트에는 **실제 읽기 완료 시각**(그 `os.read` 가 돌아온 직후의 `monotonic_ns`)을 수신 시각으로 준다(4 회차 P1-1: 틱 시작을 주면 호스트의 `valid_after_echo = expires − state_rx` 가 읽기 지연만큼 길어지고, MCU 는 그 기간을 STATE 의 실제 측정 시각에 더하므로 만료가 늦어짐 — 틱 시작 + 6 ms 에 생긴 STATE 를 + 7 ms 에 읽으면 + 106 ms 대 + 99 ms). 그래서 수신 시각은 틱 시작 `now_ns` 보다 늦을 수 있다.
- **두 시각의 쓰임**(4 회차 P1-1, 3 회차 P2-1): 실제 수신 시각 `rx_ns` 는 호스트의 echo 유효기간·신선도, 오도메트리 측정 구간(`_odom_entry` 의 `[rx − 지연 상한, rx]`), `book`·허가의 `on_state` 에 그대로 쓴다. 틱 시각으로 판정하는 곳은 틱 시작 `now_ns` 를 판정 시각으로 두고 **그보다 늦게 받은 표본은 판정 시각에 받은 것으로 본다** — 루프가 `Sample` 을 `encoder_speed` 에 넘길 때와 `Feedback.stamp_mono` 를 만들 때 `min(rx_ns, now_ns)` 를 쓴다(지금은 `encoder_speed` 가 나이 −1 ms 미만을 `stale` 로, 중재기의 `_valid_feedback` 이 음의 나이를 `no_feedback` 으로 거절함). 이 틱의 판정에서 나이 0 이니 실제보다 젊게 보지 않는다. 허가·호스트처럼 `now − rx` 를 직접 비교하는 곳은 음의 나이를 0 으로 본다(지금 코드가 그렇게 동작하는지 구현에서 하나씩 확인하고 시험으로 고정). 결정 기한(`결정 + W`)과 시작 간격 감시는 틱 시작 그대로. 시험: 틱 시작 + 1·3·6 ms 에 읽은 STATE 로 `stale`·`no_feedback`·`future` 가 하나도 없고, 같은 STATE 위의 DRIVE 의 `valid_after_echo` 가 틱 시작 기준보다 그 읽기 지연만큼 짧음. STATE 표본 수 상한(`limit`, 루프의 64)은 호스트 쪽 그대로. 장치 상실은 `host.disconnected`.
- **호스트 쪽 송신자 하나**(4 회차 P1-2, 5 회차 P1-1·P2-1, 6 회차 P1-1): 같은 장치를 다른 fd 로 연 도구(예: 관측 CLI 의 `ReconnectingLink.service()`)가 구분자 `0x00` 을 쓰면 독 바이트열 전에 반쪽 DRIVE 가 완성된다(Codex 재현). 그래서 1 절대로 실행기가 만든 pty 의 slave 를 만든 즉시 점유하고(`TIOCEXCL`, 이후 비루트 열기는 `EBUSY`), 점유 전 쓰기는 마스터에서 버리며, **점유를 실행 내내 놓지 않는다** — 반쪽 폐기·막힌 쓰기는 3 절대로 같은 fd 위에서 처리하고 닫지 않는다. 루트 열기와 다른 기계의 송신자는 막지 못한다 — 실차의 장치 잠금은 보드 확인 뒤 실행기 잠금에서(범위 밖). 시험: 점유 뒤 같은 slave 의 두 번째 열기 → `EBUSY`(반쪽 폐기 중에도); openpty 와 점유 사이에 끼워 넣은 쓰기(시험 훅)가 모형에 닿지 않음; 점유 전에 연 다른 fd(시험 훅) → `device_shared`; 모형 종료 → `device_lost`, 반쪽이 남았으면 `stream_tainted`.
- `transmit(host, now_ns, gate)`: 반쯤 쓴 프레임이 있으면 **이어 쓰기 전에** `gate(frame, finish)` 를 다시 지나고, 거부되면 그 반쪽을 3 절대로 폐기한다. 그다음 호스트 큐에서 프레임마다 `gate(frame, write)` — `write` 는 그 자리에서 `os.write` 를 부른다(비블로킹). 첫 바이트도 못 쓰면(`EAGAIN`) `host.unsent` 로 돌려준다. 끝까지 쓴 프레임만 `(kind, seq, written_ns)` 로 낸다. `partial_frame`·`partial_since_ns` 는 루프의 막힌 쓰기 판정이 읽는다(4c 그대로).
- **쓰기 시작 지연 계약**(PR 5 7.1 6, 1 회차 P2-3, 2 회차 P1-3): `gate` 의 마지막 시계 읽기에서 `os.write` 호출까지는 `send_boundary` 의 잠금 안 비교뿐이고 I/O 가 없지만, Python 에서 그 사이의 선점은 막을 수 없다. 그래서 마지막 판정의 기한을 **쓰기 여유 `A = 1 ms` 만큼 당긴다** — 비영 정상 DRIVE 는 마지막 읽기가 `min(ns, 결정 + W) − A` 이내일 때만 통과(5d 의 루프 관문 상수 `WRITE_ALLOWANCE_S`, 실차·HIL 공통). 그러면 마지막 읽기 → `os.write` 진입이 `A` 안이면 쓰기는 증거 기한 안에 시작한다. 그 구간의 합격 기준은 측정이다: p99.9 ≤ 1 ms(Jetson, 7 절 보드 날 확인) — **실차 운동 허가의 선행 조건**으로 둔다(6a 의 HIL 은 출력 잠금 보드라 운동이 없음). 시험(3 회차 P2-2): 가짜 시계로 첫 쓰기·이어 쓰기 각각, `ns` 가 먼저 오는 경우와 `결정 + W` 가 먼저 오는 경우를 번갈아 — 마지막 읽기 앞의 지연으로 `min(ns, 결정 + W) − A` 를 넘기면 쓰지 않음; 뒤의 지연이 A 안이면 쓰기가 `min(ns, 결정 + W)` 안에 시작함. 보드 측정은 분포(p99.9)와 개별 마감 초과 수를 따로 내고, 이어 쓰기는 마지막 구분자를 쓴 `os.write` 가 돌아온 시각까지 본다.
- **시각의 뜻**: 전송기는 프레임마다 `first_byte_ns`(첫 바이트 `os.write` 직전, D5 왕복용 — `TtyLink` 와 같음)와 `written_ns`(마지막 바이트를 쓴 `os.write` 가 돌아온 뒤)를 낸다. 루프의 `book.written`·허가의 `written`(S10 확인 계약)은 `written_ns`(쓰기 완료)를 쓴다.

## 3. 반쪽 프레임 폐기

반쯤 쓴 프레임을 버리고 링크를 다시 열면, 새 열기의 구분자 `0x00` 이 MCU 수신 버퍼의 반쪽을 닫는다. **본문이 다 나가고 끝 구분자만 못 나간 반쪽**은 그 구분자로 온전한 프레임이 되어 늦게 작동할 수 있다. 1판의 `0xFF 0x00` 은 틀렸다(1 회차 P1-1: 마지막 CRC 바이트도 빠졌고 그 값이 `0xFF` 이면 덧붙인 `0xFF` 가 그 바이트가 되어 원본과 바이트 단위로 같은 프레임이 됨 — Codex 가 실제 인코더로 재현).

- **독 바이트**: 반쪽을 버린 뒤의 첫 쓰기는 **96 개의 비영 바이트(`0x01` × 96) + `0x00`** 이다. 두 디코더(Python `FrameDecoder`, 펌웨어 `link.c`)는 구분자 사이 인코딩 길이가 `ENCODED_MAX`(`BODY_MAX + 1` = 91)를 넘으면 그 프레임을 길이 초과로 버린다(`_overflow`, `rx->overflow`). 반쪽이 어디서 끊겼든 그 뒤에 비영 바이트 96 개가 이어지면 구분자 전의 비영 바이트 수가 91 을 넘으므로 반쪽은 반드시 길이 초과로 버려진다(CRC 우연 일치에 기대지 않음).
- **같은 fd 위의 폐기**(5 회차 P1-1, 6 회차 P2-1·P2-2): 루프의 막힌 쓰기 판정(`_cut_stuck_write` → 전송기 재동기화)과 이어 쓰기 거절은 이 전송기에서 fd 를 닫지 않는다. 순서: ① 반쪽을 버림(그 프레임은 보고하지 않음) ② 같은 fd 위에 독 바이트열을 씀 — `EAGAIN` 으로 반쯤 쓰이면 **남은 바이트부터** 이어 쓴다(처음부터 다시 보내면 조금씩만 받는 수신기가 구분자에 끝내 닿지 못해 DISARM 이 계속 밀림 — Codex 재현) ③ 독 바이트열의 구분자까지 쓴 뒤에야 큐의 다음 프레임(DISARM 먼저). 수신 쪽은 손대지 않는다(RX 디코더 유지, `hil_plant` 유지). 장치 상실이면 1 절의 `device_lost`(반쪽·미완 독 바이트열이 남았으면 `stream_tainted`).
- **열기의 첫 쓰기**(2 회차 P1-2→P1-1)는 독 바이트열이다 — pty 를 새로 만들어도 지키는 같은 규칙이고, 실 장치(보드 확인 뒤)에서는 실행기만 재시작한 경우 MCU 수신 버퍼(펌웨어는 호스트 fd 가 닫혀도 RX 디코더를 초기화하지 않음)에 앞 실행기의 반쪽이 남았을 수 있어 필요하다. 반쪽 표식은 쓰지 않는다(언제나 독 바이트열).
- MCU 쪽은 깨진 프레임 하나를 수신 오류로 센다(기존 동작).

## 4. S10 정지 프레임의 `authority_changed` — 지금 규칙 유지

5a 구현 검토가 남긴 P2: S10 의 제어 정지 프레임이 한 틱 늦게 쓰이는 사이 권한(lease id, 제어 세대)이 바뀌면 송신 관문이 `authority_changed` 경보로 거절하고 ①(DISARM)이 된다. 1판은 움직이지 않는 프레임을 결박 검사에서 빼려 했으나 철회한다(1 회차 P1-2): S10 정지와 대기 프레임은 결정 때의 **실측 조향·승강을 목표값으로** 싣고 `movable=False` 로 기록되므로, 반쯤 쓴 프레임이 다음 틱에 끝날 때 축이 이미 움직였으면 그 프레임이 축을 옛 위치로 되돌릴 수 있다. 일반 0 속도 DRIVE 도 승강 허용오차(3 mm) 안의 목표 차이와 조향 변경을 `movable` 에 담지 않는다.

- **결정**: 예외를 두지 않는다. 권한이 바뀐 뒤의 S10 정지 프레임은 지금처럼 거절되고 DISARM 정지가 된다 — 멈추는 쪽이다. S10 이 의도한 '승강 유지 정지' 를 그 경합에서만 잃는다(DISARM 이 승강을 어떻게 다루는지는 펌웨어의 정지 동작 그대로).
- 시험(2 회차 P2-1): 반쯤 쓴 S10 정지 프레임과 그 사이 권한 변경 → 그 프레임은 완성되지 않고 폐기(재동기화), DISARM 이 쓰임 — 외부 결과로 판정한다(허가의 최종 사유는 `control_stop_discarded` 일 수 있고 틱 사유에 `authority_changed` 가 남지 않을 수 있음).

## 5. 예외 틱의 콘솔 정산

틱 안의 예외로 비상에 빠지면 `_assemble_and_arbitrate` 의 `session.tick_end()` 에 닿지 않아, 그 틱 머리에서 받은 명령(`tick_start` 의 기록)의 답이 다음 틱에 `invalid` 로 정산된다.

- **먼저 고칠 중재기 결함**(1 회차 P1-4, 정상 정산에도 있음): 원장은 요청을 `(request_token, request_seq)` 로 구분하지만 `resolve` 는 결과를 `request_id` 하나로 맞춘다 — 같은 `request_id`·다른 seq 의 제출 두 건이 한 묶음에 오면 하나의 결과가 둘에 붙는다. 그래서 **같은 묶음에서 아직 정산되지 않은 미션 요청과 `request_id` 가 같은 새 미션 요청은 적용 전에 `duplicate_request` 로 거절한다**(`Arbiter` 의 미션 요청 큐잉 자리, 기존 동작은 같은 id 가 없으면 그대로).
- **정산 계약**(1 회차 P2-1, 2 회차 P1-4): `cycle()` 은 진입하자마자 `session.last_records = None`(미기록)으로 둔다. `RealSession.tick_start` 는 **이 틱의** `commands.apply` 결과를 두 번째 `collect` **전에** `self.last_records` 에 둔다(그 `collect` 가 실패해도 결과가 남음). 예외 정산은 이 틱의 `last_records` 가 기록됐을 때 한다 — 앞 틱의 기록이 새 요청에 붙지 않는다.
- **`apply` 전·도중 예외**(3 회차 P1-1, 4 회차 P2-1): `link.begin` 은 첫 `collect` 전에 그 묶음의 명령을 미션 큐에 넣는다. 그 뒤 `apply` 전에 예외가 나면 명령이 큐에 남아 **다음 제어 세대에서** 실행될 수 있다(중재기의 `mission_context` 는 `queued` 요청의 세대 검사를 건너뜀 — Codex 재현: 옛 제출이 재무장 뒤 `m1` 으로 수락되고 AUTO). `apply` 도중 예외면 큐는 이미 비었고 앞 명령의 결과는 `log` 에만 남는다. 그래서 `MissionCommands.apply` 는 진행을 밖에서 읽을 수 있게 둔다: 시작할 때 `self.applying = ApplyProgress(records=[], pending=[정렬된 명령])` 을 세우고, 기록을 만들 때마다 `records` 에 더한 **뒤** 그 명령을 `pending` 에서 뺀다(예외를 낸 명령은 `pending` 에 남음), 정상 종료에 `applying = None`. 새 메서드 `MissionCommands.abandon(t) -> list[dict]` 는 ⓐ `applying` 이 있으면 그 `records` 그대로 + `pending` 의 명령마다 거절 기록, ⓑ 미션 큐에 남은 명령(apply 전 예외)마다 거절 기록을 돌려주고, 큐와 `applying` 을 비운다. 거절 기록은 `{"t", "command", "accepted": False, "reason": "tick_failed", "mission_id", "status", "request_id"}`(정상 기록과 같은 모양, `log` 에도 남김). **정산 목록** = 이 틱의 `last_records` 가 있으면 그것, 없으면 `abandon(t)` 의 결과 — `abandon` 은 `last_records` 가 없으면 **언제나** 부른다(5 회차 P1-2: `link.begin` 이 요청을 큐에 넣은 뒤 돌아오기 전에 실패해도 큐가 비워짐)(같은 묶음의 같은 `request_id` 는 위 `duplicate_request` 로 이미 막힘). 루프는 `tick_end` 를 부르기 **직전에** `self._tick_end_tried = True` 를 세운다(틱 머리에서 거짓으로). 예외 처리에서 **이 틱에 `link.begin` 이 돌았고**(`session.began` — `tick_start` 가 `begin` 을 부르기 **직전에** 세우고 틱 머리에서 거짓으로; 부분 실행된 `begin` 도 포함) `_tick_end_tried` 가 거짓이면 **한 번** `session.tick_end(now, 정산 목록, safety, (0.0, 0.0), None)` 을 부른다(정산 목록이 비어도 부름 — 그 틱의 다른 요청 답과 틱 토큰을 위해) — 후보는 0, 안전 상태는 `core.safety_state(t)`(그것도 실패하면 최소 상태 `{"real_exception": 사유}`). `tick_end` 가 진행 중에 실패한 경우(`_tick_end_tried` 참)에는 다시 부르지 않는다 — `Link.end` 는 원장 정산·응답 큐·lease 만료·틱 토큰 발급을 차례로 하므로 다시 부르면 틱 토큰이 두 번 나간다. 그 틱의 남은 답은 다음 틱에 `invalid` 로 정산되는 지금 동작 그대로다(기록).

## 6. HIL 통합 시험 (`realtime`, ws1)

`mcu_model --hil-plant 1` 을 pty 너머에 두고 `LoopTtyTransport` + `RealLoop` 을 벽시계로 돌린다(`tests/integration/`, `mcu_model` 고정물 — `realtime` 표시로 ws1 의 한 프로세스 단계에서 돈다).

- S10-A 한 번(`d5_pocket` 우회, 합성 스캔·SLAM): `s10_lifted` 로 끝나고 모형의 오도메트리가 STATE 를 거쳐 루프에 닫힘.
- **정지 주입**(계획: 각 주입은 비영 명령이 수락된 상태에서 시작, 입력 나이 상한 안에 정지, 기록으로 정지 시한 판정; 1 회차 P2-5 로 원인과 관측량을 나눔):
  - **송신만 끊기**(전송기 쓰기 멈춤, STATE 는 계속 — bring-up `tx_cut` 과 같은 방식). 모형이 마지막으로 수락한 seq 는 STATE 의 `last_rx_seq` 로 확인하고, 그 seq 의 DRIVE 를 실행기 기록에서 찾아 **MCU 의 실제 만료 시각** `E = echo_mcu_time_us + min(valid_after_echo_ms, MCU 상한)`(펌웨어 `drive.c` 의 계산, MCU 시각)을 계산한다(3 회차 P2-3: 수락 관측 시각부터 세면 기산점 회귀를 못 잡음). 관측 오차 = MCU 틱 1 ms + STATE 간격 한 번. 시한: ① 출력 차단 — 모형 모드가 `STOPPING` 이 되는 MCU 시각 ≤ `E` + 오차, ② 모드 전이 — `DISARMED` ≤ ① + `stop_grace_ms` + 오차, ③ 바퀴 — `STOPPING` 에서는 바퀴 목표 0 이라도 PI 출력이 계속되므로 시한은 `DISARMED`(출력 차단) 기준: 속도 0.01 m/s 미만이 `DISARMED` + 3·`PLANT_WHEEL_TAU_S`(plant.c 의 1차 지연) + 오차 안에 시작해 200 ms 유지(정확한 0 은 쓰지 않음).
  - **STATE 만 끊기**(모형에 `--state-silent-at-ms`·`--state-silent-ms` 를 더함: STATE 송신만 멈추고 명령 수신은 계속): 루프가 `measurement_stale` 경보 → DISARM 을 **씀**(전송기 기록), 모형이 그 DISARM 을 수락(STATE 가 돌아온 뒤 `DISARMED` 와 `last_rx_seq` 로 확인). 권한 철회가 먼저 오면 `authorization_revoked` 래치도 정답으로 받는다. 기존 `--silent-at-ms`(양방향 침묵)는 송신과 수신을 함께 끊어 DISARM 수락을 볼 수 없으므로 이 시험에 쓰지 않는다.
  - **입력 원천 멈춤의 공통 판정**(4 회차 P2-2, 5 회차 P2-2·P2-3): 주입마다 **비영 금지 시각** `F` 를 실제 판정과 같은 식으로 기록에서 계산한다 —
    - 스캔: 층 watchdog 의 기대 시각 `F = scan.last_s + scan_period_s + budget_s`(마지막 스캔의 `last_s`, `RealLayer` 의 `_expected_s` 와 같은 식);
    - STATE: 호스트 신선도의 `F = state_rx_ns + state_max_age_s` (MCU 시각 규칙이면 `− 그 STATE 의 지연 상한`, `McuLinkHost._age_ns` 와 같은 식);
    - SLAM: `F = pose_reply_ns + SLAM_MAX_AGE_S`(처리된 마지막 응답의 취득 시각, 루프의 `_fresh_ns` 와 같은 식).
    판정: ① 결정 시각이 `F` 이후인 비영 DRIVE 가 하나도 없음, ② **모든 비영 DRIVE 의 마지막 판정 시각** `last_gate_ns ≤ F − A` — `last_gate_ns` 는 루프 관문 `judge` 가 `write_late` 비교에 **실제로 쓴 시계 값**이다(6 회차 P2-3: 전송기가 쓰기 직전에 시계를 다시 읽으면 비교하려는 값이 바뀜). `judge` 는 그 값을 관문에 돌려주고, `send_boundary` 가 그 판정으로 `write()` 를 부를 때 전송기의 쓰기 콜백에 넘겨(`write(judged_ns)`) 전송기가 그 프레임에 첫 쓰기·이어 쓰기 중 마지막으로 성공한 쓰기의 값을 기록한다. 시간축은 모두 호스트 단조시계 ns — 스캔의 `F` 는 루프의 코어 시각 원점 `start_ns` 로 바꾼다(`start_ns + F_s × 1e9`), SLAM 의 `pose_reply_ns` 는 이미 그 축, 그리고 그 `written_ns ≤ F + 1 ms`(마지막 `os.write` 귀환 여유, 보드 날 확인), ③ 정지 쓰기 시한을 따로 본다. 추가 주입: `F` 직전에 비영 DRIVE 를 반쯤 쓰게 하고(`EAGAIN` 스크립트) `F` 뒤에 풀어 — 이어 쓰기 거절, 독 바이트열, 그 프레임 미완성.
  - 스캔 원천 멈춤: ② 첫 `layer_overdue` 평가(`F` 다음 틱, 20 ms 안)에서 대기(0 속도 DRIVE) — 그 틱부터 비영 없음; 이어 `overdue_end`(1.0 s)를 넘긴 첫 평가에서 `layer_latency_exceeded` 래치와 DISARM 쓰기 — 시한 = 첫 overdue + 1.0 s + 20 ms + 쓰기 한 틱.
  - STATE 만 끊기는 위 그대로에 ① 을 더하고, ② DISARM 쓰기 ≤ `F` + 20 ms + 쓰기 한 틱.
  - SLAM 원천 멈춤: 현행 정책에서 `slam:stale` 은 곧바로 래치 사유다 — ① 과 ② 래치 사유 `slam:stale` 와 DISARM 쓰기 ≤ `F` + 20 ms + 쓰기 한 틱.
- **양성 진입점 시험**(1 회차 P2-4): 위 S10-A 한 번은 실제 `tools/real_autonomy.py --run --hil --hil-model <빌드한 mcu_model>` 진입점으로 돈다(직접 조립이 아니라 CLI 의 확인 순서와 합성 원천 생성 경계를 지나게).
- 실 MCU 경로(`--device`)는 여전히 거부됨(시험), 합성 원천은 `Client.REAL` 에서 `SyntheticRefused`(시험).

## 8. 시험 (단위)

- `LoopTtyTransport`: pty 쌍으로 — 이어 쓰기 전 gate 재통과·거부 시 **같은 fd 위에서** 폐기(fd 번호·점유 유지)와 독 바이트열, 그 뒤 DISARM; 독 바이트열이 `EAGAIN` 으로 32 바이트씩 끊겨도 남은 바이트부터 이어 써 끝나고 DISARM 이 수신됨; `EAGAIN` 첫 바이트 → `host.unsent`; 끝까지 쓴 프레임만 보고; 첫 쓰기가 독 바이트열(`0x01 × 96 + 0x00`)이고 그 구분자 전에는 다른 프레임 없음; 재동기화에서 RX 디코더·`hil_plant` 유지; 한 틱 읽기 4096 바이트 상한.
- 디코더: DRIVE·ARM·DISARM 프레임을 **끝 구분자가 아직 전달되지 않은 모든 절단 위치**에서 자르고 독 바이트(+ 독 바이트 자체의 모든 부분 쓰기 뒤 다시 독 바이트)를 붙이면 Python `FrameDecoder` 가 아무 프레임도 받지 않음; 펌웨어 디코더는 모형 통합 시험에서 같은 경우 하나 이상.
- `motion_allowed`: `hil_plant` 는 HIL 확인 뒤에만, 실 장치는 거부.
- 4 절: 반쯤 쓴 S10 정지 프레임과 그 사이 권한 변경 → 그 프레임 미완성·폐기(재동기화)·DISARM 쓰임(외부 결과로 판정).
- 5 절: 틱 안 예외에서 그 틱의 제출 답이 정산됨(다음 틱 `invalid` 아님); `link.begin` 이 제출을 큐에 넣은 뒤 돌아오기 전에 예외 → 큐 비워짐·원장 정산·재무장 뒤 옛 제출 미실행; `apply` 전 예외면 큐의 미적용 제출이 버려지고 `tick_failed` 로 원장에 남으며 재무장 뒤에도 실행되지 않음; `apply` 도중 예외(첫 제출 수락 기록 뒤 둘째에서 예외)면 원장에 첫째는 그 결과(`m1` 수락), 둘째는 `tick_failed`; HIL 확인이 `HIL_PLANT` 만 선 STATE 를 거절하고 같은 부팅의 후속 STATE 에서 비트가 빠지면 곧바로 운동·합성 표본이 닫힘; 두 번째 `collect` 실패에도 `last_records` 로 정산; `tick_end` 진행 중 실패는 다시 부르지 않음(틱 토큰 하나); 같은 묶음의 같은 `request_id`·다른 seq 제출은 둘째가 `duplicate_request`.
- 1 절: HIL 확인이 부팅 변경에서 꺼지고 새 부팅의 STATE 확인 전까지 운동·합성 표본 없음; 모형 종료는 `device_lost` 로 실행 종료(재개방 없음); `_transmit` 이 `_cut_stuck_write` 뒤에 운동 허가를 읽음; 예약기는 깨어난 시각을 넘기고 21–25 ms 틱 연속이면 `loop_slow`.
- `--run`: 실 장치 거부 사유, HIL 이 아닌 보드 거부, 합성 원천 거부.
