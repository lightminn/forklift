## 1. `--run` 벽시계 실행

`tools/real_autonomy.py --run` 은 지금 무엇도 열지 않고 거부한다. 6a 는 **HIL 경로만** 연다:

- `--run --hil --hil-model <mcu_model 실행 파일> --duration-s <초> [--hil-model-arg …]`: 호스트 클라이언트 `Client.HIL`. **실행기가 pty 를 직접 만들고 모형을 자식으로 띄운다**(6 회차 P1-1: 이미 있는 pty 를 받으면 그 전에 연 다른 송신자가 점유 전에 구분자를 쓰고 닫을 수 있고, 사후 fd 검사는 그 쓰기를 못 봄 — Codex 재현). 순서: `os.openpty()` → slave fd 에 곧바로 `TIOCEXCL`, 이어 두 fd 에 `O_NONBLOCK`(7 회차 P2-1: openpty 의 fd 는 블로킹이라 빈 마스터 비우기가 멈춤)·slave 에 `FD_CLOEXEC`(자식이 slave 를 물려받지 않게) → `/proc/*/fd` 에서 같은 slave(`st_rdev`)를 연 다른 fd 가 있으면 `device_shared:<pid>` 로 그 pty 를 버리고 거부 → **마스터 쪽 입력을 모두 읽어 버림**(점유 전에 누가 slave 에 쓴 바이트는 모형이 보기 전에 사라짐) → 모형을 `--link-fd <마스터>`(`pass_fds`)·`--hil-plant 1` 로 띄움 → 실행기의 마스터 사본 닫기 → 3 절의 독 바이트열 → 루프 시작. slave 경로는 어디에도 알리지 않는다. 모형(`firmware/tools/mcu_model.c`)의 `--hil-plant 1` 은 build bit `HIL_PLANT` 와 `OUTPUTS_LOCKED` 를 **함께** 세운다(코어가 잠금 없는 `hil_plant` 설정을 거부함, `drive.c` 설정 검증; `--commission-build 1` 과 같이 주면 모형이 기동을 거부). 모형의 plant 는 지금도 코어가 낸 출력을 따른다(1 회차 P2-4). **재개방은 없다**: 장치 상실(`EIO`·`ENXIO`·`EBADF`, 모형 종료)이면 `device_lost` 로 실행을 끝낸다(남은 반쪽이 있었으면 사유에 `stream_tainted`) — 다시 하려면 새 실행(새 모형·pty).
- **모형의 수명**(7 회차 P2-2): 실행기가 모형을 소유한다. ① 기동: 모형을 띄운 뒤 `HIL_FIRST_STATE_S = 2.0` 초 안에 1 절 조건을 만족하는 STATE 가 없으면 `hil_no_state`(STATE 는 왔지만 비트가 틀리면 `hil_refused:<flags>`)로 루프를 시작하지 않고 끝낸다. ② 실행 중: 매 틱 끝에 `proc.poll()` — 종료했으면 `device_lost:model_exit:<code>`. 전송기의 장치 상실은 `transport.lost`(사유 문자열)에 남기고 예외로 올린다 — 루프는 지금처럼 그 틱을 비상으로 처리하고 기록하며, 실행기는 매 `cycle()` 뒤 `transport.lost` 를 보고 그 사유로 실행을 끝낸다(루프의 비상 처리에 묻히지 않게). ③ 종료(정상·예외·`SIGINT`/`SIGTERM` — 시그널 처리기가 종료 표시를 세우고 루프가 다음 틱에서 나옴): `finally` 에서 slave 닫기 → `proc.terminate()` → 1 초 기다림 → 남았으면 `proc.kill()` → `proc.wait()`(회수). 모형은 링크 읽기 오류를 입력 없음으로 보고 계속 돌 수 있으므로 slave 닫기에 기대지 않는다. 실행기가 `SIGKILL` 로 죽으면 `finally` 가 돌지 않으므로 모형에 `--duration-ms`(실행 시간 + `HIL_MODEL_EXTRA_S`, 10.3 의 한 산식)를 함께 넘겨 스스로 끝나게 한다 — `--hil` 에서 `--duration-s` 는 **필수**이고 0 초과 3600 이하(8 회차 P2-1). 모형의 수명·링크·빌드 인자(`--link`, `--link-fd`, `--duration-ms`, `--hil-plant`, `--commission-build`, `--outputs-locked`)는 실행기 소유다: `--hil-model-arg` 에 그중 하나가 있으면 `hil_model_arg_reserved:<이름>` 으로 시작 전에 거부하고, 실행기의 인자를 사용자 인자보다 **앞에** 둔다(모형은 같은 인자가 반복되면 첫 값을 씀). 시험: 빈 pty 에서 기동 순서가 멈추지 않음; STATE 없는 모형(`--silent-at-ms 0`) → 2 s 뒤 `hil_no_state`·자식 회수; 비트가 틀린 모형 → `hil_refused`; 실행 중 모형 `SIGKILL` → `device_lost:model_exit`, 실행 종료; 실행기 `SIGTERM` → 자식 회수(좀비 없음); 실행기 `SIGKILL`(`--duration-s 3`) → 모형이 모형 기동부터 3 s + `HIL_MODEL_EXTRA_S`(11 s) 안에 스스로 종료; 예약 인자를 `--hil-model-arg` 로 주면 `hil_model_arg_reserved`.
- **장치 상실의 종료 사유**(8 회차 P2-2): 모형 종료·slave 의 `POLLHUP`·쓰기 `EIO` 는 한 사건에서 함께 보일 수 있으므로 어느 것을 먼저 봤든 같은 사유를 만든다. 전송기는 상실을 처음 본 순간에 **반쪽 프레임이나 끝나지 않은 독 바이트열이 남았는지**(`stream_tainted`)와 처음 본 경로(`write_eio`·`read_hup`·`read_eio`·`model_poll`)를 `transport.lost` 에 고정하고, 실행기는 종료 처리에서 자식을 회수한 뒤(위 ③) 종료 코드를 더해 사유 `device_lost:model_exit=<code|none>:stream_tainted=<0|1>:first=<경로>` 를 기록한다. 시험: 반쪽 DRIVE 가 남은 상태에서 모형 `SIGKILL` → `model_exit=-9`·`stream_tainted=1`(전송기가 먼저 보든 `poll` 이 먼저 보든), 반쪽 없는 종료 → `stream_tainted=0`.
- **HIL 확인의 수명**(1 회차 P1-3, 3 회차 P1-2): 전송기의 `hil_plant` 는 **지금 열린 fd 와 그 위의 부팅**에 묶인다 — 그 fd 에서 받은 STATE 의 build bits 에 **`HIL_PLANT` 와 `OUTPUTS_LOCKED` 가 둘 다** 서 있고 `COMMISSION_BUILD` 가 없으며 부팅 id 를 기록했을 때 참이 된다(전송기의 자체 판정 — 호스트의 `connect_refusal(…, Client.HIL)` 은 `HIL_PLANT` 만 보므로 그것에 기대지 않음; `build_policy` 는 텔레옵 경로라 바꾸지 않음). **이후 STATE 마다 다시 보고**, 같은 부팅이라도 어느 비트가 빠지면 곧바로 거짓. 부팅 id 가 바뀌면 곧바로 거짓이 되고 그 새 부팅의 STATE 가 위 조건을 보일 때 다시 참이 된다. 장치 상실은 실행 종료다(재개방 없음). **같은 fd 위의 재동기화**(3 절)는 fd·부팅이 그대로이므로 `hil_plant` 를 바꾸지 않고 호스트 수신 디코더도 비우지 않는다(연속 스트림; 6 회차 P2-2). 호스트(`McuLinkHost`)는 바꾸지 않는다. 합성 원천은 **매 틱 `transport.hil_plant` 가 참일 때만** 표본을 낸다(거짓인 동안 아무것도 내지 않음 — 원천 객체가 남아 있어도 미검증 상대에 데이터가 가지 않음). 루프의 `_transmit` 은 운동 허가(`motion_allowed`)를 `_cut_stuck_write`(재동기화할 수 있음) **뒤에** 읽는다(지금은 앞).
- `--run --device <경로>`(실 MCU): 지금처럼 아무것도 열기 전에 거부하되 사유를 `device_refused:s10_preconditions` 로 바꾼다(4c 장치 차단 유지).
- **루프**(1 회차 P2-2): 50 Hz, 잠들 때는 예약 시각(첫 시작 + k × 20 ms, 밀린 경계는 건너뜀)을 쓰고, `cycle()` 에는 **깨어난 직후의 `time.monotonic_ns()`** 를 넘긴다 — 4c 의 시작 간격 판정은 실제 시작 간격을 본다. 그래서 21–25 ms 틱이 이어지면 경계를 하나씩 건너뛰어 실제 간격이 약 40 ms 가 되고, 세 번째 연속 초과에서 `loop_slow` 다(의도한 고장 판정). 송신 관문 25 ms 기준과 50 Hz 운용 기준은 따로 잰다(7 절).
- **원천**: HIL 에서는 합성 원천을 쓴다 — 스캔(모형 오도메트리 자세에서 설정의 장면을 광선 투사, rig 와 같은 방식), SLAM(회차 계약을 지키는 원천, 보정은 항등), IMU(정지 중 중력 + 잡음), 깊이 없음(`d5_pocket` 우회로만 S10-A 가 끝까지 감 — 실 깊이 경로는 PR 7). **합성 원천은 `Client.HIL` 이고 HIL 보드가 확인된 실행에서만 만든다** — 그 밖에서 만들려 하면 `forklift_core.live.synthetic.SyntheticRefused`(텔레옵 다리의 리허설 표식과 같은 모듈). 기록 머리에 `synthetic` 표식.
- **운동 허가**: `real_loop.motion_allowed(transport)` 는 지금 `transport.fake_mcu is True` 만 본다. 6a 는 루프용 TTY 전송기가 **HIL 보드를 확인한 뒤에만** `hil_plant = True` 를 세우고, `motion_allowed` 가 `fake_mcu is True or hil_plant is True` 를 본다. 실 MCU(`Client.REAL`)는 그대로 DISARM 만.
- **콘솔**: 텔레옵 다리처럼 `console.live.server.LiveServer` 를 띄우고 `RealChannels`·중재기(`real_requests=True`)를 묶는다. 묶음 함수는 `tools/real_autonomy.py` 안에 두고 텔레옵 다리 코드는 건드리지 않는다(보드 확인 날 동결 경로).

## 2. 루프용 TTY 전송기

새 `tools/real_loop_transport.py` 의 `LoopTtyTransport` — 4c 루프의 전송기 계약(`FakeTransport` 가 지키는 것)을 실 TTY 위에서 지킨다. 텔레옵 다리의 `real_mcu_link.TtyLink` 는 바꾸지 않고 `open_raw`·`DELIMITER` 만 가져다 쓴다.

- `receive(host, now_ns, limit)`: 한 틱에 **최대 4096 바이트**만 읽어 호스트에 넘긴다(2 회차 P2-2: `TtyLink.read_available` 처럼 빌 때까지 읽으면 계속 읽히는 스트림이 감시와 DISARM 을 늦춤). 남은 바이트는 커널 버퍼에 두고 다음 틱에 읽는다. 호스트에는 **실제 읽기 완료 시각**(그 `os.read` 가 돌아온 직후의 `monotonic_ns`)을 수신 시각으로 준다(4 회차 P1-1: 틱 시작을 주면 호스트의 `valid_after_echo = expires − state_rx` 가 읽기 지연만큼 길어지고, MCU 는 그 기간을 STATE 의 실제 측정 시각에 더하므로 만료가 늦어짐 — 틱 시작 + 6 ms 에 생긴 STATE 를 + 7 ms 에 읽으면 + 106 ms 대 + 99 ms). 그래서 수신 시각은 틱 시작 `now_ns` 보다 늦을 수 있다.
- **두 시각의 쓰임**(4 회차 P1-1, 3 회차 P2-1): 실제 수신 시각 `rx_ns` 는 호스트의 echo 유효기간·신선도, 오도메트리 측정 구간(`_odom_entry` 의 `[rx − 지연 상한, rx]`), `book`·허가의 `on_state` 에 그대로 쓴다. 틱 시각으로 판정하는 곳은 틱 시작 `now_ns` 를 판정 시각으로 두고 **그보다 늦게 받은 표본은 판정 시각에 받은 것으로 본다** — 루프가 `Sample` 을 `encoder_speed` 에 넘길 때와 `Feedback.stamp_mono` 를 만들 때 `min(rx_ns, now_ns)` 를 쓴다(지금은 `encoder_speed` 가 나이 −1 ms 미만을 `stale` 로, 중재기의 `_valid_feedback` 이 음의 나이를 `no_feedback` 으로 거절함). 이 틱의 판정에서 나이 0 이니 실제보다 젊게 보지 않는다. 허가·호스트처럼 `now − rx` 를 직접 비교하는 곳은 음의 나이를 0 으로 본다(지금 코드가 그렇게 동작하는지 구현에서 하나씩 확인하고 시험으로 고정). 결정 기한(`결정 + W`)과 시작 간격 감시는 틱 시작 그대로. 시험: 틱 시작 + 1·3·6 ms 에 읽은 STATE 로 `stale`·`no_feedback`·`future` 가 하나도 없고, 같은 STATE 위의 DRIVE 의 `valid_after_echo` 가 틱 시작 기준보다 그 읽기 지연만큼 짧음. STATE 표본 수 상한(`limit`, 루프의 64)은 호스트 쪽 그대로. 장치 상실은 `host.disconnected`.
- **호스트 쪽 송신자 하나**(4 회차 P1-2, 5 회차 P1-1·P2-1, 6 회차 P1-1): 같은 장치를 다른 fd 로 연 도구(예: 관측 CLI 의 `ReconnectingLink.service()`)가 구분자 `0x00` 을 쓰면 독 바이트열 전에 반쪽 DRIVE 가 완성된다(Codex 재현). 그래서 1 절대로 실행기가 만든 pty 의 slave 를 만든 즉시 점유하고(`TIOCEXCL`, 이후 비루트 열기는 `EBUSY`), 점유 전 쓰기는 마스터에서 버리며, **점유를 실행 내내 놓지 않는다** — 반쪽 폐기·막힌 쓰기는 3 절대로 같은 fd 위에서 처리하고 닫지 않는다. 루트 열기와 다른 기계의 송신자는 막지 못한다 — 실차의 장치 잠금은 보드 확인 뒤 실행기 잠금에서(범위 밖). **HIL 의 남는 위험**(6a-2a 구현 검토 1–2 회차, 운용 결정): 같은 사용자의 비덤프 프로세스(에이전트 등)는 `/proc` 로 fd 를 볼 수 없어 '다른 송신자 없음'을 증명하지 못한다 — 거부하면 정상 노트북에서 늘 기동이 막히므로 기록(`HilPty.uninspected`, 실행 기록에 남김)하고 진행한다. 그런 프로세스가 openpty 와 점유 사이의 순간에 slave 를 열었을 때만 남는 위험이고, HIL 보드는 출력 잠금이라 결과는 시험 자료의 오염이지 운동이 아니다. 실차 장치에는 이 판단을 옮기지 않는다(보드 확인 뒤 실행기 잠금). 시험: 점유 뒤 같은 slave 의 두 번째 열기 → `EBUSY`(반쪽 폐기 중에도); openpty 와 점유 사이에 끼워 넣은 쓰기(시험 훅)가 모형에 닿지 않음; 점유 전에 연 다른 fd(시험 훅) → `device_shared`; 모형 종료 → `device_lost`, 반쪽이 남았으면 `stream_tainted`.
- `transmit(host, now_ns, gate)`: 반쯤 쓴 프레임이 있으면 **이어 쓰기 전에** `gate(frame, finish)` 를 다시 지나고, 거부되면 그 반쪽을 3 절대로 폐기한다. 그다음 호스트 큐에서 프레임마다 `gate(frame, write)` — `write` 는 그 자리에서 `os.write` 를 부른다(비블로킹). 첫 바이트도 못 쓰면(`EAGAIN`) `host.unsent` 로 돌려준다. 끝까지 쓴 프레임만 `(kind, seq, written_ns)` 로 낸다. `partial_frame`·`partial_since_ns` 는 루프의 막힌 쓰기 판정이 읽는다(4c 그대로).
- **쓰기 시작 지연 계약**(PR 5 7.1 6, 1 회차 P2-3, 2 회차 P1-3): `gate` 의 마지막 시계 읽기에서 `os.write` 호출까지는 `send_boundary` 의 잠금 안 비교뿐이고 I/O 가 없지만, Python 에서 그 사이의 선점은 막을 수 없다. 그래서 마지막 판정의 기한을 **쓰기 여유 `A = 1 ms` 만큼 당긴다**(5d 의 루프 관문 상수 `WRITE_ALLOWANCE_S`, 실차·HIL 공통). 9 회차 P1: 지금 마지막 시계 비교는 바퀴가 움직이는 DRIVE 에만 있어, 바퀴 0·승강만 움직이는 DRIVE 의 이어 쓰기가 SLAM 만료 뒤에 완성되어 모형이 승강 목표를 바꿨다(Codex 재현). 그래서 마지막 시계 비교를 **DISARM 을 뺀 모든 프레임**에 둔다: ⓐ 모든 프레임(ARM, 모든 DRIVE — 바퀴·승강·조향·정지·대기 모두)은 마지막 읽기가 `ns − A` 이내(`ns` = 그 판정이 증거 나이를 본 시각, `ns0 + EVIDENCE_READ_MAX_S`), ⓑ **모든 DRIVE**(바퀴 이동·위치 유지·승강·조향 모두, 15 회차 P2-3)는 그에 더해 `결정 + W − A` 이내, 즉 `min(ns, 결정 + W) − A`. 어기면 `write_late`. 이어 쓰기면 관문 규칙대로 `link_stuck`. **첫 쓰기의 전이는 프레임마다 정한다**(10 회차 P2-1: 지금 `_transmit` 은 `wait` 가 나면 대기 프레임을 만들어 곧바로 다시 부르는데, 대기 프레임 자신이 `write_late` 를 내면 같은 틱에 송신을 거듭 시도함 — Codex 재현):
  - 일반 DRIVE: `wait` 류 — 지금처럼 그 자리에 대기 프레임 하나.
  - 대기 프레임(`control_stop`·`hold`): `drop` 류 — 그 프레임은 버리고(`book.discarded`) 이 틱에는 새 대기 프레임을 만들지 않는다. 한 틱의 대기 프레임 생성은 **최대 한 번**(`_wait_frames_this_tick`, 틱 머리에서 0). 앞 프레임의 MCU 만료가 정지를 맡고, 다음 틱에 다시 판정.
  - S10 정지 프레임: 지금의 폐기 처리 그대로 — 곧바로 DISARM(멈추는 쪽).
  - ARM: 새 분류 `keep` — 0 바이트였던 ARM 을 버리지 않고 호스트 큐 앞에 되돌린다(첫 바이트 `EAGAIN` 의 `host.unsent` 와 같은 길), 대기 프레임 없음. 다음 틱에 다시 판정한다(11 회차 P2-1: 허가는 한 요청에 `ARMING` 으로 머물고 호스트는 같은 요청을 `arm_in_progress` 로 거절하므로 버리면 재시도가 없음). 되돌린 ARM 은 원래 echo(요청 때 STATE 의 `mcu_time_us`)를 그대로 실으므로 재판정 기한은 **둘 중 이른 것**이다(12 회차 P2-1): ⓐ 호스트의 무장 기한(`arm_timeout_s`), ⓑ echo 만료 — 그 echo STATE 의 수신 시각 + MCU 의 echo 창(`command_timeout_ms`, 펌웨어 `arm_check` 가 보는 값; 모형 200 ms) − 그 STATE 의 지연 상한 − `A`. echo STATE 의 수신 시각과 지연 상한은 호스트가 ARM 을 큐에 넣을 때 무장 요청 기록(`_arm`)에 `echo_rx_ns`·`echo_delay_s` 로 함께 남긴다(13 회차 P2-1). 지연 상한이 없으면(`None` — 기본 수신 경로이거나 같은 부팅의 기준점이 없음) ⓑ 를 계산할 수 없으므로 되돌린 ARM 은 재판정하지 않고 아래와 같이 취소한다. 판정 시각 `ns` 가 ⓑ 를 넘으면 그 ARM 은 `drop` 이고 호스트의 무장 요청을 취소한다(`McuLinkHost.cancel_arm()` — 새 메서드, `_auth` 를 비움) — 허가는 지금 규칙대로 `arm_failed` 래치(운용자 재무장). ⓐ 를 넘으면 지금처럼 `arm_failed`.
  시험: 대기 프레임이 세 틱 연속 늦어도 틱마다 송신 시도가 대기 프레임 하나를 넘지 않음; S10 정지 첫 쓰기 늦음 → DISARM; ARM 이 50 ms 늦음 → 같은 ARM 이 다음 틱에 쓰여 `READY`, 대기 프레임 없음; 220 ms 늦음(echo 창 200 ms 와 무장 기한 300 ms 사이) → echo 만료로 `drop`·`arm_failed`, 모형이 낡은 echo 의 ARM 을 받지 않음; echo STATE 의 지연 상한이 없을 때 늦은 ARM → 곧바로 취소·`arm_failed`.
- **위치 유지 프레임의 목표**(10·13·14 회차): 지금 대기의 둘째 틱부터 `hold_frame` 은 대기 시작 때 저장한 `self.waiting = (조향, 승강)` 을 다시 싣는다 — 대기가 길어지면 그 사이 처진 승강을 **얼마든지 오래된** 목표로 되올린다(10 회차 P1, Codex 재현 27 → 29 mm). 고침: `control_stop`·`hold` 는 매 틱 **취득 나이가 `HOLD_SAMPLE_MAX_AGE_S = 0.070` 초 이하인 STATE**(구현 때 정정: 50 Hz 루프는 틱 시작에 한 번 읽으므로 이 틱 STATE 의 수신 − 측정이 읽기 주기 20 ms + 링크 지연 상한까지 되고, 프레임은 결정 + W 까지 쓰일 수 있고 관문은 `ns` = 판정 + 5 ms 로 본다 — 20 + 10 + 35 + 5 = 70 ms; 30 ms 로는 rig 의 지연 상한 20–30 ms 만으로 대기 프레임이 거의 모두 거절됨) 의 실측 조향·승강을 싣는다 — 취득 나이 = 판정 시각 − 수신 시각 + 그 STATE 의 지연 상한(13·14 회차: 수신이 이 틱이어도 전달이 늦은 STATE 는 처짐 전 값을 담음). 그런 STATE 가 없거나 지연 상한을 모르면(`None`) 그 틱에는 위치 유지 프레임을 **만들지 않고**(`wait_frame_skipped:<no_state|state_old|no_delay_bound>`), 큐에 남은 미송신 DRIVE 를 모두 버린다(14 회차 P1-1: 0 바이트 `EAGAIN` 으로 큐 앞에 돌아간 옛 `hold` 가 그 틱에 나가면 안 됨 — 지금은 `hold_frame()` 안에서만 버림). 앞서 수락된 프레임은 MCU 만료가 정지를 맡고, 공백이 이어지면 `measurement_stale` 경보가 기존대로 DISARM. `self.waiting` 은 대기 중 표시로만 남는다.
- **알려진 한계 — 펌웨어 기준값 잔여**(15 회차 P1, 총괄 결정 2026-11-20 A′): 펌웨어는 DRIVE 의 승강 목표를 받아도 기준값 `lift_ref` 를 곧바로 바꾸지 않고 `lift_rate_max` 로 옮기며 PI 가 그 기준값을 따른다(`drive.c` 출력 계산). 그래서 이전 기준값이 실측보다 위에 있으면 **실측과 같은 목표의 위치 유지 프레임도 승강을 잠시 올린다**(Codex C 재현: 처짐 없이 31.0 → 35.3 mm / 100 ms). 호스트만으로는 없앨 수 없고, 펌웨어 고침(위치 유지 DRIVE 수락 때 `lift_ref` 를 목표로 맞춤)은 **보드 확인 뒤 별도 PR**(HIL 모형 재현 시험 먼저)이다 — 6a 는 펌웨어를 바꾸지 않는다(보드 날 재플래시 범위를 늘리지 않음, 대안 C 불채택). 대기를 DISARM 으로 바꾸는 대안(B, Codex 권고)은 짧은 대기마다 재무장이 필요해 사용자 원칙(고정적 거부 대신 운용 가능하게)과 맞지 않아 불채택.

  - **값**(잠정, 경보 문턱일 뿐 변위 보장 값이 아님): `WAIT_LIFT_RISE_M = 0.005` — `LIFT_STILL_M`(3 mm, `port.py`) + 측정 잡음 여유 2 mm; `WAIT_STEER_MOVE_RAD = 0.02` — `steering_control.presteer_threshold_rad`(설정의 직진 허용오차 0.01 의 두 배, 잡음 여유). 승강 측정 방식이 미정이고(`board_config.c`) 조향 값도 S4 전 잠정이라 S4 실측 때 측정 잡음으로 다시 정한다.
  - **보장 변위**(16 회차 P1-1, 17 회차 P1-1): 최악 변위 = 문턱 + 측정 오차(기준·후속 표본 각각, 실차) + 축의 최대 속도 × 최악 지연. 경우를 나눈다 —
    - (가) 감시가 도는 경우: 최악 지연 = 표본 나이 상한(70 ms) + **최악 감시 간격** — 설계 상한은 `LATE_TICK_S` = 60 ms 에 틱 안의 수신 처리 지연을 더한 것이고, HIL 시험은 기록된 연속 감시 판정 시각의 최대 차이를 쓴다(1 절: 한 번의 60 ms 이하 간격은 `loop_slow` 가 아님 — 20 ms 로 계산하면 Codex 재현 10.48 mm 를 9.88 mm 로 낮춰 봄) + 쓰기·링크 지연 + MCU 의 DISARM 처리;
    - (나) 유효 표본이 끊긴 경우: 위치 유지 프레임은 만들지 않으므로(위 '목표' 항) 앞 프레임의 MCU 만료에서 `enter_stopping` 이 기준값을 실측으로 맞춘다 — 최악 지연 = 마지막 유효 표본 이후 앞 프레임 만료까지(쓰기 때의 표본 나이 70 ms + `DRIVE_LIFE_S`), 그 뒤 `stop_grace_ms` 동안은 실측 위치 유지 PI 의 오버슛만;
    - (다) DISARM 을 보낼 수 없는 경우(`link_stuck`·장치 상실): (나) 와 같은 MCU 만료 경로.
    - **정지 유예 항**(18 회차 P2): 셋 모두 `STOPPING` 진입부터 `DISARMED`(출력 차단)까지 펌웨어가 축 제어를 계속하므로 `최대 속도 × stop_grace_ms` 를 더한다(‘오버슛만’이라는 말로 빼지 않음).
    - **MCU 틱 지연**(18 회차 P1-1): 실 MCU 는 1 kHz 타이머로 만료를 검사하지만, `mcu_model` 은 밀린 경과 시간 전체를 직전 듀티로 적분한 뒤에 만료를 검사하므로 모형 틱이 밀리면 위 식을 넘는다(Codex 재현: 300 ms 밀림에 24.0 mm 대 식 18.2 mm). 그래서 HIL 의 식에는 **모형 틱 간격 상한 `MODEL_TICK_GAP_MAX_S = 0.005`** 를 지연 항으로 더하되, 만료 경로의 두 전이(`STOPPING` 진입, `DISARMED` 전이)에 **각각** 붙을 수 있으므로 그 경로에는 두 번 더하고(19 회차 P2: 만료 `E` 뒤 `STOPPING` 은 `E + 5`, `DISARMED` 는 `E + 109 ms` — 한 번만 더하면 `E + 105`), DISARM 수락 경로에는 한 번 더한다; 모형이 `--axis-log` 에 MCU 틱마다의 벽시계 간격을 함께 남긴다. 한 실행에서 그 간격이 상한을 넘은 적이 있으면 그 실행의 변위 판정은 **합격 근거로 쓰지 않고 관측값으로만 기록**하고 다시 돌린다(시험 결과 `observed_only:model_tick_gap`). 실 MCU 의 틱 지연은 보드 날 확인.
    HIL 시험은 (가)–(다)를 각각 주입한다. 6a 의 HIL 에서는 모형의 최대 속도(모형 plant·PI 출력 상한으로 계산, 시험이 상수로 둠)와 측정한 지연으로 이 식의 값을 내고, **관측한 최대 변위가 그 값 이하**임을 시험한다(이전 기준값을 위로 크게 둔 경우 포함). 관측점은 **모형이 MCU 틱마다 기록한 plant 의 실제 축 위치**이고 판정 구간은 `DISARMED` 까지 포함한다(17 회차 P2: 호스트 STATE 만 보면 두 표본 사이의 최대를 놓침) — `mcu_model` 에 `--axis-log <경로>`(MCU 틱마다 시각·벽시계 간격·모드·승강·조향 위치·양쪽 바퀴의 plant 순간 속도)를 더하고, 호스트 STATE 기록은 경보 시각과 감시 종료 확인에만 쓴다. 실차의 보장 변위는 S4 실측의 축 최대 속도와 보드 날 지연 측정으로 정하며, **실차에서 위치 유지 대기를 허용하는 선행 조건**으로 둔다(그 값이 축별 여유 안일 때만).
  - 시험: 위치 유지 구간에서 모형 승강 +6 mm → `wait_axis_moved:lift`·DISARM; +4 mm 는 경보 없음; 조향 ±0.025 rad → `wait_axis_moved:steer`, ±0.015 는 없음; 일반 DRIVE 를 썼지만 STATE 가 계속 옛 `hold` seq 를 보고하면 감시 유지; 일반 DRIVE 3 이 사라지고 `hold` 4 만 수락되면 감시 유지; 확인 STATE 가 수락 전 +6 mm 를 실으면 경보; 확인 STATE 와 그다음 STATE 가 통과한 뒤 감시 끝; `hold` 10 → 일반 11 → `hold` 12 에서 종료 대기 취소·감시 유지; **12 를 먼저 쓴 뒤 11 을 보고하는 STATE 두 개를 한 수신 묶음으로 전달**(두 표본 모두 문턱 안) → 감시와 기준값 유지(20 회차 P2-2); 40 ms 간격 틱으로도 관측 최대 변위 ≤ (가) 의 값; `check_bypass` 로 끌 수 없음; 이전 `lift_ref`·`steer_ref` 를 크게 둔 HIL 에서 관측 최대 변위 ≤ 보장 변위 식의 값.
- **남는 되돌림의 크기**(14 회차 P2-1): 위 기준값 잔여와 별개로, DRIVE 의 승강 값은 '목표'라 위치 유지 프레임도 그 표본 취득 뒤에 생긴 처짐은 되돌릴 수 있다 — 크기를 묶는다: 되돌림은 **표본 취득 시각(수신 − 지연 상한)부터 그 프레임의 MCU 만료 시각까지**(최대 `HOLD_SAMPLE_MAX_AGE_S`(쓰기 관문에서 다시 확인) + 프레임 수명 `DRIVE_LIFE_S`) 생긴 처짐까지만이다. 새 프레임이 없을 때 펌웨어의 정지는 세 단계로 따로 본다(15 회차 P2-2, `drive.c` `enter_stopping`·출력 계산): ① **기존 목표 폐기** — 만료 때 `enter_stopping` 이 조향·승강 목표와 기준값(`lift_ref` 포함)을 그 순간의 실측으로 맞춤, ② **`STOPPING` 진입** — 그 뒤 `stop_grace_ms` 동안 PI 가 그 실측 위치를 계속 따라감(출력 있음), ③ **`DISARMED`** — 출력 차단. 6 절의 축 운동 판정은 이 계약을 쓴다: 위치 유지 프레임은 **그 표본의 실측과 비교해** 같으면 축을 움직이지 않는 프레임이다(표본 나이 상한 안에서). 시험은 ⓐ 위치 유지 목표가 나이 상한 안 표본의 값임, ⓑ 대기 시작 때 목표를 다시 싣지 않음(10 회차 반례 — 대기 중 6 mm 처짐 뒤 다음 `hold` 가 새 실측), ⓒ 지연 전달된 STATE(취득 나이 > 70 ms) → 그 틱 생략·옛 seq 미수락, ⓓ 생략 틱 뒤 새 DRIVE 미수락, 앞 프레임 만료 때 목표·기준값이 실측으로 맞춰짐(①), `STOPPING`(②), `DISARMED` 출력 차단(③)을 **각각** 확인한다(앞 프레임 유효기간 안의 움직임은 ⓓ 의 합격에 넣지 않음).
- **반쪽 위치 유지 프레임의 이어 쓰기**(11·12 회차 P1): 전송기는 시작한 프레임을 큐보다 먼저 이어 쓰므로, 반쯤 쓴 `hold` 가 다음 틱에 끝나면 그 사이 처진 승강을 옛 목표로 되돌린다. 그래서 위치 유지 프레임(`control_stop`·`hold`·S10 정지 — 바퀴 0 이고 결정 때 실측을 목표로 실은 것)은 **첫 바이트를 쓴 틱 안에서만** 이어 쓴다. 다음 틱으로 넘어간 반쪽은 이어 쓰기 직전 관문이 거절 → 관문 규칙대로 `link_stuck`(3 절의 같은 fd 폐기·독 바이트열·DISARM). 반쪽이 다음 틱까지 남는 것은 링크가 막힌 것이라 DISARM 쪽이 맞다. 시험: 반쪽 `hold` 가 다음 틱으로 넘어가면(처짐·STATE 누락 유무와 무관) 그 이어 쓰기 거절, 독 바이트열, DISARM. 옛 seq 미수락은 **모형의 프레임별 수락 기록**으로 확인한다(12 회차 P2-2: 펌웨어는 한 틱에 여러 프레임을 처리한 뒤 STATE 를 내므로 옛 DRIVE 와 DISARM 이 같은 틱에 수락되면 `last_rx_seq` 에는 DISARM 만 남음) — `mcu_model` 에 `--accept-log <경로>`(처리한 프레임마다 한 줄: seq·종류·MCU 시각·수락/거절 사유·**처리 직전 모드·처리 직전 활성 명령의 만료 MCU 시각** — 전제 검토 2 회차 P2-2: 한 MCU 틱에 여러 프레임을 처리하므로 틱 단위 `--axis-log` 로는 프레임 직전 모드를 복원 못 함)를 더한다.
- **쓰기 여유의 측정**: 그러면 마지막 읽기 → `os.write` 진입이 `A` 안이면 쓰기는 증거 기한 안에 시작한다. 그 구간의 합격 기준은 측정이다: p99.9 ≤ 1 ms(Jetson, 7 절 보드 날 확인) — **실차 운동 허가의 선행 조건**으로 둔다(6a 의 HIL 은 출력 잠금 보드라 운동이 없음). 시험(3 회차 P2-2): 가짜 시계로 첫 쓰기·이어 쓰기 각각, `ns` 가 먼저 오는 경우와 `결정 + W` 가 먼저 오는 경우를 번갈아 — 마지막 읽기 앞의 지연으로 `min(ns, 결정 + W) − A` 를 넘기면 쓰지 않음; 뒤의 지연이 A 안이면 쓰기가 `min(ns, 결정 + W)` 안에 시작함. 보드 측정은 분포(p99.9)와 개별 마감 초과 수를 따로 내고, 이어 쓰기는 마지막 구분자를 쓴 `os.write` 가 돌아온 시각까지 본다.
- **시각의 뜻**: 전송기는 프레임마다 `first_byte_ns`(첫 바이트 `os.write` 직전, D5 왕복용 — `TtyLink` 와 같음)와 `written_ns`(마지막 바이트를 쓴 `os.write` 가 돌아온 뒤)를 낸다. 루프의 `book.written`·허가의 `written`(S10 확인 계약)은 `written_ns`(쓰기 완료)를 쓴다.

- **독립 전제 검토 반영**(새 스레드, 24 회차 수렴 뒤):
  - **정지 결정 틱의 이전 축 명령**(P1-1): 지금 `stop_decided` 는 장부의 바퀴 속도가 0 이 아닌 반쪽만 막아, 승강·조향 단독 일반 DRIVE 의 반쪽이 정지를 결정한 틱에 완성되어 새 `hold` 보다 먼저 목표를 바꿀 수 있다. 정지·대기를 결정한 틱에는 **일반 DRIVE 로 기록된 반쪽 전부**(바퀴 속도와 무관)의 이어 쓰기를 거절 → `link_stuck`. 시험: 승강 단독 반쪽 뒤 다음 틱 `arrival_wait` → 그 옛 seq 미수락(`--accept-log`).
  - **위치 유지 프레임의 표본 나이를 쓰기 때 다시**(P1-2, 2 회차 P1-2): S10 정지는 `STOP_PENDING` 이라 0 바이트 `EAGAIN` 으로 큐에 돌아가도 목표를 다시 만들지 않는다. 그래서 **S10 정지도** 큐에 넣을 때 대기 프레임과 같은 규칙(취득 나이 ≤ `HOLD_SAMPLE_MAX_AGE_S` 인 이 틱 STATE; 없으면 위치 유지 정지를 만들지 않고 곧바로 DISARM — 멈추는 쪽)을 따르고, 모든 위치 유지 프레임은 자기 표본의 취득 시각과 **만든 틱**을 장부에 남겨, 마지막 관문에서 **`ns − 취득 ≤ HOLD_SAMPLE_MAX_AGE_S`(70 ms)** 와 **'만든 틱 = 지금 틱'** 을 함께 본다 — 다음 틱 재시도는 의도적으로 허용하지 않는다(3 회차 P2: 틱 시작 4 ms 뒤 취득한 표본은 다음 틱에도 나이 상한 안일 수 있어 나이만으로는 막지 못함; 보장 변위 식의 표본 항은 '쓰기 때 70 ms'). 시험: 그 사례에서 첫 쓰기 0 바이트 `EAGAIN` → 다음 틱에 나이는 통과해도 S10 정지는 폐기·DISARM, `hold` 는 `drop`. 어기면 `control_stop`·`hold` 는 `drop`(다음 틱에 새 표본으로 새 프레임), S10 정지는 지금의 폐기 처리대로 곧바로 DISARM. 구현 때 S10 정지 분기도 `_stop_decided` 를 세우는지 확인한다.
  - **ARM 직후 필수 zero DRIVE**(P1-3, 2 회차 P1-3): 호스트가 STATE 콜백에서 만드는 이 프레임(`_ZERO_PENDING`)은 루프 장부를 거치지 않는다. 결정 시각 = 호스트가 큐에 넣은 시각(만료 − `zero_valid_ms`). 권한 결박: 루프가 ARM 을 요청하는 순간(허가가 `host.request_arm` 을 부를 때) `(lease_id, control_gen)` 을 **무장 결박**으로 만들어 무장 교환이 끝날 때까지(`READY` 또는 무장 실패) 보존하고, ARM 과 zero DRIVE 모두 관문에서 그것과 비교한다(지금은 `_book()` 이 루프 DRIVE 에만 결박을 넣고 결박 없는 프레임은 비교를 건너뜀). 시험: ARM 과 zero 사이에 lease·제어 세대가 바뀌면 zero 거절 → `authority_changed` → DISARM. 마지막 관문의 `결정 + W − A`·`ns − A` 를 그대로 적용. 0 바이트 늦음은 ARM 처럼 `keep`(자기 만료·echo 창 안에서 재판정), 다음 틱으로 넘어간 반쪽은 `link_stuck`, 기한을 넘기면 `drop` + `cancel_arm()` → `arm_failed`. 시험: 첫 쓰기 늦음 → 다음 틱 수락·`READY`; 기한 넘김 → `arm_failed`; 반쪽 넘김 → DISARM.
  - **ARM echo 의 지연 상한 출처**(P2-3, 2 회차 P1-4): 호스트의 기본 신선도는 수신 시각이라 `echo_delay_s` 가 비어 있다. 루프가 STATE 마다 계산하는 `DelayBound` 값을 최근 STATE 별로 보관하되 열쇠는 **`(boot_id, mcu_time_us)`**(한 번에 읽힌 여러 STATE 는 수신 시각이 같으므로 수신 시각은 열쇠가 못 됨), 호스트는 ARM·zero DRIVE 를 만들 때 그 echo 의 `(boot_id, mcu_time_us)` 를 큐 항목에 붙인다. 재판정은 그 열쇠로 값을 찾고 없으면 취소. echo 창: ARM 은 `command_timeout_ms`, zero DRIVE 는 그 DRIVE 의 `min(valid_after_echo_ms, command_timeout_ms)`(펌웨어 `drive.c` 와 같은 식). HIL 에서는 모형 STATE 가 MCU 시각을 실어 `DelayBound` 가 기준점을 얻는지 시험하고, 50 ms 늦은 ARM 이 복구되는 경로를 확인한다.
  - **호스트 틱 간격**(P2-1, 2 회차 P2-1): 20·60 ms 는 스케줄러의 보장이 아니다. 6 절의 모든 시한은 고정 20 ms 대신 **기록된 실제 호스트 틱 시작 시각**으로 판정한다(그 절의 '`F` 뒤 실제 첫 호스트 틱'). 한 간격이 `LATE_TICK_S` 를 넘어 감시가 멈춘 경우에는 2 절 보장 변위의 (나)(MCU 만료 경로)를 적용하고, 그 시험에서는 `--accept-log`·`--axis-log` 로 `STOPPING` 이 **만료에서 비롯됐음**(그 전에 DISARM 수락 없음)을 확인한다 — 호스트가 돌아와 DISARM 이 먼저 수락되면 그 실행은 (가) 로 판정하되 식의 감시 간격 항에 **실제 감시 공백** — 연속한 유효 축 표본의 **실제 감시 판정 시각** 차이(루프가 감시를 판정할 때마다 그 시각을 기록; 틱 시작 간격이 아님 — 4 회차 P2: 70 ms 틱이라도 STATE 처리까지 1·6 ms 면 75 ms, 판정할 STATE 가 없는 틱이 끼면 더 김) — 을 넣고, 그 최대값에는 **마지막 유효 축 판정부터 DISARM 결정까지**의 공백도 포함한다(5 회차 P2: 새 STATE 없이 권한 철회 등으로 DISARM 하면 그 공백이 연속 판정 차이에 안 잡힘; 그 뒤 송신·링크 지연은 별도 항). 시험: 70 ms 지연 뒤 새 STATE 없이 DISARM 이 먼저 수락되는 사례(3 회차 P2: 60 ms 를 전제로 한 값으로 판정하지 않음). 모형 틱 간격 검사와 별도로 호스트 지연(틱 하나를 70 ms 로)도 주입한다.
  - **세 시각의 구분**(P2-2): 관문 판정 시각(`last_gate_ns`), 시스템 호출 진입(첫·마지막 `os.write` 진입 — 전송기가 기록), 쓰기 귀환(`written_ns`), MCU 수락(`--accept-log` 의 MCU 시각)을 따로 기록한다. 마지막 시계 읽기 직후 1 ms 넘는 지연을 주입해 판정이 그 위반(마지막 쓰기 진입이 `F` 뒤)을 잡는지 확인한다. 보드의 p99.9 는 관측 분포로만 해석한다.
  - **`apply` 의 상태 변경과 기록 사이 예외**(P2-7, 2 회차 P2-3): 명령 처리기가 상태를 바꾼 뒤 기록 전에 예외가 나면 `tick_failed` 답과 바뀐 임무 상태가 어긋날 수 있다. 순서: 예외 처리는 지금처럼 `_emergency()` 를 **먼저**(DISARM 우선, 그 경로가 임무를 `cancelled`·`recovery_required` 로 끝낼 수 있음), 그다음 정산 목록을 만들 때 `abandon(t)` 를 부르되 임무 종료는 **한 곳에서** — `pending` 에 예외를 낸 명령이 있고 임무가 **아직 끝나지 않았으면**만 `terminate("failed", t, "tick_failed")`, 이미 `_emergency()` 가 끝낸 임무의 결과는 바꾸지 않는다. 시험: 제출 직후 예외 → 원장 `tick_failed`·임무 종료(그 경로의 결과)·재무장 뒤 AUTO 없음; 포크가 포켓에 든 상태의 예외 → `_emergency()` 의 `recovery_required` 가 `failed` 로 덮이지 않음.
  - **pty 설정 순서**(P2-6): `open_raw()` 는 경로를 다시 여는 함수라 쓰지 않는다 — 실행기가 점유한 slave fd 에 직접 raw termios 를 설정한 뒤 독 바이트열을 쓰고, 시험이 마스터 쪽 첫 바이트가 독 바이트열과 바이트 단위로 같음을 확인한다. 모형의 `--duration-ms` 자가 종료는 모형 루프가 정상으로 돌 때의 조건이다(멈춘 모형은 실행기의 `finally` 회수에 기댐).
  - **모형과 보드의 차이**(P3): 모형의 watchdog 은 비어 있고 명령 상한·정지 유예가 200/100 ms, 보드는 150/300 ms 와 하드웨어 watchdog 이다. 6a 의 `DISARMED` 전이는 펌웨어 코어 시한의 검증이고, 실제 전기 출력 차단과 하중을 건 정지는 보드에서 따로 관측한다(7 절).

## 3. 반쪽 프레임 폐기

반쯤 쓴 프레임을 버리고 링크를 다시 열면, 새 열기의 구분자 `0x00` 이 MCU 수신 버퍼의 반쪽을 닫는다. **본문이 다 나가고 끝 구분자만 못 나간 반쪽**은 그 구분자로 온전한 프레임이 되어 늦게 작동할 수 있다. 1판의 `0xFF 0x00` 은 틀렸다(1 회차 P1-1: 마지막 CRC 바이트도 빠졌고 그 값이 `0xFF` 이면 덧붙인 `0xFF` 가 그 바이트가 되어 원본과 바이트 단위로 같은 프레임이 됨 — Codex 가 실제 인코더로 재현).

- **독 바이트**: 반쪽을 버린 뒤의 첫 쓰기는 **96 개의 비영 바이트(`0x01` × 96) + `0x00`** 이다. 두 디코더(Python `FrameDecoder`, 펌웨어 `link.c`)는 구분자 사이 인코딩 길이가 `ENCODED_MAX`(`BODY_MAX + 1` = 91)를 넘으면 그 프레임을 길이 초과로 버린다(`_overflow`, `rx->overflow`). 반쪽이 어디서 끊겼든 그 뒤에 비영 바이트 96 개가 이어지면 구분자 전의 비영 바이트 수가 91 을 넘으므로 반쪽은 반드시 길이 초과로 버려진다(CRC 우연 일치에 기대지 않음).
- **같은 fd 위의 폐기**(5 회차 P1-1, 6 회차 P2-1·P2-2): 루프의 막힌 쓰기 판정(`_cut_stuck_write` → 전송기 재동기화)과 이어 쓰기 거절은 이 전송기에서 fd 를 닫지 않는다. 순서: ① 반쪽을 버림(그 프레임은 보고하지 않음) ② 같은 fd 위에 독 바이트열을 씀 — `EAGAIN` 으로 반쯤 쓰이면 **남은 바이트부터** 이어 쓴다(처음부터 다시 보내면 조금씩만 받는 수신기가 구분자에 끝내 닿지 못해 DISARM 이 계속 밀림 — Codex 재현) ③ 독 바이트열의 구분자까지 쓴 뒤에야 큐의 다음 프레임(DISARM 먼저). 수신 쪽은 손대지 않는다(RX 디코더 유지, `hil_plant` 유지). 장치 상실이면 1 절의 `device_lost`(반쪽·미완 독 바이트열이 남았으면 `stream_tainted`).
- **열기의 첫 쓰기**(2 회차 P1-2→P1-1)는 독 바이트열이다 — pty 를 새로 만들어도 지키는 같은 규칙이고, 실 장치(보드 확인 뒤)에서는 실행기만 재시작한 경우 MCU 수신 버퍼(펌웨어는 호스트 fd 가 닫혀도 RX 디코더를 초기화하지 않음)에 앞 실행기의 반쪽이 남았을 수 있어 필요하다. 반쪽 표식은 쓰지 않는다(언제나 독 바이트열).
- MCU 쪽은 깨진 프레임 하나를 수신 오류로 센다(기존 동작).

## 4. S10 정지 프레임의 `authority_changed` — 지금 규칙 유지

5a 구현 검토가 남긴 P2: S10 의 제어 정지 프레임이 한 틱 늦게 쓰이는 사이 권한(lease id, 제어 세대)이 바뀌면 송신 관문이 `authority_changed` 경보로 거절하고 ①(DISARM)이 된다. 1판은 움직이지 않는 프레임을 결박 검사에서 빼려 했으나 철회한다(1 회차 P1-2): S10 정지와 대기 프레임은 결정 때의 **실측 조향·승강을 목표값으로** 싣고 `movable=False` 로 기록되므로, 반쯤 쓴 프레임이 다음 틱에 끝날 때 축이 이미 움직였으면 그 프레임이 축을 옛 위치로 되돌릴 수 있다. 일반 0 속도 DRIVE 도 승강 허용오차(3 mm) 안의 목표 차이와 조향 변경을 `movable` 에 담지 않는다.

- **결정**: 예외를 두지 않는다. 권한이 바뀐 뒤의 S10 정지 프레임은 지금처럼 거절되고 DISARM 정지가 된다 — 멈추는 쪽이다. S10 이 의도한 '승강 유지 정지' 를 그 경합에서만 잃는다(DISARM 이 승강을 어떻게 다루는지는 펌웨어의 정지 동작 그대로).
- 시험(2 회차 P2-1): 반쯤 쓴 S10 정지 프레임과 그 사이 권한 변경 → 그 프레임은 완성되지 않고 폐기(재동기화), DISARM 이 쓰임 — 외부 결과로 판정한다(허가의 최종 사유는 `control_stop_discarded` 일 수 있고 틱 사유에 `authority_changed` 가 남지 않을 수 있음).

## 5. 예외 틱의 콘솔 정산

틱 안의 예외로 비상에 빠지면 `_assemble_and_arbitrate` 의 `session.tick_end()` 에 닿지 않아, 그 틱 머리에서 받은 명령(`tick_start` 의 기록)의 답이 다음 틱에 `invalid` 로 정산된다.

- **임무 수집 예외**(6a-1 구현 검토 2–6 회차): `RealSession.end_mission` 의 단계(작업 정리·시계·`end_reset`)가 예외를 내면 다시 하지 않는다(단계가 멱등이 아님) — 결과에 `collect_failed` 를 남기고 예외를 올려 비상 래치·정산, 그 뒤 새 임무는 `not_ready:collect_failed` 로 거절하고 `real_status.restart_required` 로 알린다(실행기 재시작 뒤 새 세션의 물리 확인부터).
- **먼저 고칠 중재기 결함**(1 회차 P1-4, 정상 정산에도 있음): 원장은 요청을 `(request_token, request_seq)` 로 구분하지만 `resolve` 는 결과를 `request_id` 하나로 맞춘다 — 같은 `request_id`·다른 seq 의 제출 두 건이 한 묶음에 오면 하나의 결과가 둘에 붙는다. 그래서 **같은 묶음에서 아직 정산되지 않은 미션 요청과 `request_id` 가 같은 새 미션 요청은 적용 전에 `duplicate_request` 로 거절한다**(`Arbiter` 의 미션 요청 큐잉 자리, 기존 동작은 같은 id 가 없으면 그대로).
- **정산 계약**(1 회차 P2-1, 2 회차 P1-4): `cycle()` 은 진입하자마자 `session.last_records = None`(미기록)으로 둔다. `RealSession.tick_start` 는 **이 틱의** `commands.apply` 결과를 두 번째 `collect` **전에** `self.last_records` 에 둔다(그 `collect` 가 실패해도 결과가 남음). 예외 정산은 이 틱의 `last_records` 가 기록됐을 때 한다 — 앞 틱의 기록이 새 요청에 붙지 않는다.
- **`apply` 전·도중 예외**(3 회차 P1-1, 4 회차 P2-1): `link.begin` 은 첫 `collect` 전에 그 묶음의 명령을 미션 큐에 넣는다. 그 뒤 `apply` 전에 예외가 나면 명령이 큐에 남아 **다음 제어 세대에서** 실행될 수 있다(중재기의 `mission_context` 는 `queued` 요청의 세대 검사를 건너뜀 — Codex 재현: 옛 제출이 재무장 뒤 `m1` 으로 수락되고 AUTO). `apply` 도중 예외면 큐는 이미 비었고 앞 명령의 결과는 `log` 에만 남는다. 그래서 `MissionCommands.apply` 는 진행을 밖에서 읽을 수 있게 둔다: 시작할 때 `self.applying = ApplyProgress(records=[], pending=[정렬된 명령])` 을 세우고, 기록을 만들 때마다 `records` 에 더한 **뒤** 그 명령을 `pending` 에서 뺀다(예외를 낸 명령은 `pending` 에 남음), 정상 종료에 `applying = None`. 새 메서드 `MissionCommands.abandon(t) -> list[dict]` 는 ⓐ `applying` 이 있으면 그 `records` 그대로 + `pending` 의 명령마다 거절 기록, ⓑ 미션 큐에 남은 명령(apply 전 예외)마다 거절 기록을 돌려주고, 큐와 `applying` 을 비운다. 거절 기록은 `{"t", "command", "accepted": False, "reason": "tick_failed", "mission_id", "status", "request_id"}`(정상 기록과 같은 모양, `log` 에도 남김). **정산 목록** = 이 틱의 `last_records` 가 있으면 그것, 없으면 `abandon(t)` 의 결과 — `abandon` 은 `last_records` 가 없으면 **언제나** 부른다(5 회차 P1-2: `link.begin` 이 요청을 큐에 넣은 뒤 돌아오기 전에 실패해도 큐가 비워짐)(같은 묶음의 같은 `request_id` 는 위 `duplicate_request` 로 이미 막힘). 루프는 `tick_end` 를 부르기 **직전에** `self._tick_end_tried = True` 를 세운다(틱 머리에서 거짓으로). 예외 처리에서 **이 틱에 `link.begin` 이 돌았고**(`session.began` — `tick_start` 가 `begin` 을 부르기 **직전에** 세우고 틱 머리에서 거짓으로; 부분 실행된 `begin` 도 포함) `_tick_end_tried` 가 거짓이면 **한 번** `session.tick_end(now, 정산 목록, safety, (0.0, 0.0), None)` 을 부른다(정산 목록이 비어도 부름 — 그 틱의 다른 요청 답과 틱 토큰을 위해) — 후보는 0, 안전 상태는 `core.safety_state(t)`(그것도 실패하면 최소 상태 `{"real_exception": 사유}`). `tick_end` 가 진행 중에 실패한 경우(`_tick_end_tried` 참)에는 다시 부르지 않는다 — `Link.end` 는 원장 정산·응답 큐·lease 만료·틱 토큰 발급을 차례로 하므로 다시 부르면 틱 토큰이 두 번 나간다. 그 틱의 남은 답은 다음 틱에 `invalid` 로 정산되는 지금 동작 그대로다(기록).

## 6. HIL 통합 시험 (`realtime`, ws1)

`mcu_model --hil-plant 1` 을 pty 너머에 두고 `LoopTtyTransport` + `RealLoop` 을 벽시계로 돌린다(`tests/integration/`, `mcu_model` 고정물 — `realtime` 표시로 ws1 의 한 프로세스 단계에서 돈다).

- S10-A 한 번(`d5_pocket` 우회, 합성 스캔·SLAM): `s10_lifted` 로 끝나고 모형의 오도메트리가 STATE 를 거쳐 루프에 닫힘. `s10_lifted` 기록은 정지 요청 때 먼저 남으므로(전제 검토 P2-5) 합격은 `--accept-log` 에서 **S10 정지 DRIVE 수락과 그 뒤 최종 DISARM 수락**까지 본다. 이 시험이 증명하는 것은 명령·STATE·오도메트리·임무 전이의 연결이다 — 합성 스캔과 항등 SLAM 은 같은 자세에서 나오므로 위치 정확도나 포켓 접촉의 근거가 아니다(전제 검토 P3).
- **정지 주입**(계획: 각 주입은 비영 명령이 수락된 상태에서 시작, 입력 나이 상한 안에 정지, 기록으로 정지 시한 판정; 1 회차 P2-5 로 원인과 관측량을 나눔):
  - **송신만 끊기**(전송기 쓰기 멈춤, STATE 는 계속 — bring-up `tx_cut` 과 같은 방식). 모형이 마지막으로 수락한 seq 는 STATE 의 `last_rx_seq` 로 확인하고, 그 seq 의 DRIVE 를 실행기 기록에서 찾아 **MCU 의 실제 만료 시각** `E = echo_mcu_time_us + min(valid_after_echo_ms, MCU 상한)`(펌웨어 `drive.c` 의 계산, MCU 시각)을 계산한다(3 회차 P2-3: 수락 관측 시각부터 세면 기산점 회귀를 못 잡음). 판정은 `--axis-log` 의 실제 모드 전이 시각으로 한다(20 회차 P2-1: STATE 관측에서 출발하면 오차가 겹침) — 틱 간격 `g` = 모형 `MODEL_TICK_GAP_MAX_S` 5 ms(2 절과 같은 값; 실 MCU 1 ms). 시한: ① `STOPPING` 진입(목표·기준값을 실측으로 맞춤, PI 는 계속 — 출력 차단 아님) — 실제 시각 ≤ `E + g`, ② **출력 차단** — 실제 `DISARMED` ≤ 실제 `STOPPING` + `stop_grace_ms` + `g`(STATE 로만 보면 둘 다 + STATE 간격 한 번, `E` 에서 직접 `E + 2g + stop_grace_ms + STATE 간격`), ③ 바퀴 — `STOPPING` 에서는 바퀴 목표 0 이라도 PI 출력이 계속되므로 시한은 `DISARMED`(출력 차단) 기준: `--axis-log` 의 **양쪽 바퀴 plant 순간 선속력** `|wheel_rad_s| × 유효 반지름`(바퀴마다 크기 — 부호 있는 각속도에 문턱을 바로 대지 않음, 22 회차 P2; 기존 `m_entry.py` 정지 판정과 같은 변환; STATE 의 엔코더 구간 평균 속도는 쓰지 않음, 21 회차 P2)이 모두 0.01 m/s 미만이 되는 첫 MCU 틱 ≤ 실제 `DISARMED` + 3·`PLANT_WHEEL_TAU_S`(plant.c 의 1차 지연) + `g`, 그 뒤 200 ms 동안 매 틱 미만 유지(정확한 0 은 쓰지 않음; 후진 중 끊기 사례 하나를 포함; 판정기 자체는 **합성 로그로 불합격을 확인** — 시한이 지난 뒤에도 양쪽 −0.15 m/s 가 이어지는 로그가 불합격이어야 함(23 회차 P2: 정상 감속 후진은 부호를 빠뜨려도 합격하므로 그것만으로는 부호 회귀를 못 잡음)).
  - **STATE 만 끊기**(모형에 `--state-silent-at-ms`·`--state-silent-ms` 를 더함: STATE 송신만 멈추고 명령 수신은 계속): 루프가 `measurement_stale` 경보 → DISARM 을 **씀**(전송기 기록), 모형이 그 DISARM 을 수락 — `--accept-log` 에서 그 DISARM 수락 직전 모드가 `ARMED` 이고 명령 만료보다 **먼저**임을 확인한다(전제 검토 P2-5: 만료로 이미 멈춘 뒤 받은 DISARM 도 seq 는 기록되므로 STATE 의 `DISARMED`·`last_rx_seq` 만으로는 DISARM 이 정지를 일으켰다는 근거가 아님; 만료가 먼저면 불합격으로 보고 원인 기록). 권한 철회가 먼저 오면 `authorization_revoked` 래치도 정답으로 받는다. 기존 `--silent-at-ms`(양방향 침묵)는 송신과 수신을 함께 끊어 DISARM 수락을 볼 수 없으므로 이 시험에 쓰지 않는다.
  - **입력 원천 멈춤의 공통 판정**(4 회차 P2-2, 5 회차 P2-2·P2-3): 주입마다 **비영 금지 시각** `F` 를 실제 판정과 같은 식으로 기록에서 계산한다 —
    - 스캔: 층 watchdog 의 기대 시각 `F = scan.last_s + scan_period_s + budget_s`(마지막 스캔의 `last_s`, `RealLayer` 의 `_expected_s` 와 같은 식);
    - STATE: 호스트 신선도의 `F = state_rx_ns + state_max_age_s` (MCU 시각 규칙이면 `− 그 STATE 의 지연 상한`, `McuLinkHost._age_ns` 와 같은 식);
    - SLAM: `F = pose_reply_ns + SLAM_MAX_AGE_S`(처리된 마지막 응답의 취득 시각, 루프의 `_fresh_ns` 와 같은 식).
    판정: ① 결정 시각이 `F` 이후인 비영 DRIVE 가 하나도 없음, ② **모든 비영 DRIVE 의 마지막 판정 시각** `last_gate_ns ≤ F − A` — `last_gate_ns` 는 루프 관문 `judge` 가 `write_late` 비교에 **실제로 쓴 시계 값**이다(6 회차 P2-3: 전송기가 쓰기 직전에 시계를 다시 읽으면 비교하려는 값이 바뀜). **콜백 계약**(7 회차 P2-3): 전송기가 관문에 주는 쓰기 콜백은 `write(*, judged_ns: int | None = None)` — 키워드 전용이라 기존 rig 의 `FakeTransport` 처럼 프레임을 기본 인자로 붙잡는 콜백과 섞여도 자리를 덮지 않는다(rig·`FakeTransport` 의 콜백도 같은 시그니처로 고침). `judge` 는 비교에 쓴 값을 `self._judged_ns` 에 두고(판정마다 먼저 `None` 으로), 관문은 `send_boundary(…, lambda: write(judged_ns=self._judged_ns), check)` 로 부른다 — `check` 가 돈 뒤에 읽으므로 그 판정의 값이다. 시계 비교를 거치지 않는 프레임은 직접 쓰는 DISARM 뿐이고 `judged_ns=None`. 전송기는 프레임마다 마지막으로 성공한 쓰기의 값을 `last_gate_ns` 로 기록하고, 판정은 쓰인 DISARM 아닌 프레임마다 그 값이 `None` 이 아님도 본다. ①·② 의 대상은 **용도로 가른다**(전제 검토 P2-4: 펌웨어는 3 mm·0.01 rad 보다 작은 목표 차이도 따라가므로 허용오차 분류는 '매 틱 2.9 mm 위' 같은 누적 상승을 놓침) — 출력 장부가 **일반 DRIVE**(계획·제어가 낸 것, 바퀴·승강·조향 목표 크기와 무관)로 기록한 프레임은 모두 대상이고, **위치 유지 프레임**(`control_stop`·`hold`·S10 정지)은 대상이 아니되 그 목표의 표본 출처·나이(2 절)로 따로 판정한다. 판정기 시험: 입력 만료 뒤 매 틱 실측보다 2.9 mm 높은 일반 DRIVE 가 수락되는 합성 로그 → 불합격. 그리고 그리고 **모든 DRIVE**(바퀴 이동·위치 유지·승강 단독·조향 단독)에 `last_gate_ns ≤ 결정 + W − A`(16 회차 P2: 2 절의 기한과 같게). 별도 사례(9 회차 P1): S10 rig 에서 승강만 움직이는 DRIVE 를 반쯤 쓰게 하고 SLAM 만료(`F`) 직전·직후로 이어 쓰기를 배치 — 만료 전 `ns − A` 를 넘긴 이어 쓰기는 거절(`link_stuck`), 독 바이트열, 모형의 승강 목표가 바뀌지 않음. 조향만 움직이는 DRIVE(바퀴 0, 승강 유지, 조향 0 → 0.131 rad)도 같은 대상으로 ②·`last_gate_ns` 를 확인. 시간축은 모두 호스트 단조시계 ns — 스캔의 `F` 는 루프의 코어 시각 원점 `start_ns` 로 바꾼다(`start_ns + F_s × 1e9`), SLAM 의 `pose_reply_ns` 는 이미 그 축, 그리고 그 `written_ns ≤ F + 1 ms`(마지막 `os.write` 귀환 여유, 보드 날 확인), ③ 정지 쓰기 시한을 따로 본다. 추가 주입: `F` 직전에 비영 DRIVE 를 반쯤 쓰게 하고(`EAGAIN` 스크립트) `F` 뒤에 풀어 — 이어 쓰기 거절, 독 바이트열, 그 프레임 미완성.
  - 스캔 원천 멈춤: ② 첫 `layer_overdue` 평가 — 송신 관문은 틱 시작보다 늦은 `ns` 로 watchdog 을 보므로 `F` 직전에 시작한 틱에서 먼저 날 수 있다(정상); **`F` 뒤 실제로 시작한 첫 호스트 틱**은 대기 진입의 상한이다(3 회차 P2)에서 대기(0 속도 DRIVE) — 그 틱부터 비영 없음; 이어 `overdue_end`(1.0 s)를 넘긴 첫 평가에서 `layer_latency_exceeded` 래치와 DISARM 쓰기 — 1.0 s 는 **기록된 실제 첫 overdue 평가 시각**(watchdog 이 저장한 첫 초과 시각)부터 재고, 시한 = 그 시각 + 1.0 s 뒤 실제 첫 호스트 틱 + 쓰기 한 틱.
  - STATE 만 끊기는 위 그대로에 ① 을 더하고, ② DISARM 쓰기 ≤ `F` 뒤 실제 첫 호스트 틱 + 쓰기 한 틱.
  - SLAM 원천 멈춤: 현행 정책에서 `slam:stale` 은 곧바로 래치 사유다 — ① 과 ② 래치 사유 `slam:stale` 와 DISARM 쓰기 ≤ `F` 뒤 실제 첫 호스트 틱 + 쓰기 한 틱.
- **양성 시험의 입력**(전제 검토 P1-4): 기본 `config/real/s10a.yaml` 은 지도 id·팔레트 치수가 비어 조립이 거부하므로, HIL 전용 장면 설정 `config/real/s10a_hil.yaml`(합성 장면의 지도 id·시작 자세·팔레트 치수 — 실측이 아닌 HIL 값이라고 머리에 적음)을 `--config` 로 준다. 순서(전제 검토 2 회차 P1-1, 단위 시험 `test_real_loop_console.py` 와 같은 순서): 실행기가 HIL 확인 뒤 세션을 시작(허가의 `start_session` — DISARM 두 번 왕복)하고, 시험 클라이언트는 `LiveServer` 웹소켓으로 `lease_request`(ack·lease) → 이후 **종료까지 상태의 `tick` 을 받을 때마다 `echo` 로 lease 를 갱신**(전제 검토 3 회차 P1: 기본 lease 1 s 인데 `lifted` 확인 요청은 승강 단계에서 4.5 s 이상 뒤에 열림 — 단위 rig 와 같은 방식) → `check_bypass`(`d5_pocket`, `on=True`) 를 보내고 상태에서 그 우회가 **적용됨**을 확인(HIL 에는 깊이 입력이 없고 루프의 우회 집합은 비어 시작함) → `pallet_register`(ack·`targets_revision`) → 정지 확인을 기다림(약 0.6 s) → `operator_start`(ack) → `mission_submit`(그 `targets_revision`) → 상태의 `operator_request`(`lifted`) 를 기다려 `operator_answer`(`confirm`, ack) → 결과 `s10_lifted`·허가 `LATCHED` 를 기다린다. 각 단계의 응답을 확인해 조립·권한 관문을 실제로 지났음을 남긴다. 명령 줄: `tools/real_autonomy.py --run --hil --hil-model <빌드한 mcu_model> --duration-s 60 --config config/real/s10a_hil.yaml`.
- **양성 진입점 시험**(1 회차 P2-4): 위 S10-A 한 번은 실제 위 명령 줄의 진입점으로 돈다(직접 조립이 아니라 CLI 의 확인 순서와 합성 원천 생성 경계를 지나게).
- 실 MCU 경로(`--device`)는 여전히 거부됨(시험), 합성 원천은 `Client.REAL` 에서 `SyntheticRefused`(시험).

## 8. 시험 (단위)

- `LoopTtyTransport`: pty 쌍으로 — 이어 쓰기 전 gate 재통과·거부 시 **같은 fd 위에서** 폐기(fd 번호·점유 유지)와 독 바이트열, 그 뒤 DISARM; 독 바이트열이 `EAGAIN` 으로 32 바이트씩 끊겨도 남은 바이트부터 이어 써 끝나고 DISARM 이 수신됨; `EAGAIN` 첫 바이트 → `host.unsent`; 끝까지 쓴 프레임만 보고; 첫 쓰기가 독 바이트열(`0x01 × 96 + 0x00`)이고 그 구분자 전에는 다른 프레임 없음; 재동기화에서 RX 디코더·`hil_plant` 유지; 한 틱 읽기 4096 바이트 상한.
- 디코더: DRIVE·ARM·DISARM 프레임을 **끝 구분자가 아직 전달되지 않은 모든 절단 위치**에서 자르고 독 바이트(+ 독 바이트 자체의 모든 부분 쓰기 뒤 다시 독 바이트)를 붙이면 Python `FrameDecoder` 가 아무 프레임도 받지 않음; 펌웨어 디코더는 모형 통합 시험에서 같은 경우 하나 이상.
- `motion_allowed`: `hil_plant` 는 HIL 확인 뒤에만, 실 장치는 거부.
- 4 절(13 회차 P2-2): 2 절의 틱 넘김 거절과 섞이지 않게 **같은 틱 안에서** 이어 쓰게 한다(14 회차 P2-2: S10 정지를 큐에 넣으면 허가가 `STOP_PENDING` 이라 대기 재송신이 돌지 않으므로, 시험 훅이 같은 틱 시각으로 `_transmit(now_ns)` 를 한 번 더 명시적으로 부름). 권한이 그대로면 그 S10 정지 프레임이 완성되고, 그 사이 lease 나 제어 세대가 바뀌면 미완성·폐기·DISARM(외부 결과로 판정).
- 2 절: '위치 유지 프레임의 목표'·'남는 되돌림의 크기' 의 시험 ⓐ–ⓓ, '호스트의 축 변위 감시' 의 시험(생략 틱에 미송신 옛 `hold` 버림 포함).
- 5 절: 틱 안 예외에서 그 틱의 제출 답이 정산됨(다음 틱 `invalid` 아님); `link.begin` 이 제출을 큐에 넣은 뒤 돌아오기 전에 예외 → 큐 비워짐·원장 정산·재무장 뒤 옛 제출 미실행; `apply` 전 예외면 큐의 미적용 제출이 버려지고 `tick_failed` 로 원장에 남으며 재무장 뒤에도 실행되지 않음; `apply` 도중 예외(첫 제출 수락 기록 뒤 둘째에서 예외)면 원장에 첫째는 그 결과(`m1` 수락), 둘째는 `tick_failed`; HIL 확인이 `HIL_PLANT` 만 선 STATE 를 거절하고 같은 부팅의 후속 STATE 에서 비트가 빠지면 곧바로 운동·합성 표본이 닫힘; 두 번째 `collect` 실패에도 `last_records` 로 정산; `tick_end` 진행 중 실패는 다시 부르지 않음(틱 토큰 하나); 같은 묶음의 같은 `request_id`·다른 seq 제출은 둘째가 `duplicate_request`.
- 1 절: HIL 확인이 부팅 변경에서 꺼지고 새 부팅의 STATE 확인 전까지 운동·합성 표본 없음; 모형 종료는 `device_lost` 로 실행 종료(재개방 없음); `_transmit` 이 `_cut_stuck_write` 뒤에 운동 허가를 읽음; 예약기는 깨어난 시각을 넘기고 21–25 ms 틱 연속이면 `loop_slow`.
- `--run`: 실 장치 거부 사유, HIL 이 아닌 보드 거부, 합성 원천 거부.

### 10.1 모듈과 원천 계약 — `src/forklift_core/live/real_run.py`

(겹치면 10.8 > 10.7 > 10.6 > 10.5 > 10.1–10.4 순으로 따른다.)

- **준비** `prepare_run(paths, *, clock, stop) -> RunPrep`(2 회차 P2-1): 설정 로드와 dry 검증, `RealChannels`·세션 epoch·콘솔 `welcome`, **공통 시각 원점 `start_ns`**, `PlanWorker`(준비 대기를 별도 스레드에서 하고 `stop` 이 서면 작업자 프로세스를 끝내고 나옴 — 시그널로 취소 가능). 원천과 조립은 이 `RunPrep` 을 받는다.
- `RunSources`(원천의 계약만):
  - `client`: `Client.HIL`(이 PR) 또는 `Client.REAL`(PR 7 — 그때까지 조립이 거부).

  - `imu`: 5b 의 `samples(upto_ns, limit)`. `depth`: `frames(now_ns)` + 포켓 훅 — 없으면 None(D5 는 `d5_pocket` 우회로만).

- `assemble_run(prep, sources, *, events) -> RealRun`: 호스트는 **원천의 `client` 로 만든다**(1 회차 P1: `real_host` 가 `Client.REAL` 을 고정 → `real_host(cfg, client=…)` 로 인자화; HIL 보드의 출력 잠금 수용은 `drive_refusal` 의 HIL 분기가 맡음 — `allow_locked` 와 무관, 2 회차 P3), 포트·허가(`AutoPermit`), 중재기(`real_requests=True`)를 `prep.channels` 에 묶은 `RealLink`, **재무장 콜백은 단위를 맞춰 묶는다**(2 회차 P2-4: 중재기는 단조 초를, 허가는 ns 를 쓴다 — `rearm_refusal=lambda s: permit.rearm_refusal(int(s * 1e9))`, `on_rearmed` 도 같은 변환; rig 의 직접 연결도 이 PR 에서 같은 변환으로 고친다), 실층(`RealLayer` + `ThreadWorker`), `DelayBound`, 운영 `Evidence`(rig 대역 없음: 작업자는 `PlanWorker`·층 작업자의 생존, baseline 은 코어의 baseline 판정, 측정은 최신 STATE 의 조향·승강 유효성과 계수 연속성, 링크는 호스트 신선도·빌드 거부·클록 비율), `OperatorStart`, `build_watches`, `RealLoop`(`scan_feed`, 이벤트 콜백).

### 10.2 합성 원천 — `src/forklift_core/live/synthetic_sources.py`

- `SyntheticScan`: 모형 오도메트리 자세(루프의 `odom_pose`)에서 `s10a_hil.yaml` 장면 상자를 광선 투사해 0.1 s 마다 스캔을 **취득**한다. 취득은 전달과 따로다 — 취득 이벤트를 층 전달 큐와 SLAM 쪽이 함께 받는다(2 회차 P2-3).
- `SyntheticSlam`: 취득 이벤트마다 응답을 만든다(`stamp_s` = 그 스캔의 첫 빔). 처리된 응답의 보정은 처음 항등이고, **`seed(epoch, base_pose, stamp_s)` 뒤에는 그 `map ← base_link` 자세에서 나온 보정을 이후 응답에 유지한다**(2 회차 P2-3: 계속 항등이면 선언 때 적용한 보정을 다음 응답이 덮음). 회차 계약(`relocalize` 로 epoch 이 바뀌면 그 전 응답 버림, `request_processed(not_before)` 는 그 뒤 취득분만).
- `SyntheticImu`: 정지 중 중력 + 잡음 200 Hz.
- **HIL 확인에 묶음**: 생성자는 `client is Client.HIL` 이고 생성 시점에 `transport.hil_plant is True` 가 아니면 `SyntheticRefused`. 매 호출에도 확인이 거짓이면 아무것도 내지 않고 그동안의 취득분·응답을 버리며, `hil_boot` 가 바뀌면 그 전 부팅의 것을 내지 않는다. 전송기는 같은 부팅에서 비트 위반을 한 번 보면 그 부팅 동안 계속 거부한다(6a-2a).
- **주입 지점**(시험 전용 `--hil-inject <이름>:<ms>`, 2 회차 P2-6): `scan`(층 전달만 멈춤, 취득·SLAM 은 계속 — 6 절 '스캔 원천 멈춤' 의 overdue 경로), `scan_lost`(명시적 끊김), `slam`(응답 전달만 멈춤), `tx`(전송기 쓰기만 멈춤 — '송신만 끊기'), `tx_partial`(그 시각 뒤 첫 DRIVE 의 첫 4 바이트만 쓰고 **그 DRIVE 의 나머지 바이트만** `tx_release:<ms>` 까지 `EAGAIN` — 폐기 뒤 독 바이트열과 DISARM 은 막지 않음; 3 회차 P2-5). STATE 만 끊기는 모형 인자. 기록에 주입하지 않은 원천의 마지막 표본 시각을 남긴다.

### 10.3 러너 — `tools/real_autonomy.py --run --hil`

- **모형의 수명 예산**(3 회차 P2-4, 4 회차 P2-4): 모형의 `--duration-ms` = 실행 시간 + `HIL_MODEL_EXTRA_S`, `HIL_MODEL_EXTRA_S = HIL_STARTUP_MAX_S(5, 모형 기동 뒤 첫 STATE·조립·콘솔 시작의 합) + 종료 확인 1 + 여유 5 = 11 s` — `HilPty` 가 이 한 산식으로 넘기고(6a-2a 의 +5 s 를 바꿈) 1 절의 `SIGKILL` 시험도 같은 기산점(모형 기동)과 상한을 쓴다. 모형 기동 뒤 준비가 `HIL_STARTUP_MAX_S` 를 넘으면 세션을 시작하지 않고 기동 실패(`hil_startup_slow`)로 끝낸다(`LiveServer.start()` 의 대기도 남은 예산으로). 모형은 **새 세션(프로세스 그룹)** 으로 띄워(`start_new_session=True`) 터미널 Ctrl-C 가 모형에 직접 가지 않게 하고, 러너가 종료 DISARM 을 확인한 뒤 모형을 끝낸다.
- **순서와 기동 예산**: ① 인자 검사(`--device` 와 `--hil` 동시 → 장치를 열기 전 거부, 예약 모형 인자 거부) ② `prepare_run`(설정·dry 검증·채널·`start_ns`·`PlanWorker` — 모형 기동 **전**, 시그널로 취소 가능) ③ `HilPty`(모형의 자가 종료 = 실행 시간 + `HIL_MODEL_EXTRA_S` 는 여기서부터) ④ `Client.HIL` 호스트와 `LoopTtyTransport`, 같은 둘로 첫 STATE 를 기다림(`HIL_FIRST_STATE_S`, 실패 `hil_no_state`/`hil_refused:<flags>`, 자식 종료 `device_lost:model_exit`) ⑤ 합성 원천 ⑥ `assemble_run`(그 호스트·전송기 그대로) ⑦ `LiveServer.start()`(`prep.channels` 위, 조립 뒤라 조립 전 제어 요청이 없음; 포트 출력) ⑧ 허가에 송신 콜백을 묶고 `start_session(now)` — 첫 DISARM 은 그 자리에서; 루프의 오도메트리·지연 추정·세션 확인은 루프 생성 뒤의 STATE 부터 ⑨ `run(duration_s)`. 시그널은 어디서든 종료 표시만 세우고 각 단계가 본다.
- **종료**(2 회차 P1): 기한·시그널·`transport.lost`·모형 종료(`poll`)·원천이나 기록 콜백의 예외에서 같은 종료 경로로 들어간다. 링크가 살아 있으면 ⓐ 루프에 **종료 표시**(`closing`)를 세운다 — 송신 관문은 DISARM 만 통과시키고, 중재기는 `rearm` 과 임무 요청을 `run_ending` 으로 거절한다 ⓑ 허가 래치 `run_end` 로 DISARM 을 같은 관문으로 낸다 ⓒ 틱을 계속 돌려(운동 프레임 없음) 최대 1 s 안에 **종료 DISARM 의 확인**을 받는다 — `closing` 동안 실제로 끝까지 쓴 DISARM 마다 `(boot, seq, written_ns)` 를 따로 모으고(허가의 '마지막 DISARM' 하나에 기대지 않음), 그중 하나를 같은 부팅의 STATE 가 그 쓰기 뒤에 `last_rx_seq` 로 정확히 확인하고 `DISARMED` 이며 **확인 시점에 호스트의 `health(now).fresh` 가 참**일 때(첫 시도를 잃고 재시도가 수락되는 경우 포함; 정확한 seq 라도 신선도 상한을 넘은 STATE 는 확인이 아님 — 4 회차 P2-1); `closing` 동안 지연 추정용 DISARM 과 세션 재시작은 내지 않는다(3 회차 P2-1: 그것이 쓰이면 허가의 마지막 DISARM 기록을 덮음) — 못 받으면 `disarm_unconfirmed`(새 `DISARMED` 가 와도 종료 DISARM 이 전달되지 않았으면 이것). `poll()` 이 먼저 종료를 보면 `transport.peer_exited()`(그 순간의 반쪽·독 바이트열 상태로 `lost` 고정, 첫 경로 `model_poll`). 정리는 중첩 `finally` 로 **모형부터**: `HilPty.close()`(회수) → 서버 멈춤 → 층 `ThreadWorker.close()` + `join(timeout)`(안 끝나면 기록) → `PlanWorker` 닫기(오래 걸릴 수 있어 마지막) → 기록 스레드 종료 확인. 앞 단계가 예외를 내도 뒤 단계는 돈다. 종료 사유는 회수 뒤 확정.
- **기록**(4 회차 P2-3: `closing` 시작 시각과, 허가가 확인한 각 DISARM 의 확인 시각·seq 도 남김)(JSONL, 쓰기 스레드 + 크기 제한 큐 — 틱 안에서는 넣기만, 2 회차 P2-5): 머리(`synthetic: true`, `uninspected`, `start_ns`, 설정 해시, 모형 인자), 틱(실제 시작·간격·branch·reason·notes), 프레임(seq·부팅·arm_gen·송신 순번·용도(일반/위치 유지/S10 정지/ARM/zero/DISARM)·결정 시각·echo MCU 시각·`valid_after_echo`·`last_gate_ns`·`first_byte_ns`·`last_write_ns`·`written_ns`), **STATE 마다 판정에 쓴 값**(실제 수신 시각, 지연 상한과 그때의 신선도 규칙 — 6 절 `F` 의 재계산 근거), 증거(층의 첫 overdue 평가 시각, `axis_watch_times`, `disarm_decisions`, SLAM 응답의 취득 시각), 주입, 끝(사유·종료 코드). 큐가 가득 차거나 쓰기 스레드가 실패하면 제어 틱은 기다리지 않고 그 실행에 `record_incomplete` 를 남긴다 — 쓰기 스레드가 실패해 같은 파일에 못 쓰면 stderr 와 CLI 종료 코드(3)로 알리고, 종료 이벤트가 없거나 쓰기 완료를 확인하지 못한 기록은 시험이 판정 불가로 다시 돌린다(3 회차 P3). 끝에 종료 이벤트까지 큐를 비우고 스레드 종료를 확인한다. 틱 기록에는 이어 쓰기를 거절한 관문 판정(`continuation_refused:<reason>`)과 반쪽 프레임의 seq·시작 시각도 남긴다.
- **예약기 시험**(가짜 시계): 정확히 경계에 끝난 틱, 21–25 ms 틱 세 번(`loop_slow`), 수면 중 종료 표시.

### 10.4 `config/real/s10a_hil.yaml` 과 HIL 통합 시험

- 머리에 'HIL 값, 실측 아님'. 지도 id(합성 SLAM 의 `map_id` 와 같음), 시작 자세, 팔레트 치수·자세(시험 팔레트 가정값), 장면 상자, 목적지, 최대 속도 0.15.
- 시험(`realtime`, ws1 한 프로세스 단계): 양성 CLI 시험(6 절 콘솔 순서; `s10_lifted` 와 함께 **허가가 `control_stop_confirmed` 로 확인한 정지 DRIVE 의 seq 와 `s10_stopped` 가 낸 DISARM 의 seq 를 기록에서 찾아, 모형 수락 로그가 둘 다 수락했고, 호스트 기록의 **임무 DISARM 확인 시각**(같은 부팅·그 seq 를 담은 신선한 `DISARMED` 의 수신 시각)이 **`closing` 시작 시각보다 앞섬** — 둘 다 호스트 단조시계라 MCU 시각을 바꾸지 않고 비교; 임무 DISARM 이 빠지고 `run_end` DISARM 만 수락된 로그는 불합격; 3 회차 P2-2, 4 회차 P2-3), 정지 주입 넷(`tx`·STATE 끊기·`scan`·`slam` 각각, 주입하지 않은 원천의 신선도 확인), **반쪽 DRIVE 주입**(`tx_partial` — 전제: 앞선 DRIVE 의 모형 수락을 확인; 이어 쓰기 시험은 의도한 DRIVE 가 `F` 근처까지 반쪽으로 남았고(틱 기록의 반쪽 seq·시작 시각) `F` 뒤 `tx_release` 에서 **증거 만료 판정**(`continuation_refused:` 의 사유가 입력 만료 계열)으로 거절됐음을 확인 — 그 전에 자기 쓰기 기한이나 `_cut_stuck_write` 로 버려졌으면 판정 불가로 다시; 종료 시험은 반쪽을 확인한 뒤 기한 또는 `SIGTERM` → 종료 DISARM 확인 또는 `disarm_unconfirmed`), 신호 경로(러너 PID 에만 `SIGTERM`, 러너 프로세스 그룹에 `SIGINT` — 모형은 다른 그룹이라 러너가 DISARM 을 확인한 뒤 끝냄), 축 변위 판정((가)–(다), `--axis-log`), 모형 수명, `--device` 와 `--hil` 동시 지정 거부, **종료 DISARM 이 전달되지 않는데 `DISARMED` 는 계속 오는 경우 → `disarm_unconfirmed`**, 정확한 seq 의 `DISARMED` 라도 확인 시점에 신선도 상한을 넘은 경우 → 확인 아님, IMU 의 일반 예외는 `watch_imu` 경로·`SourceFatal` 은 종료 경로, stale STATE 에서 콘솔 `rearm` 거절(단위 변환), 조립 거부 단위 시험(10.1 의 사유마다).

### 10.5 독립 전제 검토 반영 (새 스레드, 6 회차 수렴 뒤)

- **지도 id 와 점유**(P1-1): `prepare_run` 은 `--map-bundle` 이 있으면 그 번들의 id·점유를, HIL 에서 번들이 없으면 `s10a_hil.yaml` 의 `map_id` 와 장면 상자에서 만든 점유를 dry 검증·계획에 쓴다(`loaded_map_id` = 그 값). `assemble_run` 은 원천의 `slam.map_id` 를 `prep` 의 그 값과 대조한다 — 준비와 원천의 계약을 나눔.
- **PR 7 의 원천 선행 조건**(P1-2·P1-3·P2-1, 6a-2b 는 계약만 적고 구현하지 않음): 실 LiDAR 는 드라이버 stamp 가 아니라 **검증 가능한 취득 구간과 오차 상한**을 `first_s/last_s` 와 함께 내야 하고, 구간이 회차 시작을 걸치거나 상한을 확보하지 못한 스캔은 SLAM 증거로 채택하지 않는다; 실 SLAM 은 정지·저속·승강 중에도 0.5 s 안에 `processed` 를 내는 정책(키프레임 게이트를 그대로 쓰지 않음)과 회차 요청 처리를 갖춰야 한다; 스캔과 연결 이벤트는 **같은 연결 세대**로 묶어 낸다(`scans()` 의 각 스캔에 세대, 끊김/복구에 세대 — 끊김 뒤 옛 세대 스캔은 층이 버림); 실 어댑터의 명시적 끊김 감지 자리(수신 공백·소켓 오류)도 PR 7 에서. 이 넷이 갖춰지기 전에는 `Client.REAL` 조립을 거부한다(10.1).
- **D5 검사기 설치 주체**(P1-4): `assemble_run` 이 포켓 훅을 맡는다 — 깊이 원천의 `pocket_check` 빌더가 만든 검사기를 프레임의 취득 당시 임무 세대·단계·보정과 대조해 맞으면 `core.pocket["check"]` 에 등록하고 그 면제 영역을 층에 같이 넣는다(지금 rig 의 빌더가 하는 일을 조립기로). HIL 은 깊이 원천이 없어 `d5_pocket` 우회로만.
- **합성 취득의 시각과 자세**(P2-2): 첫 취득은 세션 확인 뒤 첫 `scans()` 호출에서 시작 시각만 잡고(그 전 시각을 채우지 않음), 밀린 주기는 **건너뛴다**(지난 시각에 지금 자세를 붙이지 않음 — 한 호출에 많아야 한 장, 그 시각은 이번 주기의 끝), 광선은 그 호출 시점의 오도메트리 자세 + 층 설정의 `lidar` 장착 변환으로. HIL 시작 자세는 0(오도메트리 원점과 SLAM 항등 보정이 일치) — `s10a_hil.yaml` 의 `start_rear` 를 0 으로 고정하고 조립이 확인.
- **STATE 신선도 규칙**(P2-3): HIL 은 호스트의 **수신 시각 규칙**(`gap_clock` 기본)과 `state_max_age_s = 0.05` 를 쓴다(MCU 시각 규칙은 `RateGuard` 검증이 따로 필요해 쓰지 않음). 기록의 STATE 행에 규칙 이름을 남겨 `F` 재계산이 같은 규칙을 쓴다.
- **치명 상태의 확인 자리**(P2-4): `fatal_source` 는 ① `_head` 의 원천 호출 뒤, ② 콘솔 처리(`link.begin`·`tick_start`) 직후, ③ **모든 비-DISARM 송신의 관문**(IMU 분기와 무관)에서 확인한다. 시험: IMU 우회 중 `request_processed()` 실패가 그 틱에 비상.
- **종료 확인의 STATE 단위 판정**(P2-5): 종료 확인은 마지막 STATE 하나가 아니라 **받은 STATE 마다**(`_on_state` 콜백에서) 판정한다 — 그 STATE 의 수신 시각과 실제 시계로 신선도를 보고, 같은 읽기에 재시도 확인 STATE 가 앞에 오고 뒤 STATE 가 덮어도 놓치지 않음. 세션 확인 도중 종료가 오면 허가의 세션 두 번째 DISARM 은 `closing` 이 막는다(종료 DISARM 만).
- **시간 제한과 회수**(P2-6): `PlanWorker` 는 소유권을 넘기기 전까지 준비 스레드가 쥐고, 취소되면 그 스레드가 작업자를 닫는다; `LiveServer.start()` 가 시간을 넘기면 `stop()` 을 불러 늦게 바인드된 서버도 닫는다; 층 `ThreadWorker` 는 `close()` 뒤 `join(timeout)` 을 하고 안 끝나면 기록. 원천별 틱당 최대 작업량(스캔 한 장, SLAM 응답 8 개, IMU 64 표본)을 계약에 넣는다(실 어댑터의 '빌 때까지 읽기'는 PR 7 에서 이 상한으로).
- **반쪽 DRIVE 시험의 시간대**(P2-7): 시험은 절대 시각 주입 대신 **조건 주입**을 쓴다 — 전송기 훅이 '정상 이동 DRIVE 이고 앞선 DRIVE 가 모형에 수락된 뒤의 첫 DRIVE' 를 고르고 첫 4 바이트만 쓰게 한 뒤, 그 프레임의 쓰기 기한(결정 + W) 안에서 루프의 증거를 만료시키는 원천 주입(스캔 전달 정지를 overdue 경계 직전에)과 같은 틱에 쓰기를 풀어 관문이 **증거 만료**로 거절하는지 본다; 대조 사례는 같은 조건에서 증거가 신선하면 이어 쓰기가 성공. 안 맞으면(정지 결정·쓰기 기한이 먼저) 판정 불가로 다시.
- **기록 실패와 seq 대응**(P2-8): 기록 콜백이 실패하면 `RealRun` 의 실패 표시를 직접 세운다(루프의 `_emit` 이 삼켜도 콜백이 표시); 모형 수락 로그의 16 비트 seq 는 호스트 기록의 (부팅, 송신 순번, seq) 와 **시간 창**(같은 부팅, 쓰기 시각 이후 첫 수락)으로 잇고, 판정기 시험에 큐 포화·쓰기 실패·seq 재사용을 넣는다; `F`·`E` 계산에는 실제 송신 프레임의 `valid_after_echo`(호스트 `Outgoing` 에서 복원)와 관문이 쓴 STATE 를 기록에서 잇는다.
- **결과 범위 표기**(P3): HIL 양성 결과는 'S10-A 의 명령·STATE·오도메트리·정지 전이' 범위로 적는다(위치 정확도·포켓 접촉·하중·실 센서 지연·USB 시한은 아님). 기록 머리에 모형 바이너리 해시와 모형 빌드의 차량 헤더·호스트 `vehicle.yaml` 의 보정 id 를 남긴다.

### 10.6 전제 검토 2 회차 반영

- **HIL 장면의 두 점유**(P1-1): `s10a_hil.yaml` 은 고정 장애물 `obstacles`(상자 목록)와 목표 팔레트(`pallet` 치수 + `check_pallet_pose`)를 따로 적는다. dry 계획의 점유는 **고정 장애물만**으로 만들고 목표 팔레트는 `pickup_obstacle` 로만 넘긴다(점유에 넣으면 삽입·인출이 막힘); 합성 LiDAR 는 둘 다 투사한다. 시험: 팔레트 옆의 별개 장애물은 점유에 남음.
- **송신–수락 대응**(P1-2): 모형 수락 로그의 행에 **부팅 id 와 호스트 단조시각**(모형이 같은 기계의 `CLOCK_MONOTONIC` 으로 읽은 ns — 파이썬 `time.monotonic_ns` 와 같은 시계)을 더한다. 대응: 같은 부팅에서 seq 가 같은 호스트 송신(그 프레임 마지막 조각의 **쓰기 진입** `last_write_ns`)과 모형 수락을 송신 순서대로 일대일로 짝짓되 수락 시각 ≥ 그 쓰기 진입; 한 수락에 후보가 둘 이상이거나 짝이 없으면 그 행은 합격 근거에서 뺀다(판정기 시험: seq 재사용, 쓰기 귀환보다 이른 수락).
- **치명 상태의 콘솔 분기 정산**(P2-새1): 콘솔 처리 뒤 치명 분기는 비상 뒤 `_settle_exception` 으로 그 틱의 요청을 한 번 정산한다(`tick_end` 가 아직이므로). 시험: 치명 원천 오류와 임무 요청이 같은 묶음 → DISARM 과 요청별 1 회 응답.
- **합성 빔의 '반사 없음'**(P2-새2): 사거리 안에 맞는 것이 없는 빔은 **유효한 `+inf`**(REP-117) — 무효 표본이 아님. 시험: 장애물이 드문 장면에서 층이 스캔을 받아 결과를 설치.
- **PR 7 SLAM 의 신선도 조건**(P2-새3): '응답 간격'과 '처리 시간'을 따로 0.5 s 로 두지 않는다 — 정지·저속·승강 중 **관문에서 본 증거 나이**(지금 − 마지막 `processed` 의 첫 빔) + 판정 여유(`EVIDENCE_READ_MAX_S`)가 늘 `SLAM_MAX_AGE_S`(0.5 s) 안, 즉 응답 간격 + 첫 빔에서 전달까지의 지연 + 5 ms ≤ 0.5 s.
- **PR 7 층의 연결 세대**(P2-1 남은 조건): 연결 세대가 바뀌면 대기 스캔·진행 중 작업·설치된 결과를 무효로 하고 새 세대 결과가 설치될 때까지 준비 판정을 닫는다(`LayerKey` 에 세대) — PR 7 의 선행 조건에 더함.
- **합성 스캔의 시각과 자세**(P2-2 남은 조건): 스캔의 `last_s` 는 **그 호출 시각**(경계가 아님), `first_s = last_s − 0.1 s`, 광선은 그 시각의 오도메트리 자세 ∘ 장착 변환(`SyntheticScan(mount=…)`, 층 설정의 `lidar` 장착값). 시험: 지연 틱 뒤에도 스캔 시각과 자세가 같은 순간, 비영 장착 변환.
- **세션 확인 취소**(P2-5 남은 조건): `begin_closing` 은 허가의 세션 확인을 취소한다(`AutoPermit.cancel_session()` — 두 번째 세션 DISARM 을 내지 않음). 시험: 첫 세션 DISARM 의 응답이 종료 중 도착해도 두 번째가 나가지 않음.
- **준비 대기의 취소와 인계**(P2-6 남은 조건): `PlanWorker` 생성은 준비 스레드에서 하고, 취소 표시와 생성 완료가 교차하면 **나중에 아는 쪽이 닫는다**(준비 스레드가 완성 뒤 취소를 보면 스스로 `close()`, 러너가 취소 뒤 완성을 받으면 `close()`); 생성자 안의 준비 대기 자체는 `ready_timeout_s`(30 s) 가 상한. `LiveServer.start()` 가 시간을 넘기면 러너는 `_ready` 를 최대 2 s 더 기다려 바인드됐으면 `stop()`, 그래도 아니면 데몬 스레드로 남겨 기록(프로세스 종료로 회수).
- **조건 주입 훅의 인자**(P2-7 남은 조건): 전송기의 `inject(fd, data, frame)` 는 첫 쓰기에도 그 프레임을 받는다(`_write_first` 가 넘김); 프레임의 용도는 루프 이벤트의 seq 로 시험이 판단. 시험 조건: 틱 본체의 정지 판정은 `F` 전, 이어 쓰기 관문의 증거 판정은 `F` 후, 그 프레임의 마지막 쓰기 기한은 그 뒤 — 기록으로 확인, 아니면 판정 불가.

### 10.7 전제 검토 3 회차 반영

- **대응 못 한 수락 행**(P2-새1): 대응하지 못한 수락 행이나 모형 로그 누락(모형이 정상 종료하지 않아 로그 마지막 줄을 확인할 수 없음 등)이 대상 프레임의 수락 여부를 바꿀 수 있으면 그 시험은 **판정 불가**(미수락의 증거로 쓰지 않음). 호스트 기록과 함께 모형 수락 로그의 쓰기 완료(모형의 정상 종료 코드와 마지막 줄의 완결)를 확인한다. 판정기 시험에 미대응 수락 행을 섞은 경우를 넣는다.
- **IMU 읽기 상한**(P2-새2): 64 표본은 **호출당** 상한이다(틱 머리와 송신 관문이 각각 부름; 200 Hz 라 한 틱에 보통 4 개). 송신 관문의 호출이 상한에 닿으면(밀린 표본) 관문이 필요한 최신 표본까지 읽었다고 볼 수 없으므로 그 프레임을 거절한다(`imu_backlog`, 대기 류).
- **합성 스캔은 순간 스캔**(P2-2 남은 조건): 투사 자세와 층의 배치 자세가 같은 순간이 되도록 `first_s = last_s = 호출 시각`(층의 배치는 `first_s` 의 오도메트리 자세). 시험: 이동 중 알려진 장애물이 **층에 놓인 위치**가 장면 위치와 맞음.
- **준비 인계의 원자성**(P2-6 남은 조건): `PlanWorker` 준비는 잠금 하나로 보호된 상태 `pending → done(worker) | cancelled` 의 전이로 인계한다 — 완료 게시와 취소가 그 잠금 안에서 한 번만 일어나고, 두 번째로 전이를 시도한 쪽이 작업자를 닫는다. `LiveServer` 에는 취소 표시(선택 인자)를 두어, 러너가 시작 시간 초과로 포기한 뒤 늦게 바인드된 서버 스레드도 바인드 직후 그 표시를 보고 스스로 소켓을 닫는다.
- **반쪽 DRIVE 시험의 시간대와 관측**(P2-7 남은 조건): 루프는 이어 쓰기 판정마다(거절 포함) 이벤트 `{"t": "gate", "seq", "ns0", "ns", "verdict"}` 를 내고, 틱 본체의 정지 결정 시각도 틱 기록에 남긴다. 주입은 시각이 아니라 조건으로: 앞선 DRIVE 의 수락 뒤 첫 이동 DRIVE 를 반쪽으로 만들고, 같은 틱에 스캔 전달을 멈추며, 쓰기 해제는 **층의 기대 시각 `F` 를 지난 첫 틱**에. 합격은 기록의 `gate` 이벤트가 그 seq 에 대해 `ns ≥ F` 에서 입력 만료 계열로 거절했고, 그 틱 본체의 정지 결정이 `F` 이전이 아니며, 그 프레임의 쓰기 기한(결정 + W)이 그 판정 뒤일 때 — 아니면 판정 불가.

### 10.8 전제 검토 4 회차 반영

- **반쪽 DRIVE 의 만료 분기는 rig 에서, HIL 은 일반 성질만**(P1): 실시간 HIL 에서 '틱 본체 판정은 `F` 전, 이어 쓰기 관문의 증거 평가는 `F` 후, 그 프레임의 쓰기 기한은 그 뒤'를 맞추려면 10 Hz 스캔·100 ms 층 예산에서 `F` 가 결정보다 100–200 ms 뒤라 35 ms 쓰기 기한이 먼저 끝나고, `F` 뒤 틱에서는 본체가 먼저 대기를 결정해 `stop_decided` 로 거절된다 — 시각 주입으로는 결정적으로 만들 수 없다. 그래서 **증거 만료로 인한 이어 쓰기 거절 분기는 가짜 시계 rig 의 단위 시험**(6a-1 의 관문 시험 계열: 이어 쓰기 직전에 증거 만료를 일으키고 같은 조건에서 신선하면 성공하는 대조)으로 고정하고, HIL 통합 시험은 **일반 성질**만 본다: 수락된 DRIVE 뒤의 첫 이동 DRIVE 를 반쪽으로 만들고 그 쓰기 기한 뒤에 풀면 — 거절 사유와 무관하게 — 그 반쪽은 **두 폐기 경로 중 하나로** 버려진다 — 이어 쓰기 관문의 거절(`continuation_refused:*`) 또는 프레임 자체 만료에서의 `_cut_stuck_write()`(틱이 늦어 만료에 먼저 닿은 경우) — 그리고 기록상 같은 프레임의 폐기 뒤 **독 바이트열을 끝까지 쓰고 그다음 DISARM** 을 보낸 순서가 확인된다(전송기 이벤트의 순서; 5 회차 P2-2). 모형 쪽: 완전한 모형 로그(종료 코드 0)에서 부팅 id·종류(DRIVE)·seq·주입 시간대로 그 DRIVE 의 수락을 특정할 수 있으면 **불합격**이고, 수락이 없으면 합격, 어느 송신의 수락인지 실제로 모호하거나 로그가 불완전하면 판정 불가(5 회차 P2-1 — 10.7 의 '미대응 행은 판정 불가' 는 대상 DRIVE 의 특정 가능한 수락에는 적용하지 않음). 10.7 의 조건 주입·합격 조건은 이것으로 대체한다.
- **모형 로그의 쓰기 완료 보증**(남은 P2): 모형은 `fprintf`·`fflush`·`fclose` 의 결과를 모두 확인하고, 하나라도 실패하면 종료 코드 4(`log_write_failed`)로 끝난다 — 정상 종료 코드(0)는 로그 쓰기와 닫기가 모두 성공했다는 뜻. 시험: 로그를 `/dev/full` 로 주면 종료 코드 4, 판정기는 그런 실행을 판정 불가로.
- **`imu_backlog` 의 순서**(P2-새): 송신 관문은 읽은 배치에서 `SourceFatal`, IMU 감시 트립(기울기·표본 공백 등), 기존 비상 사유를 **먼저** 판정하고, 그것들이 없을 때만 상한 도달을 `imu_backlog`(대기)로 본다. 시험: 상한에 닿은 배치에서 감시 트립도 나면 그 틱에 래치와 DISARM.

### 10.9 6a-2b 설계 검토 기록

- 독립 검토 셋: ① Codex 적대적 검토(스레드 `01a1f5a1`) 1–6 회차 → '새 P1/P2 없음', ② Codex 새 스레드 전제 검토(`01a1f5b8`, 처리 기록을 보지 않음) 1–6 회차(1 회 P1 4·P2 8 → 2 회 P1 2·P2 3+5 → 3 회 P2 2+3 → 4 회 P1 1·P2 1+1 → 5 회 P2 2 → 6 회 '새 P1/P2 없음'), ③ 원자료 재계산(설정 파일·코드에서, 2026-11-20): `HIL_MODEL_EXTRA_S = 5 + 1 + 5 = 11 s`; 위치 유지 표본 상한 `0.020 + 0.010 + W 0.035 + 0.005 = 0.070 s`(코드 값과 같음); 층 예산 `config/real/obstacle_layer.yaml` 의 `latency_budget 0.10 s`·`overdue_end 1.0 s`, 스캔 주기 `obstacle_layer_real.yaml` 의 `scan_period_s 0.1` — 결정 때 스캔 나이 0–100 ms 이므로 `F − 결정 ∈ [100, 200] ms > W 35 ms`(10.8 의 'HIL 시각 주입으로는 만료 분기를 못 만든다'를 확인); 모형 STATE 주기 10 ms(`mcu_model.c` 의 `fw_app_init(…, 10, …)`), 50 Hz 한 번 읽기로 수신 나이 ≤ 20 + 10 = 30 ms < 신선도 상한 50 ms; 합성 순간 스캔의 관문 시 SLAM 증거 나이 ≤ 100 + 20 + 5 = 125 ms < `SLAM_MAX_AGE_S` 0.5 s. 운영 조립은 이 설정 파일의 값(예산·overdue_end·스캔 주기·`state_delay_s 0.03`·`sensor_timeout_s 0.35`)을 읽어 쓴다(rig 의 0.05 등 손 상수가 아님).

### 10.10 6a-2b 구현에서 정한 것 (2026-11-20, 구현 검토 대상)

설계에 값이 없었거나 구현에서 설계와 다르게 정한 것. 모두 임시값이고 이유를 적는다.

- **스캔 배치의 STATE 지연 포함 상한 0.05 s**(10.9 의 `state_delay_s 0.03` 을 바꿈): 50 Hz 루프는 20 ms 마다 한 번 읽고 모형 STATE 는 10 ms 주기라 왕복 지연 상한이 30–40 ms 에 이른다. 0.03 s 면 한 번 읽기의 앞 STATE 가 번갈아 '포함 안 됨'이 되고, 스캔 배치는 창 안 모든 STATE 가 포함이어야 하므로 스캔이 한 장도 놓이지 않아 `layer_latency_exceeded` 로 래치했다(가짜 시계 조립 시험에서 재현). 설정 파일의 0.03 s 는 텔레옵 다리의 실측(≤ 28 ms)이다. 실행은 자기 상수 `RUN_STATE_DELAY_S = 0.05` 를 쓴다 — 호스트 신선도(수신 뒤 나이)와는 **독립된 값**이다(Codex 구현 1 회차: 측정에서 60 ms 늦은 STATE 도 방금 읽으면 신선). 나이 표의 `dt = 2 × 0.1 + 0.05 = 0.25 s` 로 커진다. 보드 날에 루프의 실제 지연 상한 분포로 다시 정함.
- **층 격자 범위 = S10-A 필드 경계 + 1 m**: 다리의 ±`hall_half_m`(20 m, 800 × 800 칸)은 S10-A 필드보다 훨씬 커 ws1 2 GB 잡이 OOM 으로 죽었다. HIL 에서는 오도메트리 원점 = 지도 원점(10.5)이라 경계가 그대로 맞는다. PR 7 의 실 원천은 시작 자세만큼 옮긴 범위가 필요(PR 7 선행 조건에 더함).
- **빠른 커널**: 벽시계 실행이므로 `prepare_run` 이 `kernels.prefer_fast()`·`warm_up()` 을 부른다(실시간 계획 D2–D3 의 규약). 없을 때 허가 질의가 틱당 약 10 ms 라 21–25 ms 틱이 이어져 `loop_slow` 로 래치했다(노트북 스모크). 켠 뒤 틱 본체 p99 4.7 ms·최대 간격 20.5 ms. 기록 머리에 커널 모드.
- **코어의 틱 선택값**(`real_run.core_options`, dry 조립도 같은 함수): 4b 의 dry 조립은 준비 경로만 보아 틱이 읽는 선택값이 비어 있었다. 명령 경사·중간 정지 감속 = `autonomy.yaml` 의 `drive_acceleration_mps2`(0.30), 커스프·관측·체류 관련은 S10-A 에서 꺼진 값(rig 와 같음), 관측 도착 상한은 Isaac 러너의 0.10 m·0.10 rad(관측이 꺼져 쓰이지 않음), 뒤축 오프셋은 차체 모델 값.

- **구현 4 회차 반영(Codex)**: 모형 축 로그에 그 틱의 호스트 `CLOCK_MONOTONIC` ns 를 8 번째 열로 남기고 판정기는 수신 지연을 뺀 오프셋 대신 그 열로 주입·구간 시각과 비교; 루프가 래치 사유마다 **증거를 판정한 시각**을 `cause` 이벤트로 남기고(준비 판정의 `ns`, 송신 직전 `send_ns`, 틱 머리 비상의 틱 시작), 판정기는 그 시각(관문 이벤트의 `ns` 포함, 더 정밀한 것 우선)이 만료(F·overdue 끝) 이후인지와 그 DISARM 이 F 뒤 첫 틱 + 한 틱 안에 쓰였는지를 따로 본다; 모형 틱 간격 초과는 `observed_only`(시험이 같은 시나리오를 최대 3 번 다시 돌림); 밀기는 그 위치 유지 프레임의 seq 로 구간에 묶고, 모형 축의 부호 있는 도약(그 MCU 틱)과 그 틱 뒤에 측정된 STATE 를 그 구간이 유효 판정했는지(`axis_judge` 에 STATE 의 MCU 시각), 경보 사례는 그 래치의 DISARM 이 종료 전에 쓰였는지; STATE 끊기의 늦은 수락은 `accepted` 행만; 기록 종료 표시는 끝 행이 큐에 못 들어간 경우에만(쓰기 스레드는 끝 행을 읽으면 스스로 끝남); `tick_deadline` 은 다음 틱이 없으면 판정 불가; `PlanWorker` 시험은 죽은 자식 회수(`proc.wait`) 중에 `alive` 거짓을 직접 확인.
