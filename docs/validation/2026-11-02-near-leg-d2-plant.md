# 근접 다리 계획 D2′ 2 부 — 적용 명령에서 plant (등록, 2026-11-02, 검증 예측 전)

계획: `docs/plans/2026-11-02-near-leg-end-stall.md` 1.6 D2′ 의 2 부. 이 문서는 **검증용 실행의 예측을 보기 전에** 목록·모델 구조·입력 정렬·지표·기준을 고정한다. 결과는 같은 문서의 아래 절에 덧붙인다.

## 자료

- S1 배치 `st_b3e3ea7f`(코드 b3e3ea7f, 질량 10 kg) 실행 66 건의 `run/result.json`(0.1 s 표본)과 `run/slam_log.npz`(120 Hz 관절·truth).
- 입력은 표본의 적용 명령이다. `speed_command_mps` 와 `steering_command_rad` 는 `drive = ackermann(...)` 뒤의 값이다. 0.1 s 값을 관절 시각(120 Hz)에 선형 보간한다. 보간은 이번 식별의 한계로 둔다(틱 단위 적용 명령은 경계 기록에만 있다).
- 출력은 `slam_log` 의 `steering_rad`(관절각)와 `base_pose_world`(x y z qw qx qy qz) 에서 낸 truth 후축 자세(차체 원점 − 0.34 m · 전방)다. 진단 기록에서 `slam_control.npy` 의 truth 후축과 0.0 mm 로 일치함을 확인했다.

## 목록

- 제외(진단·회귀 전용): st_off_random_1_s2, st_on_random_1_s2, st_on_random_1_s5, st_on_random_1_s9.
- 식별: 두 팔 × {random_1 s0·s1·s3, aisle_rack s0·s1, line_2 s0·s1, trailer s0}(16 실행).
- 검증: 나머지 전부(46 실행). 실행 단위로 나누고 틱을 섞지 않는다.

## 모델과 지표

- (a) 조향: 바퀴마다 적용 조향 명령 → 1 차 지연 τ(0.05–0.30 s, 0.01 간격) + 지연 시간(0, 0.025, 0.05 s). 식별 실행의 두 바퀴 합동 RMSE 최소로 고른다.
- (b) 운동: 적용 속도 → 1 차 지연 τᵥ(0, 0.05, 0.1, 0.15, 0.2, 0.3, 0.4, 0.5 s). 곡률은 모의한 두 바퀴 각에서 k = (tan δL + tan δR)/(2L)로 내고, L 은 식별 실행의 (적용 곡률, 적용 각)에서 중앙값으로 맞춘다. 후축 운동학을 쓴다.
  - 창: 3 s 창을 1 s 마다 둔다(적용 속도 |v| > 0.05 m/s 가 있는 창만). truth 후축 자세와 truth 속도에서 출발한다.
  - 창 끝에서 truth 대비 |방위 오차|와 truth 방위 기준 |옆 오차|를 잰다. τᵥ 는 식별 창의 방위 p95 최소로 고른다.
- 도구: `tools/near_leg_d2_plant.py`(이 커밋, md5 는 결과 절에 적는다). ws1 Slurm CPU 잡으로 돌린다. 총괄 기준의 "ws1 제출" 1 회로 센다.

## 기준 (검증 실행)

- (a) 합동 RMSE ≤ 0.02 rad, 그리고 실행별 p99 ≤ 0.06 rad 가 검증 실행의 95 % 이상.
- (b) 창 끝 |방위 오차| p95 ≤ 0.02 rad, |옆 오차| p95 ≤ 0.02 m.
- 처분:
  - 둘 다 만족하면 D2′ 3 부(제어 포함 굴림)로 간다.
  - (a) 만 만족하면 조향 응답은 검증, 운동 쪽은 미검증이다. 바퀴 쪽 힘·감쇠·미끄럼·차체 곡률 응답을 후보로 둔 2 차 식별(제출 2 회째)을 한 번 한다.
  - 2 회째에도 기준에 못 미치면 총괄 기준에 따라 C2 를 먼저 진행한다.
- 이 기준은 "기록을 재현하는가"의 판정이다. C1 에서 K3 문턱 근처를 어떻게 다룰지는 3 부에서 이 모델의 오차 분포로 따로 정한다.

## 1 회째 결과 (ws1 잡 14723, 도구 md5 ced9b883)

- (a) 조향: τ = 0.17 s, 지연 시간 0 이다. 식별 RMSE 0.0134 rad, 검증 합동 RMSE **0.0131 rad**, 실행별 p99 ≤ 0.06 rad 가 **46/46** 이다. 기준을 만족한다.
- (b) 운동: L = 0.6645 m, τᵥ = 0(지연이 나아지게 하지 않음)이다. 검증 7,819 창에서 방위 p95 **0.0417 rad**(기준 0.02), 옆 p95 **0.0232 m**(기준 0.02)로 **미달**이다.
- 처분: 등록대로 2 차 식별을 한 번 한다(제출 2 회째).

## 2 회째 등록 (2 회째 예측 전)

- 구조:
  - 모의한 바퀴각의 곡률에 기어별 실현 이득 g_f(전진)·g_r(후진)을 곱한다. 범위는 0.80–1.15, 0.01 간격이다.
  - 적용 속도에 이득 s 를 곱한다. 범위는 0.90–1.10, 0.02 간격이다.
  - τᵥ = 0 이다.
  - 근거: `docs/plans/2026-10-24-curvature-response.md` 의 실현/명령 곡률 진단(전진 약 0.90, 후진 약 1.05)이다.
- 고르는 법: 식별 창의 방위 p95 최소. 방위 변화가 창마다 기어별 곡률 적분에 선형이라 격자를 한 번에 계산한다. 그다음 검증 창을 완전히 적분해 방위·옆을 잰다.
- 목록과 기준은 1 회째와 같다.
- 한계: 1 회째 검증 집계(방위·옆 p95)를 본 뒤 구조를 골랐다. 그래서 2 회째 검증은 완전히 독립적이지 않다. 구조는 1 회째 결과가 아니라 이전 계획의 사전값에서 왔다. 그래도 독립성 보강으로 S1c 실행(새 질량, 다른 배치)에 같은 계수를 고정해 다시 잰다(제출 수에 넣지 않는 확인).
- 2 회째도 기준에 못 미치면 총괄 기준에 따라 C2 를 먼저 진행하고, C1 은 보류한다.

## 2 회째 결과 (ws1 잡 14724, 도구 md5 ad71326a)

- g_f = **0.94**(전진), g_r = **1.12**(후진), s = **0.94** 이다. 사전값(전진 약 0.90, 후진 약 1.05)과 같은 방향이다.
- 식별 창: 방위 p95 0.0186 rad, 옆 p95 0.0147 m.
- 검증 7,816 창: 방위 p95 **0.0194 rad**(기준 0.02), 옆 p95 **0.0140 m**(기준 0.02)로 **기준을 만족한다.** 방위의 여유는 0.0006 rad 로 작다.
- D2′ 2 부(plant)는 총괄 기준인 ws1 제출 2 회 안에 끝났다. 다음은 3 부(제어 포함 굴림)와 세 실패의 끝 방위 재현이다.
- S1c 확인(같은 계수 고정, 새 질량)은 S1c 가 끝난 뒤 덧붙인다.

### 2 회째 재집계 (잡 14725, 도구 md5 850311c9)

- 2 회째 코드가 속도 이득을 곱한 뒤 창을 골라, 등록(원래 적용 속도 |v| > 0.05)과 창 모집단이 달랐다(7,819 → 7,816, Codex). 구조와 계수는 그대로 두고 등록대로 다시 셌다.
- 검증 7,819 창: 방위 p95 **0.01943 rad**, 옆 p95 **0.01403 m**. 기준 안이다.
- 해석의 한계(Codex): 방위 목적함수는 s·g_f, s·g_r(0.8836 / 1.0528)만 식별한다. 그래서 (0.94, 1.12, 0.94)는 조합된 경험 계수이고, 속도·곡률 이득을 물리적으로 따로 식별한 것이 아니다. 3 s 창 성능이 7–9 s 다리 전체의 재현성을 뜻하지도 않는다.

## D2′ 3 부 — 제어 포함 굴림과 세 실패 (도구 `tools/near_leg_d2_closed.py`)

- 굴림: 실제 놓기 순간(truth 자세, 관절 조향, 보간 조향 명령)에서 시작한다.
  - 전체 경로 추종기(`skip_legs(1)`)를 쓴다.
  - 러너 명령 사슬: `ackermann_command` → `creep` → `slew_cap_stop`(가속 0.8 · 감속 1.5, 설정 확인) → 조향 명령 1.0 rad/s.
  - plant 는 2 부의 것이다.
  - 추종기 입력: (A) truth, (B) truth + 기록 추정오차(`slam_control` 제어−truth, 시각별).
- 결과(제어 좌표 끝 위치 mm, pose−goal 방위 / truth):

|---|---|---|---|
| off s2 | 66.7, 0.166 / 119.1, 0.180 | 엄격 도착 24.3, 0.006 | 잔량 0 정체 57.0, 0.131 / 109.5, 0.146 |
| on s5 | 52.8, 0.112 / 104.8, 0.136 | 잔량 0 정체 49.9, 0.136 | 잔량 0 정체 41.1, 0.076 / 93.2, 0.100 |
| on s9 | 63.4, 0.115 / 116.7, 0.129 | 잔량 0 정체 40.8, 0.060 | 잔량 0 정체 47.2, 0.075 / 100.6, 0.089 |

- 러너의 정지 검출과 1 s 완화 도착을 더하면 결과가 달라진다(Codex 재계산).
  - (B) 에서 on s5·s9 는 약 9.7–9.8 s 에 완화 도착한다. (A) 의 on s9 도 완화 도착한다.
  - 그래서 (B) 는 추종기의 잔량 0 정체는 3/3 만들지만, 실제 시간 초과는 off s2 하나만 재현한다. 제어 좌표 방위가 실제보다 0.03–0.04 rad 작다.
- (A) 의 출발 옆오차는 truth 기준 −34.6 / −74.6 / −56.0 mm 다. 그래서 "옆 40 mm 만으로 실패"라고 요약하지 않는다. on s5 의 truth 자세는 K3 의 60 mm 자세 범위 밖이기도 하다.
- 기록 추정오차를 놓기 순간 값으로 고정하면 세 건 모두 엄격 도착했다(Codex). 이 모의에서 시간에 따라 변하는 오차 주입이 결과를 바꾼다는 근거다. 다만 특정 보정 계단 하나의 필요성이나 실제 실행의 원인을 입증하지는 않는다.
- 남은 모의 차이: 추종기 입력 속도는 실제로는 StopDetector 가 조정한 오도메트리 속도인데, 모의는 plant 속도를 쓴다. permission cap 등 나머지 명령 제한도 빠져 있다.

## 처분

- 계획 2 절의 규칙("세 실패의 끝 방위도 재현할 때만 C1 을 계속 검토")에 따라 **C1 을 보류한다.** 원인은 미분리로 둔다. 판정 기준은 러너 결과 범주(시간 초과 대 완화 도착)와 제어 좌표 오차 크기다. truth 오차가 비슷하다는 것으로 판정 불일치를 대신하지 않는다.
- 총괄의 C2 선행 조건은 아직 발동하지 않았다. 조향 검증은 제출 2 회 안에 통과했고, S1c 는 시작 전이다. C2 착수는 별도 우선순위 결정으로 총괄에 올린다.
- S1c 확인: 2 부 계수를 고정해 S1c 실행에서 다시 잰다(제출 수에 넣지 않음).

- 도구 정리(머지 전): ruff format·lint 정리로 `tools/near_leg_d2_plant.py` md5 가 9e2c8d4d 로 바뀌었다. 정리 전 판(850311c9)과 같은 입력에서 출력 JSON 이 완전히 같음을 ws1 에서 확인했다.
