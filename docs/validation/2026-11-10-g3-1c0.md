# G3-1c 1c-0 시제품 결과 (2026-11-10)

- 계획: `docs/plans/2026-10-17-realtime-sim.md` 5.27(#394).
- 시제품: `ShadowMemory._apply_arrays`, `control/shadow_numba.py`(`retained`). 스위치 `FORKLIFT_SHADOW_KERNEL=1`(기본 끔). 커널 모드 `reference` 에서는 켜도 원래 경로다.
- 도구: `docs/validation/2026-11-10-g3-1c0/`
  - `g3_1c0_analyze.py`: 표본 덤프 재생.
  - `g3_1c_stream.py`: 이벤트 재생.
  - `g3_1c0_lists.py`: 이벤트 기록 실행 목록.
- 결과 JSON: `c0_line_m.json`, `c0_hall.json`(커밋 ee4d4cc2, 이동을 원래 경로로 되돌린 판).
- 예측이지 판정이 아니다. 단계 판정은 폐루프로 한다.

## 바꾼 것

- band 집합: `set(zip(…))` 로 만든다. 원래 집합 내포와 같은 키를 같은 순서로 넣는다.
- 기억 정리·후보:
  - 배열로 고르고, 원래의 세 삽입 순서(남는 기억 → whole → band FREE)로 사전을 만든다.
  - 남는 값은 원래 튜플을 그대로 쓴다. 새 값의 형은 원래 식을 따른다.
  - rho 는 `math.hypot` 으로 구한다. `sin(psi/2)` 는 쓰이는 표 행만 계산한다.
- RETAINED: numba 고정점이다. 0·NaN 이 끼면 원래처럼 reference 로 간다. numpy 모드에서는 기존 batched 경로다.
- `_move`: 원래 경로 그대로다. 시제품 첫 판은 numba 로 옮겼으나, 이벤트 기록에서 이동 자체의 몫이 5 % 문턱 아래(판단 장면 line_m 4.2 %, 두 기록 합산 4.8 %)라 계획 5.27 의 규칙대로 되돌렸다(총괄 결정 2026-11-10, 아래 이벤트 재생 절).
- 정확한 float 관문: 시각·원점·해상도·자세·띠 폭·`evidence_max_age_s`·`rho_margin_m`·오차표·기억 값이 모두 내장 `float` 이고 `free_stamp` 가 float64 일 때만 배열 경로를 쓴다. 시작 등록 호출도 원래 경로다.
- 반경에 비유한 값이 끼면 커널 대신 batched 판정으로 넘긴다. 원래의 `max()` 동작(예외 포함)을 그대로 따르기 위해서다.
- 예열: 새 커널(`retained`)을 `kernels.warm_up()` 에 넣었다. 첫 RETAINED 호출에서 새 시그니처가 컴파일되지 않음을 시험한다.
- 새 커널에는 부동소수 산술이 없다(LLVM 에 fmul·fadd·fma 0, 기계어에 vfmadd 없음). 비교와 최소만 한다.

## 기대 절감(1c-0 등록값)

- 표본은 층별 수집이라 이동 호출이 많다(약 10 %). 라이브의 보정 변경 비율 0.04 로 이동 호출의 비중을 바꿔 평균을 낸다.
- numba: 호출당 절감 비율 0.557(line_m)·0.566(hall)이다. line_m 분모 54.6 ms/sim s 에 곱하면 **약 −30 ms/sim s** 다. 단계 목표 −25~−30 안팎이다. (이동을 numba 로 옮긴 첫 판은 0.605·0.612, 약 −33 이었다.)
- 노트북 측정이고 캐시가 따뜻한 오프라인 재생이다. 실현 절감으로 읽지 않는다. ws1 이벤트 재생과 폐루프가 남았다.
- `_move` 몫은 아래 이벤트 재생으로 정했다(표본은 이동 호출이 많아 쓰지 않음).

## 이벤트 재생 장치

- 기록: 덤프 모듈의 연속 모드(`FORKLIFT_PERF_DUMP_STREAM=shadow_apply=1000000`, `EVERY=0`, `STRATA_K=0`)를 쓴다.
- 완전성 표식: `perf.stream_report()` 가 수신자별 총호출 수·기록 수·상한을 `stream_totals_<pid>.json` 에 쓴다. 러너가 `app.close()` 전에 부르고, `atexit` 은 보조다.
- 재생(`g3_1c_stream.py`):
  - 순번 연속, 기록 수 = 총호출 수, 상한 미소진, 상태 연속성을 확인한다.
  - 기준(끔) 재현을 먼저 하고, 후보(켬, 모드별)를 이어서 재생한다.
  - 덮은 경우를 센다. 입력에서 정하는 것은 시작, 이동, `extra_support`, RETAINED 유무, 원점 이동, 몸 사각형 변경, 관문 우회다. 기준 재생이 실제로 탄 분기에서 정하는 것은 reference 경로(0·NaN, 깊이 지지 포함), 후보 없음, 빈 결과, 전부 inf 결과, 도달 범위가 격자 밖에 닿는 후보다.
  - 이동 자체의 시간을 팔마다 따로 낸다(5 % 규칙용).
  - 넘긴 폴더마다 표식과 기록이 있어야 하고, 연속 모드가 아닌 기록이 섞이면 무효다.
  - 파일은 하나씩 읽는다.
- 시험: 자식 프로세스 기록으로 온전한 흐름은 받고, 접두부(상한)·빈 순번·잃은 마지막 호출·표식 없음은 거부한다.

## 이벤트 기록과 재생(ws1, 2026-11-10)

- 기록: 스냅숏 g3c0_de5f13b4. line_m 잡 17192(g3c0_F), hall 잡 17223(g3c0_H; 17192 에서는 실행 추정 기본값 탓에 시작되지 않아 따로 냈다).
- 재생: ws1 NumPy 1.26·numba 0.59, 이동을 numba 로 옮긴 첫 판(de5f13b4)의 코드다.

| | 호출 = 기록 | 상한 | 재생 | 이동 | 끔 → numba ms/호출 | _move 몫(끔) |
|---|---|---|---|---|---|---|
| line_m | 1,881 = 1,881 | 미소진 | valid, 불일치 0 | 72 (3.8 %) | 5.17 → 2.11 | 4.2 % |
| hall | 2,709 = 2,709 | 미소진 | valid, 불일치 0 | 130 (4.8 %) | 4.71 → 1.57 | 5.3 % |

- 덮은 경우: 두 기록 모두 시작 1, 원점 이동(779·1,352), 몸 변경 2, RETAINED 매 호출이다. `extra_support`·0/NaN·후보 없음·격자 밖 도달은 0 이라 단위 합성 시험이 덮는다.
- `_move` 결정(총괄 2026-11-10): 계획 5.27 의 5 % 규칙은 장면별인지 합산인지를 적지 않았다. 판단 장면(line_m) 기준으로 읽고(4.2 %), 합산(4.8 %)도 같은 결론이라 되돌렸다. "어느 장면이든 5 % 이상"(hall 5.3 %) 해석은 데이터를 본 뒤 고르지 않는다. 이동 호출 꼬리(최대 약 11 → 3 ms)는 규칙 밖의 이점이라 남기지 않고, 1c 폐루프 뒤 꼬리가 문제로 남으면 따로 등록한다.
- 되돌린 코드(ee4d4cc2)의 표본·이벤트 재생은 R1 뒤 CPU 빈틈에 다시 돌려 이 문서에 더한다.
