# EPAL 6·T11 공통 지원 / Isaac Sim 검토 인계

작성일: 2026-09-17. 다음 에이전트는 이 문서를 먼저 읽고 연결된 원자료를 확인한다.

## 1. 현재 요구와 이번 작업의 범위

사용자는 원격 Isaac Sim 시연 코드, 전날 중단한 ADR 0003 검토, 전체 개발 로드맵을 함께 검토하고 WebGPT Pro와 교차검증하도록 요청했다. 이어 **EPAL과 T11 모두 지원**해야 한다고 명시했고, 검토 결과의 문서화를 요청했다.

- 현재 문맥의 필수 대상은 **EPAL 6과 T11 ×0.6(660×660×90 mm)**이다. 하나를 정본으로 고르고 다른 하나를 제외하는 제안은 철회했다.
- 두 형상의 전체 작업 지원, 실제 제작 시험체 선택, 더 넓은 형상군의 회귀 시험은 별개다. 자동 규격 판별이나 원치수 T11 지원을 추가 요구로 추론하지 않는다.
- 인식→접근→삽입→적재→이송→하역과 A–D 완료 조건을 각 형상에 적용한다. 한 형상의 성공으로 다른 형상의 실패를 대체하지 않는다.
- 이번 검토는 문서·코드·기존 저장 결과를 대조한 것이다. 새 시뮬레이션, 실물 시험, 제어 구현은 수행하지 않았다. 이번 후속 변경은 문서화뿐이며 commit/push는 하지 않았다.
- 이 문서는 **검토 결과와 재개 지점**이다. 새로운 구현 계획·시험 수·엔진 변경을 승인한 문서가 아니다.

## 4. 채택한 판단과 아직 해결하지 않은 계약

### 공통 형상은 인식 prior만의 문제가 아니다

`DetectorParams.derived_for`와 형상군 시험은 이미 있다. 이를 처음부터 다시 만들 필요는 없지만, 유도식 회귀 통과가 두 형상의 인식·삽입 성공을 뜻하지는 않는다.

원격 `bench03/run_transport.py:168–175`는 `SyntheticMissionGeometry()`를 기본값으로 만들고 별도로 URDF 기반 삽입 기하를 읽는다. `pallet_mission.py:75–95`의 EPAL 기본값(깊이 0.60 m, 폭 0.80 m, 삽입 후축 오프셋 1.23 m, 적재 footprint 전방 1.53 m)은 URDF만 T11으로 바꿀 때 함께 바뀌지 않는다.

같은 명목 차체·삽입 깊이 0.36 m에 T11 깊이 0.66 m를 대입하면 후축 오프셋은 0.34+0.95+0.33−0.36=1.26 m, 적재 footprint 전방은 1.26+0.33=1.59 m다. **이 값은 기존 상수 재사용의 반례이며 새 승인 파라미터가 아니다.** prior·모델·URDF·진입면·목표 삽입 깊이·관측 전면→base/후축 변환·적재 footprint·평가기의 일치가 필요하다.

### 관측과 삽입 허가를 분리해야 한다

`PocketObservation.valid`는 포켓 관측의 유효성이지 안전한 삽입 허가가 아니다. 관측 계약은 수평 팔레트/yaw 중심이며 z는 prior에서 오는 값이고, 알 수 없는 σ는 0이 아니다. `pocket-observation.md:47–59`에서 검출 증거 부족을 `no_pallet`로 분류하면서 이를 “아무것도 없음”으로 설명하는 충돌이 있다. 검출 실패는 빈 공간 증거가 아니다.

선택한 팔레트와 진입면의 동일성, 관측 시각·소실·만료, 추적과 재관측, 정지 확인을 제어 입력 계약으로 연결해야 한다. 다른 후보의 valid 관측으로 선택 대상의 lost를 가려서는 안 된다. **관측 소실 상태의 예측만으로 삽입을 계속하는 승인은 보류 상태를 유지한다.**

### Isaac 성공은 M4–M6·A–D 완료가 아니다

- `insertion_geometry.py`는 현재 시점 박스 간 기하 검사임을 명시하며 PhysX 접촉력·갱신 사이 연속 swept clearance를 보증하지 않는다. 두 blade/heel의 OBB SAT와 2 mm 여유 검사는 모든 차체 부품의 접촉 검증이 아니다. 실행 코드는 insert/withdraw 단계에서 검사한다.
- 예외 발생이나 프로세스 종료가 실제 속도 0·제동·안전 정지를 보증하지 않는다. 관측 소실, 명령 만료, 동적 장애물, 적재 상태의 충돌·정지 계약이 남아 있다.
- `pallet_mission.py:119–123`의 단계별 정지는 **B의 정지 없는 곡선 진입** 완료 조건과 맞지 않는다.
- `_reservations`의 접근·삽입·추출·배송 통로 예약 때문에 현재 무작위 장애물 시연은 **C/D의 근거리·후방 장애물 모집단**을 대표하지 않는다.
- 로드맵 M4의 동적 Gazebo 조건을 Isaac 발견만으로 대체하지 않는다. 엔진별 역할과 완료 증거 변경은 별도 결정 사항이며 두 엔진 전체 중복 구현도 자동 의무가 아니다.

로봇 포함 비교 원자료는 `artifacts/hpc/20260916T133304Z/out/R_*.txt`와 해당 작업의 `jobs.tsv`다. 첫 비영 검출 거리(m)는 baseline 1.98→1.98, K2 1.56→1.56, K2tilt 1.40→1.40, mast 1.68→1.68, low 1.20→1.30이었다. 이는 Isaac 렌더나 실센서 결과가 아니다. jobs.tsv의 내장 스크립트를 읽을 때 잡음 생성·평활화·재정규화 순서를 보존한다.

ADR 0003의 floor rail 기하와 미리보기/시험의 정합성 지적(`pallet_geometry.py:233–237`, `preview_docking.py:148`, 관련 시험)은 미해결로 남긴다. 실물 제작 치수·재료·질량·포크 적합성은 H0–H4 확인 대상이다. EPAL 합성 10 kg 설정을 실물 취급 가능성으로 해석하지 않는다.

## 6. 다음 에이전트의 재개 지점

이번에 한 일은 현황 정정과 근거 보존이다. 다음 구현에 앞서 다음 순서로 좁은 계약·계획을 구체화한다.

1. 두 형상의 공통 기하 입력과 관측→임무→정지 계약을 정리한다. 위의 독립된 URDF/임무 상수 문제를 재현 가능한 반례로 고정한다.
2. 기존 데이터로 M2의 잡음·근거리 한계를 분석하고 M3의 후보/진입면 동일성·신선도·소실·재관측을 진행한다. 실물 H0–H4는 병행하되 합성값을 실측값으로 올리지 않는다.
3. 기존 Isaac 자산을 재사용하여 **각 형상의 A 전체 작업을 센서 기반으로 연결**하는 범위를 정한다. B 연속 진입, C 후진, D 후방 제약은 명시적 시나리오로 확장한다.
4. 엔진별 역할, 실제 남은 개발주차·입고일·인원, 형상별 시험 수를 확정하고 마지막 두 개발주차 통합·시연 시간을 보호한다.

로드맵의 기존 제안 표본을 그대로 형상마다 적용하면 2×4×20=160회 합성, 2×4×10=80회 실물이다. **산술상 작업량이며 확정된 신규 시험 수가 아니다.** H0/H1의 개발 2–3주차 배치와 개발 2주차까지 확보 가정도 일정 구체화 때 함께 정리한다. 일정 부족을 이유로 두 형상·A–D·포켓 추적·전체 작업 요구를 임의 삭제하지 않는다.

## 7. 교차검증 기록과 보존 상태

사용자가 지정한 송현 Chrome의 ChatGPT **6 Pro**에 소스 묶음을 첨부해 검토를 요청했고, 답변 후 Codex가 주요 지적을 문서·코드·저장 결과와 대조했다. [검토 원문](2026-09-17-dual-pallet-webgpt-review.md)은 외부 모델의 정적 리뷰이며 이 문서의 채택·한계 설명과 함께 읽는다. 공통 기하 누락과 GT 이외의 완료 조건을 보강하는 데 의견이 합치했다.

원문 중 “EPAL 평가가 전혀 없다는 판단을 철회”라는 귀속은 채택하지 않는다. 기존 답변이 평가 부재를 주장한 것은 아니며, 필요한 조치는 과거 문구와 후속 완료 기록의 현황 정합성 수정이다. 원문은 가공 없이 보존했으므로 브라우저의 `sources +1` 같은 표시는 클릭 가능한 근거 링크가 아니다. 이 문서의 파일 경로와 원자료로 확인한다.

검토에 전달한 `sources.txt`의 SHA-256은 `3ab3bf050febcf65c61f92ad54b9167aa733c574b850bd4a5bbd986926a8d719`다. 소스 묶음·검토 로그의 세션 임시 경로는 `/tmp/forklift-webgpt-review-90xlksou/`이며 영구 보존을 전제하지 않는다. 핵심 인계와 검토 답변은 이번에 저장소 문서로 옮겼다. 원격 실행 자산·큰 첨부 묶음은 저장소로 복사하지 않았으므로 재개 시 원격 경로와 버전을 다시 확인해야 한다.

검토 채팅 ID `6aab3917-7fcc-83ee-b05f-fc678546c2d3`는 사용자의 명시적 요청으로 영구 삭제했고 홈 이동·최근 목록에서 제거·작업 탭 닫기를 확인했다. 삭제 대기 작업은 없다.
