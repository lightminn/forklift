## 시제품(광선 셀 판정)

- 몸 사각형은 쓰이는 곳에서만 원래 식으로 계산한다: 넓힌 것은 차체 둘레 창에서, 줄인 것은 광선 셀에서. 오프셋은 반경별로 캐시한다.
- 광선 셀의 rho 는 원래 `np.hypot` 이다. numba 판은 행 단위 다음-비지지 열 표, NumPy 대체 판은 오프셋을 하나씩 돌며 O(셀) 메모리로 판정한다.
- 동등성:
  - 성질 시험 24 경우: 커널 모드 둘, 몸 사각형 유무, 격자 가장자리, 여러 스캔.
  - numba 판과 NumPy 대체 판의 대조.
  - 실제 덤프 1024/1024 를 스위치 켬으로 재생해 스위치 끔으로 만든 결과와 바이트까지 같았다.

## 기대 절감(1b-0 등록값)

- 호출당 절감 0.68–0.70 ms 는 원래의 약 28 % 다. 라이브의 `_clear_group` 48.5 ms/sim s 에 같은 비율을 곱하면 **약 −14 ms/sim s** 다. 시간은 노트북에서 쟀으니 ws1 과의 비율 차는 폐루프에서 본다.
- 5.20 의 단계 목표(−25–35)에 못 미친다. 남은 큰 몫은 `ray_mask`(0.78 ms, 원래 구현과 같은 일)다.
- 후보: 같은 스캔의 raw 를 다음 스냅숏에서 다시 쓰는 캐시. 스캔은 0.2–0.3 s 동안 여러 스냅숏에 쓰이고, 보정이 바뀌는 비율은 4 % 다. 이것은 호출 사이 상태라 이벤트 재생 장치가 필요하고, 1b 범위를 넘는다.

## 읽기(Codex 교차검증 반영)

- 동등성은 지지된다. Codex 가 대상 커밋으로 덤프를 직접 다시 재생했다: 원 결과 1024/1024, `_clear_group` 중간 결과 2050/2050 바이트 동등이다. ws1(NumPy 1.x) 확인은 남았다.
- 기대 절감 약 −14 ms/sim s 는 합리적인 등록 예측이다. 산정 방식에 따라 −13.6, −14.0, −14.2 가 나온다.
  - 이 값은 노트북 측정이고, 실행 순서가 고정이며, 직전 통계 계산의 캐시 효과가 들어 있다. 실현 절감으로 읽지 않는다.
  - 대체 판의 peak RSS 와 덤프의 속도 분포는 아직 내지 않았다(1b PR 에서 낸다).
- 단계 목표 −25–35 는 그대로다. −14 예측을 등록한다고 단계 합격 기준이 바뀌지는 않는다.
- 다음 순서(권고): (가) 1b 를 마무리하고 폐루프로 실현 절감을 확인한 뒤 (다) 1c 로 간다.
  - (나) raw 재사용 캐시는 범위가 넓어진다. 보정 변경률 4 % 가 적중률 96 % 를 뜻하지 않기 때문이다. 격자 원점·shape·해상도·스캔 입력·설정도 키에 들어가므로 이벤트 재생 장치가 필요하다.
- G3 합계: 1b −14 + 1d −11.5 + 1c 목표 −25–30 = −50.5~−55.5 ms/sim s 로, 예산 −100 에 44.5–49.5 가 모자란다. 1e 가 필요할 가능성은 높다. 다만 착수 판정은 등록한 결합 후보의 짝별 규칙(5.26)으로 한다.
- 도구 보완(Codex P2 셋):
  - 새 numba 커널을 `kernels.warm_up()` 에 넣었다(예열 없이는 첫 호출 184 ms).
  - 분석기는 환경 변수 스위치를 존중하고(`--clear-kernel env|on|off`), 실제 선택값·커밋·NumPy/numba 버전·후보 경로 호출 수를 기록한다. 측정 전에 모드마다 한 번 예열 재생을 한다.
  - numba 가 없으면 numba 매개변수 시험만 건너뛴다.
