- 날짜: 2026-10-28
- 결정: 총괄(2026-10-27·28). 설계 `docs/design/2026-10-15-pallet-recognition-generality.md` §6 개정 문단.
- 도구: `tools/far_frame_gaps.py`(시험 `tests/unit/tools/test_far_frame_gaps.py`)
- 자료: 효율화 세션의 learned 작업자 VRAM 시범(`docs/plans/2026-10-27-learned-worker-vram.md`). ws1 `test_runs/live/lvram_cfee06a7/`
  - 스냅숏 cfee06a7. 콘솔 live 세션이고 장면마다 4 세션 × 미션 3 이다.
  - 위치 추정(registry), team-spec.
  - 묶음 하나에 GPU 1 장, 슬롯 3.
  - CUDA 팔과 CPU 팔이 있다.
  - 장면은 line_m(`cuda/`·`cpu/`)과 random_m 재실행(`rm/`)이다. random_m 에는 경쟁 후보가 있다.

## 기준이 바뀐 경과 (결과를 본 뒤 두 번 바꿨다)

1. 설계 §6 원문: 지연 ≤ 200 ms. 최대로 읽혔고, 2026-10-19 CPU 측정의 최대 232 ms 가 GPU 로 옮긴 이유였다.
2. line_m CUDA 결과를 본 뒤 제안: "왕복 p99 ≤ 200 ms(최대는 기록) + 반영 프레임 간격 ≤ 0.5 s". random_m 확인을 조건으로 승인됐다.
3. random_m CUDA 결과를 본 뒤 결정: 왕복 p99 가 256 ms 로 2 의 조건을 넘었다. 그래서 주 조건을 **반영 프레임 간격 ≤ 0.5 s** 로 바꾸고, 왕복 분위수는 기록·감시로 내렸다.
   - 근거: 인식에 실제로 영향을 주는 양은 프레임 간격이다. 결과는 촬영 시각 순서로 반영되므로 늦은 호출은 순서를 바꾸지 않는다. 트랙은 반영 간격이 만료 0.5 s 를 넘을 때만 비활성으로 간다.

## 수치

미션마다 첫 호출은 왕복 분포에서 뺐다(첫 호출 최대는 따로 적음).

| line_m CUDA | 12 | 통과 | 0.4 | 0 | 0 | 10 | 0 | 56 / 141 / 195 / 239 | 0.7 % |

| random_m CUDA s1 | 3 | 통과 | 0.4 | 0 | 0 | 2 | 0 | 106 / 213 / 281 / 303 | 6.0 % |
| random_m CUDA s2 | 3 | 통과 | 0.2 | 0 | 0 | 0 | 0 | 101 / 177 / 223 / 262 | 2.7 % |

- random_m CPU 의 왕복 분위수는 세션별로 따로 내지 않았다. 네 세션을 모은 값은 p50 210 · p95 349 · p99 433 · 최대 558 ms, 초과율 57 % 다.
- 간격 0.4 s 는 5 Hz 주행 프레임 하나가 큐 초과로 버려진 경우다. 기록된 촬영 시각에는 약 2 × 10⁻⁸ s 의 부동소수 오차가 있어(0.40000002) 도구는 1 × 10⁻⁶ s 여유로 비교한다.
- 인식 결과는 CUDA 팔 모든 미션에서 같았다: 트랙 상실 0, 선택 트랙 전환 0, 정지 프레임 모두 반영, 미션 24/24 done(line_m 12, random_m 12).
- CPU 팔은 주 조건을 어긴 미션이 있었지만 트랙 상실·전환은 0 이었다(재연결 규칙). 그래도 계약 위반으로 센다.

## 여유와 한계

- **여유가 얇다.** CUDA 팔의 최대 간격 0.4 s 는 프레임 하나가 빠진 것이다. 둘이 연달아 빠지면 0.6 s 로 만료를 넘는다. 그래서 "연속 버림 ≥ 2" 와 "간격 > 0.4 s" 를 감시 지표로 두고, 0 이 아니면 경보로 올린다.
- **근거가 좁다.** 장면 둘(line_m·random_m), CUDA 팔 미션 24 개, 한 스냅숏, GPU 1 장에 세션 최대 3 개다.
- **원거리 추정 정확도(정답 대비)는 보지 않았다.** 미션 완주와 트랙 연속성만 봤다.
- **시뮬 전용이다.** 이 계약은 ws1 RTX 공유 GPU 에서의 live 경로 기준이다. 실차(Jetson)의 지연 예산은 별개이고, 설계 §6 의 Jetson 줄대로 실제 장치에서 다시 잰다.
