## 원인 진단(기록만, 새 실행 없음)

비교 기록: 같은 시나리오·같은 스위치(1b·1c·1d 켬)·레이어 작업자 없는 1e 판정 실행의 `g3el_f_02_cand`(잡 17342, 스냅숏 `g3de_eaac4c41`, #408 이전; 보관본에서 복원). 그 묶음의 6 세션은 모두 미션 done 이었다.

**1. #405 는 이 실패와 무관하다.** bcb21c87..b64e8af2 의 코드 변경은 #405 하나다. 그 가운데 이 실행에 닿을 수 있는 것은 콘솔 런처(`isaac_live.sbatch`)의 G3 스위치 기본값과 `result.json` 의 `scan_switches` 기록이다(나머지는 survey 런처·LiDAR 벤치). 1e-0 의 래퍼 `r1c_session.sh` 는 그 콘솔 런처를 부르지만, 측정 목록이 세 스위치 값을 명시해 기본값 변경의 영향을 받지 않는다. 비교 기록도 같은 값이다. 덱 렌더 17491(bcb21c87, #408 포함·작업자 끔)의 복귀도 done 이었다. eaac4c41..b64e8af2 의 `sim/`·`src/`·`config/` 변경에서도 작업자와 무관한 주행·설정 변경은 없다(Codex 확인).

**2. 작업자 세션만 `evidence_stale` 로 멈춘다.** 장애물층 허가의 감속 사유(`result.json` `obstacle_layer.slowed_reasons`, 틱 수)와 단계 시간(`TRANSITION`):

| g3e0 `thread` | 769 | 673 | 79 | 127.4 s | 78.5 s 뒤 시간 초과 |

- AUTO 행(`live_log.jsonl`, `mode == AUTO` 로 고른 행, 정지 틱 포함)의 명령 속력 평균: 접근 0.368 / 0.359 / 0.370 m/s 로 셋이 같다. 운반 0.236 / 0.123 / 0.124 m/s, 복귀 진입 뒤 28 s 0.463 / 0.087 / 0.084 m/s 다(작업자 없음 / delay / thread). 복귀에서 추적기 목표는 −0.4…−0.6 m/s 인데, 명령 속도가 0 → −0.15 램프를 되풀이한다. 고른 AUTO 행은 모두 `stop_kind none` 이다.
- 복귀의 AUTO 속도 0 틱 가운데 delay 672/676, thread 676/683 이 물리 틱 번호 mod 12 = 1·2 에 몰린다(Codex). 정시 설치(mod 12 = 3) 직전 틱이라는 아래 기전의 예측과 맞는다. 다만 개별 FREE 칸과 감속 사유의 대응까지 보인 것은 아니다.
- 작업자 자체는 등록대로 돌았다. 설치 2,820·2,834 회 가운데 정시(`scheduled`, 스캔 + 3 틱)가 2,784·2,812 회다. 나머지는 `refresh` 장벽 29·15, `add_scans` 6, 마지막 1 회(delay `session_end`, thread `permission_reset`)다.

**3. 기전.** 허가(`drive_permission.py` `allowed_speed`)는 매 틱, 정지 호와 경로 검사가 기댄 FREE 증거의 가장 오래된 시각이 `evidence_max_age_s` 를 넘으면 속도 0, `evidence_stale` 을 낸다. 운용 설정(`config/obstacle_layer_single_team_spec.yaml`)의 값은 `free_max_age_s: 0.2` 다.
- 스캔 시각은 물리 스텝 뒤 시각이다(`run_transport.py` 7704). 동기 결과는 제어 틱 i+1 부터, 작업자 결과는 i+k 부터 쓰인다. 그래서 작업자의 추가 사용 지연은 (k−1)/120 s 다(k = 3 에서 16.7 ms).
- 한 스캔 전에 본 FREE 칸(스캔 때 나이 0.1 s)이 끼면, 다음 설치 직전 틱의 나이는 동기 0.1 + 11/120 = 0.1917 s, k = 3 에서 0.1 + 13/120 = 0.2083 s 다. 작업자에서만 한도 0.2 s 를 넘는다. 한 스캔 걸러 보이는 칸이 정지 호나 경로 앞에 있는 동안 설치 직전 두 틱이 0 이 된다.
- k = 2 는 명목상 0.2000 s 로 한도와 같다. 엄격한 `>` 비교에 실제 dt 의 부동소수가 걸릴 수 있어, 통과한다고 단정할 수 없다(Codex).
- 계획 5.28 D5 안전 회계는 "증거 나이: 늦게 쓰면 나이가 커지는 쪽(보수)"이라고 적었다. 보수라는 판단은 맞지만, 그것이 운용 주행에서 정지를 만드는지는 검토하지 않았다. 정지 모형에는 (k−1)/120 s 를 더했고, 증거 나이 한도와 그 나이에 맞춘 격자 오차 반경에는 더하지 않았다.
- 한계: 작업자 변경에는 D5 의 정지 호 연장도 들어 있다. 그것도 검사하는 칸과 `oldest_free_s` 를 바꿀 수 있으므로, 늦은 설치만을 따로 떼어 낸 실험은 아니다(Codex). 틱별 감속 사유는 기록되지 않는다(합계만).

## 수정: 작업자를 켤 때 FREE 증거의 "사용 나이"를 하나로 닫는다

처음 적은 안(틱의 나이 비교만 넓힘)은 안전 모형을 깬다(Codex P1). 격자는 FREE 영역을 `free_max_age_s` 나이의 오도메트리 오차로 줄인다(`obstacle_grid.py` 636·692, "Sized for the oldest age this evidence may still be used at"). 비교만 넓히면 0.2 s 를 넘는 나이의 오차가 그 축소 밖이다. 그래서 다음과 같이 고친다.

**규칙.** 작업자(`delay`·`thread`·`oracle`)를 켜면, FREE 증거를 쓸 수 있는 최대 나이를 L = `free_max_age_s` + (k−1)/120 으로 하고, 그 증거를 쓰는 모든 곳이 같은 L 로 판단한다. `off` 에서는 L = `free_max_age_s` 로 지금과 같다.

| 곳 | 지금 | 작업자일 때 |
|---|---|---|
| 격자 FREE 축소의 나이(`obstacle_grid.py` 636·692) | `max(age, free_max_age_s)` | `max(age, L)` |
| 허가 틱 비교(`drive_permission.py` 870) | `evidence_max_age_s` | L |
| 텔레옵 묶음(`teleop_drive.py` 277) | 같음 | L |
| 후보 구역 나이(`obstacle_layer.py` 731) | 같음 | L |
| cusp 다음 구간 판정(`core.py` 6312) | 같음 | L |
| 그림자 기억 지평(`ShadowMemory.evidence_max_age_s`) | `free_max_age_s` | L |
| 알려진 팔레트 투영 지평(`apply_known` `horizon_s`) | `evidence_max_age_s` | L |
| 출구 접두 검증 나이(`apply_verified` `max_age_s`, `obstacle_layer.py` 595) | `free_max_age_s` | L(검토 대상) |
| 새 FREE 를 만드는 스캔 선택(`obstacle_grid.py` 483)·계획 기억 clears(`obstacle_layer.py` 309) | `free_max_age_s` | 그대로 |
| 재출발 확인 `_clearing_scans`·센서 침묵 | — | 그대로(여유 없음) |

- 스캔 선택을 그대로 두므로, 작업자의 FREE 증거 집합은 동기의 부분집합이다. 늘어나는 것은 쓸 수 있는 나이뿐이고, 그 나이까지 오차를 덮도록 축소가 커진다.
- 구현: D5 가 정지 모형에 지연을 더하는 한 곳(장애물층 설정을 읽는 곳, `run_transport.py` 4714)에서 설정에 L 을 넣는다(예: `grid.free_use_age_s`, 없으면 `free_max_age_s`). `ObstacleLayer` 가 격자 설정·허가 설정·그림자 기억을 만들 때 그 값을 쓴다. 그 설정에서 나온 모든 허가(층 허가, 텔레옵 묶음, 출구·철수 사본, 후보·탈출 허가)가 정지 모형처럼 같은 값을 갖는다.

**안전 근거(총괄 요청 ①).** 늦은 설치가 바꾸는 것은 두 가지이고, 각각 모형 안에서 닫힌다.

1. 시간(반응 지연): 늦은 설치 동안 차가 더 달리는 거리는 정지 모형의 지연으로 회계한다(D5).
   - 정지 거리 d(v) = v·t_lat + v²/(2a) + m 에서 t_lat = 0.15 → 0.15 + (k−1)/120 = 0.1667 s 다.
   - 0.30 m/s 에서 d 가 v·(k−1)/120 = 5.0 mm 늘고, 0.60 m/s 에서 10.0 mm 늘어난다. 허가는 늘어난 d 가 검증된 호 안에 들어가는 속도만 낸다.
2. 공간(증거의 위치 오차): FREE 칸은 그 증거를 쓰는 동안의 오도메트리 오차만큼 줄여 둔다. 작업자에서 쓰는 최대 나이 L = 0.2 + 2/120 = 0.2083 s 에 맞춰 축소 나이를 L 로 한다.
   - 오차표(`obstacle_odometry_age_team_spec.json`)는 계단식이라 0.2083 s 는 0.3 s 행(위치 0.0257 m, 방위 0.01424 rad)을 쓴다. 0.2 s 행은 0.0236 m, 0.01372 rad 이다.
   - 축소 반경 r = e + 2ρ·sin(ψ/2) 가 ρ = 4 m 에서 약 4.2 mm 커진다(Codex). 표 안의 값이라 외삽은 없다.
   - 허가의 틱 나이 비교가 L 을 넘는 증거를 거부하므로, 쓰이는 모든 증거의 나이는 축소에 쓴 나이 이하다.
- 두 몫은 서로를 대신하지 않는다. 정지 지연은 주행 방향의 거리이고, 위치·방위 오차의 공간 여유는 축소가 맡는다(Codex P1).
- 그림자 기억(RETAINED 판단 지평)과 알려진 팔레트 투영의 지평도 L 로 늘린다. 둘 다 "이 증거가 쓰일 동안"의 오차를 내다보는 값이라, 쓰는 기간이 늘면 같이 늘어야 한다. 늘리는 쪽은 더 큰 오차를 가정하는 보수다.
- 남는 몫: 움직이는 장애물에 대해 증거가 0.2 → 0.2083 s 까지 쓰인다(4 % 증가). 이 프로젝트의 안전 모형은 정적 장애물과 차의 자세 오차를 다루고, 움직이는 물체의 속도 상한은 따로 두지 않았다. 이 증가는 작업자를 켤 때만 생긴다.
- 행동 영향: 축소가 커지면 경계의 FREE 가 약간 줄어 검증 거리가 짧아질 수 있다. 재측정의 `evidence_stale`·`limit` 틱 수와 운반 시간으로 본다.

## 시험(총괄 요청 ②)

- 단위 시험으로 고정한다.
  - `off` 에서 L = `free_max_age_s` 이고, 위 표의 모든 곳이 지금 값을 쓴다.
  - 작업자에서 L = `free_max_age_s` + (k−1)/120 이고, 표의 "L" 칸 여덟 곳이 모두 L 을 쓰며, "그대로" 칸은 바뀌지 않는다.
  - 나이 비교 넷은 나이가 `free_max_age_s` 와 L 사이인 증거를 작업자에서만 통과시킨다.
  - 격자 축소가 작업자에서 0.3 s 행을 쓴다.
- 러너·장애물층을 건드리므로 runs29 재생 게이트 29/29(`off` 경로가 기록과 같음)와 ws1 전체 pytest 0 failed 를 거친다.

## 재측정(총괄 승인 뒤)

- 같은 1e-0 목록(2 세션 `delay` → `thread`, 등록 그대로)을 수정이 든 새 스냅숏으로 다시 낸다. 17525 의 두 세션은 쓰지 않는다. 분석기·결정 규칙은 결과 전에 고정된 그대로다.
- 대조(총괄 요청 ③): 같은 스냅숏·같은 스위치로 작업자 없는(`off`) 세션 하나를 목록 뒤에 더한다.
  - 판정에는 쓰지 않는다. 등록의 예측은 `delay` 와 `thread` 의 차로만 낸다.
  - 미션 결과, `evidence_stale`·`limit` 틱 수, 단계 시간이 수정 뒤 작업자 세션과 같은 수준인지 보는 행동 대조다. 1e-0 의 "메인 작업 증가"를 `off` 와 견주는 값도 보고만 한다.
  - 목록에 세 번째 항목이 들어가므로 분석기의 목록 검사(`delay`, `thread` 만 허용)를 결과 전에 고친다. 고치는 범위는 대조 행을 보고 항목으로 읽는 것뿐이다. 예측식과 결정 규칙은 그대로다.
- 보고 지표(총괄 요청 ④): 세션마다 단계별 `evidence_stale` 정지 틱 수(`slowed_reasons`)를 분석기 출력에 더한다. 비교 기록(0)에 견준다. 판정 규칙에는 넣지 않는다.
- 크기: 세션당 약 6 분, 3 세션 순차 단독, `--slots 1`·shard 4·CPU 4·8G·0:50.
