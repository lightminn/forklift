# 기본 속도 회귀 확인 — 추종기 허용치 변경 뒤

## 범위

2026-09-26 에 추종기에 넣은 종료 판정 변경(전환점 3 cm·0.05 rad, 목표 3 cm 지나침 허용, 관측·복귀
종점 3 cm, 공칭 시간 기반 단계 제한)은 8 km/h 설정만이 아니라 `run_transport.py` 의 기본 설정에도
들어갔다([2026-09-26 기록](2026-09-26-factory-hall-and-isaac-slam.md) 7a 절). 그 변경을 기본 설정으로
다시 돌려 확인하지 않은 채 PR #2 에 올렸으므로, 같은 조건의 이전 실행과 seed 별로 비교했다.

입력은 전부 `synthetic` 이고 정답 팔레트 좌표(인식 미사용)·정답 자세 제어다. 개발 확인용 seed
집합이며 성공률 평가가 아니다.

## v1 에서 드러난 회귀 — 복귀 3 cm

구역 seed 23 이 복귀 끝에서 `Tracking failed in return_home: pos=0.0300,yaw=-0.0407` 로 떨어졌다
(2026-09-23 에는 8.4 mm·0.0205 rad 로 완주). 추종기는 남은 거리가 위치 허용치 안에 들면 종점으로
판정하므로, 허용치 3 cm 는 **목표 3 cm 앞에서 멈춘다**는 뜻이 됐다. 방향이 수렴하기 전에 멈춰 0.03 rad
검사에 걸렸다. 완주한 seed 도 복귀 오차가 18.6–29.4 mm 로 커졌다(2026-09-23 은 3.4–8.4 mm).
2026-09-26 8 km/h 실행의 복귀 30 mm 도 같은 원인이다.

**수정.** 복귀의 위치 허용치만 8 mm 로 되돌렸다. 방향 0.03 rad(2026-09-23 규칙)과 관측의 3 cm 는
그대로다. 목표를 지나쳐 멈추는 교착은 3 cm 지나침 허용이 따로 막는다. AST 시험
`test_isaac_transport_planning_config.py` 를 같은 규칙으로 고쳤다.

## 8 km/h 설정 확인

v2 스냅숏으로 2026-09-26 의 인식 임무(`isaac_transport_fast.yaml`, `--layout factory --use-perception
--return-home --robot-camera --record-slam`) seed 16 을 다시 돌렸다(작업 281,
`artifacts/20260927_fast_mission_return_fix/`). 완주, 시뮬레이션 117.5 s(이전 118.2 s), 최고 2.23 m/s,
인식 위치 오차 2.0 mm, 하역 오차 8.1 mm(이전 12.9 mm), **복귀 8.8 mm·−0.0059 rad**(이전 29.9 mm·
−0.016 rad), 중첩 검사 1,464 회 위반 0.

## 메모리 초과

v1 구역 작업(16 GB, `--cpus-per-task=8` 기본 2,000 MB/CPU)에서 seed 3·14·18 이 exit 137 로 끝났다.
작업 cgroup `memory.events` 의 `oom_kill 3`, `sacct` 의 `OUT_OF_MEMORY`·MaxRSS 16,383,300 K 로 메모리
초과임을 확인했다. 32 GB 로 다시 낸 v2 는 같은 seed 가 모두 끝났고 MaxRSS 는 구역 6,418,412 K·공장
5,043,036 K 였다. v1 에서만 16 GB 를 넘은 이유는 규명하지 않았다. seed 24 의 첫 시도는 Isaac 시작 직후
segfault(exit 139)였고 v2 에서는 재현되지 않았다.
