# RGB-D 포켓 인식과 Isaac 정렬 접근 연결

## 범위

[현황 정본](../plans/2026-09-17-project-status-and-next-steps.md) **3순위**(이 문서를 쓸 당시의 `계획.md` 2순위)에 해당하는 연결 구현이다. main 은 같은 순위를 `run_transport.py --use-perception` 으로 따로 배선했고, 이 문서는 **병렬 갈래**의 기록이다. 과거 물리 100개·계획 1,000개
작업의 결과 집계는 사용자 요청에 따라 건너뛰었으며, 완료로 바꾸지 않았다.
물리 하드웨어 시험이나 연속 포켓 추적·삽입 검증은 이번 범위가 아니다.

## 구현과 정보 경계

- `rgbd_snapshot.py`: RGB와 float 광축 깊이(m)를 복사해 기존 `SceneInput`에
  전달한다. 정합·직선화·단위·좌표·시각을 명시적으로 검사한다.
- `observed_approach.py`: 기존 검출기의 `base_link` 포켓 관측을 정확히 같은
  촬영 시각의 로봇 변환으로 world 목표로 바꾼다. 포켓 전면과 팔레트 중심의
  차이를 EPAL 6 prior의 깊이로 계산한다. 미래·지연·clock 불일치·무효·미검출에는
  목표가 없다. `synthetic_ground_truth` 관측도 목표 입력으로 거부한다.
- `perception_camera.py`: 합성 고정 카메라 설정을 YAML에서 읽는다. 물리 시간을
  고정한 채 같은 render product의 RGB와 깊이를 읽고 촬영 전후 자세가 같은지
  확인한다. 재사용되는 SDK 버퍼를 복사하며 raw depth와 K·TF·시각을 보존한다.
- `run_perception_approach.py`: 공식 NVIDIA 창고/물품과 잠정 차체·EPAL 6을 새로
  배치한다. 기존 검출기와 prior 유도 파라미터, Hybrid A*, 기존 바퀴·조향 추종기를
  연결한다. 팔레트 정답은 검출·목표·경로 추종에 전달하지 않는다.
- `approach_evaluation.py`: 주행 종료 후에만 정답과 비교한다. 추정 목표에
  도착해도 실제 정렬·검출 오차 또는 팔레트 이동량 기준을 넘으면 실패다.

카메라는 `base_link`에서 (0.75, 0, 0.27) m, 전방을 보는 640×480 pinhole이며
fx=fy=465.741156 px다. 실물 D435i 보정이 아니다. 로봇 자기 위치와 장애물
지도에는 아직 시뮬레이터 값을 사용한다. 팔레트는 정지 상태라는 실험 가정이며,
접근 중 이동·관측 갱신은 다음 단계에서 다룬다.

## 로컬 검증

추가 시험은 입력 버퍼·단위·깊이 미지 값·좌표·시각 검사, 실제 EPAL 6 22-box
ray depth → 기존 검출 → world 목표 → Hybrid A* 통합, 미검출/무효의 목표 차단,
주행 오류 후 정지 및 정렬 평가를 포함한다. Ray depth는 양자화하지 않았다.
통합 양성은 지정한 두 자세의 결과이며 일반적인 인식 성공률로 해석하지 않는다.

`python -m pytest tests --ignore=tests/simulation -q -p no:cacheprovider -W error`:
**917 passed, 4 skipped, 82.57초**. 기존 778개 통과 기록 대비 새 시험은 139개다.
변경 Python 파일의 Ruff lint·format 검사와 `git diff --check`도 통과했다.
원본은 `artifacts/20260918_perception_approach/pytest_final.log`다.
최종 후보 한도 설정을 바꾼 뒤에는 해당 설정을 읽는 실제 깊이 회귀 2개를
다시 실행해 통과했다. 코어 검출기의 기본 설정은 바꾸지 않았다.

## 실행 기록

원본 로그와 시험 출력은 `artifacts/20260918_perception_approach/`에 모은다.
새 실행 환경의 첫 시도는 Python 환경에서 Isaac 모듈을 찾지 못해 주행 전에
종료했다. 설치된 Isaac 패키지를 사용하는 프로젝트 전용 Python 환경을 구성해
재시도했다. 기본 viewport 초기화가 지연되어 설치된 SDK의 초기화 코드와
traceback으로 대기 위치를 확인했다. CPU 스레드 수를 Slurm 할당량으로 제한하고,
`create_new_stage=False`·`disable_viewport_updates=True`로 실행한 뒤 장면을 직접
만들자 초기화를 통과했다. 최초 카메라 렌더 준비 뒤 관측이 취득됐고,
캐시가 있는 후속 관측 시험은 전체 약 20초에 완료됐다. 주행 판정은 아래의
별도 제어·정렬 평가 결과를 따른다.

첫 seed 0은 `no_opening_pattern`으로 주행하지 않았다. 같은 원본 깊이에서
거리 상한 {5, 6, 8} m × 후보 면 한도 {3, 6, 12}의 9개 조합을 모두 기록했다.
5 m에서는 3개가 미검출, 6·12개가 유효였고, 6 m에서도 같았다.
8 m에서는 3·6개가 미검출, 12개가 유효였다. 카메라 기준 5 m 범위에 팔레트가
있어 거리 완화는 필요하지 않았으며, 물품의 면들이 후보 예산을 소진한 것이
이 관측의 직접적인 제한이었다. 5 m·6개에서 팔레트 면 inlier 803개,
포켓 지지 최소 73개, 하부판 41개, 좌우 상부판 114/111개를 확인했다.

첫 수정에서는 후보 한도 6개만 지정했다. 검출기
알고리즘·형상 증거 문턱·거리 범위는 바꾸지 않았다. 이 원본은 개발에 사용한
회귀 사례이며 독립적인 성공률 평가 세트가 아니다. 숨긴 팔레트의 별도 실제
렌더도 취득했으며, 원래 설정은 미검출·6개 설정 재생은 `no_upper_deck` 무효로
거부했다. 둘 다 목표가 없으며 원래 설정의 실제 정지 속도는 0.0001071 m/s였다.

## 실제 카메라 기반 주행

동일 seed 0에 후보 한도 6개를 적용한 새 실행은 `success: true`, `status: aligned`로
완료됐다. 목표 생성과 바퀴 주행에 팔레트 정답을 전달하지 않았고, 종료 후
별도 평가에서도 통과했다.

| 측정 | seed 0 |
|---|---:|
| 접근 및 정지 시뮬레이션 시간 | 14.950초 |
| 검출 팔레트 중심 오차 | 2.733 mm |
| 검출 yaw 오차 | 0.00005993 rad |
| 실제 팔레트 기준 후륜축 정렬 오차 | 9.673 mm |
| 실제 팔레트 기준 차체 yaw 오차 | 0.005564 rad |
| 추정 목표 기준 추종 위치 오차 | 7.588 mm |
| 정지 확인 속도 | 0.0003763 m/s |
| 팔레트 평면 이동량 | 0.0000000855 m |

원본 `seed0_final/result.json`, `stop.json`, `tracking.json`과 관측 RGB·깊이·메타데이터를
보존했다. `seed0_final/approach.mp4`는 ffprobe로 1280×720, 60/1 fps,
837프레임, 13.95초를 확인했다. 마지막 1초의 정지 확인은 영상 이후 수행하며
`stop.json`과 `aligned.png`에 남는다. 실제 팔레트와의 정렬 평가 한도는 위치
40 mm·yaw 0.03 rad, 검출 한도는 중심 30 mm·yaw 0.02 rad, 팔레트 이동 한도는
18 mm다. 실물 안전 허용오차나 포켓 삽입 허용오차가 아닌 합성 접근 시험 기준이다.

같은 코드·설정으로 정한 추가 사례를 모두 실행했다.

| 사례 | 관측 | 실행 결과 |
|---|---|---|
| seed 0 | valid | 카메라 추정 목표 접근 및 정렬 평가 통과 |
| seed 17 | no_pallet / no_opening_pattern | 주행 명령 없이 정지 |
| seed 42 | no_pallet / no_opening_pattern | 주행 명령 없이 정지 |
| seed 0 팔레트 숨김 | invalid / no_upper_deck | 주행 명령 없이 정지 |

마지막 세 사례의 측정 속도는 모두 0.0001071 m/s이며 `success: false`,
`status: stopped_no_target`다. 안전 정지를 운반·접근 성공으로 세지 않는다.
seed 17·42의 RGB에는 팔레트가 보이므로 미검출을 단순 가림으로 설명하지 않는다.
검출 안정성은 남은 제한이다. 성공한 seed만 골라 전체 결과로 제시하지 않으며,
이 작은 개발 확인 세트에서 일반적인 성공률을 주장하지 않는다.

실행의 소스 SHA-256 28개와 설정·prior·모델 SHA-256 6개를 당시 작업 파일과
대조해 일치를 확인했다. 코드 검토에서 발견한 오류 후 정지 확인 누락과
추정 목표 도착만으로 성공 판정하던 문제는 회귀 시험과 종료 후 평가로 보완했다.
다음 단계는 연속 관측에 따른 근접 포켓 추적·관측 소실 대응·삽입 제어다.

## 추가 미검출 원인과 최종 검색 설정

seed 17·42·숨김 관측을 후보 한도 6·12개로 모두 재생했다. seed 17은
12개에서 유효 관측으로 바뀌었고, 숨김은 두 설정 모두 `no_upper_deck`으로
거부됐다. seed 42는 두 설정 모두 미검출이었다. 실제 팔레트 면이 다섯 번째
후보로 포함됐지만, 하부판 증거가 **9개로 기준 15개 미만**이었다. 지지점
78/128/88개와 상부판 271개가 있어도 하부판 조건을 생략하지 않았다.

최종 `config/isaac_perception_detector.yaml`은 검색 후보 한도 **12개**다.
형상 증거 문턱·거리 범위는 유지한다. 최종 설정의 실제 실행 결과는 아래에
별도로 남겨 6개 설정의 실행과 구분한다. 재생 원본과 진단은
`final_candidate_diagnostic/results.json`·`seed42_planes.json`에 보존했다.

최종 12개 설정으로 seed 0·17·42와 숨김을 모두 새 프로세스에서 실행했다.

| 사례 | 결과 | 실제 정렬 위치 오차 | 접근·정지 시간 |
|---|---|---:|---:|
| seed 0 | aligned | 9.673 mm | 14.950초 |
| seed 17 | aligned | 9.521 mm | 14.808초 |
| seed 42 | no_opening_pattern, 주행 없이 정지 | — | — |
| 숨김 첫 실행 | 촬영 전 `Snapshot acquisition requires stopped translation`으로 중단 | — | — |
| 숨김 동일 조건 재실행 | invalid / no_upper_deck, 주행 없이 정지 | — | — |

숨김 첫 실행은 실제 검출기까지 도달하지 못한 초기 정지 조건 실패이며,
관측 거부 시험 통과로 세지 않는다. 원본을 `final_hidden/`에 보존하고 동일
조건의 새 프로세스로 재확인했다. 정지 확인 기준을 낮추거나 무시하지 않았다.
seed 17의 검출 중심 오차는 3.577 mm, 실제 차체 yaw 오차는 0.011237 rad,
최종 속도는 0.0002929 m/s였다. 최종 양성 실행 원본은 `final_seed0/`,
`final_seed17/`이며 미검출 원본은 `final_seed42/`다.

숨김 재실행은 `final_hidden_repeat/`에 보존했다. 측정 속도 0.0001071 m/s,
`wheel_motion_commanded: false`로 관측 거부 후 정지를 확인했다. 초기 물리
정지 조건이 한 번 실패한 원인은 확정하지 않았으며, 재실행 성공으로 그 기록을
제외하지 않는다. 향후 고정 2초 준비 구간의 반복성을 확인하고 필요하면 한도가
있는 정지 대기로 개선한다. 최종 다섯 실행의 소스·설정·모델 해시가 모두 현재
파일과 일치하며, 전체 결과 요약은 `summary.json`이다.
