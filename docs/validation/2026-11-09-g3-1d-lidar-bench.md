## 읽기(Codex 교차검증 반영)

- **등록 문턱 통과(점추정).** 16 자세 모두 중앙값 차가 1 ms 를 넘는다. 그래서 B 는 채택 조건을 채운다.
  - 다만 line_m 의 최소 여유는 0.088 ms 다. JSON 이 반복별 원시 시간을 남기지 않아 차이의 신뢰구간은 복원하지 못한다. 반복 실행에서의 재현성은 미확인이다.
- **own 캐시.** 캐시는 맞은 광선마다 True·False 를 모두 저장하므로, own=0 이어도 선반·벽의 문자열 판정을 재사용한다. 다음 두 항목은 확인하지 못했다:
  - 실제 PhysX 에서 own=True 가 되는 분기와 적재 상태 전환.
  - 캐시 자체의 기여량. B 는 여러 정리를 묶었기 때문이다.
- 합성 시험(`test_lidar_fast.py`)은 자기 몸·접두사 변화·공유 캐시를 다룬다.
- **라이브 절감은 따로 잰다.** 측정 실행의 M4(계측 경로, 세션 표본 평균, 변환 1.9 ms)는 이 벤치(비계측 경로, 자세별 중앙값)와 모집단·통계량·경로가 다르다. 1.9 ms 를 추가 절감 가능분으로 더하지 않는다. B 도 스캔마다 `tolist()`, 광선마다 `Float3` 를 만든다.
- **예산.** 10 Hz 에서 B 의 환산은 line_m −11.5, hall −12.8 ms/sim s 다. 이것은 지금 B 에서 기대할 1 차 예산이지 상한이 아니다. 일괄 API 가 없다는 것이 질의 비용이 줄지 않는다는 증명은 아니다.
- **G3 목표와의 차.** 기존 단계 목표(1b −25~35, 1c −25~30)에 line_m 의 −11.5 를 더하면 −61.5~−76.5 ms/sim s 다. 목표 −100 에 23.5–38.5 가 모자란다. 1b·1c 의 목표를 키우거나 G3-1e(작업자화)를 계획해야 한다.
