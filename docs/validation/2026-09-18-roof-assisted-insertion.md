# 윗판 깊이 추적을 이용한 실제 포크 삽입

## 범위

기존 카메라를 유지하고, 알려진 빈 EPAL 6의 현재 윗판 깊이로 포켓 위치를
계속 추정하는 방법을 구현했다. 앞면 포켓이 보이지 않는 구간은 **모델 기반
위치 추정**이며 포켓 내부의 직접 관측이 아니다. 기존 접근·소실 시험은
[이전 기록](2026-09-18-pocket-tracking-insertion.md)에 보존한다.

차체·센서 보정·팔레트는 합성 모델이다. 로봇 자기 위치와 공장 물품의 장애물
지도는 아직 시뮬레이터 입력이다. 팔레트 정답은 배치, 독립적 접촉 중단 검사와
기록 후 오차 평가에만 사용한다. 목표는 최초 카메라 인식으로 정하며, 주행 중
관측을 잃은 뒤 정답이나 마지막 좌표로 계속 움직이지 않는다.

## 관측과 인계

- `roof_tracking.py`는 현재 깊이에서 수평 윗판 높이, 뒤쪽 모서리와 판재 사이
  홈을 측정한다. 뒤쪽 모서리는 거리, 종방향 홈은 방향과 좌우 위치를 정한다.
  포켓 위치·크기는 알려진 강체 형상에서 유도한다.
- 예상 위치는 검색 범위와 홈 대응에만 쓴다. 깊이가 없거나 뒤쪽 모서리·홈의
  증거가 부족하면 무효 관측이다. 바닥, 단순 판재, 다른 판재 배열, 뒤쪽을
  가리는 전경 물체와 unknown 깊이 조건도 시험했다.
- 멀리 있는 모서리는 한 픽셀이 수 cm를 차지할 수 있다. 인접 픽셀 광선으로
  가능한 경계 구간을 구하고, 구간까지 거리의 제곱합을 최소화한다. 구간 밖
  잔차 RMS가 3mm를 넘으면 거부한다. 원래 잔차와 픽셀 구간 폭도 기록한다.
- 앞면 1.4m 이내에서 직접 포켓 관측과 윗판 추정이 연속 3회 일치해야 인계한다.
  좌우 포켓 **각각**의 중심 차이 25mm, 방향 차이 0.03rad, 구멍 폭·높이 차이
  20mm 이내여야 한다. 중앙점만 비교해 대칭 오차를 놓치는 경우를 리뷰에서
  발견해 수정하고 회귀시험을 추가했다.
- 인계 이후 `roof_model` 관측이 소실되면 0 명령을 내리고 해당 시도를 종료한다.
  직접 포켓 검출이나 이전 위치로 조용히 되돌아가지 않는다. 최초 카메라 대상과
  world 위치 30mm·방향 0.03rad 대응 검사, 신선도 검사와 기존 정지 경로도 유지한다.

일반 접근 0.60m/s, 팔레트 앞면 1.35m부터 삽입 속도 0.055m/s를 요청한다.
물리 120Hz, 관측 10Hz, 영상은 시뮬레이션 시각 기준 60fps다. 렌더·인식 중에는
물리를 고정하므로 실시간 처리율이나 실제 장치의 지연 성능을 뜻하지 않는다.

## 사전 진단과 회귀

- 초기 프로토타입: 차체 가림을 포함한 합성 54개 위치·방향 조건 모두 유효.
  전체 최대 포켓 오차 10.53mm, 완전 삽입 위치에서는 최대 0.427mm였다.
- 새 Isaac 정적 캡처 6개도 유효했다. 이 진단에서만 차량 자세를 직접 배치했다.
  정적 파일에는 실제 팔레트 TF가 빠져 있어 명목 배치와의 비교로만 기록한다.
  실제 주행 평가는 각 프레임의 팔레트 정답 TF를 별도로 기록해 비교한다.
- 최종 코어는 기존 주행 깊이 37프레임과 새 정적 캡처 6개를 모두 처리했다.
  이 입력들은 개발·회귀 자료이며 독립 시험 세트로 보지 않는다.
- 집중 시험: 코어 26개, 인계·실행기 39개 통과. 독립 코드 리뷰 지적을 수정하고
  인계 및 픽셀 구간 적합 변경을 재검토했다.
- 전체: `python -m pytest tests --ignore=tests/simulation -q -p no:cacheprovider -W error`
  **1,097 passed, 4 skipped**. 변경 Python 6개 Ruff 검사·형식 검사와
  `examples/sensor_geometry.py`도 통과했다.

## 최종 실제 바퀴 주행

최종 실행은 동일한 코드의 `roof_tracking_v2_positive`, `roof_tracking_v2_loss`,
`roof_tracking_v2_seed17`이다. 각 실행의 소스·모델·설정 40개 SHA-256이 로컬
최종 파일과 모두 일치했다. Slurm 작업 종료뿐 아니라 `result.json`, 정지 속도,
실제 팔레트 자세와 3차원 접촉 중단 검사 결과를 확인했다.

삽입 성공이 아니므로 `success:false`를 유지한다. 두 배치는 대규모 성공률을
뜻하지 않는다. 들어 올리기·운반·하역은 이번 실행에 포함되지 않았다.

## 관측 오차와 합성 통과 간격 비교

실제 기록한 팔레트 TF로 평가한 포크 진입 구간의 최대 포켓 위치 오차는
seed 0/17에서 6.633/8.242mm였다. 주성분은 앞뒤 방향이며, 최대 좌우 오차는
0.238/0.245mm, 높이 오차는 모두 0.390mm, yaw 오차는 0.001212/0.001217rad다.
이는 관측 오차이며 위 표의 실제 최종 차량 정렬 오차와 구분한다.

중립 승강 위치·정렬된 모델의 명목 여유는 개구 높이 범위 아래 6mm/위 48mm,
안쪽 옆면 45mm/바깥쪽 옆면 127.5mm다. seed 0의 기록된 차량·팔레트 3차원
자세와 **승강 0 가정**을 적용하면 포크 진입 81프레임에서 보수적인 전체 블레이드
모서리 기준 아래 5.993mm/위 48.006mm/안쪽 41.865mm/바깥쪽 124.365mm였다.
아래 6mm는 인식에서 사용하는 z=0.022m 개구 범위까지의 여유다. 포켓 아래는
바닥으로 열려 있으므로 실제 하부 판재와의 거리라고 부르지 않는다.

실제 승강 관절값은 이 로그에 저장되지 않아 위 수치를 실측 최소 간격으로
해석할 수 없다. 별도의 실행 중 120Hz 접촉 중단 검사는 **그때 측정한 승강값**과
실제 3차원 자세를 사용했고 세 실행에서 중단이나 최종 접촉 후보가 없었다.
기하 검사·조건부 여유 비교·적은 수의 관측 오차 표본만으로 실물 안전이나
가려진 장애물에 대한 보장을 주장하지 않는다.

## 한계

이 기능은 알려진 빈 강체 팔레트의 수평 윗판과 기존 전방 카메라 방향을 전제로
한다. 적재물이 윗판을 가리거나 팔레트가 변형된 경우, 화각 밖 포켓에 새로운
장애물이 들어간 경우의 통과 간격을 직접 확인하지 못한다. 앞면 검출의 선반
유사 형상 오인식 한계도 남아 있다. 출력 sigma는 픽셀 해상도와 잔차에 근거한
측정 불확실성 지표이며 보정된 통계적 보장이나 충돌 안전 증명이 아니다.

실물 D435i·차체 교정과 제동 검증, LiDAR 지도·위치 추정 연결, 카메라 기반
삽입 후 승강·운반·하역의 통합 검증은 별도 단계다. 기존 정답 기반 운반 데모의
성공을 이 새 인식 경로의 적재·운반 성공으로 간주하지 않는다.
