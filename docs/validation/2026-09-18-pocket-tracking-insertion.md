# 연속 포켓 관측·접근과 관측 소실 정지

> 후속: 같은 날 [윗판 깊이 추적을 이용한 삽입](2026-09-18-roof-assisted-insertion.md)을
> 구현했다. 이 문서는 앞면 관측만 사용했던 이전 실행의 결과와 한계를 보존한다.

## 범위와 완료 경계

계획서 3순위의 연속 관측 제어와 정지 경로를 구현했다. **전체 삽입 완료는
아직 확인하지 못했다.** 현재 카메라는 가까워질 때 필요한 하부판 증거를 잃고,
삽입 끝에서는 카메라가 팔레트 앞면보다 전방에 놓인다. 관측을 잃은 뒤 목표
좌표만 유지해서 삽입을 끝내는 방식은 사용하지 않는다.

모든 실행은 합성 카메라·잠정 차체·EPAL 6 모델과 공식 NVIDIA 창고 물품을
사용했다. 로봇 위치와 장애물 지도는 시뮬레이터 입력이다. 팔레트 정답은
장면 배치, 독립적인 3차원 접촉 중단 검사, 종료 후 평가에만 사용한다.
실물 D435i 보정·제동 성능·충돌 안전 검증이 아니다.

## 구현

- `acquire_frozen_snapshot`: 차량이 움직이는 순간에도 물리 시각을 고정하고
  RGB-D·K·TF를 함께 얻는다. 렌더와 각 getter 뒤에 시각·자세 불변을 확인한다.
  기존 정지 차량용 API는 정지 조건을 유지한다.
- `PocketInsertionController`: 연속된 새 관측 3개와 실제 정지를 확인한 뒤
  움직인다. 시각·clock·출처·좌우 대응·상대 위치·방향·형상 변화·포크의 명목
  통과 간격을 검사한다. 누락·지연·급변·과속은 즉시 0 명령이다.
- `run_pocket_insertion.py`: 기존 인식과 Hybrid A*로 조금 먼 관측 인계 지점까지
  접근한 뒤 10Hz 관측 제어를 수행한다. 원시 깊이와 시각·변환·제어를 저장한다.
  최초 카메라 추정 물체와 현재 관측의 world 앞면 중심 차이 30mm·yaw 차이
  0.03rad를 넘으면 대응 실패다. 이는 다른 물체로 전환되는 것을 막는 검사이며
  팔레트/선반의 의미적 구분을 해결하는 것은 아니다.
- 120Hz 제어 사이에도 150ms 관측 만료를 검사한다. core는 정지 후 연속 관측
  재확인을 지원하지만, 이번 실행기는 첫 소실을 기록하고 해당 시도를 정지한다.
- 인식 예외에도 0 바퀴 명령 → 1초 물리 진행 → 병진·각속도 측정을 수행한다.
  둘 다 0.012 미만이어야 정지로 기록한다. 옆으로 미끄러지거나 회전하는 상태를
  정지로 취급하지 않는 회귀시험도 추가했다.

물리는 120Hz, 녹화는 시뮬레이션 시각 기준 60fps다. 인식·렌더 계산 중에는
물리를 멈추므로 실시간 처리율 60Hz 또는 실물 제어 지연 성능을 뜻하지 않는다.

## 근접 카메라 조사와 검출 한계

정적인 진단용 자세 배치와 실제 바퀴 주행을 구분해 기록했다.
`artifacts/20260918_pocket_tracking/isaac_probe1/`은 카메라 4개 위치 × 앞면 거리
1.05/0.82/0.59m의 12개 실제 Isaac 렌더이며 전부 유효 검출을 얻지 못했다.
이 진단에서만 차량 자세를 직접 배치했다. 주행 실행기는 바퀴·조향 명령만 쓴다.
로컬 ray 진단도 중립 차체/캐리지 box 가림을 넣은 54개 관측이 모두 실패했다.
측면 배치 4개는 1.05m에서 검출됐지만 0.82/0.59m에서는 실패했다. 바퀴·원통
형상과 실물 광학은 ray 조사에 포함되지 않았으며 가능한 모든 배치를 배제한
조사가 아니다. 원본은 `artifacts/20260918T_near_camera_probe/`에 있다.

기존 카메라의 실제 1.7/1.5/1.3m 관측에서는 다른 문제도 발견했다. RANSAC 면의
평균 위치가 주변 판재 반환점 때문에 0.132/0.186/약 0.222mm 뒤로 치우쳤고,
`depth >= 0` 하부판 조건이 같은 앞면의 반환점을 모두 제외했다. 면 방향을
유지하고 위치만 중앙값으로 구하면 세 관측의 하부 증거가 195/402/568개로
복구됐다. 1.2m에서는 증거 자체가 화각 밖이라 복구되지 않았다.

`median_plane_offset=True`는 **최초 인식한 대상과 대응되는 근접 추적에서만**
사용한다. 기본값 False는 기존 인식 동작을 유지한다. 하부판 증거 문턱이나
앞쪽 점을 배제하는 조건은 완화하지 않았다. 별도 형상 진단에서는 이 보정이
바닥까지 이어진 기둥/선반도 통과시키므로, 이를 보편적인 인식 개선이나
하부판 실재 증명으로 해석하지 않는다. 그 한계를 명시한 시험도 보존했다.
새 실제 깊이 fixture는 개발에 사용한 회귀 입력이지 독립 평가 데이터가 아니다.

## 0.04m/s 기준 실제 주행

`tracking_v3_natural`과 `tracking_v3_loss`는 같은 코드/배치에서 실제 바퀴로
움직인 결과다. `success:false`는 삽입 미완료이며 의도한 정지와 구분한다.

|---|---:|---:|
| 유효 관측/전체 관측 | 124/134 | 22/32 |
| 첫 소실 시각, 추적 시작 기준 | 12.400s | 2.200s |
| 소실 직전 실제 속도 | 0.04001m/s | 0.04029m/s |
| 소실 후 최종 위치까지 이동 | 0.431mm | 0.707mm |
| 최종 병진 속도 | 0.000221m/s | 0.000177m/s |
| 최종 각속도 | 0.000242rad/s | 0.000836rad/s |

추적 영상은 1280×720, 60fps, 804프레임, 13.4초다. 후속 1초 정지 검증은
`pocket_braking.json`에 별도로 남긴다. 원본 실패 실행 v1/v2도 보존했다.

## 사용자 요청에 따른 0.6m/s 설정

일반 접근과 근접 제어의 비삽입 구간 목표를 0.60m/s로 변경했다. 근접 제어의
가속 한도는 0.60m/s², 앞면 거리 1.35m부터 목표는 0.055m/s다. 포크 끝의
base x=0.95m보다 0.40m 앞에서 감속을 요청한다. 관측 소실에는 가속 제한을
적용하지 않고 즉시 0을 명령한다. 10Hz에서 0.6m/s 이동은 프레임당 약 60mm이므로
관측의 로봇 기준 이동 허용 한도는 90mm로 설정하며, world 대상 대응 30mm
조건을 함께 유지한다. 설정값을 실측 속도로 보고하지 않고 실행 로그로
별도 확인한다.

## 0.6m/s 설정의 실제 결과

최종 `tracking_fast_v1_natural`·`tracking_fast_v1_loss` 실행은 소스·설정·모델
SHA-256 **각 37개가 현재 파일과 모두 일치**한다. 두 시도 모두 전체 삽입
성공은 False, 관측 소실 정지는 확인됐다.

| 측정 | 자연 관측 소실 | 주행 1초 뒤 깊이 소실 주입 |
|---|---:|---:|
| 일반 접근 최고 실측 속도 | 0.60208m/s | 0.60208m/s |
| 연속 관측 접근 최고 실측 속도 | 0.59778m/s | 0.59419m/s |
| 유효 관측/전체 관측 | 27/37 | 12/22 |
| 첫 소실 시각, 추적 시작 기준 | 2.700s | 1.200s |
| 소실 직전 실제 속도 | 0.05512m/s | 0.59419m/s |
| 소실 후 최종 위치까지 이동 | 0.735mm | 58.571mm |
| 최종 병진 속도 | 0.000158m/s | 0.000286m/s |
| 최종 각속도 | 0.000850rad/s | 0.000309rad/s |

자연 소실 시도에서는 속도가 올라간 뒤 설정한 거리에서 감속하고 나서 관측을
잃었다. 주입 시도는 감속 전 약 0.6m/s에서 관측을 끊어 빠른 주행 중 정지를
검사했다. 제동 거리에는 시뮬레이터의 명목 구동기·마찰·고정된 관측 처리 시각이
적용되므로 실물 제동 거리로 쓰지 않는다. 최고 속도는 로그 표본의 최대값이며
전체 경로의 평균 속도가 아니다.

명목 형상에서 포크 끝 x=0.95m이고 최종 앞면은 각각 1.2176/1.3499m였으므로
두 정지는 포크 진입 전이다. 따라서 포켓 내부의 수직 여유·관측 오차·제동 거리
수용 여부 또는 실제 삽입 비접촉 성공을 확인한 결과로 해석하지 않는다.

영상 `artifacts/20260918_pocket_tracking/approach_tracking_0p6mps.mp4`는 자연 소실
시도의 `approach.mp4`와 `pocket_tracking.mp4`를 순서대로 연결한 것이다.
1280×720, **60fps, 1124프레임, 18.733초**이며 시간 배속을 적용하지 않았다.
초기 인식/계획 대기와 접근 후 1초 정지 확인은 주행 녹화 구간 밖이다.
별도 주입 영상과 원본 결과는 같은 artifact 디렉터리에 보존했다.

## 검증과 남은 일

- 최종 전체 회귀: **1058 통과, 4 건너뜀**, 85.49초. 명령은
  `python -m pytest tests --ignore=tests/simulation -q -p no:cacheprovider -W error`.
- 변경 Python 9개에 대한 Ruff lint/format 검사 통과.
- 관측 누락·지연·대상 전환·watchdog·옆미끄럼·회전·인식 예외·제동 실패 및
  0.6→0.055m/s 속도 전환을 회귀시험했다. 빠른 명령의 가속 제한과 소실 순간
  즉시 0 명령을 실제 core/구동 변환을 사용하는 SDK 경계 시험에서 확인했다.
- 첫 리뷰에서 watchdog 후 즉시 재출발과 회전/옆미끄럼을 정지로 취급하는
  문제를 찾아 수정했고 추가 시험 및 재리뷰를 통과했다.
- 실제 장착 가능한 근접 관측 배치, 유사 형상 구분, 삽입 끝까지 관측 유지,
  포켓 내부 정지·간격 검증이 남아 있다. 이 단계의 완료 표시를 하지 않았다.
