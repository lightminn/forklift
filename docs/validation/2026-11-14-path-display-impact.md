# 계획 경로 표시선 누출 — 최근 결론의 영향 조사 (기록만, 2026-11-14)

- 결함: 계획 경로 표시선과 목적지 고리가 렌더되는 장면 prim 이라 인식 카메라에 찍혔다(#509 3 절). 수정 계획은 `docs/plans/2026-11-14-path-display-perception-leak.md`(#510)이고, 구현은 별도 PR 이다.
- 배정(총괄, 2026-11-14): 수정과 나란히 기록만으로 조사한다.
  - 대상: K1 승격, 층 예산 58 회와 진단, 곡률 규칙. 텔레옵·SLAM 은 해당 여부만 본다.
  - 영향 가능 / 없음 / 재확인 필요로 나누고 규모를 적는다.
  - K1 효과의 방향은 따로 적는다.
  - 우선순위는 팔레트 인식 지표로 정한다: 원거리 인식률, 근접 캡처 채택, 오검출.
- 새 Isaac 실행은 하지 않았다. 근거는 이미 있는 실행뿐이다. #509 의 재실행 19041 과 표시 끔 진단 19043(aisle_rack s0·s1 × B0·R, 진단 스냅숏 `pdoff_27daf0b0`), 그리고 각 결과 문서의 축약본이다.

- 표시를 끈 R 은 s0 이 운반에서 실패했고(cusp 의 endpoint_heading) s1 은 완주했다. 근접 캡처 실패가 표시선만의 탓인지는 정해지지 않았다(#509 3 절).

## 2. 단계별 노출(기전과 근거의 수준)

|---|---|---|---|
| 원거리 인식(첫 팔레트) | 관측 단계의 첫 경로는 그리지 않는다. 관측 중 재계획한 경로(`Observe`)만 코어가 그린다 | depth 0/4 바뀜(aisle_rack 두 seed, 결정 모드 oracle 제안) | 측정한 범위(aisle_rack 두 seed의 depth·추정)에서는 변화 없음. 학습 제안기 인식률의 근거는 아니다 |
| 원거리 인식(연속 이송의 다음 팔레트) | 앞 사이클의 운반·복귀 경로와 목적지 고리가 남아 있다 | 없음 | 재확인 필요 |

### 3.1 K1 의 효과 방향

- K1 이 바꾼 것은 근거리 관측 다리의 도착 범위다. 기하 조건이고 인식과 무관하다. 그래서 안전(항목 1)과 시간(항목 5)의 판정은 표시선과 상관없다.
- 인식에 걸린 항목은 셋이다: 근접 거부·오프셋(항목 3), 완주(항목 2, 특히 random_1 s19), 개입 6 사건의 "캡처 채택".
  - 두 팔 모두 근접 캡처 채택은 38/38, 거부는 0·0 이었다.
  - 개입 6 사건도 모두 채택됐다.
- 방향: **미확정이다.**
  - K1 은 트럭을 접근 경로 위로 더 바로 세운다. 정지 횡 오차가 B0 의 38–54 mm 에서 도착 오차 약 28 mm 로 줄었다. 그래서 근접 캡처 때 접근 경로선이 놓이는 자리가 두 팔에서 다르다.
  - 1 절의 접근선 영향(추정 오차 0.4–1 mm)은 aisle_rack B0 두 실행에서 잰 값이다. K1 항목 3 은 random_1 30 seed 의 횡 오프셋 분류이고, 선의 위치·영상 기하가 다르다. 그래서 이 값을 K1 실행에 그대로 옮길 근거는 없다.
  - 경계 사례가 있다. B0 의 0.08 초과 4 건은 문턱 바로 위이고(K1 문서 2 절), 그중 random_1 s19 는 문턱을 0.091 mm 넘었다. 1 mm 안팎의 영향만으로도 이 건의 분류가 바뀔 수 있다. 그 경우 항목 3 은 노출 부족(B0 < 4)이 된다.
  - 그래서 K1 결론이 표시선 때문에 생겼다는 근거도, 그렇지 않다는 근거도 없다. 등록 기준에 따른 "승격 검토 대상" 판정을 지금 뒤집을 근거는 없지만, 재확인이 필요하다.
- 재확인 방법은 총괄이 정한다(2026-11-14). 같은 80 실행 목록을 수정 뒤 스냅숏으로 다시 돌리면 약 2.0 h 다. 또는 수정 뒤 첫 기준선 비교에 K1 기본값을 넣어 함께 본다.
- 참고: aisle_rack 의 `no_expected_candidate` 근접 캡처 실패가 여러 배치에 되풀이된다. K1·① 의 aisle_rack s2(두 팔), 층 예산 58 회의 Bb10 aisle_rack s2, 진단의 B0 aisle_rack s11 이다. 표시선 몫인지는 모른다. 수정 smoke 에서 aisle_rack s2 B0 를 관측 실행으로 한 번 돌린다.

## 4. 팔레트 인식 지표 기준 우선순위

1. **근접 캡처 채택**: 측정된 영향이 있다(depth 4/4, 거부 2 건이 표시 끔에서 채택). 수정 뒤 새 기준선에서 가장 먼저 다시 잰다. 근접 추적(삽입 중 프레임)도 같은 묶음으로 본다.
2. **원거리 인식률**: 첫 팔레트는 측정된 변화가 없다(0/4). 연속 이송의 다음 팔레트는 앞 사이클의 선과 고리가 남아 있어 재확인이 필요하다. 연속 이송 기준선에서 본다.
3. **오검출**: Isaac 음성 집단과 학습 데이터 렌더에는 해당이 없다. 미션 중 학습 제안기의 오검출은 비결정 실행에서만 해당하고, 측정이 없다.

## 5. 이 조사의 한계

- 측정은 aisle_rack 두 seed × 두 팔의 표시 끔 진단뿐이다. 다른 장면·단계의 영향은 기전으로만 추정했다.
- 연속 이송의 다음 팔레트, 근접 추적 프레임, 학습 제안기는 측정이 없다.
- 결정 모드 배치는 학습 제안기를 oracle 로 바꾸므로, 이 배치들의 원거리 인식률은 RGB 표시선에 대한 근거가 되지 않는다.
- 이 문서는 Codex 적대적 검토를 거쳤다(P2 3 건·P3 2 건 반영: ① 판정 유지와 원인 무관성의 구분, K1 경계 사례로 방향 미확정, 층 예산의 판정 질문과 인식 실패 실행의 분리, 원거리·학습 제안기 표현의 범위 한정).
- **수정 전·후 Isaac 결과는 섞지 않는다(총괄 결정).** 위 분류는 수정 전 결과를 그대로 쓸 수 있는지에 대한 판단이다. 수정 뒤 비교는 새 기준선에서 시작한다.
