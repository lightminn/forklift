## 7. 총괄 결정 (2026-11-08)

결정 초안을 Codex 가 반박 검토했고(P2 2: 결정 1 의 근거가 판정 원천을 사후에 바꿔 읽음, 결정 3 의 '충돌 없이 충족'이 3.2 문구와 맞지 않음), 총괄이 두 지적을 받아들여 아래로 고쳤다.

1. **페이스 — 보류.** 등록 판정(전 구간)은 판정 불가이고, 민감도(300 s 이하)는 B 악화(stall A 3, B 5)다. 이 불확실성에서 총괄이 보수적으로 보류를 결정했다. 전 구간이 판정 불가인 것은 A 의 random_m 두 세션이 3.4 겹침 확인에 떨어졌기 때문이다. 관측되지 않은 A 의 뒤쪽 구간에 따라 전 구간의 A/B 관계는 반대일 수도 있다. 공통 기준 미통과라 ②④⑤ 모두 이번에 라이브 승격하지 않는다. 각 기능이 개별적으로 악화시켰다는 뜻은 아니다. 3.4 절의 stall 분해는 사후 분석이라 판정을 바꾸는 근거로 쓰지 않고, 다음 배치의 가설로만 둔다. 결과는 '목표 0.3, 실측 0.279–0.284' 조건에서만 유효하다. 이 자료는 0.4 를 지지하지 않으며, 0.4/0.3 최종 결정은 VM 이 돌아온 뒤에 한다.
2. **생명주기 1 — 판정 불가.** 통과로 세지 않는다. 원인은 래퍼가 런처를 TERM 해 epoch `result.json` 과 틱 기록이 사라진 하네스 결함이다. 임무 done 과 임무 기록의 금지 접촉 0 은 보조 사실이다. 탐침 STOP 송신 → 확인 지연은 미측정이다.
3. **② 최소 유효 발화 — 미충족.** 등록 3.2 대로 최소 유효 발화는 오탐이 아닌 감시 정지로만 채우며, 정지 0 건이라 ② 는 재현 불가 보류다. 384 틱 상한은 3.3 '상한 1 회'를 채운 보조 사실이다. 정지 → 수동 회복은 미확인, 적재 정지는 `loaded_hold` 운용 공백이다.
