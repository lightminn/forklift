# G3 1b·1c·1d 운용 기본 켬 (2026-11-10, 총괄 결정 — 머지는 ④⑤ rv3 배치 뒤)

- 결정: 1b·1c·1d 단계 확인과 1e 판정 실행(`2026-11-10-g3-1e-run-results.md`, 셋 끔 대비 절감 62.0·63.9·62.8 ms/sim s, 미션·안전 열화 없음) 뒤 총괄이 운용 기본 켬을 승격했다. 머지는 ④⑤ rv3 배치가 끝난 뒤다.
- 대상 스위치:

| 단계 | 스위치 | 바뀌는 것 |
|---|---|---|
| 1b | `FORKLIFT_GRID_CLEAR_KERNEL=1` | 격자 해제 묶음 `_clear_group` 를 광선 셀만으로 판정(`obstacle_grid.py`) |
| 1c | `FORKLIFT_SHADOW_KERNEL=1` | 그림자 적용의 배열 경로(`shadow_memory.py`, `kernels.mode() != "reference"` 일 때만) |
| 1d | `--lidar-cast fast` | LiDAR 광선 루프의 바인딩·변환 정리와 몸체별 자기 판정 캐시(`planar_lidar.py`) |

## 적용 범위

- **콘솔 live 런처(`deploy/console/isaac_live.sbatch`)만 기본 켬이다.**
  - 기본값 `FORKLIFT_GRID_CLEAR_KERNEL=1`, `FORKLIFT_SHADOW_KERNEL=1`, `LIDAR_CAST=fast` 이다. 명시한 값(0/1, loop/fast/oracle)이 이긴다. 측정 목록의 명시 0 은 0 으로 남는다.
  - EXTRA_ARGS 의 `--lidar-cast` 는 런처의 것보다 뒤에 붙어 이긴다(argparse 는 마지막 값을 쓴다).
  - 런처가 요청값을 `SCAN_SWITCHES` 줄과 `env.sh` 에 남긴다. `runner.sh` 가 두 환경 스위치를 export 하고 `--lidar-cast` 를 넘긴다.
  - 러너는 실제 적용값을 `result.json` 의 `scan_switches` 에 남긴다: 두 모듈 상수, 그림자 배열 경로가 실제로 도는지(커널 모드가 reference 가 아닌지), 커널 모드, LiDAR 모드, NumPy·numba 버전.
- **`--near-tracking` 실행은 셋 모두 끔이다.** 근접 계약은 `lidar_cast: loop` 만 비교하고 두 환경 스위치를 보지 못한다(`near_tracking.py`). 그래서 기본값이 0/0/loop 이고, 켬을 명시하면 런처가 거부한다.
- **SLAM 조사(`slam_survey.sbatch`)는 끔으로 고정한다.** 지도를 실행 사이에 비교하기 때문이다. 콘솔과 같은 `runner.sh` 를 글자 그대로 쓰는 계약(시험)은 유지한다.
- **측정 래퍼(`r1c_session.sh`)는 끔이 기본이다.** 지금까지의 목록이 같은 뜻으로 다시 돌게 하려는 것이다. 목록이 스위치를 명시하면 그 값을 쓴다.
- **riib 장면 런처(`riib_scene.sbatch`)는 바꾸지 않는다.** `--live` 없이 돌아 커널 모드가 reference 이므로 1c 배열 경로가 돌지 않는다. 단계 확인(live, numba)의 절감도 그대로 옮겨 말할 수 없다. 전체 커널 모드를 바꾸는 것은 다른 커널과 계획 벽시계 예산까지 바꾸므로 이 승격에 넣지 않는다.
- 배치 러너 기본값, 재생 게이트, 시험의 기본값은 그대로 끔이다.

## 스위치별 출력 동등성 근거

- **1b — 덤프 재생 불일치 0.**
  - 기록된 실제 덤프 1024/1024 를 스위치 켬으로 재생하면 끔 결과와 바이트까지 같았다(노트북 NumPy 2.x). Codex 독립 재생도 1024/1024, `_clear_group` 중간 결과 2050/2050 이 같았다(`2026-11-10-g3-1b0.md`).
  - ws1(NumPy 1.26·numba 0.59)에서 두 커널 모드로 덤프 전부를 재생했고 EQUAL_EXIT 0 이었다(잡 17269, #393 머지 때).
  - 성질 시험 24 경우(두 커널 모드, 몸체 사각형 유무, 격자 가장자리, 여러 스캔)도 같았다.
- **1c — 덤프 재생과 연속 이벤트 재생 불일치 0.**
  - 표본 덤프 재생: line_m 259/259, hall 329/329 가 두 모드에서 자기 재현·동등이다(ws1, `2026-11-10-g3-1c0.md`).
  - 연속 이벤트 재생: line_m 1,881 호출, hall 2,709 호출 모두 valid, 불일치 0 이다. 머지된 코드(`_move` 원래 경로)로 다시 재생해도 같았다(ws1 잡 17259–17261).
- **1d — 같은 물리 상태에서 배열이 같다(허용 오차 없음).**
  - fast 는 loop 와 같은 광선을 같은 순서로 같은 인자로 질의한다. 자기 판정은 `(접두사 집합, rigidBody, collision)` 을 키로 한 순수 함수의 메모이며, loop 의 부분 문자열 판정을 그대로 쓴다. 그래서 질의 결과가 같으면 거리·충돌·자기 판정이 비트까지 같아야 한다.
  - 단위 시험(`tests/unit/sim/test_lidar_fast.py`): 가짜 질의로 몸체·접두사 변화·스캔 사이 캐시 공유를 덮는다.
  - 실제 PhysX 벤치(#388, 잡 17120): 두 장면 16 자세에서 배열이 같았다. 다만 그 자세들에서는 자기 몸에 맞은 광선이 없었다. 즉 own=False 경로만 확인했다.
  - 남은 것(own=True 와 적재 팔레트의 접두사 전환)을 아래 B 로 확인한다. **머지 조건이다.**

## B. 머지 전 1d 확인 (등록, rv3 뒤 실행)

**B1. 실제 PhysX 접두사 순서 벤치** (`sim/isaac/lidar_bench.py --prefix-sequence P_1,P_2`).
- 장면: 1e 판정 실행 세션 g3el_f_02_cand 가 저장한 `run/scene.usda`(트럭과 세션 팔레트 P_1–P_3).
- 트럭·P_1·P_2 의 모든 충돌체를 겨눈다. 충돌체 중심 둘레에 원점 8 개를 두고, 각 원점에서 9 광선의 부채꼴을 쏜다.
- 접두사 집합 F, F+P1, F, F+P2, F 순서로 loop 와 fast 를 같은 물리 상태에서 돌린다. fast 의 캐시는 순서 전체에 하나다(러너 모듈 캐시와 같다). F 는 트럭 접두사이고, P 는 러너가 만드는 세션 팔레트 자기 접두사(`self_filter_prefix`)다.
- 합격(모두):
  - 모든 단계·스캔에서 거리·충돌·자기 배열이 같다(불일치 스캔 0, 광선 0).
  - 단계마다 트럭에 맞은 광선이 있고 모두 own 이다.
  - 단계마다 P1·P2 에 맞은 광선이 있다. 팔레트 광선은 그 접두사가 든 단계에서만 own 이고, 다른 단계에서는 own 이 아니다.
  - 나머지 광선은 own 이 아니다.
  - 뒤의 두 F 단계에서 앞 단계가 만든 캐시 항목으로 답한 광선이 있다(캐시 재사용).
- 실패하면 종료 코드 1 이다. 기록: `lidar_bench.json` 의 `prefix_sequence`.

**B2. Isaac oracle 세션** (live, 같은 상태에서 loop 와 fast 를 광선마다 대조).
- `r1c_session.sh` far K f 1.0(line_m, confirm 미션), `FORKLIFT_GRID_CLEAR_KERNEL=1`, `FORKLIFT_SHADOW_KERNEL=1`, `LIDAR_CAST=oracle`. 단독, 묶음 실행기 `--slots 1`.
- 합격: `result.json` 의 `lidar_cast` 에서 `mismatched_scans = 0`, `mismatched_rays = 0`, `scans > 0` 이다.
- 보고만 한다(판정 아님): `own_true_rays`, `prefix_sets`(적재 팔레트 접두사가 들었는지), `own_cache_entries`.
- 미션 완료와 안전(금지 포켓 접촉·무허가 진입)은 따로 보고한다. oracle 은 두 경로를 다 돌리므로 그 시간은 절감 측정에 쓰지 않는다.
- confirm 은 P-1 만 운반한다. 다른 팔레트로의 접두사 교체는 B1 이 덮는다.

**머지 조건:** B1·B2 합격, 바뀐 스냅숏의 재생 게이트 29/29, ws1 전체 pytest. 재생 게이트는 장애물층과 LiDAR 를 기록된 응답으로 대신하므로 계산의 증명으로 세지 않는다. 계산의 증거는 위 동등성 재생과 B 다.

## 한계

- **켜면 실행 속도가 바뀐다.** 물리 dt 는 그대로다. 그러나 실현 sim/wall 배율이 바뀌고(1e 판정 실행 AUTO 배율 0.885–0.890 → 0.933–0.943, 관측값), 비동기 응답(SLAM·계획 작업자·원거리 인식)이 도착하는 sim 시각과 순서가 달라질 수 있다.
  - 그래서 이 기본값 이전의 live 기록(rv3·④⑤ 배치, 그 전 콘솔 기준선)과 이후 기록을 한 분모에 섞지 않는다.
  - 그 전 기록에 `scan_switches` 가 없으면 끔으로 읽는다. 단, 단계 확인처럼 켬으로 돌린 실행은 그 목록과 `args.txt` 로 판별한다.
- 배속(FACTOR)은 바꾸지 않는다.
- 동등성과 성능 근거는 ws1(Isaac 5.1, NumPy 1.26, numba 0.59)의 것이다. Jetson 으로 넓히지 않는다. numba 가 없으면 NumPy 대체 경로가 돌고(1b 성질 시험이 두 모드를 덮는다), numba 는 필수가 아니다.
