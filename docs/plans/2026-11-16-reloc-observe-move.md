# 출발 위치 추정 뒤 앞뒤 짧은 이동 효과 시험 (2026-11-16, 계획)

- 배정(총괄, 사용자 지시 2026-11-16): "앞뒤로 조금 움직이는 것도 얼마나 결과 좋아지는지 테스트". 학교 규모로 한다. 기존 재시도·재정합 코드를 다시 쓰고, '확인 전 위치' 설계(pose_check 등)는 끌어오지 않는다.
- 배경: B-P2d seed 5 ([검증](../validation/2026-10-29-b-p2d-start-relocalization.md)) — 출발 93, 유효 84, 성공 68(81 %), 틀린 확정 0, 운용자 요청 16(모두 남쪽 반복 선반 칸). 지금 규칙은 제자리 스캔 최대 3 회, 공유 기한 30 s 이다. `RelocConfig.attempts` 주석이 "이동은 S-P1 전에는 없음"이라고 미뤄 둔 그 이동을 이번에 시험한다.

## 1. 무엇을 바꾸나 (B 팔, 옵션, 기본 끔)

- 러너 옵션 `--reloc-observe-move D`(m, 기본 0 = 끔). `--start-relocalize` 와 `--reloc-unattended` 가 함께 있어야 한다(`--reloc-inject` 와 같은 검사). 근접 계약 `POST_MEASUREMENT_ARGUMENTS` 에 끔 값 0 으로 등록한다.
- `reloc_phase._run`, 무인일 때만 동작한다. 제자리 단계가 확정 없이 끝나면(`awaiting_pick`·`reloc_failed`, 지금은 여기서 세션이 끝남) 아래 순서로 간다.
  1. 출발점에서 **앞으로 D** 직진 → 서서 → `relocalizer.retry(generation, attempts=2)` → 재정합 최대 2 회(스캔 세트 1 + 재스캔 1). `retry` 에 그 세대만의 시도 한도 `attempts` 를 더한다(구현 예정): `StartRelocalizer` 가 `_limit` 을 갖고, 생성 때와 `attempts` 없는 `retry()` 는 `cfg.attempts`(3), `retry(…, attempts=2)` 는 2 로 둔다. `record()` 의 재스캔 조건은 `self.attempts < self._limit` 이 된다. 늦은 확정 거부(`late`)는 그대로다. 콘솔의 재시도는 `attempts` 를 넘기지 않으므로 바뀌지 않는다(시험으로 고정).
  2. 그래도 확정이 안 되면 **뒤로 2D**(출발점 기준 −D) 직진 → 서서 → 같은 재정합.
  3. 그래도 안 되면 지금처럼 `needs_operator`/`failed` 로 끝낸다. 출발점으로 되돌아가지는 않는다. 확정되면 그 자리에서 기존 다리(`write_reloc_pose` → 다리 시작)로 이어진다.
- 앞뒤 둘 다 보는 이유: 제자리로 돌아와 다시 재면 같은 장면이라 새 정보가 없다. 사용자가 말한 '앞뒤 조금'을 +D 와 −D 두 자리에서 각각 보는 것으로 읽는다.
- **그 자리 스캔에서 통로가 빈 방향만 간다.** 움직이기 전에 그 자리의 마지막 스캔(레이저 좌표, 이미 받은 것)에서 진행 방향 직사각 통로를 본다. 폭은 차체 폭 + 2×0.10 m, 길이는 이동 거리 + 여유 0.15 m 다. 그 안에 점이 하나라도 있거나, 그 통로를 덮는 각도 구간에 유효한 빔이 없으면(차체 가림·사거리 밖) 그 방향은 건너뛴다. 장애물 층은 위치 추정 뒤에야 지도 좌표로 채워지므로, 위치를 모르는 이 단계에서는 이 검사로 대신한다. 층을 임시 좌표로 채우는 일은 하지 않는다.
  - **한계(이 시험의 범위):** 낮은 장애물·스캔 평면 아래, 이동 중 새로 나타난 장애물은 보지 못한다. 이동 중에 멈추는 장치도 없다. 그래서 이 검사는 정적 시뮬 장면 실험용이다. 실차나 콘솔 경로로 옮길 때는 장애물 층과 현장 정지가 따로 필요하다(4 절). 이동 중 무언가에 닿았는지는 참값으로 기록만 한다: 명령 거리 대비 실제 이동이 70 % 미만이거나 기울기가 생기면 `move_contact` 로 표시한다.
- 주행: `run_steering_probe` 방식(`ackermann(v, κ=0)` → `robot.apply_action`)으로 0.10 m/s(`recovery_reverse_mps`)로 D/v 동안 가고, 0 으로 세운 뒤 1 s 가라앉힌다. 거리는 개루프이고 정밀하지 않아도 된다. 바퀴 명령은 `RelocInputs` 에 넣는 `drive(v)` 콜백 하나로 들어온다(러너가 만들고, `reloc_phase` 는 엔진 객체를 모른다).
- **STOP 과 기한.**
  - 이동 틱은 `_run` 의 `step("move")` 로 돈다. 그래서 콘솔이 있으면 `gate`/`service` 를 거친다. 틱마다 `relocalizer.state` 를 본다. STOP 으로 `stopped` 가 되면 바퀴를 0 으로 세우고 이동을 끝낸다. 남은 이동은 다시 하지 않는다. 무인에서는 거기서 `needs_operator` 로 끝낸다.
  - 기한: 정적 단계는 지금과 같다(첫 스캔부터 30 s, 최대 3 회). 이동한 자리마다 `retry(…, attempts=2)` 가 새 30 s 를 열고, 그 안에서 스캔 세트는 최대 2 회다. 30 s 를 넘긴 확정은 지금 규칙대로 받지 않는다. 운용자 기한(`operator_deadline_at`)은 그대로 전체에 걸린다. 그래서 B 의 최악 추가 시간은 두 자리 × (이동 ≈ 0.3/0.1 + 1 s 또는 0.6/0.1 + 1 s + 재정합 ≤ 30 s)이다. 시간 지표로 보고한다.
- **참값 경계.** 스캔 수집의 정지 검사(`scan_capture.scan_set` 의 '놓인 자리에서 2 cm')는 이동 뒤 기준을 선 자리(엔진 참값)로 옮긴다. 이것은 '서 있는지' 확인하는 계측 쪽 검사다. 정합 입력은 지금처럼 `got["sent"]`(잡음 낀 거리) 하나뿐이다. 바뀐 기준값은 정합 입력, 초기값, 후보 선택, 성공 판정 어디에도 넘기지 않는다. 시험으로 고정한다: 기준값을 크게 바꿔도 정합에 들어가는 점이 바이트 단위로 같다.
  - 판정(`reloc_judge`)은 이미 다리 시작 시점의 `verdict.slam_base` 와 `verdict.truth_base` 를 비교하므로 이동해도 그대로 맞다. 운용자 요청으로 끝난 세션의 `truth_in_shown` 분석용 `out["truth"]` 는 마지막 스캔 자리의 참값으로 바꾸고, 자리별 참값은 `truth_by_phase` 로 남긴다(기록만).
- 기록: 시도마다 `phase`(`static`·`move+D`·`move-D`), 이동마다 `{dir, d_m, blocked, travelled_m(참값, 기록만), wall_s}`, 그리고 **이동 전 결과** `static_outcome` 을 남긴다.

## 2. 비교 (Isaac 한 번으로 짝 비교)

- B 팔만 돌린다. A 는 각 세션의 정적 단계에서 만든다. 이것은 같은 세션의 정적 단계 결과를 공유하는 단계별 비교다.
  - 정적 단계는 A 와 B 가 같은 코드, 같은 스캔 잡음 키, 같은 30 s 기한이다. B 의 이동은 A 라면 세션이 끝났을 바로 그 자리에서 시작한다.
  - 정적 단계에서 확정된 세션: B 는 움직이지 않으므로 그 세션 자체가 A 의 실행이다. A 의 최종 결과(다리 시작·hold 포함)는 그 세션의 `reloc_judge` 결과를 그대로 쓴다.
  - 정적 단계에서 확정되지 않은 세션: A 는 거기서 `needs_operator`/`failed` 로 끝나 다리를 시작하지 않는다. 그래서 무인 성공이 아니다(B-P2d 의 정의와 같다). A 의 다리·hold 결과를 지어낼 필요가 없다.
  - Isaac 의 비결정성은 A·B 사이에 끼지 않는다.
- 같은 출발 목록 `docs/validation/assets/b-p2d/val_s5.json`(93), 같은 세계·지도·런처 기본값이다. B-P2d 당시 동결(`freeze1.json`)은 코드가 바뀌어 맞지 않으므로 `--frozen` 없이 판정하고, 바뀐 것은 기록한다. 지난 81 % 와는 직접 비교하지 않는다(코드가 바뀜). 이번 A 를 새 기준으로 삼는다.
- **사전 등록(결과 보기 전, 이 커밋으로 고정)**
  - 주 지표는 정적 단계 실패를 이동이 무인 성공(다리 시작·hold 까지)으로 바꾼 수를 **보수적으로** 센다. A 는 정적 단계에서 끝나고, B 는 최종 성공까지 가야 구제로 친다. 같은 종료 지점에서 두 군을 비교하는 것은 아니다. 유효 세션 짝에서 구제 b = (A 실패, B `reloc_judge` 성공: 정합기 확정·오차 성공 등급·hold 통과), 악화 c = (A 성공, B 실패). 구제 수 b 와 단측 정확 McNemar p = P(X ≥ b | X ~ Bin(b + c, 1/2)). c 는 구조상 0 이어야 한다(A 성공 세션은 이동하지 않음). 0 이 아니면 결함으로 본다. McNemar 는 불일치 짝만 쓰므로 c = 0 이면 p = 2⁻ᵇ 이고, '구제가 우연이 아닌가'만 말한다. 효과의 크기는 정적 실패 세션 중 구제 비율 b / n_정적실패(Clopper-Pearson 95 % 구간)와 전체 성공률 A → B 로 따로 보고한다.
  - 안전: B 의 틀린 확정 0(> 0.30 m 또는 0.10 rad, `reloc_judge` 기준). 하나라도 있으면 효과와 상관없이 불채택이다.
  - 시간: 이동한 세션의 추가 시간(이동 시작부터 확정 또는 종료까지) 중앙값·최대. 자리별로 실제 스캔 세트 수와 30 s 기한 초과 여부를 함께 적는다(기한을 넘기면 두 번째 스캔 없이 그 자리가 끝난다).
  - 0.6 m 한 번 더: 구제 ≥ 3 이고 틀린 확정 0 이면 같은 목록에서 D = 0.6 을 한 번 더 돌린다. 아니면 0.3 결과로 끝낸다. 0.6 m 는 0.3 m 결과를 보고 정하는 **탐색적 후속**으로 보고한다(같은 목록이라 독립 확인이 아니다). 0.3 m 만이 사전 등록된 확인이다.
  - 막힘: 두 방향 모두 막혀 움직이지 못한 세션 수를 따로 센다(효과 분모에서 빼지 않는다).
- 판정 도구: `tools/reloc_judge.py` 의 세션 결과에 `static_outcome` 으로 A 를 다시 만드는 작은 집계를 더한다(`tools/reloc_move_compare.py`, 시험 포함).

## 3. 실행

- 묶음: B-P2d 와 같은 `isaac_bundle` live, 3 슬롯, `shard:4`. 측정 잡 규칙대로 단독으로 돌리고, VM 이 꺼져 있고 옆에 CPU 잡이 없을 때만 낸다. 제출 전 squeue 를 보고 총괄에 크기를 한 줄로 알린다.
- 시험(먼저, 가짜 엔진, `tests/unit/tools/test_reloc_phase.py`): 정적 실패 → +D 에서 확정, 정적 실패 → +D 실패 → −2D 에서 확정, 한쪽 막힘 → 다른 쪽만, 양쪽 막힘 → 움직이지 않고 지금처럼 끝, 빔 없는 통로 = 막힘, 이동 중 STOP → 바퀴 0·남은 이동 없음·`needs_operator`, 정적 성공 세션은 이동 없음, 옵션 끔 = 지금과 같은 결과, 참값 기준을 바꿔도 정합 입력이 같음, `static_outcome` 기록. 러너 인자 검사와 근접 계약 등록 시험.
- 머지 전: 러너를 건드리므로 재생 게이트 29/29를 본다. 이것은 기본 끔 경로가 그대로인지를 확인하는 몫이고, 새 경로는 위 시험과 smoke 가 맡는다. Isaac smoke 는 B-P2d 에서 운용자 요청으로 끝났던 남쪽 출발 2 개(이동 켬; 실제 이동, 기록, 막힘 검사가 도는지)와 정적 성공 출발 1 개(켬, 이동 없음)로 한다. ws1 전체 pytest 도 돌린다.
- 결과는 짧은 문서 PR 로 낸다(`docs/validation/2026-11-16-reloc-observe-move.md`).

## 4. 하지 않는 것

- 여러 자리의 스캔을 오도메트리로 합치는 정합, 제자리 회전, 장애물 층 임시 좌표 채우기, 콘솔(사람) 경로의 이동 버튼은 하지 않는다. 효과가 보이면 그때 따로 정한다.

## 5. 검토

- **Codex 1 회차(적대적).** P1 3 건 반영: '막히면 안 움직임'을 그 자리 스캔 통로 검사의 한계와 함께 좁혀 썼다(빔 없는 구간 = 막힘, 이동 중 접촉은 참값으로 기록만). STOP 과 기한을 정했다(이동 틱 STOP → 정지·남은 이동 없음, 자리마다 새 30 s, 운용자 기한 그대로). 참값 기준은 정지 검사에만 쓰고 정합 입력이 같다는 것을 시험으로 고정한다. P2 4 건 반영: A 정의(정적 단계에서 확정된 세션은 그 세션 자체가 A, 확정 안 된 세션은 A 실패이고 다리를 지어내지 않음), McNemar 짝·구제 정의, 0.6 m 는 탐색적 후속, smoke 범위(이동하는 남쪽 출발 2·정적 성공 1)와 재생 게이트의 몫.
- **Codex 2 회차.** P1 1 건: 이동한 자리의 시도 한도를 `retry(generation, attempts=2)` 로 정했다(기한 30 s, 콘솔 재시도는 그대로). P2 1 건: 주 지표가 보수적 단계별 구제 수라는 것을 한 문장으로 한정했다.
- **Codex 3 회차.** P1: 세대별 시도 한도를 `record()` 까지 어떻게 넘기는지(`_limit`) 적었다. P2: McNemar p 는 불일치 짝 방향만 말한다는 것을 적고, 효과 크기는 구제 비율과 구간·전체 성공률로 따로 보고한다.
- **Codex 4 회차.** 새 P1 없음. P2 1 건(자리별 스캔 수·기한 초과를 시간 보고에 함께)을 반영해 수렴했다.
