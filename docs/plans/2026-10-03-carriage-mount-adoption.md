# 낮은 캐리지 장착 적용과 3순위 재평가 (4순위 B1·B2, 계획)

작성일: 2026-10-03 · 상위: [장착 연구 기록](../validation/2026-10-03-near-field-mount-study.md)(선택: provisional (0.559, 0, 0.27)·틸트 0.10 rad),
[근접 추적 계획](2026-10-03-near-field-pocket-tracking.md)(보류), [다섯 번째 동결 평가](../validation/2026-10-03-fifth-frozen-evaluation.md)(지금 장착에서 3순위 완료)

## 요청과 범위

사용자(2026-10-03): B 단계를 1 → 2 → 3 순서로 "진행해". 이 계획은 1(Isaac 에 새 장착 적용·렌더 확인)과 2(3순위 재평가)를 다룬다. 3(근접 추적 설계)은
2 의 결과를 보고 별도 계획으로 쓴다.

## B1a — Isaac 렌더 확인 (실행함, 2026-10-03)

`render_mount_check.py` 에 `--camera`·`--camera-tilt` 를 더했고(기본값 = 10/01 장착), provisional USD·장착 (0.559, 0, 0.27)·0.10·face_gap −0.36…1.20 m
157 칸을 렌더했다(ws1 작업 740, 24 분 34 초; 157 칸 모두 유효·관통 0·미확인 0·마스크 확인 157). 결과는 [기록](../validation/2026-10-03-carriage-mount-render.md):

- **깊이:** 48,230,400 화소 중 Isaac − CPU 차가 10 µm 를 넘는 화소는 **1 개**(한 칸의 가장자리). 영역 내부 최대 3.9 µm.
- **1 mm 양자화 깊이에서 근접 연구를 그대로 재생**(Codex 요구: 깊이 수 일치는 윗판 연쇄 결과의 일치를 보장하지 않는다): 157 칸 × 12 seed 의 앞면·윗판·인계 판정과
  seed 별 무관측이 **CPU 와 모두 같다**(인계 칸 53, 최대 무관측 0.01 m, 종단 0, 진입 뒤 윗판 12/12). 장착 연구의 선택은 Isaac 깊이에서도 성립한다.
- **양자화하지 않은 깊이에서는 근거리 앞면 검출이 깨진다:** Isaac 원시 깊이는 전 seed 성공이 face_gap 1.11 m 너머에서만, CPU float32 도 0.77 m 너머 — 10/01 기록의
  결과 4(µm 이하 값에 대한 검출기 민감성)와 같은 현상이다. **실행기는 원시 깊이를 검출기에 넣는다** — 그대로 장착만 바꾸면 근거리 이점이 사라진다(→ B1c).

## B1b — 임무 실행기에 장착 선택 (두 검토 반영)

- `--perception-mount {legacy, carriage_low}`(기본 `legacy`). `carriage_low` = base (0.559, 0, 0.27)·틸트 0.10, provisional URDF 에서만 허용.
- **인식 카메라와 표시용 카메라 모두** `carriage_low` 일 때 `fork_carriage` 아래에 두고, 방향은 장착 회전 행렬에서 만든 쿼터니언으로(`camera_axes="ros"` 에서만 허용 —
  다른 축 규약은 거부). 읽어 낸 USD 변환이 계획 장착과 1e-6 안인지 확인한다.
- **승강 검사는 캡처의 모든 렌더 단계에서:** `SensorCapture` 에 선택적 `guard_fn` 을 더해 캡처 시작 전과 매 단계 뒤에 부르고, `carriage_low` 에서는 승강 관절
  위치 |z| ≤ 1 mm 를 요구한다(넘으면 `CaptureFailure("lift_not_zero")`). `pose_fn` 은 base 자세 그대로다(`accepted_pose` 는 base 자세라는 계약 유지).
- **장착 변환을 캡처마다 기록하고 G3 가 그것을 쓴다:** 관측 시도 기록에 `base_from_optical`(행렬)을 남기고, `tools/diagnose_detection.py` 는 기록이 있으면 그 변환으로
  재생하며 legacy 문자열 검사 대신 기록된 변환과 실행 인자의 일치를 게이트로 둔다(기록이 없으면 지금처럼 기본 장착).
- 오프라인 투영(`mission_views.project_world_opening`)은 승강을 반영하지 않는다 — 운반 중 오버레이가 어긋날 수 있다(영상만). 로봇 영상 메타데이터의
  `baseline_0p50` 표기를 장착 이름으로 바꾼다.
- 실행 중 관측점 생성기는 후축→카메라 0.899 m 를 받는다(지금 1.09). 생성기의 수평 가정으로 생기는 화각 오차는 1 % 미만이다(검토 ③).
- **고정 관측 후보는 옛 장착에서 골랐다**(`observation_candidate_design.py` 의 리그 기본 카메라, 실행기 순서 근거). 낮은 카메라는 낮은 소품(상자 0.188 m) 너머를 덜 본다 —
  검토 ③ 의 근사 계산으로 159 seed × 고정 후보 8 쌍 중 27 쌍이 크게 가려지고 3 쌍은 덜 가려지며, 모든 고정 후보를 잃는 seed 는 0. 실패보다 재관측·시간 증가가 예상된다.
  seed 마다 쓰인 후보가 바뀐 것을 기록한다.

## B1c — 깊이를 1 mm 로 양자화해 검출기에 넣는다

D435i 의 깊이 출력은 1 mm 단위 정수(z16)이고, 데이터셋 계약도 uint16 밀리미터다. `--depth-quantize-mm {0, 1}`(기본 0 = 지금 기록 재현)을 두고 `carriage_low`
평가는 1 로 한다. 양자화는 검출·윗판 입력 깊이에만 적용하고 저장 깊이(`perception_capture_*_depth_m.npy`)는 원시를 유지한다(G3 재생은 같은 양자화를 적용).
이 변경은 원거리 검출에도 닿으므로 B2 는 장착과 양자화의 **합친 효과**를 본다.

## B2 — 3순위 재평가 (판정 고침)

1. **Isaac 개발 실행:** seed 159 개를 `carriage_low` + 양자화 1 mm 로 한 번. 같은 작업에서 **같은 코드의 `legacy`(양자화 0) 대조**를 seed 3012·4007·4013·3008 과 기록과
   결과가 달라진 seed 에 대해 돌린다 — 소스 해시가 바뀌므로 legacy 재현은 AST 시험만으로 확인되지 않는다(검토 ③).
   판정(실행 전 고정, **비열등성 판정이며 약 3 % 회귀를 허용하는 느슨한 기준임을 밝힌다**):
   - 기준 완주 155 개 중 **실패로 바뀐 것 ≤ 5**(성공 → 실패와 실패 → 성공을 따로 센다 — 순완주 수만 보면 회복 4 개가 회귀 9 개를 가린다, Codex).
   - 실패로 바뀐 seed 중 **검출 관련(관측 후보 소진, 검출 기각 뒤 도달 불가, 검출 기각으로 관측이 늘어 시간 예산 초과)** ≤ 3.
   - 실패로 바뀐 seed 마다 legacy 대조 결과를 적어 "장착/양자화 탓" 과 "실행 변동" 을 가른다.
   - 5000–5029 는 이 실행으로 개발 데이터가 된다.
2. **동결 평가:** 1 을 넘으면 seed **6000–6029** 를 `carriage_low` + 양자화로 한 번. 다섯 번째 동결 평가의 규칙(미사용 확인, 코드·설정 동결, 재실행 예외, 분모 30,
   결과 확정 뒤 G3, 같은 seed 로 고쳐 다시 평가하지 않음)을 그대로 승계하고 합격선 28/30. 이 시험의 검정력은 낮다(실제 성공률 0.90 이면 통과 확률 약 0.41,
   0.97 이면 0.94 — 검토 ③). **6000–6029 는 이 평가의 것이다** — 보류된 근접 추적 계획의 6000–6029 예약은 7000–7029 로 옮기고, 평가 도구의 예약도 함께 고친다.
   합격하면 `carriage_low` 를 기본값으로 바꾸는 것은 사용자 결정으로 묻는다.

## 이 계획이 말하지 않는 것

- 실물 D435i 장착(브래킷·케이블·진동), 실측 차체(measured 는 x 가 다르다), T11.
- 근접 추적(3 단계)은 아직 하지 않는다. 이 계획은 장착을 바꿔도 지금 임무가 유지되는지만 본다.
- 정지 캡처는 승강 0 에서만 일어난다는 전제 — 승강 중 관측은 다루지 않는다.

## 자체 검토

**① 원자료 재계산.** provisional URDF 의 `fork_lift` 관절 원점이 0(승강 0 에서 캐리지 = base 프레임), 기준 155 = 125 + 30(두 기록 모두 실행기 해시 `53f6ef00…`),
B1a 의 깊이 차 화소 수와 Isaac 깊이 재생 결과를 원자료에서 직접 계산했다.

**② Codex 적대적 검토(판정 보류, 높음 3 건).** 캡처 내부 승강 변화(0 → 2 mm → 0 도 승인됨) → 렌더 단계마다 `guard_fn`; B1a 의 "깊이 같으면 윗판도 같다" 추론
→ Isaac 깊이로 직접 재생(위, 모두 같음), B1a 와 실행기의 검출 입력 차이 → B1c; G3 가 새 장착을 재생하지 못함 → 장착 변환 기록·G3 사용; 표시 카메라 부모·축 규약;
B1a 전체 격자 확인 조건; 회귀·회복 분리와 시간 초과의 분류; 6000–6029 중복 예약·동결 규칙 승계; "같은 코드" 표현과 legacy 대조.

**③ Claude 서브에이전트 독립 검토(Codex 결론 비공개, 차단 없음·수정 3 건).** 고정 관측 후보가 옛 장착에서 고른 것이고 낮은 카메라는 낮은 소품에 더 가려짐(근사 27/1218
쌍, 전부 잃는 seed 0); 표시 카메라·오프라인 투영의 base 기준 가정; 승강 검사를 매 단계로; legacy 대조·비열등성 기준의 느슨함·동결 평가 검정력·5000–5029 의 개발 데이터화.
range_min 0.8 m 는 카메라 기준 거리라 장착이 바뀌어도 의미가 유지되고, 운반 중 카메라는 팔레트와 겹치지 않는다(z 0.435 대 윗면 0.361) — 확인.

두 검토가 따로 같은 결론에 이른 것: 캡처 중 승강 검사 강화, 표시 카메라도 옮길 것, legacy 대조 필요.
