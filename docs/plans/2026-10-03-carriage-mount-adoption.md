## 요청과 범위

사용자(2026-10-03): B 단계를 1 → 2 → 3 순서로 "진행해". 이 계획은 1(Isaac 에 새 장착 적용·렌더 확인)과 2(3순위 재평가)를 다룬다. 3(근접 추적 설계)은
2 의 결과를 보고 별도 계획으로 쓴다.

## B1a — Isaac 렌더가 CPU 결론을 뒤집는가

장착 연구는 CPU 리그로 했다. 10/01 렌더 확인은 **다른 장착**(measured (0.61, 0, 0.20)·틸트 0)에서 Isaac 깊이가 CPU 와 µm 안에서 같음을 보였을 뿐이다.

- `sim/isaac/render_mount_check.py` 에 `--camera X,Y,Z`·`--camera-tilt` 를 더한다(기본값은 지금 상수 — 10/01 실행 재현). 카메라는 지금처럼 `fork_carriage`
  아래에 두고, 국소 변환은 리그 `Camera(xyz, tilt).base_from_optical()` 에서 만든다(기존 코드가 이미 회전 행렬을 쓴다).
- 실행: provisional 차체 USD(`artifacts/base_scene_warehouse_forklift/forklift.usd`), 장착 (0.559, 0, 0.27)·0.10, face_gap −0.36…1.20 m 1 cm(157 칸), seed 12.
- 판정(결과 전 고정): 모든 유효 칸에서 Isaac − CPU(float64) 깊이 차 최대 ≤ 10 µm, 1 mm 양자화 뒤 앞면 검출 성공·유효 수가 칸마다 같다. 넘으면 차이 지도로 영역을
  가르고, CPU 결론(장착 선택)을 그 범위에서 보류한다. 윗판 추적은 같은 양자화 깊이를 입력으로 하므로 깊이가 같으면 결과도 같다 — 깊이 일치를 근거로 삼는다.

## B1b — 임무 실행기에 장착 선택을 넣는다

- `--perception-mount {legacy, carriage_low}`(기본 `legacy`: 지금까지의 모든 기록을 그대로 재현). `carriage_low` 는 base 기준 (0.559, 0, 0.27)·틸트 0.10 —
  상수는 장착 연구 기록에서 가져오고 provisional 차체에서만 허용한다(다른 URDF 면 거부; measured 는 x 0.619 가 필요하다).
- 카메라 prim 을 `carriage_low` 일 때 `/World/Forklift/fork_carriage/PerceptionCamera` 로 둔다(실물처럼 승강과 함께 움직인다). URDF 의 `fork_lift` 관절 원점이
  0 이므로 승강 0 에서 carriage 프레임 = base 프레임이고, 인식 변환(`base_from_optical`)은 승강 0 일 때만 맞다 — **모든 정지 캡처에서 승강 위치 |z| ≤ 1 mm 를
  요구**하고 넘으면 캡처를 거부한다. 지금 임무에서 캡처는 관측 단계에서만 일어나므로(들어올리기 전) 이 조건은 항상 성립해야 한다.
- 카메라 방향은 지금 `OPTICAL_QUATERNION_XYZW` 상수만 쓰고 틸트를 무시한다(`run_transport.py:991`, 표시용 카메라 `:1039`). 장착 회전 행렬에서 쿼터니언을
  만들어 쓰고, 읽어 낸 USD 변환이 계획 장착과 1e-6 안인지 확인한다(렌더 확인 도구와 같은 검사).
- 실행 중 관측점 생성기(`runtime_viewpoints`)의 후축→카메라 거리는 장착 x 에서 그대로 따라온다(0.34 + 0.559). 생성기는 카메라를 수평으로 가정한다(틸트 0.10 은
  점수의 화각·거리 판정에 반영하지 않는다) — 이 차이를 기록에 적는다.
- 시험: 장착 상수, 틸트 쿼터니언(회전 행렬 왕복), `legacy` 의 모든 인자·변환이 지금과 같음(AST/값), 승강 검사 분기, provisional 외 URDF 거부.

## B2 — 3순위 재평가

장착이 바뀌면 원거리 인식 입력이 바뀐다. 장착 연구의 원거리 비교는 소품 없는 격자의 회귀 경고일 뿐이다.

1. **Isaac 개발 실행:** 지금까지 쓴 seed 159 개(0–8, 1000–1029, 2000–2029, 3000–3029, 4000–4029, 5000–5029)를 `carriage_low` 로 한 번. 비교 기준은 같은 코드의
   `legacy` 실행 기록(0–4029: 작업 718 의 125/129, 5000–5029: 작업 725 의 30/30 — 둘 다 같은 소스 `53f6ef00…`).
   판정(실행 전 고정): 완주 수가 기준 155/159 에서 **5 개 넘게 줄지 않고**, 실패 사유 중 **검출 관련(관측 후보 소진·검출 기각 뒤 도달 불가)** 이 기준보다 5 개
   넘게 늘지 않는다. 장착이 원인일 수 있는 실패는 seed 마다 적는다(관측 시도의 G3 분류 포함). 넘으면 원인을 진단하고 동결 평가로 가지 않는다.
2. **동결 평가:** 1 을 넘으면 새 seed **6000–6029**(지금 예약)를 `carriage_low` 로 한 번. 합격선 28/30(앞의 평가와 같다). 합격하면 `carriage_low` 를 실행기
   기본값으로 바꾸는 것은 사용자 결정으로 묻는다.

## 이 계획이 말하지 않는 것

- 실물 D435i 장착(브래킷·케이블·진동), 실측 차체(measured 는 x 가 다르다), T11.
- 근접 추적(3 단계)은 아직 하지 않는다. 이 계획은 장착을 바꿔도 지금 임무가 유지되는지만 본다.
- 정지 캡처는 승강 0 에서만 일어난다는 전제 — 승강 중 관측은 다루지 않는다.
