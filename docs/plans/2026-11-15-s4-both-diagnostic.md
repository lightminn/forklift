# S4 both 진단 — 라이브 영상 픽셀 지연 0 과 11/120 s 중 어느 쪽이 렌더된 선에 맞는가 (2026-11-15, 결과 전 고정)

- 근거: [S4 라이브 결과](../validation/2026-11-15-s4-live-overlay.md) 7 절 총괄 결정. 지연 방향을 눈으로 판단할 수 없어, `--path-display-pixel-lag-s` 를 정하기 전에 한 번 잰다. 진단 변수 사용은 이 1 회만 승인됐다(총괄, 2026-11-15).
- 방법 변경 경위: 처음 승인은 두 세션(지연 0 / 11/120)에서 마젠타 overlay 와 렌더된 선의 거리를 바로 비교하는 것이었다. 콘솔 프레임이 JPEG q80·색차 4:2:0 이라, 렌더된 선 위에 정확히 겹친 1 px 마젠타는 압축 뒤 선 색과 섞여 마젠타로도 선 색으로도 잡히지 않는다(합성 프레임으로 확인). 그러면 잘 맞는 프레임일수록 측정에서 빠진다. 그래서 총괄 승인으로 아래 1 세션 맞춤으로 바꿨다.

## 1. 실행

- 1 세션, S4 팔 A 와 같은 조건(random_m, registry 위치 추정, known start, seed 0, FACTOR 0.4, `P-4:D-1` 한 다리, MAX_EPOCHS 1, 틱 추적, `--max-sim-seconds 1200`, shard:1·CPU 4·7G·1:15)에 `FORKLIFT_PATH_DISPLAY_DIAGNOSTIC=both` 만 더한다. overlay 지연 설정은 0 이다.
  - both: 표시 다각선이 장면 prim(폭 18 mm 곡선, 표시 색)으로 렌더되고, 같은 프레임에 1 px 마젠타 overlay 가 그려지며, `path_display.jsonl` 에 표시 행이 기록된다(stage 단독은 기록하지 않아 쓸 수 없다).
  - stage prim 은 perception 카메라에도 보여 미션 인식이 바뀔 수 있다. 결과는 정렬 측정에만 쓴다.
- 래퍼 `deploy/console/s4_overlay_run.sh` 의 `ARM=D`. 이름에 `diag` 가 든 스냅숏(`snapshots/s4diag_<커밋 8자>`)에서만 돈다. 그 스냅숏의 런처 사본에서만 진단 변수 거부 세 줄(`isaac_live.sbatch` 의 `FORKLIFT_PATH_DISPLAY_DIAGNOSTIC is diagnostic only` 블록)을 지우고, 지우기 전·후 sha256(`before_sha256`·`after_sha256` 줄)과 diff 를 스냅숏의 `DIAG_PATCH.txt` 에 남긴다. 래퍼는 그 파일이 없거나, 런처가 아직 거부하거나, 런처의 sha256 이 `after_sha256` 과 다르면 시작하지 않는다. 저장소 런처는 바꾸지 않는다.
- 제출 전 점검은 S4 와 같다(squeue 0 두 번, qemu 0, persistence 2/2, vm_watch 켬, 단독).

## 2. 무효 조건

S4 등록 6 절과 같다(미션이 차를 움직이기 전에 끝남 포함). 더해서:
- `path_display.jsonl` 머리 줄의 mode 가 `both` 가 아니다(진단 변수가 러너에 닿지 않음).
- 아래 3 절의 맞춤에서 선회 프레임으로 센 것이 30 장 미만이다(판정 불가로 보고).

## 3. 측정과 판정(결과 전 고정)

도구: `tools/live_frames.py fit --run OUT/epoch_1/run --frames OUT/frames --per-frame`.

- 렌더된 선 마스크: 표시 색(`overlay_colours`, contrast 와 Return 보라는 뺌 — 압축된 마젠타가 Return 보라 쪽으로 번진다) 가운데 하나와 RGB 체비셰프 거리 40 이하이고, 마젠타 같은 픽셀(R−G ≥ 60, B−G ≥ 60, |R−B| ≤ 40)이 아닌 픽셀. 그 뒤 3×3 닫기로 overlay 가 가린 1 px 를 메운다. 허용차 40 은 60 에서 노란 판((230, 200, 60))이 주황 선으로 잡혀서 정했다.
- 프레임마다, 지연 k/120 s(k = 0–20)의 카메라(참값 base 자세 + 마운트 + 리프트, S4 delta 와 같은 재구성)로 그 프레임의 합성 시각에 서 있던 표시 다각선을 투영한다.
- 프레임마다 k 별 값: 렌더된 선 픽셀 가운데 어느 k 의 투영에서든 40 px 안인 픽셀들에서, 그 k 의 투영까지 거리(40 px 로 자름)의 평균. 렌더된 쪽에서 재는 것은 넓은 선을 가운데에서 맞추기 위해서고, 평균은 1 px 차이를 가르기 위해서다(정수에 가까운 거리의 중앙값은 같아진다).
- 가림 표본 처리: stage prim 은 깊이 시험을 받으므로 물체에 가려진 곳은 렌더 픽셀이 없어 재지 않는다(overlay 는 마젠타라 표시 색 픽셀을 만들지 않는다). 표시 색과 비슷한 물체·표시되지 않은 선의 픽셀은 40 px 자르기로 묶는다. 잴 픽셀 집합(ROI)은 모든 k 의 투영 합집합에서 정하므로 모든 k 가 같은 픽셀을 잰다.
- 세는 프레임: 화면 안 투영 표본(모든 k 에서 화면 안) 20 개 이상, 잰 렌더 픽셀 50 개 이상.
- 선회·직진: S4 delta 와 같이 t − 11/120 s 의 yaw rate 가 0.05 rad/s 이상이면 선회.
- 세는 프레임 집합은 모든 k 에 공통이다(포즈·화면 안 표본·ROI 픽셀 수가 모든 k 의 합집합·교집합으로 정해짐). 단 참 지연이 0 이면 가는 선 위의 마젠타가 렌더 픽셀을 지워 그 프레임이 빠질 수 있다(4 절). 그래서 제외 사유별 수(`counts.not_counted`)와 센 프레임의 시각 분포(`counted_time_s`)를 함께 보고하고, 판정은 이 공통 집합에 대한 조건부 결과로 적는다.
- **판정:** 선회 프레임의 k 별 값의 중앙값을 k = 0 과 k = 11 에서 비교한다. 작은 쪽이 렌더된 선에 더 맞다. 차이가 1 px 이하이면 "구별 불가" 다. 직진 프레임의 두 중앙값도 적는다. 지연이 맞다면 직진에서는 두 k 의 차가 선회보다 작아야 한다(일관성 확인, 판정 아님).
- 기술용(판정 아님): k = 0–20 전체의 선회 중앙값 곡선과 그 최솟값의 k.

## 4. 도구 검증(합성 프레임, `tests/integration/test_live_frames_tool.py`)

- 제자리 선회(0.3 rad/s)하는 카메라와, 원호 주행(0.4 m/s·0.3 rad/s, 0.8 m 앞부터 근거리 경로 + 목적지 고리, 두 색)으로, 알려진 지연(0, 11, 16 스텝)만큼 이른 자세에서 선을 그리고(폭 5–12 px, 표시 색) 그 위에 지연 0 의 1 px 마젠타를 그린 뒤 JPEG q80 으로 저장했다. 노란 판 방해물을 둔 경우도 있다.
- 맞춤의 최솟값 k 는 참 지연에서 2 스텝 안이고, 판정(0 대 11)은 참 지연 0 이면 0, 11·16 이면 11 이다.
- 남는 한계: 선이 3 px 이하로 가늘고 마젠타가 정확히 그 위에 있으면(참 지연 0 일 때 먼 선) 렌더 픽셀이 사라져 그 프레임은 세지 않는다. 그래서 참 지연이 0 이면 센 프레임이 줄 수 있다.

## 5. 한계

- 카메라 자세는 재구성이다(overlay 가 쓰는 카메라 prim 자세 이력이 아니다). 그 오차가 시간에 따라 변하면 k 마다 다르게 들어가 승자를 바꿀 수 있다. 재구성 오차가 지연 효과(선회 중앙 약 10 px)만큼 크면 판정이 흐려진다.
- 판정은 이 세션의 기술적 요약이다. 연속 프레임은 독립 표본이 아니고 신뢰구간이 없다. 실제 지연의 확정값이나 일반화된 주장으로 쓰지 않는다.
- 합성 시험은 특정 렌더 조건에서 도구가 지연을 되찾는다는 근거일 뿐, 실제 프레임의 조명·가림·선 겹침에서도 0 대 11 을 가른다는 근거는 아니다. 그래서 선회 프레임의 잰 픽셀 수와 프레임별 값을 함께 보고한다.
- 미션 하나, seed 하나다. 결과는 이 세션의 선회 구간에 대한 것이다.
- stage prim 이 perception 에 보여 미션 경로가 S4 A 와 다를 수 있다. 두 k 는 같은 프레임에서 비교하므로 판정에는 영향이 없다.
- 기본값(라이브 싱크에만)은 이 결과를 보고 총괄이 정한다.

## 6. 자체 검토

- 측정 방법이 바뀐 계기(JPEG 색차 편향)와 도구의 편향 두 가지(가는 선의 바닥 평탄, 중앙값 동점)는 합성 시험으로 찾아 고쳤다. 고친 뒤 시험은 4 절과 같다.
- Codex 적대 검토 1 회차: P1 선회·포함 규칙의 집합 문제 → 포함 규칙이 모든 k 에 공통임을 적고 제외 사유·시각 분포 보고와 조건부 해석을 3 절에. P2 합성 시험 대표성 → 원호 주행·근거리·두 색 시험 추가, 한계를 5 절에. P2 ROI·색 오염 → ROI 가 모든 k 에 공통임과 가림 처리 문구를 고침. P2 자세 재구성이 k 공통이라는 단정 → 고침. P2 래퍼 보호 → `after_sha256` 대조 추가. P3 기술적 요약 → 5 절.
- Codex 2 회차: 새 P1/P2 없음(남은 것은 해석 범위 — 5 절에 적은 대로 이 세션의 기술적 비교로 읽는다).
