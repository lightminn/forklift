## 1. 범위

### 1.1 운전자 전제

- 운전자는 차가 실제로 어느 자리(어느 칸·통로)에 있는지 안다는 것이 전제다.
  - 실차: 차 곁에 있거나 직접 볼 수 있다.
  - Isaac 검증: 탐침이 참값에 클릭 오차를 더해 놓는다.
- 반복 칸에서는 이웃 칸에서도 스캔 겹침이 똑같이 맞는다(검토 지적). 그래서 겹침 화면은 다른 칸을 고른 실수를 막는 장치가 아니다. 이 계획은 그 실수를 막는다고 주장하지 않고, 기록만 한다(4.5).
- 운전자 화면에는 지도, 전역 정합의 보인 후보(있으면), 놓은 자세의 외곽, 미리보기의 스캔 겹침이 보인다. 카메라 영상은 이 계획의 범위 밖이다.

### 1.2 명령과 상태 (콘솔 계약)

- **놓기** `relocalize_place {generation, pose: [x, y, yaw]}` (map, base_link):
  - `awaiting_pick`·`reloc_failed`·`place_preview` 에서 받는다.
  - 받으면 `placing`(국소 정합 중)으로 간다. `place_preview` 에서 받으면 그 미리보기는 무효가 된다.
- **미리보기** `place_preview`: 국소 정합이 확정되면 `preview_id` 와 추정 자세, 스캔 끝점을 보인다.
  - 거부되면 사유와 함께 놓기 전 상태로 돌아간다.
- **확정** `relocalize_place_confirm {generation, preview_id}`: `place_preview` 에서만 받는다.
  - `chosen` 으로 간다(출처 `operator_placed`). 그 뒤 `reloc_pose.json` → 브리지 경로는 지금 그대로다.
- **무효화**: 미리보기는 다음 가운데 어느 것에서든 무효가 된다. 그 뒤의 확정은 `reloc_stale_pick` 으로 거부한다.
  - STOP(→ `stopped`), 새 놓기, 다시 시도(전역), 세션 끝, 운전자 시간 끝.
- **묶음**: 모든 명령은 지금처럼 lease·epoch·control generation·세대에 묶인다.
  - 확정은 표시된 `preview_id` 와 일치해야 한다.
  - 같은 요청이 두 번 오면 한 번만 처리한다.
  - `interrupt()` 는 `placing`·`place_preview` 도 다룬다.
- **놓기 횟수**: 세션마다 국소 정합은 최대 N_PLACE = 3 번 시작할 수 있다(확정·거부 모두 센다). 한도는 새 국소 정합의 시작만 막는다.
  - 이미 만든 미리보기는 세 번째라도 확정할 수 있다.
  - 전역 다시 시도는 놓기 횟수를 되돌리지 않는다.
- **상태별로 받는 명령** (STOP·세션 끝·lease 관리는 어느 상태에서나 받는다):

  | 상태 | 받는 명령 |
  |---|---|
  | `awaiting_pick` | 후보 고르기, 놓기(횟수가 남았을 때), 다시 시도 |
  | `reloc_failed` | 놓기(횟수가 남았을 때), 다시 시도 |
  | `placing` | 없음. 정합이 끝나면 `place_preview` 로 간다. 거부되면 후보 단계의 상태로 돌아간다: 보일 후보가 있으면 `awaiting_pick`, 없으면 `reloc_failed`. 무효가 된 미리보기로는 돌아가지 않는다. |
  | `place_preview` | 확정, 놓기(횟수가 남았을 때), 다시 시도 |
- **입력 검사**: 놓은 자세가 지도 범위 밖이면 `reloc_place_invalid` 다.
  - 외곽이 벽·선반에 걸리는 것은 거부하지 않는다(검토 지적). 클릭 오차 안의 정상 클릭을 막기 때문이다. 창 탐색이 빈 자리만 후보로 삼는다.

### 1.3 국소 정합

- **스캔**: 놓을 때마다 정지 스캔 5 장을 새로 모은다. 정지 검사(1.2 단계 3 과 같은 한계)를 다시 하고, 어긋나면 `reloc_unsteady` 다(유효 세션의 실패).
  - 새로 모으는 이유: 운전자가 몇 분 뒤에 놓을 수 있고, 그사이 차가 밀렸는지 보아야 한다.
- **창**: 놓은 base_link 자세에서 위치 반경 R_LOC, 방향 ±Θ_LOC 다.
  - base 로 정의하므로 LiDAR 레버암 오차가 생기지 않는다(검토 지적).
  - 탐색은 기존 `global_match` 의 격자·점수 그대로이고, 후보 base 자세를 창으로 제한한다.
- **판정** (모두 통과해야 미리보기):
  1. 정밀화 뒤 자세의 끝점 비율 ≥ E_MIN(0.80, B-P1b 동결).
  2. 정밀화가 격자 자세에서 벗어나지 않는다(`refine_moved` 아님).
  3. **창 경계**: 정밀화 뒤 자세가 창 안에 있고, 경계에서 위치 0.3 m·방향 0.1 rad 보다 안쪽이다. 아니면 `reloc_place_edge` 로 거부한다. 참값이 창 밖일 수 있기 때문이다.
  4. **모호성**: 창 안의 억제 전 격자 잎 전부(점수 ≥ keep_ratio × 격자 최고점)를 본다. 1 위 자신의 격자 잎도 뺄 대상이 아니다.
     - 거리·방향은 **정밀화된 최종 base 자세**에서 잰다.
     - 점수 비율은 **원래 격자 최고점**에 대해 잰다.
     - 최종 자세에서 성공 허용(0.10 m 또는 0.05 rad) 밖에 있는 잎의 점수가 격자 최고점의 R_AMB 이상이면 거부한다(`reloc_place_ambiguous`).
     - 격자 1 위를 기준으로 재면, 정밀화가 허용 안에서 옮긴 만큼 부정확한 확정이 통과한다(Codex v2 검토의 수치 반례).
     - 같은 방향 미끄러짐, 가까운 방향 차이, 여러 봉우리를 한 규칙으로 덮는다. 한 줄 모양을 가정하지 않는다(검토 지적).
     - 전역 r_max 는 창 안에서 쓰지 않는다.
- **마감**: T_LOC = 10 s 다. 스캔 시작부터 미리보기 또는 거부까지를 잰다. 넘으면 `timeout`(놓기 한 번으로 센다).
- **운전자 시간**: 지금처럼 러너 시작부터 540 s 다. 놓기·미리보기도 그 안이다.
- 브리지 대조와 판정 자세(`running` 틱의 SLAM 자세)는 그대로다.

### 1.4 범위 밖

- 이웃 칸을 고른 운전자 실수를 막는 것(1.1).
- 모호한 자리의 해결. 차를 옮겨 다시 시도하는 길은 지금처럼 세션 끝 → 텔레옵이 열린 다음 세션이다. 주행 관측은 S-P1 뒤다.
- 무인 배치(7.1: 무인 런처는 알려진 시작).

### 1.5 바뀌는 곳

- `global_match.py`: 창 제한 탐색과 억제 전 잎 목록을 돌려준다. 기존 호출은 그대로다.
- `start_reloc.py`: `placing`·`place_preview` 상태, 놓기 횟수, 모호성·경계 검사.
- `sim/isaac/reloc_phase.py`: 놓기 처리, 스캔 재수집, 미리보기·확정.
- `safety/validate.py`·`arbiter.py`: 두 명령의 계약.
- `console/web`: 놓기(클릭·끌기), 미리보기 겹침, 확정.
- 판정 도구에 놓기 세션 분류를 더한다.
- 콘솔 탐침에 "참값 + 클릭 오차로 놓고 미리보기를 확정" 시나리오를 더한다.
- 러너가 바뀌므로 재생 게이트 runs29 29/29 를 거친다.

## 2. 정할 값

| 값 | 잠정 | 근거와 정하는 법 |
|---|---|---|
| 클릭 오차 모형 | base 위치는 반경 ≤ 1.0 m 원판에 면적 균일(반경 = √u), 방향은 ±0.35 rad 균일 | 지도 0.05 m 격자를 확대해 놓는 운전자의 오차를 넉넉하게 잡았다. 판정 전에 고정한다. 방향 180° 착각은 모형 밖이다(4.5 에 기록). |
| R_LOC | 2.0 m | 클릭 오차 1.0 m + 경계띠 0.3 m + 여유 0.7 m. 반복 칸 반주기 3 m 보다 작다. |
| Θ_LOC | 0.6 rad | 클릭 방향 오차 0.35 rad + 경계띠 0.1 rad + 여유. 반대 방향 쌍둥이는 뺀다. |
| R_AMB | 개발에서 정한다(0.80 ≤ R_AMB ≤ 1) | 규칙: 개발 세션에서 틀림·부정확 0 을 만드는 값 가운데 구제가 가장 많은 것. 같으면 더 엄격한 쪽이다. 하한 0.80 은 잎 보존 하한(keep_ratio 0.8)이다. 그보다 낮은 잎은 목록에 없다. |
| N_PLACE | 3 | 운전자 한 번의 호출에서 세 번 놓아 보면 충분하다고 본다. 판정이 이 정책 그대로 세션을 센다. |
| T_LOC | 10 s | 창 탐색은 작다. 개발 p95 의 3 배를 넘지 않게 확인한다. |

## 3. 개발 (seed 4 개발 지도 `9a5cefd5`)

- **오프라인**: B-P1b 시작 목록(`val3_s4.json`)마다 정지 스캔 묶음을 3 개 캡처한다. 각 묶음은 다른 잡음이고, B4a 캡처 도구를 쓴다.
  - 세션 모의: 시작마다 놓기를 최대 3 번 한다. 클릭은 모형에서 뽑고, 놓기마다 다른 스캔 묶음을 쓴다.
  - 모의 운전자는 첫 미리보기를 무조건 확정한다(고정 정책). 모든 운전자 행동보다 보수적이라는 뜻은 아니다. 첫 미리보기를 거절하고 다시 놓는 운전자는 다른 결과를 낼 수 있다.
  - 세션은 첫 확정에서 끝나고, 그 자세를 참값과 대조한다.
  - 지도 밖 클릭(`reloc_place_invalid`)도 다시 뽑지 않고 놓기 한 번의 실패로 센다.
  - 이것으로 R_AMB 를 정하고 시간을 잰다.
- **이웃 칸 클릭**: 반복 칸 시작에서 같은 줄로 6 m 옆에 놓는다. 확정 수와 그때의 끝점 비율을 적는다.
- **Isaac 끝단 개발**: seed 4 에서 탐침이 운전자로 놓고 확정하는 세션 몇 개를 돌린다. 순서·시간·화면·무효화를 확인한다.

## 4. 사전 등록 판정 (새 결과 전에 고정)

### 4.0 분류

- B-P2d 판정기의 분모 규칙을 그대로 따른다(`tools/reloc_judge.py`).
  - 명시적인 최초 물리 입력 실패(`reloc_invalid_input`)만 무효다.
  - 실행되지 않은 시작(캡처·세션 없음)은 `not_run` 이다. 판정을 보류하고 다시 돌린다.
  - 그 밖의 끝(실행 오류 포함)은 유효 실패다.
  - `running` 에 들어간 뒤 판정 자세 기록이 없으면 안전 상한과 통과를 보류한다.
- 자세 분류는 B-P2 4.0 그대로다(검토 지적).
  - 성공: ≤ 0.10 m 이고 ≤ 0.05 rad.
  - 틀림: > 0.30 m 또는 > 0.10 rad.
  - 확정됐지만 둘 다 아니면 모두 부정확이다.
- 세션 결과:
  - 놓기로 구제: 확정 → `running` → 판정 자세 성공 → 정지 유지 10 s.
  - 놓기 실패: 3 번 모두 거부, `unsteady`, 시간 끝, 운전자 시간 끝.
  - 출발 뒤 실패: 브리지 대조 거부, 정지 유지 실패.
  - 틀림, 부정확.
  - 판정 기록 소실: 안전은 보류.

### 4.1 표본

- **세계**: 새 seed 3 이다(4.4a 순서). 같은 절차를 밟는다: 자이로 조사, V2′, 잡음 seed 대체, 보완 순회, 3 m 소진 추출(seed 1031).
  - seed 5(B-P2d 세계)도 함께 쓴다. F1 의 값은 seed 4 에서만 정한다. 다만 seed 5 의 사람 요청 수는 (b) 를 고르는 데 썼으므로 그 점을 밝힌다.
- **어려운 집단**: 동결된 B-P2 무인 경로로 먼저 돌려, 사람 요청·후보 없음·마감으로 끝난 유효 세션이다. F1 이 풀어야 할 집단이다(검토 지적: 전체 분모로는 목적을 볼 수 없다).
  - seed 5 는 B-P2d 의 16 건을 그대로 쓴다.
  - seed 3 은 새로 돌린다.

### 4.2 안전 (주 판정)

- **(a) 정합기 수준, 오프라인**: 두 세계의 모든 유효 시작에서 3 절의 세션 모의를 한다.
  - 시작마다 스캔 묶음 3 개, 정책 그대로, 클릭 seed 는 고정한다.
  - 확정된 세션 가운데 틀림 0, 부정확 0 이어야 한다.
  - 분모는 유효 시작 ≥ 120 이다. 단측 95 % CP 상한을 적는다.
  - 결론의 범위는 "이 클릭 모형, N_PLACE = 3 정책, 첫 미리보기를 무조건 확정하는 운전자" 다. 정책을 넘는 무제한 재시도나 다른 확인 행동의 위험은 아니다(검토 지적).
- **(b) 출발 수준, Isaac 끝단**: 두 세계의 어려운 집단 시작마다 콘솔 세션 하나를 돌린다.
  - 무인 경로가 사람 요청에 닿으면, 탐침이 모형에서 클릭을 뽑아 놓고 첫 미리보기를 확정한다. 놓기는 최대 3 번이다.
  - `running` 틱의 판정 자세로 틀림 0, 부정확 0 이어야 한다.
  - B-P2d 의 출발 안전 근거는 새 경로에 이어 쓰지 않는다. 오프라인 정합 오차가 작아도 SLAM 자세가 다를 수 있다(B-P2 4.0 의 반례, 검토 지적).
  - 표본이 작다(약 30). 상한은 그 크기로 적고 5 % 조건은 요구하지 않는다. 기본값 승격(콘솔 놓기 켜기)은 총괄이 이 상한을 보고 정한다.

### 4.3 구제 (목적)

- **Isaac 끝단**: 어려운 집단 가운데 구제된 세션 ≥ 70 %(관측값)이어야 한다. CP 하한을 함께 적는다.
  - 근거: B-P2d 의 16 건 가운데 15 건은 창이 덮을 모양이었다(0 절). 운전자가 불려 온 세 번 가운데 둘보다 많이 그 자리에서 끝나야 쓸 만하다.
- **오프라인**: 어려운 집단의 구제 비율을 기록한다(통과 조건 아님).

### 4.4 시간

- 국소 정합 한 번(T_LOC 범위)의 p95 ≤ 2 s, 최대 ≤ 10 s(ws1 1 스레드, 오프라인 측정).

### 4.5 기록 (통과 조건 아님)

- 거부 사유별 수: 모호성, 경계, 낮은 끝점 비율, `unsteady`, 시간.
- 이웃 칸 클릭의 확정 수와 그때의 끝점 비율. 겹침이 방어가 아님을 수치로 남긴다.
- 모형 밖 클릭(위치 1.5 m, 방향 0.5 rad, 방향 180° 착각)의 확정·틀림 수.
- seed 5 의 16 건 가운데 구제된 수(유형별).

### 4.6 동결

- **1 차 동결**(개발 뒤): B-P2d 와 같은 방식이다.
  - 판정 경로 지문(새 파일 포함), 브리지 이미지 digest, 참조 세션의 공통 인자.
  - R_LOC·Θ_LOC·경계띠·R_AMB·N_PLACE·T_LOC.
  - 클릭 모형과 seed, 판정 스크립트.
- **2 차 동결**(수집 전): seed 3 지도 ID, keep-out, 시작 목록 sha256, 두 세계의 어려운 집단 목록.

## 5. 위험과 한계

- 이웃 칸에 놓은 실수는 확정될 수 있다. 안전은 운전자 전제(1.1)에 기댄다.
- 판정은 모형 안의 클릭과 정해진 정책에 한정된다. 모형 밖의 운전자 행동은 기록만 한다.
- Isaac 끝단 표본이 작다. 출발 안전 상한은 넓다.
- 같은 홀 조건부다. 공간 상관 때문에 유효 표본이 줄 수 있다.
- 실차 지도와 실제 차이(가구 이동 등)는 범위 밖이다.

## 6. 자체 검토

### ① 원자료 재계산 (Claude)

- seed 5 사람 요청 16 건의 분류를 다시 셌다. 1 판의 "반복 칸 12" 를 11 로 고쳤다(11 + 2 + 2 + 1 = 16). "보인 후보 안 12" 에 마감 초과 032 가 들어가 있음을 확인했다.
- B-P1b 쌍 수를 다시 셌다: 후보가 둘 이상인 모든 시작 136/33, 거부된 시작 76/19(Codex 지적과 일치).

### ② Codex 적대 검토 (1 판 대상) — P2 6, P3 3

1. 전역 탐색의 후보 억제(0.30 m/0.10 rad, 최대 8)가 창 안 모호성을 지운다. 합성 반례로 0.069 rad 어긋난 확정을 재현했다.
   → 1.3 의 4 번: 억제 전 잎 전체로 성공 허용 밖의 경쟁을 본다. 방향 모호성도 포함한다.
2. 오프라인 정합 판정에 B-P2d 의 `running` 안전 근거를 이어 쓸 수 없다.
   → 4.2 (b): 새 경로의 끝단 판정을 Isaac 에서 한다.
3. 미리보기 확인의 상태·명령 계약이 없었다.
   → 1.2: `placing`·`place_preview`, 확정 명령, 무효화, `interrupt()`.
4. 방향만 부정확한 경우가 빠졌다.
   → 4.0: 성공·틀림이 아닌 확정은 모두 부정확이다.
5. K = 5 상한은 무제한 재시도 세션의 위험 상한이 아니다.
   → N_PLACE = 3 정책을 고정하고, 판정을 세션 단위로 하며, 결론 범위를 정책에 한정한다.
6. 전체 80 % 는 사람 요청 사례를 못 구해도 통과한다.
   → 4.1 어려운 집단, 4.3 구제 하한.
- P3 처리:
  - 창 밖 확정 → 1.3 의 3 번: 위치·방향 경계.
  - 클릭 모형·분모·시간 범위 → 2 절(면적 균일), 4.0, 1.3(T_LOC 범위, 540 s 는 러너 시작부터).
  - 쌍 수의 범위 → 0 절.

### ② 의 재검토 (2 판 대상) — P2 2, P3 3

1. 모호성 검사의 기준이 모호했다. 격자 1 위를 기준으로 재면 정밀화가 옮긴 만큼 부정확이 통과한다(수치 반례).
   → 1.3 의 4 번: 거리·방향은 정밀화된 최종 자세, 점수 비율은 격자 최고점, 1 위의 잎도 포함한다.
2. 미리보기에서 받는 명령과 3 회 한도가 충돌했다.
   → 1.2: 상태별 명령 표, 한도는 새 정합의 시작만 막고 세 번째 미리보기의 확정은 허용, 전역 재시도는 횟수를 되돌리지 않는다.
- P3 처리:
  - R_AMB 범위를 0.80–1 로 묶었다(잎 보존 하한).
  - 분모와 기록 소실 처리는 판정기 규칙을 계승한다(4.0).
  - "보수적 운전자" 표현을 고정 정책으로 고쳤다(3, 4.2).
- 3 차 확인에서 P3 1 건: 미리보기에서 다시 놓은 정합이 거부될 때 돌아갈 상태를 정했다(1.2 표의 `placing`: 후보가 있으면 `awaiting_pick`, 없으면 `reloc_failed`). 그 밖의 새 P1/P2 는 없었다(수렴).

### ③ 다른 관점의 독립 검토 (`agy`, Gemini 4 Argon, 1 판 대상, ①·② 를 보지 않음)

1. 운전자가 맞는 칸을 안다는 숨은 전제가 있다. 반복 칸에서는 겹침도 똑같이 맞는다.
   → 1.1 에 전제로 밝혔다. 겹침을 방어로 주장하지 않는다.
2. base 클릭 오차와 LiDAR 중심 창 사이의 레버암, 그리고 경계띠 때문에 정상 클릭이 거부된다.
   → 창을 base 로 정의하고, R_LOC 를 2.0 m 로 넓혔다.
3. 0.3–0.9 m 의 같은 방향 경쟁이 r_max 에 걸려 계속 거부될 수 있다.
   → 창 안에서는 r_max 대신 R_AMB 규칙을 쓴다. R_AMB 는 개발에서 정한다.
4. 한 줄 모양 축퇴 가정, 그리고 드문 사례에 맞춘 과적합.
   → 모양을 가정하지 않는 모호성 규칙으로 바꿨다. 판정은 두 세계의 끝단·오프라인이다.
5. 전체 시작 분모는 쉬운 자리에 희석된다.
   → 어려운 집단 판정(②-6 과 같은 지적).
6. 놓을 때마다 스캔을 다시 모으는 비용과 `unsteady`.
   → 유지했다. 운전자가 늦게 놓을 수 있어 정지 확인이 필요하다. 비용은 T_LOC 에 넣어 잰다.
7. 외곽 빈 칸 검사가 정상 클릭을 막는다.
   → 놓기 입력의 외곽 검사를 뺐다.
- 빠진 정보 8 개 → 반영했다.
  - 운전자 화면 → 1.1.
  - 억제·격자 → 1.3 의 4 번.
  - 모호성 정의 → 1.3 의 4 번.
  - 각도 경계 → 1.3 의 3 번.
  - 미관측 칸 → 외곽 검사를 뺐으므로 해당 없음.
  - 모의 클릭의 무효 처리: 다시 뽑지 않고 실패로 센다(3 절).
  - 확인 상태 전이 → 1.2.
  - 모호할 때의 탈출 → 1.4.
