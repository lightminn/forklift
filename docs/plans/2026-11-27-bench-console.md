# 벤치 콘솔 — fw-bench 의 main 반영과 콘솔 '벤치' 화면 (2026-11-27)

- 상태: 계획.
- 요청: 사용자 "모터 테스트 GUI 를 콘솔에 통합해서, 안전장치 우회도 가능하게". 총괄 전달 2026-11-27.
- 범위와 기본안 세 가지는 총괄 동의를 받았다(아래 0 절).
- 원칙: 실차 검사는 세션 한정으로 우회할 수 있다. 우회 불가는 멈추는 쪽만이다(메모 real-checks-bypassable).
- 수준: 학교 수준으로 단순하게. 화면 하나에 기존 콘솔 프런트를 재사용하고, Isaac·실차 콘솔 동작은 바꾸지 않는다.

## 0. 정한 것 (총괄 동의 2026-11-27)

1. **백엔드는 별도 도구** `tools/bench_console.py`(Jetson)다. 실차 운영 콘솔(`tools/real_autonomy.py --run --client real`)과 동시에 띄우지 않는다(같은 보드 잠금). 운영 판정·잠금 코드와 섞지 않는다.
2. **'원시 0 근처 MISO low 고착' 위험 수정은 A1 에 포함**한다.
3. **그래프는 canvas 에 직접 그린다**(외부 라이브러리 없음, 기존 `map.js` 방식).

4. **측정 원천을 축별로 고른다**(사용자 추가 요구 2026-11-27): 나중에 MT(MT6701 증분 엔코더, L·R 바퀴 모터축, ABZ 4체배 4,096 카운트/회전)도 쓴다. 그래서 위치·회전 측정을 원천과 무관한 틀로 만든다(아래 0.1).

### 0.1 측정 원천

| 원천 | 축 | 값 | 기준 | 카운트/회전 |
|---|---|---|---|---|
| `kth` | M(조향 KTH), H(승강 KTH) | 절대각 12비트 → 펌웨어 이동량 카운터(이어 붙인 누적) | 센서 원시 0(절대) | 4,096 |
| `mt` | L·R(바퀴 모터축) | 증분 ABZ 카운트(이미 있는 LPTIM 바퀴 카운트) | 실행 시작 위치(상대) | 원천 설정값, 기본 4,096(4체배) |
| `none` | 어느 축이든 | 측정 없음 — 듀티 구동만, 시간으로만 멈춤 | — | — |

- 축의 기본 원천: M→`kth`(조향), H→`kth`(승강), L·R→`mt`. 화면과 도구에서 바꿀 수 있다. 측정이 없는 조합은 hold 와 거리 정지를 고를 수 없다.
- 원천 설정(카운트/회전, 부호)은 `config/real/` 의 한 곳에 둔다(KTH 4,096 고정, MT 는 `vehicle.yaml` 의 바퀴 카운트와 같은 값 — 이중 정의 금지).
- **정지 조건·hold 를 원천 무관하게:** `N 바퀴` / `N 카운트` / 목표 위치.
  - KTH 목표: 영점(원시 0)·절대값·지금·`±N`.
  - MT 목표: 지금 위치·`±N 카운트`(영점 없음).
- **실물 MT 는 미장착**이다. 검증은 `mcu_model` 의 엔코더 모형으로 한다.

순서는 A1 → A2 → B → C 다. 각 PR 은 Codex 수렴까지 돌리고, 최종 트리에서 ws1 전체 pytest 를 한 번 돌린다. 펌웨어 교차 빌드는 노트북에서 한다. 실물 확인은 사용자가 벤치 날에 한다.

## 1. A1 — fw-bench 의 main 반영

진단 브랜치 `diag/fw-bench`(태그 `diag-fw-bench-3`, 14 커밋, 약 2,200 줄)를 main 의 정식 빌드 종류로 옮긴다.

- **벤치 이미지 = 별도 빌드 종류.** 지금처럼 `FW_BUILD=commission FW_MOTOR_OUTPUT=1 FW_BENCH=1` 이고, 제품 문자열 끝은 `bench<세대>` 다.
  - **완료 조건 1 — 운영 빌드에 못 들어감:** `FW_BUILD=normal`(운영)·`hil`·`fw-single` 과 `FW_BENCH=1` 의 조합은 configure 에서 `FATAL_ERROR` 로 멈춘다.
  - 벤치 코드는 `FW_CORE_BENCH` 로만 컴파일되고, 운영 이미지 바이너리에는 벤치 메시지 처리기가 없다. 이를 교차 빌드 시험으로 고정한다: 운영·HIL·fw-single 이미지의 `nm` 에 벤치 심볼 0 개, 벤치 조합 configure 실패.
  - **호스트 게이트(Codex 계획 1 회차 P1-1):** BENCH_SET·BENCH_HOLD 를 보낼 수 있는 것은 **벤치 전용 호스트 객체 하나**다. 조건은 셋이다. 같은 fd 에서 읽은 제품 문자열이 정확히 `forklift-mcu commission OPEN …` 접두부이고, 끝 토큰이 이 도구가 지원하는 세대(A1 은 MISO 수정으로 세대를 `bench5` 로 올리고 `bench4` 이하는 거부)이며, 그 연결의 첫 STATE 가 `COMMISSION_BUILD` 와 일치해야 한다.
    - 일반 `mcu_host`·REAL 운영 전송기·HIL·teleop 경로의 두 메시지 송신은 거부한다. 운영 전송기의 쓰기 직전 보호(`ARM`·`DRIVE` 만 이름으로 막음)는 벤치 메시지 종류도 막도록 넓힌다.
    - 합격 시험: 일반 REAL·HIL·teleop 경로에서 두 명령의 송신 바이트 0. 재연결·부팅 변경·제품 문자열 누락·구세대·문자열과 STATE 불일치 각각에서 벤치 호스트도 거부.
  - **운영·비벤치 이미지는 벤치 메시지를 모름(P2):** 운영 normal OPEN, 일반 commission OPEN, HIL, fw-single 각각에 유효한 `0x06`·`0x07` 프레임을 보내면 unknown 으로 거부되고, 수락 seq·설정·출력이 바뀌지 않아야 한다.
    - 이를 비벤치 컴파일 변형의 호스트 시험으로 고정한다(호스트 시험용 코어는 지금 늘 `FW_CORE_BENCH=1` 이라 변형을 따로 만든다).
    - `nm` 심볼 확인은 보조로만 쓴다.
    - 잘못된 빌드 조합은 다른 인자가 모두 유효한 상태에서 *벤치 조합 사유로* configure 가 실패해야 한다.
  - **우회 수명(P1-6):** 지금은 BENCH_SET 값이 DISARM 에서 초기화되지 않고 부팅까지 남는다. A1 에서 펌웨어 계약을 바꾼다.
    - **ARM 마다 그 실행의 BENCH_SET 수락이 필요하다**(SET 일련이 ARM 직전 것이어야 함).
    - 쓰이지 않은 SET 은 만료되고, DISARM·FAULT·실행 종료에서 기본값으로 돌아간다.
    - 시험: 같은 부팅에서 `SET → 호스트 종료 → 새 세션`, `우회 실행 → 기본 실행`.
- **옮기는 것:**
  - 펌웨어: BENCH_SET(0x06, DISARMED 에서만, 우회 비트 `steer_range`·`lift_range`, 축별 듀티·연속 시간 상한), KTH 이동량 카운터(STATE `kth_alt_crc_errors` 칸), BENCH_HOLD(PI + 감쇠 D + 최소 듀티 + 데드밴드).
  - **원천 일반화(0.1):** BENCH_HOLD 와 펌웨어 쪽 정지 조건이 원천을 받는다.
    - `kth` 는 이동량 카운터를 쓴다.
    - `mt` 는 그 축의 LPTIM 바퀴 카운트(이미 STATE `wheel_count_left/right` 로 보냄)를 시작 시점 기준 상대값으로 쓴다.
    - BENCH_HOLD 메시지에 `source` 와 축을 넣는다. 골든 벡터 갱신이 필요하니 메시지 세대를 올린다.
    - 펌웨어는 축과 원천의 짝을 검사한다(M·H↔kth, L·R↔mt). 맞지 않는 짝은 거부한다.
    - 원천 손실은 KTH 는 `BENCH_KTH_LOST`, MT 는 기존 엔코더 결함(`enc_stuck` 등)이 맡는다. 손실이면 그 축을 세운다.
  - 호스트·도구: `mcu_link/messages` 의 메시지·인코딩, `plant/bench_limits`, `mcu_host` 의 큐, `tools/bringup.py commission` 의 `--bench-*`·`--stop-kth-turns`·`--hold-*`, `mcu_model` 의 벤치 동작.
  - 시험: 기존 진단 브랜치 시험(골든 벡터, 펌웨어 호스트 시험, 모형 시험, `test_bringup_bench_tool`).
- **MISO 원시 0 근처 위험 수정**(진단 기록 2026-11-27 '남은 위험'):
  - 지금 규칙: 직전에 센 각이 원시 0 에서 ±512 안이면 0x0000 프레임도 센다. MISO 가 low 로 붙으면 0x0000 이 CRC 를 통과하므로, 가짜 이동(예: −256)을 세고 hold 가 듀티 상한까지 밀 수 있다. 3 ms 손실 정지도 걸리지 않는다.
  - **프레임만으로는 가릴 수 없다**(Codex 계획 1 회차 P1-2): KTH7801 각도 프레임은 각도 12비트 + CRC 4비트뿐이고, 원시 0 의 CRC 도 0 이다. 그래서 '0 을 세는 범위를 ±32 로 좁히기'는 쓰지 않는다. 진단 태그의 정상 영점 정지 시험(직전 33 → 0)을 깨기 때문이다. 0x0000 을 세는 범위는 진단 그대로 ±512 다.
  - 대신 **구동 중 무변화 감시**를 펌웨어 계약으로 둔다(P1-3).
    - hold 의 **실제 적용 출력**(최소 듀티·D 항·상한을 모두 거친 뒤 듀티 레지스터에 쓰는 값)의 크기가 문턱(잠정 0.05) 이상인 MCU 시간이 연속 T(잠정 0.3 s) 쌓이는 동안 이동량 카운터가 1 카운트도 바뀌지 않으면 `BENCH_KTH_LOST` 로 세운다.
    - 이 타이머는 MCU 시각으로 재고, 다시 보낸 `BENCH_HOLD` 로 초기화되지 않는다.
    - 이 정지 뒤의 해제·재 ARM 은 **원시값이 0x0000 이 아닌, 센 프레임**이 온 뒤에만 된다. 붙은 MISO 는 0 만 내므로 재 ARM 할 수 없다. 정상 영점 정지는 서 있는 동안 센서 잡음(11-27 정지 흔들림 1–2 카운트)으로 비영 프레임이 온다.
    - 문턱·T 는 실물 전 잠정값이다. 코깅으로 실제 축이 서도 이 감시에 걸려 멈출 수 있다 — 멈추는 쪽이라 받아들인다.
  - 진단 코드의 순서 문제도 고친다: 최소 듀티를 적용한 **뒤** D 항을 빼서 출력이 최소 듀티 아래로 가던 것, 데드밴드 안에서 D 항이 남던 것.
  - **합격 시험(펌웨어 호스트):**
    - 기존 33→0 영점 정지 보존.
    - 경계 ±512/±513→0. 부팅부터 전부 0. 정상 정지 뒤 고착.
    - `min_duty=0`. 데드밴드 안 무출력 유지. 데드밴드 밖 실정지(코깅 모사). 느린 1 카운트 이동. 왕복 잡음.
    - 고착을 유지한 채 CLEAR·재 ARM 거부.
- **우회할 수 없는 것**(그대로): 과전류, 드라이버 결함(`DRIVER_FAULT_*`, TSD 래치 포함), STOP, DISARM, 명령 만료(링크 끊김), IWDG, 사이클 초과, `BENCH_KTH_LOST`.
- **검증:** 호스트·모형 시험, 노트북 교차 빌드(이미지 크기·제품 문자열), 완료 조건 1 의 빌드 거부 시험, ws1 전체 pytest.

## 2. A2 — 2차 우회 비트

BENCH_SET 의 우회 비트를 늘린다. 틀은 A1 그대로다.

| 비트 | 뜻 | 기본 |
|---|---|---|
| `kth_invalid` | **결정 필요(아래)** — 지금 M/H 구동 중 그 축의 KTH 가 무효가 되면 FAULT 다 | — |
| `enc_stuck` | MT 축(L·R) 바퀴 엔코더 정지 검출로 멈추지 않음 — 켜면 그 축의 `mt` hold·거리 정지는 쓸 수 없음(측정 신뢰 없음) | 끔 |
| `enc_polarity` | MT 축 바퀴 엔코더 극성 검출로 멈추지 않음 — 켜면 `mt` hold 는 거부(부호를 믿을 수 없음) | 끔 |
| `--bench-absent` (도구) | 부재 부품의 무효 표식을 판정에서 뺌. 기존 `steer`/`lift`/`wheels` 부재 계약에 맞추고, **구동 중인 축의 고장은 가리지 않는다** | 없음 |

- **`axis_lock` 은 넣지 않는다**(P2): fw-bench 는 이미 비영 출력 한 구간 동안 축을 잠그고, GUI 는 실행마다 한 축이다. 풀어야 하는 사례가 없다. ARM 단위 잠금을 새로 넣지도 않는다(M/H 실행이 첫 0 의 L 에 묶이는 문제를 피함).
- **결정이 필요한 것(A2 전, Codex P1-4):**
  - `enc_stuck`·`enc_polarity` 의 실제 정지는 펌웨어가 아니라 호스트(`bringup.early_stop`)에 있다. 기존 설계는 탈거 벤치에서 두 호스트 정지의 우회를 허용했다.
  - `kth_invalid` 는 선택 축의 구동 중 피드백 소실을 푼다.
  - 기본안: **선택 축의 구동 중 피드백 소실(KTH 무효·MT 정지/극성)과 전류센서 무효는 우회 불가**(멈추는 쪽)로 둔다. 기존 탈거 벤치 예외만 '부재 부품'(`--bench-absent`, 그 축을 구동하지 않을 때만)으로 계승한다.
  - 펌웨어에 효과 없는 우회 비트는 만들지 않는다. 사용자·총괄 결정에 따라 표를 확정한다.

- 멈추는 쪽은 비트가 없다(1 절).
- 우회가 걸려 있으면 STATE 고장 비트 31 `BENCH_OVERRIDES` 가 선다(지금과 같음).
- **검증:** 비트마다 켬/끔 호스트 시험, 멈추는 쪽은 비트로 꺼지지 않음을 고정, 골든 벡터 갱신.

## 3. B — 벤치 세션 백엔드 `tools/bench_console.py`

- **실행:** Jetson 에서 `python tools/bench_console.py --device /dev/forklift-mcu --host 127.0.0.1 [--console-lan --console-origin-host H]` 로 띄운다.
  - 보드를 실행기 잠금으로 연다. 제품 문자열에 `bench` 토큰이 없으면 시작을 거부한다.
  - 콘솔 서빙은 실차 콘솔과 같은 `LiveServer` 다(Origin 검사·루프백 기본 그대로).
- **보드 쓰기 주체는 하나**(Codex 계획 1 회차 P1-5): 실행 스레드 하나가 보드 쓰기를 모두 맡는다. 다음 셋은 BENCH_SET 대기부터 ARM, 구동, 정리까지 **어느 단계에서든** 그 실행을 취소한다.
  - 소유 연결의 단절.
  - heartbeat 만료(lease).
  - STOP — 관찰자와 공통 Escape 키에서도 오며, 공용 채널의 우선 처리 이름 `stop` 을 그대로 쓴다.
  - 취소는 미전송 동작을 버리고 이후 갱신(hold 재전송)을 막는다. 이미 MCU 가 STOPPING 이면 기존 전기제동 정리 절차를 지킨다.
  - **HIL 합격:** ① USB 를 살린 채 브라우저만 끊기 ② 브라우저를 살린 채 heartbeat 만 끊기 ③ Jetson 송신 자체를 끊기(MCU 명령 만료). 각각 마지막 비영 명령 시각, 정지까지 지연, DISARM 확인 여부를 기록한다.
- **중복 실행 방지(P2):** 요청에 토큰을 붙이고, 같은 토큰의 결과는 재사용한다(프런트의 ACK 재송신이 같은 시험을 다시 시작하지 않게). `bench_run` 과 `clear_faults` 는 하나의 직렬 큐로 처리한다. 보드 fd 의 `flock` 은 대기·정리까지 유지한다. REAL 운영 콘솔·teleop·CLI 가 먼저 또는 나중에 잠금을 잡는 경우, 두 탭의 동시 시작을 시험한다.
- **Origin:** `LiveServer` 에 허용 목록을 늘 준다(루프백 기본, LAN 은 `--console-lan`·허용 Origin). control·media 양쪽에서 누락·불일치를 거부한다.
- **확인 문구(P2):** 기존 `commission` 의 확인 — 범위 우회를 끈 M/H 의 `window`, hold 의 축 조건, 전원 스위치 확인, 큰 바퀴 실행의 TTY 재입력 — 은 웹 요청의 명시 필드로 옮긴다(`power_switch_in_hand`, `wheels_lifted`, `window`, 큰 실행 확인 문구). 서버가 확인값을 대신 참으로 채우지 않고, 제어 스레드가 stdin 을 기다리지 않는다. 모형의 제품 문자열 주입은 시험 경계에만 둔다.
- **명령**(WebSocket 제어 채널, lease 하나):
  - `bench_run {axis, source: kth|mt|none, mode: duty|hold, duty, seconds, stop: {turns?|counts?}, hold: {target: zero|here|abs:N|rel:±N, kp, ki, kd, deadband, min_duty, sign}, bypass: [...], bench_duty_max, bench_time_max, absent: [...]}` → 기존 `bringup.py commission` 의 실행 함수를 같은 프로세스에서 부른다.
    - 원천이 `mt` 면 `zero`·`abs` 를 거부한다.
    - 카운트/회전은 원천 설정에서 읽는다.
    - 도구 인자도 원천 무관하게 맞춘다: `--stop-turns`/`--stop-counts` + `--source`. 기존 `--stop-kth-turns` 는 `--source kth --stop-turns` 의 별칭으로 남긴다.
  - `bench_stop`(즉시 0 + DISARM), `bench_disarm`, `clear_faults {cause}`(FAULT·ESTOP 일 때만, 6.5 절 순서는 화면 안내).
  - 실행 중 다른 `bench_run` 은 거부한다.
- **스트림:** STATE 를 약 20 Hz 로 보낸다(화면 갱신용). 무효 측정값(KTH 무효 시 NaN)은 `null` 과 사유로 보낸다. 공용 WebSocket 인코더는 NaN 이 든 메시지를 버리기 때문이다(P3). 드라이버 상태는 네 바이트를 그대로 보낸다(BOOT 의 `C0/00/00/00`, 과열 `0xE2` 가 보이게). 필드: 모드, 축별 듀티·전류, 드라이버 상태 바이트, 원천별 측정(KTH 이동량 카운터와 각, MT 바퀴 카운트), hold 목표·오차, 고장 비트, 우회 표식. 단위는 원천 설정으로 카운트·바퀴·각을 함께 보낸다.
- **기록:** 실행마다 `~/bench_runs/<모드>_<축>_<시각>/` 를 **배타 생성**하고 `run.jsonl`·`result.json` 를 남긴다. 기존 CLI 의 append 열기는 쓰지 않는다. 같은 시각의 두 실행, 디스크 오류, 중단 뒤에도 이전 기록이 보존되는지 시험한다. 우회 목록과 `--cause` 도 기록한다.
- **결과 판정은 둘로 나눈다(P2: `chk` 만으로는 정착 실패 hold 도 PASS — 11-27 `hold_here2` 는 PASS 인데 정착 뒤 데드밴드 안 0.7 %):**
  - ① **실행·정리 정상**: `chk` 의 조건(`result ok`·`cleanup_confirmed`·`aborted` 없음·벤치 평상 외 고장 없음·마지막 DISARMED·네 축 듀티 0 확인, 기록 누락 없음).
  - ② **hold 목표 충족**: `abs(final_error) < deadband`, 정착함(`settled_after_s` 있음), 정착 뒤 데드밴드 안 비율 ≥ 0.8.
  - `BENCH_KTH_LOST` 는 발생 축과 ARM 전후를 구분해 적는다.
  - 판정·최고 전류·정지 사유는 20 Hz 화면 스트림이 아니라 **원래 STATE 기록**에서 계산한다(P3).
- **검증:** pty 위 `mcu_model`(벤치 이미지 모형, MT 는 모형의 엔코더 카운트)로 HIL 시험. KTH·MT 원천 각각 hold·거리 정지를 시험한다. 듀티 구동·hold·STOP·고장 해제·우회 표식을 돌리고, 링크 끊김이면 보드가 명령 만료로 서는지 본다. 4 CPU 로 돌린다.
