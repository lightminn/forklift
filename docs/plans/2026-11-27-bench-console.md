# 벤치 콘솔 — fw-bench 의 main 반영과 콘솔 '벤치' 화면 (2026-11-27)

- 상태: 계획 — 검토 수렴(Codex 적대적 12 회차, 독립 스레드 4 차 모두 '새 P1/P2 없음', 원자료 재계산 일치). 순서 A1a → B → C → A1b → A1c → A2(총괄 승인).
- 요청: 사용자 "모터 테스트 GUI 를 콘솔에 통합해서, 안전장치 우회도 가능하게". 총괄 전달 2026-11-27.
- 범위와 기본안 세 가지는 총괄 동의를 받았다(아래 0 절).
- 원칙: 실차 검사는 세션 한정으로 우회할 수 있다. 우회 불가는 멈추는 쪽만이다(메모 real-checks-bypassable).
- 수준: 학교 수준으로 단순하게. 화면 하나에 기존 콘솔 프런트를 재사용하고, Isaac·실차 콘솔 동작은 바꾸지 않는다.

## 0. 정한 것 (총괄 동의 2026-11-27)

1. **백엔드는 별도 도구** `tools/bench_console.py`(Jetson)다. 실차 운영 콘솔(`tools/real_autonomy.py --run --client real`)과 동시에 띄우지 않는다(같은 보드 잠금). 운영 판정·잠금 코드와 섞지 않는다.
2. **'원시 0 근처 MISO low 고착' 위험 수정은 A1 에 포함**한다.
3. **그래프는 canvas 에 직접 그린다**(외부 라이브러리 없음, 기존 `map.js` 방식).

4. **측정 원천을 축별로 고른다**(사용자 추가 요구 2026-11-27): 나중에 MT(MT6701 증분 엔코더, L·R 바퀴 모터축, ABZ 4체배 4,096 카운트/회전)도 쓴다. 그래서 위치·회전 측정을 원천과 무관한 틀로 만든다(아래 0.1).

### 0.1 측정 원천

| 원천 | 축 | 값 | 기준 | 카운트/회전 |
|---|---|---|---|---|
| `kth` | M(조향 KTH), H(승강 KTH) | 절대각 12비트 → 펌웨어 이동량 카운터(이어 붙인 누적) | 센서 원시 0(절대) | 4,096 |
| `mt` | L·R(바퀴 모터축) | 증분 ABZ 카운트(이미 있는 LPTIM 바퀴 카운트) | 실행 시작 위치(상대) | 모터축 1 회전 = `vehicle.yaml` 의 그 쪽 `motor_counts_per_rev`(지금 4,096) |
| `none` | 어느 축이든 | 측정 없음 — 듀티 구동만, 시간으로만 멈춤 | — | — |

- 축의 기본 원천: M→`kth`(조향), H→`kth`(승강), L·R→`mt`. 화면과 도구에서 바꿀 수 있다. 측정이 없는 조합은 hold 와 거리 정지를 고를 수 없다.
- 원천 설정의 출처는 하나다(Codex 3 회차 P2). KTH 는 4,096 고정. MT 는 `vehicle.yaml` 의 `wheel_counts.<쪽>.motor_counts_per_rev` 만 쓴다(L·R 이 달라도 각자).
  - 그 쪽이 `counts_per_wheel_rev` 형식이면 모터축 CPR 이 없으므로, MT 의 `N 회전` 정지와 MT hold 는 거부한다. `N 카운트` 정지와 듀티 구동은 된다.
  - 펌웨어는 CPR 을 스스로 정하지 않는다. 호스트가 회전을 카운트로 바꿔 보내고, hold 에는 그 원천의 CPR 을 메시지로 싣는다(KTH 는 4,096 이 아니면 펌웨어가 거부).
  - 시험: L/R CPR 이 다른 설정, 한쪽만 `counts_per_wheel_rev` 인 설정.
- **정지 조건·hold 를 원천 무관하게:** `N 회전`(KTH 는 센서축, MT 는 모터축) / `N 카운트` / 목표 위치. 바퀴 회전은 표시용 파생값이다.
  - KTH 목표: 영점(원시 0)·절대값·지금·`±N`.
  - MT 목표: 지금 위치·`±N 카운트`(영점 없음).
- **실물 MT 는 미장착**이다. 검증은 `mcu_model` 의 엔코더 모형으로 한다.

순서는 **A1a → B → C → A1b → A1c → A2** 다(총괄 승인 2026-11-27, 처음 동의한 A1 → A2 → B → C 에서 바꿈 — 기능은 빠지지 않고 듀티 구동 화면을 먼저 쓰게 된다). 독립 검토(P2)가 A1 이 진단 이식과 새 기능을 한 번에 검증해야 한다고 지적해 A1 을 셋으로 나눴다. 아래 1 절은 A1 전체의 계약이고, PR 의 몫은 이렇다:

- A1a — 벤치 빌드 격리(완료 조건 1), 벤치 wire 계약의 메시지 넷과 호스트 게이트, 연결 경계, `duty`·시간 상한 구동(측정 없음)과 STOP·정리, 진단 태그의 범위 우회 비트(`steer_range`·`lift_range`), 운영 판정기의 `bench<N>` 제외(3 절, A1a 의 CLI 기록부터 적용 — 우회 없는 CLI 기록도 제외되는 시험). 진단 태그의 hold 는 옮기지 않는다.
- A1b — M·H 의 KTH 카운터·MISO 수정·진행 감시·hold·거리 정지·판정 증거(합의대로 MISO 수정은 hold·거리를 여는 PR 에 함께).
- A1c — MT 원천(L·R hold·거리 정지). 원천을 고르는 틀은 A1a 부터 두고, 이 PR 전에는 `mt` 선택이 '아직 없음'으로 거부된다.
- B·C 는 A1a 뒤 듀티 구동으로 먼저 붙이고, A1b·A1c 가 들어오면 hold·거리 칸을 연다. A2 는 B·C 의 선행 조건이 아니다.

각 PR 은 Codex 수렴까지 돌리고, 최종 트리에서 ws1 전체 pytest 를 한 번 돌린다. 펌웨어 교차 빌드는 노트북에서 한다. 실물 확인은 사용자가 벤치 날에 한다.

### 0.2 물리 구성 안내 (독립 검토 P1, 총괄 결정 2026-11-27)

벤치 화면은 축 하나를 고르지만, 그것이 다른 출력 채널의 전기적 격리를 뜻하지는 않는다. 시운전(=벤치) 빌드의 `STOPPING` 은 고르지 않은 축까지 네 축 모두 전기제동을 건다(계약 3.4). 축 하나만 제동하는 동작은 `fw-single` 의 별도 계약이고 벤치 이미지는 그것을 쓰지 않는다.

- **강제하지 않는다**(총괄 결정, 사용자 원칙 '우회는 자유, 고정적 거부 금지'): 물리 구성은 화면 안내와 기록으로만 다룬다.
  - KTH·범위 우회(`kth_invalid`·`steer_range`·`lift_range`)를 체크하면 화면에 '권장: 기구에서 모터 분리'([부분 구성 절차](2026-11-25-bench-partial-parts.md) 3 절)를 보인다. 막지 않는다.
  - 실행 기록에 사용자가 고른 물리 구성(선택 입력: 기구 결합 / 분리 / 바퀴 들어 올림 등, 비워도 됨)을 남긴다.
  - 고장 해제 칸에 'VM 차단 후 해제 권장'([주말 인계](2026-11-27-weekend-bench-handoff.md) 6.5 절 순서)을 보인다. 막지 않는다.
- 시험: 안내 문구 표시, 물리 구성 입력이 비어도 실행·해제가 진행됨, 기록에 입력값(또는 빈 값)이 남음.

## 1. A1 — fw-bench 의 main 반영

진단 브랜치 `diag/fw-bench`(태그 `diag-fw-bench-3`, 14 커밋, 약 2,200 줄)를 main 의 정식 빌드 종류로 옮긴다.

- **벤치 이미지 = 별도 빌드 종류.** 지금처럼 `FW_BUILD=commission FW_MOTOR_OUTPUT=1 FW_BENCH=1` 이고, 제품 문자열 끝은 `bench<세대>` 다.
  - **완료 조건 1 — 운영 빌드에 못 들어감:** `FW_BUILD=normal`(운영)·`hil`·`fw-single` 과 `FW_BENCH=1` 의 조합은 configure 에서 `FATAL_ERROR` 로 멈춘다.
  - 벤치 코드는 `FW_CORE_BENCH` 로만 컴파일되고, 운영 이미지 바이너리에는 벤치 메시지 처리기가 없다. 이를 교차 빌드 시험으로 고정한다: 운영·HIL·fw-single 이미지의 `nm` 에 벤치 심볼 0 개, 벤치 조합 configure 실패.
  - **호스트 게이트(Codex 계획 1 회차 P1-1):** 벤치 세 송신 명령(`BENCH_SET`·`BENCH_HOLD`·`BENCH_ARM`)을 보낼 수 있는 것은 **벤치 전용 호스트 객체 하나**다(B 와 CLI 가 같은 객체를 쓴다). 조건은 셋이다. 같은 fd 에서 읽은 제품 문자열이 정확히 `forklift-mcu commission OPEN …` 접두부이고, 끝 토큰이 이 도구가 지원하는 세대(A1 은 MISO 수정으로 세대를 `bench5` 로 올리고 `bench4` 이하는 거부)이며, 그 연결의 첫 STATE 가 `COMMISSION_BUILD` 와 일치해야 한다.
    - 일반 `mcu_host`·REAL 운영 전송기·HIL·teleop 경로의 세 명령 송신은 거부한다. 운영 전송기의 쓰기 직전 보호는 지금 `not real_operating` 일 때만 막으므로, 벤치 세 명령은 **운영 권한 부여 전후 모두** 송신 바이트 0 이어야 한다(2 회차 P2).
    - B 도 같은 판별기를 쓴다. bench5 문자열과 `OUTPUTS_LOCKED` 또는 `HIL_PLANT` 가 함께 오면 거부한다.
    - **기존 도구의 무장 경로(4 회차 P2):** bench5 에서는 `bringup commission` 이 벤치 옵션이 없어도 늘 `BENCH_SET → BENCH_ARM → COMMISSION(0)` 으로 간다. 일반 commission·fw-single 은 운영 `ARM` 그대로다. 운영 HIL 모형(`--hil-plant`)과 벤치 pty 모형은 별도 프로필이다. 세 경로를 각각 합격 시험으로 고정하고, 진단 통합시험의 순서 기대(`SET` 뒤 공용 `ARM`)는 bench5 순서로 바꾼다.
    - 합격 시험: 일반 REAL·HIL·teleop 경로에서 벤치 세 명령(`BENCH_SET`·`BENCH_HOLD`·`BENCH_ARM`)의 송신 바이트 0. 재연결·부팅 변경·제품 문자열 누락·구세대·문자열과 STATE 불일치 각각에서 벤치 호스트도 거부.
  - **벤치 wire 계약(Codex 3 회차 P1-1):** 운영 v3 의 메시지(`ARM` 12 바이트, `STATE` 84 바이트, 모든 `STATE.flags` 비트 배정됨)는 길이도 필드 뜻도 바꾸지 않는다. 벤치는 **벤치 전용 메시지 넷**을 쓴다. 연결 계약 문서에 '벤치 확장' 절을 새로 두고, 그 wire 세대는 제품 토큰 `bench5` 로 정한다. 운영 `version` 3 과 그 고정 벡터는 그대로다.
    - `0x06 BENCH_SET`(DISARMED 에서만): `boot_id`·`echo_mcu_time_us`, `run_id`(u32, 0 아님), 구동 모드(`duty`·`hold`), 측정 축, 원천, 우회 비트, 축별 듀티·연속 시간 상한, 거리 정지 `stop_counts`(i32, 0 = 없음), `count_sign`(듀티 부호와 카운트 증가 방향의 관계, ±1 — KTH·MT 모두. hold 의 `sign` 은 이 값과 같아야 하고 다르면 거부, 6 회차 P1-1).
    - `0x07 BENCH_HOLD`: `boot_id`·`arm_gen`·`echo_mcu_time_us`·`valid_after_echo_ms`(운영 `COMMISSION` 과 같은 신선도 검사)와 `run_id`, 축, 원천, 목표 종류(`zero`·`abs:raw`·`here`·`rel:±N`)와 값, 그 원천의 CPR, 이득·데드밴드·최소 듀티·부호.
    - `0x08 BENCH_ARM`: 운영 `ARM` 의 `boot_id`·`echo_mcu_time_us` + `run_id`.
    - `0x82 BENCH_STATE`(MCU → 호스트, 벤치 이미지만, 매 `STATE` 와 짝). `boot_id`·`arm_gen`·`mcu_time_us` 는 짝 `STATE` 의 것을 쓰고 다시 싣지 않는다(6 회차 P2). payload 48 바이트, 리틀 엔디언, 이 순서로 고정하고 A1 에서 고정 벡터로 묶는다:

      | 필드 | 형 | 필드 | 형 |
      |---|---|---|---|
      | `pair_seq`(짝 STATE 헤더 seq) | u16 | `run_id` | u32 |
      | `result_run_id` | u32 | 측정 축 | u8 |
      | 원천 | u8 | 카운트 상태(`none_yet`·`valid`·`lost`) | u8 |
      | KTH 손실 비트(bit0 M, bit1 H) | u8 | 같은 틱의 원시각 | u16 |
      | 같은 틱의 누적값 | i32 | 해석된 hold 목표 | i32 |
      | 거리 기준 | i32 | 출력 차단 위치 | i32 |
      | 정지 사유 | u8 | `distance_confirm`(없음·도달·보류) | u8 |
      | 차단한 구동 요청 수 | u16 | 버린 쌍 수 | u16 |
      | 증거 나이(이 틱 기준, ms, 포화) | u16 | 구동 끝 시점의 증거 나이(ms, 포화, 0xFFFF = 아직) | u16 |
      | MCU 우회 비트 | u8 | 구동 상태(준비·구동·끝)·모드 | u8 |
      | 연결 세대 | u8 | 예약(0) | u8 |
      | 결과 칸의 측정 축 | u8 | 결과 칸의 원천 | u8 |

      합계 48 바이트. 결과 칸(`result_run_id`·정지 사유·차단 위치·`distance_confirm`·차단 수·구동 끝 증거 나이)은 자기 축·원천을 따로 가지므로, 다음 SET 이 측정 축·원천을 바꿔도 이전 결과의 축과 단위를 복원할 수 있다(7 회차 P2).

    - KTH 이동량 카운터는 `BENCH_STATE` 로 옮긴다. 운영 `STATE.kth_alt_crc_errors` 는 원래 뜻(CRC 변형 계수)으로 돌아간다.
    - 목표 계산은 MCU 가 한다. `here`·`zero`·`abs`·`rel` 은 **그 ARM 에서 처음 받아들인** `BENCH_HOLD` 의 틱의 원시각·누적값으로 한 번 해석해 고정한다(4 회차 P1-1). 뒤따르는 `BENCH_HOLD` 는 마감만 늘리고, 목표 종류·값·이득이 첫 것과 다르면 거부한다(진단 CLI 가 목표를 한 번 계산해 같은 값을 재전송하던 것과 같은 결과). 카운트 상태가 `valid` 가 아니면 hold 를 거부한다.
    - 시험: `here` 유지 중 축을 밀고 갱신(목표 불변), 움직이는 중 `rel` 갱신(목표 불변), 이전 ARM 의 `BENCH_HOLD` 가 새 ARM 에 도착(`arm_gen_mismatch`), 다른 `run_id`.
    - **짝과 귀속(4 회차 P1-2, 5·6 회차 P2):** `BENCH_STATE` 는 payload 48 바이트(wire 약 56 바이트)다. 짝 `STATE`(wire 92 바이트)와 한 쌍 약 148 바이트, 100 Hz 에서 약 15 kB/s, 1,024 바이트 TX 링에 6 쌍이다. 정확한 wire 길이는 COBS 에 따라 달라지므로 링 경계 시험은 최악 길이로 한다. 링에 **둘 다 들어갈 자리가 있을 때만** 한 번에 넣고, 아니면 둘 다 버리고 버린 쌍 수를 올린다. `BENCH_STATE` 의 헤더 seq 는 공통 송신 seq 를 그대로 잇고, payload 의 짝 seq 는 짝 `STATE` 의 헤더 seq 다. 호스트는 `pair_seq` 가 짝 `STATE` 의 헤더 seq 와 같은 둘만 짝으로 쓰고, 표본 연속성은 seq 가 아니라 `mcu_time_us` 간격(STATE 주기)으로 본다(송신 seq 는 삽입이 성공할 때만 올라, 쌍째 빠져도 seq 공백이 없음). 시험: STATE 하나만 들어갈 자리(둘 다 안 들어감), 링·seq 랩, 쌍째 빠져 seq 공백 없이 시각만 건너뜀.
    - **결과 칸:** 정지 사유·차단 위치·차단한 요청 수는 `result_run_id` 와 함께 **최초 원인으로 래치**되고, 뒤이은 명령 만료·DISARM·STOPPING 이 덮어쓰지 않는다. `distance_provisional` 도 최초 원인으로 남고, 뒤이은 확인은 별도 칸 `distance_confirm` 으로만 갱신한다(DISARM 뒤 비영 프레임이 와도). 이 칸들은 다음 `BENCH_ARM` 이 새 SET 을 소비할 때 비워진다. 벤치 호스트 객체(B·CLI 공통)는 이전 실행의 결과 칸을 `result_run_id` 로 읽기 전에는 다음 `BENCH_ARM` 을 보내지 않는다.
    - **재시작(5 회차 P2):** 같은 `boot_id` 에 새 호스트가 붙으면, 남은 결과 칸을 '이전 실행(이 호스트의 소유 기록 없음)'으로 기록해 회수한 뒤 진행한다. `boot_id` 가 바뀌었으면 이전 실행을 '중단·결과 유실'로 마감하고, 새 부팅 상태(결과 칸 비어 있음)를 확인한 뒤 진행한다. 시험: 결과 읽기 직전 호스트 종료, MCU 리셋, DISARM 뒤 비영 프레임으로 잠정 결과가 확인되는 경우.
    - 시험(한 시나리오): 한쪽 프레임 유실 → 거리 래치 → DISARM → 결과 읽기 지연 → 다음 SET(축과 원천을 모두 바꿈, 예: M·KTH → L·MT) → 호스트 재시작 → 새 호스트가 이전 결과를 이전 축·단위로 회수. 결과가 이전 `run_id` 로 남고, 다음 ARM 전에는 비지 않아야 한다. USB 배출 정체에서 쌍 단위 버림과 버린 쌍 수.
    - 벤치 이미지는 운영 `ARM` 을 `wrong_build` 로 거부하고, 비벤치 이미지는 0x06·0x07·0x08 을 unknown 으로 버린다. 호스트 송신 금지 목록에 `BENCH_ARM` 도 넣는다.
    - 시험: 운영 `ARM`·`STATE`·`DISARM` 고정 벡터 불변, 비벤치의 `BENCH_ARM` 거부, bench5 의 운영 `ARM` 거부(양방향), `BENCH_STATE` 고정 벡터.
  - **운영·비벤치 이미지는 벤치 메시지를 모름(P2):** 운영 normal OPEN, 일반 commission OPEN, HIL, fw-single 각각에 유효한 `0x06`·`0x07`·`0x08` 프레임을 보내면 unknown 으로 거부되고, 수락 seq·설정·출력이 바뀌지 않아야 한다.
    - 이를 비벤치 컴파일 변형의 호스트 시험으로 고정한다(호스트 시험용 코어는 지금 늘 `FW_CORE_BENCH=1` 이라 변형을 따로 만든다).
    - `nm` 심볼 확인은 보조로만 쓴다.
    - 잘못된 빌드 조합은 다른 인자가 모두 유효한 상태에서 *벤치 조합 사유로* configure 가 실패해야 한다.
  - **우회 수명(P1-6, 2 회차 P1-6):** 지금은 BENCH_SET 값이 DISARM 에서 초기화되지 않고 부팅까지 남는다. A1 에서 펌웨어 계약을 바꾼다.
    - **ARM 마다 그 실행의 BENCH_SET 수락이 필요하다.** SET 은 호스트가 만든 실행 식별자(무작위 32 비트)와 축에 묶이고, 같은 식별자를 실은 수락된 ARM 에서 **한 번 소비**된다.
    - **연결 경계(3·4·5 회차):** 이전 연결의 `SET → BENCH_ARM` 이 뒤늦게 처리되지 않게 한다.
      - **콜백 진입에서 먼저 막는다(6 회차 P1-2):** 연결 변경 콜백은 맨 처음 '경계 중' 표식을 세운다. 제어 틱은 이 표식이 서 있으면 RX 링을 읽지 않고 모든 명령 소비를 멈춘다. 그다음 메인 루프 문맥(지금처럼 `tud_task()` 가 도는 곳)에서 USB **RX** FIFO 를 비우고(`tud_cdc_n_read_flush`) 연결 세대와 경계 시각을 올린 뒤 표식을 내린다. 제어 틱은 세대가 바뀐 것을 보면 RX 링·부분 디코더·소비 전 SET 을 버린다. 두 문맥이 같은 FIFO·endpoint 를 만지지 않는다. **TX FIFO 는 비우지 않는다**(독립 검토 P1): DWC2 slave 포트는 IN 전송 중 인터럽트가 TinyUSB 송신 FIFO 를 그 자리에서 읽으므로 비우면 그 전송이 깨진다(보드 설계 2026-11-12 5.1 '옛 프레임'). 그래서 재개봉한 호스트가 받는 옛 바이트는 지금 설계대로 많아야 320 B(STATE 약 4 개)이고, 다시 열 때의 구분자 재동기와 아래 echo 규칙·재개봉 정리가 그것을 거른다. 시험(실보드, 벤치 날): 활성 IN 전송 중 포트를 닫았다 연다.
      - **ARM 은 연결 경계를 넘지 못한다:** 벤치 이미지는 연결이 바뀌면 ARMED 를 STOPPING → DISARMED 로 끝낸다. 그래서 늦게 도착한 이전 연결의 비영 `COMMISSION` 도 `not_armed` 로 거부된다.
      - 폐기보다 늦게 도착한 이전 연결의 벤치 명령은 **echo 규칙**이 막는다: 벤치 세 명령의 `echo_mcu_time_us` 는 마지막 경계 시각 이후여야 한다. 호스트가 재개봉 직후 경계 전 STATE(이미 USB 에 실려 있던 것)를 echo 하면 MCU 가 `stale_echo` 로 거부하고, 호스트는 더 새 STATE 로 다시 보낸다.
      - 시험: 두 프레임이 모두 링에 대기 중일 때 연결 변경, 연결 변경 콜백 직후 틱 선점, 이전 OUT 완료가 폐기보다 늦게 도착, **이전 STATE 쌍 → 경계와 같은 시각의 쌍 → 새 쌍** 각각을 echo 한 명령의 수락 여부, 기존 ARM 의 늦은 비영 `COMMISSION`, 만료 전 재연결, 같은 seq.
    - 쓰이지 않은 SET 은 만료되고, DISARM·FAULT·실행 종료에서 기본값으로 돌아간다.
    - 시험: 같은 부팅에서 `SET → 호스트 종료 → 새 세션`, `우회 실행 → 기본 실행`.
- **옮기는 것:**
  - 펌웨어: BENCH_SET(0x06, DISARMED 에서만, 우회 비트 `steer_range`·`lift_range`, 축별 듀티·연속 시간 상한), KTH 이동량 카운터(진단의 STATE `kth_alt_crc_errors` 칸에서 `BENCH_STATE` 로 옮김), BENCH_HOLD(PI + 감쇠 D + 최소 듀티 + 데드밴드).
  - **원천 일반화(0.1):** BENCH_HOLD 와 펌웨어 쪽 정지 조건이 원천을 받는다.
    - `kth` 는 이동량 카운터를 쓴다.
    - `mt` 는 그 축의 LPTIM 바퀴 카운트(이미 STATE `wheel_count_left/right` 로 보냄)를 시작 시점 기준 상대값으로 쓴다.
    - BENCH_HOLD 메시지에 `source` 와 축을 넣는다(위 벤치 wire 계약). 벤치 고정 벡터는 `bench5` 로 새로 만든다.
    - 펌웨어는 축과 원천의 짝을 검사한다(M·H↔kth, L·R↔mt). 맞지 않는 짝은 거부한다.
    - 원천 손실은 KTH 는 `BENCH_KTH_LOST`, MT 는 같은 규칙의 진행·방향 감시(아래)가 맡는다. 손실이면 그 축을 세운다. **정지는 모두 MCU 가 하고**, 호스트는 `BENCH_STATE` 의 정지 사유를 기록·판정만 한다.
  - **H 의 KTH 카운터와 손실 표식(Codex 2 회차 P1-2):** 진단 펌웨어는 M(`abs_frame[0]`)만 누적하고, STATE `kth_alt_crc_errors[0:2]` 는 M 카운터 하나의 하위·상위 16비트이며 `BENCH_KTH_LOST` 도 하나다. bench5 에서 이렇게 바꾼다.
    - 펌웨어는 M·H 각각의 이동량 카운터와 손실 상태를 둔다. H 는 `lift_m` 역변환이 아니라 승강 KTH 원시 프레임(`abs_frame[1]`)을 직접 이어 붙인다.
    - `BENCH_STATE` 가 **그 실행의 측정 축**(BENCH_SET 이 정함)의 원시각·누적값을 싣고, 축별 손실 비트 둘(M·H)을 함께 싣는다.
    - **손실·복구는 축과 실행에 한정한다(3 회차 P2):** 손실은 그 축을 측정하는 hold·거리 실행만 막는다. 다른 축의 실행, 시간 한정 듀티 구동, 무관한 결함의 CLEAR 는 막지 않는다.
    - 시험: M 고정·H 만 움직임, H 손실 중 M 정상 프레임이 와도 H 는 복구 안 됨, H 미장착에서 M 영점 hold 유지, H 미장착에서 무관한 결함 CLEAR → M 재 ARM.
  - **MT 의 단위(P1-3):** 지금 설정은 모터축 4,096 카운트/회전, 감속비 80 이라 바퀴 1 회전이 327,680 카운트다. 그래서 MT 의 '회전'은 **모터축 회전**(4,096 카운트, 원천 설정)으로 고정한다. 바퀴 회전은 `vehicle.yaml` 의 `counts_per_wheel_rev` 로 나눈 파생값으로만 보여 준다.
    - hold 의 이득 단위는 진단 그대로 rad 당 듀티이고, 카운트 → rad 는 메시지에 실린 그 원천의 CPR 로 바꾼다.
    - 엔코더 부호는 STATE 누적 전에 이미 적용되므로 `count_sign`(듀티와 카운트 방향의 관계, hold 의 `sign` 과 같은 값)과 겹쳐 적용하지 않는다. 거리 모드도 이 값을 SET 으로 받는다.
    - 모형 시험의 독립 기대값: 4,096 입력 카운트 = 모터축 1 회전 = 바퀴 1/80 회전. L/R·양방향.
  - **진행 감시(KTH·MT 공통, 3·4·5 회차):** 보드의 정지·극성 검출 문턱은 듀티 0.1 이고, LPTIM 안정 읽기가 실패하면 HAL 은 직전 값을 돌려준다. 그래서 '검출이 꺼져 있지 않음'을 피드백 유효의 근거로 쓰지 않는다. hold·거리 실행에서 펌웨어는 원천과 무관하게 한 규칙을 쓴다.
    - 매 틱의 카운트 변화는 **그 변화를 만든 이전 틱의 실제 적용 출력**(최소 듀티·D 항·상한을 거친 뒤 듀티 레지스터에 쓴 값)에 귀속한다. '밀기'는 귀속 출력의 부호가 같고 0 이 아닌 연속 틱이고, 그 부호가 바뀌거나 0 이 되면 끝난다. 기대 방향은 `count_sign × 밀기 출력 부호`다.
    - **타이머 하나(6·7 회차 P1-1):** 귀속 출력이 0 이 아닌 틱마다 MCU 시간을 더한다. 출력 0 틱은 더하지도 되돌리지도 않는다. 밀기마다 기준점을 두고(밀기 시작 위치), **그 기준점으로부터 기대 방향으로 R = 2 카운트에 이르면** 타이머를 0 으로 되돌리고 **기준점을 그 위치로 옮긴다**. 그래서 이미 인정한 위치로 돌아갔다 다시 오는 것(`0→2→1↔2`)은 새 진행이 아니다. 반전 이전의 이동, 반대 방향 변화, `+1/−1` 왕복은 되돌리지 않는다. 0.3 s 가 되면 정지한다. 출력 크기 문턱은 없다.
    - 그래서 역극성(늘 반대로 셈)과 고정 출력의 `±1` 잡음은 0.3 s 안에 서고, 짧은 구간을 번갈아도 새 밀기는 그 시작점에서 다시 2 카운트를 가야 한다(5 회차 반례: 290 ms 역방향 뒤 반전 → 새 밀기에서 2 카운트를 못 가면 300 ms 에 정지; 반전 직후 `+1` 하나로는 되돌리지 않음). 정상 제동은 새 밀기의 관성 구간이 먼저 반대로 가지만 모터가 돌아서 시작점을 2 카운트 넘으면 되돌려진다. 그 전에 데드밴드에 들어가면 출력 0 이라 시간이 멈춘다. 그보다 긴 제동, 저듀티에서 실제로 안 도는 축, 코깅으로 선 축은 멈춘다 — 멈추는 쪽이다.
    - **정지 원인을 나눈다(6 회차 P2):** 그 0.3 s 동안 KTH 프레임이 전부 정확히 0x0000 이었으면 `kth_zero_suspect`(MISO 고착 의심)이고, 그 축의 hold·거리 실행은 마지막 손실 이후 같은 축의 센 비영 프레임이 와야 다시 된다. 그 밖(유효 측정에서 진행 없음, MT 포함)은 `no_progress` 이고, 다음 ARM 에서 바로 다시 할 수 있다. 3 ms 프레임 손실은 그대로 `BENCH_KTH_LOST` 다.
    - 정지 판정은 그 틱의 명령 처리보다 먼저다. 만료 틱에 온 `BENCH_HOLD` 갱신·출력 반전·모드 전환은 정지를 늦추지 못하고, `BENCH_HOLD` 갱신은 타이머를 되돌리지 않는다. 데드밴드 안에서는 출력 0 이다(최소 듀티·D 항 없음, 아래 순서 수정).
    - 모형·펌웨어 호스트 시험(모형 내부 실제 이동과 보고 카운트를 따로 확인, 한 묶음): 시작부터 고정, 구동 도중 고정, 상한 0.04 의 저듀티 고정, 무출력 `here`, 저듀티 역극성, 정상 오버슈트 → 제동 → 데드밴드 정착은 통과, `299 ms → 출력 0 한 틱 → 다시 밀기`(타이머 유지), 반복 반전(5 회차 반례), 반전 직후 기대 방향 `+1` 하나(되돌리지 않음), 고정 출력의 `+1/−1` 왕복(정지), 고정 출력의 `0→2→1↔2`(첫 2 에서 한 번만 되돌리고 그 뒤 정지), 만료와 출력 반전이 같은 틱, 정지 후 같은 HOLD 갱신, 거리 모드의 역극성(KTH·MT), 무잡음 비영 KTH 의 `min_duty > 0` 정체(`no_progress`, 다음 ARM 가능)와 원시 0 고착(`kth_zero_suspect`, 비영 프레임 전 재실행 거부)을 따로.
  - **판정 증거의 시효(4·5 회차 P2):** 펌웨어 안의 마지막 증거 시각은 KTH 면 제어 틱에서 마지막으로 센 비영 프레임, MT 면 마지막 기대 방향 진행의 MCU 시각이다(100 Hz 스냅숏이 아니라 1 kHz 제어 틱 기준). wire 에는 이 시각 대신 `BENCH_STATE` 의 '증거 나이'(이 틱 기준 ms)와 '구동 끝 시점의 증거 나이'를 싣는다. hold 의 '목표 충족'은 **구동 끝 전이(감시 정지·거리 래치·종료 0·명령 만료 중 처음) 시점의 증거 나이**가 KTH 0.1 s, MT 1 s 안일 때만이고, 넘으면 '판정 보류(증거 나이 x s)'다(6 회차 P2). MCU 가 그 시점의 나이를 결과 칸에 고정하므로, 그 뒤 정리 0 구간의 새 프레임이나 정리 중 만료는 판정에 들어가지 않는다. 나이는 ARM 마다 '아직'으로 시작해 이전 ARM 의 증거도 쓰지 않는다. 시험: 정리 중 움직임으로 생긴 비영 프레임, 정리 중 만료, 이전 ARM 의 증거. MT 는 정지 중 카운트가 생기지 않으므로 오래 정착한 MT hold 는 보류가 정상이다(실물 MT 미장착, 0.1 절).
  - **구동 모드는 ARM 에 묶는다(5 회차 P1-3):** SET 의 모드가 `duty` 면 그 ARM 에서 `BENCH_HOLD` 를 거부하고, `hold` 면 비영 `COMMISSION` 을 거부한다(진단 코어는 `COMMISSION` 을 받으면 `hold_on` 을 꺼 hold 감시를 벗어났음). **구동 시작은 첫 `BENCH_HOLD` 수락 또는 첫 비영 `COMMISSION` 수락**이다(물리 출력과 무관, 6 회차 P2). 그 전의 0 명령(무장 직후 L(0), 선택 축의 준비 0 반복)은 준비다. 구동 시작 뒤 받아들인 0 `COMMISSION` 은 그 ARM 의 구동을 끝내는 전이다. 감시 정지·거리 래치·명령 만료, 그리고 구동 중 `FAULT`·`ESTOP` 전이(결과 래치 전 `nFAULT` 포함, 정지 사유 `fault`)도 같은 끝 전이다(10 회차 P2). **끝 전이에서 MCU 는 스스로 기존 정리(STOPPING 의 전기제동 → DISARMED)로 간다**(7 회차 P2). 단 `FAULT`·`ESTOP` 끝 전이는 **결과 칸 래치만 공통**이고, 출력과 모드는 기존 그대로다: `ESTOP` 의 안전 출력, `FAULT` 래치가 남고 STOPPING·DISARMED 로 바꾸지 않는다. 한 틱짜리 `nFAULT` 라도 명시적 CLEAR 전에는 다시 ARM 할 수 없다(11 회차 P1, 시험으로 고정). 그래서 끝난 뒤 남은 명령 마감이 만료돼도 `COMMAND_TIMEOUT` 이 붙지 않는다(만료가 끝 전이보다 먼저였을 때만 붙음). 끝난 뒤의 0·비영 명령은 `stopping`·`not_armed` 로 거부되고 고장으로 세지 않는다. 벤치 호스트는 끝 전이를 본 뒤 기존 CLI 의 '종료 뒤 0.5 s 0 전송'을 하지 않고, 정상 정리 경로에서는 DISARMED 를 기다린다(`FAULT`·`ESTOP` 이면 3 절의 실패 마감). 시험: 종료 0 이 만료보다 먼저 온 뒤 기존 정리 구간을 끝까지 거쳐도 실행·정리 정상 판정 유지. 시험: 첫 HOLD → 같은 축 비영 COMMISSION → HOLD 갱신, 0.3 s 감시 만료 틱에 HOLD 갱신·모드 전환 명령 각각(정지 우선, 같은 ARM 에서 출력 재발생 없음), **L(0) → M/H 준비 0 반복 → 무출력 HOLD 수락 → 종료 0 → 늦은 HOLD**(거부), 종료 0 과 명령 만료가 같은 틱.
  - **듀티 + 거리 정지의 펌웨어 경로(P1-5):** 거리 정지는 펌웨어가 한다. BENCH_SET 에 `{axis, source, stop_counts(부호 있는 상대값)}` 를 싣는다.
    - 기준 카운트는 **첫 비영 구동 직전 MCU 틱**에 한 번 잡는다. ARM 준비 중 표류와 재전송은 빼기 위해서다.
    - 목표를 넘으면 그 ARM 동안 출력 0 을 유지한다. **`BENCH_HOLD` 를 포함한 모든 구동 요청**이 출력과 마감을 바꾸지 못한다(3 회차 P1-4). 차단한 요청 수와 정지 사유 `distance_reached` 는 `BENCH_STATE` 에 다음 SET 소비까지 남는다(DISARM 뒤에도 호스트가 읽을 수 있게).
    - 거리 정지는 `duty` 모드에만 있으므로 `BENCH_HOLD` 는 위 모드 규칙으로 거부된다. SET 에서 고른 축이 아닌 축의 비영 명령도 거부한다. 무장 직후 L 의 0 준비 프레임은 받는다.
    - 시험에 목표 통과 틱에 `BENCH_HOLD` 와 비영 `COMMISSION` 이 함께 들어오는 경우, 다른 축 비영 명령, 명령 만료와 거리 도달의 정지 사유 구별을 더한다.
    - 시험: LPTIM 16 비트 `65535↔0`, STATE 32 비트 `0x7fffffff↔0x80000000`, 음방향, 반범위 밖 목표 거부, 도중 재부팅·카운트 유실.
  - 호스트·도구: `mcu_link/messages` 의 메시지·인코딩, `plant/bench_limits`, `mcu_host` 의 큐, `tools/bringup.py commission` 의 `--bench-*`·`--stop-kth-turns`·`--hold-*`, `mcu_model` 의 벤치 동작.
  - 시험: 기존 진단 브랜치 시험(골든 벡터, 펌웨어 호스트 시험, 모형 시험, `test_bringup_bench_tool`).
- **MISO 원시 0 근처 위험 수정**(진단 기록 2026-11-27 '남은 위험'):
  - 지금 규칙: 직전에 센 각이 원시 0 에서 ±512 안이면 0x0000 프레임도 센다. MISO 가 low 로 붙으면 0x0000 이 CRC 를 통과하므로, 가짜 이동(예: −256)을 세고 hold 가 듀티 상한까지 밀 수 있다. 3 ms 손실 정지도 걸리지 않는다.
  - **프레임만으로는 가릴 수 없다**(Codex 계획 1 회차 P1-2): KTH7801 각도 프레임은 각도 12비트 + CRC 4비트뿐이고, 원시 0 의 CRC 도 0 이다. 그래서 '0 을 세는 범위를 ±32 로 좁히기'는 쓰지 않는다. 진단 태그의 정상 영점 정지 시험(직전 33 → 0)을 깨기 때문이다. 0x0000 을 세는 범위는 진단 그대로 ±512 다.
  - 대신 위 **진행 감시(KTH·MT 공통)**를 펌웨어 계약으로 둔다. 진단 태그에는 이 감시가 없고(이전 계획 회차의 '출력 0.05 이상 0.3 s 무변화' 안은 쓰지 않음), A1 에서 새로 넣는다.
    - `kth_zero_suspect` 뒤에는 그 축의 hold·거리 실행이 **마지막 손실 이후 같은 축의 센 비영 프레임**이 온 뒤에만 다시 된다(아래 복구 조건). 붙은 MISO 는 0 만 내므로 다시 시작할 수 없다.
    - 0.3 s 는 실물 전 잠정값이다.
  - 진단 코드의 순서 문제도 고친다: 최소 듀티를 적용한 **뒤** D 항을 빼서 출력이 최소 듀티 아래로 가던 것, 데드밴드 안에서 D 항이 남던 것.
  - **저출력 고착(2 회차 P1-1):** 진행 감시에 출력 크기 문턱이 없으므로, 0.05 아래 출력에서 MISO 가 붙어도 0.3 s 안에 선다(진단 계획 2 회차의 별도 '전부 0 연속 감시'는 이 규칙에 합쳐져 따로 두지 않는다). 데드밴드 안 무출력 유지(정상 33→0 뒤 출력 0)는 출력 0 이라 시간이 쌓이지 않는다.
  - **거리 정지와 0x0000(3 회차 P1-2):** 0x0000 프레임으로 넘거나 들어온 걸음으로 거리 목표를 넘으면, 그 틱에 **출력을 끊고 래치**한다(정지 사유 `distance_provisional`). 확인을 기다리며 계속 밀지 않는다(11-27 실측 20 회전/s 로 0.3 s 더 밀면 약 6 회전). 그 뒤 센 비영 프레임의 부호 있는 변위가 목표를 넘었으면 `distance_reached` 다. 못 넘었으면 가짜 걸음과 정상 교차 뒤 반동을 가릴 수 없으므로 '판정 보류'로 남긴다(출력은 이미 끊김, 4 회차 P2). 실행이 끝날 때까지 비영 프레임이 없어도 '판정 보류'다.
  - **무출력 hold 유지와 목표 검증을 나눈다(3 회차 P1-2):** 원시 256 에서 `zero` hold 중 MISO 가 붙으면 가짜 256→0 으로 오차가 사라져 출력이 0 이 되고, 진행 감시도 출력 0 이라 걸리지 않는다. 정상 33→0 과 같은 프레임이라 펌웨어가 가릴 수 없다. 그래서 출력 0 유지는 그대로 두고(멈추는 쪽과 같음), **증거 시효(KTH 0.1 s) 안에 센 비영 프레임이 없으면** 결과를 '목표 충족'이 아니라 '판정 보류(0 프레임만 — 고착과 구별 불가)'로 적는다(위 '판정 증거의 시효'). 정착 구간 앞쪽의 비영 프레임은 증거가 아니다.
  - **복구 조건:** 마지막 손실 이후 **같은 축**에서 정상적으로 센 비영 프레임. 시험은 센서 잡음에 기대지 않고 그 프레임을 명시적으로 넣는다.
  - **합격 시험(펌웨어 호스트):**
    - 기존 33→0 영점 정지 보존: HOLD 를 계속 갱신하며 **0.3 s 를 넘겨** 유지(출력 0 이라 진행 감시 시간이 쌓이지 않음). 증거 시효 안에 비영 프레임이 없으면 호스트 판정은 '판정 보류'.
    - 기존 최소 듀티 시험(한 ARM 에서 최소 듀티·목표를 바꾸던 것)은 ARM 별 설정 시험과 갱신 중 변경 거부 시험으로 옮긴다.
    - 원시 256 에서 `zero` hold 중 고착 → 출력 0 유지, 판정 '판정 보류'(가짜 성공 아님). 데드밴드 안 비영 프레임 하나 뒤 고착도, 마지막 1 s **안에서** 정상 표본 직후 고착(끝에서 0.99 s 전 비영 하나)도 '판정 보류'.
    - 실제 거리 교차 뒤 원시 0 이 계속 옴 → `distance_provisional` 래치, 출력 0, 판정 보류.
    - `here` 를 원시 16 에서 잡고 kp 1·ki=kd=min_duty=0·데드밴드 12, 고착 0 → 진행 감시로 0.3 s 안에 정지(2 회차 반례).
    - 경계 ±512/±513→0. 부팅부터 전부 0. 정상 정지 뒤 고착.
    - `min_duty=0`. 데드밴드 안 무출력 유지. 데드밴드 밖 실정지(코깅 모사, 0.3 s 에 정지). 느린 이동(0.3 s 안에 기준점에서 2 카운트면 유지, 1 카운트뿐이면 정지). 왕복 잡음.
    - 고착을 유지한 채 그 축의 hold·거리 실행 거부. 다른 축 실행과 무관한 결함의 CLEAR 는 가능.
- **우회할 수 없는 것**(그대로): 과전류, 전류센서 무효, 드라이버 결함(`DRIVER_FAULT_*`, TSD 래치 포함), STOP, DISARM, 명령 만료(링크 끊김), DRVOFF·무장 절차, IWDG, 사이클 초과. `BENCH_KTH_LOST` 는 hold·거리 정지의 기능 요건이라 우회 대상이 아니다(2 절).
- **검증:** 호스트·모형 시험, 노트북 교차 빌드(이미지 크기·제품 문자열), 완료 조건 1 의 빌드 거부 시험, ws1 전체 pytest.

## 2. A2 — 2차 우회 비트

BENCH_SET 의 우회 비트를 늘린다. 틀은 A1 그대로다.

| 비트 | 뜻 | 기본 |
|---|---|---|
| `kth_invalid` | M/H 구동 중 그 축의 KTH 무효로 FAULT 가 되지 않음(듀티 구동, 시간 상한으로 끝남). 펌웨어 비트 | 끔 |
| `enc_stuck` | MT 축(L·R) 바퀴 엔코더 정지 검출로 멈추지 않음. 실제 정지가 호스트(`bringup.early_stop`)에 있으므로 호스트 쪽 우회다(펌웨어는 지금처럼 보고만) | 끔 |
| `enc_polarity` | MT 축 바퀴 엔코더 극성 검출로 멈추지 않음. 호스트 쪽 우회 | 끔 |
| `--bench-absent` (도구) | 부재 부품의 무효 표식을 판정에서 뺌. 기존 `steer`/`lift`/`wheels` 부재 계약에 맞추고, **구동 중인 축의 고장은 가리지 않는다** | 없음 |

- **`axis_lock` 비트는 넣지 않는다**(P2): 1 절대로 무장 직후 L(0) 준비 프레임은 받고, 비영 출력은 SET 에서 고른 축으로만 제한된다. GUI 도 실행마다 한 축이라 풀어야 하는 사례가 없다.
- **결정(총괄 2026-11-27, 사용자 원칙 real-checks-bypassable):**
  - `enc_stuck`·`enc_polarity`·`kth_invalid` 는 **구동 중인 축에서도 우회할 수 있다**(세션·ARM 한정, '우회 중' 표시, 기록). 듀티 구동(개루프)에서 의미가 있다.
  - **피드백이 필요한 기능은 기능 요건으로 거부한다**(안전 검사가 아니라 측정 없이는 동작할 수 없으므로 우회 대상이 아님). hold 와 거리 정지(`N 회전`·`N 카운트`)는 그 원천이 무효이거나 원천의 검출이 우회 중이면 시작하지 않는다. 실행 중 원천이 무효가 되면 그 실행을 멈춘다(MCU 가 멈춘다: 프레임 손실 `BENCH_KTH_LOST`, 진행 감시 `no_progress`·`kth_zero_suspect`). 듀티 구동은 시간 상한으로 끝난다.
  - **전류센서(IPROPI) 무효는 우회 불가**다. 펌웨어 과전류 보호의 전제다(과전류 = 멈추는 쪽).
  - `--bench-absent` 는 그대로다(부재 축은 구동하지 않음).
  - 펌웨어에 효과 없는 우회 비트는 만들지 않는다. `enc_stuck`·`enc_polarity` 는 호스트 쪽 우회로만 둔다.

- 멈추는 쪽은 비트가 없다(1 절).
- **MCU 우회**(`steer_range`·`lift_range`·`kth_invalid`)의 표식은 `BENCH_STATE` 의 우회 비트에 싣는다. 운영 v3 `STATE.fault_flags` 의 25–31 은 0 예약이므로, 진단이 쓰던 비트 31 `BENCH_OVERRIDES` 는 bench5 에서 쓰지 않는다(4 회차 P2). 호스트 우회(`enc_stuck`·`enc_polarity`)는 어느 MCU 우회 비트도 켜지 않고 화면·기록에만 그 축의 호스트 우회로 남는다. 시험으로 둘 다 고정한다.
- **검증:** 비트마다 켬/끔 호스트 시험, 멈추는 쪽은 비트로 꺼지지 않음을 고정, 골든 벡터 갱신.

## 3. B — 벤치 세션 백엔드 `tools/bench_console.py`

- **실행:** Jetson 에서 `python tools/bench_console.py --device /dev/forklift-mcu --host 127.0.0.1 [--console-lan --console-origin-host H]` 로 띄운다.
  - 보드를 실행기 잠금으로 연다. 제품 문자열에 `bench` 토큰이 없으면 시작을 거부한다.
  - 콘솔 서빙은 실차 콘솔과 같은 `LiveServer` 다(Origin 검사·루프백 기본 그대로).
  - **세션 접합(독립 검토 P2):** `LiveServer` 는 연결과 메시지만 전달하고, 브라우저 lease 는 실행기가 보내는 `tick` 에 대한 `echo` 로 유지된다(`main.js`). 벤치 세션도 같은 계약을 쓴다: `welcome` 에 `session: "bench"` 와 제품 문자열을 싣고, 실행 스레드와 별개의 주기(지금 실행기와 같은 주기)로 `tick` 을 보내며, `echo` 가 끊기면 lease 가 만료된다(3 절 취소 사유). C 에서 벤치 패널은 공용 연결·STOP·Escape 를 그대로 쓰고 자기 요청만 더한다.
- **보드 쓰기 주체는 하나**(Codex 계획 1 회차 P1-5): 실행 스레드 하나가 보드 쓰기를 모두 맡는다. 다음 셋은 BENCH_SET 대기부터 ARM, 구동, 정리까지 **어느 단계에서든** 그 실행을 취소한다.
  - 소유 연결의 단절.
  - heartbeat 만료(lease).
  - STOP — 관찰자와 공통 Escape 키에서도 오며, 공용 채널의 우선 처리 이름 `stop` 을 그대로 쓴다.
  - 취소는 미전송 동작을 버리고 이후 갱신(hold 재전송)을 막는다. 쓰기 주체가 **각 프레임의 첫 바이트를 쓰기 직전** 취소 표식을 확인한다(기존 `real_channels` 의 첫 쓰기 경계와 같은 방식). 그래서 `stop`·`disarm`·lease 반납/교체는 이미 대기 중인 ARM 이나 다음 비영 프레임보다 먼저 효력을 갖는다(2 회차 P1-6, 지금 `Bench.cycle()` 은 `poll()` 보다 먼저 보냄).
  - **부분 쓰기(4·5·6 회차 P1):** 벤치 호스트 객체는 REAL 링크의 `TtyLink`(비차단 tty, 여는 때마다 독 `POISON` = 비영 96 바이트 + 구분자)를 쓴다. 한 프레임의 나머지 바이트는 짧은 상한(20 ms) 안에서만 이어 쓰고, **이어 쓰기마다 취소·만료를 먼저 확인**해(기존 `real_loop_transport` 의 continuation 게이트와 같은 방식) 취소면 남은 바이트를 버리고 바로 독으로 바꾼다. 상한 안에 못 끝내도 독을 보내 MCU 디코더가 그 조각을 길이 초과로 버리게 한다. 단일 `0x00` 은 쓰지 않는다 — 본문·CRC 까지 나간 조각을 완성시켜 취소한 명령이 실행될 수 있기 때문이다. 기한(50 ms) 안에 독을 못 보내면 포트를 닫는다(MCU 는 명령 만료로 선다). 시험: `BENCH_ARM`·비영 `COMMISSION`·`BENCH_HOLD` 각각 구분자 직전 short write → STOP → `EAGAIN` 에서, 그리고 `EAGAIN` 이 20 ms 안에 잠깐만 나고 쓰기가 풀리는 경우에서, 그 프레임이 MCU 에 수락되지 않고 DISARMED 가 확인된다.
  - **재개봉 정리(7 회차 P1-2, 8 회차 P2):** 재개봉한 호스트는 **경계 이후 표본**을 받기 전에는 아무 명령도 보내지 않는다. 경계 이후 표본은 마지막으로 본 것과 `boot_id` 가 다르거나, 같은 부팅에서 연결 세대가 바뀐 쌍이다(처음 붙는 호스트는 첫 쌍). MCU 가 연결 경계에서 스스로 ARMED 를 끝내므로 호스트는 DISARM 을 보내지 않는다. 그 표본의 모드에 따라:
    - `BOOT`: 초기화 중으로 화면에 보이고 무장을 막은 채 DISARMED 를 기다린다(11-27 실물의 BOOT 정체가 그대로 보이게).
    - `DISARMED`: 바로 진행.
    - `ARMED`·`STOPPING`: 전기제동이 끝나 DISARMED·FAULT·ESTOP 이 되기를 기다린다(상한: 제동 유예 + 1 s, 넘으면 보고).
    - `FAULT`·`ESTOP`: 정지 확인으로 보고, 명시적 고장 해제 요청을 받을 수 있다.
    - 결과 칸이 비어 있으면(`result_run_id` 0 — 구동한 실행이 아직 없음) 회수할 것이 없다.
    - 시험: 구동 중 USB 재개봉 → 첫 새 STATE 지연 → 제동 유예 종료 → 정리 확인(그 사이 DISARM 송신 0), 연결 세대 값이 같은 새 부팅 → BOOT → DISARMED, 첫 새 표본이 FAULT 인 재개봉.
  - **상태별 정지 규칙 하나(8 회차 P1):** `BENCH_ARM` 을 아직 안 보냈으면 실행 취소만 한다. 보냈으면(수락 STATE 를 받았든 못 받았든) 0 `COMMISSION` 을 보내고 다음 표본을 본다. 구동 중이면 그 0 이 끝 전이라 MCU 가 스스로 STOPPING → DISARMED 로 가므로 **DISARM 을 보내지 않고** 기다린다(운영 계약에서는 DISARM 이 STOPPING 의 전기제동을 끊는다. 벤치 이미지는 끊지 않지만(계약 8.3) 보낼 이유도 없다). DISARM 은 **이번 STOP 의 0 이 받아들여졌음을 보여 주는 표본**(같은 연결 세대·`boot_id`·`arm_gen` 이고, `last_rx_seq` 가 그 0 의 seq 와 같거나 뒤 — 펌웨어와 같은 16 비트 모듈러 비교 `(int16)(last_rx_seq − zero_seq) ≥ 0`, 10 회차 P1)이 ARMED·구동 상태 '준비'일 때만 보낸다(0 이 구동을 끝내지 않은 경우, 9 회차 P1). 그 0 을 받기 전에 만들어진 '준비' 표본은 근거가 아니다. DISARM 의 수신 확인(`last_rx_seq`)만으로 끝내지 않고 DISARMED 표본까지 확인한다. 그사이 MCU 가 STOPPING 으로 넘어갔으면 벤치 이미지는 DISARM 으로 제동을 줄이지 않는다(계약 8.3) — 제동이 끝나 DISARMED 가 될 때까지 기다린다. ARMED·'구동'인데 0 이 아직 반영되지 않았으면 0 을 다시 보낸다. FAULT·ESTOP 이면 정지 확인으로 닫는다. `bench_stop` 과 공용 `stop` 은 같은 규칙이다. 시험: ARM 송신 직후 수락 STATE 전 취소, **같은 fd 에서 구동 중 STOP → 0 수락 → STOPPING STATE 지연**(제동 유예 동안 DISARM 송신 0), 준비 단계 취소(DISARM 송신), STOP 지연 중 **구동 전 '준비' 표본이 늦게 전달**되는 경우(DISARM 송신 0), 같은 순서의 seq 랩(지연 표본 `0xFFFE`, 첫 비영 `0xFFFF`, STOP 의 0 `0x0000` → DISARM 송신 0).
  - **HIL 합격:** ① USB 를 살린 채 브라우저만 끊기 ② 브라우저를 살린 채 heartbeat 만 끊기 ③ Jetson 송신 자체를 끊기(MCU 명령 만료). 각각 취소 뒤 새 비영 프레임 0 개, 마지막 유효 명령부터 출력 0 까지의 상한(명령 만료 이내), 링크가 살아 있으면 자동 정리에서는 그 실행의 끝 표본(구동 상태 '끝' 뒤 DISARMED)을, 준비 취소에서는 DISARM 응답을 확인한다.
- **중복 실행 방지(P2):** 요청마다 **요청별 식별자**(연결 토큰 + `request_seq`)를 붙이고, 같은 식별자의 결과는 재사용한다(프런트의 ACK 재송신이 같은 시험을 다시 시작하지 않게). `bench_run` 과 `clear_faults` 는 하나의 직렬 큐로 처리한다. 보드 fd 의 `flock` 은 대기·정리까지 유지한다. REAL 운영 콘솔·teleop·CLI 가 먼저 또는 나중에 잠금을 잡는 경우, 두 탭의 동시 시작을 시험한다.
- **Origin:** `LiveServer` 에 허용 목록을 늘 준다(루프백 기본, LAN 은 `--console-lan`·허용 Origin). control·media 양쪽에서 누락·불일치를 거부한다.
- **구동 중 범위 창(재확인 P1):** 범위 우회를 끈 M·H 실행은 지금 CLI 의 `CommissionSession.early_stop()` 처럼 **구동 중 사용자 지정 `window` 를 벗어나면 정지**한다. B 의 새 실행 루프가 이 검사를 그대로 가져가고, 창 밖으로 나가는 모형 시험으로 고정한다.
  - **두 우회 비트의 조합(재확인 P2):**

    | `kth_invalid` | 범위 우회 | 준비 수락 | 구동 중 정지 |
    |---|---|---|---|
    | 끔 | 끔 | KTH 유효일 때만 | 창 밖 → 정지, KTH 무효 → FAULT(펌웨어) |
    | 끔 | 켬 | KTH 유효일 때만 | 창 검사 없음, KTH 무효 → FAULT |
    | 켬 | 끔 | KTH 무효여도 수락 | KTH 가 **유효한 표본에서만** 창 검사(창 밖 → 정지). 무효(NaN) 표본은 창 정지로 치지 않고 건너뛴다. 다른 정지 조건(공통 정지 규칙)이 먼저 나지 않으면 시간 상한으로 끝 |
    | 켬 | 켬 | KTH 무효여도 수락 | 창 검사 없음, 다른 정지 조건이 먼저 나지 않으면 시간 상한으로 끝 |

    지금 `early_stop()` 은 NaN 도 창 정지로 처리하므로, 셋째 줄은 B 에서 바꾼다. 시험: 네 조합 각각 준비부터 구동 끝까지(무효 KTH 로 시간 상한까지 도는 것, 유효한 창 밖 표본에서 서는 것 포함). 부분 구성 절차의 '결합축 0.2 s' 와 '분리한 모터에서만 센서 없는 구동'은 총괄 결정대로 0.2 절의 안내·기록으로만 남는다(강제하지 않음 — 물리 조건은 운영자 몫).
- **확인 문구(P2):** 기존 `commission` 의 확인 — 범위 우회를 끈 M/H 의 `window`, hold 의 축 조건, 전원 스위치 확인, 큰 바퀴 실행의 TTY 재입력, M/H `|duty| > 0.3` 의 `vcc_watched` — 은 웹 요청의 명시 필드로 옮긴다(`power_switch_in_hand`, `wheels_lifted`, `window`, `vcc_watched`, 큰 실행 확인 문구). 빠진 요청은 서버가 거부하고, 명시 확인이 있으면 진행함을 둘 다 시험한다. 서버가 확인값을 대신 참으로 채우지 않고, 제어 스레드가 stdin 을 기다리지 않는다. 모형의 제품 문자열 주입은 시험 경계에만 둔다.
- **명령**(WebSocket 제어 채널, lease 하나):
  - `bench_run {axis, source: kth|mt|none, mode: duty|hold, duty, seconds, stop: {turns?|counts?}(turns 는 센서축/모터축 회전), hold: {target: zero|here|abs:N|rel:±N, kp, ki, kd, deadband, min_duty, sign}, bypass: [...], bench_duty_max, bench_time_max, absent: [...]}` → 기존 `bringup.py commission` 과는 **입력 검증·단위 환산·한계 계산만 공유**하고, 실행 루프는 B 에서 새로 쓴다(독립 검토 P2: 기존 실행 함수는 종료 0 을 반복하고 자체 정리를 하므로 1·3 절의 끝 전이·재개봉 규칙과 맞지 않음).
    - 준비 명령의 수락 조건: 계약 3.4 대로 M·H 의 KTH 가 무효면 듀티 0 준비 명령도 거부된다. 그 축의 `kth_invalid` 우회가 없으면 실행은 구동 전에 '구동 없음'으로 닫힌다. 시험: 시작부터 KTH 무효인 M 의 우회 없음(구동 없음 마감)과 우회 있음(준비 통과).
    - 원천이 `mt` 면 `zero`·`abs` 를 거부한다.
    - 카운트/회전은 원천 설정에서 읽는다(MT 모터축 CPR 이 없으면 `turns` 와 MT hold 를 거부).
    - 도구 인자도 원천 무관하게 맞춘다: `--stop-turns`/`--stop-counts` + `--source`. 기존 `--stop-kth-turns` 는 `--source kth --stop-turns` 의 별칭으로 남긴다.
  - `bench_stop`(위 상태별 정지 규칙), `bench_disarm`, `clear_faults {cause}`(FAULT·ESTOP 일 때만, 순서는 주말 인계 문서 `2026-11-27-weekend-bench-handoff.md` 6.5 절 '정지·고장 해제'를 화면에 안내).
  - 실행 중 다른 `bench_run` 은 거부한다.
- **스트림:** STATE 를 약 20 Hz 로 보낸다(화면 갱신용). 무효 측정값(KTH 무효 시 NaN)은 `null` 과 사유로 보낸다. 공용 WebSocket 인코더는 NaN 이 든 메시지를 버리기 때문이다(P3). 드라이버 상태는 네 바이트를 그대로 보낸다(BOOT 의 `C0/00/00/00`, 과열 `0xE2` 가 보이게). 필드: 모드, 축별 듀티·전류, 드라이버 상태 바이트, 원천별 측정(KTH 이동량 카운터와 각, MT 바퀴 카운트), hold 목표·오차, 고장 비트, 우회 표식. 단위는 원천 설정으로 카운트·바퀴·각을 함께 보낸다.
- **우회 기록(2·3 회차 P2):** 기록·화면에 **MCU 가 확인한 우회**(BENCH_SET 수락)와 **호스트가 적용한 우회**(`enc_stuck` 등)를 축·수명과 함께 따로 남긴다. `source=none` 은 우회를 **자동으로** 켜지 않는다(명시한 우회는 그대로 받는다 — A1a 의 시간 상한 듀티에서 범위 우회를 쓰는 것이 첫 화면의 용도, 재확인 P2). 시험: `source=none` + 명시한 `steer_range` 우회 수락, 우회 없이 `source=none` 이면 MCU 우회 비트 0. 기록 생성에 실패하면 ARM 을 거부하고, 구동 중 기록 쓰기에 실패하면 취소·정리한다(기존 `emit()` 은 오류를 세고 계속함 — 바꿈). 시험: 기록 생성 실패 시 `BENCH_ARM` 송신 0 건, 구동 중 쓰기 실패 시 정지·DISARMED 확인.
- **운영 판정에서 제외(독립 검토 P2):** main 의 판정기(`plant/judgement.diagnostic_image`)는 `diag-` 토큰만 진단 이미지로 본다. main 에서 빌드한 벤치 이미지는 그 토큰이 없으므로, 제품 문자열의 `bench<N>` 끝 토큰도 진단 이미지로 보게 넓힌다(진단 태그에 있던 규칙의 이식). 시험: 우회를 모두 끈 `bench5` 기록도 게이트 근거에서 제외.
- **기록:** 실행마다 `~/bench_runs/<모드>_<축>_<시각>/` 를 **배타 생성**하고 `run.jsonl`·`result.json` 를 남긴다. 기존 CLI 의 append 열기는 쓰지 않는다. 같은 시각의 두 실행, 디스크 오류, 중단 뒤에도 이전 기록이 보존되는지 시험한다. 우회 목록과 `--cause` 도 기록한다.
- **결과 판정은 셋으로 나눈다(P2: `chk` 만으로는 정착 실패 hold 도 PASS — 11-27 `hold_here2` 는 PASS 인데 정착 뒤 데드밴드 안 0.7 %):**
  - ① **실행·정리 정상**: `chk` 의 조건(`result ok`·`cleanup_confirmed`·`aborted` 없음·벤치 평상 외 고장 없음·마지막 DISARMED·네 축 듀티 0 확인, 기록 누락 없음). 자동 정리의 `cleanup_confirmed` 는 호스트 DISARM 의 echo 가 아니라 `BENCH_STATE` 구동 상태 '끝' 뒤 DISARMED 표본이다(8 회차 P2).
  - **실행 닫기와 정상 판정을 나눈다:** 실행은 MCU 가 DISARMED·FAULT·ESTOP 중 하나에 이르고, 구동이 시작됐던 실행이면 그 `run_id` 의 결과 칸을 읽으면 닫힌다. 구동 전에 끝난 실행(준비 취소, 구동 시작 전 FAULT)은 결과 칸이 비어 있어도 '구동 없음'으로 닫는다(9 회차 P2). FAULT·ESTOP 이면 실패로 닫히고, 직렬 큐는 다음 요청(명시적 `clear_faults`, 그 자체의 DISARM echo 확인 포함)을 받는다. 시험: 거리 래치 → 제동 중 FAULT → 결과 마감(실패) → 명시적 CLEAR, 준비 취소 → 빈 결과 칸으로 마감 → 다음 요청 처리, 구동 시작 전 FAULT 마감, **첫 구동 → 결과 래치 전 FAULT → 그 `run_id` 의 결과(사유 `fault`)로 실패 마감 → 다음 요청 처리**.
  - **고장 해제 요청은 받은 때의 상태에 묶는다(9 회차 P2):** `clear_faults` 는 요청을 받은 때의 연결 세대·`boot_id`·결함 비트를 함께 기록하고, 실행 직전과 **선행 DISARM 응답 뒤 CLEAR 프레임 송신 직전**에 이 셋이 하나라도 다르면 보내지 않고 새 요청을 받으라고 거부한다(10 회차 P2). 시험: CLEAR 대기 → 재부팅 또는 재개봉 → 새 FAULT → 이전 CLEAR 송신 0 건, 재개봉 없이 DISARM 응답에 새 결함 비트가 실림 → CLEAR 송신 0 건.
    - **남는 틈(11 회차 P2, 받아들임):** `CLEAR_FAULTS` 는 운영 계약 그대로 `boot_id` 만 싣고 래치를 지운다(`COMMISSION_TIME_LIMIT` 보존 예외는 계약 그대로). 그래서 호스트가 마지막으로 대조한 뒤 MCU 의 다음 틱에 새로 래치된 결함은 같은 CLEAR 로 함께 지워질 수 있다. 벤치용 CLEAR 메시지를 새로 만들지 않는 이유: CLEAR 는 다시 초기화(모든 DRVOFF → `CLR_FLT`)를 거치고, 그 뒤 nFAULT 가 정상이 아니면 다시 `FAULT` 가 되며, 과전류·드라이버 결함은 해제 조건에 들지 않는다(계약 3.2). 재초기화 중에도 관측되는 결함은 곧바로 다시 보인다. 구동할 때만 드러나는 원인은 남을 수 있고, STATE 사이에 생겼다 지워진 비트는 전후 기록에 모두 빠질 수 있다. 그래도 CLEAR 자체는 구동을 재개하지 않고(다시 ARM 이 필요) 재초기화는 출력이 꺼진 채 한다. 기록에는 CLEAR 직전·직후의 결함 비트와 드라이버 상태 네 바이트를 남겨 사람이 본다. 시험: CLEAR 송신 뒤 새 STATE 전에 지속 드라이버 결함을 주입 → CLEAR 뒤 재초기화에서 다시 `FAULT`.
  - ② **hold 목표 충족**: `abs(final_error) < deadband`, 정착한 뒤 **최소 1 s 관찰과 연속 50 표본 이상**이 있고, 그 구간 데드밴드 안 비율 ≥ 0.8. 표본은 같은 실행에서 받아들인 hold 의 **연속 유효 STATE** 만 센다(연속성 기준은 아래 '시간 조건'의 '간격 > 1.5 × STATE 주기' 하나다. 시험: 정상 지터 11–14 ms 는 이어짐, 한 쌍 누락 20 ms 는 끊음). 증거 시효(1 절)를 넘었으면 충족이 아니라 보류다. 시험: 마지막 표본 하나만 데드밴드 안인 기록, 중간 STATE 공백이 있는 기록을 둘 다 거부(기존 `settled_after_s` 는 최초 진입 시각).
  - ③ **거리 실행**: `BENCH_STATE` 의 정지 사유로 목표 도달·잠정 도달(판정 보류)·시간 소진·명령 만료·원천 손실을 구별한다. 출력을 끊은 위치와 관성 정지 위치를 둘 다 기록한다(실물 11-27: 3.03 / 3.67 바퀴).
  - 구동 축의 ARM 뒤 손실은 정리가 성공해도 목표 판정은 실패다.
  - `BENCH_KTH_LOST` 는 발생 축과 ARM 전후를 구분해 적는다.
  - 판정·최고 전류·정지 사유는 20 Hz 화면 스트림이 아니라 **원래 STATE 기록**에서 계산한다(P3).
- **시간 조건(독립 검토 P2):** pty 위 모형은 시각이 호스트 스케줄을 따르고 명령 유효시간도 보드(150 ms)와 다르다(모형 200 ms). 그래서 표본 연속성·정착 판정 시험은 **고정 시각의 합성·기록 STATE 열**로 하고, pty HIL 시험은 동작(명령·정지·정리·기록)만 본다. 벤치 모형 프로필은 보드의 명령 유효시간을 쓴다. 연속성 기준은 '간격 > 1.5 × STATE 주기'를 누락으로 센다(11-27 실물 30 s hold 의 인접 간격 3,079 개는 모두 10 ms — 짝 148 B 를 싣기 전 기록). 실보드의 짝 유실·명령 만료·1 kHz 틱 여유는 벤치 날 기록으로 따로 본다.
- **검증:** pty 위 `mcu_model`(벤치 이미지 모형, MT 는 모형의 엔코더 카운트)로 HIL 시험. KTH·MT 원천 각각 hold·거리 정지를 시험한다. 듀티 구동·hold·STOP·고장 해제·우회 표식을 돌리고, 링크 끊김이면 보드가 명령 만료로 서는지 본다. 4 CPU 로 돌린다.

### 3.1 B1 구현 결정 (2026-11-27, Codex 구현 전 검토 1·2 회차 반영)

B 를 두 PR 로 나눈다.
- **B1** 은 A1a 범위(듀티 구동, 시간 상한, 측정 없음)의 백엔드 전체다.
- **B2** 는 A1b·A1c 가 들어온 뒤 hold·거리 정지와 판정 ②·③ 을 연다.

B1 에서 다음은 '아직 없음'으로 거부한다.
- `mode: hold`, `stop.turns`·`stop.counts` → `not_yet_a1b`
- `source: mt` → `not_yet_a1c`
- 우회 `kth_invalid` → `not_yet_a2`. A1a 의 MCU 우회 비트는 `steer_range`·`lift_range` 둘뿐이다. 3 절 두 우회 비트 표에서 `kth_invalid` 를 켜는 두 줄의 실동작 검증은 A2 몫이다.

`source: kth` 는 화면용(STATE 의 조향·승강 값)일 뿐이다. 실행 기록에는 실제 wire 원천인 `none` 을 남긴다.

**콘솔 접합 — 기존 중재기를 일부만 쓴다.**
- `Arbiter` 에 다음을 더한다. 5c-1 의 `real_requests` 와 같은 방식이다.
  - 설정 `bench_requests`(기본 꺼짐).
  - `BENCH_LEASED = (bench_run, bench_stop, bench_disarm, clear_faults)`.
  - 응답 훅 `bench_request`.
- 벤치 요청은 장부를 거쳐야만 받는다. `request_token` 이 없으면 `token_required` 다.
- 설정이 꺼진 백엔드의 격리 기준은 4 절 그대로 '벤치 훅 호출 0 회·MCU 송신 0 바이트'다. 형식이 틀리거나 큐가 차면 공용 채널이 `invalid`·`busy` 로 답할 수는 있다.
- **차량용 `RealLink.begin` 은 쓰지 않는다.** 그 안의 `observe`·`mission_context` 가 피드백 없이 10 s 가 지나면 `stop("not_stopped")` 를 부른다. 벤치 연결은 `BenchLink` 가 맡고 순서는 다음과 같다.
  1. 비상 묶음(연결·STOP·DISARM)
  2. 장부 만료(`_expire`·`ledger.purge`)
  3. 일반 요청
  4. `tick`
  - 중재기의 정지 검출기·`step`·임무 판정은 돌리지 않는다.
- **STOPPED 잠금 해제.**
  - 벤치 실행은 중재기 모드를 보지 않는다.
  - 다음 실행은 직전 실행의 정리가 확인된 뒤, **현재 `control_gen` 의 명시적 새 요청**으로만 연다. STOP 은 경계를 만들어 `control_gen` 을 올리므로 STOP 전에 만든 요청은 `stale_control` 이다.
  - 정리가 확인되면 중재기에 `release_stop(now, reason)`(`bench_requests` 일 때만, STOPPED → PAUSED, 경계 하나)을 부른다. 화면이 STOPPED 에 남지 않게 하기 위해서다.
- **브라우저에 세대 전달.** 지금 프런트는 `control_gen` 을 lease ACK 가 아니라 공용 `state`·`real_status` 에서 갱신한다.
  - 그래서 B1 의 `bench_state` 에 `session_epoch`, `mode`(중재기), `control_gen`, `lease`(소유 client_id·남은 시간), `stops` 를 싣는다.
  - C 는 그것으로 세대와 lease 소유자를 갱신한다(C 의 계약). 차량용 `state` 메시지는 보내지 않는다.

**취소 — 표시는 쓰기와 같은 잠금에서, 확정은 권한 검사 뒤.**
- `BenchChannels(RealChannels)` 는 아래 요청을 받는 즉시, 그 잠금 안에서 비상 일련번호를 올린다.
  - `stop`·`disarm`(지금처럼)
  - `bench_stop`·`bench_disarm`·`lease_release`
  - 연결 추가·끊김
- 그래서 비상 묶음을 꺼낸 뒤에 이런 요청이 들어오면, 그 주기의 첫 바이트·이어 쓰기가 모두 거부된다. 다음 주기에 그 요청을 먼저 처리한다.
- 실행은 시작 때의 `lease_id`·`arbiter.stops`·소유 연결·`control_gen` 을 적어 둔다. 다음 중 하나면 그 실행의 취소를 확정한다.
  - STOP 수 증가
  - lease 소실·교체
  - 소유 연결 단절
  - `bench_stop`·`bench_disarm`·공용 `disarm` 수락
- heartbeat 만료는 수신 사건이 없다. 그래서 문(gate)이 매번 **현재 단조시각**으로 lease 기한(`renewed + lease_timeout_s`)을 다시 본다.

**쓰기 주체 하나와 문(gate) — 프레임 종류별.**
- 제어 스레드 하나가 순서대로 처리한다: `BenchLink` 의 묶음과 요청 → 실행 엔진 → 쓰기. 보드 쓰기는 이 스레드만 한다.
- 쓰기는 `ReconnectingLink(exclusive=True, link_factory=BenchTtyLink)` 로 한다.
- `BenchTtyLink` 는 프레임마다 `gate(frame, write)` 를 부른다. 첫 바이트와 **이어 쓰기마다** 다음 셋을 모두 본다.
  - `send_boundary(channels, serial, write, check)` 의 일련번호 비교
  - 프레임 자체 만료(`expires_ns`)
  - 프레임 종류별 조건(아래 셋)
- **실행 프레임**(`BENCH_SET`, `BENCH_ARM`, 준비 0, 비영 `COMMISSION`): 실행이 살아 있고 취소되지 않았을 때만 나간다. lease 가 유효하고 기한 안이며, 소유 연결이 있고, 실행 때의 `control_gen` 과 무장 세대가 같아야 한다.
- **정리 프레임**(이번 정지의 0 `COMMISSION`, DISARM): 취소와 무관하게 나간다. 일련번호 비교만 받는다.
- **`CLEAR_FAULTS`**: 송신 직전에 요청 때의 묶음(연결 세대·`boot_id`·결함 비트)을 다시 대조한다.
- 영구 취소가 확정되면 큐의 실행 프레임을 버린다(호스트에 `drop_frames(kinds, reason)` 를 더한다). 그래서 `unsent` 로 큐 맨 앞에 돌아간 SET·ARM 이 정리를 막거나 다음 실행에 다시 나가지 않는다.
- 이어 쓰기가 거부되거나 20 ms 를 넘기면 그 프레임을 버린다(`frame_abandoned`, 재전송 없음). 독은 다음 프레임 유무와 관계없이 곧바로 쓴다.
- 독을 50 ms 안에 다 못 쓰면 `LinkLost` 다. 기존 재연결기가 fd 를 닫고 `host.disconnected()` 를 부른다.
- 독 뒤에는 실행 상태를 다시 판정한다. 아직 필요한 정리 0·DISARM 은 **새 seq** 로 다시 발행한다. 다만 정리 0 의 확인 대상 seq 는 **첫 정리 0 의 seq** 로 고정하고, 재시도마다 앞으로 옮기지 않는다.
  - 근거: 첫 정리 0 이후에 큐에 넣은 프레임은 모두 정리 프레임이다. 그래서 `last_rx_seq ≥ 첫 정리 0` 이면 그중 하나가 수락된 것이다.
- 기존 `TtyLink`(bringup CLI 가 bench5 를 구동하는 링크)와 `LoopTtyTransport`(HIL·REAL, 벤치 프레임 거부)는 바꾸지 않는다. B1 의 변경은 새 콘솔의 쓰기 경계뿐이다. 기존 CLI 의 `SET → BENCH_ARM → 0` 성공과 REAL/HIL 의 벤치 송신 0 바이트를 시험으로 함께 고정한다.

**ARM 직후의 정지.**
- `BENCH_ARM` 을 큐에 넣는 순간부터 실행은 '무장 송신됨'이다.
- 호스트의 무장 교환이 끝나지 않은 동안(`host.arming`)에는 정지 규칙이 `wait` 다. 비영 송신은 실행 프레임 조건으로 이미 막혀 있다.
- ARM 프레임의 마지막 바이트보다 먼저 받은 표본은 닫기 근거가 아니다. 그래서 늦게 도착한 이전 DISARMED 쌍으로 실행을 닫지 않는다.
- 새 ARMED 를 받으면 호스트가 준비 0 을 스스로 만든다. 그 뒤 정지의 0 을 보내고, 3 절 DISARM 조건을 적용한다. 준비 0 은 정지의 0 보다 seq 가 앞이라 둘이 구별된다.
- 무장이 거부되거나 만료되면 ARM 이후에 받은 DISARMED 표본으로 닫는다.
- 회귀 시험: ARM 완료 → STOP → 이전 DISARMED 쌍 지연 도착 → 새 ARMED 수신.

**입력 검증.**
- 웹 경계에서 먼저 타입을 본다.
  - 확인값(`power_switch_in_hand`, `wheels_lifted`, `vcc_watched`)은 실제 불리언이어야 한다.
  - 수치는 유한한 수, `window` 는 두 수, 우회는 문자열 목록이어야 한다.
- 그다음 bringup 인자 이름공간으로 옮겨 `_check_commission_args`·`bench_limits` 로 검증한다.
- `synthetic`·제품 문자열은 요청에서 받지 않는다.
- 우회 목록 생략과 `[]` 는 같은 요청이다. 늘 `BenchAsk` 를 만들어 M/H 의 기본 시간 상한이 이미지 기본에서 여유를 뺀 값으로 같게 한다.
- 큰 실행은 검증된 `RunAsk` 의 `confirmation_phrase()` 와 요청의 `large_confirm` 이 정확히 같아야 한다.
- `absent` 에 든 축은 구동을 거부한다.

**M·H 의 준비와 창 검사.**
- 호스트의 무장 준비 0 은 L 축이다. M/H 는 무장 뒤 **그 축의 0 `COMMISSION`** 을 보내고, 그 수락(`last_rx_seq`·거부 없음)을 확인한 뒤 비영 구동을 연다.
- 그 축의 0 이 거부되면(KTH 무효, 계약 3.4) 실행은 '구동 없음'으로 닫는다.
- 구동 중 창 검사는 최신 표본만이 아니라 **읽힌 모든 STATE** 에 적용한다. 호스트의 `on_state` 로 모은다.

**고장 해제 상태 전이.**
- `clear_faults` 는 다음 순서로 간다. bringup `clear_faults` 와 같은 확인을 비차단으로 옮긴 것이다.
  1. 요청 때 묶음을 적는다.
  2. 경계 이후 쌍과 새 fd 의 제품(`bench_refusal` 의 이미지 조건)을 확인한다.
  3. DISARM 을 보내고, 그 echo 를 같은 연결·부팅·이후 표본으로 확인한다.
  4. 묶음을 다시 대조한다.
  5. `CLEAR_FAULTS` 를 보낸다(문에서 한 번 더 대조).
  6. 그 echo 를 확인한다.
  7. DISARMED·`DRIVERS_READY` 를 확인한다.
- 재개봉 뒤에는 정리·CLEAR 도 새 fd 의 제품이 bench5 이고 경계 이후 쌍이 있을 때만 연다.
- `mcu_model --bench` 는 같은 부팅 안의 연결 세대 변경을 흉내 내지 않는다. 같은 부팅의 재개봉은 경계 사건을 주입하는 시험으로 본다.

**스트림·기록.**
- `bench_state` 를 50 ms 마다 모든 연결에 보낸다. NaN 은 `null` 과 사유로 바꾼다.
- 기록은 `~/bench_runs/<mode>_<axis>_<시각>/` 을 배타 생성한다.
  - `run.jsonl` 은 줄마다 flush 한다. 쓰기 오류가 나면 그 실행을 취소한다.
  - `result.json` 은 임시 파일에 쓴 뒤 이름을 바꾼다.

**결과.** B1 은 판정 ①(실행·정리 정상)과 '구동 없음' 닫기만 낸다. ②·③ 은 B2 에서 연다.

**2 회차 반영(순서와 시점).**
- **공용 DISARM 의 세대 경계.** 벤치(`bench_requests`)에서 공용 `disarm` 을 받아들이면 `control_gen` 이 하나 오른다. 그래서 DISARM 보다 먼저 접수됐지만 뒤에 처리되는 `bench_run` 은 `stale_control` 이 된다(같은 주기에 비상 묶음이 먼저 처리되기 때문).
- **쓰기의 기준 번호.** `BenchLink.begin` 은 처리한 비상 묶음의 일련번호를 돌려준다. 쓰기는 그 번호와 비교한다. `begin` 뒤에 새로 읽은 번호는 쓰지 않는다.
- **호스트의 무장 0.** 이미 나간 ARM 에 대해 호스트가 스스로 만든 무장 0(L, 0)은 취소 중에도 문을 통과한다(`echo` 가 있고 같은 권한 세대일 때). 정지는 그 0 이 닿아 호스트가 준비될 때까지 기다린 뒤 자기 0 을 보낸다. 무장 교환이 열린 동안은 `arming`(대기·0 대기 모두)으로 보고 `wait` 다.
- **ARM 의 '송신됨'.** ARM 프레임 전체가 쓰였을 때만 송신으로 본다. 첫 바이트 전에 버린 ARM 은 미송신 취소다(`cancel_arm`).
  - 송신 뒤 결과가 불명이면, 다음 표본만 닫기 근거로 쓴다: 무장 세대가 바뀐 표본, 또는 같은 부팅에서 MCU 시각이 ARM echo + 보드의 echo 허용 시간(`command_timeout_ms`, 150 ms)을 지난 표본. 호스트 수신 시각만으로는 늦게 도착한 이전 DISARMED 를 배제하지 못하기 때문이다.
- **정지 0 의 확인 대상.**
  - 확인 대상은 **실제로 다 쓰인 첫 정지 0** 이다.
  - 그 0 의 근거가 되는 표본은 두 조건을 모두 갖춰야 한다: 쓰기가 끝난 뒤에 받았고, 그 0 이 echo 한 STATE 보다 MCU 시각이 뒤다. 16 비트 비교만으로는 호스트가 들고 있던 오래된 '준비' 쌍을 걸러내지 못한다(반 바퀴 이상 떨어진 seq).
  - 근거가 없으면 `wait` 다. DISARM 도 재송신도 하지 않는다.
  - 아직 쓰이지 않은 정지 0 이 있으면 두 번째를 넣지 않는다.
- **문 설치.** `BenchTtyLink` 의 `gate` 는 필수 인자다. 재연결기의 팩터리가 최초 개봉과 재개봉 때마다 같은 문을 묶어 만든다.
- **시간 검사의 위치.** 20 ms 는 문 안에서 실제 이어 쓰기 직전에 본다. 50 ms 는 독의 다음 바이트를 쓰기 전에 본다. 넘었으면 한 바이트도 더 쓰지 않고 `LinkLost` 다.
- **사용자 창.** 사용자 창은 무장 전 현재 값과, 첫 비영 송신까지 받은 모든 표본에 적용한다. 그 축의 0 이 거부된 경우는 정지 규칙으로 MCU 종료 모드를 확인한 뒤 '구동 없음'으로 닫는다. 그때 보드가 아직 ARMED·준비일 수 있기 때문이다.
- **CLEAR 대조.** 요청 때 묶음을 선행 DISARM 직전, 그 echo 뒤, CLEAR 실제 쓰기 직전(문)에 대조한다. 어긋나면 그 해제를 거부하고 CLEAR 프레임을 큐에서 뺀다. 새 요청을 받으라고 답한다.
- **시작 경로의 두 확인(CLI 와 같음).**
  - 이전 결과 칸이 있으면 기록에 쓰고 flush 한 뒤에만 ARM 한다. 새 ARM 이 결과 칸을 비우기 때문이다.
  - ARMED 쌍이 이번 `run_id` 를 말한 뒤에만 첫 비영을 보낸다.
