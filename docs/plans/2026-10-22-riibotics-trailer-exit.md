## 1. 문제와 원인

트레일러 장면(`scenes_riib_b35fcc9/trailer.json`)에서 팔레트를 꺼낸 뒤 운반 첫 틱부터 주행 허가가 `transport:occupied` 로 0 이 되어, 추종 시간 초과로 끝난다.
정답 위치로 돌린 t1_trailer(ws1 `test_runs/riibotics/t1_trailer`, 스냅숏 riib_b35fcc9, 2026-10-21)와 SLAM 으로 돌린 r4_trailer 가 같은 곳에서 멈췄다.

- **장면 치수**(장면 파일의 계획기 소품 사각형에서): 트레일러 안쪽 벽 면 |y| = 2.339 − 3.322/2 = 0.678 m(안 폭 1.356 m), 입구 x = 3.3 − 2.6/2 = 2.0 m.
  집는 팔레트의 정답 중심 (2.46, 0.05), yaw −0.035 rad(장면 파일의 `scenario.pickup` 은 명목 (2.50, 0, 0) 에 오차를 넣은 정답 위치다). EPAL 6 0.6 × 0.8 m.
- **꺼낸 자리.** 꺼내기는 고정 0.65 m(`SyntheticMissionGeometry.extraction_m`)다. 꺼낸 뒤 후축 (0.551, 0.117, −0.035)이고, 실은 외곽(앞 1.56·뒤 0.17·반폭 0.40 m)의
  앞 모서리 최대 x 가 2.124 m(yaw 포함)로 **아직 입구 안** 에 있다.
- **벽의 점유 띠.** 장애물 층은 LiDAR 점마다 r = e(나이) + 2ρ·sin(ψ(나이)/2) + 0.06 m 를 붙여 칸을 점유로 표시한다(`perception/obstacle_grid.py` `radius_m`, 나이는 최대
  `occupied_max_age_s` 0.3 s → `config/obstacle_odometry_age.json` 에서 e 0.042 m·ψ 0.026 rad; ρ 1.5–3 m 면 r ≈ 0.14–0.18 m, 칸 0.05 m 를 더해 띠 ≈ 0.19–0.23 m).
  운반 시작 때의 격자(`obstacle_dump_6.npz`)에서 입구 근처(x 1.6–2.3) 점유 칸 중심의 최소 |y| 는 양쪽 0.525 m(칸 가장자리 0.50 — 벽 면에서 0.178 m), 그 칸들이
  x 1.875–2.275 에 있다(벽 끝 x 2.0 보다 0.125 m 바깥까지).
- **막힌 칸.** 운반 경로의 앞 구간은 곧바로 회전 후진(곡률 −0.29 → +0.29)이다. 짐의 앞 왼쪽이 +y 로 돌아 칸 (x 1.93–2.08, y 0.525) 에 들어가 `path_blocked`(검증 거리
  0.02 m) 가 된다. 주행 허가는 지금 외곽 안의 칸은 빼고 앞으로 들어가는 칸만 본다(`control/drive_permission.py` `_enters`).
- **경로 계획과의 어긋남.** 운반 경로는 계획 여유 0.10 m 로 벽 사각형만 피한다(`planner_config.clearance_m`). 장애물 층의 띠(≈ 0.2 m)는 계획에 들어가지 않는다.

## 3. 설계

**D1 — 운반 경로 앞에 "출구 직진" 을 붙인다(기본 꺼짐, 장면 배치 전용).**
- 꺼내기(0.65 m)는 그대로 둔다. 운반 경로를 계획할 때마다(처음 계획·모든 재계획), 그 계획의 출발 자세에서 **직진 후진 Δ** 를 먼저 두고 나머지를 Hybrid A* 로 잇는다:
  `path = straight(start → start − Δ) + search(start − Δ → predelivery) + 하역 직진`. 운반 단계 안이라 주행 허가가 적용된다(P1 해소). 단 `permission_acting` 은 운반
  추종기의 남은 거리 ≤ `delivery_straight_m` 이면 하역 직진으로 보고 허가를 끄며, SLAM 의 `arm_docking()` 은 하역 직진을 잘라낸 경로로 추종기를 바꾼다 — 짧은 운반이면
  접두부가 그 창에 들어갈 수 있다(Codex 2 회차 P1: Δ 0.40 m 반례에서 분리 뒤 남은 0.40 m 가 허가 꺼짐). 그래서 **출구 접두부는 하역 직진이 아니다** 를 명시한다:
  운반 경로 설치 때 접두부 길이를 함께 남기고, 추종기 진행이 접두부 안이면 `permission_acting` 이 허가를 켠다(기존 backoff 예외와 같은 방식, 하역 직진 예외는 그대로).
- Δ 의 규칙: 0, step, 2·step, … cap 중 가장 작은 값으로, ⑴ start − Δ 에서 실은 외곽과 **출구 장애물** 사이 최소 거리 ≥ X, ⑵ start → start − Δ 직진의 실은 외곽이
  계획기의 소품·경계·격자 검사(`_straight_plan`, 계획 여유)를 통과. 처음부터 ⑴ 이면 Δ = 0(기존 경로와 같다). cap 안에 없으면 직진 없이 지금처럼 계획하고 `unmet` 을 기록한다.
- Δ 는 **계획에 들어온 실제 출발 자세**로 구한다 — 처음 계획은 인식 목표(`planning_pickup`)에서 꺼낸 자세, 재계획은 그때의 측정 자세다. 정답 위치를 쓰지 않는다(P2 해소).
- **출구 장애물(입력 계약, P2 해소).** 장면 파일의 `visuals` 중 `kind == "wall"` 이고 높이 ≥ 장애물 층의 `band_bottom_m`(지금 1.044 m)인 사각형이다 — Isaac 에서 실제
  충돌체로 만들어지는 벽이다(`run_transport.py` 장면 배치의 `scene_layout.obstacles`). 소품(계획 금지 영역)·바닥 팔레트는 넣지 않는다. 이 기능은 `--layout scene` 에서만
  허용한다(다른 배치에서 켜면 인자 오류). 일반 mesh 의 높이별 단면은 다루지 않는다.
- 러너 인자 `--exit-clearance-m X`(기본 None). None 이면 출구 장애물을 만들지도, 계획 함수에 넘기지도 않는다 — 계획 호출이 지금과 같다. 켜면 `plan_transport`·
  `plan_transport_leg`·`plan_loaded_delivery` 에 `exit_prefix=ExitPrefix(obstacles, clearance_m=X, step_m=0.05, cap_m=1.0)` 를 넘긴다(러너의 첫 계획 호출과 core 가 쓰는
  hooks 두 개, 계획 작업자(`plan_worker` — hooks 를 거치지 않고 모듈 함수를 부른다: `plan_transport`, 운반 leg 의 일반·tight 호출, `plan_loaded_delivery`)로 가는 인자,
  그리고 drive 의 재생 입력 스냅숏(`drive_inputs`)에도 같은 값). 각 계획의 Δ·최소 거리·`unmet`·계산에 쓴 출발 자세·계획 식별자를 `state["exit_prefix"]` 에 쌓는다.
- **X = 0.30 m 는 이번 장면의 실험 후보값이다(보장값이 아니다).** 띠 추정 0.19–0.23 m 에 허가 표본 여유(이동·회전, 약 0.025 m)를 더하면 남는 몫은 약 0.05 m 다. SLAM 위치
  오차(운반 중 최대 0.16 m)를 덮는 값이 아니다. 트레일러에서는 정답 위치로 Δ = 0.35 m(꺼내기와 합쳐 1.00 m, 최소 거리 0.304 m), 명목 위치로 0.30 m(0.95 m 상당).
  CPU 로 본 D7 운반 경로는 꺼내기 1.00 m 상당에서 1 551 보간 표본 내내 측벽에서 0.304 m 이상이었다(Codex 계산) — 뒤늦은 회전이 벽에 다시 다가가는 반례는 없었다.
  Δ 규칙의 끝점 조건만으로 임의 경로를 보장하지는 않으므로, 경로 전체는 허가가 매 틱 본다.
- 근접 추적 계약: `POST_MEASUREMENT_ARGUMENTS["exit_clearance_m"] = None`. riib 실행은 근접 추적 실행이 아니므로 켜도 계약에 걸리지 않는다(구현 때 확인). 근접 추적 실행에서
  켜면 계약이 거부하는 것이 정상이다. t1_trailer·r4_trailer 의 `arguments.near_tracking` 은 false 였다(확인).

**D2 — 하지 않는 것.** 장애물 층의 r·칸·`occupied_max_age_s`, 주행 허가의 여유와 적용 범위(꺼내기·하역 직진 제외 포함), fleet `PALLET_KEEP_M` 은 바꾸지 않는다. 계획 여유
(0.10 m)를 전역으로 올리거나 띠와 맞추지 않는다 — 트레일러 안에서는 꺼낸 자세 자체가 0.21 m 로 띠보다 가까워 출발이 불가능해지고, 다른 장면의 계획이 모두 달라진다(agy 의
"근본 해결" 제안에 대한 판단). 꺼내기 거리도 바꾸지 않는다. 장면 도구·`riib.sbatch` 는 고치지 않는다(`EXTRA_ARGS`).

## 4. 검증

- **V1 단위 시험(먼저 쓴다).** ⑴ 트레일러 벽 두 개에서 X 0.30 이면 Δ > 0, start − Δ 의 최소 거리 ≥ 0.30, 경로 첫 구간이 직진 후진 Δ, ⑵ X 꺼짐(None)이면 계획 함수가 받는
  인자와 경로가 지금과 같음(`exit_prefix` 미전달), ⑶ 출구 장애물이 멀면 Δ = 0 이고 경로가 기존과 같음, ⑷ cap 안에 없으면 직진 없이 기존 계획·`unmet`, ⑸ 직진이 소품·경계·
  격자에 걸리는 Δ 는 고르지 않음, ⑹ 재계획(`plan_transport_leg`)도 같은 규칙, ⑺ 장면 배치가 아니면 인자 오류, 벽 visual 만 출구 장애물(높이 < band_bottom 제외),
  ⑻ 근접 추적 계약 키 등록, ⑼ 비유한·음수 X·step·cap 거부, ⑽ **짧은 운반에서 하역 직진을 잘라낸 뒤에도 접두부 안에서는 허가가 켜져 있고**, 접두부 앞 칸이
  OCCUPIED·UNKNOWN 이면 실제 명령이 0 으로 제한됨(`armed` 상태 포함), 하역 직진 예외는 그대로, **접두부 정보의 수명** — `arm_docking()` 의 뒤쪽 절단에서는 유지,
  재계획에서는 새 계획 값(Δ = 0·`unmet` 포함)으로 교체, 실제 하역 직진 설치에서는 0 으로 초기화(남으면 하역 직진에서 허가가 켜진다), ⑾ 계획 작업자 세 호출과 재생
  스냅숏이 같은 `ExitPrefix` 를 받고, 직렬화 → 복원 뒤 hooks 호출까지 같음(`drive_inputs` 는 drive 의 `_bound` 에서 입력을 모은다).
- **V2 오프라인 재생.** dump 6 격자에서 새 운반 경로(직진 Δ + 검색)가 `check_path` 로 막히지 않고, 접두부를 실제 추종기(앞보기 0.28 m 라 직선 위에서도 끝 무렵 곡률을
  낸다 — Codex 계산 0.20 m 에서 0.065, 0.30 m 에서 0.197 m⁻¹)의 명령 곡률·속도로 따라가며 `check_arc`·`allowed_speed` 도 통과.
- **V3 Isaac 재평가(ws1, 자리 날 때).** 트레일러를 정답 위치(t1 과 같은 설정)와 riib 기본 설정(SLAM·인식)으로 각 1–2 회, `EXTRA_ARGS="--exit-clearance-m 0.30"`.
  판정: ⑴ 운반이 입구를 지나 `transport:occupied` 연속 정지 없이 진행, ⑵ 정답 위치 실행은 하역(오차 < 0.08 m)과 복귀까지 완주. 완주가 모든 단계의 허가 검증은 아니다
  (꺼내기·하역 직진·미인증 withdraw 는 허가 적용 밖). SLAM 실행은 ⑴ 만 판정하고 그 뒤 실패는 원인만 적는다.
- **V4 회귀.** ws1 전체 pytest, 기본값 실행의 계획 호출 동일(V1 ⑵).

## 5. 열린 점

- X 는 이번 장면의 후보값이다. SLAM 오차가 크면 띠가 그만큼 밀린다 — V3 의 SLAM 실행에서 본다.
- 직진 후진 뒤쪽 공간: 계획기는 소품·경계·격자를, 허가는 실시간 격자(뒤쪽 UNKNOWN 포함)를 본다. 실제 도크의 뒤쪽 통로 폭은 장면에 들어 있는 만큼만 본다(agy).
- 트레일러 두 줄(T11)에 경로가 없다는 앞 결론(8 주차 11 쪽)은 그대로다. 좁은 통로(①)처럼 계속 벽 옆이면 `unmet` 으로 지금과 같다.
- 실차의 차체 기울기(적재 피칭)로 생기는 거짓 점유는 이 계획 밖이다(장애물 층의 band_bottom 0.07° 가정).

## 6. 자체 검토

- **① 재계산(2026-10-22).** 장면 파일 사각형에서 벽 안쪽 면 2.3389 − 3.3221/2 = 0.6779 m, 입구 3.3 − 2.6/2 = 2.0 m. 나이 표의 0.3 s 값 e 0.04207 m·ψ 0.02596 rad,
  r(ρ 1.5) = 0.042 + 0.039 + 0.06 = 0.141 m, r(ρ 3) = 0.180 m. 꺼내기 e 별 실은 외곽–벽 최소 거리(직사각형 표본 계산): 0.65 → 0.211, 0.80 → 0.212, 0.90 → 0.242,
  0.95 → 0.270, 1.00 → 0.304 m. 재생 표(2 장)는 스크립트 출력.
