## 0. 목적과 결정(총괄, 2026-11-08)

- 목적: ②(저상 감시)·④(복귀 출발 후진 boxed)·⑤(C2) 를 라이브 런처 기본에 넣어도 **페이스를 나쁘게 하지 않는지**(A/B 상대 비교)와 각 기능이 라이브에서 **실제로 동작하는지**(최소 유효 발화)를 다시 본다. 범위는 앞 등록과 같다(SCENE_FILE · line_m · random_m · team_spec · 등록 지도 · CT 인식 설정, factory 는 현행).

## 2. 동시 수 기준선

- 조건: 팔 A(라이브 현재 기본) + CT 인식 설정, line_m·random_m 등록 지도, team_spec, `D7_HOLD` on, 배속 0.3, 따라잡기는 0 절의 G1 결정값, H4, `FORKLIFT_LIVE_TICK_TRACE=1`, 영상·기록 설정은 본배치와 같게.
- 세션: 1 동시 2 개(line_m, random_m 를 차례로), 2 동시 2 개(line_m·random_m 한 쌍), 3 동시 3 개(line_m·random_m·line_m). 임무는 앞 배치와 같은 세 임무 큐. 모두 같은 스냅숏.
- 세션 통계(측정 창 = 첫 임무 제출부터 마지막 임무 종료까지, 앞 등록과 같음):
  - **창 배율** F = (창 끝 `tick_t` − 창 시작 `tick_t`) / (창 끝 `mono` − 창 시작 `mono`), 스텝별 기록에서.
  - **ok=false 비율** R = 창 안 스텝 가운데 `pacing_ok` false 인 스텝의 벽시계 몫.
  - 참고(판정에 안 씀): 렌더 스텝 평균 초과량, stall 수.
- 고르는 규칙(사전 고정): F₁ = 1 동시 두 세션 F 의 평균. N 동시는 그 N 동시의 **모든** 세션이 F ≥ 0.97 × F₁ 이고 R ≤ R₁ + 0.03(R₁ = 1 동시 두 세션 R 의 평균)일 때 '유지'다. 본배치 동시 수는 유지된 가장 큰 N 이다. 1 동시도 F₁ 이 0.27(pacer 의 ok 기준, 목표의 0.9) 아래면 동시 수를 고르지 않고 총괄에 올린다(렌더 비용이 간격을 넘는 구조라 동시 수로는 풀리지 않는다는 뜻).
- 근거로 쓸 앞 배치 값(3 동시, 16782 기록에서 다시 잼): F 0.2793–0.2873(통합 A/B 0.2818–0.2836). R(ok=false 스텝의 벽시계 몫) 통합 A/B 0.119–0.185, 전체 0.045–0.328. R 이 1 s 배율의 0.27 미만 표본 비율(통합 A/B 0.043–0.094, 전체 0.009–0.145)보다 큰 것은 pacer 가 한 번 떨어지면 ok 를 1 s 동안 다시 세우지 않기 때문이다. 간격을 넘긴 시간의 90.8–93.4 %(세 세션 합 92.3 %)가 렌더 스텝 뒤 간격에서 생겼다(16782 결과 3.5).

### 3.3 판정 (결과 전 고정)

**페이스(본판정, 통합 A/B 16 세션, 전 구간 틱 기록).**

- 원천은 틱 기록의 `S` 하나다(H4 로 전 구간이 남는다). 틱 기록에 빠진 행이 있는 세션은 그 구간이 판정 불가이고 수를 적는다. 앞 등록 3.4 의 대체 원천은 쓰지 않는다.
- 팔별로 짝 16 세션을 합쳐 본다(장면·seed 별 표도 같이 적는다).
  1. **ok=false 비율**: B 의 합산 R 이 A 의 합산 R + 0.01 이하.
  2. **최장 연속 ok=false**: B 의 세션별 최댓값이 A 의 세션별 최댓값의 1.2 배 + 2 s 이하.
  3. **stall 수(> 0.25 s)**: 앞 행 표시로 나눈다 — 렌더 스텝(앞 행 `rendered`, `capture` 아님), 캡처 처리(앞 행 `capture`), 그 밖. B 의 합산 캡처 처리 stall + 그 밖 stall 이 A 의 같은 합 + 2 이하. 렌더 스텝 stall 은 팔과 무관하다는 가설(아래)로 따로 적고 판정에 넣지 않는다.
  4. ⑤ 의 동기 재계획 스텝은 따로 빼서 2.0 s 상한으로 본다(앞 등록과 같음).
- 셋 다 통과하면 페이스 통과, 하나라도 못 미치면 보류다. 결과의 유효 범위는 실측 창 배율(예: '목표 0.3, 실측 0.28')로 적는다.
- **가설(사전 등록, 앞 배치의 사후 분석에서 옴)**: 렌더 스텝 stall 은 두 팔이 같은 수준이고, 팔 B 의 추가 stall 이 있다면 캡처 처리 제어 틱에서 문턱 근처로 나온다. 이 가설은 위 3 의 분류 근거이고, 맞는지는 결과에서 적는다.

**안전(팔 B·fixture·생명주기, 앞과 같음).** 금지 접촉 0, 낮은 소품 겹침 0(러너의 `session_neighbour_gap` 0 인 것과 `session_rest_largest` 경계 초과 0), `unpermitted_dir_entries` 0, 적재 안전 실패 0. 기록이 없으면 그 항목은 판정 불가이고 승격하지 않는다.

**기능(최소 유효 발화).**

- ②: 최소 유효 발화는 앞 등록 3.2 그대로 **오탐이 아닌 감시 정지**로만 채우고, 그 확인은 **별도 주입 배치**에서 한다(정지 → 수동 회복 → 다음 임무 1 회 이상, 오탐 판정의 독립 확인은 H3 기록, 적재 정지는 `loaded_hold` 운용 공백으로 따로 셈). v2 본배치의 감시 표적은 상한 발화와 안전값의 보조 자료다.
- ④: 후진 표적에서 설치 → 실제 후진 → 복귀 완료 1 회 이상(앞과 같음). 막힌 시작(`trigger: boxed`) 라이브 발동이 나오면 개별 조사.
