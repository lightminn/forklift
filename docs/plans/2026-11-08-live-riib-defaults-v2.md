# 라이브 런처 riib 기본 ④⑤ 재검증 v2 (② 는 별도 주입 배치) — 사전 등록 초안 (2026-11-08)

- 앞 배치: [16782 결과](../validation/2026-11-08-live-riib-defaults-validation.md) — 총괄 결정으로 ②④⑤ 모두 보류(페이스: 등록 판정 불가·민감도 B 악화, 생명주기 1 판정 불가, ② 최소 유효 발화 미충족). 앞 등록: [2026-11-08-live-riib-defaults-validation.md](2026-11-08-live-riib-defaults-validation.md)(3.4 보정 포함). 이 문서는 그 등록을 고치지 않는 새 등록이다.

## 0. 목적과 결정(총괄, 2026-11-08 — 경위는 6 절)

- **v2 의 대상은 ④(복귀 출발 후진 boxed)·⑤(C2)** 다. 팔 B = 팔 A + ④ + ⑤. ④⑤ 의 승격은 v2 결과만으로 판정한다. 범위는 앞 등록과 같다(SCENE_FILE · line_m · random_m · team_spec · 등록 지도 · CT 인식 설정, factory 는 현행).
- **②(저상 감시)는 별도 주입 배치**에서 ④⑤ 위에 ② 켬/끔으로 본다(H5, 4 절). 그 배치는 두 부분이다: ⓐ 주입하지 않는 페이스 A/B 짝(v2 와 같은 지표·예산·짝 규칙), ⓑ 주입 세션(정지 → 수동 회복 → 다음 임무, 오탐 판정 원천은 H3 기록, 생명주기 기준을 ② 켬 조건으로 다시 봄). ② 승격은 ⓐ·ⓑ 를 모두 통과해야 한다. ② 가 복귀 후진 경로를 참조하므로 ④ 가 켜진 위에서 시험한다.
- 본판정은 **A/B 상대 비교**다. 절대 배율 0.3 은 합격 조건이 아니라 **결과가 유효한 범위**로 적는다.
- 동시 수는 1·2·3 동시를 같은 조건에서 잰 **기준선**으로 2 절의 규칙대로 고른다.
- **따라잡기 설정은 G1 결정을 따른다**(자리만 둠). 시뮬-물성의 G1(잡 16785, 따라잡기 0 / 6 / 6+위상 6)의 보고를 받고 총괄이 운용 기본값을 정하면, 그 값을 기준선·본배치·주입 배치에 똑같이 쓴다. 기준선 제출 전에 이 자리를 채우고 다시 검토한다.

## 2. 동시 수 기준선

- 조건: 팔 A(라이브 현재 기본) + CT 인식 설정, line_m·random_m 등록 지도, team_spec, `D7_HOLD` on, 배속 0.3, 따라잡기는 0 절의 G1 결정값, H4, `FORKLIFT_LIVE_TICK_TRACE=1`, 영상·기록 설정은 본배치와 같게. 모두 같은 스냅숏, seed 0, 세 임무 큐(앞 배치와 같은 순서), 자동 재시도 0.
- **자원 구성(기준선·본배치·주입 배치 모두 같게 고정)**: 묶음 잡마다 `--gres=shard:4 --cpus-per-task=8 --mem=19G --nodelist=ws1`(`sizes live` 의 3 슬롯 값), 동시 수는 `BUNDLE_ARGS="--slots N --retries 0"` 로만 바꾼다. 브리지 CPU 는 묶음 실행기 기본(같은 할당 CPU 에서 같은 규칙), 실시간 물러남 끔, 시차 60 s.
- 실행: 동시 수마다 묶음 잡 하나, 순서 1 → 2 → 3, 다른 잡 없음.
  - 1 동시: line_m, random_m 를 차례로(슬롯 1 묶음 하나).
  - 2 동시: line_m·random_m.
  - 3 동시: line_m·random_m·line_m.
  - 기반 실패(Isaac 기동 실패·`startup_silent`·`startup_viewport`·탐침 전 래퍼 종료)일 때만 그 동시 수를 한 번 다시 낸다. 잡음이 의심된다는 이유로는 다시 재지 않는다.
  - 무효화: 그 묶음이 도는 동안 노드에 다른 Slurm 잡이 겹치면(`sacct -a`) 그 묶음은 무효이고 다시 낸다. Slurm 밖 부하는 시작·끝의 `/proc/loadavg`·`docker ps`·`nvidia-smi` 로 기록만 한다.
- 측정 구간: N 동시의 통계는 **N 세션이 모두 측정 창(첫 임무 제출부터 마지막 임무 종료까지) 안에 있는 공통 구간**에서만 낸다. 공통 구간이 15 분 미만이면 그 동시 수는 판정 불가이고 총괄에 올린다. 1 동시는 세션 측정 창 전체다.
- 세션 통계(구간 [a, b], 스텝별 기록 = `live_log` 의 `pacing_ok` 기록, `step`·`mono`·`tick_t`):
  - 쓰는 스텝: a ≤ `mono` ≤ b 인 스텝 기록. 첫·끝 스텝을 k₀·k₁ 이라 한다.
  - **창 배율** F = (`tick_t`[k₁] − `tick_t`[k₀]) / (`mono`[k₁] − `mono`[k₀]).
  - **ok=false 비율** R = Σ (`mono`[k+1] − `mono`[k]) · [`pacing_ok`[k] = false] / Σ (`mono`[k+1] − `mono`[k]). 합은 k₀ ≤ k < k₁ 이고 k 와 k+1 이 둘 다 있는 쌍에 대해서다. 간격 [`mono`[k], `mono`[k+1]) 에는 왼쪽 스텝 k 의 상태를 쓴다.
  - **결측**: 빠진 `step` 의 간격은 분자·분모 모두에서 뺀다. 세션이 판정 불가가 되는 경우는 셋이다.
    - 빠진 스텝 비율(k₀..k₁ 의 예상 스텝 수 k₁ − k₀ + 1 가운데 기록 없는 스텝)이 1 % 초과.
    - 결측 벽시계(빠진 스텝 앞뒤 관측 스텝의 `mono` 차의 합)가 구간 벽시계의 1 % 초과, 또는 결측 공백 하나가 5 s 초과.
    - `read_live_log` 가 거부.
  - 참고(판정에 안 씀): 렌더 스텝 뒤 간격의 평균 초과량, stall 수.
- 고르는 규칙(사전 고정):
  - F₁·R₁ = 1 동시 두 세션 F·R 의 평균.
  - N 동시는 그 N 동시의 **모든** 세션이 F ≥ 0.97 × F₁ 이고 R ≤ R₁ + 0.03 일 때 '유지'다.
  - 본배치 동시 수(나머지 묶음)는 유지된 가장 큰 N 이다(2 동시 유지·3 동시 탈락이면 2). 통합 A/B 는 짝 단위로 돌므로 **2 동시가 유지된 경우에만** 짝 동시(슬롯 2)로 돌고, 2 동시가 탈락했으면(3 동시 유지 여부와 무관) 1 동시가 유지된 경우 한 세션씩(슬롯 1) 돈다(3.1).
  - **유지된 N 이 하나도 없으면** 동시 수를 고르지 않고 총괄에 올린다(1 동시가 자기 평균 기준에서 떨어지는 경우 포함).
  - 중단선: F₁ < 0.27(pacer 의 ok 기준, 목표의 0.9)이면 고르지 않고 총괄에 올린다. 이 중단선은 원인을 진단하지 않는다.
  - 0.97·+0.03 은 **총괄 정책 결정(2026-11-08 승인)**이다: 검증 배치의 처리량을 위해 배율 3 %·ok=false 3 %p 손실까지 받아들인다는 정책이고, 운용 콘솔의 기준이 아니다. 세션 2/2/3 개로는 반복 변동을 추정하지 못한다는 한계를 결과에 적는다.
- 근거로 쓸 앞 배치 값(3 동시, 16782 기록에서 다시 잼): F 0.2793–0.2873(통합 A/B 0.2818–0.2836). R 통합 A/B 0.119–0.185, 전체 0.045–0.328. R 이 1 s 배율의 0.27 미만 표본 비율(통합 A/B 0.043–0.094, 전체 0.009–0.145)보다 큰 것은 pacer 가 한 번 떨어지면 ok 를 1 s 동안 다시 세우지 않기 때문이다. 간격을 넘긴 시간의 90.8–93.4 %(세 세션 합 92.3 %)가 렌더 스텝 뒤 간격에서 생겼다(16782 결과 3.5).

## 3. 본배치

### 3.1 공통

- 래퍼는 앞 배치의 복사본(`riib_session.sh`)에 H1·H4 를 넣은 것이다. 자원 구성은 2 절과 같다. 본배치가 도는 동안 CPU 잡은 내지 않는다(총괄 규칙). 노드 조건과 같은 시간대 다른 잡을 `sacct -a` 로 남기고, 다른 Slurm 잡이 겹친 묶음은 무효로 다시 낸다.
- 팔 A = 라이브 현재 기본. 팔 B = A + ④ + ⑤(기본값). ①·②·③·⑥ 은 두 팔 모두 끔.
- **묶음 구성(공정성)**:
  - **통합 A/B 묶음**: 같은 장면·seed 의 A 와 B 를 한 짝으로 동시에 돌린다. 묶음 실행기는 슬롯 하나만 비어도 다음 실행을 넣으므로(`tools/isaac_bundle.py`), **짝마다 묶음 잡 하나**(실행 2 개, 슬롯 2, 시차 60 s)로 내고 짝 잡들을 `--dependency=afterany` 로 차례로 잇는다. 그래서 한 짝이 다 끝나기 전에는 다음 짝이 들어오지 않는다. 짝 안에서 먼저 시작하는 팔은 고정 seed(`random.Random(20261108).choice`)로 짝마다 정해 목록에 적는다. 짝 순서는 line_m s0, random_m s0, line_m s1, random_m s1, … s3 이다.
  - 짝의 페이스 지표는 **짝의 공통 구간**(두 세션이 모두 측정 창 안에 있는 구간 — 시차 60 s 의 앞 꼬리와 먼저 끝난 팔 뒤에 남은 팔만 도는 꼬리를 뺀 구간)에서만 낸다. 공통 구간이 15 분 미만인 짝은 페이스에서 빼고 센다.
  - 2 동시가 탈락하고 1 동시만 유지되면, 통합 A/B 는 짝마다 묶음 잡 하나(슬롯 1, 먼저 시작하는 팔이 먼저)로 돌고 지표는 각 세션의 측정 창 전체에서 낸다.
  - **나머지 묶음**(C2·후진 표적·생명주기): 통합 A/B 묶음이 끝난 뒤 따로, 기준선이 고른 동시 수로 돌린다. 이 세션들은 페이스 판정에 쓰지 않는다.
  - 실행 목록(순서·짝·먼저 시작하는 팔)은 제출 전에 결과 폴더에 고정하고 그 해시를 총괄에 준다.

- 다시 낼 수 있는 경우는 둘뿐이다: (a) 기반 실패(Isaac 기동 실패·`startup_silent`·`startup_viewport`·탐침 전 래퍼 종료) — 그 세션(통합 A/B 는 그 짝 전체)을 한 번, (b) 다른 Slurm 잡이 겹쳐 무효가 된 묶음 — 그 묶음 전체를 한 번. 같은 세션을 두 번 넘게 내지 않는다.
- 상한은 **실제로 돌린 세션 수 전체**(최초 + 다시 낸 것 + 무효가 된 것) 30 이다.
- 순서: 최초 24 세션을 모두 마친 뒤에 다시 낸다. 무효가 된 묶음을 먼저, 그다음 기반 실패를 원래 실행 목록 순서로 낸다. 하나를 다시 내는 데 필요한 세션 수(통합 A/B 는 짝 2, 무효 묶음은 그 묶음 전체)가 남은 상한 안에 다 들어갈 때만 시작하고, 안 들어가면 그것부터 뒤는 내지 않는다.
- 상한에 닿았거나 한 번 다시 낸 것이 또 실패하면 더 내지 않는다. 그 항목은 판정 불가로 처분한다: 통합 A/B 짝은 빠진 짝으로 세고(위 2 짝 규칙), 생명주기·후진 표적·C2 는 그 기준을 통과하지 못한 것으로 보고 해당 항목을 보류한다.
- 잡음·결과가 나쁘다는 이유로는 다시 내지 않는다.

### 3.3 판정 (결과 전 고정)

**페이스(본판정, 통합 A/B 16 세션 = 8 짝·팔당 8 세션).**

- 원천: stall 과 스텝 간격은 틱 기록의 `S`(H4 로 전 구간), F·R·최장 ok=false 는 스텝별 기록(2 절과 같은 정의). 구간은 짝 동시 실행이면 짝의 공통 구간, 한 세션씩이면 세션의 측정 창이다(3.1). stall 은 그 구간 안의 `S[k]` 로 센다. 앞 등록 3.4 의 대체 원천은 쓰지 않는다.
- **짝 적격(업무량)**: 짝의 두 세션이 모두 세 임무를 제출해 셋 다 `done` 으로 끝났을 때만 그 짝을 페이스에 넣는다. 한쪽이라도 임무 거부·대기열 조기 중단·미완료가 있으면 그 짝은 빼고 수와 사유를 적는다. 팔 B 쪽만 그런 경우는 'B 만의 실패'로 따로 조사한다.
- **결측**: 그 구간 안에 틱 기록 행이 빠졌거나(`tick_trace.dropped` > 0 또는 `live_step` 끊김) 2 절의 결측 기준에 걸린 세션은 그 짝째 뺀다. 짝을 빼는 사유는 셋이다: 적격(업무량) 미달, 결측, 짝 공통 구간 15 분 미만(3.1). **세 사유로 빠진 짝을 모두 합쳐** 2 개를 넘으면 페이스는 판정 불가이고 보류다.
- 팔별 합산(장면·seed 별 짝 표도 적는다):
  1. **창 배율**: 합산 F = 팔의 모든 세션의 시뮬 시간 합 / 벽시계 합(각 세션 [k₀, k₁]). B ≥ 0.97 × A.
  2. **ok=false 비율**: 합산 R = 팔의 모든 세션의 false 벽시계 합 / 전체 벽시계 합. B ≤ A + 0.01.
  3. **최장 연속 ok=false**: 연속은 `pacing_ok` false 인 스텝이 `step` 번호로 끊김 없이 이어지는 동안이다. 시작은 첫 false 스텝의 `mono` 이고, 끝은 셋 중 하나다.
     - 다음 스텝이 창 안의 true 스텝이면 그 true 스텝의 `mono`.
     - 다음 `step` 이 빠졌으면(결측) 끊기기 전 마지막으로 관측된 false 스텝의 `mono`. 결측 구간은 길이에 넣지 않는다.
     - 창 끝(k₁)까지 false 면 k₁ 의 `mono`.

     **팔 전체 최댓값끼리** 비교한다: max_B ≤ 1.2 × max_A + 2 s. 짝별 값은 표로 보고한다(판정에는 안 씀).
  4. **stall 수(> 0.25 s, 틱 기록 `S[k] − S[k−1]`)**: 전체 stall 로 판정한다. B 의 합산 stall ≤ A 의 합산 stall + 2. ⑤ 의 동기 재계획 스텝만 뺀다(아래).
- **⑤ 동기 재계획 스텝**: 임무 `records.json` 의 `state.observe_end_stands` 가운데 **`kind == "near"`**(C2; 원거리 O1 재계획도 같은 목록에 `installed`·`planning_wall_s` 를 남기므로 `kind` 로 가른다)이고 `planning_wall_s` 가 있는 기록(`installed`·`failed:*` — 계획을 실제로 부른 것; `shadow`·`no_budget` 처럼 부르지 않은 것은 제외)의 `time_s` 와 같은 `tick_t` 를 가진 스텝 k 를 찾고, 그 간격 `S[k] − S[k−1]` 을 stall 수에서 뺀다. 그런 모든 간격에 2.0 s 상한을 두고, 넘으면 ⑤ 는 비동기 처리 검토가 먼저이고 승격하지 않는다. **이 상한은 페이스 판정과 별개로, 이 배치의 모든 유효 세션(통합 A/B 의 B 팔, C2 fixture, 후진 표적, 생명주기)의 측정 창 전체에 있는 C2 계획 호출 스텝에 적용한다.** 페이스에서 빠진 세션이라도 그 스텝의 간격은 본다. 대응 스텝을 못 찾으면 ⑤ 의 시간 판정은 판정 불가다. 이 제외는 stall 수에만 적용하고 F·R·최장 ok=false 에는 적용하지 않는다.
- 넷 다 통과하면 페이스 통과, 하나라도 못 미치면 보류다. 결론은 '이 네 지표가 각각의 예산 안에 있음'으로만 쓴다. 결과의 유효 범위는 실측 창 배율(예: '목표 0.3, 실측 0.28')로 적는다.
- 허용치(F ×0.97, R +0.01, 최장 1.2 배 + 2 s, stall +2)는 '악화 없음'이 아니라 **이만큼의 악화까지 허용하는 총괄 정책 예산(2026-11-08 승인)**이다. F ×0.97 은 기준선과 같은 3 % 정책이다. 나머지의 근거는 운용 영향이다: 팔마다 약 1 시간 운전에서 ok=false 시간 1 %p, 0.25 s 넘는 끊김 2 회, 최장 끊김 20 % + 2 s 까지는 콘솔 조작과 텔레옵 허가에 실질 영향이 없다고 본다.
- stall +2 는 16782 에서 본 B 의 추가 stall 2 개와 같은 크기다. 그래서 v2 가 통과해도 16782 의 B 악화 신호를 반박하는 독립 증거가 아니라, 이 예산 안에서의 회귀 확인일 뿐이다. 16782 자료는 v2 판정에 합치지 않는다. (16782 의 B 는 ②④⑤ 였고 v2 의 B 는 ④⑤ 라 팔 구성도 다르다.)
- 8 짝은 회귀 확인이지 비열등성 입증이 아니다(드문 악화가 없음을 입증하는 표본 수도 아니다). 결과에 적는다.
- **가설(사전 등록, 앞 배치의 사후 분석에서 옴, 판정에 쓰지 않음)**: stall 을 앞 행 표시로 나누면(렌더 스텝 = 앞 행 `rendered` 이고 `capture` 아님, 캡처 처리 = 앞 행 `capture`, 그 밖) 렌더 스텝 stall 은 두 팔이 같은 수준이고, B 의 추가 stall 은 캡처 처리에서 문턱 근처로 나온다. 이 분류는 시간상 분류다. `S[k] − S[k−1]` 에는 앞 스텝의 물리·미디어와 현재 제어 틱이 함께 들어가므로, 분류가 원인을 가르지는 않는다. 결과에는 분류별 수를 팔별로 따로 집계해 적고(특히 캡처 렌더 뒤 제어 틱 stall), 가설이 맞았는지만 쓴다(총괄 조건).

**기능(최소 유효 발화).**

- ④: 후진 표적에서 아래가 한 임무 안에서 모두 이어진 경우가 1 회 이상.
  - 설치: 임무 `records.json` 의 `state.return_start_backoffs` 에 `where: release_replan`·`adopted: true` 항목.
  - 설치된 경로: 그 임무 `records.json` 의 `state.paths.return_home` 에 `start_backoff`(`status: prefix`, 길이 L)가 있고 첫 방향이 후진(−1)이다. `state.paths.return_home` 은 놓은 뒤 재계획이 설치한 경로의 기록(`path_record`)인데, 복귀 중 다른 재계획(`stall_replans` 등)이 나중에 덮어쓰면 접두가 남지 않는다(16782 후진 표적 6 임무 중 3 개가 그랬고, 그 재계획 기록은 덮인 경로를 남기지 않는다). 그런 임무의 ④ 실제 후진은 판정 불가로 두고 최소 발화에 세지 않는다.
  - 실제 후진: 참값 뒷차축은 spool `slam.control` 의 참값 열(7 열 중 4–6: x, y, yaw; 0 열 = 시뮬 시각)에서 읽는다(`state.samples` 의 `rear_pose` 는 SLAM 실행에서 추정 자세라 쓰지 않는다). 시작 시각 t₀ 는 run `result.json` `transitions` 의 그 임무 `return_home` 진입 시각이다. t₀ 부터 참값 이동 거리가 L 이 되거나 시뮬 10 s 가 지날 때까지, t₀ 의 참값 방향 기준 앞뒤 변위가 −0.8 × L 이하로 내려가면 충족이다. 팔 A 의 복귀도 후진으로 시작하므로(16782 에서 확인) 이 조건만으로는 접두를 가르지 못한다. 접두의 실행 증거는 위 설치된 경로 기록이고, 이 조건은 그 경로를 실제로 따라 움직였다는 필요조건이다.
  - 복귀 완료: 임무가 `complete` 까지 감.
  - 막힌 시작(`trigger: boxed`) 라이브 발동이 나오면 개별 조사.
- ⑤: line_m C2 on 에서 아래가 1 회 이상: 임무 `records.json` 의 `state.observe_end_stands` 에 `kind: near`·`outcome: installed`(계획 호출 `planning_wall_s` 있음) → 그 임무 `state.near_capture.status: done` → 임무 `complete`.
- ②: v2 대상 아님(H5 주입 배치).

**생명주기(각각 필수 도달·응답·최종 결과; 하나라도 못 미치면 그 생명주기는 미통과).**

- 1 (`main --end-session`): 캡처 안 STOP(`stopped_in_capture`) → 재무장 ack → 재개 ack → `auto_again` → TELEOP 진입 ack → arm ack → 데드맨 만료(`expired_disarmed`) → 재접속 뒤 새 lease ack 와 옛 lease 요청 `stale_lease` 거부 → 마지막 재개 ack → 임무 `done` → `session_end` ack → epoch 종료 코드 0, `result.json`·`tick_trace.npz` 있음.
- 2 (`--cancel-at transport:5`): 운반 단계 도달 → 취소 ack → 임무 `cancelled`(`operator`) → 재제출 두 번 모두 `cargo_held` 거부 → `session_end` ack → epoch 종료 코드 0. H3: `live_log` 에 그 취소의 적용 기록(`t`·`request_id`)이 있고, 탐침 송신 ≤ 런타임 수신 ≤ 적용 기록 시각(같은 시계로 맞춘 값) ≤ 탐침 응답 순서다.
- 3 (시작 재위치 무인): (i) 재위치 확정 → 세션 `running` → 큐 임무 `done` → `session_end` ack → epoch 종료 코드 0 이면 통과. (ii) 실행기가 `reloc_needs_operator` 로 끝나면 '기록대로 끝남'이고, 이때는 안전값이 없으므로 생명주기 기준에서 통과로도 실패로도 세지 않는다. 그 밖의 끝은 미통과.
- 4 (`--stop-wait-at approach:5`): `approach` 도달 → STOP 송신·응답 ack → `STOPPED` → 재무장 ack → 취소 ack → m1 `cancelled` → (회복이 필요하면 `--manual-recovery` 완료) → m2 수락·`done` → `session_end` ack → epoch 종료 코드 0. 보고(판정에 안 씀): 송신 → 응답 지연(`reply_mono − sent_mono`), `reply_mono` 뒤 첫 상태의 정지 래치·적용 바퀴 명령 0, 송신 → 정지(보고 속도 0.005 m/s 미만)까지 시간. 단계 미도달이면 STOP 지연은 미측정이고 생명주기 4 는 미통과다.
- 생명주기 기준은 1·2·4 가 통과하고 3 이 통과 또는 '기록대로 끝남'일 때 통과다. 다시 내는 것은 3.2 의 통일 규칙을 따른다.

- ④·⑤ 는 시험한 조합(④⑤ 함께)으로 권고한다. 둘 중 하나만 기능 확인이나 판정 불가로 떨어지면, 남은 하나만 켠 조합은 페이스를 시험하지 않았으므로 권고하지 않고 총괄에 올린다.

- 그 밖은 보류이고 사유를 적는다.

## 4. ② 주입 배치와의 관계(H5)

- 주입 배치는 별도 계획에서 등록한다. 등록에 들어갈 것: ⓐ 페이스 A/B(A = ④⑤, B = ④⑤ + ②, 주입 없음, 이 문서 3.1·3.3 의 묶음·짝·지표·예산 그대로), ⓑ 주입 세션(정지 → 수동 회복 → 다음 임무, 오탐 판정 원천 H3, ② 켬 생명주기).
- **코드 동일성**: 주입 배치 스냅숏은 v2 스냅숏과 진단 주입 파일만 달라야 한다. 주입 계획이 허용 파일 목록을 고정하고, 두 스냅숏의 **전체 파일 트리**를 비교해(두 커밋의 `git diff --name-only`, 그리고 스냅숏 폴더의 파일별 해시) 목록 밖의 변경이 없는지 본다. 실행 기록 `source_sha256` 는 `forklift_core/**/*.py`·`sim/isaac/**/*.py`·`tools/scene_rig.py` 만 덮으므로(런처·탐침·설정 파일은 못 잡는다) 보조 대조로만 쓴다. v2 뒤 main 변경을 합치면서 ④⑤ 나 감시·공유 제어·런처 기본값 같은 운용 경로가 바뀌면, ④⑤ 의 v2 결과를 그 코드에 옮기지 않는다. 그때는 새 스냅숏에서 **원래 비교(A 대 A + ④ + ⑤)를 v2 의 짝 규칙·지표·예산으로 다시** 한다. ⓐ(④⑤ 대 ④⑤ + ②)는 ② 의 추가 영향만 보므로 ④⑤ 재확인을 대신하지 못한다. 안전·기능 근거는 그 근거를 낸 코드 경로와 관련 설정·입력(설정 파일, 런처, 래퍼, 탐침, 장면 파일, 지도 번들)이 모두 같을 때만 다시 쓴다.
