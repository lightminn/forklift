## 2. 동시 수 기준선

- 조건: 팔 A(라이브 현재 기본) + CT 인식 설정, line_m·random_m 등록 지도, team_spec, `D7_HOLD` on, 배속 0.3, 따라잡기는 0 절의 G1 결정값, H4, `FORKLIFT_LIVE_TICK_TRACE=1`, 영상·기록 설정은 본배치와 같게. 모두 같은 스냅숏, seed 0, 세 임무 큐(앞 배치와 같은 순서), 자동 재시도 0.
- 실행: 동시 수마다 묶음 잡 하나(슬롯 = N), 그 묶음 안에서 시차 60 s 로 N 세션을 동시에 시작한다.
  - 1 동시: line_m, random_m 를 차례로(잡 2 개 또는 슬롯 1 묶음 하나).
  - 2 동시: line_m·random_m.
  - 3 동시: line_m·random_m·line_m.
  - 순서는 1 → 2 → 3, 같은 노드(`--nodelist=ws1`), 다른 잡 없음.
  - 기반 실패(Isaac 기동 실패·`startup_silent`·`startup_viewport`·탐침 전 래퍼 종료)일 때만 그 동시 수를 한 번 다시 낸다. 잡음이 의심된다는 이유로는 다시 재지 않는다.
- 측정 구간: N 동시의 통계는 **N 세션이 모두 측정 창(첫 임무 제출부터 마지막 임무 종료까지) 안에 있는 공통 구간**에서만 낸다. 시차로 늘어선 시작과 끝 꼬리를 빼서 실제 동시 수가 N 인 구간만 본다. 공통 구간이 15 분 미만이면 그 동시 수는 판정 불가이고 총괄에 올린다. 1 동시는 세션 측정 창 전체다.
- 세션 통계(구간 [a, b], 스텝별 기록 = `live_log` 의 `pacing_ok` 기록, `step`·`mono`·`tick_t`):
  - 쓰는 스텝: a ≤ `mono` ≤ b 인 스텝 기록. 첫·끝 스텝을 k₀·k₁ 이라 한다.
  - **창 배율** F = (`tick_t`[k₁] − `tick_t`[k₀]) / (`mono`[k₁] − `mono`[k₀]).
  - **ok=false 비율** R = Σ (`mono`[k+1] − `mono`[k]) · [`pacing_ok`[k] = false] / Σ (`mono`[k+1] − `mono`[k]). 합은 k₀ ≤ k < k₁ 이고 k 와 k+1 이 둘 다 있는 쌍에 대해서다. 간격 [`mono`[k], `mono`[k+1]) 에는 왼쪽 스텝 k 의 상태를 쓴다.
  - 결측: 빠진 `step` 의 간격은 분자·분모 모두에서 뺀다. 빠진 비율이 1 % 를 넘거나 `read_live_log` 가 거부하면 그 세션은 판정 불가다.
  - 참고(판정에 안 씀): 렌더 스텝 뒤 간격의 평균 초과량, stall 수.
- 고르는 규칙(사전 고정):
  - F₁·R₁ = 1 동시 두 세션 F·R 의 평균.
  - N 동시는 그 N 동시의 **모든** 세션이 F ≥ 0.97 × F₁ 이고 R ≤ R₁ + 0.03 일 때 '유지'다.
  - 본배치 동시 수는 유지된 가장 큰 N 이다(2 동시 유지·3 동시 탈락이면 2).
  - **유지된 N 이 하나도 없으면** 동시 수를 고르지 않고 총괄에 올린다(1 동시가 자기 평균 기준에서 떨어지는 경우 포함).
  - 중단선: F₁ < 0.27(pacer 의 ok 기준, 목표의 0.9)이면 고르지 않고 총괄에 올린다. 이 중단선은 원인을 진단하지 않는다.
  - 0.97·+0.03 은 **총괄 정책 결정(2026-11-08 승인)**이다: 검증 배치의 처리량을 위해 배율 3 %·ok=false 3 %p 손실까지 받아들인다는 정책이고, 운용 콘솔의 기준이 아니다. 세션 2/2/3 개로는 반복 변동을 추정하지 못한다는 한계를 결과에 적는다.
- 근거로 쓸 앞 배치 값(3 동시, 16782 기록에서 다시 잼): F 0.2793–0.2873(통합 A/B 0.2818–0.2836). R(ok=false 스텝의 벽시계 몫) 통합 A/B 0.119–0.185, 전체 0.045–0.328. R 이 1 s 배율의 0.27 미만 표본 비율(통합 A/B 0.043–0.094, 전체 0.009–0.145)보다 큰 것은 pacer 가 한 번 떨어지면 ok 를 1 s 동안 다시 세우지 않기 때문이다. 간격을 넘긴 시간의 90.8–93.4 %(세 세션 합 92.3 %)가 렌더 스텝 뒤 간격에서 생겼다(16782 결과 3.5).

### 3.3 판정 (결과 전 고정)

**페이스(본판정, 통합 A/B 16 세션 = 8 짝·팔당 8 세션).**

- 원천: stall 과 스텝 간격은 틱 기록의 `S`(H4 로 전 구간), R·최장 ok=false 는 스텝별 기록(2 절과 같은 정의). 앞 등록 3.4 의 대체 원천은 쓰지 않는다. 측정 창은 세션마다 첫 임무 제출부터 마지막 임무 종료까지다.
- 결측: 측정 창 안에 틱 기록 행이 빠진(`tick_trace.dropped` > 0 이거나 `live_step` 이 끊긴) 세션, 또는 2 절의 결측 기준에 걸린 세션은 페이스에서 빼고 수를 적는다. 그 짝의 다른 팔도 함께 뺀다. 빠진 짝이 2 개를 넘으면 페이스는 판정 불가이고 보류다.
- 팔별 합산(장면·seed 별 표도 적는다):
  1. **ok=false 비율**: 합산 R = 팔의 모든 세션의 false 벽시계 합 / 전체 벽시계 합. B 가 A + 0.01 이하.
  2. **최장 연속 ok=false**: 연속은 `pacing_ok` false 인 스텝이 이어지는 동안이고, 길이는 첫 false 스텝의 `mono` 부터 그다음 true 스텝(또는 끊긴 스텝 앞 마지막 스텝의 다음 스텝)의 `mono` 까지다. 빠진 `step` 은 연속을 끊는다. B 의 세션별 최댓값이 A 의 세션별 최댓값의 1.2 배 + 2 s 이하.
  3. **stall 수(> 0.25 s, 틱 기록 `S[k] − S[k−1]`)**: **전체 stall 로 판정한다**. B 의 합산 stall 이 A 의 합산 stall + 2 이하. ⑤ 의 동기 재계획 스텝(C2 기록 `time_s` 의 스텝)만 빼서 따로 2.0 s 상한으로 본다. ⑤ 의 제외는 stall 수에만 적용하고 R·최장 ok=false 에는 적용하지 않는다.
- 셋 다 통과하면 페이스 통과, 하나라도 못 미치면 보류다. 결과의 유효 범위는 실측 창 배율(예: '목표 0.3, 실측 0.28')로 적는다.
- 허용치(R +0.01, 최장 1.2 배 + 2 s, stall +2)는 '악화 없음'이 아니라 **이만큼의 악화까지 허용하는 총괄 정책 예산(2026-11-08 승인)**이다. 근거는 운용 영향이다: 팔마다 약 1 시간 운전에서 ok=false 시간 1 %p, 0.25 s 넘는 끊김 2 회, 최장 끊김 20 % + 2 s 까지는 콘솔 조작과 텔레옵 허가에 실질 영향이 없다고 본다.
- stall +2 는 16782 에서 본 B 의 추가 stall 2 개와 같은 크기다. 그래서 v2 가 통과해도 16782 의 B 악화 신호를 반박하는 독립 증거가 아니라, 이 예산 안에서의 회귀 확인일 뿐이다. 16782 자료는 v2 판정에 합치지 않는다.
- 8 짝은 회귀 확인이지 비열등성 입증이 아니다(드문 악화가 없음을 입증하는 표본 수도 아니다). 결과에 적는다.
- **가설(사전 등록, 앞 배치의 사후 분석에서 옴, 판정에 쓰지 않음)**: stall 을 앞 행 표시로 나누면(렌더 스텝 = 앞 행 `rendered` 이고 `capture` 아님, 캡처 처리 = 앞 행 `capture`, 그 밖) 렌더 스텝 stall 은 두 팔이 같은 수준이고, B 의 추가 stall 은 캡처 처리에서 문턱 근처로 나온다. 이 분류는 시간상 분류다. `S[k] − S[k−1]` 에는 앞 스텝의 물리·미디어와 현재 제어 틱이 함께 들어가므로, 분류가 원인을 가르지는 않는다. 결과에는 분류별 수를 팔별로 따로 집계해 적고(특히 캡처 렌더 뒤 제어 틱 stall), 가설이 맞았는지만 쓴다. 판정에는 쓰지 않는다(총괄 조건).
