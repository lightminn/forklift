## 0. 범위·도달 범위·지금 할 수 없는 것

- **하는 것**:
  - 관측 실행에서 D435i depth 센서를 연다. IMU 와 같은 프로세스, 같은 장치다.
  - 깊이 프레임과 취득 구간·메타데이터를 기록한다. 픽셀은 옆 파일(npz)에 둔다.
  - 실 깊이 원천 `RealDepthSource` 를 만든다(`frames`·`pocket_frame`·`pocket_check` 계약).
  - 실 `PocketCheck` 생성기를 만든다. 기존 `sim/isaac/pocket_check.py` 를 실 프레임·실 장착·운용자 팔레트 자세에 맞게, 실 경로 옵션을 붙여 쓴다(6 절).
  - 실 경로의 D5 관문이 취득 구간을 따르게 한다. 정지 시작·대기 시작·나이를 구간 아래끝 `lo` 로 판정한다(Codex P1-1).
  - 기록 깊이의 재생(`ReplayDepth`)과 `--replay` 조립, 그리고 시험.
- **완료 조건을 셋으로 나눈다**(설계 7 절, Codex P2-8). 셋은 따로 닫히고, 어느 하나가 다른 것을 대신하지 않는다.
  1. **근접 인식**: 실촬영 근거리 검출기가 valid 관측을 내는가. 지금 0/240(#594)이다.
     - 7e 코드로는 닫지 않는다. 검출기 개선은 후속 범위다.
     - 7e 는 실 프레임을 검출기의 오프라인 입력 형식(#594 의 `tools/` 경로)으로 옮길 수 있게 기록하는 데까지 한다(벤치 B4).
  2. **D5 깊이 검사**: 새 깊이 프레임으로 정지 가능 공간을 확인하는가. 인식과 별개로 시험하고, 팔레트 자세는 운용자 입력이다(출처 `operator_input`).
     - **코드 쪽**은 합성 프레임으로 닫는다.
       - 빈 포켓: 면제 영역 안의 정지 호에서 양의 허용치가 나온다.
       - 알려진 표면(팔레트·바닥·자기 차체)에서 **표면 허용폭보다 멀리 떨어진** 포켓 안 물체: `pocket_obstacle`(별도 물체로 검출)이 나온다. 단순히 제한 0 인지가 아니라 이유까지 본다(Codex P2-1).
       - 표면 허용폭은 거리에 따라 커진다(6.2 의 표: σ_a 0.0058·표면 여유 20 mm 에서 1.0 m 38 mm, 1.2 m 46 mm, 1.5 m 61 mm). 그보다 얇게 표면에 붙은 물체는 표면으로 분류되며, 검출 한계로 기록한다. D0 범위(3 cm 미만 돌출은 범위 밖)와 함께 이 한계를 B5 에서 실측한다(Codex 2 회차 P2-3).
       - 이때 실제 잡음 꼴(꼬리·공간 상관·결측)과 운용자 자세 오차를 넣는다.
       - 코드 쪽의 결과에는 **팔레트–차 상대 오차 상한의 합성 잠정값**(시험한 형상·장착·경로에서)이 포함된다(6.2). 실 D5 운용 승인은 S10 전 실 장착·팔레트 확인 뒤다. 실차의 운용자 자세 오차 + SLAM 위치 오차가 그 상한을 넘으면 실 D5 는 그 조건에서 쓸 수 없고 우회만 남는다. 이 결과는 총괄에 보고한다.
     - **실 프레임 쪽**은 벤치 B5 로 닫는다. 빈 포켓의 거짓 양성률(영구 래치)도 잰다(agy 1).
  3. **우회 운용**: `d5_pocket` 은 운용자가 미션 전에 고르는 5d 우회다(검사 영역 면제, 0.06 m/s 상한).
     - 실 검사가 실패해도 자동으로 우회로 바꾸지 않는다.
     - 우회로 끝난 실행은 D5 검증으로 세지 않는다.
     - 미션 결과에 별도 필드 `d5: {source, real_counts}` 를 남긴다(6.4). `source = depth` 여도 HIL·재생·합성 입력의 미션은 실 D5 검증 수에 넣지 않는다. 종료 기록에서 시험으로 확인한다(Codex P2-5, 2 회차 P2-6).
- **도달 범위**: 하드웨어 없이 닫히는 범위는 7r 과 같다.
  - 재생 깊이는 기록한 차의 자세에서 찍은 프레임이다. HIL 모형이 움직이면 어긋나므로, 재생은 프레임 시각·외부 변환·`pocket_check` 호출 조건과 배관을 보인다.
  - D5 판정이 맞는지는 2 의 합성 프레임 시험(코드)과 B5(실 프레임)로 본다.
- **지금 할 수 없는 것**:
  - 출하 설정 `config/real/depth.yaml`(새로 만듦)은 전달 지연 상한과 장착이 미측정이다. 그래서 운영 깊이 원천은 만들어지지 않고(`depth_source:delay_unmeasured`·`mount_unmeasured`), D5 는 `d5_pocket` 우회로만 간다. 7b 의 IMU 와 같은 규칙이다.
  - 재생도 출하 설정이면 `replay_needs_bound` 로 거부한다.
  - S10 시험 팔레트의 실측 기하가 없다. 기하 파일이 없거나 S10-A 의 외곽 치수와 다르면 생성기가 거부한다(`pallet_geometry_unset`/`pallet_geometry_mismatch`).
- **하지 않는 것**(설계 7 절 후속 범위):
  - `instance_ids` 없는 proposer;
  - ARM64 ONNX provider;
  - 방향 불명·깊이 오래됨이면 삽입 정지(5d 의 나이 검사가 이미 하는 부분은 제외);
  - 승강 높이별 외부 변환의 실측(S7, B6);
  - 근거리 검출기 개선;
  - 실 잡음에 맞춘 검사기 판정 규칙의 재설계(다중 프레임 일치·후처리 필터). B5 결과로 필요하다고 판정되면 후속 PR 로 연다(분기 기준: 10 절 B5).

## 1. 장치 — 같은 프로세스에서 depth 센서 열기

- 설계 5 절: 프로세스가 D435i 를 하나만 연다. `tools/imu_record.RealSenseSource` 가 motion 센서 객체를 직접 연다. 같은 장치에서 depth 센서 객체를 따로 연다.
- **프로필**: Z16, 기본 640×480, 15 Hz.
  - 해상도는 팀 잡음 측정과 같게 둔다(`config/depth_noise_d435i_team.yaml` `source_fx` 388.8 = 640 폭, `tools/capture_d435i_noise.py` 기본 640×480).
  - 실제로 열린 프로필(해상도·fps·`depth_units`)을 기록한다.
  - 15 Hz 가 예산 부등식(2 절)을 못 맞추면 30 Hz 로 올린다. 그때 USB 대역(B2)을 다시 본다.
- **센서 설정을 고정하고 기록한다**(agy 4). `config/real/depth.yaml` `sensor`:
  - `global_time_enabled`(장치 시각 도메인 고정);
  - 시각 프리셋, 이미터·레이저 출력, 자동 노출과 노출 상한;
  - 후처리 필터는 쓰지 않는다(SDK 필터 없음).
  - 연 뒤 실제 값을 읽어 기록한다. 설정과 다르면 열기를 거부한다.
  - 메타데이터가 비는 백엔드(RSUSB 등)는 그 사실을 기록하고, `timestamp_domain` 이 `system_time` 뿐이면 진단 전용으로 둔다.
- **콜백**: 동기화기를 쓰지 않는다.
  - 깊이 콜백은 SDK 프레임을 붙잡지 않는다. `uint16` 버퍼를 즉시 복사하고 메타데이터만 읽은 뒤 크기 제한 큐(기본 8 장)에 넣는다(agy 7).
  - 그래서 깊이 처리가 밀려도 IMU 콜백이 기다리지 않는다(설계 5 절).
  - 큐가 차면 가장 오래된 것을 버린다. 관측 실행에서는 이 큐가 기록기 앞이므로 **원본 상실이고 기록이 미완**이다(`record_incomplete`, Codex 2 회차 P2-5). 운영 원천에서 기록된 뒤 검사기 쪽 큐에서만 버린 것은 세대 경계다(2 절).
- **장치 상실과 부분 실패**(agy 7):
  - 장치 하나에 원천 둘이므로 `set_devices_changed_callback`·열기 실패·스트림 중단은 두 원천 모두에 `lost` 로 알린다.
  - 한 센서만 열리면 전체를 닫고 거부한다(관측 실행은 종료 2).
  - 정리 순서: 정지 → 닫기, 두 센서 각각, 실패해도 다음 단계를 한다.
- 프레임마다 남기는 것:
  - 호스트 수신 단조 ns, `frame_number`;
  - SDK `timestamp` 와 `timestamp_domain`;
  - 메타데이터: `frame_timestamp`·`sensor_timestamp`·`time_of_arrival`·노출(있는 것만);
  - `depth_units`, 내부 보정, **보정 식별자**(4.3).

## 2. 시각 — 취득 구간과 예산

- **구간**: 설계 3.1 의 IMU 규칙을 따른다. 취득 구간은 `[lo, hi] = [호스트 수신 − delay_bound_s, 호스트 수신]` 이다.
- **장치 시각**은 구간에 쓰지 않는다. 쓰는 곳:
  - 순서·중복·되감기(재시작) 판정;
  - 지연 일관성 검사. 같은 장치 시계 세대 안의 **모든 프레임 쌍**에 대해, IMU(`imu_source.py` 390 부근)와 같은 누적 min/max 식으로 수신 지연 차이가 `상한 + 1 ms + 100 ppm × 장치 시각 간격` 안인지 본다. 이웃 쌍만 보면 지연이 조금씩 쌓이는 것을 놓친다(Codex P2-2). 위반하면 운영 출력을 멈추고 세대를 연다.
- **상한**:
  - `delay_bound_s` 가 null(미측정)이면 프레임은 진단 전용이다.
  - 일정한 지연 몫은 장치 시각 맞춤이나 정지 기록(B1)으로 보이지 않는다(3.1). 그래서 상한은 측정 근거나, 7a-3 처럼 근거를 문서로 적은 공학 상한 결정(`basis: engineering`, 총괄 예외 결정)으로만 기입한다. B1 은 그 판단의 원자료다.
- **예산 부등식**(agy 3, Codex P2-2): 설정 검증과 관측 프로필 기록에서 확인한다(IMU `fits_watch` 와 같은 자리).
  - 식: `delay_bound_s + 1/fps + 수신 간격 변동 + STATE 확보 대기 + tick_s + WRITE_MARGIN_S ≤ frame_max_age_s`. 수치: 0.2 s, 송신 여유 35 ms, 틱 20 ms.
  - STATE 확보 대기는 깊이 `hi` 뒤에 계측 구간이 시작하는 STATE 가 올 때까지의 시간이다(3 절 `_span`). 최대 `STATE 지연 상한 + STATE 수신 간격` 이다. Codex 3 회차 P2-1 의 예는 상한 50 ms·간격 20 ms 로 두 틱을 기다렸다.
  - 15 Hz 무손실이면 상한은 0.2 − 0.0667 − 0.035 ≈ 0.098 s 에서 변동·STATE 대기·틱을 뺀 값보다 작아야 한다.
  - 넘으면 대안을 순서대로 본다: 30 Hz, 노출 상한 고정, 그다음 `frame_max_age_s`·정지 모형 재설계(후속).
- **세대**: 다음에서 깊이 세대가 오른다.
  - 수신 공백(`receive_gap_s`, 기본 0.3 s, 15 Hz 의 4.5 주기);
  - 장치 시각 되감기, 시각 도메인 변경, 지연 일관성 위반;
  - 큐 넘침, 장치 상실.
  - 세대가 바뀌면 원천은 경계보다 `lo` 가 이른 프레임을 내지 않는다. **검사기 안에 이미 들어간 인증도 지운다**(6.2). 원천 큐와 첫 프레임 캐시만 비워서는 검사기 메모리가 남는다(Codex P1-3).
- **상한의 적용 조건**(Codex 2 회차 P2-2): LiDAR 의 `timing.applies_to` 처럼 깊이 설정의 상한은 `applies_to` 에 적힌 촬영 조건에만 붙는다. 조건은 장치 일련번호·펌웨어·USB 종류·백엔드·프로필(해상도·fps)·센서 설정 실제 값의 sha256 이다. 조건이 다른 프레임과 `timestamp_domain` 이 `system_time` 인 프레임은 설정에 상한이 있어도 **진단 전용**이다. 재생의 재판정에서도 그대로다.
- **보정 묶기**(Codex 2 회차 P2-2): 운영 원천은 처음 낸 프레임의 `calib_id` 에 묶인다. 다른 `calib_id` 가 오면 세대 경계를 두고, 그 보정으로 만든 검사기는 `depth_calibration_changed` 로 무효가 된다(검사기는 첫 내부 보정으로 계속 투영하므로).
- **검사기에 넣는 시각**:
  - `stamp_s = hi`, `PocketConfig.frame_lag_s = delay_bound_s`. 그러면 기존 후속 프레임 나이 규칙 `t − (stamp − lag) ≤ frame_max_age_s` 가 `lo` 기준이 된다.
  - 다만 첫 프레임 관문과 정지 관문은 `stamp_s` 만 본다. 그래서 실 경로에서 그것을 바꾼다(3 절, Codex P1-1).

## 3. 실 경로의 D5 관문 — 구간 아래끝으로(7e-2, 미션 코어·실 루프 변경)

- 실 깊이 프레임은 `lo_s` 를 함께 든다. `lo_s` 를 읽는 코드는 **실차 분기 안에만** 둔다(코어는 `self._real_vehicle()` 안, 루프 `_feed_depth` 는 실차 루프 전용). Isaac 재생의 프록시는 기록에 없는 속성 조회를 `getattr(…, 기본값)` 이어도 실패로 보므로, Isaac 경로에서는 새 속성을 조회하지 않는다(Codex 2 회차 P2-4, `mission/replay.py` 728). `lo_s` 가 없는 프레임의 대체값은 호출 지점마다 다르다(아래).
- `core._known_first_frame`(실차 분기):
  - 신선도 `0 ≤ t − lo_s ≤ KNOWN_FRAME_MAX_AGE_S`, 그리고 기존의 미래 거부 `stamp_s ≤ t` 는 그대로;
  - 정지 구간 `lo_s ≥ still_since`;
  - `lo_s` 없는 프레임의 대체값은 `stamp_s`(지금 식과 같음).
- `real_loop._feed_depth`:
  - 나이 `t − lo_s ≤ max_age`. `lo_s` 없는 프레임은 지금 식 `t − (stamp − lag)` 그대로다. `lo_s = stamp_s` 로 대체하면 지연이 있는 프레임의 허용 범위가 넓어진다;
  - 미래 `hi` 거부(`stamp > t`)는 그대로;
  - 삽입 전 정지 해제는 `lo_s ≥ wait_started` 그리고 `lo_s ≥ still_from`, 그리고 그 프레임이 6.2 의 **정지 해제 관측** 요건을 채울 때만(`out.new` 만으로는 풀지 않음, Codex 2 회차 P1-1).
- 정상 DRIVE 질의는 `t + 송신 여유` 에서 나이를 다시 본다(`core.py` 6849 부근). `last_new_s − frame_lag_s` 가 `lo` 이므로 이미 맞는다. 이를 시험으로 고정한다.
- **자세·승강은 구간 전체로, STATE 의 계측 구간으로**(Codex P1-2, 2 회차 P1-2, agy 2):
  - 지금 `pose_history` 는 마지막 STATE 의 자세를 **제어 틱 시각**에 적는다. 그래서 그것을 쓰면 카메라 구간을 덮어도 STATE 계측 시각과의 차이가 빠진다. 예: 0.15 m/s, STATE 가 50 ms 전 계측이면 7.5 mm 인데, 깊이 상한 20 ms 의 여유는 3 mm 다.
  - 그래서 `_span(lo, hi)` 는 LiDAR 배치와 같은 원자료를 쓴다. 루프의 `odom_history`, 즉 각 STATE 의 계측 구간 `[lo, hi]`(지연 상한 `DelayBound`)과 그때의 오도메트리 자세다(`slam_real_scan.pick_odom` 과 같은 규칙).
  - 조건: 깊이 구간을 덮는 계측 구간의 STATE 들이 연속이어야 한다.
    - **아직 뒤따르는 STATE 가 오지 않은 경우**(`pick_odom` 의 `not_yet`)는 버리지 않고 보류한다(7c 의 SLAM 원천과 같은 구분, Codex 3 회차 P2-1). 신선도 한도 안에서 다음 틱에 다시 본다.
    - 복구할 수 없는 경우(지연 상한 없음·끊김), 보류 중 신선도 한도를 넘김, 보류 중 깊이 세대·적용 보정이 바뀜이면 버린다.
    - 보류는 신선도 한도 안의 프레임 여럿이다(15 Hz 면 최대 3 장, 30 Hz 면 6 장). 틱마다 그중 **뒤따르는 STATE 를 확보한 후보 가운데 최신 것** 하나를 처리한다. 최신 도착 한 장만 두면 30 Hz 에서 뒤따르는 STATE 가 오기 전에 새 프레임이 후보를 계속 대체해, 준비된 프레임이 0 장이 된다(Codex 4 회차 P2-1: 0–360 ms 동안 0 장).
  - 넣는 자세: 깊이 `hi` 에서 보간한 오도메트리 자세에 그 구간 전체에서 같은 적용 보정을 합성한 지도 자세다(보정이 구간 안에서 바뀌면 이미 `depth_span_mixed` 로 버림).
  - 불확도: `(깊이 상한 + STATE 계측 구간 폭) × (구간의 최대 속도 상한 + 최대 회전율 × 팔)`. 두 시계의 상대 오차를 여기 넣는다.
  - 승강도 같은 STATE 들에서 읽는다. 모두 유효하고 폭이 `lift_tol_m`(잠정 0.005 m) 안일 때만 쓴다.
- **외부 변환은 프레임마다 확인한다**(Codex P1-2): 검사기는 첫 프레임의 `base_from_optical` 로 계속 투영한다. 그래서 실 경로는 승강이 `lift_fixed_range_m`(설정, 잠정 [0, 0.01] m) 안인 프레임만 넣는다. 이 범위에서 외부 변환이 고정이라는 것이 승강 0 장착 기준의 근거다. 밖이면 `depth_lift_out_of_range` 로 버린다. 승강별 외부 변환(B6, S7)이 생기기 전까지의 제한이다.

## 4. 기록 형식과 왕복 시험

### 4.1 형식(7e-1)

- 관측 기록(`observe_record/1`)에 `depth` 행을 더한다. 키:
  - `host_ns`·`lo`·`hi`·`gen`·`verdict`;
  - `frame_number`·`timestamp`·`domain`·`meta`;
  - `units`·`intrinsics`·`calib_id`;
  - `npz`·`key`(옆 파일 이름과 그 안의 배열 이름)·`sha256`(원시 Z16 바이트);
  - `shape`·`dtype`.
- **옆 파일**: 기록마다 전용 폴더 `<기록 이름>.depth/` 를 **배타적으로** 만든다(이미 있으면 거부, JSONL 의 배타적 생성과 같음, Codex 2 회차 P2-5). 그 안에 `depth_NNNN.npz`(무압축 `np.savez`)를 두고, 프레임마다 배열 하나(`f000123`)를 둔다. JSONL 의 `npz` 키는 그 폴더 기준 상대 이름이다.
  - 한 파일에 최대 30 장(15 Hz 로 2 s, 약 18 MB). 기록기가 메모리에 붙잡는 양을 줄인다(agy 9).
  - 파일을 닫을 때 fsync 하고 sha256 을 `depth_file` 행으로 남긴다.
  - **마지막 부분 묶음**은 종료 때 같은 규칙으로 닫는다. 그 쓰기나 fsync 가 실패하면 기록이 미완이고 `.ok` 를 만들지 않는다(Codex P2-3).
- **완결성**: 깊이 큐 넘침은 원천 세대 경계로 남지만, **기록기 큐** 넘침(원본 상실)은 `record_incomplete` 다. 그 기록은 재생할 수 없다.
- 머리에는 장치(일련번호·펌웨어·USB 종류)·열린 프로필·센서 설정 실제 값·깊이 설정 전체(sha256 포함)를 남긴다.
- **저장 용량**: 실제로 열린 프로필로 계산한다. 필요량 = 폭 × 높이 × 2 B × fps × 기간 × 1.2. 시작 때 빈 공간이 이보다 작으면 거부한다. 640×480·15 Hz 면 9.2 MB/s 이고 30 분에 약 16.6 GB(여유 포함 20 GB)다. 30 Hz 면 두 배다(Codex 2 회차 P3).

### 4.2 재생 자격과 같은 바이트(7e-1)

- 7r 의 `load_replay_record` 를 확장한다. 다음 중 하나라도 어긋나면 `replay_depth_mismatch`:
  - 옆 파일이 모두 있고 해시가 맞음;
  - 각 `depth` 행의 배열이 `uint16`·`shape` 일치, 이름 대응, 프레임 해시 일치;
  - `units` 가 유한 양수이고 머리와 같음;
  - `calib_id` 를 행의 `intrinsics` 에서 다시 계산한 값과 같음.
- 검증 패스에서 `lo`·`hi`·`gen`·`verdict` 를 기록 설정으로 다시 판정해 기록과 같은지 본다(7r 의 IMU 대조와 같은 방식).
- **같은 바이트**: 검증한 옆 파일의 `(dev, inode, size, mtime_ns)` 를 고정한다. 재생 읽기 스레드는 열 때 그것을 대조하고, 프레임 해시도 다시 확인한다. 검증 뒤 바뀐 파일은 읽기 오류(원천 치명)다.

### 4.3 보정 식별자

- `calib_id = sha256(정규 직렬화)`. 정규 직렬화는 JSON 이다: 키 정렬, 실수는 `repr`(왕복 보존).
- 담는 것: 장치 일련번호, 펌웨어, 스트림 종류·해상도, `fx·fy·ppx·ppy`, 왜곡 모델 이름과 계수 다섯.
- **왜곡**(agy 11): `DepthCamera` 는 핀홀만 다룬다.
  - 계수가 모두 0 이 아니면, 그 계수로 화면 안 최대 픽셀 편차를 계산한다.
  - 편차가 `distortion_max_px`(설정, 잠정 0.5 px)를 넘으면 생성기가 거부한다(`depth_distortion`).
  - 실제 값은 B1 에서 확인한다.

### 4.4 왕복 시험

총괄 지시, 설계 1.1. 픽셀은 바이트 단위, 단위·보정 식별자는 동치로 비교한다.

- **7e-1**: 합성 Z16(경계값 0·1·65535, 홀수 폭이 아닌 실제 형상) → 기록기 → npz·JSONL → 재생 기록 읽기(4.2)까지. 실패 사례:
  - 단위가 다름;
  - **식별자는 그대로 두고 내부 보정 한 값만 바꾼 행**;
  - 검증 뒤 바뀐 npz;
  - 옆 파일 한 바이트 변경, 옆 파일 누락;
  - 종료 때 마지막 부분 묶음의 쓰기 실패 → `.ok` 없음.
- **7e-2**: 같은 기록 → `ReplayDepth` → `RealDepthSource` 의 미터 배열. `depth × units`, 0 은 NaN(무측정)이다. 운영 출력까지의 왕복을 본다.

## 5. 실 깊이 원천 `RealDepthSource`(`forklift_core/live/real_depth.py`, 7e-2)

- **입력**: 장치 큐(관측 실행) 또는 재생 스트림(7 절), 깊이 설정, 루프의 자세·승강·미션 이력.
- **계약**(6a·5d, `RunSources.depth`):
  - `frames(now_ns)`: 새 프레임. 각 프레임은 `stamp_s`·`lo_s`·`depth`(미터, NaN 무측정)·`mission_gen`·`phase`·`correction`·`gen`·`frame_number`·운동 상한(3 절)을 든다.
  - `pocket_frame()`: 알려진 시작의 첫 프레임 훅. `scene`·`stamp_s`·`lo_s`·`rear`·`base`·`mission_gen`·`phase`·`correction` 를 낸다. `scene` 에는 깊이·내부 보정·`base_from_optical`.
  - `pocket_check(axis_yaw, rear, base, stamp_s, rear_at_stamp, *, frame)`: 6 절의 생성기.
- **`mission_gen`·`phase`·`correction`**(설계 1.2): 취득 구간 전체에서 루프 이력의 값이 하나로 같을 때만 붙인다. 아니면 버린다(`depth_span_mixed`). 루프에 그 세 값의 변경 시각 목록을 더한다(읽기 전용).
- **외부 변환**: `config/real/depth.yaml` `mount`(`base_from_optical`·`rides_lift`·`measured`)와 3 절의 고정 승강 범위.
- **`base_z_m`**: 바닥에서 `base_link` 원점까지의 높이다. 차체 모형 URDF 에서 읽는다(Isaac 이 쓰는 값과 같은 정의).
  - 실차 훅의 `base` 는 `base_from_rear()` 라서 세 번째 값이 yaw 다(`start_reloc.py` 55). 그것을 z 로 쓰지 않는다(Codex P1-2).
  - `base_from_optical` 의 원점은 같은 `base_link` 다.
- **HIL 확인**(7r 과 같은 규칙): 매 호출에서 확인한다. 다음은 버린다:
  - 확인을 잃은 동안의 프레임;
  - 부팅 경계 앞 `lo` 의 프레임;
  - 캐시된 첫 프레임.
- **소진**(agy 5, Codex P2-4): `pocket_frame()`·`frames()` 어느 쪽을 불러도 그 호출의 도착분까지 원천을 진행시킨다.
  - 검사기가 없거나 우회일 때 둘 다 불리지 않은 틱이면, 실행이 틱 뒤에 원천을 진행시키고 출력은 버린다(7r 의 IMU 와 같은 자리).
  - 첫 프레임 후보는 마지막으로 진행한 시점의 최신 유효 프레임 하나만 둔다.
- **읽기 상한**(agy 8): 한 틱에서 검사기 `add_frame` 은 최대 1 장이다(최신 프레임 우선). 밀린 프레임은 버리고 센다. `add_frame` 의 실행 시간은 기록하고, Jetson 측정(B8)의 대상이다.
- **운영 거부**:
  - 설정 `measured: false` → `depth_source:delay_unmeasured`;
  - 장착 미측정 → `depth_source:mount_unmeasured`;
  - 예산 부등식 위반 → `depth_source:budget`.
  - 실 관측 실행은 진단 모드다. 기록만 하고 검사기에 주지 않는다.

## 6. 실 `PocketCheck` 생성기(`real_depth.make_pocket_check`, 7e-2)

### 6.1 인자

- `PocketCheck` 는 `sim/isaac/pocket_check.py` 의 것을 importlib 로 읽는다(`real_run._insertion_geometry` 방식).
- `estimate`: 운용자 팔레트 자세(`pocket["planning_pickup"]`, 출처 `operator_input`).
- `pallet_geometry`: S10-A `pallet.kind` 로 찾는 `config/real/pallet_geometry_<kind>.yaml`.
  - 없으면 `pallet_geometry_unset`.
  - 외곽 치수가 S10-A 의 `pallet_depth_m`·`pallet_width_m` 과 1 mm 넘게 다르면 `pallet_geometry_mismatch`.
  - 구조는 `pallet_boxes` 가 다루는 블록형이어야 한다. 시험 팔레트의 구조 확인은 B7 이다(agy 10).
- `blades_rear`·`body_*`·`insertion_depth_m`: 차체 모형 URDF, Isaac 과 같은 식.
- `base_z_m`: 5 절. `camera`: 기록된 내부 보정(4.3 의 왜곡 거부).
- `stopping`: 층 설정의 정지 모형.
- 첫 프레임은 생성기가 `add_frame` 까지 한다. 그 프레임의 `lo_s`·구간 운동·승강으로 한다(3 절, agy 6).

### 6.2 실 경로 옵션(생성자 인자, 기본은 지금 동작 — Isaac 호출 그대로)

- `synthetic_noise=False`: 합성 가우스 잡음을 더하지 않는다.
- `freshness="evidence"`(Codex P1-3, 2 회차 P1-1): 세 가지를 따로 정의한다.
  1. **장치 프레임의 신규성**: 픽셀 해시가 아니라 **(깊이 세대, `frame_number`)** 로 판정한다. 픽셀이 같아도 새 장치 프레임이면 새 프레임이다. 신규성은 신선도를 올리지 않는다.
  1′. **쓸 수 있는 관측의 신선도**(`depth_stale` 의 기준, Codex 5 회차 P1-2): 새 프레임 가운데, **V 투영 영역**에서 유효 깊이 픽셀이 `view_min_px`(잠정 2,000) 이상이고 그 비율이 `view_valid_min`(잠정 0.5) 이상인 프레임만 `last_new_s` 를 올린다. V 투영 영역은 **픽셀 광선이 V 부피와 교차하는 픽셀의 집합**이다. 지금의 복셀 중심 투영(중복 제거)을 쓰면 삽입 끝에서 1,430 픽셀뿐이라 모든 픽셀이 유효해도 문턱을 못 넘는다(Codex 6 회차 P2-2: 광선 교차로는 27,548 픽셀). 이 마스크를 분모로 쓰는 시험을 고정한다. 전 픽셀 NaN 이나 거의 비어 있는 프레임은 새 프레임이어도 신선도를 올리지 않는다. 그래서 정지 호가 전부 가려졌거나 화면 밖인 자세에서도, NaN 프레임이 이어지면 `depth_stale` 이다. 이 문턱은 정지 호 인증의 근거가 아니다(인증은 복셀별 ②–④). 카메라가 살아 있고 앞을 보고 있다는 것만 판정한다.
  2. **기대 가시성 — 오차를 넣은 세 상태**(Codex 3 회차 P1-1, 4 회차 P1-1): 프레임마다, 시야에 든 V 복셀 각각이 알려진 표면에 가려지는지를 측정과 무관하게 기하로 계산한다. 알려진 표면은 추정 자세의 팔레트 기하와 자기 차체 상자다. 오차는 근거별로 따로 두고, 그 오차를 넣어 세 상태로 나눈다(Codex 6 회차 P2-1).
     - **팔레트–차 상대 오차** `pallet_rel_error_m`: 팔레트 상자에만 적용한다. 운용자 지도 자세 오차(줄자, B7)에 SLAM 위치 오차(지도에서 본 차 자세)를 더한 값이다. 두 근거를 각각 기록한다.
     - **자기 차체 형상 오차** `own_error_m`: 자기 차체 상자에만 적용한다. URDF 상대 형상의 오차다.
     - **카메라 광선 오차**(Codex 7 회차 P1-2): 장착의 병진 오차 `cam_trans_error_m`, 장착·자세의 회전 오차 `cam_rot_error_rad`, 취득 구간 운동(3 절 불확도)을 더한다. 이것은 팔레트와 자기 차체 **양쪽** 가림 판정의 광선을 움직인다. 명목 광선이 앞면 x = 38 mm 를 지나 막혀도, 카메라 원점을 옆으로 10 mm 옮기면 43 mm 를 지나 비킨다. 그래서 상자를 키우고 줄이는 양에 그 상자까지 거리 `d` 에서의 광선 옆 이동 `cam_trans_error_m + d × cam_rot_error_rad + 운동 불확도` 를 더한다. 팔레트 상자에는 `pallet_rel_error_m` 과 함께, 자기 차체 상자에는 `own_error_m` 과 함께 넣는다. 보수적인 근사이고, 상자 면에서의 광선 옆 이동을 덮는다.
     - **확실히 보임**: 표면 상자를 오차만큼 **키워도** 광선이 먼저 만나지 않는다.
     - **확실히 가림**: 표면 상자를 오차만큼 **줄여도** 광선이 먼저 만난다.
     - **불확실**: 그 사이. 오차 범위 안에서 판정이 뒤집힌다. Codex 의 재현에서 팔레트를 20 mm 옮기면 정지 호 복셀 156 개와 44 개가 반대로 분류됐다. 이 띠가 그 경우다. **불확실은 확실히 보임과 똑같이 다룬다.** 반환이 알려진 표면과 양립한다는 것만으로는 가림으로 받지 않는다(Codex 5 회차 P1-1: 불확실 띠의 측면 부착물 반환이 표면 허용폭 안에 들어 장기 인증이 남는 반례).
  3. **프레임의 판정**(복셀마다, 그 프레임에서):
     - 확실히 보임: 지남(free)이면 인증 시각을 그 프레임으로 갱신한다. 지나지 못하면(NaN·앞막힘) **반박**이다(아래).
     - 불확실: 확실히 보임과 같다. 지남이면 갱신하고, 아니면 반박이다.
     - 확실히 가림: 그 프레임은 그 복셀에 대해 아무것도 바꾸지 않는다.
     - **반박**(Codex 4 회차 P1-2): 기대상 보여야 할 복셀을 최신 프레임이 지나지 못했다. 그 복셀의 인증을 **지운다**(인증 시각 −∞). 그래서 직전 인증이 0.2 s 안이어도 다음 질의에서 막힌다. 나중 프레임에서 가려졌다는 이유로 되살아나지 않고, 다시 지나는 프레임만 인증한다. Codex 재현(정상 프레임 60 ms 뒤 정지 호 픽셀 NaN, 나이 165 ms 인 직전 인증 1,166 개가 신선해 `inf, ok`)이 이 규칙으로 막힌다.
  4. **정지 호에 쓸 수 있는 인증**(`limit` 이 정지 호의 상자마다 묻는 것): 정지 호와 겹치는 복셀마다 본다.
     - 최근 새 프레임(①)에서 확실히 보임이었으면 `frame_max_age_s` 안 프레임의 인증이 필요하다.
     - 불확실이었으면 확실히 보임과 같다.
     - 확실히 가림이었으면 수명(`lifetime_s`) 안의 이전 인증을 쓴다. 근거리에서 팔레트 뒤로 숨은 띠가 여기다. Isaac D5 가 근거리 삽입을 통과하는 근거이고, 실 경로 수명은 깊이 설정 값(잠정 20 s, B5 재검토)이다.
     - 반박된 복셀은 인증이 없다.
     - `depth_stale` 은 **마지막 쓸 수 있는 관측(1′)** 이 `frame_max_age_s` 안인지로 판정한다(새 장치 프레임이 아님, Codex 6 회차 P2-2).
  - **정지 해제 증거**(`await_still_frame`): 다음을 모두 만족하는 프레임으로만 푼다. `out.new` 만으로는 풀지 않는다.
    - 새 프레임(①)이고 쓸 수 있는 관측(1′)이다;
    - 정지 구간 안에서 찍혔다(3 절);
    - 현재 깊이 세대·적용 보정의 프레임이다;
    - 삽입 첫 정지 호의 확실히 보임·불확실 복셀을 모두 인증했다. 그런 복셀이 없어도 앞의 셋은 필요하다(빈 집합으로 풀리지 않음).
  - 표면에 붙은 범위 내 물체(D0: 3 cm 이상)가 있으면, 그 뒤 복셀은 기대상 보이는데 그 프레임에서 지나지 못한다. 그래서 반박으로 인증이 지워지고, 장애물 래치 여부와 상관없이 그 앞에서 멈춘다. 기존 D5 설계의 전제를 실 경로에서도 지키는 규칙이다(`docs/plans/2026-10-04-lidar-obstacle-map.md` 2366, Codex 3 회차 P2-2).
  - **이 규칙의 대가 — 실 D5 가 쓸 수 있는 조건**(Codex 6 회차 P2-1): 정렬된 빈 포켓이어도 상대 오차 띠 안의 복셀은 불확실이 된다. 정상 표면에 가려 지나지 못하므로 반박되고, 삽입 끝 가까이에서 멈춘다. EPAL 6 합성 픽스처에서 오차 20 mm 이면 삽입 끝 0.30 m 전 가시 복셀 924 개 중 246 개, 오차 0 이면 0 개다.
    - 따라서 실 D5 는 팔레트–차 상대 오차가 작을 때만 삽입 끝까지 통과한다.
    - 7e-2 는 합성 시험으로 **통과 가능한 상대 오차 상한의 잠정값**을 구한다. 두 가지를 본다:
      - 정렬된 빈 포켓에서 설정값만 바꾼 경우(0·5·10·15·20 mm);
      - 그 설정값 안에서 실제 팔레트를 앞뒤·좌우·회전으로 어긋낸 경우(Codex 7 회차 P2): 빈 포켓 통과와 장애물 앞 정지를 둘 다 확인한다.
    - 합성 결과는 **시험한 형상·장착·경로에서의 잠정값**이다. S10 에 적용하기 전에는 실제 장착·실제 팔레트에서 후보 상한 안의 오차를 주입해 빈 포켓 통과와 장애물 앞 정지를 둘 다 확인해야 한다(S10 선행 조건, 이 PR 밖).
    - 통과값이 없거나 실측 오차 상한을 확인하지 못하면 실 D5 운용은 **미승인**이다.
    - 실차에서 운용자 자세 오차와 SLAM 위치 오차의 합(지금 SLAM 자체 오차는 cm 단위)이 그 상한을 넘으면, 실 D5 는 그 조건에서 쓸 수 없다. D5 는 `d5_pocket` 우회로만 남는다. 이것은 규칙을 풀어 해결하지 않는다. 결과는 총괄에 보고하고 S10 의 D5 운용 결정 근거로 쓴다.
    - 상대 오차를 줄이는 길(근접 인식으로 상대 자세 추정, 정지 상태의 깊이 맞춤)은 후속 범위다.
  - 기대 가시성 계산은 V 복셀 수(수만 개)에 대한 광선·상자 검사다. 계산 시간은 B8 에서 `add_frame` 시간으로 함께 잰다. 정상 접근을 막지 않는지는 Isaac D5 기록의 오프라인 재생(`tools/d5_replay.py`, ws1)으로 확인한다. 정지가 늘면 규칙과 근거를 다시 본다(9.2).
- `forget(reason)`: 인증 메모리를 지운다(인증 시각 −∞). 장애물 래치는 남긴다.
  - **언제**: 깊이 세대가 바뀔 때, 그리고 적용 보정이 바뀔 때다. 옛 보정의 프레임으로 인증한 복셀이 지도 자세가 옮겨진 뒤에도 남지 않게 한다.
  - **반영 시점**(Codex 2 회차 P2-1, 3 회차 P1-2): 검사기 생성자에 `guard`(실 경로만, 기본 None)를 준다. `guard()` 는 원천의 현재 깊이 세대와 코어의 지금 적용 보정을 돌려준다.
    - 검사기는 `limit()` 과 `add_frame()` 맨 앞에서 `guard()` 를 읽고, 마지막 값과 다르면 먼저 `forget` 한다.
    - 그래서 D5 질의는 어디서 부르든 지운 뒤에 답한다. 삽입 완료(`_real_insert_end`)·재개(`path_blocked:pocket`)·정상 DRIVE 모두다. 그리고 새 세대 프레임은 `add_frame` 전에 경계가 적용된다.
    - 루프의 허가 질의 직전에만 두면, `core.arrive()` 안의 삽입 완료 관문이 먼저 옛 인증으로 통과해 `lift` 로 넘어간다(Codex 재현).
    - `forget` 은 인증만이 아니라 신선도(`last_new_s = −∞`)와 정지 해제 근거도 무효로 한다. 경계 시각 `boundary_s` 를 남긴다.
    - **프레임을 지금 세대에 묶는다**(Codex 4 회차 P1-3): `add_frame` 은 그 프레임이 든 (깊이 세대, 적용 보정)이 `guard()` 의 지금 값과 같을 때만 받는다. 원천에서 세대 G 프레임을 꺼낸 뒤 `add_frame` 전에 G+1 이 공개되면, 그 프레임은 거부하고 센다(`frame_generation_stale`).
    - **정지 해제 권한도 경계에 묶는다**: 실 경로에서는 다음을 지킨다.
      - 루프의 `_feed_depth` 는 검사기의 `boundary_s` 가 코어의 `still_frame_s` 보다 늦으면, 삽입 단계(또는 접근 끝 대기)에서 `await_still_frame` 을 다시 켠다.
      - `_real_insert_end` 는 실차 분기에서, 검사기가 실 깊이 검사기일 때만(`bypass` 가 아닐 때) `still_frame_s ≥ boundary_s` 를 요구한다. 명시적 우회(`BypassPocketCheck`)에는 두 값이 없고, 우회 중에는 정지 프레임 대기를 만들지 않는 기존 동작 그대로다(Codex 5 회차 P2-1).
      - 그래서 새 세대의 움직이는 프레임으로 인증이 채워져도 재정지 관문을 건너뛰지 않는다.
      - 두 곳의 새 조회는 실차 분기 안에만 둔다(Isaac 프록시).
    - **송신 관문까지 묶는다**(Codex 5 회차 P2-2): `limit()` 이 허가한 뒤 첫 바이트나 이어 쓰기 전에 원천이 새 세대를 공개할 수 있다.
      - D5 가 결정에 든 출력(정상 DRIVE·재개·삽입 완료 뒤 승강)은 그 판단에 쓴 (깊이 세대, 적용 보정)을 출력 후보에 남긴다.
      - 송신 관문은 그것을 `guard()` 의 지금 값과 대조한다. 다르면 그 출력을 내지 않고 대기 프레임으로 바꾼다(`d5_generation_changed`).
      - 픽셀 계산은 송신 관문에서 반복하지 않는다.
      - **정상 DRIVE·재개**의 불일치는 대기 프레임이다. 다음 틱에 검사기가 `guard` 로 지운 뒤 다시 판정한다.
      - **삽입 완료 뒤 승강**(Codex 6 회차 P1): 지금 순서는 삽입 완료 판정 → `transition("lift")` → 검사기·면제 제거 → 승강 목표 → 송신이다. 그래서 첫 승강 출력을 막아도 다음 틱에 검사기 없이 `lift` 가 새 승강 출력을 만든다. 실 경로는 다음을 지킨다.
        - 승강 출력은 삽입 완료 판단 때의 **토큰**을 들고, 첫 승강 명령이 실제로 송신될 때까지 매 출력에 그것을 붙인다. 토큰은 (깊이 세대, 적용 보정, **유효 기한**)이다.
        - 유효 기한은 다음 중 가장 이른 시각이다(Codex 7 회차 P1-1): 마지막 쓸 수 있는 관측의 `lo + frame_max_age_s`, 그 판정에 쓴 정지 호 복셀 인증들의 만료 시각. 세대가 그대로여도 증거는 만료된다. 취득 하한 0.810 s 인 증거는 판정 시각 1.000 s 에 `inf, ok` 였지만 25 ms 뒤에는 `0, depth_stale` 였다.
        - 송신 관문에서 세대·보정이 다르거나 쓰기 시각이 유효 기한을 넘으면, 그 출력을 내지 않고 미션을 `recovery_required` 로 끝낸다(`d5_generation_changed` 또는 `d5_evidence_expired`). 제어 정지가 따르고 승강은 측정 위치에 멈춘다. 재판정할 검사기가 없으므로 대기로 두지 않는다.
        - 정상 DRIVE·재개의 토큰에도 같은 유효 기한을 넣는다. 넘으면 대기 프레임이다.
        - 첫 승강 명령이 송신된 뒤에는 토큰을 붙이지 않는다. 그때부터는 D5 범위 밖(들어 올림)이다.
      - 토큰은 출력 후보만이 아니라 **송신 큐의 프레임**에도 묶는다. 첫 쓰기와 이어 쓰기 직전에 세대·보정과 유효 기한을 대조한다. 이미 일부 바이트를 쓴 프레임은 기존 `link_stuck`·이어 쓰기 경로를 따르고, 불일치·만료면 그 프레임을 포기하고 독 바이트열 경로로 간다.
  - **회복**: 알려진 팔레트 접근은 `approach` 진입부터 적용 보정을 hold 하므로(`core.py` 554·1755) 접근 중에는 보통 지워지지 않는다.
    - 지워졌을 때 제자리에서 다시 볼 수 있는 띠(카메라 시야 안)는 다음 새 프레임이 기대 가시 복셀로 지나면 다시 인증된다.

    - 합성 시험에서 '삽입 끝 0.10 m 전 지움 → 새 프레임 세 장 모두 `pocket_unverified`'(Codex 재현)를 그대로 고정한다.
- `surface_estimate_m` 은 깊이 설정의 값이다. 근접 검출 추정 오차(20 mm)가 아니라 운용자 줄자 자세 오차에서 정한다(잠정 0.02 m, B5·B7 에서 재검토, Codex P2-1). `sigma_a` 도 깊이 설정의 값이다. 팀 측정의 `frame_640` 성분과 B5 로 정한다(잠정 0.0058, agy 1).

- **자기 차체 형상**(Codex 2 회차 P2-3): 지금 검사기의 자기 차체 필터는 내부 상수다(포크 두께 24 mm, 캐리지 앞면 깊이 20 mm 단일 상자). 측정 차체 URDF 는 포크 25 mm, 캐리지 가로대 28 mm 다(`dls08_measured/forklift.urdf` 1969·2059). 그래서 대조해 거부하지 않는다. 실 경로는 옵션 `own_boxes_from=urdf` 로 URDF 의 포크·캐리지 충돌 상자를 그대로 자기 차체 상자로 쓴다. 기본값(지금 상수)은 Isaac 그대로다.
- `summary()` 의 깊이 설명 문구는 실 경로이면 `real D435i depth` 로 바꾼다(Codex P3).
- 이 옵션들은 생성자 인자다. 검사기 프록시(`RecordingProxy`)는 만든 뒤의 객체를 감싸므로(`run_transport.py` 5900–5925) 기록 경계 밖이다. 그래도 검사기 파일을 바꾸므로 재생 게이트로 확인한다.

### 6.3 유효성과 거부

- 생성기는 `PocketCheck` 의 `valid`·`invalid_reason` 을 그대로 쓴다.
- `RealHooks.build_pocket_check` 는 유효하지 않으면 `pocket_check_refused:<사유>` 로 끝낸다.
- 프레임이 없어 시한을 넘기면 `pocket_stop in approach: pocket_first_frame` 로 끝낸다. 사유가 서로 다르다는 것을 시험으로 고정한다.
- 자동 우회는 없다.

### 6.4 D5 판정 출처

- 미션 결과에 `d5: {source: "depth" | "bypass" | null, real_counts: bool}` 를 둔다.
- `real_counts` 는 다음을 모두 만족할 때만 참이다(Codex 2 회차 P2-6):
  - 실 깊이 검사기가 그 미션의 D5 를 끝까지 판정했다;
  - 입력이 실 센서였다. HIL·재생·합성 입력, 판정 제외 표식이 붙은 실행은 거짓이다. PR 7 동안 운영 REAL 조립은 거부되므로 실제로는 늘 거짓이고, 필드는 S10 을 위한 자리다;
  - 우회, 검사기 없이 끝남, 검사기 거부가 아니다.
- `PocketCheck.summary()` 의 `first_frame` 이 코어 표식을 덮으므로(`pocket_check.py` 357), 출처는 그 키가 아니라 이 필드로 남긴다.
- 실행 결과 집계(`mission_counts`)에 D5 검증 수를 따로 둔다. F1 제외와 섞지 않는다.

## 7. 재생 — `ReplayDepth`(7e-2)

- 7r 의 `ReplayScan`·`ReplayImu` 와 같은 틀(Δ 앵커, 옮긴 도착 시각, 파일 순서 색인, 읽기 스레드, HIL 확인·부팅 경계, EOF)을 쓴다.
- 깊이는 세 번째 스트림이다. 픽셀은 읽기 스레드가 npz 에서 미리 읽는다(4.2 의 같은 바이트 확인). 큐는 30 장(약 18 MB)이다. 틱 안에서는 디스크를 읽지 않는다.
- **기록 종류별 조립**(Codex P2-4):
  - 깊이 없는 기록(7e 이전): `depth=None`. D5 는 우회로만 가고, 우회 없는 알려진 미션은 첫 프레임 시한으로 끝난다.
  - 깊이 있는 기록 + 측정 깊이 설정(`--depth-config`): 운영 깊이 원천. 진단 설정으로 찍은 기록도 같다. 실행 패스는 지금 설정으로 다시 판정하고, 기록 판정과의 차이를 센다(7r 의 IMU 와 같은 규칙). 단 설정의 `applies_to` 가 기록의 촬영 조건(머리의 장치·프로필·센서 설정)과 다르거나 `system_time` 도메인인 프레임은 재판정 뒤에도 진단 전용이다(2 절). 그런 프레임만 있으면 운영 프레임 0 으로 `replay_no_operating_depth` 거부.
  - 깊이 있는 기록 + 미측정 설정: `replay_needs_bound`. `depth=None` 으로 조용히 넘어가지 않는다.
- 표식 대상 설정 목록에 깊이 설정과 팔레트 기하 파일을 더한다.
- EOF 는 깊이 스트림까지 끝나야 한다.

## 8. 관측 실행 `--depth`(7e-1)

- `tools/real_observe.py --imu --depth`: 같은 장치로 둘 다 연다. `--depth` 만 줄 수도 있다.
- 기록은 4 절 형식이고 진단 표식을 단다.
- 원천 진단도 남긴다: 세대, 버림, 수신 지연 분포, 예산 부등식, 센서 설정 실제 값. 검사기에는 주지 않는다(관측 실행에 미션 코어가 없음).
- IMU 를 함께 켰을 때 IMU 의 수신 간격·`fits_watch` 결과도 기록한다(B2 의 비교 지표, agy 7).

### 9.2 7e-2

- **좌표 검산**(Codex P1-2, agy 12): 독립 식으로 알려진 기준점을 투영한다. 광학 Z 전방·X 우·Y 하 ↔ `base_link` X 전방·Y 좌·Z 상. 비영 yaw·카메라 경사·후륜축 오프셋·`base_z_m` 을 넣는다.
- **관문**(Codex P1-1):
  - 구간 `[0.980, 1.040] s`, 정지 시작 1.000 s → 첫 검사기 설치 0 건, 삽입 대기 해제 0 건;
  - `lo ≥ 정지 시작` 인 프레임 → 설치·해제됨;
  - 첫 프레임 나이 `t − lo`;
  - DRIVE 질의 시각(`t + 35 ms`)의 나이.
- **구간 운동**: 구간 앞부분에서 더 빨랐을 때 불확도가 그 속도로 커짐, 이력 끊김 → 버림, 승강 폭 초과·범위 밖 → 버림.
- **신선도·메모리**(Codex P1-3, 2 회차 P1-1·P2-1):
  - 인증 뒤 스트림 끊김 → `depth_stale`;
  - 전 픽셀 NaN 프레임 → 여전히 `depth_stale`(지금 코드는 `inf, ok`);
  - **유효 픽셀 하나만 남긴 프레임** → 정지 호 `pocket_unverified`, 정지 해제 없음(지금 코드는 자유 복셀 3 개 갱신 뒤 `inf, ok`);
  - **정지 호 표적 가림**: 삽입 끝 0.65 m 전에 현재 정지 호와 겹치는 기대 가시 복셀의 픽셀만 NaN 으로 만든 프레임(나머지 시야 95 % 는 정상, Codex 재현) → `pocket_unverified`. 같은 시험 안에서 정상 삽입 말기(확실히 가림 복셀이 수명 안 인증) → 통과. 둘을 대조한다;
  - **반박**: 정상 프레임 60 ms 뒤 정지 호 픽셀 NaN → 송신 여유 35 ms 질의에서 막힘(직전 인증 나이 165 ms 여도). 그다음 프레임이 그 복셀을 가려도 되살아나지 않음;
  - **통과 가능한 상대 오차 상한**: 실제 팔레트와 추정을 일치시킨 정렬된 빈 포켓, 640×480 핀홀, 잡음 없음과 실제 잡음 꼴 두 가지. `pallet_rel_error_m` 을 0·5·10·15·20 mm 로 두고, 삽입 끝까지 통과하는 가장 큰 값을 기록한다(Codex 6 회차 P2-1: 20 mm 에서 0.30 m 전 924 개 중 246 개 반박, 0 에서 0 개). 이 값은 시험한 형상·장착·경로의 합성 잠정값이다(운용 승인은 6.2 의 S10 선행 조건 뒤).
  - **V 투영 영역**: 삽입 끝 프레임에서 광선 교차 마스크가 분모가 됨(27,548 대 1,430), 모든 픽셀 유효면 1′ 통과, NaN 이면 불통과.
  - **오차 안에서 어긋난 자세**: 후보 상한 안에서 실제 팔레트를 앞뒤·좌우·회전으로 어긋낸 장면 → 빈 포켓 통과와 장애물 앞 정지를 각각 본다(Codex 7 회차 P2).
  - **카메라 광선 오차**: 상자 옆면 x = 40 mm·앞면 0.60 m, 카메라 원점 10 mm 이동 사례 → 그 복셀은 확실히 가림이 아니다(Codex 7 회차 P1-2).
  - **자세 오차**: 실제 팔레트를 추정보다 ±20 mm 옮긴 합성 장면, 삽입 끝 0.30 m 전(Codex 4 회차 P1-1 재현의 156·44 개 사례).
    - 실제로 보이는 복셀이 수명 인증을 쓰는 경우는 0 건이어야 한다.
    - 불확실 띠를 보임으로 다루므로 빈 포켓에서도 정지(`pocket_unverified`)할 수 있다. 그 수를 센다. 안전 쪽 실패이고, 줄이는 길은 자세 오차를 줄이는 것(운용자 측정 개선·인식)이지 규칙을 푸는 것이 아니다. Isaac 기록 오프라인 재생과 B5 에서 그 빈도를 본다;
  - **불확실 띠의 측면 부착물**: 장기 인증이 이미 있는 상태에서, 불확실 띠에 표면 허용폭 안으로 붙은 30 mm 이물(Codex 5 회차 P1-1 사례: 깊이 차 28.0 mm, 반환이 상자에서 10 mm) → 반박으로 인증이 지워지고 접촉 전 정지;
  - **정지 호 전부 가림·화면 밖 + NaN 프레임 연속** → `depth_stale`, 정지 해제 없음(Codex 5 회차 P1-2);
  - 인증된 정지 호에 표면(바닥)에 붙은 3 cm 상자가 새로 나타남(표면 허용폭보다 얇아 장애물 래치는 안 됨) → 접촉 전 정지(Codex 3 회차 P2-2);
  - 같은 픽셀의 정상 새 프레임(다른 `frame_number`) → 새 프레임;
  - 세대·보정 변경 → `guard` 로 `limit`·`add_frame` 맨 앞에서 `forget`. 다음 경우를 포함한다:
    - 프레임이 없는 세대 변경;
    - `_feed_depth` 뒤 같은 틱의 보정 해제;
    - **삽입 도착 틱에 프레임 없이 세대가 바뀜** → `lift` 전이 0 건, 승강 출력 0 건(Codex 3 회차 P1-2);
    - **꺼낸 프레임과 `add_frame` 사이의 경계**: 옛 세대 프레임 거부(`frame_generation_stale`)(Codex 4 회차 P1-3);
    - **새 세대 프레임은 있으나 정지 증거가 없는 삽입 도착** → `await_still_frame` 재개, `lift` 전이 0 건;
    - **명시적 우회** → 정지 프레임 대기 없이 삽입 완료와 승강 진입까지 기존대로(Codex 5 회차 P2-1);
    - **질의와 쓰기 사이의 경계 주입**:
      - DRIVE 는 그 틱 출력 0 건·대기 프레임;
      - 첫 승강은 그 틱과 **다음 틱** 모두 승강 출력 0 건, 미션 `recovery_required/d5_generation_changed`;
      - 같은 세대에서 증거 만료: 그 틱 안 만료(판정 1.000 s, 증거 하한 0.810 s, 쓰기 1.025 s)와 층 대기로 다음 틱으로 밀린 만료 → 승강 출력 0 건, `recovery_required/d5_evidence_expired`;
      - 일부 바이트를 쓴 승강 프레임은 이어 쓰기 전 대조로 포기(Codex 5 회차 P2-2, 6 회차 P1);
  - 제자리에서 볼 수 있는 띠는 다음 새 프레임의 기대 가시 인증으로 회복;
  - 삽입 끝 0.10 m 전 지움 → `pocket_unverified` 가 이어져 `pocket_recertify_s` 뒤 `pocket_recertify_failed`;
  - `calib_id` 변경 → 세대 경계와 검사기 무효(`depth_calibration_changed`).
- **실 경로 임계값의 정상 접근 확인**: Isaac D5 기록 몇 건을 `tools/d5_replay.py` 로 실 경로 옵션(`freshness=evidence`·`own_boxes_from=urdf`·`synthetic_noise=False`)을 켜고 오프라인으로 돌린다(ws1). 기존 결과 대비 정지(`depth_stale`·`pocket_unverified`)가 늘지 않는지 본다. 늘면 임계값을 조정하고 근거를 남긴다.
- **회귀**(Codex 2 회차 P2-4): `lo_s` 없고 `lag` 가 0 이 아닌 구형 프레임의 나이는 지금 식 그대로, 미래 `hi` 거부 그대로, Isaac 경로에서 새 속성 조회 0 회(재생 게이트).
- **생성기**(합성 깊이 — `DepthCamera` 핀홀로 팔레트 기하를 투사):
  - 빈 포켓: 면제 영역 안 정지 호의 양의 허용치. 양방향 질의(전진·후진 정지 호, 안전 배선 7.3)를 둘 다 본다(Codex P2-6).
  - 포켓 안에서 알려진 표면과 허용폭(6.2 표)보다 떨어진 3 cm 상자 → `pocket_obstacle`. 바닥·포켓 벽에 붙은 상자는 높이가 그 거리의 허용폭을 넘을 때만 `pocket_obstacle` 이고, 넘지 않으면 표면으로 분류된다는 것을 검출 한계로 고정한다(Codex 2 회차 P2-3).
  - 실제 잡음 꼴: 팀 모형의 상관 성분, 결측 5 %, 꼬리 ±4σ 몇 픽셀. 운용자 자세 오차 ±2 cm. 이 경우 결과를 기록하고, 1픽셀 영구 래치로 빈 포켓이 막히는 비율을 센다(판정 규칙 재설계 여부의 입력, agy 1).
  - 기하 없음·불일치·왜곡·차체 상수 불일치 → 거부 사유.
  - `synthetic_noise=False`: 독립 검사기 둘에 같은 입력 → 같은 결과. 중복 판정은 따로 본다(Codex P3).
- **촬영 조건**(Codex 2 회차 P2-2): 설정의 `applies_to` 와 다른 기록 머리 → 진단 전용 유지·`replay_no_operating_depth`, `system_time` 프레임 → 진단 전용.
- **구간 자세**(Codex 2 회차 P1-2, 3 회차 P2-1):
  - STATE 가 50 ms 전에 계측된 경우 불확도가 그 폭만큼 커짐;
  - 지연 상한 없는 STATE 만 덮는 깊이 구간 → 버림;
  - 깊이 `hi` 0.990 s, STATE 간격 20 ms·상한 50 ms → 1.000·1.020 s 틱은 보류, 1.040 s 에 반영;
  - 보류 중 신선도 만료 → 버림, 보류 중 세대·보정 변경 → 버림;
  - 연속 30 Hz 깊이 + STATE 20 ms·상한 50 ms → 준비된 프레임이 끊기지 않음(최신 확보 후보 선택, Codex 4 회차 P2-1).

  - EOF 가 깊이까지 기다림;
