### 1.2 v2 와 같게 두는 것

- 팔:
  - A = 라이브 현재 기본.
  - B = A + ④(`--return-start-backoff boxed`) + ⑤(`--near-end-stand on`).
  - ①·②·③·⑥ 은 두 팔 모두 끈다.
- 설정:
  - 따라잡기 6(`FORKLIFT_LIVE_CATCHUP_STEPS=6` 명시), 위상 unset, 배속 0.3.
  - `ENCODER_MODEL=team_spec_quantized`, `D7_HOLD=on`, `MAX_EPOCHS=1`, `--max-sim-seconds 1200`, `FORKLIFT_LIVE_TICK_TRACE=1`.
  - CT 인식 설정은 래퍼가 넣는 그대로다.
- 자원: 모든 묶음 `--gres=shard:4 --cpus-per-task=8 --mem=19G --nodelist=ws1`, 자동 재시도 0, 시차 60 s.
- **기준선은 다시 재지 않는다.**
  - 따라잡기 6 과 동시 수(통합 A/B 슬롯 2, 나머지 슬롯 3)는 v2 기준선 결과의 총괄 결정값을 그대로 고정한다.
  - 이 배치의 페이스 판정은 **이 고정 조건에서의 새 코드 A/B 상대 회귀 확인**이다(v2 3.3 의 지표·예산). 기준선의 유지 판정(F ≥ 0.97 × F₁, R ≤ R₁ + 0.03)이나 최적 동시 수가 새 코드에서도 맞다고 주장하지 않는다.
  - 유효성 가드: 통합 A/B 의 어느 세션이든 **짝 공통 구간**의 창 배율 F < 0.27(v2 기준선의 중단선)이면 페이스를 판정하지 않고 총괄에 올린다. F 를 계산하지 못한 세션은 v2 3.3 의 결측 규칙(그 짝을 뺌, 빠진 짝 2 개 초과면 판정 불가)을 따른다. 이 가드는 R 의 절대 악화를 막지 않는다. R 은 A/B 예산으로만 본다.

## 2. 판정 (결과 전 고정)

- **페이스·안전·기능·생명주기 1–3**:
  - v2 3.3 을 그대로 적용한다. 지표, 예산, 짝 적격, 결측, 2 짝 규칙, C2 2.0 s 상한, 안전 원천, ④⑤ 최소 유효 발화, 생명주기 1–3 연쇄가 모두 같다.
  - 1.2 의 유효성 가드가 페이스 판정보다 앞선다.
- **생명주기 4**:
  - 확인 등록 §4 를 그대로 적용한다(§6.3 의 판독 규칙과 같다).
  - **판정 팔은 B 다.** B seed 0·1 두 세션이 모두 다음을 채워야 한다.
    - 연쇄 1–11.
    - STOP 유효 조건.
    - 대상 대조.
    - 안전·기록 완결.
    - C2 상한.
  - 팔 A 의 두 세션은 대조군이다.
    - A 의 실패로 B 의 실패를 면제하지 않는다.
    - 기록으로 설명되지 않는 A 실패가 남으면 자동 승격하지 않고 총괄에 올린다.
  - 실제 정지 위반(`stop_hold`)도 총괄에 올린다.
- **생명주기 기준**: 1·2·4 가 통과하고, 3 이 통과 또는 '기록대로 끝남'일 때 통과다.
- **실패의 처분(미해결 실패 없음)**:
  - 0 절의 예외로 받아들인 원인 미확정 실패는 **세 사건뿐**이다: 확인 실행 B seed 1·A seed 0 의 m2 운반 실패, 재현 배치 s25 H1 의 관측 `invalid_start`. 이 배치에서 같은 모양의 실패가 다시 나도 이 예외에 들어가지 않는다.
  - **예상된 끝(실패로 세지 않음, 결과 전 고정)**:
    - C2 `shadow` 의 회복 없는 종료: 그 임무에 실제 shadow 발화(`observe_end_stands` 의 `kind: near`·`shadow`)가 있고 종료 사유가 `Tracking timeout in observe` 인 경우만(v2 본배치와 같은 끝). 세션 이름만으로 면제하지 않는다.
    - 생명주기 2 의 운반 중 취소(`cancelled`·`operator`)와 재제출 두 번의 `cargo_held` 거부.
    - 생명주기 3 의 `reloc_needs_operator`(기록대로 끝남).
    - 생명주기 4 m1 의 STOP 뒤 취소(`cancelled`).
  - **그 밖의 모든 임무 실패·거부·미완료**를 27 세션 전체에서 목록으로 만든다(통합 A/B·나머지·생명주기 4). 각 항목은 셋 중 하나로 처분한다.
    - **B 쪽에만**(같은 장면·seed 의 A 짝이나 대조 세션에는 없음): 미해결 실패, 승격하지 않는다(v2 3.3 의 팔 B 만의 실패).
    - **A 쪽에만**: 자동 승격하지 않고 총괄에 올린다(확인 등록의 '설명 안 된 A 실패' 규칙을 배치 전체로 넓힘).
    - **양쪽 모두**(같은 장면·seed 의 A·B 가 모두 실패): 자동 승격하지 않고 총괄에 올린다. v2 3.3 의 페이스는 이런 짝을 빠진 짝으로만 세지만, 이 처분은 페이스와 별개다.
    - 짝이 없는 세션(나머지 묶음의 팔 B 단독 세션)의 실패는 B 쪽에만으로 본다.
  - 집계 도구는 확인 판정의 `judged_pass` 만이 아니라 `to_lead`·`stop_hold` 위반도 그대로 결합 결과에 올린다.
- **승격 권고**: v2 3.3 의 승격 표를 그대로 쓴다.
  - ④·⑤ 의 기능 확인은 이 배치의 후진 표적·C2 on 에서 본다.
  - 공통 기준과 팔 B 만의 실패도 이 배치에서 본다.
  - ④⑤ 는 함께 권고한다. 하나만 떨어지면 총괄에 올린다.
  - ② 는 이 결과로 판정하지 않는다. ④⑤ 가 승격된 뒤 주입 배치에서 본다.
- **결과 처리**:
  - 통과하고 총괄에 올릴 항목이 없으면, ④⑤ 승격을 권고한다(0 절의 예외 포함). 결정은 총괄이 한다.
  - 그 밖에는 보류이고 원인 조사로 넘긴다. ② 도 보류다.
- **승격 PR 관문**:
  - PR 의 기준(그때의 main)과 고정 커밋 사이에서 운용 경로(`src/`·`sim/`·`deploy/`·`config/`, 런처·래퍼·탐침)가 바뀌지 않아야 한다.
  - PR 자체는 라이브 런처의 ④⑤ 기본값만 바꿔야 한다.
  - 그 사이에 운용 경로가 바뀌면 이 배치의 근거를 옮기지 않고 총괄에 올린다.

## 3. 도구와 순서

- 집계: `tools/riib_v2_verdict.py`.
  - 통합 A/B·나머지 묶음은 v2 본배치 판정 경로로 집계한다.
  - 생명주기 4 묶음은 `--confirm` 경로로 집계한다.
  - 두 결과를 생명주기 기준으로 합치는 기능(나머지 묶음에 생명주기 4 가 없을 때 확인 판정을 생명주기 4 로 쓰는 것)과 2 절의 실패 목록·처분은 집계 하위 명령으로 넣는다. 확인 판정의 `to_lead` 를 보존한다. 시험을 먼저 쓰고, 결과 전에 머지한다.
  - 이 변경이 v2·확인 실행 원자료의 기존 판정을 바꾸지 않는다는 회귀 시험을 둔다.
- 순서:
  1. 이 등록 → Codex 검토 수렴 → 총괄 보고 → 고정.
  2. 집계 하위 명령(시험 먼저) → 판정 PR → main 병합과 ws1 전체 pytest → 머지.
  3. 고정 커밋 → 스냅숏 `rv3_<hash>` → 래퍼 v3(허용 diff·해시) → 목록 생성과 `isaac_bundle.py check` → 동일성 관문(첫 고정 매니페스트) → 총괄에 이름·해시를 한 번 알린다.
  4. 총괄 신호에 따라 묶음군을 GPU 빈틈에 단독으로 낸다(배속 판정 실행이라 CPU 잡과도 겹치지 않는다). 묶음군마다 동일성 재대조를 한다. 생명주기 4 앞에는 CPU 계획 관문(1.4)을 낸다.
  5. 판정 → 결과 문서 → 보고. 결론 해석과 권고는 Codex 교차검증을 거친다.
- 시간(명목):
  - v2 본배치는 4 시간 24 분(통합 A/B 8 짝과 나머지 8 세션), 확인 실행은 25 분이었다.
  - 이 배치는 통합 A/B 약 3 시간 + 나머지 약 1 시간 + 생명주기 4 약 25 분이다.
