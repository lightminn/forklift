# 지게차 프로젝트 현황과 앞으로 할 일


> **이 문서는 현황·우선순위의 정본이다.** 단계별 완료 조건은 [개발 로드맵](2026-09-11-development-roadmap.md),
> 하드웨어는 [`docs/hardware.md`](../hardware.md), 엔진·삽입 결정은 [ADR 0004](../decisions/0004-simulation-engine-and-insertion-depth.md)가 정본이고
> 여기서는 요약과 링크만 둔다. [2026-09-17 인계문](../validation/2026-09-17-dual-pallet-isaac-review-handoff.md) §6 은
> **그 시점의 재개안**으로 남긴다.
작성일: 2026-09-17

**2026-09-19 갱신: 인식기 출력으로 Isaac 지게차를 움직이는 배선(3순위)을 마쳤고, seed 0–8 중 4개가 픽업 목표를 카메라 추정치로 설정해 접근·삽입·운반·하역까지 완료했다**(로봇 자세·충돌 지도·런타임 검사·목적지는 여전히 정답). 나머지 5개는 검출 단계에서 멈춘다. seed 0에 대해서는 원시 depth로 실패 지점을 확정했고(하부 데크 증거 14점 대 기준 15점), 나머지는 같은 오류 문자열이거나 다른 항목(상부 증거 0)이며 내부 원인까지 개별 확인하지는 않았다. 현재 후보 목록·순서와 순차 재관측으로는 해결되지 않았다. **다음 핵심 작업은 그 검출기 판정 재설계다.** 형상·삽입 규칙·계획 여유를 공통 계약으로 묶는 일(2순위)은 2026-09-18 에 닫았다. 인식 연결 실험도 로봇 위치·장애물 지도는 여전히 시뮬레이터 정답을 쓰므로, 센서 인식부터 하역까지 연결된 자율주행 시스템의 완성 단계는 아니다.

이 문서는 현재 저장소와 검증 기록을 정리한 작업 목록이다. 체크된 항목은 아래에 명시한 범위에서 구현·확인됐다는 뜻이며 실물 검증 완료를 뜻하지 않는다. 대규모 작업의 실시간 상태나 최종 성공률은 이 문서에서 새로 확인하지 않았다.

### 확인된 주요 결과

- [x] Gazebo EPAL 6 렌더 데이터에서 가림 없는 양성 60개 장면의 포켓 검출을 확인했다. 해당 카메라 배치·팔레트·거리 조건의 결과이며, 독립적인 미관측 평가 세트나 실물 D435i 성능 결과는 아니다.
- [x] Isaac에서 팔레트를 물리 접촉으로 들어 올리고 운반·하역·포크 이탈까지 완료한 사례를 확인했다. 팔레트를 지게차에 고정하거나 주행 중 위치를 강제로 옮기는 방식은 사용하지 않았다.
- [x] 동일 seed 0에서 접근/운반 속도를 0.14/0.12 m/s에서 **0.35/0.30 m/s**로 올렸다. 전체 작업 시간은 **103.758초 → 62.475초**, 목적지 중심 오차는 **5.229mm → 1.784mm**였다. 삽입은 **0.055m/s**를 유지했다.
- [x] 기어 전환 후 NumPy 정수 때문에 로그 저장이 중단되던 버그를 재현·수정했다.
- [x] 조향 바퀴 외곽과 실제 팔레트 위치를 충돌 검사에 반영했다. 삽입·낮춘 포크 이탈 중에는 실제 자세와 승강 위치로 포크/팔레트 박스 사이의 3차원 기하 검사를 수행한다.
- [x] 최종 로컬 시험 기록은 **778개 통과, 4개 건너뜀**이다. 변경 범위의 Ruff 검사는 통과했으며 저장소 전체의 기존 lint 문제는 별도로 남아 있다.
- [x] **물리 100개 seed·경로 계획 1,000개 seed** 대규모 검증을 제출하고 실행 시작을 확인했다는 기록이 있다.
- [ ] 대규모 검증의 최종 완료 여부·전체 성공률·실패 원인 집계를 확인하고 반영한다.
- [x] **카메라 추정 위치를 계획 목표로 써서** 집기·운반·하역을 완료한 사례를 개발 seed 0–8 중 4개에서 확인했다(2026-09-19). 직전 버전 실행의 성공 3건에서 읽은 인식 위치 오차는 0.78–3.53 mm이고, 4건 모두 삽입·이탈 중 포크/팔레트 상자 중첩 검사(검사 시점마다 2 mm 여유)와 최종 배달 검사(목적지 80 mm·높이 8 mm)를 통과했다 — 접촉력 측정이나 검사 시점 사이의 연속 무접촉 증명은 아니다. 로봇 위치·장애물 지도·목적지·런타임 중단 조건은 여전히 정답을 쓰며, 나머지 5개 seed는 검출 단계에서 멈춘다. 근거: [실측 기록](../validation/2026-09-19-perception-isaac-hookup.md).

근거: [EPAL 6 인식 평가](../validation/2026-09-14-epal6-capture-and-evaluation.md), [Isaac 수정·시험·대규모 제출 기록](../validation/2026-09-17-isaac-hybrid-astar-bench.md).

| 팔레트 위치·방향 | 기본 실행은 시뮬레이터 정답 좌표. **`--use-perception`에서는 계획 목표만 깊이 인식기 추정치**(2026-09-19, 개발 seed 4/9 성공). 충돌 지도·런타임 검사는 여전히 정답 | 검출 강건성 확보 후 전 seed로 확대 |
| 지게차 위치·방향 | 시뮬레이터 정답 좌표 | 바퀴·조향 피드백 기반 오도메트리 + LiDAR 위치 추정 |

## 3. 앞으로 할 일 — 권장 순서

### 1순위: 현재 계획·운반 검증 결과 정리

- [ ] 물리 100개와 계획 1,000개에서 요청한 seed가 빠짐없이 처리됐는지 확인한다.
- [ ] 계획 실패, 추종 실패, 삽입 간격 부족, 적재물 이탈, 하역 오차, 기록·실행 오류를 구분한다.
- [ ] 실패 배치를 재현하고 원인별로 수정한다. 성공한 seed만 남기거나 검색 실패를 곧바로 물리적 불가능으로 판정하지 않는다.
- [ ] 성공률과 함께 작업 시간·위치 오차·정지 및 기어 전환·하중 안정성을 비교한다.

완료 기준: 원본 결과와 연결된 전체 집계, 대표 성공·실패 사례, 다음 수정 목록이 남아 있다.

### 2순위: 팔레트 형상·삽입 규칙·계획 여유를 공통 계약으로 묶기 — **완료 (2026-09-18)**

- [x] `SyntheticMissionGeometry` 의 오프셋·적재 외곽을 팔레트 깊이·폭·축-포크끝 거리에서 유도한다(`init=False` 파생 필드, `627850c`). T11 ×0.6 은 이제 규칙대로 **삽입 깊이 360 mm** 를 낸다.
- [x] 실행기·대규모 검증기가 `--pallet-geometry` 를 필수로 받고, 입력 URDF 의 외곽(`1bc8b03`)과 22박스 이름별 배치(정사각 T11 90°/180° 오정렬까지, `7f43037`)를 1 mm 로 대조해 어긋나면 spawn 전에 거부한다.
- [x] 삽입 규칙 상수(0.6 / 0.406 / 0.046)를 `pallet_geometry.py` 의 `target_insertion_depth_m()` 하나로 모았다. `build_t11_drawing.py` 는 그 함수를 쓰고, `preview_docking.py`·`summarise_sweep.py`·`docking_clip.py` 세 곳은 EPAL 전용으로 명시적으로 동결한 채 같은 함수에서 값을 뽑는다(`627850c`).
- [x] 계획 여유 `0.10` 의 정본을 `DEFAULT_TRANSPORT_CLEARANCE_M`(`pallet_mission.py`) 하나로 정하고, 근접-여유 변이 회귀 시험으로 고정했다 — 이 값을 `0.00` 으로 바꾸면 새 시험이 실패함을 직접 확인 후 원복했다(`18649a8`).

사양·근거·먼저 쓴 시험·3라운드 교차검증 기록은 [운반 계획의 「형상 일반화」 절](2026-09-17-hybrid-astar-transport.md)에 있다. 구현은 `627850c`(핵심 형상·규칙 함수) → `1bc8b03`(실행기·검증기 배선) → `7f43037`(정사각 T11 이름별 대조) → `18649a8`(여유 계약·해시·22박스 assertion 일반화) 네 커밋으로 나눠 각 단계 Codex 적대적 검토와 전체 회귀(933 passed, 1 skipped)를 거쳤다. ⚠️ **T11 실행은 이 작업으로 풀리지 않는다** — 팔레트 모델이 없고 삽입구 235/350 해석이 미확정이다. 코드는 합성 깊이로 이미 독립 검증됐다.

완료 기준(달성): 두 형상의 유도값이 시험으로 고정되고, 형상 불일치·비중심 URDF·정사각 T11 90° 오정렬·계획 여유 축소가 각각 시험에서 잡힌다.

### 3순위: 기존 팔레트 인식기를 Isaac 운반에 연결 — **배선 완료, 검출기 강건성 미해결 (2026-09-19)**

- [ ] 로봇 인식용 RGB-D 카메라의 장착 위치·방향을 정하고 영상·깊이·내부 파라미터·시각·TF를 출력한다. 장착(`baseline_0p50` 0.75, 0, 0.50 m를 `/World/Forklift/base_link` 자식 prim으로)과 광학축 규약(`camera_axes="ros"`, 축 방향 smoke check 통과)까지는 됐다(`f8b29bd`, `cff9dbf`). **미완료: ① 실제 K를 읽어 명목값(`fx=fy=465.741156`)과 대조하는 자체 점검 ② 영상 프레임 ID/시각과 동기화된 TF 기록** — 지금 신선도 판정은 영상 프레임 식별자가 아니라 `world.current_time`(물리 시각)이다. 설계문서가 둘 다 요구한다.
- [x] 해당 입력을 기존 `detect_pockets()` 입력 계약에 맞추는 어댑터를 만든다. `sim/isaac/perception_adapter.py`(`ce3bc72`) — isaacsim을 import하지 않아 로컬 pytest로 시험된다. depth는 캐시가 아니라 annotator에서 직접 읽는다(`3098013`).
- [x] 인식기의 팔레트 형상 정보(prior)를 실제 시험 팔레트와 맞춘다. `--pallet-prior config/pallet_prior_epal6.yaml` 필수 인자로 받고 `DetectorParams.derived_for(prior)`를 쓴다.
- [x] 로봇 기준 포켓 관측을 관측 시점의 로봇 자세로 계획 좌표계에 변환하고 Hybrid A* 접근 목표로 사용한다. 포켓 전면 중점 → 팔레트 중심 변환(깊이/2 만큼 안쪽)까지 포함(`ce3bc72`), `plan_transport(target_pickup=…, start_rear=…)`로 목표만 추정치로 바꾼다(`07014d9`). 단 변환에 쓰는 자세는 **캡처 함수가 반환한 직후 읽은 시뮬레이터 자세**이고, 그것이 실제 영상 프레임의 시각과 일치하는지는 ①과 함께 미검증이다.
- [x] 이 단계에서는 로봇 위치·장애물 지도는 정답으로 유지해 인식 연결의 영향을 분리한다. ~~팔레트 정답은 오차 평가에만 사용한다.~~ 정확히는 **정답을 계획 목표로 쓰지 않는다**. 팔레트 정답 자세는 충돌 지도·삽입 중 3차원 기하 검사·런타임 중단 조건·사후 오차 평가에 계속 쓰이고 목적지도 정답이다. 검출 실패 시 정답 목표로 돌아가는 fallback은 없다.

완료 기준: 팔레트의 정답 위치를 목표 입력으로 쓰지 않고, 카메라로 추정한 위치·방향으로 정렬 지점까지 접근한다. 미검출·무효 관측은 기록하고 정지 또는 재관측으로 처리한다.

**달성 상태 — 부분 달성.** seed 0–8(후보·순서·`primitive_length_m`을 맞춰본 **개발 집합**) 중 **4개(2, 3, 5, 6)** 가 픽업 목표를 카메라 추정치로 설정해 접근·삽입·운반·하역까지 완료했다(계획의 충돌 지도는 여전히 정답). 직전 버전 실행의 성공 3건(seed 2·5·6)에서 읽은 인식 위치 오차는 0.78–3.53 mm다 — **최종 버전 4건의 인식 오차는 따로 읽지 않았고 seed 3은 어느 버전에서도 읽지 않았다.** 삽입 단계의 종점 추종 오차는 7.64–7.73 mm로 정답 경로(seed 0, 7.72 mm)와 비슷하다 — **다만 이 값은 계획 종점 대비 추종 오차이지 실제 포켓 기준 정밀도가 아니다.** 실제 팔레트 기준 근거는 삽입·이탈 중 검사 시점마다 도는 포크/팔레트 상자 중첩 검사(2 mm 여유, 위반 시 즉시 중단)와 하역·최종 배달 검사를 4건 모두 통과했다는 것이다. 이 검사는 접촉력 측정도, 검사 시점 사이의 연속 무접촉 증명도 아니다. 미검출은 전부 사유와 함께 기록하고 정지하며, 후보 목록을 순서대로 재관측하는 처리까지 구현했다(`1b71d1b`). **나머지 5개(0, 1, 4, 7, 8)는 검출 단계에서 멈춘다.**

**남은 블로커 — 검출기의 하부 데크 증거 채점.** seed 0의 실제 캡처를 오프라인 재현해 보면 개구부 2개(220/220 mm)·중앙 간격(150 mm)·좌중우 지지대(464/597/372)·상부(1,482)를 모두 찾고 **하부 증거만 14점으로 기준 15점에 한 점 모자라** 패턴 전체가 탈락한다. seed 4·7·8은 같은 오류 문자열이지만 내부 원인까지 같은지는 확인하지 않았고, seed 1은 다른 항목(상부 증거 0)에서 걸렸다. 같은 관측 후보라도 도착 경로가 다르면 성패가 뒤집힐 만큼 재현성이 약한 것까지 확인했으므로 **현재 후보 목록·순서로는 해결되지 않는다**(seed 3은 후보를 바꿔 실제로 해결됐으므로 "관측 지점으로는 절대 해결 불가"는 아니다). 앞쪽 여유값(`depth >= -ε`)을 주는 안은 `grounded` 음성 장면도 함께 통과시켜 기각했고, 문턱 완화(15→14)는 원인 해결이 아니라서 채택하지 않았다(음성 영향은 미시험). 유망한 방향은 **블록 행 사이 구간에서만 하부 증거를 세는 것**이며 `PalletPrior` 계약 확장이 필요하다 — 다음 작업이다.

근거: [실측 기록](../validation/2026-09-19-perception-isaac-hookup.md), 설계 [2026-09-18 문서](2026-09-18-perception-isaac-hookup.md) v1–v6. 구현은 `07014d9` … `1b71d1b` 12개 커밋이며 각 단계마다 Codex 교차검증을 거쳤고, 기록된 4회 실행에서 `--use-perception` 없는 경로의 회귀 무변경(seed 0 삽입 오차가 소수점까지 동일)을 확인했다.

### 4순위: 근접 포켓 추적과 삽입 제어

- [ ] 접근 중 연속 프레임에서 좌우 포켓 대응과 상대 위치·방향을 갱신한다.
- [ ] 가까워질 때 포켓이 화각 밖으로 나가거나 포크·마스트에 가려지는 문제를 확인한다. 기존 평가의 원거리 인식 성공을 근접 삽입 성공으로 간주하지 않는다.
- [ ] 필요하면 카메라 높이·기울기·장착 위치를 조정하고 데이터를 다시 캡처한다. 승강부 장착이면 승강 위치에 따라 TF를 갱신한다.
- [ ] 관측 누락·지연·오검출 때 삽입을 중단하고, 재획득 조건을 정한다. 마지막 정답이나 추정값을 무기한 유지해 삽입하지 않는다.
- [ ] 측정한 인식 오차·제어 오차·정지 거리를 포켓과 포크의 실제 여유에 대조한다.

완료 기준: 마지막 접근부터 삽입 완료까지 유효한 포켓 관측을 사용하고, 관측을 잃었을 때 의도한 정지 동작을 확인한다. 현재의 정답 자세 기반 기하 검사는 이 기능의 대체물이 아니다.

### 5순위: LiDAR 장애물 지도와 위치 추정 연결

- [ ] Isaac LiDAR와 ROS 2 스캔·시각·좌표계를 연결하고 관측 범위를 확인한다.
- [ ] LiDAR로 생성·갱신한 장애물 지도를 Hybrid A* 충돌 검사에 연결한다.
- [ ] 일반 주행 중 새 장애물이 나타나는 경우 정지·재계획·재개를 시험한다.
- [ ] 바퀴·조향 피드백과 시간 정보를 사용해 오도메트리를 만들고 LiDAR 위치 추정과 연결한다.
- [ ] 로봇 위치의 정답 입력을 위치 추정 결과로 대체하고 위치 오류가 경로 추종·삽입에 미치는 영향을 평가한다.

완료 기준: 관측 기반 로봇 위치와 장애물 지도로 주행한다. 팔레트 인식과 지도 기반 위치 추정의 좌표·시각이 맞고, 오래된 정보로 계속 주행하지 않는다.

### 6순위: SLAM이 필요한 운용 조건 검증

- [ ] 지도 없는 창고에서 사용할 경우 LiDAR SLAM으로 지도 작성과 위치 추정을 연결한다.
- [ ] 지도를 미리 만들 수 있는 시험장에서는 기존 지도 기반 위치 추정을 먼저 검증한다.
- [ ] 재기동, 후진·회전, 위치 소실, 지도 변경 조건을 시험한다.

완료 기준: 선택한 운용 방식에서 위치 오차·재위치 추정·지도 유지가 검증된다. **SLAM은 로봇 위치와 지도를 담당하며, 팔레트 포켓 인식·근접 추적을 대신하지 않는다.**

### 병행 작업: 실물 장비 확인과 전환

- [ ] 차체 입고 후 구동·조향·승강 구조, 치수, 회전 반경, 포크·팔레트 규격을 측정한다.
- [ ] D435i 장착·보정과 RPLIDAR 세부형·설정을 확정하고 실제 데이터를 기록한다.
- [ ] Jetson에서 센서 동시 동작·처리 지연·발열·저장·재부팅 후 재현을 확인한다.
- [ ] 기존 제어기 활용 여부와 MCU 필요성을 결정하고, 확인된 인터페이스에 맞춰 하위 제어를 구현한다.
- [ ] 속도·조향·승강 피드백, 통신 단절·명령 만료 시 정지, 물리 비상정지를 검증한다.
- [ ] 실측 구동 한계·지연·제동 거리로 모델과 설정을 갱신한다. 시뮬레이션의 합성 토크·마찰·조향값을 실물 사양으로 복사하지 않는다.
- [ ] 실물 팔레트·센서 데이터로 인식 평가 후 저속·무부하부터 적재 운반까지 단계적으로 검증한다.

## 4. 통합 완료 조건

최종 연결 순서는 **팔레트 검출 → 로봇 기준 포켓 자세 → 장애물 회피 경로 → 추종·포켓 추적·삽입·적재 → 목적지 이동·하역**이다.

아래 네 조건을 인식·계획·제어가 연결된 상태에서 확인한다. 현재 A–D 계획 단위시험 통과가 센서 기반 전체 작업이나 실물 A–D 검증을 뜻하지는 않는다.

⚠️ **EPAL 6 과 T11 ×0.6 각각에 대해 아래 A–D 와 전체 임무를 검증한다. 한 형상의 성공이 다른 형상의 완료를 대신하지 않는다**([ADR 0002](../decisions/0002-test-pallet-and-geometry-generality.md), 사용자 2026-09-17). ⚠️ **T11 은 지금 막혀 있다** — 팔레트 모델이 없고([운반 계획의 「형상 일반화」 절](2026-09-17-hybrid-astar-transport.md)) 삽입구 235/350 해석이 미확정이다.

⚠️ **이 표는 [개발 로드맵](2026-09-11-development-roadmap.md) 완료 조건의 요약이다.** 로드맵의 B 연속 진입·무경로 처리·전체 작업 조건을 대체하지 않는다.

| 사례 | 조건 | 확인할 행동 |
|---|---|---|
| A | 정면·정렬된 팔레트 | 직진 접근과 삽입 |
| B | 옆으로 어긋나 있고 접근 공간이 충분함 | 가능한 조건에서 멈추지 않는 곡선 접근과 삽입 |
| C | 너무 가까워 바로 삽입하기 어려움 | 먼저 후진해 공간을 만들고 정렬·접근 |
| D | 너무 가깝고 뒤에도 장애물이 있음 | 후방 장애물을 피하며 이동해 접근 공간 확보 |

- [ ] 각 사례에서 접촉·충돌, 팔레트 이탈, 위치·방향 오차, 관측 소실, 작업 시간과 실패 원인을 기록한다.
- [ ] 성공률과 비접촉 조건을 확보한 뒤 같은 조건에서 작업 시간을 줄인다.
- [ ] 시뮬레이터 정답 기반 시험, 센서 기반 시뮬레이션, 실물 시험을 구분해 보고한다.
