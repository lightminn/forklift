# SLAM 그래프 크기 묶기 — keyframe 비용을 운용 시간에서 떼어 내기 (계획 v3, 2026-10-26)

상위: [slam_link_failed](2026-10-25-slam-link-failed.md) 6.3·6.4(임시 완화와 그 수명) · [상시 운용 세션의 SLAM](2026-10-20-slam-localization-session.md)(PR #62, 위치 추정 모드의 설계와 S1–S5 기록)

## 1. 문제와 목표

- 같은 길을 되풀이하는 운용에서 slam_toolbox(mapping 모드)의 keyframe 처리 시간이 통과 횟수에 따라 커진다. 원인은 루프 닫기 후보 정합이다(상위 계획 2.2–2.3, 6.1).
- 지금 기본값인 임시 완화(R4 + R5 + R7)는 증가율을 약 1/8 로 줄였을 뿐이다. 이어 붙인 재생에서 keyframe 하나가 1 s 를 처음 넘은 것은 sim 약 3,425 s 다(6.4). 증가는 포화하지 않는다.
- **목표(총괄 결정): sim 1 h 연속 운용에서 keyframe 처리 시간이 모두 1 s 미만.** 지도와 위치의 정확도는 지금 기본값보다 나빠지지 않아야 한다. 이 계획의 판정은 그보다 강하게, 재생 전체(sim 5,000 s)에서 비용이 시간에 묶여 있는지를 본다(4 장).

## 2. 운용 전제

- **P1** 작업(미션) 하나는 1 h 를 넘지 않는다(총괄 전달, 사용자 확인). 상시 운용 세션은 미션을 여러 개 이어서 몇 시간씩 띄운다.
- **P2** 세션은 에폭으로 나뉘고, 에폭이 바뀌면 브리지와 slam_toolbox 가 새로 뜬다(PR #62 2.4). **지금 코드에는 에폭 안에서 SLAM 을 다시 시작하는 경로가 없다.** 그래서 P1 만으로는 그래프 크기가 묶이지 않는다. 미션 사이 리셋·저장 지도 재적재가 가능한지는 S0 에서 확인한다.
- **P3** 계획기는 SLAM 지도를 정적 층으로 쓰고(`latest_map.npz`, 위치 추정에서는 조사 격자), 주행 허가는 SLAM 지도를 보지 않는다(PR #62 2.4). 지도를 버리거나 바꾸는 후보는 계획이 쓰는 격자의 품질을 함께 잰다.
- **P4** 시뮬의 LiDAR 는 수평 2D ray-cast 이고 장면의 정적 물체가 운용 중 거의 바뀌지 않는다. 실차 창고의 바뀌는 배치(lifelong 모드가 노리는 상황)는 이 시험이 대표하지 못한다.
- **P5** 운영 런처의 SLAM 오도메트리 기본은 PR #137 부터 관절각 모델 `team_spec_quantized` 다. 재생은 기록된 실행의 오도메트리(`reported`)를 쓰므로 후보 사이 비교에는 영향이 없다. 새로 만드는 조사 지도와 Isaac 확인은 team-spec 으로 한다.

## 3. 후보

### 공통 함정 — 노드를 지우면 최근 scan 이 루프 후보에서 빠질 수 있다 (Codex, 소스 확인)

karto 의 scan 저장소는 상태 ID 를 키로 하는 `std::map` 이고(`Mapper.cpp` 281–290 `GetScan`), `FindPossibleLoopClosure` 는 `GetScans().size()` 를 ID 상한으로 0 부터 훑는다(1960–2009). 노드를 지우면 살아 있는 개수가 ID 최댓값보다 작아져 **상한보다 큰 ID(최근 scan)는 루프 후보로 방문되지 않는다.** B(lifelong)와 A(위치 추정의 버퍼 삭제) 모두 해당한다. 비용이 줄어도 그것이 정상적인 후보 정리인지, 최근 후보를 빠뜨린 결과인지 구분해야 한다. 어떤 ID 를 실제로 검사했는지는 slam_toolbox 를 고쳐 빌드하지 않고는 잴 수 없으므로, 그 대신 정확도의 시간 추이와 그래프 연결성(4 장)으로 본다.

### A. 미리 만든 지도에서 위치 추정 (PR #62 L1·L3)

- 조사 지도(묶음)를 읽고 `localization_slam_toolbox_node` 로 돈다. 새 노드는 `scan_buffer_size` 를 넘으면 오래된 것부터 그래프에서 지워진다(PR #62 2.2). **저장 노드의 수는 유지되지만 기하는 고정이 아니다.** Ceres 는 첫 노드만 고정하므로 루프 닫기가 저장 노드도 움직일 수 있다. 계획기는 고정된 조사 격자를 쓴다(`run_transport.py` 4453–4456) — 둘이 어긋날 수 있다.
- A 는 사용자의 제안("오래된 위치 기록을 지우게")과 같지 않고, **미리 만든 지도에 기대는 다른 운용 방식**이다. 지도에 없는 길로 가면 붙지 못할 위험이 있다(조사 덮개, PR #62 L2).
- 이미 있는 것: 조사 에폭·묶음 작성기(`tools/slam_survey_bundle.py`), 브리지의 `localization_bundle`·`expected_map_id`·`map_start_pose`, 런처의 `MAP_BUNDLE`, 설정 변형 J(`tools/slam_localization_params.py`).
- 남은 위험: PR #62 의 조사 지도는 world 정확도 V2′ 0.10 m 를 넘지 못했다(0.152 m). 배포 묶음에는 V2′ 0.10 m 조건이 그대로 남는다(이 계획의 0.20 m 상한이 그것을 면제하지 않는다). 위치 추정 모드는 `serialize_map` 을 거절하므로 최종 그래프 dump 로 저장 노드 이동을 잴 수 없다 — 대신 브리지의 `/map` 과 계획 격자로 잰다.

### B. lifelong 모드 (`lifelong_slam_toolbox_node`, slam_toolbox 2.8.5 실험 기능)

- 새 scan 마다 그 경계 원 안의 이어진 노드(또는 kd-tree 이웃)를 겹침 점수로 매겨 `lifelong_node_removal_score` 아래인 노드를 지운다(`src/experimental/slam_toolbox_lifelong.cpp` 149–178, 332–345). 시간이 아니라 **겹침** 기준이다.
- 지울 때 인접 edge 와 최적화기 제약도 지우고, 이웃끼리 새 제약을 만들지 않는다. 차수 2 노드도 지워지므로 `u—v—w` 에서 v 를 지우면 연결이 끊길 수 있다. 소스는 실험 기능이라 경고하고 지운 노드의 제약 처리를 미해결로 남긴다(343 행).
- sync 노드와 처리 순서가 다르다: `shouldProcessScan()` 을 거치지 않아 시작 2–4 번 scan 도 처리하고, `/pose` 는 노드 삭제 전에 나간다. 그래서 응답 지연(`wall_s`)은 삭제 작업을 포함하지 않는다 — 삭제가 밀리면 다음 keyframe 의 지연으로 나타난다.
- **설정:** 우리 online 설정에 배포 YAML(`mapper_params_lifelong.yaml` 22–29 행)의 lifelong 값을 명시해 넣는다(C++ 미지정 기본값과 다르다: 예 overlap scale YAML 0.06, C++ 0.5). 실행마다 유효 설정 전체를 저장한다.

### C. 시간 기준 오래된 노드 삭제 (mapping 모드, 사용자 제안 그대로)

- slam_toolbox 에 이 기능이 없다. 구현하려면 소스에서 빌드한 이미지에 "sim T 초보다 오래된 노드를 지운다" 를 넣어야 한다. 삭제 함수는 lifelong 이 쓰는 것을 그대로 쓸 수 있지만, 위의 공통 함정과 연결 끊김이 그대로 따라온다.
- 총괄의 잠정 의견과 Codex 의 판단: mapping 의 `scan_buffer_size` 는 순차 정합 버퍼만 제한하고 그래프를 지우지 않으며, 위치 추정의 버퍼 삭제·직렬화 재적재도 mapping 의 시간별 선택 삭제를 대신하지 못한다. 지운 scan 만 관측했던 지도 정보와 그 제약은 사라진다(다른 scan 이 덮은 곳은 남는다). **조건부로 동의한다:** C 는 C++ 수정이 필요하고, A 는 지도를 잃지 않지만 사전 지도에 기대는 다른 방식이다.
- 이 계획의 처리: C 는 먼저 C′ 로 근사한다. C 의 C++ 구현은 A·B·C′ 가 모두 떨어질 때 따로 판단한다.

### C′. 미션 경계에서 SLAM 새로 시작 (지도 버림)

- 미션이 끝나 차가 서 있을 때 slam_toolbox 를 새 mapping 세션으로 시작한다. 그래프는 미션 하나로 묶인다. 컨테이너를 다시 띄우는 대신 이미 있는 `/slam_toolbox/reset` 서비스를 쓸 수 있다(`slam_toolbox_common.cpp` resetCallback).
- **한계: 미션 하나가 1 h 까지 가면 C′ 는 그 안의 증가를 막지 못한다.** 미션 안에서는 지금 기본값과 같고, 그 기본값은 sim 3,425 s 에서 1 s 를 넘었다. 그래서 C′ 는 "미션 길이 상한 × 기본값의 수명"으로만 판정한다(4 장).
- **인계 계약(Codex):** 새 세션은 보정을 항등으로 시작하므로 새 map 좌표를 이전 map 으로 옮기는 고정 변환을 자세와 격자 원점 모두에 적용해야 한다. `MapStore` 판본이 0 으로 돌아가면 계획기가 새 지도를 `older_than_loaded` 로 거절한다. tracker 의 시작 규칙(`scan_id ≥ 4`)은 전역 scan ID 를 쓰면 첫 응답에서 tracking 이 된다. 진행 중 요청 회수·새 연결·재시작별 시작 번호·지도 판본·정적 층과 계획 캐시의 인계가 모두 필요하다. **재생에서는 비용 진단으로만 잰다.**

## 4. 비교 실험

### 4.1 입력 — 같은 궤적의 복제를 피한다 (agy)

- 같은 실행을 14 번 복제하면 잡음·궤적이 단위마다 똑같아 겹침 점수(B)와 위치 추정(A)이 과대평가될 수 있다. 그래서 **같은 장면의 서로 다른 실행을 이어 붙인다:** line_m 의 CT-2 실행(`ct2_624d0616_auto_line_m_s1`·`_fixed_line_m_s3`·`_auto_line_m_s4`, `ct2_41a2a7e8_fixed_line_m_s2`, `lf_67694d16_main_line_m_s0`)에서 각 실행의 출발 자세로 돌아온 구간을 단위로 잘라 번갈아 잇는다. seed·경로·잡음 시드가 단위마다 다르다. 출발 자세가 같은 장면이므로 이음 조건(0.10 m·0.05 rad)은 같은 방식으로 검사한다. 이어 붙여 sim 5,000 s.
- 같은 실행 복제 입력(상위 계획 E1·6.4)도 기준선 비교용으로 함께 돌린다.
- 재생 기록의 각 줄은 **원본 실행 ID 와 원본 scan ID** 를 남긴다(지금의 `src` 는 원본 scan 번호뿐이라 서로 다른 실행의 같은 번호를 구분하지 못한다).
- **비용 실행과 지도 계측 실행을 나눈다(Codex).** 비용은 배포 설정 그대로 잰다. 위치 추정에서 브리지는 첫 지도 뒤 `/map` 구독을 끊으므로(`isaac_slam_bridge.py` 363–380·518–528), 운용 중 지도 변형을 보려면 구독을 유지하는 계측 전용 실행이 따로 필요하다. 구독을 유지하면 slam_toolbox 가 지도를 다시 만들어 비용이 달라지므로, 그 실행의 비용은 판정에 쓰지 않는다. 계측 실행은 단위 시작마다 새 그래프를 반영한 지도를 받아 둔다.
- **기준선:** 지금 기본값(R4 + R5 + R7)의 같은 입력 재생.
- 재생은 오픈 루프다(SLAM 지연·점프가 차를 움직이지 않는다). Isaac 과 함께 도는 CPU 경합도 없다. 이 둘은 S4 의 Isaac 확인이 본다.

### 4.2 후보별 실행

- **A:** 지도는 **확인용과 다른 실행**으로 만든다. `lf_67694d16_main_line_m_s0` 의 단위 0 을 mapping 으로 재생해 직렬화한 묶음 위에서, 4.1 의 섞인 입력(그 실행 제외)을 위치 추정으로 재생한다. 변형은 PR #62 의 {버퍼·chain 10/10, 3/3} × {루프 켬, 끔} 과 J. 묶음의 노드 world 오차(V2′ 와 같은 계산)를 함께 적는다.
- **B:** `lifelong_slam_toolbox_node`, 우리 online 설정 + 배포 YAML 의 lifelong 값. 변형: `lifelong_search_use_tree` {false, true}, `lifelong_node_removal_score` {0.04, 0.1}. 끝에서 그래프를 직렬화·dump 해 노드·edge 수와 연결 성분을 센다.
- **C′:** 단위 경계마다 리셋(지도 버림)한 비용 진단. 판정은 아래 3 의 방식.

### 4.3 판정 (결과 전에 고정)

같은 입력의 기준선 대비:

1. **비용(A·B):** 재생 전체(sim 5,000 s)의 keyframe 최대 ≤ 0.5 s(기한 1 s 에 두 배 여유), 그리고 끝까지 돈 단위별 최대에 맞춘 직선의 기울기 ≤ 0.005 s/단위. 첫 1 h 만 보는 기준은 단위별 최대가 0.95 + 0.004 × 단위처럼 1 s 바로 아래에서 천천히 커지는 경우를 통과시키므로(Codex 반례) 쓰지 않는다.
2. **비용(C′):** 미션 하나 안의 증가는 기준선과 같으므로, 기준선 재생에서 keyframe 최대가 0.5 s 를 처음 넘는 sim 시각 T₀.₅ 를 구한다. C′ 는 "미션 길이 상한 < T₀.₅" 일 때만 합격 후보다. P1(1 h)과 비교해 그 상한을 적는다. 기준선의 T₀.₅ 가 1 h 보다 짧으면 C′ 단독으로는 P1 아래 목표를 채우지 못한다. 같은 실행 복제 입력의 기준선 T₀.₅ 는 이미 sim 1,709 s 다(상위 계획 6.4) — 섞인 입력에서도 비슷하면 C′ 는 미션 약 28 분 상한이 있어야 한다.
3. **위치 정확도:** 응답 자세 기준 위치 오차 중앙값 ≤ 기준선 + 1 cm, 최대 ≤ 기준선 + 5 cm, 방향 최대 ≤ 기준선 + 1.0°. 절대 상한 위치 0.20 m·방향 3°. **시간에 따른 악화는 같은 원본 구간의 반복끼리 비교한다**(섞인 입력에서 첫·마지막 단위를 비교하면 경로 난도 차이가 표류를 가린다 — Codex 반례): 원본 실행마다, 그 실행이 마지막으로 나온 단위와 처음 나온 단위의 위치 오차 중앙값 차이 ≤ 2 cm(원본 실행 가운데 최대). 함께, 단위마다 같은 원본 구간의 기준선 오차를 뺀 초과 오차의 중앙값이 커지지 않을 것(마지막 − 첫 ≤ 2 cm). 최근 scan 이 후보에서 빠져 보정이 멈추면 여기서 드러난다.
4. **지도(계획이 쓰는 격자):** 장면의 참값 물체(`scenario.json` 의 1.15 m 이상 물체)를 같은 격자로 래스터해, 고정 world 영역(장면 경계)에서 계획 격자의 점유 칸과 비교한다. 참값 경계 칸 가운데 계획 격자가 점유로 가진 비율(보존) ≥ 기준선 − 5 %p, 계획 격자의 점유 칸 가운데 참값 경계 0.10 m 안인 비율(정합) ≥ 기준선 − 5 %p. 단위 시작마다 잰다. 알려진 칸 비율만으로는 장애물이 FREE 로 바뀐 경우를 못 잡으므로 쓰지 않는다. A 는 계획 격자(조사 격자)와 위치 추정 중의 `/map` 을 둘 다 잰다.
5. **그래프(B):** 끝 그래프가 하나의 연결 성분이고, 첫 노드에서 모든 노드에 닿는다.
