## 1. 묻는 것: 팔레트가 왜 포크에 옆으로 치우쳐 실리는가

- 지금까지 본 사실은 셋이다(진단 결과 문서, 기록 확인 (3)).
  - 큰 하역 오차는 들어 올릴 때 이미 있던 횡 치우침에서 왔다. Ub3 random_1 s1 의 `slip_watch.baseline.seat` 횡값은 −52.7 mm, 같은 seed B0 는 −7.9 mm 다.
  - 삽입 중 팔레트는 움직이지 않았다. 표본 기록에서 insert 첫 표본과 lift 첫 표본의 팔레트 참 위치 차이가 0.0 mm 다(Ub3·B0 random_1 s1). 그래서 치우침은 포크가 처음부터 포켓 중심에서 비켜 들어간 결과다.
  - 같은 실행에서 삽입 끝의 SLAM yaw 오차(`slam_error_insert_end.yaw_rad`)는 Ub3 −0.0335 rad, B0 −0.0020 rad 다. 근접 캡처 오차(`near_capture.near_error`)는 Ub3 1.6 cm, B0 3.1 cm 다.
- 포크가 비켜 들어간 몫을 같은 시각(lift 전환)·같은 팔레트 원점 기준의 자세 변환으로 나눈다(Codex 검토 ② P1).
  - g(X) 는 "참 팔레트 원점을 자세 X 의 좌표로 본 횡좌표"다. A 는 참 후륜축 자세, E 는 추정 후륜축 자세, G 는 그 삽입의 활성 목표 자세(insert 경로의 끝점)다.
  - **T 목표 항** = g(G). 활성 목표가 참 팔레트에서 얼마나 비켜 있었나.
  - **F 추종 항** = g(E) − g(G). 차가 추정상 목표에 얼마나 못 미쳤나.
  - **L 위치 추정 항** = g(A) − g(E). 추정 자세와 참 자세의 차이가 팔레트 원점에서 만든 횡 차이. yaw 오차는 후륜축에서 팔레트 원점까지의 거리(약 1.27 m)만큼 커진다.
  - 정의상 S = g(A) = T + F + L 이다. 이 항등식이 성립하는 것은 인과의 증거가 아니라 회계다. S 가 `slip_watch.baseline.seat` 의 횡값과 맞는지로 계산을 검산한다.
- T 는 다시 세 항(D·C·P)으로 나눈다(Codex 검토 ② P2).
  - 계산은 하나로 고정한다(Codex 검토 ② 2회차 P2). 관측은 `base_link` 기준이고 `capture_control` 은 후륜축 자세라 rear→base 오프셋을 먼저 적용한다. 목표 추정은 팔레트 중심이고 G 는 후륜축 목표라(정상이어도 약 1.26 m 떨어져 있다) 단순 위치 차이를 쓰지 않는다.
    - 캡처에 쓴 관측은 `observation_attempts[near_capture.near_attempt − 1]` 이다(시도 번호는 1 부터).
    - q: 관측 포켓 중점에서 관측 방향으로 팔레트 깊이의 절반만큼 간 중심(`sim/isaac/perception_adapter.py` 의 기존 계산).
    - Qd, Qe: q 를 캡처 당시의 참·추정 **base** 자세로 세계에 놓은 점. Qe 가 저장된 `near_estimate_m` 와 맞는지로 계산을 검산한다.
    - V: g 가 쓰는 lift 시점의 참 팔레트 원점. n: G 방향의 왼쪽 단위벡터.
  - **D 검출 항** = n·(V − Qd). 검출기의 몫이다. 캡처부터 lift 까지 팔레트가 움직였다면 그 몫도 여기에 섞이므로, 3 절의 정지 사전 검사로 따로 확인한다.
  - **C 캡처 위치 항** = n·(Qd − Qe). 캡처 당시 위치 추정의 몫이다.
  - **P 계획 항** = n·(Qe − G.xy). 계획기 끝점이 목표 추정에서 비켜 있는 몫이다(agy 검토 ③).
  - 정의상 T = D + C + P 다. Codex 가 16 실행에서 재구성했을 때 Qe 는 `near_estimate_m` 와 부동소수점 오차 수준으로 맞았고 P ≈ 0 이었다. Ub3 random_1 s1 은 D −1.2, C −13.2, P ≈ 0, T −14.4 mm 다.
  - `near_capture.near_error` 는 D 가 아니다. 캡처 당시 추정 자세로 놓은 목표와 `scenario.pickup` 의 차이라 C 가 섞여 있다(Ub3 random_1 s1 은 16.1 mm 가운데 검출 몫이 약 1.2 mm).

## 3. 기록 수준 분해(Isaac 없음)

- 입력 필드와 뜻(Codex 검토 ② 로 코드에서 확인):

| 필드 | 뜻 |
|---|---|
| `slip_watch.baseline.seat` | insert→lift 전환 때 참 팔레트 원점을 차체 좌표로 본 [앞뒤, 횡, 요]. S 의 검산값 |
| `result.paths.insert` | insert 경로 전체(poses·directions·curvatures). G 는 끝점. `tracker_versions` 로 insert 동안 교체가 없었는지 확인한다 |
| `slam_control.npy` | [시뮬 시각, 추정 후륜축 x·y·yaw, 참 후륜축 x·y·yaw]. lift 전환 시각의 행이 E·A |
| `observation_attempts[*]`, 캡처의 `capture_control` | 근접 관측과 캡처 당시 추정·참 자세. D·C 를 계산한다 |
| `slam_error_insert_end` | 참 후륜축 좌표의 추정−참 앞뒤·횡·요(삽입 끝). L 의 대조값 |
| `insertion_error` | 추정 후륜축에서 경로 끝까지의 무부호 거리와 요. 횡 이탈값이 아니어서 쓰지 않는다 |
| `lateral_clearance_min_m.insert` | insert 전체의 좌우 포크별 최소 여유(보수적 AABB). 보조로만 적는다 |

- C + L(위치 추정 두 항의 순기여)을 판정 밖 서술값으로 함께 적는다. 로컬 18 실행에서 C 와 L 이 ±30–66 mm 로 크고 서로 반대 부호여서, 결과를 본 뒤 더한 값이다. 이 값만으로 "위치 추정 편향의 변화"라고 읽지 않는다. 세계 좌표의 일정한 편향 b 만 있어도 lift 때 추정 yaw 가 경로 끝과 다르면 C + L = (n_E − n_G)·b 가 생긴다. 편향 변화로 해석하려면 캡처 기준으로 정렬한 상대 자세 오차를 따로 확인한다(구현 Codex 리뷰).
- 실행마다 T(D·C·P)·F·L·S 를 부호와 함께 적고, 두 잔차 S − (T + F + L) 과 T − (D + C + P), 자료 완전성(어느 항을 계산하지 못했나)을 적는다. 최종 하위 항의 합 D + C + P + F + L 과 S 의 차이도 함께 적는다.
- **팔레트 정지 사전 검사**: 캡처 시각(`capture_control.time_s`) 이후 첫 표본부터 lift 전환 첫 표본까지, 참 팔레트의 최대 평면 이동과 요 변화를 모든 실행에서 잰다. 0.5 mm 또는 1 mrad 를 넘는 실행은 별도 "팔레트 이동" 항을 두고 귀속을 보류한다. 지금까지 확인한 16 실행은 이 구간에서 최대 약 1.51 μm·0.30 μrad 였다(0.1 s 표본 기준, Codex 재계산).

### 3.1 판정(결과 전 고정)

- **대상 선별**: |S| 이 10 mm 를 넘는 실행을 "치우침 실행"으로 고른다. 탐색용 선별값이고, 물리 문턱이 아니다. 5·10·15 mm 로 바꿨을 때의 대상 수와 결과도 함께 적는다.
- **기여 표기**: "주 기전"이라고 쓰지 않는다. 치우침 실행마다 S 와 **같은 부호**인 항 가운데 가장 큰 것을 "같은 부호의 가장 큰 기여"로 적고, S 와 **반대 부호**인 항은 "상쇄 항"으로 그 크기와 함께 적는다.
- **보류**: 계산하지 못한 항이 있거나, 3 절의 두 잔차와 하위 항 합계 차이 가운데 하나라도 |값| 이 max(2 mm, 0.1 |S|) 를 넘거나, 팔레트 이동이 있으면 그 실행은 "귀속 보류"로 두고 묶음 집계에서 뺀다.
- **묶음 결과**: 같은 부호 가장 큰 기여별 실행 수, 항마다의 부호 있는 분포(중앙값·최대), 상쇄가 컸던 실행 목록이다. 팔별(B0, 섭동 팔)로 나눠 적는다. 통계 검정은 하지 않고, 비율을 일반화하지 않는다.
- 결과로 내는 것은 "다음에 고칠 곳의 후보"까지다. 문턱이나 제어 값을 바꾸지 않는다.

### 3.2 다음 단계로 넘어가는 조건

- 같은 부호 가장 큰 기여가 L 이면: 근접 캡처부터 lift 까지의 상대 오도메트리 오차와 SLAM 보정 이력을 본다. approach 동안 보정을 붙잡아 두는(hold) 기본 흐름이 있으므로, insert 중 적용된 보정만 보지 않는다. 선행 #332(hold 시작 SLAM 오차, 횡 편향)와 이어서 본다.
- C 이면: 캡처 당시 위치 추정을 본다(위와 같은 자료).
- D 이면: 근접 검출 오차를 본다. 선행 #331·#337(평면 정제 비교, A2 후보)의 도구(`tools/near_refit_compare.py`)와 이어서 본다.
- P 이면: 계획기 끝점이 목표 추정과 왜 다른지 본다.
- F 이면: insert 추종기의 횡·요 오차와 조향 응답을 본다.
- 보류가 많아 나눠지지 않으면, 삽입 단계 계측을 더한 Isaac 재실행을 제안한다. 그때 잡 수·시간을 총괄에 올리고 신호를 받는다.
