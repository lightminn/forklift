## 1. 문제

원자료: ws1 `test_runs/live/newtq_occ_4c53486_line_m_s0/live/epoch_1/run`(스냅숏 `occ_4c53486`). 판정은 Codex 의 격자 재구성(덤프 1–4 의 전체 셀 상태·`free_stamp` 일치)으로 했다.

- 복귀 첫 회전에서 허가가 D-2 칸 표지 끝의 칠한 칸(halo)을 occupied 로 보고 0 으로 막았다(450.1 s).
- 그 뒤 13 s 동안 0.1 s(12 틱 = 스캔 한 주기)짜리 전진 펄스가 11 번 나갔다. 매번 같은 흐름이다.
  1. 직전 상한 0(halo 칸 A 또는 B 에 막힘).
  2. 새 스캔의 비어 있음(FREE) 광선이 A·B 를 지운다. 같은 스캔의 표시는 그 칸을 다시 칠하지 않는다.
  3. 다음 칸 C 까지 검증 거리 0.06–0.10 m → 상한 `speed_for(d)` 0.059–0.223 m/s → 가속하며 전진.
  4. 다음 스캔에서 halo 가 다시 칠해져 상한 0.
- 허가 우회는 없다: 1,668 틱에서 명령 > 같은 틱 상한 0 건, 상한 0 에 양의 명령 0 건. 표지 실물까지 차체 최소 간격은 참값 0.222 m 였다.
- 해가 되는 점은 둘이다.
  - 펄스마다 몇 mm 씩 누적해 6 cm 다가갔다. P6 재계획 순간 출발 외곽–추가 사각형 간격이 8 mm 가 되어 탈출 쓸림의 출발 여유(0.01 m)에서 모든 후진이 거부됐다.
  - P6 정지 감시(`permit_stop_tick`)는 상한 0·이유 occupied 가 3 s 이어져야 발동하는데, 펄스마다 감시가 처음부터 다시 시작돼 450.1 s 가 아니라 463.7 s 에 발동했다. 450.1 s 자세(간격 7.6 cm)에서는 후진 탈출 쓸림이 통과한다.

이 진동은 지금 규칙의 의도된 동작이다: 새 스캔의 FREE 증거는 거리 오차만큼 짧게 자른 광선과 오도메트리 침식을 거친 뒤 이전 표시를 덮는다. halo 는 실제 표면이 아니라 표시 반경이므로 그 소실을 표면 소실로 볼 근거는 없다. 고칠 것은 "한 스캔의 소실만 보고 occupied 정지에서 다시 출발하는 것"이다.

## 2. 설계 (2판 — Codex 적대적 검토 P2 3 건·P3, agy 독립 검토 반영)

### R1 재출발 확인 상태

- **거는 때**: 허가 자체의 상한(`obstacle["layer"].limit`)이 이유 `occupied` 로 0 일 때, 그 단계·추종기에 확인을 건다.
- **적용 자리**: 허가가 작동하는 단계(`permission_acting` 의 acting)이고 포켓 단계가 아닐 때, 허가 자체의 상한에만 건다(Codex P3). 포켓·도킹 직선의 상한, D4 경로 막힘 정지(`path_blocked_ticks`, slew 제동)는 지금 그대로다.
- **확인 중 출력**: 원래 상한이 양수여도 출력 상한은 0 이다. 최종 상한은 `min(원래, 확인)` 이라 기존 판정을 완화하지 않는다.
  - 원래 상한이 0 인 틱은 원래 이유를 그대로 둔다(`sensor_silent:*`·`unknown` 등을 덮지 않는다 — N9 종료 검사 유지, Codex P3).
  - 원래 상한이 양수인데 확인 때문에만 0 인 틱(이하 "확인 대기 틱")은 이유를 `occupied` 로 둔다.
- **세는 것**(Codex P2-2): 칸을 지울 수 있는 센서(`may_clear`)마다, 마지막으로 원래 상한이 0 이었던 틱 이후 새로 받은 스캔 시각.
  - 확인 대기 틱마다 그 센서들의 최신 스캔 시각을 모은다. 마지막 0 틱 때 이미 받았던 스캔은 세지 않는다.
  - 모든 `may_clear` 센서가 서로 다른 새 스캔 N 개씩을 모으면 확인을 푼다. 그 틱부터 원래 상한이 나간다.
  - 원래 상한이 0 인 틱(이유 무관)이 끼면 모은 것을 비운다(연속 조건).
- **계획 대기 중**(`permission_watch`, Codex P2-3): 그 틱은 정지 방향으로 잰 관측이라 확인 계산에 쓰지 않는다. 대신 모은 것을 비운다(관측 공백 뒤엔 새로 N 개).
- **버리는 때**: 단계가 바뀌거나 그 단계의 추종기 객체가 바뀌면(재계획 설치, 탈출·물러남, 근접 보정) 확인을 버린다. 같은 경로 대기(`same_path`)는 추종기를 바꾸지 않으므로 유지된다.
  - agy 는 새 다리의 첫 틱이 halo 가 지워진 순간이면 바로 전진할 수 있다고 지적했다. 새 다리는 P6 재계획이면 막힌 칸을 장애물로 넣어 다시 계획한 경로이고, 탈출이면 막힌 칸에서 멀어지는 곧은 길이라, 버리는 쪽을 택한다(Codex 도 같은 판단). 한계에 적는다.
- **기본 N** 은 Isaac 비교로 정한다. 기록 선별(Codex)에서 N = 2 는 첫 펄스 12 틱을 남기고, N = 3 은 11 펄스를 모두 보류한다.

### R2 정지 감시·재계획과의 연결 (Codex P2-1, agy 전제 3)

- 확인 대기 틱은 정지 시간 누적을 **멈추기만** 한다. 세지도, 처음부터 다시 시작하지도 않는다.
  - P6 정지 감시(`permit_stop_tick`): 확인 대기 틱의 작업 시간을 따로 모아, 정지 시간(`work_elapsed(시작, t)`)에서 뺀다. 시작 시각은 그대로 둔다 — 작업 시계는 일시정지·계획 대기를 건너뛰므로, 시작을 작업 시간만큼 옮기면 같은 양이 빠지지 않는다(Codex 재검토 P2). 원래 상한이 0 인 틱만 3 s 에 더해진다. 그래서 펄스가 감시를 처음부터 다시 시작하지도 않고, 장애물이 비켜선 뒤 확인을 기다리는 0.N 초가 P6 를 앞당기지도 않는다. 감시를 새로 시작하면(다른 다리·추종기, 감시 공백, 부적격) 모은 확인 대기 시간도 버린다.
  - 그리드 모드 막힘 재계획(`blocked_ticks`, 120 틱): 확인 대기 틱은 더하지도 0 으로 되돌리지도 않는다.
  - `force_replan`·cusp 넘김의 방향과 강제 재계획은 그대로다.
- 확인 대기 틱은 기록에 따로 센다(`restart_confirm.gate_ticks`).

### R3 스위치와 기록

- 러너 `--restart-confirm-scans N`(정수, 0 = 끔, 기본 0). 끔이면 새 포트 읽기(`last_scan_s`·센서 목록 포함) 전에 빠져 지금과 비트 단위로 같다. 근접 계약 기본 0 으로 등록한다.
- 리보틱스 런처 `RESTART_CONFIRM`. CT-1 런처 기본값은 Isaac 비교 뒤 sw-연속이송-재관측과 합의해 정한다.
- `result.json["obstacle_layer"]["restart_confirm"]`: N, 확인이 걸린 횟수, 확인 대기 틱 수, 풀린 횟수와 걸린 시간 분포.

### R4 고르지 않은 안

- **최근 T 초 안에 occupied 였던 칸을 계속 막기**: 지도·보정 좌표계의 재투영과 정상적인 장애물 소실 뒤의 지연까지 바뀐다. 유한 T 로는 누적 접근을 막는다는 보장도 없다.
- **FREE 증거 규칙을 바꾸기**: 격자 전체의 소실 판정을 바꿔 영향이 넓다.

## 4. 위험과 한계

- 재출발이 스캔 N 주기(10 Hz 에서 N × 0.1 s)만큼 늦어진다. 실제 장애물이 비켜선 뒤의 출발도 그만큼 늦다(그 대기는 P6 를 앞당기지 않는다).
- halo 가 2 스캔 지워지고 1 스캔 칠해지기를 되풀이하면 확인이 풀리지 않는다. 차는 서 있고 P6 정지 감시가 그 0 틱들로 3 s 를 채워 재계획으로 넘어간다(agy 전제 2 — 의도한 동작).
- 새 추종기에서 확인을 버리므로, 새 다리의 첫 틱이 halo 소실 순간이면 바로 출발할 수 있다(agy 전제 1).
- 정지 중 조향(조향 유지는 허가 0 의 기존 hold 와 같다), 센서 패킷 분할 같은 드라이버 수준 시각은 범위 밖이다(agy 전제 4·5).
- halo 가 N 스캔 넘게 연속으로 지워지면 여전히 다가간다. 그때는 계획 여유(KEEPOUT, 이 사례의 (a))가 맡는다.
- 이 규칙은 칠한 반경과 계획 여유의 차이 자체를 없애지 않는다. 그것은 (a) 다.
