# occupied 정지 뒤 재출발 확인 (2026-10-25)

지시: 총괄(2026-10-25) — 인계 사례(CT-1 line_m P-3 return_home 정체)의 (c) "정지 중 재전진". 정책(사용자 2026-10-24): 안전 판정 규칙·런처 기본값은 사용자 결정 없이 정하고 문서·보고로 남긴다.
branch `fix/zero-permit-creep`.

## 1. 문제

원자료: ws1 `test_runs/live/newtq_occ_4c53486_line_m_s0/live/epoch_1/run`(스냅숏 `occ_4c53486`). 판정은 Codex 의 격자 재구성(덤프 1–4 의 전체 셀 상태·`free_stamp` 일치)으로 했다.

- 복귀 첫 회전에서 허가가 D-2 칸 표지 끝의 칠한 칸(halo)을 occupied 로 보고 0 으로 막았다(450.1 s).
- 그 뒤 13 s 동안 0.1 s(12 틱 = 스캔 한 주기)짜리 전진 펄스가 11 번 나갔다. 매번 같은 흐름이다.
  1. 직전 상한 0(halo 칸 A 또는 B 에 막힘).
  2. 새 스캔의 비어 있음(FREE) 광선이 A·B 를 지운다. 같은 스캔의 표시는 그 칸을 다시 칠하지 않는다.
  3. 다음 칸 C 까지 검증 거리 0.06–0.10 m → 상한 `speed_for(d)` 0.059–0.223 m/s → 가속하며 전진.
  4. 다음 스캔에서 halo 가 다시 칠해져 상한 0.
- 허가 우회는 없다: 1,668 틱에서 명령 > 같은 틱 상한 0 건, 상한 0 에 양의 명령 0 건. 표지 실물까지 차체 최소 간격은 참값 0.222 m 였다.
- 해가 되는 점은 둘이다.
  - 펄스마다 몇 mm 씩 누적해 6 cm 다가갔다. P6 재계획 순간 출발 외곽–추가 사각형 간격이 8 mm 가 되어 탈출 쓸림의 출발 여유(0.01 m)에서 모든 후진이 거부됐다.
  - P6 정지 감시(`permit_stop_tick`)는 상한 0·이유 occupied 가 3 s 이어져야 발동하는데, 펄스마다 감시가 처음부터 다시 시작돼 450.1 s 가 아니라 463.7 s 에 발동했다. 450.1 s 자세(간격 7.6 cm)에서는 후진 탈출 쓸림이 통과한다.

이 진동은 지금 규칙의 의도된 동작이다: 새 스캔의 FREE 증거는 거리 오차만큼 짧게 자른 광선과 오도메트리 침식을 거친 뒤 이전 표시를 덮는다. halo 는 실제 표면이 아니라 표시 반경이므로 그 소실을 표면 소실로 볼 근거는 없다. 고칠 것은 "한 스캔의 소실만 보고 occupied 정지에서 다시 출발하는 것"이다.

## 2. 설계

### R1 재출발 확인 상태

- 허가가 이유 `occupied` 로 상한 0 을 내면 그 다리(추종기)에 재출발 확인을 건다.
- 확인이 걸려 있는 동안 출력 상한은 0 이다. 허가 자체(원래 상한)는 매 틱 그대로 계산한다.
- 원래 상한이 양수인 틱마다, 그 틱의 최신 스캔 시각(장애물 층이 받은 센서 스캔 시각 중 가장 늦은 것)을 모은다.
  - 서로 다른 스캔 N 개에서 연속으로 양수가 되면 확인을 푼다. 그 틱부터 원래 상한이 그대로 나간다.
  - 그 사이 원래 상한이 다시 0 이면 모은 스캔을 비운다(연속 조건).
- 최종 상한은 언제나 `min(원래 상한, 확인 상한)` 이다. 기존 판정을 완화하지 않는다.
- 추종기가 바뀌면(재계획 설치, 탈출, 단계 전환) 확인 상태를 버린다. 새 다리는 자기 허가로 시작한다.
- 기본 N 은 Isaac 비교로 정한다. 기록 선별(Codex)에서 N = 2 는 첫 펄스 12 틱을 남기고, N = 3 은 11 펄스를 모두 보류한다.

### R2 P6 정지 감시와의 연결

- 확인으로 상한이 0 인 틱은 이유를 `occupied` 로 둔다. 그래서 P6 정지 감시가 펄스 때문에 처음부터 다시 시작되지 않는다.
- 확인 중 이유는 기록에 `restart_confirm` 표시를 따로 남긴다(이유 문자열은 감시가 읽는 `occupied` 그대로).

### R3 적용 범위

- 허가가 작동하는 단계(`permission_acting`)의 상한에만 건다. 도킹 직선·포켓 단계의 별도 상한은 건드리지 않는다.
- 이유가 `occupied` 인 0 만 확인을 건다. `unknown`·`sensor_silent`·`evidence_stale` 의 0 은 지금처럼 그 원인이 풀리면 바로 풀린다(관측이 돌아오면 다시 판정하는 구조라 같은 halo 진동이 아니다).

### R4 스위치와 기록

- 러너 `--restart-confirm-scans N`(정수, 0 = 끔, 기본 0). 끔이면 지금과 비트 단위로 같고 새 포트 읽기가 없다. 근접 계약 기본 0 으로 등록한다.
- 리보틱스 런처 `RESTART_CONFIRM`, CT-1 런처 기본값은 Isaac 비교 뒤 정한다(CT-1 런처는 sw-연속이송-재관측과 합의).
- `result.json["obstacle_layer"]["restart_confirm"]`: 설정 N, 확인이 걸린 횟수, 확인으로 0 이 된 틱 수(원래 상한은 양수였던 틱), 풀린 횟수와 걸린 시간 분포.

### R5 고르지 않은 안

- **최근 T 초 안에 occupied 였던 칸을 계속 막기**: 지도·보정 좌표계의 재투영과 정상적인 장애물 소실(사람이 비켜섬) 뒤의 지연까지 바뀐다. 유한 T 로는 누적 접근을 막는다는 보장도 없다.
- **FREE 증거 규칙을 바꾸기**: 격자 전체의 소실 판정을 바꿔 영향이 넓다.

## 3. 검증 계획

1. 단위 시험(먼저): 펄스 반례(원래 상한 0 → 한 스캔 양수 → 0)에서 출력 상한이 0 으로 유지; N 개 서로 다른 스캔 연속 양수 뒤 풀림; 같은 스캔이 여러 틱이면 하나로 셈; 중간 0 이면 다시 셈; 추종기 교체 시 버림; occupied 가 아닌 0 은 확인 안 함; P6 감시가 확인 중 타이머를 이어 감; 끔이면 비트 동일·새 읽기 없음.
2. CPU 재생: 이 실행 기록에 규칙을 적용(Codex 재구성 상한 열 사용)해 N = 2·3 의 보류 틱과 P6 발동 시각을 구한다.
3. 재생 게이트 runs29(끔), ws1 전체 pytest.
4. Isaac(묶음 런처, 같은 시간대, 켬/끔): CT-1 line_m·random_m 세션(sw-연속이송-재관측과 실행 조건 합의) 과 리보틱스 장면(aisle_rack·trailer·line_2_m). 기록: return_home 정체, P6 발동·탈출 결과, 확인으로 늦어진 재출발 시간, 완주.

## 4. 위험과 한계

- 재출발이 스캔 N 주기(10 Hz 에서 N × 0.1 s)만큼 늦어진다. 실제 장애물이 비켜선 뒤의 출발도 그만큼 늦다.
- halo 가 N 스캔 넘게 연속으로 지워지면 여전히 다가간다. 그때는 계획 여유(KEEPOUT, 이 사례의 (a))가 맡는다.
- 이 규칙은 칠한 반경과 계획 여유의 차이 자체를 없애지 않는다. 그것은 (a) 다.
