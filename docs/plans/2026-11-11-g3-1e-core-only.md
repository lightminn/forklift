# 1e (c) 코어만 추가: 같은 스냅숏 직접 대조 등록 (2026-11-11, 결과 전 고정)

- 배경: 1e 단계 1(`docs/validation/2026-11-11-g3-1e-core-results.md`)에서 (a) 스레드 작업자 + 코어 추가는 불합격이었다.
  - 보고만 한 다른 잡 비교에서는 코어를 하나 더 주는 것만으로 W 가 약 0.07–0.09 줄었다. 코어 둘 D 0.786–0.802, 17604 의 코어 하나 D 0.874 다.
  - 총괄 결정(2026-11-11): 단계 2 는 보류한다. (c) 코어만 추가를 같은 스냅숏에서 직접 대조한다.
- 검토 예외(총괄 결정): #420 에서 독립 검토 3 회를 거친 설계의 축소판이라, 독립 검토 3 회 대신 Codex 적대 검토 한 스레드를 수렴할 때까지로 한다.

## 팔과 배정

| 팔 | 세션의 물리 코어 | 잡 CPU | 1e |
|---|---|---|---|
| A | 하나(논리 CPU 둘) | 4 | off |
| B | 둘(논리 CPU 넷) | 6 | off |

- 단일 슬롯 잡이고, 묶음 실행기의 `--bridge-cpus auto` 가 브리지에 코어 하나를 뗀다. 세션 코어는 묶음 요약의 `session_cpus` 로 확인한다(ws1: CPU n 과 n + 12 가 한 코어).
- 두 팔은 다음이 같다.
  - 같은 스냅숏(새 main, #424 뒤).
  - line_m far K f 1.0 confirm(`r1c_session.sh`), seed 0, INSTR off.
  - G3: `FORKLIFT_GRID_CLEAR_KERNEL=1`, `FORKLIFT_SHADOW_KERNEL=1`, `LIDAR_CAST=fast`(명시).
  - ④⑤: 런처 기본값 그대로다(#424 이후 `RETURN_START=boxed`, `NEAR_END_STAND=on`). 목록에서 정하지 않고, 분석기가 네 세션의 `env.sh` 기록이 같은지 대조한다.
  - shard 4, 메모리 8G, `--slots 1 --retries 0`. 1e 단계 1 의 잡 감싸개로 CPU sampler 와 스레드 표본기를 함께 띄운다.

## 순서와 짝

- 잡 넷을 A B B A 로 낸다. 각 잡은 앞 잡 뒤(afterany)에 시작한다(`docs/validation/2026-11-11-g3-1e-c/g3_1e_c_submit.sh`).
- 짝은 (A 1, B 1)과 (B 2, A 2)다. CPU 배정이 잡 단위라서, 한 잡 안의 대조는 묶음 실행기 변경 없이는 안 된다.
- 크기: 세션당 약 4 분 + 기동, 넷이면 약 25–30 분.

## 판정(결과 전 고정)

- W: AUTO 행의 일을 그 시뮬 시간으로 나눈 값(1e-0 의 모집단 규칙).
- 짝마다 절감 = W(A) − W(B).
- **두 짝 모두 절감 ≥ 0.03707 s/sim s 이면 "(c) 합격"**, 아니면 "(c) 불합격"이다.
- 무효:
  - 환경·설정 무효는 그 짝을 한 번 다시 낸다(다시 낸 짝도 무효면 총괄에). 환경·설정 무효에 드는 것: 다른 잡 겹침(자기 GPU 감시·CPU sampler), 감시 실패, 묶음 재시도·미시작, 단일 슬롯 아님, 세션 코어 수 불일치.
  - 미션 실패와 안전 사건(기록 누락 포함)은 재실행으로 지우지 않고 총괄에 올린다.
  - 네 세션의 ④⑤ 기록이 다르면 총괄에 올린다.
- 분석기: `docs/validation/2026-11-11-g3-1e-c/g3_1e_c_analyze.py`. 보고만 하는 항목은 세션별 AUTO 배율·W·`evidence_stale`·미션, 스레드 표본(이름별 CPU·실행 큐 대기)이다.

## 합격·불합격 뒤(총괄 결정 2026-11-11)

- 합격: 실시간이 중요한 실행(라이브 콘솔 단독·시연·실시간 측정)의 세션 CPU 를 6 으로 올리는 PR 을 낸다. 큰 배치는 등록마다 정한다(동시 세션 6 → 4 맞바꿈).
- 불합격: 단계 2(프로세스 작업자) 결정으로 돌아간다.
