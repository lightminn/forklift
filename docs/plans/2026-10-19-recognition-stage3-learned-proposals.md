## 1판에서 바뀐 것 (Codex 1판 검토 — 아래 "검토 기록")

- **기하형만으로는 맞닿은·적층 팔레트를 가르지 못한다.** 그리고 하류 맞춤(`fit_scene`)도 한 제안을 하나의 후보로만 맞춰, 합쳐진 마스크를 **조용히 잘못된 비규격 후보 하나**로 낸다(Codex CPU 재현: 2단 적층·맞닿은 나란함 → `fitted parametric:x` 1 개).
  - 그래서 인스턴스 분리는 학습 제안기가 맡는다.
  - 기하형은 합쳐졌을 수 있는 덩어리를 **실패로 닫는다**.
- 평가 정의를 구현 전에 고정한다: 일대일 대응, 분모, 라벨 이동, 거리, 위험 지표.

## 작업 1 — 평가 정의와 분할 지표 (제안기 무관)

`tools/evaluate_recognition.py` + `evaluation_multi` 에 넣는다. 검출기 이름은 `<제안기>-fit`(`oracle-fit`, `geometric-fit`, `learned-fit`)과 `<제안기>-proposals`(분할만)이다.

- **정답 마스크:** 깊이 격자 기준 정답을 쓴다.
  - 잡음판은 `apply_noise` 가 RGB·라벨을 깊이 대비 2 px 옮겨 저장한다(`depth_noise.py:138`).
  - 같은 장면의 `isaac_clean` 인스턴스 ID(깊이와 정렬)를 분할 정답으로 쓴다. 장면 ID·조리법 해시가 같은지 확인하고, 다르면 거부한다.
  - RGB 를 쓰는 학습 제안기는 이동된 RGB 를 입력으로 받는다. 그 이동이 낳는 오차는 분할 오차로 그대로 센다 — 실제 센서의 RGB–깊이 정렬 오차와 같은 종류다.
- **분모:** 정답의 `eligible` 인스턴스 — 접근 가능한 면 중 노출 ≥ `EXPOSURE_MIN` 인 면이 있는 인스턴스(`recognition_truth.py:189`).
  - 보이지만 eligible 이 아닌 인스턴스에 대응된 제안은 추가 제안으로 세지 않고 따로 센다(`ineligible_matched`).
- **판정 순서**(3판, Codex 2판 반례):
  1. **합침 먼저:** 한 제안이 둘 이상의 정답 인스턴스 각각을 그 인스턴스 화소의 ≥ 30 % 덮으면 합침이고, **대응 후보에서 뺀다**(두 정답의 정확한 합집합은 각각 IoU 0.5 라도 대응 0).
  2. **일대일 대응:** 남은 제안 × eligible 정답의 IoU 행렬에서 IoU ≥ 0.5 인 쌍만 두고 헝가리안 최대 IoU 대응을 한다. 동률은 (정답 id, 제안 순번) 순.
     - **재현율** = 대응된 eligible / eligible.
     - **IoU p50·p5** 는 대응된 쌍.
  3. **쪼갬:** 대응되지 않은 정답 중, 그 화소의 ≥ 5 % 를 덮는 제안이 둘 이상이고 그 제안들의 **합**이 ≥ 50 % 를 덮으면 쪼갬(여섯 등분 16.7 % 조각도 쪼갬).
- **추가 제안:** 대응되지 않고 합침·쪼갬·`ineligible_matched` 도 아닌 제안. 제안 화소가 방해물(−2)·배경(−1)·인스턴스 중 어디가 가장 많은지로 나눈다.
- **음성(N) 장면:** 제안이 하나라도 있는 장면 비율, 장면당 제안 수.
- **거리 구간:** 정답에서만 계산한다. 접근 가능한 면 중 노출이 가장 큰 면의 포켓 중점과 카메라의 수평 거리이고, 대응 여부와 무관하다. 구간 [0, 1.5), [1.5, 2.0), [2.0, 2.5), [2.5, 3.0), [3.0, ∞), 빈 분모는 "–".
- **맞춤 지표:**
  - 기존 판정(놓침·추가 후보·대상 선택).
  - 위험은 `pose_dangerous`(원거리 집기 보류 계약에서도 의미 있는 자세 위험, `evaluation_multi.py:161`)와 포켓 오차 p95 로 본다 — `dangerous` 는 `pickable is True` 만 보므로 원거리에서 무효(Codex).
  - 각 지표의 표본 수·제외 수·미대응 수를 함께 낸다.
  - `oracle-fit` 과는 장면 단위로 비교한다: **oracle 이 맞은 장면 중 새로 틀린 비율**과 그 반대를 따로 낸다.
- **ID 해석:** 반드시 로더가 디코딩한 `sample.instance_ids` 를 쓴다(PNG 원값 0 = 배경, 65535 = 방해물).
- 시험(먼저 실패 확인):
  - 정답 마스크를 제안으로 주면 재현율 1·IoU 1·추가 0.
  - 두 정답을 정확히 합친 제안 → 대응 0·합침 1(1판의 IoU 0.5 반례).
  - 한 정답을 여섯 조각 → 쪼갬 1(1판의 0.167 반례).
  - 정답 이동 2 px 의 IoU 영향 → clean 정답 사용 확인.
  - eligible 아닌 인스턴스 대응은 추가가 아님.
  - 거리 분모에 놓친 인스턴스 포함.

## 작업 2 — 기하 대체 제안기 (작고, 실패로 닫힘)

`src/forklift_core/perception/geometric_proposals.py`.

1. 유효 깊이를 base 로 복원한다(거리 ≤ 4.5 m).
2. 바닥 띠 `z ≤ a + b·r²` 를 지운다.
3. 깊이 불연속 `c + d·r` 로 8-이웃 연결 성분을 만든다.
4. 수직면(`fit_faces`)이 없는 성분은 지운다.
5. **마스크 계약:** 성분의 외곽선 안에 갇힌 **무효 깊이** 구멍만 메운다(최대 반경 4 px). 유효 깊이로 보이는 포켓 안쪽은 메우지 않는다. 그래야 `proposal_points` 의 3 px 깎기가 내부 결손을 외곽처럼 넓히지 않는다(Codex 반례: 5 % 결손에서 맞춤 점 2,015 → 519).
6. **합침은 깊이로 막지 못한다 — 식별로 막는다(3판):** 깊이만으로는 2단 적층(EPAL 6 0.288 m, T11 0.180 m — 단일 팔레트 높이 범위와 겹침)과 맞닿은 나란함을 가를 신호가 없다(Codex 2판 CPU 재현: 폭·높이·면 수가 단일과 같음).
   - 그래서 기하 제안의 후보는 합쳐졌을 수 있고, 안전 계약은 **식별**이다. 기하 제안 후보는 늘 `unconfirmed` 라 자동 선택되지 않고(설계 §7.5), 대상 선택에서는 반경 안의 `uncertain` 으로 재관측을 부른다.
   - 기록에 `geometric_unsplit` 경고를 남겨 콘솔이 미확인으로 보이게 한다.
   - 수평 폭 > 2.0 m 성분만 제안하지 않고 실패 `oversize` 로 기록한다(반경 안이면 재관측).
7. 프레임당 제안 상한 8(설계 §8): 큰 성분부터, 버린 수를 기록한다. 버린 대상도 재현율 분모에 남는다.

기하 제안의 식별은 늘 `unconfirmed`(설계 §7.5)라 자동 선택되지 않는다. 진단 실행 `geometric-fit-gate-open`(식별 관문을 강제로 연 것)은 기록만 하고, "학습 경로의 상한"이라고 쓰지 않는다 — 랙·크레이트도 함께 열리고 마스크도 학습 제안과 다르다(Codex).

시험:
- 단일 팔레트 → 제안 1, clean 정답 IoU ≥ 0.9.
- 앞뒤 두 팔레트 → 둘.
- **맞닿은 나란함·2단 적층 → 후보는 `unconfirmed` + `geometric_unsplit`, 지시 반경 안이면 선택 `reobserve`, 자동 `selected` 없음**(Codex 반례를 그대로 입력).
- 폭 2 m 넘는 성분 → 실패 `oversize`.
- 바닥만 → 0.
- 결손 5 % 에서 맞춤 점 수가 정답 마스크의 ≥ 90 %.
- 제안 9 개 이상 → 8 개와 버린 수.
- 결정적.

## 작업 3 — 학습 데이터 (Isaac 렌더, 학습 대역)

- **대역:** `train` seed 대역(5,000,000–). 정지 장면 조리법(`tools/generate_recognition_scenes.py`)을 학습 대역으로 늘린다 — 사례 S1–S7·N 를 같은 비율로, 장면 약 8,000.
- **렌더:** `sim/isaac/render_recognition_scenes.py` 로 RGB·깊이·인스턴스 ID 를 렌더한다(ws1, shard 나눠). 실측 1,020 장면 11.5 분 → 8,000 장면 약 1.5 GPU 시간.
- **외형 무작위화(필수):** 지금 렌더는 팔레트가 늘 나무색(`WOOD`)이고 방해물이 늘 회색(`GREY`)이라(`recognition_render_core.py:30`) 모델이 색으로 맞힐 수 있다.
  - 학습 대역에서는 팔레트·방해물·바닥·벽의 색을 같은 분포에서 무작위로 고른다: 나무색 계열, 플라스틱 원색(파랑·빨강·검정·회색), 흰색.
  - 조명 세기·방향과 노출도 무작위로 한다.
  - "색이 다른 팔레트"(회사 사례)를 학습 분포에 넣는 것이기도 하다.
- **입력:** RGB 640 × 480, 팀 잡음판을 입힌 깊이는 학습 입력에 쓰지 않는다(RGB 모델). 라벨은 RGB 기준 인스턴스 마스크다 — 잡음판의 2 px 이동을 RGB 쪽에 적용한 것을 그대로 쓴다.
- **형식:** YOLO 분할 형식. 클래스는 `pallet` 하나이고, 방해물은 배경이다.
  - **한 인스턴스 = 한 라벨 행.** 가림으로 여러 조각이 된 인스턴스는 조각들의 외곽선을 가장 가까운 점끼리 잇는 가는 다리로 한 다각형에 합친다(Ultralytics COCO 변환의 `merge_multi_segment` 방식). 외곽선마다 행을 만들면 가림을 두 팔레트로 학습한다(Codex: 좁은 장애물 앞 EPAL 6 → 외곽선 2).
  - 구멍(포켓 너머의 배경)은 다각형에 넣지 않는다 — YOLO 다각형은 구멍을 못 나타낸다. 그 차이는 IoU 로 잰다.
  - 시험: 변환 → Ultralytics 데이터 로더 왕복 → **인스턴스 수 보존**, 원래 마스크와 IoU ≥ 0.9(구멍 제외 기준). 가림 조각 장면을 포함한다.
- **분할:** 학습 대역 안에서 train 90 % / val 10 %. dev·eval 장면(eval_pool)은 학습에 쓰지 않는다.
- **범위 밖(기록):** 사실적 외형 메쉬(설계 §6 — 나뭇결·못·모서리)는 이번 범위에 넣지 않는다. 그래서 학습 모델의 실물 성능은 주장하지 않는다.

## 작업 5 — 학습 제안기와 식별 문턱 τ

- `src/forklift_learned/`(선택 의존성 `[learned]`, 코어는 import 하지 않는다 — 설계 §4).
  - `LearnedProposer(onnx_path, providers)` → `propose(scene) -> list[InstanceProposal]`(출처 `learned`, 점수 = 인스턴스 신뢰도). 마스크는 깊이 격자 크기로.
  - 실패·시간 초과는 기하 대체로 넘어가고, 그 후보는 `unconfirmed`(설계 §10)다.
- **τ 결정**(dev 에서 한 번, 설계 §7.5): 같은 dev 곡선 위에 다음을 놓는다.
  - S5(손상) 놓침.
  - S6·N 추가 후보·음성 오검출.
  - **애매하지 않은 지시의 재관측·확인 요청률**(`deferred_unambiguous`, 설계 §3.4 콘솔 요청률 ≤ 10 %).
  - 대상 선택 오류.

  설계 §3.4 의 상한(놓침 ≤ 5 %, 음성 오검출 ≤ 10 %, 추가 후보 ≤ 10 %, 요청률 ≤ 10 %, 선택 오류 ≤ 5 %)을 동시에 만족하는 가장 낮은 τ 를 고른다. 없으면 가장 가까운 점과 미달을 기록한다.

  저신뢰 제안을 버려 모호성 보호를 없애는 방식으로 맞추지 않는다. τ 아래 제안도 `unconfirmed` 후보로 남는다(Codex: 반경 안 저신뢰 가짜 → `reobserve` 를 놓침·추가·위험 어디에도 안 세던 반례).
- 시험(CPU, onnxruntime-cpu 가 없으면 건너뜀 표시): 가짜 ONNX 출력으로 마스크 크기·점수·출처·상한 8, 예외 → 기하 대체.
- **ONNX 동등성(필수, ws1 학습 venv):** 고정 RGB 몇 장에서 학습 체크포인트(PyTorch)와 내보낸 ONNX 를 비교한다 — 인스턴스 수 같음, 점수 차 ≤ 1e-3, 원본 좌표로 되돌린 마스크 IoU ≥ 0.99.

## 작업 6 — 평가

1. **정지 dev**(`isaac_team_frame_640`, `isaac_clean`): `learned-proposals`·`learned-fit`·`geometric-fit`·`oracle-fit` 를 작업 1 지표로 나란히 둔다. 사례·형상·거리별로 낸다.
2. **Isaac 미션:** `run_transport --recognition far --recognition-proposals learned`.
   - 원거리 관측의 제안을 정답 분할 대신 학습 제안기로 받는다(의미 분할은 평가 기록에만 남긴다).
   - 판정 J1·J2 는 통합 시험(`docs/validation/2026-10-19-isaac-recognition-far-capture.md`)과 같다. seed 0–2 와 대조 `off`.
   - 학습 모델의 1 회 시간을 기록한다(설계 §6 예산: 5 Hz·200 ms).
   - **평가 전용 정답 대응(3판, 4판 정정):** **지연 추정**은 제안 id(`i0`)에 기대지 않는다. 평가 기록에만 남긴 의미 분할에서 정답 인스턴스 0 과 IoU 가 가장 큰 제안의 후보를 쓴다. 인식은 이 대응을 읽지 않는다.
   - **J1 은 계획에 실제로 넘어간 관측(`used`)을 채점한다** — 대응된 단일 후보로 채점하면 융합 관측의 오류를 숨긴다(Codex 3판: 단일 0 mm·융합 50 mm). 시험: 단일 후보는 정확하고 융합 관측만 틀린 경우 J1 이 실패한다. 시험: 같은 판독의 제안 id·순서를 바꿔도 지연 판정이 같다(Codex: 이름만 `learned_0` 으로 바꾸자 11 스텝·채택 → `None`).
   - **재계산 자료:** 프레임마다 RGB 를 저장하고, 실행 기록에 모델 해시·τ·전후처리 설정을 남긴다. 재계산 도구가 learned 경로를 다시 돌린다(onnxruntime 이 있는 곳).
3. 기록: `docs/validation/2026-10-2x-recognition-stage3-learned-proposals.md`.

## 위험

- **Sim2Real:** 상자 조합 팔레트와 단순 재질로 학습한 모델은 실물로 옮겨지지 않을 수 있다. 실사 평가(MR6D, 팀 촬영)는 다음 단계다.
- **색 지름길:** 무작위화를 해도 상자 모양 자체가 지름길이 될 수 있다(방해물도 상자). dev 의 N·S6 오검출로 본다.
- **AGPL:** 회사 전달·배포 때 다시 정한다(§13).
- **실측 환경(agy 1판 검토):** 랩 필름·검은 플라스틱(IR 흡수)·햇빛·화물 돌출·차체 기울기·바닥 경사는 렌더에 없다. 기하 대체의 바닥 띠·깊이 불연속은 이것들에 약하다.
- **배경 범위(Codex):** 렌더 장면의 배경은 상자 방해물·바닥·벽(카메라에서 ≥ 5.25 m)이다. 공장 실제 잡동사니·근거리 벽·팔레트에 붙은 짐은 작업 6 의 Isaac 미션(공장 배치)에서만 본다.
- **잡음판의 경계 혼합 화소:** 모형으로 넣은 현상이다. 실측으로 검증된 것이 아니다.
