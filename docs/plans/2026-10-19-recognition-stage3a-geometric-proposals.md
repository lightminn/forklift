# 팔레트 인식 단계 3a — 기하 제안기 (실제 깊이에서 인스턴스 마스크)

> **실행 방식:** 이 세션에서 직접 구현, Codex 검토를 수렴까지 받고 진행한다.

**Goal:** 지금까지의 인식·추적 결과는 모두 **정답 인스턴스 마스크**(`oracle`)를 제안으로 썼다. 단계 3a 는 깊이 영상만으로 물체별 마스크를 내는 **기하 제안기**(설계 §4 의 "높이 무관 수직면 분할 + 연결 성분")를 만든다. 그리고 같은 정지 장면에서 정답 마스크와 비교해 분할 품질을 잰다.

사용자 지시(2026-10-19): "첫번째꺼 시작해" — 실제 제안 생성기, 기하형부터.

**Spec:** 설계 `docs/design/2026-10-15-pallet-recognition-generality.md`.
- §4 제안 인터페이스: `instance_proposals.py`, 출처 `geometric`.
- §7.5 식별: 기하 제안만으로 나온 후보는 `unconfirmed` — 학습 제안기의 점수나 근거리 재관측·콘솔 확인 전에는 자동 선택되지 않는다.
- §10 학습 제안기가 실패하면 기하 제안기로 넘어간다.

## 범위와 한계 (먼저 밝힘)

- **기하 제안만으로는 미션이 자동으로 대상을 고르지 못한다**(설계 §7.5). 식별을 정하는 것은 단계 3b 의 학습 제안기다.
- 3a 가 보이는 것은 두 가지다.
  - **분할 품질:** 정답 인스턴스를 몇 개 찾았고, 경계가 얼마나 맞고, 방해물·음성 구조물을 몇 개 제안했는가.
  - **분할이 맞춤에 주는 영향:** 같은 장면에서 기하 마스크로 맞춘 포켓이 정답 마스크로 맞춘 것보다 얼마나 나빠지는가.
- 두 번째는 식별을 확정으로 **가정한 진단 실행**으로만 잰다(`geometric-fit-assumed`). 이것은 학습 제안기가 완벽할 때의 상한이지, 미션 결과가 아니다.
- 3b(학습 제안기, YOLO 인스턴스 분할 — 2026-10-15 사용자 결정)는 별도 계획이다. ws1 에 학습용 패키지(ultralytics·onnxruntime)를 **별도 venv** 로 설치해야 하므로 그 단계 시작 때 사용자 확인을 받는다.

## 알고리즘 (1판 — dev 로 매개변수를 정한다)

입력은 `SceneInput`(축 깊이, 내부 파라미터, base←optical)이다. 다른 입력은 쓰지 않는다 — RGB·정답·사례 이름을 쓰지 않는다.

1. **점 복원:** 유효 깊이 화소를 base 좌표로 복원한다(`instance_fit.pixel_rays`·`camera_xyz` 재사용). 거리 상한 `range_max_m = 4.5`(보정표가 4 m 까지, 여유 0.5 m).
2. **바닥 제거:** base 의 z 가 바닥 띠 `z ≤ floor_band(r) = a + b·r²` 안인 점을 지운다. r 은 카메라 수평 거리이고, 깊이 잡음이 거리의 제곱으로 커지는 것을 따른다.
   - 바닥이 z = 0 인 것은 base_link 정의다(장면 생성과 실행기 모두). 경사·요철은 범위 밖으로 기록한다.
   - a·b 는 dev 에서 정한다.
3. **연결 성분:** 남은 화소를 영상 격자에서 8-이웃으로 잇는다. 이웃 깊이 차가 `τ_d(r) = c + d·r`(상대 깊이 불연속) 이하일 때만 잇는다 — 앞뒤로 놓인 물체가 갈린다.
4. **수직면 분할(높이 무관):** 성분마다 `instance_fit.fit_faces`(맞춤 단계와 같은 수직면 RANSAC)로 수직면을 찾는다.
   - **수직면이 없는 성분은 제안하지 않는다** — 바닥 잔여·천장·매달린 물체.
   - 한 성분에 수직면이 둘 이상이면(모서리가 보이는 팔레트) 하나의 제안으로 둔다. 두 면 사이 가로 간격이 팔레트 최대 폭(1.4 m)보다 넓으면 갈라 둘로 낸다.
5. **크기 거름:** 성분의 수평 폭이 `[0.25, 2.0] m` 밖이면 버린다. 높이 범위 상한은 두지 않는다(높이 무관 — 적층 팔레트는 한 마스크로 나와 맞춤 단계의 분할 가설이 가른다, 설계 §7.4).
6. **점수:** `score = min(1, 화소 수 / 기준 화소 수)` — 기하 제안의 점수는 식별에 쓰이지 않는다(§7.5). 진단 기록용이다.
7. **출력:** `InstanceProposal(f"g{k}", mask, score, "geometric")`. 순서는 성분의 왼쪽 위 화소 순(결정적).

매개변수(a, b, c, d, 최소 화소 수, 폭 범위)는 `GeometricParams` 로 두고, dev 결과로 한 번 정한 값을 기록한다.

## 평가

`tools/evaluate_recognition.py` 에 검출기 셋을 더한다. 장면 판정(`judge_scene`)은 지금 그대로다.

| 검출기 | 제안 | 식별 | 뜻 |
|---|---|---|---|
| `geometric-fit` | 기하 | 설계대로(`unconfirmed`) | 실제 동작 — 자동 선택 없음이 정상 |
| `geometric-fit-assumed` | 기하 | 모두 `confirmed` 로 가정 | 진단: 완벽한 식별기가 있을 때의 상한 |
| `geometric-proposals` | 기하 | — | 분할만: 아래 분할 지표 |

**분할 지표**(장면 단위·인스턴스 단위, 사례·형상별):
- **인스턴스 재현율:** 정답 인스턴스(진입면 노출 ≥ 50 %) 중 IoU ≥ 0.5 인 제안이 있는 비율. 거리 구간별로도 낸다.
- **IoU 분포:** 대응된 제안의 IoU p50·p5.
- **합침·쪼갬:** 한 제안이 정답 둘 이상에 각각 IoU ≥ 0.2 로 걸치면 합침, 한 정답에 IoU ≥ 0.2 인 제안이 둘 이상이면 쪼갬.
- **추가 제안:** 정답과 IoU < 0.2 인 제안 수. 방해물(−2) 위 제안과 배경 위 제안을 나눠 센다.
- **음성 장면(N):** 제안이 하나라도 나온 장면 비율과 장면당 제안 수.
- 처리 시간 p50·p95.

**비교 기준:** `oracle-fit`(같은 데이터·같은 맞춤). 2A 의 지표를 같은 표에 둔다.

**합격선:** 3a 는 설계 §3.4 의 합격 판정이 아니다(식별이 없으므로 자동 선택 지표를 채울 수 없다). 개발 목표만 미리 고정한다. 결과를 보고 고치지 않는다.

| 지표 | 개발 목표 |
|---|---|
| 알려진 형상의 인스턴스 재현율(dev, team_frame_640, 2.5 m 안) | ≥ 95 % |
| 대응 IoU p50 | ≥ 0.8 |
| `geometric-fit-assumed` 의 놓침 | `oracle-fit` 대비 +5 %p 이내 |
| `geometric-fit-assumed` 의 위험 오위치 | `oracle-fit` 대비 +5 %p 이내 |

미달이면 원인(바닥 띠·불연속·면 거름)을 기록하고 3b 와 함께 다룬다. 추가 제안·음성 제안은 목표 없이 **기록**한다 — 그것을 가르는 것은 3b 의 식별이다.

## 작업

1. `src/forklift_core/perception/geometric_proposals.py`(`GeometricParams`, `propose(scene, params)`). 시험(먼저 실패 확인):
   - CPU 리그 렌더(`tools.instance_rig`)에서 팔레트 하나 → 제안 하나, 정답 IoU ≥ 0.9.
   - 앞뒤 두 팔레트(삽입축 간격 0.65 m) → 둘로 갈림.
   - 나란한 두 팔레트(가로 간격 0.1 m) → 둘로 갈림.
   - 적층 두 팔레트 → 한 제안(높이 무관).
   - 바닥만 → 제안 없음.
   - 수직면 없는 물체(얇은 판 바닥 위) → 제안 없음.
   - 너무 작은·넓은 성분 거름.
   - 입력 순서 무관·결정적.
2. `tools/evaluate_recognition.py`: 검출기 `geometric-fit`, `geometric-fit-assumed`, `geometric-proposals` 와 분할 지표(`evaluation_multi` 에 함수 추가). 시험: 정답 마스크를 제안으로 주면 재현율 1·IoU 1·추가 0, 합침·쪼갬 판정.
3. dev 실행(ws1 Slurm, CPU) → 매개변수 한 번 정함 → 결과 기록 `docs/validation/2026-10-19-recognition-stage3a-geometric-proposals.md`.

## 위험

- **바닥이 평면·z = 0 이라는 가정:** 실제 창고 바닥의 경사·요철·반사는 바닥 띠를 넘길 수 있다. 실측 D435i 데이터로 확인할 일로 남긴다.
- **맞닿은 물체:** 팔레트에 붙은 상자·랙 다리는 같은 성분이 된다. 맞춤 단계의 증거 소유권(§7.2)이 가르지만, IoU 는 떨어진다.
- **원거리:** 3 m 밖에서는 깊이 잡음이 커서 불연속 기준과 바닥 띠가 같이 넓어지고, 분할이 나빠질 수 있다 — 거리 구간별로 본다.
- **Isaac 렌더의 깊이:** 실측 잡음 판을 입혔지만 날림 화소(flying pixel)·다중 경로는 렌더에 없다.
