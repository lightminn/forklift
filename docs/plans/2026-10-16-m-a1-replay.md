# M-a1 마지막 판정: 계측 기준 기록과 재생 (1판, 2026-10-16)

상위 계획: [M-a 미션 코어](2026-10-15-m-a-mission-core.md) 4절 M-a1 행, 5절 "M-a1 7 조각 설계"·"7.0 감사"·"7.1 재생 입력 상의". 사용자 결정(2026-10-16): 재생 판정까지 진행한다.

## 1. 판정 문구(개정)

M-a1 의 전체 동등성은 **"설정 입력을 보충해 계측한 이동 전 소스(`a8b4f66`)의 기준 기록을, 이동 뒤 코드가 처음부터 끝까지 같은 요청·출력·분기·종료로 재생한다"** 로 판정한다. 동결 기록 4 개(`ma1base_*`)는 지금처럼 접두·회귀 기준으로 남기고, "동결 기록 재생 완료" 라고 쓰지 않는다. 증거의 범위는 D2 와 같다 — 계측된 기준 실행에 대한 동등성이다(계측이 지도 콜백·마감 시점을 흔들지 않는다고 보장하지 못한다).

## 2. 구조

**실행기를 둘로 나눈다(이동 뒤 코드).** `run()` 은 지금 tick -1 전(약 1,530 줄, 3113 행까지)에 Isaac 호출과 순수 계산을 섞어 세계를 만든다. 이를 

- `setup(args) -> SetupResult` — Isaac 의존(장면·자산·관절·카메라·정착·서비스 생성)과 그 결과 값,
- `drive(setup, ports) -> result` — tick -1 의 초기 계획부터 끝까지, Isaac 을 import 하지 않는 CPU 실행부(`sim/isaac/transport_driver.py`),

로 나눈다. `drive` 가 Isaac 에 닿는 곳은 모두 포트(기록되는 프록시)나 어댑터(Sink: USD 프림·영상·오버레이)를 거친다. Isaac 실행에서는 `setup` 이 실제 객체를, 재생에서는 하네스가 스냅숏과 재생 포트를 넘긴다.

**`drive` 에 넘어가는 설정 결과(이동 뒤 코드에서 tick -1 시점에 살아 있는 이름, AST 분석 102 개)의 분류:**

| 분류 | 예 | 재생에서 |
|---|---|---|
| 모듈·클래스·함수 import | `Rectangle`, `CUSP_STALL`, `bicycle_rollout`, `site_poses` | 다시 import |
| 설정 파일·인자에서 계산 | `args`, `settings`, `scenario`, `geometry`, `planner_config`, `travel_config`, `pickup_bounds`, `pickup_zone`, `return_to_pose`, `truth_destination`, `mission_stages`, `unloaded_shape`, `PALLET_BOXES`, `dwells`, `safety_stops`, `dwell_d_end_m`, `max_cusp_replans`, `cusp_stop_*`, `grid_planning`, `insertion_geometry`, `estop`, `new_obstacles`(일정 파일) | 스냅숏의 입력(인자·파일 내용 해시)으로 **다시 계산**하고, 스냅숏의 값과 같은지 확인 |
| Isaac 에서 온 값 | `wheels`·`steers`·`lift_index`(DOF 이름 순서), `initial_pallet`, 자산 오프셋, `perception_mount`·`perception_calibration`, `factory` 배치, 라이다 장착·빔 각 | 스냅숏의 값을 그대로 씀(원래 읽은 값을 복사) |
| 살아 있는 서비스 | `robot`, `world`, `pallet`, `stage`, 카메라, `perception_capture`, `obstacle["layer"]`, SLAM 추적기·링크, 근접 추적기 | 재생 포트(기록 응답) |
| 공유 컨테이너의 초기 상태 | `state`, `obstacle`, `near`, `pocket` 의 설정 단계 키 | 스냅숏의 값으로 만들고, 서비스 자리는 재생 포트로 채움; 별칭 관계(같은 리스트를 두 곳이 가리킴)를 논리 ID 로 복원 |
| 설정 단계 클로저 | `grid_kwargs`, `grid_world`, `correction_grid`, `read_pocket_frame`, `build_pocket_check`, `near_tracker_*` … | `drive` 안에서 같은 입력으로 다시 만든다 |
| Sink | `overlay`, `inset`, `inset_font`, `extra_cameras`, `camera`, `recorder`, `boundary` | 재생에서는 기록하지 않는 어댑터 |

**적용 시점(Codex 7.1 P2-1).** tick -1 은 초기 계획만 덮는다. 그 뒤 루프 전까지 실행기는 SLAM 링크·추종기·시계 원점(`initial_time = world.current_time`)·배송 기준 스캔(`robot.get_world_pose()` 와 광선 투사)을 만든다. 이 구간의 Isaac 읽기는 지금 기록되지 않는다(프록시는 루프 직전 설치). 계측은 프록시를 **tick -1 직전**에 설치하고 tick -1 을 루프 직전까지 늘려(또는 이 구간을 tick -2 "bootstrap" 으로 따로 열어) 그 읽기를 기록한다. 스냅숏은 **계획 전 입력**만 담고, 초기 계획·후보 변경·추종기 구성·`initial_time` 이후의 값은 재생이 다시 계산하거나 기록된 응답에서 얻는다 — 기준 실행의 `paths`·`trackers` 를 정답으로 주입하지 않는다.

## 3. 계측 패치

같은 계측을 두 소스에 넣는다: `a8b4f66`(기준 기록용, 별도 브랜치 `rec/a8b4f66-replay`)과 이동 뒤 코드(하네스 자기 검증용). 기록 전용이며 동작을 바꾸지 않는다.

1. **설정 스냅숏**: tick -1 직전에 2 절 표의 "다시 계산"·"Isaac 값"·"컨테이너 초기 상태" 를 버전 있는 값 DTO(`forklift_setup_snapshot/1`, JSON + 배열 파일)로 쓴다. pickle 은 쓰지 않는다. 읽은 지역 변수만 복사하고 추가 조회·step·상태 변경을 하지 않는다.
2. **프록시 설치 시점**: 2 절 "적용 시점" 대로 앞당긴다. 프록시는 호출을 그대로 통과시키므로 동작은 같다(M-a0 에서 루프 구간에 대해 확인한 성질).
3. **계획 메모리(Codex 7.1 P2-2)**: `Obstacles.memory` 가 돌려주는 `PlanningMemory` 를 `RecordingProxy("Memory")` 로 감싸 그 메서드 호출(`retract_endpoints` 등)과 응답을 기록한다. 비필드 상태(`_pending`)는 직렬화하지 않는다 — 그 상태에 기대는 결과는 이 호출 기록으로 공급된다.
4. **이동 전 재작도 콜백(Codex 7.1 P2-3, `a8b4f66` 쪽만)**: `near_capture_redraw` 의 `redraw_docking` 이 끝난 뒤, 콜백이 채운 `rollouts_` 의 번호·`config_`·`start_`·결과를 Trace 항목(`recorder.call("Trace", "redraw_rollouts", …)`)으로 복사한다. 다시 rollout 하지 않는다. S4b `near_redraw` 의 콜백은 부수 효과가 없어 계측하지 않는다.

**무해성 확인**: (a) 패치 diff 가 기록 경로 밖 문장을 바꾸지 않음(AST 대조), (b) 결정적 대역 포트로 원본/계측본을 같은 입력에 돌려 비기록 호출·결과가 같음, (c) Isaac 에서 계측본 기록 켬/끔 비교(M-a0 정규화 규칙, 다른 행은 원인 기록).

## 4. 재생 하네스(`tools/boundary_replay.py`)

- **복원 층**: `read_record` 위에 타입 복원(dataclass 이름 → 클래스 등록표, 튜플·키 복원), 예외 재발생(타입·속성), `request_after` 를 호출자 인자에 적용, `watched` 의 append/delete/값을 대상 사전에 적용(예외 때도).
- **재생 포트**: 호출마다 기록의 다음 항목과 `port`·`method`·요청을 대조(인코딩 동일; opaque 자리는 타입만; 벽시계 응답은 기록값을 그대로 돌려준다)하고 응답을 돌려준다. 건너뛰기 없음 — 순서가 어긋나면 그 자리에서 실패. 통째로 기록된 서비스(`Vehicle.step`, `Capture.capture`, `Frames.read_pocket_frame`)는 응답과 변경분만 복원한다.
- **이동 전/뒤 호환 어댑터**: 기준 기록의 `Planner.redraw_docking` + `Trace.redraw_rollouts` 쌍은 이동 뒤 코드의 `Planner.redraw_docking_traced` 한 호출에 대응한다. 요청(`start_rear`, 순서 있는 `dry_configs`, 나머지 Planner 인자)을 대조하고 응답 `(plans, record, 궤적들)` 을 Trace 에서 만든다. 이 대응 하나만 명시적으로 허용한다.
- **판정**: 틱마다 호출 순서·요청, `tick_end` 출력, 분기 목록, 종료(성공·실패 사유·종료 틱)가 같고, 기록의 미소비 호출이 0.

## 6. 열린 문제

- 원본→원본 재생(Codex 권고 순서 4)을 `a8b4f66` 코드로 하려면 그 코드도 `drive` 로 나눠야 한다 — 기록 전용 패치의 범위를 넘는다. 1판은 R4 의 하네스 자기 검증을 **이동 뒤 코드 → 자기 기록**으로 하고, 기록 충족성(무엇이 빠졌나)은 그 단계에서 드러난다고 본다. 이 대체가 충분한지 검토 요청.
- `new_obstacles` 일정은 기록된 포트가 없다 — 재생은 같은 일정 파일로 Schedule 을 다시 돌린다(일정의 입력 `driven`·`leg` 는 재생에서 같게 나와야 함).
- D2 필수 분기 목록에서 4 구성이 덮지 못하는 분기의 목록과 그것을 내는 구성.
