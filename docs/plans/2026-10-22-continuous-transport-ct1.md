# 연속 이송 CT-1 — 한 세션에 여러 팔레트 (4판)

브랜치 `feat/continuous-transport`(origin/main `ec4bece`). 8주차 1차 목표 — 일자(③)·랜덤(④) 배치 연속 이송을 인식·SLAM 포함 완주 — 의 첫 단계. 사용자 결정(2026-10-22, 총괄 세션 경유): 착수, 단계별 PR, 콘솔 대기열(PR #90)을 그릇으로, 다리 끝 크리프·교착은 다른 세션, 열린 하역 정밀도는 다른 세션(인터페이스만 맞춤), 속도 최적화 범위 밖.

단계: **CT-1**(이 계획, PR 네 개) → **CT-2** 다음 팔레트 순서·하역 칸 배정 규칙과 그 위치(콘솔 JS 해석기 대 차량 추천 계약) → **CT-3** 완주율 개선.

## 1. 사실

조사 두 건(우리 러너의 단일 팔레트 가정 지도, 팀원 브랜치 `feat/fleet-five` 재사용 검토), 소스 확인, Codex·agy 검토, UBAI CPU 스윕.

### 지금의 단일 팔레트 구조

- **Isaac.** 강체 팔레트는 하나다(`scene.py` `create_pallet`, 강체 1 개 단언 432행). 장면의 이웃은 정적 복사본이라 들 수 없다(`add_scene_pallets` 257–281행). 충돌 계수(546–548·636–637행)와 LiDAR 자기 필터(`run_transport.py` 5660·5905행)는 `/World/Pallet` 만 본다.
- **truth 읽기.** `pallet` 손잡이 하나가 truth 읽기를 모두 맡는다: 정착, 매 tick 자세·기울기, 외곽 충돌, 떨어짐·밀림, 금지 접촉, 삽입 측정, 인식 평가, 하역 판정, 원거리 인식 truth(인스턴스 0 고정 — `far_recognition_runtime.py` 252행), 리플레이 포트 "SimTruth".
  - 루프는 tick 앞에 `ppos`·`pq` 를 한 번 읽어 그 tick 끝까지 쓴다(6997행). 준비 결과 채택(7313행)은 그 뒤에 온다.
- **장면 파일 v1.** 미션 하나만 담는다. 장면 도구는 k 번째 미션마다 장면을 따로 만든다(`_sequence_scene` 177–199행).
  - 일자: 적재 3·하역 3, 하역 칸 간격 1.062 m(진입 축 방향).
  - 랜덤: 적재 5(기울기 −8/10/−6°)·하역 3, 하역 칸 간격 1.287 m(옆 방향).
- **targets.** P-1·D-1, live 만 D-0 이 있다.
- **live 준비**(`live_prepare` 6767–6795).
  - 관측 후보: 첫 팔레트 후보를 옮긴 것.
  - 장면: 소품 고정.
  - `pickup_bounds`: 첫 자리에서만 준다.
  - truth 목적지: {D-1, D-0} 만.
  - 준비 가능 판정 `prepare_start_ok`(6700–6763)는 세션 장면과 그 미션 팔레트 하나로 판정한다.
- **계획 장애물**(`--layout scene`).
  - 관측 다리: 장면 소품 + 픽업 구역/추정.
  - 운반: 소품.
  - 복귀: 소품 + 하역 사각형.
  - 운반·복귀 계획기는 `options.scenario.props` 를 읽는다(`pallet_mission.leg_obstacles` 957–995). 그래서 다른 팔레트는 관측 격자가 아니라 장면 소품 자체에 들어가야 한다(agy ③).
- **사전 팔레트 장애물 크기.** 러너는 픽업 구역(중심 ±0.25 m)을 팔레트 반대각선 0.5 m 만큼 키운다 → 1.5 m 정사각형(3448–3459행). `preparation_obstacle` 은 사전 팔레트에 그것을 돌려준다.
- **live 와 인식.** live 는 원거리 인식(`--recognition far`)과 밑판 검사를 거부한다(1100·917행).
  - 원거리 인식의 정지 캡처 보호는 `.capture()` 를 감싸지만 live 캡처는 `.session()` 이다(3155행, core 3680행).
  - 밑판 거절은 루프를 끊어 세션을 끝낸다(7381행).
  - 원거리 구역 `set_zone` 은 중심·반경만 바꾸고 트랙을 비우지 않는다(`far_recognition_runtime.py` 220행).
  - `MissionBaseline` 에 `recognition`·`bottom_deck` 이 없다(`baseline.py` 22행).
- **콘솔 탐침 cycle.** STOPPED 에서 자동으로 재무장·재개하고 실패해도 다음 항목으로 간다(`live_console_probe.py` 971·1020행). 실제 대기열(PR #90)은 실패·복구 필요·취소에서 멈춘다(`console/web/js/queue.js` 319행).

## 2. 결정 필요 (사용자)

**D1. 아직 인식하지 않은 이웃 팔레트를 계획 장애물로 둘 크기:**
- **(가) 공칭 외곽 + 0.25 m.** 시험한 값 가운데 6 장면이 모두 계획되는 최대값이다(경로 존재 근거이지 안전 여유 검증이 아니다; 0.25–0.30 사이는 재지 않았다).
  - 지금 장면의 오차로 회전된 외곽을 계산하면 +0.25 m 안쪽 잔여 폭은 최소 약 0.124 m 다(random_1, 오차 (0.06, −0.08) = 평면 0.10 m — Codex 2차).
  - 픽업 구역이 허용하는 truth 범위 전체(중심 ±0.25 m·yaw ±12°)를 감싸려면 축별 약 0.33·0.30 m 가 필요하다. 그래서 +0.25 m 는 구역이 허용하는 모든 배치를 덮지 못한다.
  - PR ② 의 truth 외곽 대조 검사가 실제 여유를 잰다.
- **(나) 공칭 외곽 + 0.30 m.** 팀원 관례와 같다. line_1 의 추출이 막혀 일자 첫 미션이 안 된다.
- **(다) 구역 전체.** 일자 1·2 추출이 막힌다.

**결정(사용자, 2026-10-22): (가).** 조건:
- 근거는 안전 여유 검증이 아니라 경로 존재 상한이다. **임시값 — 실차 SLAM 오차를 실측한 뒤 다시 정한다.** 남는 최소 폭 약 0.124 m 는 소규모 장면 미션 전체의 SLAM 최대 오차 0.14–0.16 m 보다 작다.
- PR ② 에 공칭·truth 생성 규칙 확정과 truth 외곽 대조 CPU 검사를 넣는다. Isaac 평가 때 이웃 팔레트와의 실제 최소 거리를 기록한다. 대조 결과가 나쁘면 다시 올린다.
- 팀원 fleet 의 `PALLET_KEEP_M` 0.3 축소 보류는 그대로다. 이 결정은 우리 계획기의 미인식 이웃 장애물 크기에만 적용된다.

D1 은 아직 인식하지 않은 이웃에만 적용된다. 하역된 팔레트는 지금 규칙(추정 외곽 + 불확실도 0.21 m) 그대로이고, 대상 자신의 관측용 구역도 그대로다.

## 3. PR 구성 (Codex 1차 제안 수용)

1. **PR ① 단일 팔레트 live 인식 지원** — live 에서 `--recognition far` 를 허용한다.
   - 캡처 세션(`.session()`)에 원거리 인식의 정지 캡처 보호를 맞춘다.
   - 캡처·추론·계획 중에도 제어 tick 을 유지하고, 캡처 중 STOP·취소를 처리한다.
   - 인식 거절은 미션 실패로 끝내고 세션은 살린다.
   - 미션마다 원거리 인식 상태(트랙·구역·기록)를 초기화하고, 그 소유를 미션 기준선에 넣는다.
   - 원거리 인식 구역: 사전 팔레트는 파일의 원래 구역, 인식·하역된 팔레트는 현재 추정 위치 기준 구역(`pickup_bounds` 도 같은 기준) — P-1:D-1 뒤 P-1:D-0 에서 원래 자리를 찾지 않게(Codex 2차; line_1 원래 중심과 D-1 거리 9.216 m, 인식 반경 0.354 m).
   - 원거리 인식의 무거운 일은 제어 스레드 밖(작업 스레드)에서 돌고, 결과는 (미션, 다리) 꼬리표로 틱에서 적용·폐기한다 — 세부는 `docs/plans/2026-10-22-live-far-recognition.md` 2판 결정 T1(Codex 3차 P1: 동기 추론은 콘솔 대기열의 2 s 무상태 중단과 STOP 처리 계약을 깨뜨린다). 관측 실패 뒤 후보 재계획도 계획 작업자로.
   - 합격 조건: 캡처·추론·계획 중 STOP·취소, 인식 거절 뒤 세션 생존과 새 제출 성공, 늦게 끝난 일이 현재 상태를 바꾸지 않음.
   - 밑판 검사의 live 지원은 범위 밖(지금처럼 거부).
   - 확인: 단일 팔레트 장면 live 로 미션 셋(P-1:D-1 → P-1:D-0 → P-1:D-1), 그리고 캡처 중 STOP·재개, 관측 중 취소 뒤 새 제출, 인식 거절(구역 밖으로 옮긴 팔레트) 뒤 새 제출.
2. **PR ② 세션 장면 형식·공통 팔레트 장애물·CPU 기하 검증.**
   - 장면 파일 v2(세션): 팔레트별 id·truth·공칭·픽업 구역·관측 후보와 하역 칸 목록. 형상은 세션에 하나로, 로더가 섞임을 거부한다. v1 → 세션 변환.
   - 장면 도구 `--session line|random`.
   - 공통 함수 `session_pallet_props(targets, exclude_id, zones, shape, prior_grow_m)` 하나를 준비·`prepare_start_ok`·SLAM 해제 뒤 예상·작업자 입력이 모두 같이 쓴다.
   - teleop 허가(`zones_from`, `run_transport.py` 6404행)와 수동 복구도 팔레트별 `id → 구역` 을 받는다. 계획기용 D1 여유와 teleop 의 자세 오차 여유는 별도 계약으로 둔다(Codex 2차).
   - v2 의 공칭·truth 생성 규칙: 공칭 자리의 yaw 에 도면 기울기를 넣는다(랜덤 −8/10/−6°). truth = 공칭 + 그 팔레트의 오차.
   - truth 외곽 대조: 같은 계획 경로(관측·삽입·추출·운반·복귀의 차체 외곽 스윕)와 이웃 팔레트 truth 외곽의 최소 거리를 계산해 기록한다 — 0 이하면 D1 을 다시 올린다.
     - 사전 팔레트: D1 의 크기.
     - 하역·인식된 팔레트: 추정 외곽 + 불확실도.
     - 지금 운반 중인 팔레트: 넣지 않는다.
   - 관측 후보: 사전 팔레트는 파일의 후보·구역. 인식·하역된 팔레트는 공칭 → 현재 추정으로 옮긴 후보(`relocate_waypoints`, 하역된 팔레트 재이송 대비).
   - CPU 검증: 세션 미션 열(일자 3·랜덤 3)을 계획만으로, 앞 미션의 하역 자리를 장애물로 넣어 각 미션의 관측·삽입·추출·운반·복귀.
3. **PR ③ 다중 강체 팔레트·원자적 미션 전환·상태 수명.** 독립 합격 시험: 서로 다른 자세의 두 팔레트로 채택 tick 의 모든 truth 소비자가 같은 id 를 보는지, 준비 실패·취소에서 이전 id 가 유지되는지, 종료 뒤 cargo·복구가 남을 때 유지되는지(Codex 2차 P3).
   - 모든 팔레트를 강체로 둔다(`create_pallet` 에 경로·이름 인자, pallet.usd 한 번 가져오기, 물리 재질·충돌 계수는 모든 팔레트 경로, LiDAR 자기 필터는 실제로 싣고 있는 팔레트만).
   - 준비 결과를 채택하면 그 다음 tick 의 머리(truth 표본을 읽기 전)에 지금 팔레트 손잡이·truth 표본·원거리 인식 truth 인스턴스·truth 장애물 목록을 한꺼번에 바꾼다. 기준 자세·truth 목적지·하역 고리는 채택 때 새 팔레트를 직접 읽어 정한다. 세부는 `docs/plans/2026-10-22-rigid-session-pallets.md` 2.3.
     - 준비 실패·취소면 바꾸지 않는다.
     - 종료 뒤 cargo·복구가 남으면 그 팔레트를 계속 가리킨다.
   - 지금 팔레트가 아닌 팔레트의 밀림 감시: 쉬는 자세를 세션 시작과 그 팔레트가 지금 팔레트에서 나가는 전환 순간에 확정한다. 1 cm·0.01 rad 를 넘으면 장면 손상 → 그 미션 종료·이후 제출 거부.
   - 인식 평가는 `perception_error_actual`(truth 대비)로.
4. **PR ④ 실제 대기열로 연속 실행 검증.**
   - 탐침에 "이상 시 멈춤" 모드(대기열과 같은 정책 — 실패·복구 필요·취소·끊김에서 다음 제출 없음)를 더하거나 콘솔 대기열 자체를 쓴다.
   - ws1 장면 live sbatch.
   - Isaac 일자 3·랜덤 3(5 개 중), 인식·SLAM 포함: 미션별 결과·하역 오차·밀림 0·금지 접촉 0, 첫 이상 뒤 다음 제출 없음.

## 4. 공통 조건

- 새 러너 인자는 근접 추적 계약(`POST_MEASUREMENT_ARGUMENTS`)에 등록한다.

## 5. 위험

- 다른 강체 팔레트가 시야·근처에 늘어난다. 근접 캡처의 예상 위치 선택은 원거리 선택의 연속성일 뿐 P-k 식별이 아니다(core 3880행).
- 원거리 구역은 장애물 사각형이 아니라 사전 팔레트면 그 원래 배치 구역, 인식·하역된 팔레트면 추정 위치 기준 구역이다. 이웃과 섞이는지는 PR ④ 의 Isaac 에서 본다.
- 한 세션에서 주행이 3–5 배 길다. SLAM 오차 누적은 기록하고 CT-3 에서 본다(agy ③).
- 강체 팔레트가 늘면 물리 비용이 는다(랜덤 5). 실시간 배율만 기록한다.
- 하역 뒤 포크를 뺄 때 그 팔레트는 아직 지금 팔레트라 밀림 감시 대상이 아니다. 쉬는 자세는 그 팔레트가 지금 팔레트에서 나가는 전환 순간에 확정한다(PR ③ 계획 2.4).
