# 끔 경로 이어 재생 — 면제가 작용한 실행의 뒤 단계 실패 (2026-10-31, 설계 1 판 → 구현하지 않음)

지시: 총괄(2026-10-31). 다음 riib 배치 등록의 규칙 6 에서 "면제가 작용한 실행의 뒤 단계 실패"를 끔 재생 대조로 가린다. 예로 든 방법은 "면제가 닫힌 뒤 단계부터 끔 경로로 이어 재생"이다. 재생 도구만 바뀌고 러너는 그대로여야 한다.
앞선 것:
- `docs/validation/2026-10-31-riib-exit-prefix-default-batch.md`: 규칙 6 미입증. B 에만 나온 return_home·settle 실패는 latch 가 작용한 실행의 뒤 단계에서 났고, 끔 경로 재생은 latch 자리에서 어긋나 근거가 되지 못했다.
- `tools/boundary_replay.py --off exit_prefix_exempt`: PR #229.

## 결정(총괄 2026-10-31, 검토 뒤)

- **이어 재생은 구현하지 않는다.** 1 판 검토(Codex P2 3·P3 1, agy)의 결론은 두 가지다. 이어 재생은 on 경로 재생과 사실상 같아서 "닫힌 latch 가 결정에 손대지 않는다"까지만 보인다. 그리고 그 성질은 단위 시험으로 고정할 수 있다.
- 닫힌 latch 의 무해성은 `tests/unit/mission/test_core_exit_prefix_exempt.py` 의 두 시험으로 고정했다.
  - 닫힌 뒤의 틱은 latch 가 없는 core 와 같은 결정·같은 층 호출을 낸다.
  - 닫히는 틱과 그 뒤 처음 설 때까지의 settling 은 면제 쪽에 귀속된다. Codex 가 짚은 "닫힘과 실패가 같은 틱" 구멍은 이 기준으로 막는다.
- 규칙 6 은 (가)+(나) 로 다음 배치 등록에 넣는다.
  - (가) 미션 단위 판정: seed 짝의 두 방향 불일치("A 완주·B 실패", "B 완주·A 실패")를 결과 전에 정한 단측 부호 검정으로 판정한다. 면제가 작용한 B 실행의 뒤 단계 실패는 후속 결함 목록으로 따로 올린다.
  - (나) 반복 대조: 대상 장면에서 "A 완주·B 실패"가 난 seed 만 두 팔을 각 4 회 더 돌린다. "B 실패 ≥ 3/4 이고 A 완주 ≥ 3/4"면 면제 탓으로 불합격이다. 추가 실행 수 상한은 등록에서 정한다.
- 아래 1–4 절은 1 판 내용을 그대로 두고(검토 기록), 5 절에 검토를 적는다.

## 1. 무엇을 보일 수 있고 무엇은 못 보이는가

- 재생은 기록된 센서·시뮬 입력과 포트 응답을 돌려주고, 미션 코드의 결정만 다시 계산한다. 물리 step 은 돌리지 않는다.
- 그러므로 재생으로 보일 수 있는 것은 하나다. **"latch 가 닫힌 뒤, 같은 입력에서 면제 코드가 꺼져 있어도 결정이 같다"**, 곧 닫힌 뒤의 결정이 면제 코드에 의존하지 않는다는 것이다.
- 보일 수 없는 것도 하나다. **면제가 만든 차량 상태가 뒤 단계 실패를 불렀는가.** 면제가 차를 칸 밖으로 꺼내 위치·자세·SLAM 상태가 달라졌고, 끈 팔이었다면 그 상태에 이르지 못했다. 이것은 반사실 물리라 재생으로는 답할 수 없다.
- 따라서 규칙 6 의 무관 판정은 두 부분으로 나눈다(§3).
  - 코드 무관: 이어 재생으로 보인다.
  - 상태 노출: 면제 없는 실행에서의 같은 단계 실패율과 비교한다.

## 2. 이어 재생(`--off-after exit_prefix_exempt`)

- 동작:
  - 기록을 on 경로 그대로 재생한다(지금의 재생과 같다).
  - 면제 latch 가 닫힌 틱에서 전환한다. 닫힌 틱은 기록 분기 `state.exit_prefix_exempt[...]` 가 처음 나타난 틱이고, 그 틱의 대조가 끝난 뒤가 전환 시점이다.
  - 전환 뒤에는 재생 쪽 러너 인자를 `exit_prefix_exempt=off` 로 바꾸고, `--off` 와 같은 장부 제외(분기 `state.exit_prefix_exempt[`, 종단 키 `state.exit_prefix_exempt`)를 켠다.
- 전환 뒤에도 그대로 남는 것:
  - core 의 `_exit_latch`(상태 `closed`)는 그대로 둔다. 닫힌 latch 는 `exit_exempt_boundary` 에서 바로 반환하고, `exit_exempt_open()` 은 거짓, `exit_exempt_tick_end` 는 아무것도 하지 않는다.
  - `exit_exempt_counts` 는 평가 귀속에만 쓰이고, 그 결과(`exempt_*`)는 종단 투영에서 이미 빠져 있다.
  - 이것을 시험으로 고정한다. "닫힌 latch 를 가진 core 와 latch 가 없는 core 가 같은 입력에서 같은 결정을 낸다."
- 러너 인자를 읽는 곳은 매 틱 읽기다(`run_transport.py` 의 `exit_on_`, `add_scans` 키워드, 종단 결과 키). 전환 뒤 읽기는 끔 값을 본다. core 의 `options.exit_prefix_exempt` 는 꺼내기 → 운반 전환에서만 읽힌다(대기 latch 생성). riib 단일 미션에서는 전환 뒤 다시 읽히지 않는다. 연속 이송(미션 여럿)에서 두 번째 꺼내기가 오면, 재생은 그 전환 틱에서 "이어 재생 범위 밖"으로 멈추고 실패로 센다.
- 통과: 기록 끝까지 `REPLAY_EXIT 0`(모든 틱·같은 끝·종단 일치, 장부 제외만). 면제가 열리지 않은 실행(`no_prefix` 또는 latch 기록 없음)은 지금의 `--off` 를 처음부터 쓴다.
- 구현 범위: `tools/boundary_replay.py`(옵션, 전환 틱 감지, 인자 교체)와 `ReplaySession`(전환 뒤부터 장부 제외)만 바꾼다. 러너·core 는 바꾸지 않는다.

## 3. 규칙 6 판정안(등록에 넣을 문구 후보)

B 에만 나온 실패 유형의 실행마다:
- (i) 코드 무관: 그 실행의 경계 기록이 `--off-after exit_prefix_exempt` 로 `REPLAY_EXIT 0` 이다. latch 가 열리지 않은 실행은 `--off` 로 본다. 기록이 없거나 재생이 어긋나면 불합격이다. 그래서 다음 배치는 B 대상 실행 전부에 경계 기록을 붙인다(디스크 예산에 반영).
- (ii) 상태 노출: 그 실패 유형이 면제 없는 실행에서도 같은 단계에 이른 실행 가운데 나온다. 비교 대상은 이번 배치 A 팔과, 등록에 이름을 적어 둔 이전 배치의 A 팔이다(결과 전 고정). 그리고 B 에서 그 단계에 이른 실행 중 그 유형의 비율이, 참조 실행에서 같은 단계에 이른 실행 중 비율의 상한을 넘지 않는다. 상한은 등록에서 정한다(예: 참조 비율의 단측 95 % 상한).
- (i)·(ii) 를 모두 만족하면 "면제와 무관한 기존 결함의 노출"로 보고, 그 유형은 따로 후속 목록에 올린다. 하나라도 못 지키면 불합격이다.
- 이 판정은 면제가 상태에 준 영향을 증명하지 않는다. (ii) 는 그 영향이 기존 실패율을 키우지 않았다는 데까지만 본다. 그 한계는 등록에 그대로 적는다.

## 4. 확인

- 단위 시험:
  - 전환 틱 감지(분기 처음 등장)
  - 전환 전에는 장부를 비교한다.
  - 전환 뒤에는 인자가 끔이고 장부를 제외한다.
  - 닫힌 latch 와 latch 없음의 결정 동등성
  - 두 번째 꺼내기 → 운반 전환은 범위 밖 실패다.
- 실기록 확인: rx 배치의 `rx_B_aisle_rack_s0`·`s5`(return_home), `s1`(settle) 기록에 이어 재생을 돌려 `REPLAY_EXIT 0` 인지 본다(스냅숏 `rx_6e6d8e1c`). 대조로, 면제가 작용한 aisle 기록에 지금의 `--off` 를 돌리면 latch 자리에서 어긋나는지도 본다.
- 재생 게이트 runs29 29/29(재생 도구 변경), ws1 전체 시험, Codex 수렴.

## 5. 자체 검토

- ① 원자료·코드 재확인: 닫힌 latch 를 읽는 곳을 모두 확인했다. `exit_exempt_boundary` 는 `closed` 에서 바로 `None` 이고, `exit_exempt_tick_end` 는 `active` 가 아니면 반환하며, `exit_exempt_open()` 은 거짓이다. `exit_exempt_counts` 는 평가에만 쓰인다.
- ② Codex 1 차(`tmp/rx/codex_ocr1.out`): P1 없음, P2 3·P3 1.
  - 참조율 상한 비교는 B 표본 불확실성을 빼먹는다. 예: 참조 1/5 의 95 % 상한이 65.7 % 라 B 5/8 도 통과한다.
  - 단계 도달 조건부 비교는 면제가 만든 추가 실패를 숨길 수 있다(반례).
  - 닫힘이 마지막 틱이면 전환 뒤 0 틱으로 통과한다(CPU 반례).
  - 닫힘 기록이 없다고 latch 가 안 열린 것은 아니다(active 인 채 끝난 실행).
  - 확인된 것: 닫힘 감지 경로는 하나이고, 인자를 `setattr` 로 바꾸는 방식은 안전하며, 닫힌 latch 는 제어 결정 관점에서 무해하다. 이어 재생은 on 경로 재생과 대부분 같다.
- ③ agy(Argon, 1–3 절만 보고 "적히지 않은 전제"를 물음):
  - 이어 재생은 플래그 비의존성만 보이고, 열려 있던 동안 쌓인 상태는 그대로 넘어온다.
  - 단계 도달 비교에는 선택 편향이 있다(A 가 못 간 단계의 0 건 → 억울한 탓, 작은 표본 → 넓은 면죄부).
  - 대안으로 반사실 실험(handoff 자세에서 면제 이력 없이 뒤 단계만)과 handoff 상태 분포 비교를 제안했다.
