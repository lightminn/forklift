# 최종 목표 크리프 정체: 도착할 수 없는 띠의 크리프를 정체 수신자에게 넘긴다 (9판)

브랜치 `fix/goal-creep-stall`(origin/main `4d762c6e`)이다. 사용자 결정(2026-10-24, 총괄 경유)으로 on_s7 교착을 별건으로 고친다. 방향은 "작은 남은 길이·미소 명령에서 멈춘 최종 목표를 복구 경로가 받게" 한다는 것이고, 도착 허용은 넓히지 않는다. on_s2(근거리 대조)는 D5 v11 의 (a) 소관이라 건드리지 않는다.

## 1. 사실

- **사건**(`docs/validation/2026-10-23-joint-angle-odometry-rejudge.md` 4 절, ws1 `test_runs/jao3/jao3_tq_on_s7`): team-spec 오도메트리, 격자 모드(`--layout factory`)에서 return_home 마지막 다리(후진, 끝 (−2.34, 0, 0))의 끝에서 섰다.
  - 추종기 상태: `tracking`, 남은 길이 0.0241 mm, 위치 오차 8.35 mm(허용 8 mm), yaw 오차 0.057 rad(허용 0.03).
  - 명령: −3.6×10⁻⁵ m/s(1.5 × 남은 길이). 진행도는 약 53 s 고정, 마지막 1 m 진행 갱신부터 60 s 감시가 `obstacle_no_progress` 로 끝냈다.
  - team-spec 계수는 정지 중 바뀌지 않아 제어 자세가 네 값 사이에서만 움직였다.
  - 두 팔 교대 반복 2 회에서 같은 기록 궤적(slam_log SHA `47bb15d5…`)으로 재현됐다.
- **하한이 꺼진 이유**(`path_tracking._leg_end_floor`, #105).
  - (a) 지금 heading 으로 외삽한 끝 옆 거리 8.32 mm 가 허용 + `LEG_END_ACROSS_MARGIN_M`(0.5 mm) = 8.5 mm 안이다.
  - (b) 진행도 뒤 거리 0.29 mm 가 `LEG_END_BEHIND_M` 1 mm 안이다.
- **도착 판정이 안 되는 이유.** `at_endpoint` 는 위치 오차 ≤ 허용(또는 지나침 허용)을 요구한다. 8.35 mm 는 남은 길이가 0 이어도 도착이 아니다.
- **수신자가 받지 않는 이유**(`core.follow`).
  - 정체 판정 `stalled` 는 명령 0, `stop_now`, 그리고 `remaining_to_goal_m() ≤ 1 µm`(또는 목표 heading 실패, D7c 재접근 cusp)를 요구한다.
  - `stop_now`(`StopDetector`)는 명령 0 이 0.2 s 이어져야 참이다. 미소 크리프 명령은 0 이 아니라서 거짓으로 남는다.
  - 장면 장치(PR #112)의 트리거는 cusp 와 permit-stop 이라 최종 목표는 받지 않는다.
- **기존 수신자는 두 레이아웃 모두에 있다.** 정체 재계획 블록(`stall_replans`, 예산 2)은 `grid_planning` 이나 장면 여부로 막히지 않는다. 리보틱스 장면 실행 17 개에 return_home `stall_replans` 기록이 있다(ws1 `test_runs/riibotics/*`). 블록은 SLAM hold 를 먼저 해제·재투영(`release_before_stall_replan`)한 뒤 다리를 다시 계획한다.
- **수신자가 이 상태를 받을 수 있음:** 장치 소유 세션이 CPU 로 확인했다. 실제 `plan_return_leg` 로 목표에서 옆 8.35 mm·yaw 0.057 rad 떨어진 시작을 계획하면 성공했다(1.00 m, cusp 1: 후진 약 0.5 m → 전진 접근).
- **#105 의 0.5 mm 여유**(계획 `2026-10-22-leg-end-missed-stop.md` 6판)는 허용 경계에서 수렴해 들어오는 도착(옆 8.000845 mm 삽입)을 지키려고 넣었다. 데드밴드 0 이상 플랜트에서는 이 띠의 크리프도 약 3 s 에 남은 0 에 닿아 수신자가 받는다(같은 계획의 표 "목표 옆 8.4 mm·heading 0"). 정지 중 고정 계수나 데드밴드가 있으면 닿지 못한다.

## 2. 고칠 것

### G1. 추종기의 읽기 전용 질의: 기하 거름망

- `RearAxlePathTracker.leg_end_out_of_reach() -> bool`: 마지막 `update` 의 자세와 진행도로 판정한다. 명령·상태는 바꾸지 않는다.
- 이 질의는 **증명이 아니라 거름망**이다(3판은 "도착 불가" 라 불렀으나 Codex 3차가 거친 원호 끝·지나침 없는 설정의 정상 도착 반례를 냈다). 혼자서는 아무것도 바꾸지 않고, G2 의 관측과 함께일 때만 쓴다.
- 참은 다음을 모두 만족할 때다.
  1. 지금 다리의 끝이 경로의 마지막 점이다(최종 목표; cusp 끝은 K2·cusp 래치 소관).
  2. 보류·실패·도착이 아니다.
  3. 0 < 남은 길이 ≤ `LEG_END_SLACK_M`(4 mm). 1 µm 이하도 포함한다(Codex 2차 P2-3).
  4. 하한이 0 이다(`_leg_end_floor` 와 같은 계산).
  5. 외삽 끝 옆 − κ_max · d² / 2 − 0.01 mm > 위치 허용. d = 자세→끝 법선 거리 + 지나침 허용(없으면 0) + 0.1 mm.

### G2. 코어: 남은 0 에 가까운 크리프와, 명령만큼 움직이지 않는 크리프를 기존 수신자에게 넘긴다

- **R1 — 남은 ≤ 1 µm, 자세가 진행 지점에 있고 크리프만 남음.** 다음을 모두 만족하면 그 틱의 명령을 0 으로 바꾼다.
  - 최종 다리, `tracking`, 0 < 남은 ≤ 1 µm, 하한 0, 거름망(G1) 참.
  - 자세에서 끝 법선까지 거리 ≤ 0.01 mm.
  - 추종기 출력이 크리프 목표와 같다(|출력| ≤ 1.5 × 남은). 즉 감속 slew 잔여가 없다.
  - 직전 적용 바퀴 속도(`slam["applied_speed"]`)도 그 수준(≤ 1.5 µm/s)이다. 값이 없으면 R1 을 건너뛴다.
  - 남은 길이가 작아도 감속 중이면 출력은 클 수 있고(55 mm/s 에서 감속 중 0.375 s 에 지나침 허용 안으로 도착, Codex 6차 P2), 그 정상 도착을 R1 이 먼저 멈추면 안 된다.
  - 진행도는 단조 증가라 남은 ≤ 1 µm 여도 자세가 진행 지점보다 뒤에 있을 수 있다. 그때는 정상 접근이 남아 있으므로 넘기지 않는다(Codex 5차 P2: 10 mm 뒤·0.13 mm 뒤 반례).
  - 자세가 진행 지점에 있으면 남은 크리프(≤ 1.5 µm/s)는 60 s 감시 안에 0.09 mm 도 못 간다. 그 거리로는 옆 거리가 바뀌지 않아 도착할 수 없다.
  - 기존 "남은 0" 항(`remaining_to_goal_m() ≤ 1e-6`)이 이미 이 범위를 끝으로 본다. 그 항은 명령이 정확히 0 이어야 받는데, 크리프 명령 1.5 × 남은은 남은이 정확히 0 이 아니면 0 이 아니다(Codex 2차 P2-3: 7.5×10⁻⁷ m/s 로 영구 정체).
  - 명령을 0 으로 바꾸면 `StopDetector` 가 정지를 확인한다. 그러면 기존 항(`stalled`, `dock_stop`)이 그대로 받는다.
- **R2 — 1 µm < 남은 ≤ 4 mm.** 다음 둘을 모두 만족하는 틱마다 (a, b) 를 창에 넣는다.
  - 조건: 거름망(G1)이 참이고, 직전 틱에 실제로 적용된 바퀴 명령이 0 이 아니다.
  - a = |직전 적용 명령|·dt (명령한 이동), b = |`slam["odom_speed"]`|·dt (오도메트리 이동).
  - 창은 **최근 명령 이동 0.8 mm, 그리고 적어도 최근 120 틱(1 s)** 을 남기도록 앞에서 덜어 낸다(슬라이딩). 누적하지 않는다.
    - 누적하지 않으므로 정지 전의 정상 이동 이력이 그 뒤의 정지를 가리지 않는다(Codex 5차 P2: 누적이면 정지 뒤 321 s 에야 고정).
    - 최소 120 틱은 빠르게 들어올 때 창이 표본 몇 개로 차서 잡음 표본으로 판정하는 것을 막는다(Codex 7차 P2: 30 mm/s 진입이면 0.4 mm 창이 두 표본 0.017 s 로 차서 reported 잡음이 정상 접근을 0.02 s 에 고정).
  - 조건이 끊기거나 틱이 건너뛰어지면(직전 관측 뒤 1.5 dt 넘게 지남: 일시정지·계획 대기·장면 장치 점유) 창을 비운다.
  - 창이 120 틱 이상이고 명령 이동 Σa ≥ 0.8 mm 이며 Σb < 0.25 Σa 이면 **도착 불가 정지** 로 고정한다.
- **R2 의 근거.**
  - 절대 문턱(4판 0.05 mm/2 s)은 24 µm/s 로 실제 움직이는 정상 접근을 고정했다(Codex 4차). 그래서 명령한 만큼 움직였는지로 본다.
  - 이상 플랜트는 B ≈ A 라 고정되지 않는다.
  - **창 길이 0.8 mm 의 근거**는 실제 team-spec 센서 모형(`QuadratureWheelEncoder`)에서 구했다.
    - 바퀴 히스테리시스 0.088°(바퀴 둘레로 0.192 mm) 때문에, 방향이 바뀐 직후 첫 계수까지 한 계수 + 히스테리시스(약 0.384 mm)가 걸릴 수 있다(Codex 8차).
    - 곡률 상한 0.36·윤거 0.53 m 에서 안쪽 바퀴는 명령 이동의 0.905 배만 간다. 오도메트리 이동은 두 바퀴의 평균이다.
    - 역회전 직후·임의 시작 위상(400 개)에서 센 이동의 최솟값을 계산했다. 명령 이동 0.4 mm 면 최악 B/A = 0.240 으로 문턱 0.25 밑이다(Codex 8차 반례: 12.3 s 에 도착할 접근을 1.08 s 에 고정). 0.6 mm 면 0.479, 0.8 mm 면 0.599, 1.0 mm 면 0.671 이다.
    - 0.8 mm 에서 여유가 두 배 넘게 남아 0.8 mm 로 정했다.
  - reported 잡음 오도메트리는 B 가 커서(정지 표본 240 개에 26–28 mm, Codex) 고정되지 않는다. 지금처럼 잡음이 진행도를 밀어 기존 수신자에 닿게 둔다.
  - on_s7 의 명령 3.6×10⁻⁵ m/s 로는 창이 차는 데 약 22 s 다(기록 53 s 정체). 정지 전 이동이 있어도 창은 정지 뒤 0.8 mm 명령분만 보므로 같다.
- **적용 명령의 값(계약).** 러너는 물리 스텝 직전에 그 스텝에 실제로 낸 바퀴 속도를 `slam["applied_speed"]` 에 쓴다. 코어는 다음 틱에 그 값을 직전 적용 명령으로 읽는다. 그 틱의 `slam["odom_speed"]` 가 바로 그 스텝 구간의 오도메트리라 둘이 짝이 맞는다.
  - 배치에서는 `assemble_command` 의 `drive.speed_mps` 다.
  - live 에서는 arbiter 가 덮어쓴 값(teleop·preempt)과 물리 스텝 직전 정지 훅이 만든 0 까지 반영한 최종값이다.
  - `slam["last_command"]` 는 조립 전 `requested_speed` 라 쓰지 않는다(Codex 4·5차 P3).
  - 값이 없으면(첫 틱·SLAM 없음·이 필드가 없는 옛 기록의 재생) R1·R2 를 건너뛴다.
  - **기록·재생**: 바퀴 명령 뒤에 값을 쓰는 줄은 러너 루프에 있어(기록된 물리 스텝 밖) 재생에서도 실행된다. 물리 스텝 안에서 바퀴를 0 으로 만드는 경우(preempt, 자이로 고장, live 정지)의 0 은 스텝 안에서 쓰이므로, 물리 스텝의 `step_watch` 에 `slam["applied_speed"]` 를 더해 재생이 복원하게 한다(Codex 6차 P3). 그래서 옛 기록을 재생해도 R1·R2 가 켜진다. 재생 게이트가 새 동작을 실제로 거친다(agy 9판 검토).
- **상태의 자리.** 관측 창·고정은 코어 인스턴스의 `goal_creep_watch` 에 두고 `baseline.CORE_FIELDS` 에 등록한다(미션마다 초기값으로 되돌림; 재생의 최종 상태 비교에 들지 않음). 고정 기록 `state["goal_creep_stalls"]` 는 `MISSION_KEYS["state"]` 에 등록해 미션 기록으로 넘긴다(Codex 구현 1차 P2).
- **고정과 풀림.** 고정되면 그 틱부터 명령을 0 으로 바꾼다. 그 뒤 자기 명령 0 때문에 관측 조건이 끊겨도 고정은 유지한다(A, B 만 되돌린다). 풀리는 경우는 다음뿐이다: 추종기·다리가 바뀜(수신자가 새 경로를 설치), 단계가 바뀜, 거름망이 거짓이 됨.
- **수신자는 기존 그대로다. 우선순위도 기존과 같다.**
  - 운반이고 도킹이 무장(`armed`)·`holding` 이면 D7c(a) `dock_stop` 의 OR 에 더한다(Codex 1차 P2).
  - 그 밖(`goal_heading_miss` 와 같은 조건: SLAM, transport/return_home, cusp·off_path 아님, 정체 예산이 남았거나 D7 소유)은 다음 순서다.
    1. 명령 0(`status="braking"`)으로 둔다.
    2. `stalled` 의 OR 에 더한다(`stop_now` 는 그대로 요구).
    3. 120 틱 뒤 기존 분기가 받는다. D7 소유면 도킹 재시도, 아니면 `stall_replans` 다(실패면 `stall_replan_failed:<status>` 로 미션이 끝난다).
- **예산이 다 쓰였으면**(D7 소유도 아니면) R2 는 바꾸지 않는다. 지금처럼 미소 크리프로 남는다. R1 은 명령만 0 으로 바꾸고 수신자는 기존 항 그대로다. 종료는 다음 셋 중 하나다.
  - 격자 모드에서 permission 이 돌면 60 s 진행 감시(`obstacle_no_progress`).
  - 장면 모드나 permission 이 꺼진 운반 마지막 직선이면 `Tracking timeout`.
  - 예산은 운반·복귀가 공유하고, CT-1 연속 미션에서는 미션마다 초기화된다(Codex 1차 P3).
- **넘기지 않는 것.**
  - 거름망이 거짓인 정지(외삽 끝 옆 ∈ (허용, 허용 + κ_max·d²/2], 지나침 30 mm 에서 약 0.17 mm 폭).
  - reported 잡음 오도메트리의 정지.
  - 창이 차기 전에 감시가 끝나는 아주 느린 크리프. 1 µm < 남은 이고 명령이 1.5 × 남은이면 창이 차는 데 0.8 mm / (1.5 × 남은) 이 걸린다. 남은 ≥ 8.9 µm 면 60 s 안이다.
  - R1 에서 자세가 진행 지점보다 뒤에 있는 정지(정상 접근과 구별할 수 없다).
  - 바퀴가 앞뒤로 한 계수씩 떠는 정지. b 를 절댓값으로 더하므로 Σb 가 부풀어 고정되지 않는다. 부호를 붙이면 reported 잡음의 부호 합이 커서(22 s 창에서 표준편차 약 7.7 mm) 정상 접근을 잘못 고정하므로 절댓값을 쓴다(agy 9판 검토 A 에 대한 처리).
  - 실차 구동계의 백래시·타이어 변형. 0.8 mm 근거는 엔코더 사양(히스테리시스·양자화)과 곡률만 담는다. 실차 값은 실측 뒤 다시 본다.

### 하지 않는 것

- 추종기 명령·하한·여유 0.5 mm·도착 허용·`TrackerConfig`·`TrackingCommand`·`rollout.py` 는 바꾸지 않는다. 추종기에는 읽기 전용 질의만 더한다.
- 장면 장치에 트리거를 더하지 않는다. 기존 정체 수신자가 장면 레이아웃에서도 돈다(1 절). 같은 장치를 두 번 만들지 않는다(장치 소유 세션과 2026-10-24 조율).

## 4. 영향

- 바뀌는 것: 최종 목표 다리 끝에서 두 경우에만 미소 크리프가 기존 수신자(도킹 정지·도킹 재시도·정체 재계획)로 넘어간다.

- 근접 추적 계약·러너 인자: 바뀌지 않는다.
- 연속 이송(장면 장치)과 V-G2 `feat/p6-permit-stop`: 장치·트리거·예산을 건드리지 않는다. `core.follow` 의 정체 블록만 바꾼다. 충돌 지점을 두 세션에 알린다.
- 도킹: 무장 도킹 정지점의 띠 정체는 D7c(a) 도킹으로, D7 소유면 도킹 재시도로 간다. 기존 "남은 0" 상태의 수신자와 같다.
