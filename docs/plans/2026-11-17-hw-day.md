# 11-17 하드웨어 날 — Jetson·A2M12·H743 한 번씩 연결해 실측 (순서표)

작성 2026-11-16 · 사용자 결정(학교에서 한 번씩 연결) · 총괄 배정. H743 몫은 펌웨어 세션의 [보드 확인](2026-11-17-h743-board-check.md) 6 절이 정본이다. 스크립트는 모두 `tools/hwday/` 에 있고, 사용자가 `!` 로 한 줄씩 실행한다. 결과 원자료는 `data/` 아래(커밋 안 함)에 남고, 그날 결과 문서 PR 하나로 모은다(아래 형식).

## 0. 아침에 한 번

- `! bash tools/hwday/sync_main.sh` — 하드웨어 날 작업 트리를 최신 main 으로 맞춘다(펌웨어 세션의 링크 확인 도구 포함).
- 세션 환경에 `JETSON_SSH_PASS`·`JETSON_SUDO_PASS` 가 있어야 한다(없으면 세션 재시작).

## 2. 판정 기준(사전 고정, `tools/hwday/judge.py`)

| 항목 | 합격 |
|---|---|
| A2M12 회전 | 주기 중앙값 80–125 ms(8–12.5 Hz) |
| A2M12 주기 꼬리 | p99 ≤ 150 ms(7b 허가가 느린 주기로 닫는 선) |
| A2M12 끊김 | 10 분 동안 수신 간격 최대 ≤ 350 ms(7b 허가의 침묵 선), 어댑터 버림 0, 거부는 처음 10 개(시계 짝 수립)만 |
| A2M12 stamp→수신 | p99 ≤ 150 ms(7b 가 그보다 늦은 스캔을 버림) |
| A2M12 점 수 | 한 바퀴 ≥ 400 점(카탈로그 1600) |
| A2M12 유효 거리 비율 | ≥ 0.5(실내) |
| 각도 규약 | 오른쪽 상자의 최근접 점이 right 구역(지지율 ≥ 0.8) |
| 7b 허가(정지) | 비운 5–20 초 전진 열림 ≥ 90 %, 사람이 선 동안 3 초 이상 연속 닫힘, 마지막 10 초 다시 열림 ≥ 90 % |
| Jetson 다리 정체 | 정지: 40 ms 넘는 주기 간격 0. 부하: 80 ms 이상 간격 0(노트북 리허설에서 80 ms 는 견디고 124 ms 에서 `mcu_stopping`) |
| H743 링크 | 펌웨어 세션 문서 6 절(10 분 끊김 0, STATE ≥ 95 %, 오류 0, 왕복 ≤ 50 ms 등) |
| Jetson 기록 | 값만 적는다(JetPack·Ubuntu·커널·디스크 여유·nvpmodel 전후·dialout 소속·udev 규칙 일치) |

장착 위치 조건(차체 둘레 띠가 가려지면 그 방향 허가가 늘 0)은 이 날 기록만 하고 판정하지 않는다(절차서 11a, 점검표 "A2M12 장착").

## 3. 실패하면 볼 것 (3 개 이내)

- **A2M12**:
  - `data/a2m12_check/…/device.txt` — 장치가 하나만 잡혔는지 본다. 여럿이면 `DEV=/dev/serial/by-id/…` 를 앞에 붙인다.
  - `driver.log` — 보율(256000)과 장치 권한(그룹)을 본다.
  - `scan_check.out` 의 `refused` 사유를 본다.
- **7b 허가**:
  - `permit.out` 의 `why_f` 를 본다. `unknown` 이면 주변이 가리거나 가까운 것이고, `no_snapshot` 이면 스캔이 안 들어온 것이다.
  - 라이다 둘레 비움(앞 1.5 m·뒤 1.2 m·옆 0.6 m)을 확인한다.
  - 평면 높이 인자를 확인한다.
- **Jetson 찾기·ssh**:
  - Jetson 화면에서 `ip -4 addr` 로 IP 를 읽는다.
  - 노트북과 같은 망인지 본다.
  - 세션 환경 변수를 확인한다.
- **Jetson 준비**:
  - `setup.txt` 에서 pip·cmake 실패를 본다(인터넷·패키지).
  - `info.txt` 에서 docker·dialout 을 본다.
  - `power.txt` 에서 재부팅 필요 여부를 본다.
- **다리 정체**:
  - `stall/hwday_stall/*/bridge.log`·`bench.log` 를 본다.
  - nvpmodel 이 고정됐는지 본다(`host.txt`).
  - 큰 간격이 gc 때문인지 본다(`verdict.txt` 의 gc max).
