## 구현 (run_transport.py, 기본 동작 불변)

1. **`--planning-target {perception, oracle_nominal}`**, 기본 `perception`. `oracle_nominal` 은 G2a 계약대로 **유효 검출 분기
   안에서만**, 추정값·오차 기록을 끝낸 뒤 `plan_transport` 의 `target_pickup` 인자만 `scenario.pickup`(생성 당시 명목 자세)으로
   바꾼다. 검출·재관측·캡처 실패 처리와 관측 순서는 그대로다.
2. **인계 상태 기록(모든 인식 실행):** 첫 유효 검출 시점의 시도 번호·후보 번호, `accepted_pose`, 차체 선속도·각속도, 조향 관절
   위치, 실제 팔레트 자세(`pallet.get_world_pose()`, 실행기와 같은 경로), 시뮬레이션 시간, 주 루프 `step` 번호, 캡처 전 `t`, 승인 캡처 depth 배열의 sha256,
   `planning_target_source`. 인식 오차를 **명목 자세 대비(기존 필드)와 실제 자세 대비(새 필드)** 둘 다 기록한다 — spawn 검사는
   XY 5 mm 와 z 만 보고 yaw 는 보지 않으므로 둘이 다를 수 있다.
3. **`--repeat-captures N --repeat-at-attempt K`**, 기본 0(끔). 진단 전용 실행(G2r)이다. 원래 흐름을 그대로 따라가다 K 번째
   관측 시도에서, 원래 캡처·검출·기록을 끝낸 뒤(관측 기록과 `rear` 는 이때 확정) 바퀴 속도 0 을 적용하고 같은 정지 계약으로 N 번
   더 캡처·검출한 다음 **검출 결과와 무관하게 종료**한다(`success` 거짓, `phase = "repeat_capture_done"`). 반복 검출은 원래 분기
   결정을 바꾸지 않는다. 캡처마다: `CaptureDiagnostics` 전체, 첫 캡처 승인 자세 대비 누적 위치·yaw 차, depth 의 첫 캡처 대비
   변화(공통 유효 화소의 수치 변화 수·최대·평균 절댓값과, 유효↔무효 전환 화소 수를 따로), 유효 화소 비율, 검출 상태·사유, 좌우
   포켓 중심과 `insertion_yaw_rad`. 반복 중 캡처 실패는 사유를 기록하고 그 묶음을 끝낸 뒤 종료한다(실행 오류로 올리지 않는다).
4. **구성 기록 보강(모든 실행):** 단계별 `TrackerConfig` 전체, 검출에 쓴 `DetectorParams` 전체, carb `/rtx/rendermode` 를 첫 캡처
   전과 실행 끝에 읽은 값, 장면 파일 sha256(`scene.usda` 와 그것이 참조하는 `forklift.usd`·configuration 레이어), 초기
   `phase = "startup"`.

SDK 비의존 부분(반복 요약 통계, 인계 대응 판정, 오라클 목표 선택, 실제 자세 대비 오차)은 함수로 빼서 단위시험한다.

## 판정 규칙 (결과 보기 전 고정)

- **G2–G2a 대응:** seed 별로 두 실행의 인계 상태가 모두 같을 때만 "대응 성립" 으로 — 첫 유효 검출 시도 번호·후보 번호 일치,
  승인 캡처 depth sha256 일치, `accepted_pose`·차체 선속도·각속도·조향 관절 위치·실제 팔레트 자세 각 성분 차 ≤ 1e-6, 시뮬레이션
  시간 차 ≤ 1e-9 s, 주 루프 `step` 번호 일치, 접근 단계에 넘길 캡처 전 `t` 차 ≤ 1e-9 s(전체 한도는 주 루프 횟수이고 접근
  단계는 캡처 전 `t` 로 시작하므로, 이 둘이 같아야 남은 예산이 같다). 이를 만족할 때 네 조합(인식×오라클 성공·실패) 표에 넣는다. 아니면 "대응 불성립" 으로 따로 적고 목표 치환의 효과로 해석하지 않는다.
  유효 검출이 없는 seed 는 두 실행 모두 관측 기록(시도별 depth sha256)이 같을 때 "미검출 대응" 으로 적는다. 오라클 성공률이
  인식 성공률 이상이라는 단조성은 가정하지 않는다.
- **G2r 대응:** 같은 seed·K 에서 G2r 의 K 번째 시도의 후보 번호가 같고, 원래 캡처의 depth sha256 이 같고, `accepted_pose` 각
  성분 차 ≤ 1e-6 일 때만 "G2 의 그 관측점" 의 분산으로 부른다. G2r 이 K 번째 시도 전에 유효 검출을 얻으면(G2 와 흐름이 갈림)
  계획 전에 `phase = "repeat_target_not_reached"` 로 종료하고 비대응으로 적는다. 관측 후보가 K 전에 소진돼도 같다.
- **G2r 해석:** depth 는 렌더 모드와 무관하게 결정론적이었고(검증 기록 §21.4) 검출기의 RANSAC seed 도 고정이라, 완전히 정지하면
  반복 결과는 같다고 예상한다. 그러므로 **분산 0 은 강건함의 증거가 아니다. "이 묶음에서 검출 출력 변화가 관측되지 않았다"**
  까지만 말하고, 정지 여부는 자세 기록으로 따로 판정한다(같은 출력이 미세 이동이나 검출기의 둔감함에서도 나올 수 있다). 분산이
  있으면 원인을 자세 이동과 그 밖으로 가른다. 누적 이동이 1 mm 또는 1 mrad(캡처 정지 계약과 같은 값)를 넘은 캡처는 "이동"
  으로 표시하고 분산 통계에서 빼되 기록은 남긴다. 반복 0 은 원래 캡처다. 통계: 유효 검출 수, 검출 상태가 바뀐 반복 수, 유효 2 개
  이상일 때만 좌우 중심 표준편차와 **첫 유효 검출(번호 기록) 대비** 최대 편차, yaw 는 그 검출 대비 각차(±π 감기). 유효가 1 개
  이하면 이 통계는 null 이다. 원래 캡처가 무효였으면 그 사실과 기준으로 쓴 반복 번호를 함께 적는다.
