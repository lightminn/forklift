## 2. 이번 기준선이 말하는 것

- 라이브 L(넷 없음, 런처 기본)은 결정 모드 16 세션·운영 모드 16 세션의 96 임무를 모두 완주했다. 실패가 0 이라, 넷이 고칠 사례가 이 표본에는 없다. 수정 전 현황 조사 D(넷 켬)도 48/48 이었고, 같은 seed·순번에서 결과가 다른 임무가 없다.
- 따라서 이 자료는 "넷이 없어도 이 장면·임무에서는 같다"까지만 말한다. 넷이 필요한 상황(저상 소품 근접·점유 정지 뒤 재출발·복귀 cusp 요 실패·출구 접두)이 이 표본에 노출되지 않았다. 승격의 이득도 해도 보여 주지 않는다.

## 3. 제안(항목별)

1. **① 출구 접두 면제 — 승격하지 않는다(검증 불필요).** 라이브에 출구 접두가 없어 켜도 동작이 같다. 라이브나 실차 장면에 출구 여유(`--exit-clearance-m`)를 쓰는 경우가 생기면 그때 다시 본다.
2. **③ 재출발 확인 — 라이브는 지금대로 두고, 실차 값은 S8·S9 실측으로 정한다.** N 은 시뮬 LiDAR 10 Hz 와 칠하기·지우기 규칙에서 정한 값이다. 실차 A2M12 의 스캔 주기·잡음, 사람이 지나간 뒤 재출발 지연은 Isaac 배치로 정할 수 없다(port-review 그 행). Isaac 검증은 하지 않는다.
3. **⑥ 복귀 cusp 재계획 — 지금은 승격하지 않는다.** 이번 기준선 L(⑥ 없음) 96 임무에서 return_home 실패가 0 이다. 수정 전 현황 조사는 ⑥ 을 켠 채 돌았으므로 그 표본은 대상 유무의 근거로 쓰지 않는다. 승격하려면 먼저 (a) 라이브에서 그 실패가 생기는 조건을 찾는 노출 조사와 (b) 동기 재계획이 라이브 배속·STOP 지연에 주는 비용 측정이 필요하다. 라이브 세션에서 이 실패가 보이면 그때 올린다.
4. **② 저상 소품 감시 — 넷 가운데 유일하게 검증 경로를 연다.** 실차의 저상 장애물 위험(port-review)과 직접 이어지기 때문이다. 필요한 검증은 다음과 같다.
   - 11-09 주입 계획의 B(진단 고정 장면, 낮은 소품을 빈 차·적재 다리 근처에 둠)를 ④⑤ 승격 뒤 스냅숏으로 등록한다. 상한 발화·정지·회복이 각각 관측되는지 본다.
   - 라이브 A/B 로 배속과 정체를 비교한다. 틱 비용은 소품 옆에서 1.7–2.9 ms 이고, 최적화 뒤 라이브 배율은 재측정하지 않았다.
   - 적재 중 상한 0 정지의 운용 처리(자체 복구가 없음, 11-08 ② 운용 미해결)를 정한다.
   - 실차에서 켤지는 S8 의 추종 편차·SLAM 오차 실측과 현장 저상 물체 목록이 나온 뒤 S9 에서 정한다. Isaac 결과만으로 실차 기본을 정하지 않는다.

## 4. 결정 요청

- (가) ①·③·⑥ 은 현행 유지로 기록만 할지.
- (나) ② 는 주입 B 등록을 지금 시작할지, 실차 S8 뒤로 미룰지. 시작하면 Isaac 규모는 그 등록에서 산정해 따로 올린다.
