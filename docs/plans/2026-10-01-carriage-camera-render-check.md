# 캐리지 하단 카메라 Isaac 렌더 확인 — 계획 (4단계)

작성일: 2026-10-01 · 개정 같은 날(독립 검토 반영, 아래 자체 검토 절)

## 요청과 질문

사용자(2026-10-01): 선택지 1–5 진행, 단계마다 Codex 교차검증 수렴까지. 4단계: CPU 리그에서 추가 검증 후보로 둔
**(0.61, 0, 0.20) 틸트 0** 장착이 Isaac 렌더에서도 같은 기하 결과를 내는가. 이 확인이 말할 수 있는 것은 **"Isaac 렌더
기하가 CPU 결론을 뒤집는가"** 뿐이다. 장애물·포크 모두 URDF 상자이고 잡음·스테레오 가림·어두운 재질(포크 rgba 0.045)의
영향은 다루지 않으므로, 일치하더라도 장착이 실물에서 좋다는 근거가 아니다.

## 설계 — CPU 리그와 같은 조건을 Isaac 으로

`sim/isaac/render_mount_check.py`(신규), ws1 Slurm GPU. 물리는 한 번도 진행하지 않는다(timeline 정지, `delta_time 0` 렌더).

- **최소 장면.** 창고·공장 환경을 쓰지 않는다 — 배경 물체가 검출기 평면 후보(예산 5)를 차지하면 실패가 장착 탓으로 읽힌다.
  CPU 리그와 같은 것만 둔다: 바닥(윗면 z = 0), base 기준 x = 6 m 벽, 실측 차체(실측 base scene 이 참조하는 `forklift.usd`,
  장면–URDF 검사 통과), EPAL 6 팔레트. 차체 base_link 원점을 바닥 z = 0 에 둔다(URDF 에서 뒤 spin 관절 z = 바퀴 반지름이라
  base 원점이 접지면이다). 시작 시 base←carriage = 단위, base←camera = (0.61, 0, 0.20)·설정 회전을 USD 에서 다시 읽어 검사한다.
- **팔레트는 시각 전용.** 기존 `create_pallet` 은 질량을 붙인 자유 강체라 쓰지 않는다. 팔레트 URDF 를 가져온 USD 의 visual 만
  참조하는 Xform 을 만들고, 칸마다 그 Xform 의 변환만 바꾼다. 정답 포켓은 **다시 읽은 base←pallet 변환**으로 팔레트 로컬 정답을
  옮겨 계산한다(정렬·같은 바닥이면 포켓 (0.95 + face_gap, ±0.18625, 0.061), 입구 광학 z 0.34 + face_gap — Codex 재계산).
- **카메라.** `/World/Forklift/fork_carriage/MountCamera`, 640 × 480, focal 465.741156 px. K 는 `IsaacIntrinsics` 로 한 번 정규화
  (주점 319.5, 239.5).
- **영역 식별 — 세 번 렌더.** 칸마다 ① 전부 보이는 렌더 ② `fork_carriage` 의 visual instance 루트를 숨긴 렌더 ③ 팔레트 visual
  루트를 숨긴 렌더를 낸다(instance 루트 자체의 가시성은 편집 가능하고 proxy 는 건드리지 않는다 — 대상이 proxy 가 아닌지 검사).
  마스크는 **양자화 전 원시 깊이**에서 만든다. 화소가 유효하려면 비교하는 두 렌더 모두 유한·양수여야 하고(벽이 모든 광선을 받으므로
  0 = 무교차는 위반으로 무효), 캐리지 화소는 ① < ② − 2 mm, 팔레트 화소는 ① < ③ − 2 mm, 나머지는 바닥·벽이다. 4-이웃 중 다른
  영역이 있는 화소는 **경계**로 표시한다.
  포크 끝 가시: CPU 도구와 같은 표본(날 윗면 끝 20 mm, 5 × 5)을 정규화 K 로 **최근접 화소**에 투영해, 그 화소가 캐리지 화소이고
  ①의 깊이가 표본 광학 깊이와 5 mm 안이며 0.175 m 이상이면 보임. 같은 화소에서 깊이를 읽고 보간하지 않는다. 경계 화소에 떨어진
  표본은 따로 세어 보고하고, 분모 25 에서 빼지 않는다. 끝 근처에는 날 말고 다른 캐리지 부재가 없다(힐·가로대는 x ≤ 0.604).
- **프레임 갱신 확인.** 이어진 두 프레임이 같다는 것만으로는 한 칸 지연을 걸러내지 못한다(Codex 반례). 그래서 매 렌더를 **현재 USD
  자세에서 계산한 예상 깊이**와 대조한다: 팔레트 앞면 중앙 블록·바닥·벽의 비경계 기준 화소 몇 개에서, 다시 읽은 자세로 광선 교차를
  계산해 렌더 깊이가 3 mm 안이어야 한다. 이 검사를 자세 변경 뒤·숨김 뒤·복원 뒤 각각 적용한다(첫 프레임은 버리되 그것을 신선도
  보장으로 보지 않는다). 숨김·복원에서는 고정 기준 화소가 바뀌지 않을 수 있으므로(face_gap 0.10 에서 중앙 블록·바닥·벽 화소는 캐리지
  숨김 전후 같다 — Codex 반례), **그 전환으로 예상 깊이가 6 mm 넘게 바뀌는 비경계 화소**를 CPU 기하(같은 K·같은 자세)로 골라 함께
  대조한다: 캐리지 숨김은 캐리지에 가려진 화소, 팔레트 숨김은 팔레트 화소. 그런 화소가 없는 칸(예: 캐리지가 화면에 없는 경우)은 그
  전환을 갱신 확인 불가로 표시하고, 그 칸의 해당 마스크·가시 판정을 미확인으로 둔다. 시작 때 포크가 확실히 보이는 기준 칸에서 보임 → 숨김 → 보임의 변화와 복원도 확인한다. 실패한 칸은 원시
  배열·재시도 기록을 남기고 **무효**로 표시한다.
- **CPU 짝.** 같은 칸·같은 K(주점 319.5)로 CPU 리그 깊이를 렌더해(리그에 선택 인자 `intrinsics=` 를 추가, 기본값은 기존 그대로),
  ① Isaac − CPU **화소별 깊이 차이 지도**를 저장하고 ② 두 깊이에 같은 처리(1 mm 양자화 켬/끔 → min-range 0.175 마스크, CPU
  순서와 같음)를 적용해 검출기를 같은 seed 0–11 로 돌린다. 오차는 M2(좌→좌·우→우 3 차원 오차 중 큰 값) ≤ 20 mm.
  CPU 쪽 포크 끝 가시도 같은 화소 판정으로 함께 내고(기존 연속 광선 판정과 구분), 두 렌더러의 차이와 판정 규약의 차이를 가른다.
- **거리.** face_gap −0.20 ~ 0.70 m 를 **1 cm 격자**(91 칸)로 사전 고정한다. CPU 결과의 첫 비영(양자화 0.11·1/12, 무양자화
  0.25·6/12)·첫 전 seed(0.42·0.46)·포크 끝 경계(−0.11 / −0.12) 가 모두 이 안에 있다. 음수 칸은 캐리지·포크 **전체 상자**와 팔레트
  상자의 부피 중첩(접면 제외)이 없는지 확인한 비접촉 삽입 자세이며, 접촉·하중 상태가 아니다.

## 범위 밖

T11, 승강 > 0, 측방·yaw, 잡음 모형, 스테레오 가림, RGB 기반 검출, 공장 배경 포함 렌더, 장착 확정.

## 완료 기준

1. SDK 비의존 부분(정답 변환, 표본 투영·화소 판정, 깊이 차 마스크, 칸 목록, 관통 검사, 리그 `intrinsics=` 기본값 불변)의 단위시험,
   기존 시험 새 실패 없음, Ruff.
2. ws1 실행이 91 칸 중 무효 칸 수를 보고하고, 유효 칸마다 Isaac·CPU 의 좌우 가시율(경계 표본 수 포함), 양자화 켬/끔 검출 성공 수,
   깊이 차이 통계를 남긴다. 영역별 통계는 위 마스크(①②③ 모두 유효한 화소, 경계 제외와 포함을 각각)에서 낸다.
3. **실행 완료와 비교 성립을 구분한다.** 무효 칸은 검출 실패·비가시로 세지 않고 미확인으로 둔다. 어떤 거리 경계(첫 비영·첫 전 seed·
   포크 끝 가시 끝)를 결론으로 쓰려면 그보다 가까운 칸이 모두 유효해야 하고, 아니면 "그 칸까지 미확인" 으로 적는다.
4. Isaac 과 CPU 가 다르면 깊이 차이 지도로 어느 영역에서 갈렸는지를 적는다. 판정 규약 차이(연속 광선 vs 화소)는 따로 적는다.
