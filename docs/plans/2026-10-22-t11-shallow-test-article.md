# 얕은 T11 시험체로 밑판 검사 사이클 확인 (2판)

브랜치 `feat/t11-shallow`(`feat/t11-bottom-deck` 머지 뒤 main 에서). 앞선 기록은 `docs/validation/2026-10-22-t11-bottom-deck.md` 다. T11 x0.6(깊이 0.66 m)은 지금 삽입 규칙에서 명목상 중심을 0 mm 넘어, 0.29 m 간격의 사이클이 0/6 이었다.

**사용자 결정(2026-10-22, forklift-97 경유) — 시험체 한정:**
- 시험용 T11 을 얕게(깊이 ≤ 0.61 m) 만든다.
- T11 정본 형상(ADR 0002, 구멍 235/350 미정)을 정한 것이 아니다. 기존 정본 파일(`config/pallet_geometry_t11_06.yaml` 등)은 덮어쓰지 않고, 이름부터 구별되는 별도 시험체로 만든다.
- 깊이 외 치수는 T11 x0.6 과 같다. 포크 간격은 0.29 m 그대로다.
- 진짜·grounded 얕은 T11 로 검사 끔·켬 사이클을 다시 돌린다.

## 1. 깊이 선택 (계산)

삽입 목표 = min(깊이 × 0.6, 캐리지 한계 0.346 − 예비 0.016) 이다(`target_insertion_depth_m`). 중심을 넘는 명목 깊이는 그 값에서 깊이/2 를 뺀 값이다.

| 깊이 | 목표 | 중심 | 중심 넘는 명목 깊이 |
|---|---|---|---|
| 0.660(T11 x0.6) | min(0.396, 0.330) = 0.330 | 0.330 | 0 mm |
| 0.610 | min(0.366, 0.330) = 0.330 | 0.305 | 25 mm(결정의 하한) |
| **0.600** | min(0.360, 0.330) = 0.330 | 0.300 | **30 mm** |

**0.600 m 를 고른다.**
- EPAL 6(깊이 0.6 m)과 같은 명목 30 mm 다. EPAL 6 는 이 여유로 사이클을 마쳐 왔다.
- 0.610 m 는 결정의 하한(25 mm)이라 실측 미달(3–26 mm, T11 x0.6 실행)에 여유가 더 적다.
- 블록 배치: 3 열 × 0.08 m 블록이 x = −0.26 / 0 / +0.26 m 에 놓이고, 사이 틈이 0.18 m 다(0.66 m 일 때 0.21 m). 너비 방향(포크 구멍)은 T11 x0.6 그대로다(구멍 중심 ±0.145 m, 폭 0.21 m).

## 2. 작업

1. **형상·모형**
   - `config/pallet_geometry_t11_06_d600.yaml`: `geometry_version: t11_06_d600`, `source_provenance: t11_06_shallow_cycle_test_article`, `overall_depth_m: 0.600`. 나머지는 T11 x0.6 그대로이고, 머리말에 결정·날짜·"시험체 한정, 정본 아님"을 적는다.
   - prior: `tools/build_pallet_prior.py` 로 `config/pallet_prior_t11_06_d600.yaml` 을 만든다. prior 로더의 출처 허용 목록(`pallet_prior.py` 103행)에 `t11_06_shallow_cycle_test_article` 을 더한다(없으면 러너 시작 전 `Unsupported source_provenance`).
   - 모형: `tools/build_pallet_model.py` 로 `sim/models/t11_06_d600_pallet/` 을, `tools/build_grounded_pallet.py` 로 `sim/models/t11_06_d600_grounded/` 를 만든다.
2. **인식에 알리기 — 같은 앞면의 변형**
   - 앞면(진입면)은 T11 x0.6 과 똑같아 앞면만으로는 깊이를 구별하지 못한다. 세 번째 형상으로 함께 넣으면 인식기는 이름 순서상 `t11_06:x` 를 고르고, 관측 변환의 깊이 검사(0.66 ≠ 0.60)에서 거부된다(Codex CPU 재현). 그래서 앞면으로 구별되지 않는 깊이 가설은 실행 지시(실행 형상)로 정한다.
   - `pallet_model.VARIANT_OF = {"t11_06_d600": "t11_06"}` 를 둔다.
   - 원거리 인식의 `known_specs(root, run_shape)` 는 실행 형상이 변형이면 **부모 키(`t11_06`)를 빼고 변형 키(`t11_06_d600`)를 넣는다.** 키를 그대로 두고 값만 바꾸면 `FarRuntime.truth_face()` 의 `self.specs[self.pallet_shape]` 가 `KeyError` 를 낸다(Codex 반례).
   - 치환은 `FarRuntime` 생성자 안의 공통 경로에서 한다. 그러면 원거리 재계산(`tools/recompute_far_recognition.py`, 저장된 `pallet_shape` 로 다시 만든다)도 따라온다.
   - 가설 이름은 `t11_06_d600:x` 가 된다. 실행 형상이 변형이 아니면 지금 그대로다.
   - `KNOWN_ENTRY_AXES["t11_06_d600"] = ("x",)`: 0.60 m 면(y 진입)은 구멍이 0.18 m 라 0.29 m 간격에서 바깥 여유 47.5 mm < 66 mm 로 들 수 없다.
   - `config/site_load_defaults.yaml` 에 `t11_06_d600` 을 추가한다(T11 과 같은 10 kg, 중심 하중).
   - `fork_fit.TEST_FORK_SPACING_M["t11_06_d600"] = 0.290`.
3. **러너:** 하는 일 없음. 형상은 `--pallet-geometry` 로 읽고, 밑판 검사 spec 은 실행 형상에서 만든다(`KNOWN_ENTRY_AXES` 에 항목이 있어야 한다).
4. **시험(먼저 실패 확인)**
   - 형상 파일이 0.600 m 이고 나머지 수치가 T11 x0.6 과 같다.
   - prior 생성 → 로더 재읽기 왕복.
   - 원거리 전체 경로: `FarRuntime.stop()` → 저장 → `recompute_far_recognition` 이 같음.
   - 변형 실행 뒤 같은 프로세스에서 EPAL 6·T11 실행의 spec 이 오염되지 않는다.
   - 밑판: 리그의 얕은 T11 옆면(틈 0.18 m)에서 진짜 `present`·grounded `absent`. 기록 형상 `t11_06_d600` 은 부모 `t11_06` 목표에 대해 게이트가 거부한다.
   - 삽입 목표가 중심 +30 mm 다.
   - `known_specs` 가 실행 형상이 변형일 때만 바꿔 넣고, EPAL 6·T11 실행은 지금과 같다.
   - CPU 리그에서 얕은 T11 의 원거리 인식이 `t11_06_d600:x` 로 `selected` 되고 관측 변환(깊이 검사)이 통과한다.
   - 밑판 판정 spec 이 만들어진다.
5. **Isaac:**
   - 먼저 진짜 검사 끔 seed 0 한 번으로 장면 적재·스폰·인식을 확인한다.
   - 그다음 0.29 m 장면·차체로 진짜 검사 끔·켬, grounded 검사 끔·켬, 각 seed 0–2(12 회)를 돌린다.
     - grounded 끔은 검사가 없을 때 grounded 를 집는지 보는 대조다.
     - `--near-tracking`·`--pocket-check` 는 끈다(새 형상에는 근접 추적 측정 조건이 없다).
   - 보고: 완주율, 들기 기울기, 중심 넘은 깊이, 채택 전 대조 거부. 근거리 SLAM 측면 오차로 인한 거부는 따로 분류한다.
   - 결과가 엇갈리면(같은 조건 3 회 중 성공·실패가 섞이면) 그 조건만 seed 3–5 를 더 돌린다.

## 3. 위험

- **변형 매핑:** 실행 형상을 아는 상태에서만 바꿔 넣는다(지시가 형상을 알려 준다는 전제). 같은 앞면의 T11 x0.6 과 얕은 T11 이 한 장면에 섞이면 가리지 못한다. 시험체 한정이라 받아들인다.
- **CPU 평가 대상 아님:** eval2·D6 의 형상 집합에는 넣지 않는다.
- **안정성:** 중심 +30 mm 가 들기 안정을 보장한다는 근거는 없다. EPAL 6 와 같은 명목 여유일 뿐이다. T11 x0.6 실행의 실측 미달(3–26 mm)이 되풀이되면 최악 +4 mm 다. 들기 실패가 남으면 원인(깊이 외)을 따로 본다.
- **대표성:** 이 시험체는 소프트웨어 사이클 확인용 우회 시험체다. 정본 T11(0.66 m)은 캐리지 연장(≥ 0.371 m) 같은 다른 결정이 따로 필요하고, 그때 다시 검증한다.

## 4. 자체 검토

- **직접 재계산(1판):** 깊이 표의 목표·중심·초과 깊이는 `target_insertion_depth_m` 로 다시 계산했다(0.330/0.300/+30 mm). 블록 배치는 `pallet_boxes` 로 다시 뽑았다(x = −0.26/0/+0.26, 틈 0.18 m). y 진입 여유는 구멍 [0.04, 0.22] 와 날 [0.1175, 0.1725] 에서 47.5 mm 다.

## 5. 검토 기록

### 1판 → 2판

- **② Codex 적대적 검토(1차): P1 없음, P2 1·조건부 P2 1·P3 2.** 모두 받아들였다.
  - P2: prior 로더가 새 출처를 거부한다 → 허용 목록 추가와 왕복 시험.
  - 조건부 P2: 부모 키를 그대로 두고 값만 바꾸면 `truth_face` 에서 `KeyError` 가 난다 → 키 교체·생성자 공통 경로·전체 `stop()` 시험을 명시했다.
  - P3: "모호해진다"는 설명을 실제 동작(이름 순으로 부모 선택 → 깊이 검사 거부)으로 고쳤다.
  - P3: 실험 범위에 grounded 끔 대조를 더했고, 근접 추적·포켓 검사 끔을 고정했다.
  - 계산(330/30 mm, 블록·틈, 여유 77.5/47.5 mm)은 Codex 재계산과 일치했다.
- **③ 독립 검토(agy, Gemini 3.8 Flash High — Argon 은 일할 한도 보류).** ①·② 결론을 보이지 않고 1판만 주고 적히지 않은 전제를 물었다.
  - 반영: 좁아진 옆면 틈(0.18 m)에서 밑판 판정 CPU 확인, 본 실행 전 1 회 시험 실행, 엇갈리면 seed 확장, 최악 미달 시 여유 +4 mm, 시험체가 정본 T11 을 대표하지 않음.
  - 반영하지 않은 것:
    - truth 자세 대조 실행: 이 러너에 그런 모드가 없다.
    - 접촉력 로깅: 범위 밖.
    - 하중 무게중심 검증: 시험은 빈 팔레트이고, 모형의 합성 관성은 중심 대칭이다.
