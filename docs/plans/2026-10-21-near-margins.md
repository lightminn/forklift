# 근거리 촬영·삽입 여유 — 밑판 근거, 정렬 재작도, 삽입 깊이 원인 (3판)

브랜치 `feat/near-margins`(main `090a7af` 에서). 출발점은 2026-10-21 실패 분석이다. 밑판 검사를 켠 사이클의 실패 3 건과 끈 사이클의 실패 1 건을 원자료로 진단했고, Codex 2차에서 "새 P1/P2 없음"으로 수렴했다(`docs/validation/2026-10-21-bottom-deck-cycle.md`, 원자료 ws1 `test_runs/bd_isaac/`).

사용자 결정(2026-10-21):
- 실패 분석 표의 세 방향으로 진행("그렇게 가").
- 밑판 근거는 "검사 켬일 때만 lower 문턱 끔(권장)". 앞면 재적합은 해결책이 아니라는 스파이크 결과를 보이고 받은 결정이다.

## 1. 사실 (원자료에서 다시 계산)

### C — 근거리 포켓 인식의 밑판 띠(lower)

- **실패:** 근거리 촬영이 `no_opening_pattern` 으로 끝났다. 실패 이유는 `insufficient_evidence`, 모자란 항목은 `lower` 하나다.
  - 실패 실행: `f_real_on_s2` 의 lower 0, `f_real_off_s3` 의 lower 13. 문턱은 15 = round(100·(0.078/0.200)²).
  - 검출이 `valid` 였던 근거리 프레임 18 장(사이클 실패 실행 포함)의 lower 는 20–54 다.
  - 저장 깊이(잡음 없음, 1 mm 양자화) 재생이 기록값을 정확히 재현한다.
- **lower 가 세는 것:** 맞춘 앞면 평면보다 뒤(부호 거리 `depth >= 0`)에 있고, 밑판 높이(0.022 ± 0.006 m)이며, 구멍 범위 안인 점이다. 앞면과 거의 같은 평면의 점이 이 경계에 걸쳐 있어 평면 위치가 서브밀리미터만 달라도 수가 크게 바뀐다.
  - 앞면 평면을 최종 인라이어로 다시 맞추면 실패 두 장이 0→16, 13→19 가 된다(Codex 계산).
  - 양자화를 없애고 다시 맞추면 성공 두 장이 24→0, 20→0 이 된다.
  - 같은 문제를 `docs/plans/2026-10-14-near-capture-lower-evidence.md` 가 기록하고 보류했다.
  - 1판에 적은 "앞면 동일 평면 점의 중앙 부호 거리" 비교는 철회한다. 선택된 평면과 lower 의 가로 범위를 적용하지 않은 값이었다(Codex 1차 P2).
- **판별력이 거의 없다:** CPU 리그(`tools/scene_rig.py`) 결과다. 카메라 (0.619, 0, 0.27), 팔레트 중심 x 2.0–3.2 m(카메라–앞면 1.08–2.28 m), 양자화 0/1 로 구조별 8 칸씩 봤다.

  | 구조 | 탈락 칸 수(lower) |
  |---|---|
  | 진짜 팔레트 | 3/8(0·2·14) |
  | 선반 | 1/8 |
  | 밑판 없음 | 4/8 |
  | grounded | 2/8 |

  - 탈락하지 않은 칸의 lower 는 선반 15–98, 밑판 없음 18–43, grounded 28–88 이다.
  - 재적합은 칸마다 결과가 뒤섞인다(진짜 x 2.0: 미양자화 0→50, 양자화 2→0).
- **lower 를 판정에서 빼고 다시 돌린 결과(Isaac 저장 근거리 프레임 20 장, 같은 검출기, lower 항목만 판정에서 제거):**
  - 원래 `valid` 18 장은 그대로 `valid` 이고, 포켓 중심 차이는 0.00 mm 다.
  - 실패 2 장은 `valid` 가 된다. `f_real_on_s2` 의 결과는 앞면 중심 측면 +0.014 m, yaw +0.0061 rad 이고, 같은 순간 truth(팔레트 중심의 base 측면 +0.017 m, 상대 yaw +0.007 rad)와 맞는다.
  - 이번 계획에서 실제로 기대하는 복구는 검사 켬 `f_real_on_s2` 다. 검사 끔 `f_real_off_s3` 는 그대로 실패해야 한다.
- **근거리 목표가 쓰이는 순서:** 검출 → 목표 추정 → `planning_pickup` 채택 → `known_pallet` 갱신 → 경로 설치 → 접근 → 삽입 게이트(`approach → insert`).
  - 기록과의 대조(`insert_refusal`: 같은 형상, 중심 0.15 m, 진입축 15°)는 지금 삽입 게이트에서만 한다.
  - 채택 전에 대조하는 것은 재관측(`returning`)뿐이다(`core.py` 2578행 부근).
  - Codex 탐침에서 기록과 0.30 m 다른 근거리 후보가 계획에 반영되고 접근한 뒤에야 게이트에서 거부됐다.

### B — 근거리 촬영 정렬

- **실패:** `f_real_on_s4` 는 근거리 정지에서 새 진입선 대비 yaw 0.0539 rad 이 나와 상자(0.05 rad)를 넘었다.
  - 합성: SLAM yaw 오차 변화(목표를 정한 원거리 촬영 → 근거리 촬영) −0.0410 의 부호를 바꾼 값 + 추종 잔차 +0.0130 − 인식 오차 0.0001.
  - 검출 성공 실행의 offset yaw 는 −0.041…+0.038 이다.
- **현재 구조:** 근거리 수락 분기는 상자(0.05 m / `near_capture_box_yaw_rad` 0.05 rad, 최소 길이 0.3 m)와 시운전(도착, 6 mm·0.015 rad)을 본다. 통과하지 못하면 `near_capture_redraw` 를 부른다.
  - 이 재작도(0.12 rad 상자)는 `near is not None` 일 때만 동작한다. 근접 추적이 꺼진 배치 실행에서는 바로 `require` 로 끝난다.
  - 러너는 `--near-capture-redraw` 가 `on` 이 아니려면 `--near-tracking` 을 요구한다(`run_transport.py` 1096행).
  - `near_capture_redraw` 는 이미 근접 추적 계약의 `RUN_SPECIFIC_ARGUMENTS` 에 있다(`near_tracking.py` 1051행).
- **재작도 자체의 검사(`redraw_docking`):**
  - 접근 직선: 소품과 인식한 팔레트에 대해 접근 여유로 검사.
  - 삽입·추출 직선: 소품에 대해 검사.
  - 두 속도의 시운전 도착: 6 mm·6 mm·0.015 rad.
  - 시운전 궤적: 접근 직선 검사를 통과해야 한다.
  - 검사 격자: `correction_grid`.
- **근접 추적이 있을 때만 더해지는 것:**
  - 재작도 시점: 보정점 검사(`correction_points_check`).
  - 이후 근접 추적이 주는 보호 전체: 마지막 0.6 m 보정 시점의 보호 예측, 보정, 정지.

  근접 추적 없이 재작도한 접근은 hold 상태 오도메트리로 달리고 A 의 거리 오차를 그대로 가진다. 두 시운전 통과가 실제 주행 오차를 검증하지는 않는다.
- **S4 판정기(`tools/s4_judge.py`):**
  - 기록 인자가 `on` 일 때만 stage 1 을 허용한다(3885행).
  - 재작도 기록에 tracker 시작·보정점을 요구한다(3608행).
  - 판정기 자체가 근접 추적 실행(`near_tracking.json`)을 전제로 한다.

### A — 삽입 깊이

- **실패:** `f_real_on_s1` 은 포크가 중심을 못 미쳤다(beyond_centre −3.4 / −6.8 mm). 근거리 촬영 → 삽입 끝 동안 SLAM 이 hold 상태였고, 그동안 오도메트리가 앞으로 +27 mm 과대계상했다.
- **언제 생겼나:** Codex 가 `slam_log.npz` 120 Hz 입력으로 오도메트리를 차이 0 으로 재현했다. 과대계상의 대부분이 접근 첫 선회(k 0.36)에서 생겼다(`f_real_on_s1` 1.1–1.4 s 16.5 mm, `d_real_off_s1` 1.3–1.6 s 12.2 mm).
- **같은 구간에서 바퀴 입력 자체가 맞지 않는다.** 단위는 mm 다.

  | 실행 | 바퀴 각속도 적분 | 바퀴 관절각 변화 × 반지름 | truth 후륜축 이동 |
  |---|---|---|---|
  | `f_real_on_s1` | 117.4 | 101.3 | 101.0 |
  | `d_real_off_s1` | 109.6 | 97.8 | 97.3 |

  관절각 변화는 실제 이동과 맞고, 보고된 각속도 적분만 크다.
- **오도메트리 입력:** 이번 실행의 오도메트리(`--encoder-model reported`)는 보고된 바퀴 각속도와 실제 조향 관절각에 잡음을 더해 적분한다(`run_transport.py` 5609행 부근, `slam_pose.py` 129행). 팀 엔코더 모형(`team_spec_quantized`)은 관절각을 읽는다.
- **이미 계획된 대응:** 삽입 직전 거리 재확인은 근접 추적(D5)이 맡는다. D5 는 실차 타이어 실측을 기다리는 중이다.

## 2. 범위

- **C:**
  - 밑판 검사가 켜져 있고, 기록이 `present` 이며, 재관측 대조를 통과한 뒤(`status == "done"`)의 근거리 촬영에서만 검출기의 lower 항목을 판정에서 뺀다. lower 수는 계속 기록한다.
  - 같은 조건의 근거리 촬영은 **목표를 채택하기 전에** 기록과 대조하고, 맞지 않으면 그 자리에서 거부한다(`bottom_deck_target_mismatch`, stage `near`). 면제 여부와 관계없이 검사 켬의 모든 근거리 촬영에 적용한다.
  - 검사 끔, 원거리 촬영, 재관측, 근접 추적의 판정은 그대로다.
- **B:** `--near-capture-redraw always` 를 추가한다. 근접 추적이 켜져 있으면 `on` 과 같고, 꺼져 있으면 근거리 재작도를 허용하되 보정점 검사는 하지 않는다.
  - 기본값 `on` 의 동작은 바뀌지 않는다.
  - 재정렬(`start_near_realign`)은 근접 추적 전용으로 남긴다.
- **A:** 원인 분리 진단까지만 한다. 고치기는 결과를 보고 따로 정한다(D5 와 겹치지 않게).
- **범위 밖:**
  - 검사 끔의 lower 문턱, 검출기 평면 맞춤, 깊이 목표(330 mm), 상자 0.05 rad, D5.
  - 앞 밑판만 파손된 팔레트: 옆면 판정은 앞 밑판을 보지 않는다. 지금의 lower 도 이를 가리지 못했다(아래 위험).

## 3. 작업

### 작업 C — 검사 켬 근거리 촬영: 채택 전 기록 대조와 lower 면제

1. 검출기
   - `detect_pockets(scene, prior, params, *, lower_evidence=True)` 키워드 인자를 둔다. 명시적 bool 만 받는다.
   - `False` 면 `evidence_failed` 의 최솟값에서 `lower` 를 뺀다. 거절 기록의 `failed_items`·`evidence` 에는 lower 수를 그대로 남긴다.
   - `DetectorParams` 는 바꾸지 않는다. `asdict(params)`·근접 추적 측정 조건 비교(`near_tracking.py` 1216행)·러너 검사(3759행)가 그대로 맞게 하려는 것이다.
2. 미션 core `capture_and_detect`
   - 근거리 촬영(`near_capture.status == "pending"`)이고, `bottom_deck_on()`, `state["bottom_deck"]["status"] == "done"`, 기록 verdict `present` 이면 `lower_evidence=False` 로 검출한다.
   - 시도 기록에 `"lower_evidence": false` 와 그때의 lower 수를 남긴다.
   - 러너의 검출기 훅(`run_transport.py` 5086행 `lambda *a: detect_pockets(*a)`)이 키워드를 넘기도록 고친다. 경계 기록 함수(`recorded_function`)를 거치는 호출도 키워드를 기록·전달하는지 확인한다.
   - 최상위 `detector_params` 는 그대로다.
3. 미션 core `observe_succeeded`
   - 검사 켬이고 근거리 촬영이면 목표 채택(`set_inset_estimate`·`planning_target`) **전에** 기록과 대조한다. 대조는 `bottom_deck_permit.insert_refusal`(같은 형상·중심 0.15 m·진입축 15°)로 한다.
   - 맞지 않으면 `_bottom_deck_refuse(..., "bottom_deck_target_mismatch", stage="near")` 로 끝낸다. 이때 `planning_pickup`·`known_pallet`·경로는 바뀌지 않아야 한다.
   - 대조 결과는 `deck["near_check"]` 에 남긴다. 삽입 게이트는 그대로 둔다(이중 확인).
4. 기록을 읽는 도구
   - `diagnose_detection`: 선택한 시도의 `lower_evidence` 가 있으면 그 값으로 다시 검출하고, 후보를 다시 만드는 `_opening_candidates` 호출(434행)에도 같은 값을 준다. 없는 옛 기록은 `True` 로 읽는다.
   - 이를 위해 `_opening_candidates` 도 `lower_evidence` 키워드를 받는다(검출기 내부와 같은 기준).
   - boundary replay: `bottom_deck_check=on` 기록을 지금처럼 거부한다. 지원 확장은 범위 밖이다.
   - 밑판 기록의 `params_sha256` 는 `BottomDeckParams` 해시로 그대로 둔다(면제는 시도 기록이 나타낸다).
5. 시험(먼저 실패 확인)
   - 키워드 검증(bool 만).
   - 리그 진짜 팔레트 x 2.0 양자화 장면: 기본은 `no_pallet`, 면제는 `valid`.
   - 면제해도 supports·upper·폭 검사가 남는다(blocks 장면은 여전히 `no_pallet`).
   - core: 면제 조건(`bottom_deck_on`, `done`, `present`, 근거리 pending)의 참·거짓 조합. 검사 끔과 재관측(`returning`)에서는 면제하지 않는다.
   - core: 기록과 0.30 m 다른 근거리 후보 → 채택 전 거부, `planning_pickup`·`known_pallet`·`plan_transport` 호출 없음. 맞는 후보 → 지금처럼 진행.
   - 기존 `detector_params` 기록·근접 추적 조건 비교가 바뀌지 않는다.
   - `diagnose_detection` 이 면제 시도를 그 설정으로 다시 검출하고 `selection.replica_matches` 가 참이다(Codex 2차 탐침: 검출만 면제하면 `selection_replica_mismatch`).
   - 러너 훅을 그대로 거치는 면제 호출 시험(지금 람다는 `TypeError`).
6. 검증
   - 저장 근거리 20 장 재생: 면제 조건을 흉내 내어 지금 `valid` 18 장이 바뀌지 않고, `f_real_on_s2` 가 회복되고, `f_real_off_s3` 는 끔이라 그대로인지 본다.
   - 리그 음성 구조 × 거리에서 면제가 바꾸는 판정 수를 기록한다(면제는 옆면 `present` 뒤에만 적용되므로 판정 기준이 아니라 기록이다).
   - Isaac 검사 켬 실행으로 사이클을 확인한다.
   - 근거: 판정 문턱 자체는 바꾸지 않으므로 eval2·ADR 0004 D6 의 평가 대상이 아니다.

### 작업 B — `--near-capture-redraw always`

1. 러너
   - 선택지에 `always` 를 추가한다.
   - `--near-tracking` 요구는 `off` 에만 남긴다.
   - `--near-capture-box-yaw-rad`(좁히기만, (0, 0.05])는 지금 `--near-tracking` 을 요구한다(1098행). `--near-capture-redraw always` 와 함께면 근접 추적 없이도 허용한다. 검증에서 재작도를 강제하는 데 쓴다.
   - 근접 추적 계약은 이미 이 인자를 실행별 인자로 둔다. 새 등록은 필요 없다(Codex 1차 확인).
2. core 재작도 조건
   - `on`: 근접 추적이 있을 때 재작도(지금 그대로).
   - `always`: 근접 추적이 있으면 `on` 과 같고, 없으면 재작도한다.
3. 근접 추적 없이 `near_capture_redraw` 를 부르면 다음과 같이 한다.
   - `correction_points_check`·`held_pockets`·`tracking_frame` 을 건너뛴다.
   - 기록에 `"tracking": false` 를 남기고, 보정점 항목은 두지 않는다.
   - 재작도가 거절되면 재정렬로 넘어가지 않고 `require` 로 끝낸다(사유 보존).
4. S4 판정기
   - stage 1 허용 조건을 `near_capture_redraw in ("on", "always")` 로 넓힌다. 근접 추적 실행에서 `always` 는 `on` 과 같다.
   - 근접 추적 없는 실행은 판정기 대상이 아니다. 판정기가 그런 기록을 받으면 이름 붙은 오류로 거부하게 하고, 그 시험을 둔다.
5. 시험(먼저 실패 확인)
   - 인자 검증(`always` 는 근접 추적 없이 허용, `off` 는 요구).
   - core, 근접 추적 없음 + `always` + 상자 밖 0.054 rad → 재작도 호출·approach/insert/extract 설치, 보정점 검사 안 부름.
   - core, 근접 추적 없음 + 기본 `on` → 지금처럼 `require`.
   - core, 재작도 거절 → `require`(사유 보존), 재정렬 없음.
   - s4_judge: `always` 근접 추적 기록은 `on` 과 같은 판정이고, 근접 추적 없는 기록은 거부.
6. 검증(필수 완료 조건)
   - **재작도 수락:** Isaac 에서 `--near-capture-redraw always --near-capture-box-yaw-rad 0.01` 로 상자를 좁혀 재작도가 자주 일어나게 한다. 검사 켬·끔 각 3 seed. 좁힌 상자도 통과할 수 있으므로(예: yaw 0.009) **실제 `accepted` 재작도 기록과 설치된 경로가 있는 실행**이 생길 때까지 seed 를 늘리고, 그런 실행이 최소 3 개 있어야 완료로 본다.
     - 재작도한 접근의 hold 유지, 소품·팔레트와의 최소 여유(실제 궤적), 근거리 정지 도착 오차를 기록한다.
     - 삽입 종점 오차와 beyond_centre 를 기록한다.
     - 기본 접근 속도 0.60 m/s 와 `--approach-straight-speed` 지정 속도를 둘 다 본다.
   - **재작도 거절:** CPU 시험(core)으로 보인다. Isaac 에서 거절을 확실히 만드는 방법은 없어서 기록만 한다.
   - 기본 `on` 배치(근접 추적 없음)가 지금과 같은지: 같은 snapshot·seed 에서 재작도 기록이 없는지 본다.

### 작업 A — 접근 첫 선회의 오도메트리 과대계상 원인 분리(진단)

1. 도구 `tools/odom_drift_terms.py` 를 만든다. 먼저 `slam_log.npz`(바퀴 각속도·관절각·조향 관절각·truth 자세)와 기록 잡음으로 기록 오도메트리를 재현하고(최대 차이 0), 그 위에서 단계별로 나눈다.
   - 재현 조건(Codex 2차): 잡음은 접근 구간이 아니라 **로그 첫 샘플부터** 재생한다. 기록의 초기 후륜 자세·geometry·잡음 설정, 후륜 입력 `[2:4]`, 실제 stamp 간격, base↔rear 변환을 쓴다.
   - (i) 잡음 몫: 잡음을 넣은 적분과 뺀 적분의 차.
   - (ii) 보고 각속도 적분 ↔ 관절각 변화 × 반지름: 같은 바퀴의 두 입력이 어긋나는 몫.
   - (iii) 관절각 거리 ↔ truth 후륜축 이동: 바퀴가 실제로 굴러간 거리와 차체 이동의 차(미끄럼·접지 반지름).
   - (iv) 실제 조향 관절각 기반 yaw ↔ truth yaw.
   - 합산 잔차를 확인한다. 항이 서로 얽혀 가산으로 나뉘지 않으면 그 사실과 구간별 상한을 적는다.
2. 실행 17 개(검사 켬·끔)의 접근 구간에 적용한다. (ii)가 큰 구간에서 PhysX 관절 속도와 위치의 관계(보고 시점, 감쇠·구동 목표)를 살핀다.
3. 이 실행들은 타이어 접촉 기록(`--tyre-contact-log`)이 꺼져 있었다. (iii)의 원인을 접촉으로 가르려면 접촉 기록을 켠 재실행 몇 개가 필요하고, 필요하면 그때 돌린다.
4. 결과는 진단 문서로 쓰고, 고칠 방향(예: 오도메트리를 관절각에서 읽기, 팀 엔코더 모형으로 바꾸기)은 사용자 결정으로 넘긴다.

## 4. 순서와 시험

C → B → A 다. 각 작업은 시험 먼저 쓰고 Codex 구현 검토가 수렴한 뒤 다음으로 간다. pytest 는 ws1(`FORKLIFT_REPO=<worktree> ~/bin/forklift-ws1-pytest`), Isaac 은 ws1 Slurm `bd.sbatch` 로 돌린다.

## 5. 위험

- **C 면제의 근거:** 면제는 "옆면에서 밑판을 본 그 팔레트"가 근거리 목표라는 연결에 기댄다.
  - 연결은 위치·형상·진입축 대조(0.15 m·15°)뿐이다. 그 안의 같은 형상 다른 물체는 가리지 못한다(기존 한계, 거리 검사는 개체가 같다는 증명이 아니다).
  - 채택 전 대조로 기록과 다른 후보가 경로·지도에 들어가는 것은 막는다.
  - 리그에서 lower 만 면제하면 x 2.0 의 선반·grounded·밑판 없음이 `valid` 가 된다(Codex). 이는 옆면 판정이 그 자리를 `present` 로 본 경우에만 문제가 되고, 옆면 평가에서 음성 `present` 는 0/299 였다(시뮬 모집단 조건부).
- **앞 밑판 파손:** 옆면 판정은 앞 밑판을 보지 않는다. 지금의 lower 도 판별력이 없었으므로 면제로 새로 잃는 보호는 없다. 다만 "앞 밑판이 있다"는 보증도 여전히 없다.
- **C 기록 계약:** 시도 수준 기록과 `diagnose_detection` 만 바꾼다. boundary replay 는 검사 켬 기록을 계속 거부한다.
- **B 기본값 보존:** `always` 는 명시할 때만이다. 근접 추적 실행에서 `always` 는 `on` 과 같고, 판정기도 그렇게 읽는다.
- **B 재작도의 안전 근거:** 재작도는 `redraw_docking` 의 검사에 기댄다. 근접 추적 없는 접근에는 보정·보호 예측·정지가 없고, hold 오도메트리로 달린다. 재작도로 선회가 늘면 A 의 과대계상이 늘 수 있다(Gemini 독립 검토). 그래서 검증에서 도착·삽입 오차와 실제 여유를 필수로 잰다.
- **A 진단:** 시뮬 접촉·관절 보고 모형의 성질일 수 있다(실차 타이어 미측정). 실차로 일반화하지 않는다.
- **시뮬 일반화(Gemini):** 근거리 깊이는 잡음 없는 렌더(1 mm 양자화)다. 실제 D435i 잡음에서 면제·재작도의 결과는 따로 확인해야 한다. 이번 결과는 파이프라인 논리 검증으로 한정한다.

## 6. 자체 검토 — 직접 재계산

1판에서 원자료로 다시 확인한 것:
- **리그 표:** 원 출력(`refit_probe.py`)에서 다시 셌다. 진짜 3/8 탈락(0·2·14), 선반 7/8 통과(15–98), grounded 6/8 통과(28–88). 밑판 없음은 처음에 5 칸으로 적었으나 다시 세니 4 칸(18–43)이라 고쳤다. 재적합 칸(진짜 x 2.0: 미양자화 0→50, 양자화 2→0)도 확인했다.
- **근거리 lower:** valid 18 장의 값 23·26·24·49·22·51·42·46·38·28·45·35·38·54·26·30·20·35 → 20–54. 실패 0·13. 문턱은 round(100·0.39²) = 15.
