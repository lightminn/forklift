# 실측 차체 재검증 — 계획 (2단계)

작성일: 2026-10-01 · 개정 같은 날(독립 검토 반영, 아래 자체 검토 절)

## 요청

사용자(2026-10-01): 다음 작업 선택지 1–5 를 진행하고 단계마다 Codex 교차검증이 수렴할 때까지 진행. 2단계는 "실측 모델로
계획기·A–D·운반 seed 재검증". 뒤차축 중심 최소 회전 반경이 1.580 → 2.728 m(1.73 배), 계획기 반경이 2.000 → 3.448 m 로 바뀌어
기존 성적은 모두 잠정 모델 기준이다.

## 조건 — 무엇이 함께 바뀌는가

"차체만 바뀐 비교" 가 아니라 **"차체와 그에 대응하는 설정을 바꾼 비교"** 다. EPAL 6 기준(URDF·현재 코드에서 재계산):

| 조건 | 곡률 계획/추종 | 여유 | 삽입 목표 | 적재 footprint 앞 | 무부하 footprint | 비고 |
|---|---|---:|---:|---:|---|---|
| **P** 잠정 | 0.50 / 0.62 | 0.046 | 0.360 | 1.530 | 1.29 / 0.17 / 0.36 | `isaac_transport.yaml` |
| **M** 실측 진단 | 0.29 / 0.36 | 0.016 | 0.330 | 1.560 | 1.29 / 0.17 / 0.36 | `isaac_transport_measured.yaml`, 진단 여유 |
| M-κ 민감도 | 0.32·0.36 / 미실행 | 0.016 | 0.330 | 1.560 | 같음 | R1(CPU 계획)만. 추종 비율을 유지하면 0.397·0.447 로 실측 URDF 구동 한계 0.3665 를 넘으므로 동적 실행은 하지 않는다 |

- **무부하 footprint 는 두 조건 모두 같은 추정값이다.** 차축–포크 끝 1.29 와 뒤 0.17 은 추정 배치이고, 반폭 0.36 은 잠정 기하에서
  나온 값이다(실측 기하로는 조향 바퀴 외곽 약 0.336 m — 0.36 이 여전히 감싸므로 보수적으로 둔다). 그래서 M 의 차이는 **곡률과
  삽입 목표**에서 온다. 결과를 "실측 차체 성적" 이라 부르지 않고 "실측 반영 조건" 이라 쓴다.
- **M 의 곡률 0.29 자체가 미확정이다**(15° 를 두 바퀴 한계로 둔 해석). 바깥 바퀴·자전거 모델 해석의 반경에 같은 79 % 를 적용하면
  약 0.36 · 0.32 → R1 에서 민감도로 함께 낸다.
- **여유는 진단값**(1단계 seed 0 한 번의 결과). 모든 표에 여유를 적고, 결론에는 "정책 여유 0.046 에서는 미검증" 을 적는다.
- P 에 같은 여유 0.016 을 줘도 목표는 깊이 × 0.6 = 0.360 에서 잘려 바뀌지 않는다(잠정 한계 0.406) — 별도 조건이 필요 없다.

## 작업

### R1. CPU 계획 — `tools/bay_planning_sweep.py`(신규)

- 기본 구역 7.7 × 4.8 m, 자산은 `sim/isaac/factory_assets.py` 오프라인 전체 정밀도 치수 중 **기본 구역 세 자산만 기존 순서로**,
  공장 전용 운반 휴리스틱은 쓰지 않는다(run_transport 의 bay 경로와 같음).
- 인자: `--seeds`, `--settings`, `--forklift-urdf`(차축–포크 끝·캐리지 한계), `--insertion-reserve-m`, `--curvature`(민감도
  덮어쓰기, 기록), `--scene-from`(장면 생성 조건; 기본 = 계획 조건), `--return-home`, `--max-expansions`, `--timeout-s`.
- **장면 동일성.** 같은 seed 라도 적재 footprint 예약 때문에 조건마다 장면이 달라질 수 있다. 각 seed 의 장면 해시를 남기고,
  P 와 M 의 해시가 다른 seed 만 P 장면을 M 으로 계획한 교차 결과를 추가한다(Codex 사전 계산: seed 0–199 에서 P 와 M 진단은 장면이
  모두 같고, 정책 여유 M 은 seed 109 만 다르다). 장면 생성 실패(ValueError)는 `scene_failure` 로 센다.
- **단계별 진단.** `MissionPlan` 은 어느 단계든 실패하면 경로 필드를 비운다. `plan_transport` 에 선택 인자 `trace: list | None`
  을 두어 **탐색 구간과 덧붙이는 직선 구간을 따로** (이름, 상태, 길이, 확장 수, 기어 전환 수)로 실패 지점까지 남긴다 — 예:
  `approach_search` 성공 뒤 `approach_straight` 실패. 기본 None 이면 동작 불변이고, trace 를 켜도 반환 경로·상태가 같아야 한다
  (시험). 자식 프로세스는 기록을 단계마다 JSON 줄로 파일에 덧붙여, 시간 초과로 끝나도 완료된 단계 기록이 남는다.
- **실행 관리.** seed 마다 별도 프로세스·시간 제한(`timeout`·`crash`·`planning_failure` 구분), seed 하나 끝날 때마다 원자적 저장,
  입력 해시 기반 재개. 먼저 0–24 로 시간을 재고 같은 조건으로 199 까지 늘린다. 200 개는 개발 진단 집합이다.
- **예산 진단.** `expansion_limit` 실패 seed 는 확장 한도 100,000 으로 한 번 더 계획해, 탐색 예산 부족과 미발견을 가른다.
  `no_path` 는 "해당 설정·해상도에서 미발견" 이지 물리적 불가능의 증명이 아니다(`hybrid_astar.py:383`). 곡률이 줄면 primitive
  당 방향 변화(0.25 × κ)가 방위 해상도 10° 대비 0.72 → 0.42 배로 작아진다 — 실패가 늘면 이 이산화 효과를 의심하고 기록한다.

### R2. A–D 차체 규모 배치 — `tools/chassis_ad_cases.py`(신규)와 기록

기존 A–D 시험은 차체와 무관한 일반 기하(footprint 0.55 · 곡률 1.0)다. 배치는 **결과를 보기 전에** 계획기 반경 R 로 정의하고,
**R_P = 2.000 기준 배치 4 개와 R_M = 3.448 기준 배치 4 개를 각각 P·M 두 계획기로** 계획한다(16 회). 무부하 접근만 본다:
`plan_hybrid_astar` 직접, footprint 1.29/0.17/0.36, 여유 0.10, 임무 설정과 같은 primitive 0.25 m·확장 30,000, 기본 구역 경계,
후륜축 자세, 시작 (−2.34, 0, 0).

| 사례 | 배치(R 은 기준 반경) |
|---|---|
| A | 목표 (1.5, 0, 0) |
| B | 측방 Δy = 0.72 m. L = √(4RΔy − Δy²) + 0.8(반경 R 원호 두 개로 이은 참조 경로의 종방향 + 마지막 직진). 목표 (−2.34 + L, 0.72, 0) — R_P 0.749, R_M 1.528 |
| C | 목표 (−2.34 + L/2, 0.72, 0) — R_P −0.795, R_M −0.406. 그 거리로는 위 참조 경로가 성립하지 않는다 |
| D | C 와 같은 시작·목표, 후방 장애물 0.15 × 0.8 m(yaw 0) 의 **앞면이 차체 뒤끝(x −2.51)에서 0.30 m 뒤**(앞면 x −2.81, 중심 −2.885, 뒷면 −2.96 으로 구역 안) |

기록: 상태, 첫·마지막 기어, 기어 전환 수, 최대 yaw, 경로 길이, 확장 수, D 는 경로 전체에서 차체–장애물 최소 간격. **브리프의
기대 동작(A 직진, B 정지 없는 곡선, C 후진 후 진입, D 제한된 후퇴 또는 재배치)과 다르면 발견으로 적는다** — Codex 사전 계산에서
현재 계획기는 C 를 처음부터 후진하지 않는다(P 배치: 전진 시작·후진 종료; M 배치를 P 계획기로: 전진 → 후진 → 전진, 기어 전환 2 회). 계획기에는 목표 진입
기어 계약이 없으므로 이것은 계획기 행동의 발견이지 시험 실패가 아니다. 성공하는 좌표를 찾아 바꾸지 않는다. 시험
(`tests/scenarios/test_chassis_scale_ad.py`)은 배치 계산(B·C 좌표, D 장애물이 구역 안), A 가 두 계획기 모두에서 전진만인지, 도구가
16 행을 내는지만 단정한다.

### R3. Isaac 운반 — 현재 코드로 P 와 M 각 25 회

9/23 기록(25 개 중 8 개 완주)은 그 뒤 추종 허용치(복귀 30 mm, 기어 전환 30 mm·0.05 rad, 초과 30 mm)가 바뀌어 대조군이 아니다 —
**같은 현재 코드로 P(잠정 base scene·URDF·설정)와 M(실측 base scene·URDF·설정·여유 0.016)을 seed 0–24, 기본 구역, 복귀 포함,
영상 없음, 정답 좌표로 각각 돌린다**(50 회). 9/23 결과는 역사적 참고로만 쓴다.

- **장면 동일성.** 두 base scene 은 같은 창고 USD(`Simple_Warehouse/full_warehouse.usd`)를 참조한다(ws1 확인). 기존 장면에는
  `/World/Forklift` 아래 구동 설정 덮어쓰기가 있었으나 실행기가 시작 때 모든 관절의 구동 방식·강성·감쇠·최대 힘과 articulation
  반복 수를 다시 설정하므로(`scene.py:393–430`) 동작에 영향이 없다. 남은 차이는 저장된 속도 같은 상태값과 렌더 설정뿐이다.
  저장된 속도가 `world.reset()` 뒤에도 남는지는 코드로 확인되지 않으므로, reset 직후와 120 스텝 안정화 뒤 **계획 전에** 차체 선속도·
  각속도·관절 속도를 기록해 P·M 의 실제 값을 비교한다(0 여부로 판정하지 않는다 — 1단계 9 실행의 첫 표본 전방 속도는 모두
  0.0000446 m/s 로 같았다). 실행마다 `scenario.json` 해시를 남겨 P·M 의 seed 별 장면 동일성을 확인한다.
- 집계: 완주 여부·실패 단계와 사유, 삽입 계측(1단계), 들기 최대 기울기, 복귀 오차.

## 범위 밖

T11 운반(1단계 경계가 너무 좁음), 인식 사용 임무(4단계 정리 뒤), 공장 홀, 정책·추종 허용치 변경, 차체 footprint 실측 반영.

## 완료 기준

1. R1·R2 도구·시험 통과, `plan_transport(trace=None)` 동작 불변, 기존 시험 새 실패 없음, Ruff.
2. R1: P·M·M-κ(0.32, 0.36) × seed 0–199 결과와 조건별 완료·시간 초과·장면 실패 수, 예산 진단. R2: 배치 8 × 계획기 2 의 상태·동작과 브리프 기대 동작과의 차이.
   R3: P·M × 25 의 완주·실패 사유와 장면 해시 확인.
3. 결론은 "실측 반영 조건, 진단 여유" 로 한정해 쓴다.

## 자체 검토

**① 직접 재계산.** 반경 1.580 → 2.728 m(1.727 배), 계획기 2.000 → 3.448 m. 적재 앞 길이 P 1.530 · M 1.560. 기본 구역 7.7 × 4.8 m.
ws1 두 base scene 의 창고 참조가 같음과 기존 장면 덮어쓰기의 내용을 확인했고, 실행기가 덮어쓰는 항목을 `scene.py` 에서 확인했다.

**② Codex 적대적 검토.** 수정 필요 6 건 반영: 9/23 대조군 부적합(→ R3 현재 코드로 P·M 50 회), R2 가 모든 실패를 통과시키고
배치가 임의(→ R 기준 사전 정의·기대 동작·쌍으로 된 C/D), 교차 조건의 구현과 중복(→ 해시가 다른 seed 만), 실패 단계 통계 소실
(→ trace), 실행 시간·재개(→ 프로세스별 제한·저장·재개), 창고 동일성(→ 확인 완료·장면 해시). 수치 정정(1.73 배).

**② Codex 2차(개정본).** 6 건 반영: R2 공통 배치 vs 조건별 배치 충돌(→ 두 기준 × 두 계획기 16 회), C 가 처음 후진을 보장하지 않음
(→ 발견으로 기록, 단정하지 않음), D 장애물 정의 부족·구역 이탈(→ 크기·기준점·위치 고정), M-κ 추종 곡률이 구동 한계 초과(→ 미실행),
trace 의 합성 단계·시간 초과 계약(→ 구간별 기록·JSON 줄), 저장 속도 초기화 근거(→ 첫 표본 속도 확인).

**③ Claude 서브에이전트 독립 검토(Codex 결론 비공개).** 8 건 반영: 함께 바뀌는 변수(→ 조건표), "실측 footprint" 가 실제로
잠정값(→ 명시), 옛 코드 기준선(→ R3), 같은 장면 제한의 선택 편향(→ 각 조건 자체 장면 + 해시 다른 seed 교차), A–D 를 반경 기준으로
(→ R2), 이산화·예산과 차체 한계 혼동(→ 예산 진단), 곡률 0.29 미확정(→ M-κ), 진단 여유 결론 혼입(→ 표·결론 표기).
