# 원거리 단계를 지시 대상에 묶기 — 재집기 대상 선택 (총괄 2026-10-28)

관련: `docs/validation/2026-10-28-adoption-zone-path-margin.md`(8a 측정), `docs/plans/2026-10-28-adoption-zone-check.md`. 총괄 결정: 콘솔 경로 재집기 결함(과제 1)과 칸이 붙은 배치의 재집기(과제 2)를 한 계획으로 묶는다. 진단과 계획을 먼저 올리고, 수정 뒤 같은 12 세션 구성으로 재집기와 구역 검사의 재집기 단계를 함께 확인한다. 콘솔(대기열 auto·TargetsBook)과 계획 단계에서 맞춘다.

## 2. 고칠 것

### F1. 인식 끔의 원거리 관측에 기대 위치 (D1)

- **적용 범위:** 인식 끔(`--recognition off`)의 원거리 캡처(`capture_and_detect` 의 원거리 갈래)에서, `detect_pockets` 대신 `detect_pockets_expected` 를 부른다.
  - 옆면 검사 뒤의 복귀 관측(`bottom_deck_returning`)에는 적용하지 않는다. 그 관측은 자기 재시도 계약(recognition 의 `reobserve` 사유)과 기록 대조(중심 0.15 m·축 15°)를 이미 갖고 있고, `no_expected_candidate` 를 넣으면 남은 관측 자리가 있어도 바로 `bottom_deck_reobservation_failed` 가 된다(Codex P2, CPU 재현).
  - 인식 켬은 이미 지시 반경으로 묶여 있으므로 바꾸지 않는다(F2).
- **기대 위치:** 이번 미션의 채택 사각형을 쓴다(구역 검사 2 절의 지도 좌표 사전 정보). 캡처 때 SLAM 해제 뒤 확정된 base·yaw 로 base_link 에 옮긴다(근거리 기대 위치와 같은 변환).
  - 중심 = 사각형 중심.
  - 반경 = **"사각형 + 여유"의 외접원**: hypot(반폭 + m, 반높이 + m). 구역 검사가 축별로 m 까지 허용하는 자리를 모두 덮어야 하기 때문이다(Codex P2: 반대각선 + m 이면 구역 검사는 통과할 후보가 원 밖으로 떨어진다). 0.5 × 0.5 m 구역, m 0.10 이면 0.495 m. 재집기 0.2 × 0.2 m 정사각형이면 0.283 m. 칸 간격의 절반(line_m 0.53 m, random_m 0.64 m)보다 작다.
  - 원은 사각형 + 여유보다 넓다. 그래서 원 안이지만 사각형 + 여유 밖인 추정은 이 단계에서 `no_expected_candidate` 로 다룬다. 그 관측은 실패하고 다음 관측 자리로 간다. 원거리 추정이 채택된 뒤 구역 검사로 미션이 끝나는 일은 이 경로에서 없게 한다(agy).
  - 축 = 사각형의 yaw 중심 ± (yaw 반폭 + 5°).
    - 처음 자리: 세션은 `SessionZone.yaw_centre_rad`·`yaw_half_rad`, 배치는 `PickupZone` 의 0 중심·`yaw_half_rad` 를 쓴다(PickupZone 은 0 중심 범위다).
    - 재집기: `put_down_pose.yaw` ± 15°.
    - 이를 위해 `AdoptionZone` 에 yaw 중심·반폭을 더한다. 구역 검사의 판정에는 쓰지 않는다(기록만).
  - 배치 실행의 `scenario.pickup` 은 truth 이므로 쓰지 않는다.
  - 사각형이 없으면(구역 검사의 `adoption_zone_undefined` 경우) 원거리 캡처도 그 사유로 미션을 끝낸다. 검사 끔이어도 F1 이 켜져 있으면 같다.
- **안에 후보가 없으면:** `no_expected_candidate` 다. 그 관측은 실패하고 관측 사다리의 다음 자리로 간다. 모두 실패하면 미션이 `perception_no_pallet` 으로 끝난다. 이웃을 채택하지 않는다. 원거리 캡처의 `expected` 기록(후보·안/밖)을 시도 기록에 남긴다.
- **ID 대조(콘솔과 합의):** 비전 결과에는 ID 가 없다. 원거리 단계를 미션 팔레트 ID 의 TargetsBook 자세에 묶는 것을 위치로 하는 대조로 삼는다. 처음 자리는 등록 자세·구역, 재집기는 `put_down_pose` 다. 사각형은 준비 때 고정되고, 미션 안의 해제 때는 구역 검사와 같은 규칙으로 다시 표현된다.
- **인자:** `--far-capture-expected {off,on}`(기본 off). 근접 추적 계약에는 **`POST_MEASUREMENT_ARGUMENTS["far_capture_expected"] = "off"`** 로 등록한다. 채택 대상과 그 뒤 경로를 바꾸므로 측정 조건이다(Codex P2: RUN_SPECIFIC 이면 on/off 차이가 비교에서 사라진다). 운영 런처는 4 의 확인 뒤 on 으로 한다.
- **전제(적어 둔다):**
  - `put_down_pose` 는 하역 목표(도킹이 맞춘 목적지)이지 하역 뒤 관측한 위치가 아니다. 8a 의 재집기 검사에서는 원거리 추정이 그 정사각형 안에 있었다(최대 `edge_m` −0.07).
  - 하역한 팔레트를 사람이나 다른 차가 옮기면 기대 위치가 틀린다. 그 경우는 거부(`perception_no_pallet`)로 끝나고, 대기열은 멈춘다(운영자 개입).

### F2. 원거리 인식 켬 — 바꾸지 않음

line_m 의 `uncertain_in_radius` 는 막힌 배치에서 옳은 동작이다. random_m 에서는 원거리 단계가 맞았다. 반경을 바꾸는 근거가 없다.

### F3. 막힌 수동 재집기의 사전 거부 — 콘솔 세션 담당

콘솔 세션이 맡는다. 사유는 `reject(blocked)` 이고, `detail` 에 막는 쪽을 싣는다(예: `pickup:D-2`, `delivery:P-3`). 표기는 `next_pick` 의 blocked 목록과 같다. 범위는 `mission_submit` 의 pallet_id 가 delivered(재집기)일 때만이다. 정본은 `docs/interfaces/2026-10-13-operator-console-contract-draft.md` 의 mission_submit 행이다. 이 계획과는 별개로 진행한다.

### D2·D3 진단 (수정 전)

- D2: s2 와 s1 의 근거리 캡처에서 depth 를 비교한다(`perception_capture_2_depth_m.npy`, 대상 앞면 영역의 유효 픽셀·평면 잔차). 그리고 검출기 진단(`rejected_plane_reasons`, `opening_rays`)을 대조한다. 가설 하나: 검출기는 기대 위치 필터 전에 화면 전체에서 평면을 `max_plane_candidates`(8) 개만 뽑는다(`pocket_detector.py:74`). A-off s2 는 후보 평면이 8 개로 상한에 닿았다. 그래서 대상 앞면이 상위 8 개에서 밀렸을 수 있다(agy). 원인이 나오면 별도 항목으로 올린다.
- D3: 관측 추종 실패 두 건의 경로·추종 기록을 본다. 재집기와 관계가 있는지만 먼저 가린다.

## 3. 시험 (먼저 쓴다)

1. **원거리 기대 위치 만들기:** 사각형 중심·외접원 반경·축 허용이 위 규칙대로 나와야 한다.
   - 다룰 경우: 처음 자리, 재집기, 장면 없음(BAY), 사각형 없음(`adoption_zone_undefined`).
   - 처음 자리 yaw 가 0 이 아닌 경우와 ±π 경계를 넣는다.
   - SLAM 해제 뒤 base 로 옮기는 변환을 넣는다.
   - Codex 반례 두 개가 통과해야 한다. 구역 모서리 `(0.349, 0.349)` 와 재집기 `(0.199, 0.199)` 다.
2. **미션 코어:** `--far-capture-expected on` 이고 인식이 꺼져 있을 때를 본다.
   - 원거리 캡처가 `detect_pockets_expected` 를 부른다.
   - 이웃만 보이면 `no_expected_candidate` 로 그 관측이 실패하고, 관측 사다리의 다음 자리로 간다.
   - 원 안이지만 사각형 + 여유 밖이면 같은 실패로 다룬다(구역 검사로 미션이 끝나지 않는다).
   - 옆면 복귀 관측에는 적용되지 않는다.
   - 끔이면 지금과 같고, 포트 호출 순서도 같다(재생 게이트).
3. **러너 인자 등록:** `POST_MEASUREMENT_ARGUMENTS["far_capture_expected"] = "off"`. off 기록과는 맞고, on 은 옛 측정 조건과 다르다고 거부되는지 시험한다.

## 4. Isaac 확인 (판정 규칙은 결과 전에 고정)

- 팔: 8a 와 같은 A-far·A-off(위치 추정·team-spec), `--far-capture-expected on`, `--adoption-zone-check on`(경로 기본 여유).
- **재집기 가능한 대기열:**
  - line_m `P-1:D-1,P-1:D-2,P-2:D-3`. D-1 에 놓은 P-1 을 D-2 가 빈 채로 다시 집는다. D-2 로 옮긴 뒤 P-2 는 맨 앞 D-3 에 놓는다.
  - random_m `P-4:D-1,P-5:D-2,P-4:D-3`. 이웃은 옆에 있다.
  - seed 6·7·8(8a·8b 와 겹치지 않음)로 12 세션을 돈다.
- **막힌 대기열 회귀(A-off 만):** line_m `P-1:D-1,P-2:D-2,P-1:D-3` seed 6–8 의 3 세션.
  - **F1 성공**은 다음 셋이 모두 기록에 있을 때만이다: m3 의 원거리 캡처에 도달했고, `expected` 기록이 남았고, 이웃(P-2 자리) 후보가 그 기록에서 밖(`inside: false`)으로 걸러졌다.
  - 구역 검사의 거부만 있는 실행은 F1 성공으로 세지 않는다. 8a 의 세 건은 F1 없이도 `edge_m` 0.96 m 라서 m 0.10 의 구역 검사만으로 거부된다(Codex P2).
  - 콘솔 사전 거부(F3)로 캡처에 도달하지 않은 실행도 F1 성공으로 세지 않는다.
  - P-2 를 채택하면 F1 실패다.
- **판정**(모두 기술 통계다. 대기열·seed 가 8a 와 달라서 F1 의 효과만 떼어 낼 수 없다 — Codex P3):
  - 재집기 집계는 미션 순번이 아니라 `put_down` 사각형을 쓴 미션으로 한다. line_m 새 대기열의 재집기는 m2 다.
  - 재집기 완료 수와 실패 사유를 적는다. 실패가 D2(근거리 `no_expected_candidate`)·D3(관측 추종 실패)로 나면 따로 센다.
  - 지시된 팔레트의 오거절 0. 대상은 구역 검사 8b 의 0.50 m 규칙으로 가른다. 0.50 m 를 넘지만 다른 물체 위치와 맞지 않으면 판정 불가다(올바른 거절로 세지 않는다).
  - 막힌 대기열 회귀에서 F1 성공 3/3.
  - 구역 검사의 재집기(`put_down`) 단계: **도달한 세션 3 개 이상**, 그 검사에 판정 불가 0, 오거절 0 이면 그 단계를 확인한 것으로 본다. 모자라면 운영 런처 기본 on 은 미루고 재집기 표본을 늘린다(agy).
- 크기: live 묶음, 15 세션.

## 5. 남는 위험

- F1 은 기대 위치 안의 다른 물체를 막지 못한다. 사각형 + 여유 안의 이웃이나 다리형 선반이 그런 경우다(현장 규칙 전제).
- D2·D3 는 원인을 모른다. 재집기 완료율을 F1 만으로 올린다고 기대하지 않는다.
- 막힌 칸의 재집기는 F1 이 이웃 채택을 막을 뿐 해결하지 않는다. 관측 자리를 다 쓰고 끝나며, 대기열은 멈춘다. 이런 요청을 미리 거부하는 것은 F3 이다.
- 여유 0.10 m·기대 위치는 Isaac 값이다. 실차의 D435i 깊이 잡음, 카메라 외부 파라미터, 오도메트리에서는 다시 잰다. 실차에서도 근거리 캡처는 기하 검출기를 쓴다.

  - 반영한 것: 원과 사각형의 불일치(원 안·사각형 + 여유 밖은 관측 실패로), 재집기 축 허용 ±5° 가 너무 좁다(±15° 로), D2 의 평면 상한 가설, 재집기 단계 확인 기준(1 세션 → 3 세션), `put_down_pose` 가 관측값이 아니라는 전제와 사람이 옮긴 팔레트(5 절·F1 전제), 막힌 대기열 회귀가 거부만 본다는 점(F1 성공 조건), 실차 차이(5 절).
  - 반영하지 않은 것: "준비 때 고정한 사각형이 미션 안의 SLAM 해제로 어긋난다." 구역 검사와 같은 다시 표현 규칙을 따르고, 8a 의 재집기 검사가 모두 사각형 안(최대 `edge_m` −0.07)이었다. 확인 실행에서 다시 본다.
