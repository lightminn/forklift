# 온라인 SLAM 위치 폐루프 — slam_toolbox 를 Isaac 주행에 붙인다 (5·6순위 선행 실증, 계획 v2)

작성일: 2026-10-04 · 상위: [현황과 다음 단계](2026-09-17-project-status-and-next-steps.md) 5·6순위, [로드맵](2026-09-11-development-roadmap.md) M4,
[공장 홀·Isaac SLAM 기록 초안](2026-09-26-factory-hall-and-isaac-slam.md)(오프라인 재생)

## 요청과 범위

사용자(2026-10-04, `/goal`): "우리가 계획했던 진짜 SLAM 을 구현하고 isaac 심에 붙인 뒤 시뮬레이션 영상 성공적으로 렌더링할 때까지 계획서 내용을 따라가며
진행, 중간 단계·계획서마다 Codex 교차검증 수렴".

**지금(9/26 초안):** Isaac 이 2D LiDAR 스캔·바퀴·조향·정답 자세를 기록하고, 주행이 끝난 뒤 ROS 2 컨테이너의 slam_toolbox 가 그 기록을 재생했다. 주행은
**시뮬레이터 정답 자세**로 돌았고 SLAM 결과는 로봇을 움직이지 않았다(현황 문서: "5순위 폐루프 아님").

**이 계획이 만드는 것 — 정확한 이름:** "**정답 장애물 지도·알려진 출발 자세를 쓰는 합성 온라인 SLAM 위치 폐루프 실증**". 주행 중 slam_toolbox 가 온라인으로
지도를 만들고 위치를 추정하며, **실행기의 모든 제어 입력(위치·속도·정지 판정·계획 출발점·인식 결과의 세계 변환)이 그 추정에서 나온다.** 정답은 물리·평가·
안전 검사에만 쓴다. 현황 5순위의 "정답 위치를 위치 추정으로 대체하고 그 영향을 평가" 와 6순위의 "LiDAR SLAM 으로 지도 작성과 위치 추정을 연결" 의 **선행 실증**
이다. 5·6순위나 로드맵 M4 의 **완료가 아니다** — 남는 것: LiDAR 장애물 지도의 계획기 연결(5순위), 기존 지도 기반 위치 추정·재기동·위치 소실·지도 변경
(6순위), 동적 장애물·정지 계약(M4). (Codex 검토 10.)

**범위 밖(명시):** 계획기 장애물은 시나리오가 아는 사각형이다 — LiDAR(높이 1.05 m)는 그 평면 아래 물체(드럼 0.90 m, 바닥 팔레트, 기존 구역 소품)를 보지 못해
SLAM 지도만으로 계획하면 부딪힌다(로드맵 §7). 팔레트 인식 경로·카메라 장착(legacy)·목적지는 지금 main 그대로. factory 배치에서는 실행 중 관측점 생성이 꺼져
있다(배치 구역이 다르다).

## 설계

### 구성 — 한 Slurm 작업, 두 프로세스, 락스텝

```
Isaac 실행기 (ws1 venv, GPU)                          ROS 2 컨테이너 (forklift/ros2-dev:jazzy, --network none)
  모든 물리 스텝 = step_world():                        forklift_ros.isaac_slam_bridge (새 노드, 멀티스레드 executor)
    물리 1 스텝 → 오도메트리(120 Hz, 잡음) →             소켓 스레드 ↔ ROS 스레드
    물리 tick 12 마다 스캔 → SCAN 메시지 ──유닉스 소켓──▶   /clock, /tf(odom→base_link), /odom, /scan  @t_k
    ◀── MAP_ODOM(scan_id, t_k, 상태, 보정, 버전) ────────   /pose(@t_k) 를 기다려 map←odom = /pose ∘ (odom←base @t_k)⁻¹
                                                        slam_toolbox (online_sync_launch, lifecycle autostart, use_sim_time)
```

- **연결:** 실행기와 컨테이너는 출력 폴더에 바인드 마운트한 **유닉스 소켓**으로만 잇는다. ROS 노드는 모두 한 컨테이너 안이므로 `--network none` 으로 DDS 를 격리한다
  (병렬 작업끼리 도메인·포트가 섞이지 않는다 — 검토 ③). 컨테이너 이름은 작업 ID 로 정하고 EXIT trap 에서 `docker rm -f`, `--cpus 2 --memory 4g`,
  `--group-add 2000`.
- **응답 계약(두 검토의 P0 — TF 존재로 락스텝을 풀지 않는다):** slam_toolbox 의 스캔 처리 문턱을 0 으로 둔다(`minimum_time_interval`·`minimum_travel_distance`·
  `minimum_travel_heading`, CHANGED). **사전 측정(ws1 작업 747, 9/26 seed 0 잡음 없는 bag 재생):** 스캔 2,454 개 중 `/pose` 2,451 개, **모두 스캔과 같은 stamp**,
  처리 지연 중앙값 약 14 ms·최대 0.145 s. 빠진 3 개는 **첫 스캔 직후의 2·3·4 번째**(초기 제외)다. 그래서 브리지는:
  - 스캔 k 를 보내기 전에 `/clock`·`/tf`·`/odom` 을 t_k 로 먼저 발행하고(slam_toolbox 의 odom 조회가 실패하지 않게), 스캔을 발행한 뒤 **stamp 가 t_k 인 `/pose`**
    를 기다린다. 받으면 `processed`, map←odom 을 계산해 회신한다(버전 +1).
  - k ∈ {1, 2, 3}(0 부터 셈)은 `warmup` 으로 기다리지 않고 직전 보정을 회신한다. 이 규칙은 위 측정에서 나왔고, S0 에서 다시 확인한다.
  - 벽시계 10 s 안에 해당 `/pose` 가 없거나 소켓·컨테이너가 끊기면 `failed` — 실행기는 임무를 실패로 끝낸다(신선도와 구분되는 **시스템 실패**).
- **신선도(시뮬레이션 시각):** 제어는 "마지막 `processed` 보정의 스캔 시각 ≥ 지금 − 0.25 s"(연속 누락 2 개까지)일 때만 추정을 쓴다. 넘으면 0 명령으로 정지하고
  `localization_stale` 로 끝낸다(로드맵: 오래된 정보로 계속 주행하지 않는다). 워밍업 0.5 s 동안은 로봇이 출발하지 않는다.
- **도킹 구간의 보정 고정(검토 ③):** 삽입·인출·들어올림·내림 단계에서는 새 보정을 받되 **적용하지 않고**(기록만) 오도메트리로 이어 간다 — 8 mm 도착 판정 직전의
  보정 점프가 off_path·overshoot 를 만들지 않게. 이 구간 길이는 1.3 m 안팎이다. 운반 단계에 들어가며 다시 적용한다. 루프 폐쇄로 보정이 크게 바뀐 횟수·크기를 기록한다.

### 실행기 — 정답이 제어에 들어가는 모든 곳을 바꾼다 (Codex 검토 4 의 표)

| 사용처 | 지금 | `--slam-feedback` 에서 |
|---|---|---|
| 추종기 자세 | 정답 base/yaw → rear | **추정 map←base → rear** |
| 추종기 속도 `signed_speed` | 정답 선속도 투영 | **오도메트리 속도**(뒷바퀴 각속도 × 반지름, 잡음 포함) |
| cusp 재계획 정지 판정 | 정답 평면 속도·yaw 각속도 | **오도메트리 속도·yaw rate**(속도 × 곡률) |
| 캡처 뒤 자세 재설정(`accepted_pose` → base/q/yaw/rear) | 정답 | **수락 시점의 추정 자세**. 정답 `accepted_pose` 는 캡처 유효성(합성 센서 계약)에만 |
| 인식 관측의 세계 변환·임무 출발점 | 위 base/yaw·rear | 추정 자세 |
| 재관측 후보 계획 출발 | rear | 추정 rear |
| cusp 재계획 출발 | rear | 추정 rear |
| 최초 관측 후보 계획 출발 | `scenario.start_rear` | 알려진 출발 자세(허용 — 추정 초기값과 같은지 시험) |
| 인셋·로봇 카메라 주석 | 정답 현재 자세로 재투영 | 추정 자세로 재투영(영상이 SLAM 기반 추적을 정확히 보여 주게) |
| `--planning-target oracle_nominal` | 시나리오 pickup | `--slam-feedback` 과 함께 금지 |

정답 그대로(허용, 평가·안전): 물리, 런타임 footprint 겹침·포크 금지 접촉·낙하·미끄러짐·기울기 검사, 삽입 실측·하역 평가, 영상의 조감 카메라. 이들이 주행·재계획을
돕는 입력으로 넘어가지 않음을 시험으로 고정한다.

### 공통 물리 스텝 (두 검토의 P0/P1)

지금은 캡처가 자체 `world.step` 을 돌려 외부 루프의 관절·스캔 기록을 우회한다(최대 약 1.67 s). **모든 물리 스텝은 `step_world(render)` 를 지난다:** 물리 1 스텝 →
관절 상태 읽기 → 오도메트리 갱신 → 물리 tick 계수로 12 tick(10 Hz)마다 스캔·SLAM 교환 → 기록. 캡처의 `step_fn` 도 `step_world(render=True)` 다. 스캔 예약은
외부 `step` 변수가 아니라 실제 물리 tick 수로 한다.

### 좌표 규약 (두 검토 P1)

- 오도메트리는 **알려진 world 출발 자세**에서 시작한다: rear = `scenario.start_rear`, base = rear 에서 +0.34 m(회전 적용, 실행기의 `base_start` 와 같음). 그래서
  odom = world. slam_toolbox(Karto)는 첫 노드의 보정 자세를 그 odometric 자세로 두므로 **map = odom = world**(첫 보정 = 항등). S0 에서 0 이 아닌 출발 x·yaw 로
  확인한다.
- 오도메트리·평가·영상이 같은 규약을 쓰도록 하나의 함수로 둔다(영상 합성기가 world 자세를 다시 변환하지 않게).

### 오도메트리와 잡음 (`forklift_core.localization.slam_pose` — 작성됨, 시험 25 통과)

`IncrementalWheelOdometry` 는 기존 일괄 적분기 `integrate_wheel_odometry` 와 **비트 단위로 같은** 증분판이다. 잡음은 9/26 재생과 같은 가정값을 **같은 표본 주기**로
넣는다: 관절 120 Hz 마다 뒷바퀴 각속도 σ 0.2 rad/s·조향 σ 0.005 rad, 스캔 거리 σ 0.02 m(유효 거리 범위로 자름), 센서별 독립 난수 흐름(seed 고정). **A2M12·
엔코더 사양이 아니다.** (10 Hz 에만 넣으면 적분 표준편차가 √12 배 달라진다 — Codex.) 9/26 의 잡음 없는 오도메트리 방향 어긋남 0.110 rad/116 m(모델과 PhysX
접촉의 차이 후보)은 SLAM 이 바로잡아야 하는 대상이다.

## 단계와 판정 (결과 보기 전 고정)

오차는 **실제 제어에 쓴 추정 자세**를 정답과 **정렬 없이** 비교한다(기존 `trajectory_error` 의 ATE 는 최소자승·첫 자세 정렬이라 일정 오프셋을 0 으로 읽는다 —
Codex 반례). 매 스캔과 120 Hz 제어 입력 모두에서 위치 RMSE·최대, yaw RMSE·최대, 누락·워밍업·실패 수를 낸다. 위치 오차 목표는 **실험 목표이지 삽입 안전 근거가
아니다.**

**S0 — 연결 검증.** CPU: 응답 계약(가짜 브리지), 공통 스텝의 tick·스캔 예약, 좌표 규약(0 이 아닌 출발 x·yaw), 잡음 흐름, 신선도 정지, 정답 사용처 표의 시험.
ws1: 문턱 0 설정의 오프라인 재생 품질(9/26 seed 0 bag, 시작 정렬 RMSE 가 기존 0.025 m 의 2 배 이하 — 매 스캔 처리가 지도를 망치지 않는지), 컨테이너 + 실행기
연결 스모크(조사 경로 30 s): 워밍업 3 개, 나머지 `processed`, 첫 보정 항등.

**S1 — 공장 조사 경로 폐루프.** `run_slam_drive.py` 의 116 m 조사 경로(seed 0)를 추정 자세로 추종. 잡음 없음·합성 잡음 각 1 회, 같은 코드의 정답 자세 주행 대조.
판정: 경로 완주(정답 도착 오차 ≤ 0.10 m), `failed`·`localization_stale` 0, 제어 입력의 raw 위치 RMSE ≤ 0.08 m·최대 ≤ 0.15 m(실험 목표).

**S2 — 공장 운반 임무 폐루프.** `run_transport.py --layout factory --return-home --use-perception --slam-feedback`, seed 0–5, 합성 잡음. 대조: 같은 코드·같은
seed 의 정답 자세 실행(먼저 돌려 기대 완주 seed 를 고정한다 — 9/26 의 2/6 은 인식 미사용·옛 코드라 쓰지 않는다). 판정:
- **안전(필수):** 포크/팔레트 금지 접촉 0, 런타임 장애물 겹침 0.
- **성공:** SLAM 완주 ≥ 3/6, 그리고 대조에서 완주한 seed 중 SLAM 에서 실패한 것 ≤ 1(기술 실증 기준 — 6 건에서 1 건 허용은 16.7 %p 를 허용하는 느슨한 기준임을 밝힌다).
- **삽입(완주한 SLAM 실행마다, 정답 기하로):** 양 포크 실측 삽입 깊이 ≥ 목표 − 20 mm, 각 포크와 포켓 측벽(가운데·바깥 블록) 사이 **횡 최소 간격 ≥ 10 mm**(명목
  45 mm, 접촉 검사 여유 2 mm 제외 43 mm — 깊이·yaw 와 섞지 않는다), 삽입축 yaw 오차 ≤ 3°. 캡처 시점에서 삽입 끝까지 **추정−정답 오차의 변화량**(좌우·yaw)을 함께
  적는다(절대 위치 오차는 인식 변환에서 상쇄되고, 삽입을 가르는 것은 이 변화량이다 — 검토 ③).
- 위치 추정 실패·신선도 정지는 사유와 함께 실패로 센다.

**S3 — 렌더링.** S2 에서 완주한 SLAM seed 하나를 `--video --robot-camera` 로 다시 돌린다. 판정: 그 실행이 **S2 의 안전·성공·삽입 조건을 다시 통과**하고, 로봇 조감 +
**그 프레임 전에 실제로 받은 SLAM 지도**(브리지가 `/map` 수신 시각·버전을 기록) 위 추정·정답 궤적 + 로봇 카메라의 3 분할 영상이 실행 길이·프레임 수와 맞으며, 지도
패널이 기록된 지도에서 그려졌음을 프레임으로 확인한다(`tools/compose_slam_video.py` 를 수신 시각 기준 선택으로 확장).

## 자원과 일정

한 Slurm 작업: CPU 8(컨테이너 2), GPU 1, 메모리 16 GB. 조사 경로 2,454 스캔 × 처리 약 15 ms + 교환 지연 → 벽시계 수 분 추가. 처리 지연의 최대(0.145 s)와 한도
10 s 를 기록에 남긴다.

## 이 계획이 말하지 않는 것

- 실물 RPLIDAR A2M12·엔코더 잡음·지연(가정값), 회전 왜곡 없는 순간 스캔.
- LiDAR 장애물 지도의 계획기 연결, 동적 장애물·정지 계약(M4), 재기동·위치 소실 뒤 재위치 추정·기존 지도 기반 위치 추정(6순위의 나머지).
- 루프 폐쇄의 효과는 조사 경로가 한 바퀴라 일부만 시험된다.
- 잠정 차체·합성 공장 배치·EPAL 6·legacy 카메라 장착.
