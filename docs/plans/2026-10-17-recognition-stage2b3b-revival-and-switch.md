# 팔레트 인식 단계 2B-3b — 만료 트랙 재연결과 판독 전환

> **실행 방식:** 이 세션에서 직접 구현, Codex 검토를 수렴까지 받고 진행한다.

**Goal:** 2B-3 개발 평가(`docs/validation/2026-10-17-recognition-stage2b3-tracking-fusion.md`)의 불합격 원인 두 가지를 사용자 결정(2026-10-17)대로 고치고, **새 seed 의 평가 집합**에서 같은 고정 기준으로 다시 판정한다.

**사용자 결정 (2026-10-17):**
1. 만료된 트랙은 선택에 쓰지 않되, 다시 관측되어 관문을 통과하면 **같은 트랙 id 로 되살린다**.
2. 같은 포켓 쌍을 가리키는 **알려진 형상 ↔ 비규격 판독 전환은 한 트랙**으로 본다. T11 의 면 전환(x ↔ y)은 설계 §8 대로 추적 실패(새 트랙)로 둔다.

**Spec:** 설계 §6(0.5 s 넘은 후보는 새 선택·재선택에 쓰지 않음), §8(선택 대상이 사라지면 다른 후보로 자동 대체하지 않고 재관측, 진입면 전환은 추적 실패), §7.4-7(동치 가설 묶기). 2B-3 계획 `docs/plans/2026-10-17-recognition-stage2b3-tracking-fusion.md` 의 §1–§7 은 아래만 바꾸고 그대로 둔다.

## 바꾸는 것

### 1. 트랙 상태: 활성 → 정지 → 삭제

- **활성:** 마지막 수락 관측의 취득 시각에서 0.5 s 이내. `tracks()` 출력(대상 선택이 읽는 것)에는 활성 트랙만 나온다 — 설계 §6 그대로.
- **정지(stale):** 0.5 s 초과 1.0 s 이하. 출력에 나오지 않는다. 연결은 **두 단계**다: 먼저 활성 트랙과 새 관측으로 유일 최대 매칭(보류 규칙 그대로), 그다음 **활성 트랙 어느 것과도 관문이 이어지지 않은 관측만** 정지 트랙과 같은 규칙으로 맞춘다 — 활성 단계에서 보류되거나 매칭에서 남은 관측은 정지 트랙에 넘기지 않는다(활성 단계가 모호하다고 본 관측을 정지 트랙이 가져가지 않게). 정지 트랙의 넓은 관문이 활성 트랙의 관측을 보류시키지 않는다(agy 지적 — 활성 트랙 굶김). 정지 트랙이 관문(시간차 dt 의 주행 기록 상한으로 넓어진 같은 식)과 유일 매칭을 통과하면 같은 id 로 활성이 된다(재연결 횟수 +1). 같은 팔레트의 재관측이므로 설계 §8 의 "다른 후보로 자동 대체"가 아니다. 정지 동안 대상 선택·제어기가 무엇을 하는지는 실행기 연결(단계 4)의 계약이다.
- **삭제:** 1.0 s 초과. 영구 삭제, 이후 같은 팔레트 관측은 새 id.
- **T_keep = 1.0 s 는 개발 정책이다(정체 분리의 보장이 아니다).** 2B-3 보정표의 알려진 형상 행으로 가장 먼 구간의 관문 폭은 dt 1.0 s 에서 가로 0.50–0.52 m, 삽입축 0.61–0.64 m(지렛대 4.59–5.09 m; 0.6 s 도 표의 1.0 s 칸으로 올려 같다), 2.0 s 면 삽입축 0.76 m 다. 나란한 이웃의 같은 쪽 포켓은 폭만큼(T11 x0.6 0.66 m, EPAL 6 0.80 m), 앞뒤 이웃은 깊이 + 0.05 m 이상(EPAL 6 0.65 m, T11 0.71 m) 떨어진다. 그러나 **관측 간격은 참 간격과 다르다** — 앞 관측 +100 mm, 뒤 관측 −90 mm 면 0.65 m 간격이 0.46 m 로 보이고, 둘 다 행의 삽입축 경계 안이다(Codex 반례). 대상이 빠지고 이웃만 다시 보이면 정지 트랙이 이웃을 잡을 수 있다. 그래서 1.0 s 는 공백 4 프레임까지를 덮는 정책값이고, 이웃 오연결은 평가의 정체 오류와 아래 회귀 시험으로 드러낸다. 재보정 뒤 계열 조합별 관문 폭을 기록에 다시 적는다.
- 조회가 트랙을 정지로 만들 뿐 삭제하지 않으므로, 조회 뒤에 도착한 더 새로운 프레임(취득 시각이 마지막 처리 프레임보다 늦은 것)이 정지 트랙을 되살릴 수 있다. 처리 프레임보다 이른 프레임은 지금처럼 무시한다.

### 2. 판독 계열 호환과 포켓 쌍 기준

- 트랙은 **알려진 형상 가설**(처음 수락한 알려진 형상 판독의 `hypothesis`, 예 `epal6:x`)을 기억한다. 이력 재설정·창 탈락 뒤에도 유지된다. 처음 원거리 오판독이 굳는 위험(agy)은 남는다 — 2B-3 보정 집합에서 알려진 형상끼리 바뀐 경우는 0 건이었다. 새 관측의 키가 트랙과 **호환**이면 관문의 나머지 검사로 간다:
  - 비규격 판독(`parametric`)은 어느 트랙과도 호환.
  - 알려진 형상 판독은 트랙의 알려진 형상 가설이 없거나 같을 때만 호환(EPAL 6 ↔ T11, T11 x ↔ y 는 비호환 → 새 트랙).
- 포켓 위치·yaw·받침 검사는 그대로다. 두 관측의 경계 행은 각자의 계열 표에서 읽는다.
- **포켓 쌍 구간:** 마지막 관측끼리만 배치를 비교하면 한 걸음씩 옮겨 가 다른 개구 쌍에 닿을 수 있다(Codex 반례: 왼쪽 포켓 180 → 0 mm 를 45 mm 씩). 기준 관측 하나를 두고 b_s 가 줄 때 바꾸는 방식도 0 → 44 → 60 mm(b_s 32.5 → 15.3 → 1.0 mm)처럼 옮겨 간다(Codex 2판 반례). 그래서 트랙은 포켓마다 **수락한 모든 관측이 허용하는 면 좌표 구간의 교집합** ∩[x_i − b_s,i, x_i + b_s,i] 을 갖고, 새 관측의 구간 [x − b_s, x + b_s] 이 그 교집합과 겹칠 때만(그리고 마지막 관측과의 경계 합 안일 때만) 잇는다. 수락하면 교집합을 좁힌다. 이력 재설정 뒤에도 유지된다.
- 융합은 계열이 섞여도 같다(같은 포켓 쌍의 강체 자세). 출력은 최신 관측의 판독(`hypothesis`·`pending`·형상)을 그대로 쓴다 — 최신이 비규격이면 `entry_axis` 가 다시 미확인으로 나온다.

### 3. 시퀀스 모집단 — rank 결함 수정과 S7 보정 표본

- **결함:** `recognition_sequences.recipe_for` 가 조리법을 매번 `generate(..., count=1)` 로 만들어 rank 가 늘 0 이었다. rank 가 장면 유형을 고르므로(`recognition_scenes._scene`, `_s7_spec`) 2B-3 의 시퀀스는 **S2 전부 맞닿음, S5 전부 S1 배치, S7 전부 블록 4 개·집을 수 있는 유형**이었다(Codex). 2B-3 기록에 이 모집단 제한을 적는다.
- **수정:** `recognition_scenes` 에 조리법 한 개를 만드는 함수(`recipe(case, shape_key, seed, rank, split)`)를 떼어 내고 `generate` 도 그것을 쓴다(카탈로그 출력 불변 — 골든 다이제스트 시험). 시퀀스는 rank = 색인.
- 보정 시퀀스는 **전부 다시 만든다**(칸당 6, S7 은 30 — 비규격 경계 행이 1.5–2.5 m 만 채워졌고 3.0–4.0 m 는 0 표본이었다). 20 표본에 못 미치는 구간은 지금처럼 추적하지 않는다.

### 4. 재보정과 새 평가 집합

- 바뀐 트래커와 늘린 보정 시퀀스로 보정표와 W 를 같은 규칙으로 다시 정하고 평가 전에 커밋한다.
- 평가는 **새 대역** `evaluation_b` = 1,700,000 + 칸 × 1,000 + i(13 칸 × 8, 직선·곡선·피치)에서 한 번. 2B-3 평가 집합(1,600,000–)은 진단에 쓰였으므로 판정에 다시 쓰지 않는다.
- 판정 기준은 2B-3 계획 §7 그대로(사례별 하한 포함). 유지 = 선택 트랙이 **활성**이고 대상을 가리킴 — 되살아난 선택 트랙은 유지로 센다. 재연결 횟수와 정지 상태 프레임 수를 함께 기록한다.
- **포켓 쌍 라벨:** 채점 라벨을 (인스턴스, 면) 에서 **(인스턴스, 면, 포켓 쌍)** 으로 넓힌다. 각 정답 면의 모든 개구 중심(형상의 `opening_intervals_m` 을 그 프레임 base 로)을 기록하고, 후보의 각 포켓을 가장 가까운 개구에 붙인다(0.2 m 밖이면 미대응). 대상 = 정답 면의 `fork_fit` 쌍. 정체 오류 = 수락 관측의 인스턴스 전환, 또는 대응된 관측의 (면, 포켓 쌍) 전환.
- 평가기는 기록의 대역이 `evaluation_b` 가 아니거나 예상 파일(13 칸 × 8 × 3 종)과 다르면 거부하고, 파일 목록 해시를 결과에 남긴다.

## 작업

1. `candidate_tracking.py`: 정지 상태·T_keep(설정 `keep_s`, 기본 1.0)·재연결 횟수, 계열 호환과 트랙의 알려진 형상 가설. 시험(먼저 실패 확인):
   - 0.6 s 공백 뒤 같은 팔레트 → 같은 id, 정지 동안 조회에는 없음, 재연결 뒤 다시 나옴
   - 1.0 s 초과 공백 → 새 id
   - 활성 트랙 둘이 한 관측을 두고 보류되면 그 관측과 이어진 정지 트랙도 받지 못함
   - 조회 뒤 도착한 더 새 프레임은 정지 트랙을 되살림, 처리 프레임보다 이른 프레임은 무시
   - 알려진 형상 → 비규격 → 같은 알려진 형상: 한 트랙
   - 알려진 형상 A → 비규격 → 알려진 형상 B: 새 트랙
   - T11 x → y: 새 트랙
   - 시간 경계: 0.5 s 정각 활성·+1 ns 정지, 1.0 s 정각 정지·+1 ns 삭제
   - 활성 트랙의 관측이 정지 트랙 관문과 겹쳐도 활성 트랙이 갱신됨(활성 먼저)
   - 비규격으로 시작한 트랙이 처음 알려진 판독의 가설을 기억, 이력 재설정 뒤에도 유지
   - 포켓 쌍 구간: 45 mm 씩 옮겨 가는 연쇄, b_s 가 줄며 옮겨 가는 연쇄(0 → 44 → 60 mm) 모두 끊김
   - 대상이 빠지고 이웃만 다시 보임: 관문 밖 이웃은 새 트랙, 관문 안 이웃은 같은 트랙(알려진 한계를 시험으로 고정)
   - 같은 포켓 배치·받침의 비규격 물체가 알려진 형상 트랙 자리에 나타남: 관문 안이면 같은 트랙(한계 고정)
   - 기존 2B-3 시험 중 "만료는 영구"를 가정한 시험은 새 계약으로 고친다(무엇을 바꿨는지 커밋에 적는다).
2. `recognition_scenes.recipe` 분리, `recognition_sequences` 의 rank = 색인·`evaluation_b` 대역·개구 중심 기록, 평가기의 포켓 쌍 라벨·재연결·정지 집계·대역 검사. 시험: rank 가 색인을 따르고(S2 에 맞닿지 않은 배치, S7 에 블록 3 개 유형이 나옴), 카탈로그 다이제스트 불변, 포켓 쌍 라벨, 대역 거부.
3. UBAI: 보정 전부(칸당 6, S7 30) + 새 평가 104 × 3 생성 → 재보정·커밋 → 평가 한 번 → 기록 `docs/validation/2026-10-17-recognition-stage2b3b-revival-and-switch.md`.

## 위험

- 대상이 빠지고 관문 안의 이웃만 보이면 정지 트랙이 이웃을 잡을 수 있다(관측 간격은 참 간격보다 좁아 보일 수 있다). 유일 매칭은 둘 다 보일 때만 막는다. 그런 장면이 평가 시퀀스에 나오면 정체 오류로 세지만, 나온다는 보장은 없다 — 트래커 수준의 한계는 시험으로 고정한다.
- 비규격 판독은 어느 트랙과도 호환이라, 관문 안에 같은 포켓 배치·받침을 가진 다른 물체가 있으면 받는다(시험으로 고정한 한계). 평가 시퀀스는 그런 물체를 만들지 않는다(방해물은 제안되지 않음) — 이 경로의 실제 빈도는 이 평가로 말할 수 없다.
- 되살린 트랙의 창에는 공백 앞 관측이 남을 수 있다(W 1.2 s). 공백 동안의 주행 기록 오차는 예산의 상한 항이 덮는다.
