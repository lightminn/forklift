# B-P2 시작 재위치 — 계획과 사전 등록 (2026-10-29)

상위 계획: `docs/plans/2026-10-27-autonomous-survey-and-relocalization.md` B 절(B1 주입, B2 모호성, B3 상실, C 3 단계). 이 문서는 B-P2 의 구체 설계와 판정을 정한다. 상위 계획의 B1–B3 설계는 그대로 따르고, 바꾸는 곳만 적는다.

- 지시: 사용자 "출발 위치도 정해진 위치가 아닌 곳에서도 가능하게". 총괄(2026-10-29)이 B-P2 시작과 등록 원칙 다섯 가지를 정했다(아래 4 절).
- 앞선 결과:
  - `docs/validation/2026-10-28-b-p1-global-match.md`(B-P1, 6 절 정정 포함)
  - `docs/validation/2026-10-29-b-p1b-search-budget.md`(B-P1b: 새 세계 84 곳, 틀린 확정 0, 성공 82 %, 최대 10.5 s)

## 0. 지금 있는 것 (코드 조사, 2026-10-29)

- 시작 자세는 장면의 `start_rear`(후축, world) 하나다. 차는 거기에 놓이고, 오도메트리도 그 참값에서 시작한다(`odom = map = world`). 근거는 `run_transport.py` 3090·3246–3265·5382–5416 이다.
- 위치 추정 세션은 이렇게 연다.
  1. 감독자가 브리지(slam_toolbox 위치 추정 + 브리지 노드)를 등록부의 `start_pose`(map ← base_link)로 먼저 띄운다.
  2. 그다음 러너를 띄운다(`tools/live_supervisor.py` 296–315).
  3. 러너는 시작 7 장 bootstrap 뒤 SLAM 자세를 장면의 시작 참값과 0.10 m·0.05 rad 로 대조한다(`run_transport.py` 6876–6893).
  4. 그 뒤에야 콘솔 서버를 연다(8063).
- 위치를 모르는 세션은 없다. 없는 것:
  - "위치 미확정" 상태
  - 참값과 다른 곳에 차를 놓는 인자(live 텔레포트도 없다)
  - 콘솔 후보 화면
  - 에폭 안의 브리지 재시작
- 정지 중에는 `KeyframeGate` 가 처리 keyframe 을 보내지 않는다(`slam_link.py` 82–99). 그래서 정지 상태에서 위치 추정을 새로 확인하려면 브리지가 새로 떠서 시작 7 장을 받아야 한다.

## 1. 설계

### 1.1 세 자세를 나눈다 (좌표 계약)

- **참값 출발 자세**(world, base): 차를 놓는 곳이다.
  - 새 인자 `--start-pose x,y,yaw` 로 준다. `--start-relocalize` 와만 같이 쓴다.
  - 물리 배치와 판정(참값 대조)에만 쓴다. 위치 추정 경로는 이 값을 읽지 않는다(시험으로 고정).
- **등록 출발 자세**(map, base): 등록부의 `start_pose` 다. 재위치 세션에서는 사전 정보로도 쓰지 않는다(B-P2 범위). home·대기 자세 같은 고정 map 목표는 그대로 장면의 값이다.
- **추정 자세**(map, base): 정합기가 확정했거나 사람이 고른 자세다.
  - 오도메트리를 이 자세에서 시작한다. odom = map 이 시작에서 성립하므로 지금 코드의 "시작 = map = odom" 가정이 그대로 맞는다.
  - 장애물 층 초기화도 이 자세에서 한다.
  - 브리지의 `map_start_pose` 도 이 자세다.
- 변환: laser = base + (−0.12)·(cos ψ, sin ψ), 후축 = base − 0.34·(cos ψ, sin ψ). 이미 `relocalization_samples`·`global_match_eval` 에 있는 것을 한 곳으로 모은다.

### 1.2 재위치 세션의 순서

`--start-relocalize`(기본 끔)일 때만 이 경로를 쓴다. 끈 실행은 지금과 같다(재생 게이트 29/29 로 확인).

1. 감독자가 러너를 먼저 띄운다. 브리지는 아직 띄우지 않는다.
2. 러너가 장면을 세우고, 차를 참값 출발 자세에 둔다. 묶음 격자로 `MapIndex` 를 만든다.
3. 러너가 콘솔 서버를 연다. 상태는 `relocalizing` 이다.
   - STOP·세션 끝·후보 고르기·다시 시도만 받는다.
   - 자동 주행과 텔레옵은 막는다. 텔레옵은 S-P1 저상 안전 근거가 없어 B-P2 에서는 열지 않는다.
4. 정지 스캔을 모은다. 바퀴 0 으로 물리를 진행하며, live 공유 송신 경로의 스캔 5 장(12 걸음 간격)을 쌓는다.
5. `relocalize()` 를 부른다. 설정은 B-P1b 동결(`docs/validation/assets/b-p1b/match_config.json`, `dev_choice.json`)이다. 경쟁 비율·반복 구조 검사는 끌 수 없는 기본 경로다(총괄).
6. 확정이 아니면 재스캔한다. 새 스캔 5 장으로 다시 부르고, 최대 2 번(시도 3 번)이다.
   - 이 차는 제자리 회전을 못 한다. S-P1 보류로 전진 관측 이동도 끈다. 그래서 재시도는 정지 재스캔뿐이다.
   - 재스캔은 잡음만 새로 뽑고 기하는 같다. 경쟁·반복 구조로 거부된 자리는 대개 되풀이된다. 이것을 하한 등록에 반영한다(4.2).
   - 모든 시도는 마감 하나(첫 시도 시작부터 30 s)를 나눠 쓴다. 남은 시간이 다음 시도에 모자라도 시도는 하고, 마감이 그것을 끊는다.
7. 그래도 확정이 아니면 사람에게 넘긴다.
   - 콘솔에 후보(최대 4 개, 점수·끝점 비율)를 보인다.
   - 사람이 하나를 고르면 그 후보도 끝점 비율 ≥ E_MIN 이고 `refine_moved` 가 아니어야 받는다. 경쟁 비율은 사람이 판단한 것으로 보고 묻지 않는다.
   - 고를 때까지 대기한다. STOP·세션 끝은 언제나 된다.
8. 추정 자세가 정해지면 러너가 에폭 폴더에 `reloc_pose.json` 을 쓴다. 내용은 자세(map, base), 출처(`matcher` 또는 `operator`), 시도 수, 정합 기록이다.
9. 감독자가 그것을 읽고 브리지를 `SLAM_MAP_START_POSE` = 추정 자세로 띄운다. `bridge_ready` 를 기다린 뒤 `bridge_go` 를 쓴다.
   - 이것이 상위 계획 B1 의 채택안(위치 추정 노드를 그 자세의 `map_start_pose` 로 띄움)이다. B-P2 는 에폭의 첫 브리지라 재시작이 아니다. 에폭 안 재시작은 B-P3 몫이다.
10. 러너가 `bridge_go` 를 받고 SLAM 링크를 연다. 오도메트리·장애물 층을 추정 자세에서 시작하고, 지금과 같은 시작 7 장 bootstrap 을 한다.
    - 시작 대조: 지금의 "장면 시작 참값과 대조" 를 "추정 자세와 대조" 로 바꾼다. 허용 오차 0.10 m·0.05 rad 와 사유 문자열은 그대로다.
    - 이 대조는 참값을 읽지 않는다. SLAM 이 지도에서 추정 자세를 받아들였는지를 본다.
11. bootstrap 이 통과하면 상태를 `running` 으로 바꾸고, 자동 주행을 연다.
    - 판정용 기록(참값 대조)은 이때의 추정 자세와 참값을 남긴다. 러너는 이 기록을 읽어 행동하지 않는다.

- 시간 한계:
  - 감독자 쪽: 4–9 단계의 전체는 `RELOC_WAIT_S`(기본 600 s, 사람 고르기 포함)를 넘으면 에폭을 끝낸다. 브리지 시작에서 `bridge_ready` 까지는 지금의 대기 한계를 쓴다.
  - 러너 쪽: `bridge_go` 를 120 s 안에 못 받으면 `reloc_bridge_timeout` 으로 끝낸다.
- 실패 사유를 더한다:
  - `reloc_operator_timeout`
  - `reloc_bridge_timeout`
  - `reloc_pick_refused`(고른 후보가 검증 실패, 다시 고르기로 돌아감 — 끝내지 않음)
  - `slam_not_localized`: 기존 사유다. 브리지 대조 실패 때 쓴다.

### 1.3 상태와 콘솔

- 세션 상태에 `relocalizing`·`awaiting_pick`·`localizing`(브리지 bootstrap 중)을 더한다. `slam` 필드에 시도 수, 마지막 사유, 후보를 싣는다.
- 새 명령:
  - `relocalize_pick {candidate}`(RELIABLE)
  - `relocalize_retry`(RELIABLE, 사람 고르기 화면에서 재스캔 3 번을 다시 시작)
- 거부 사유:
  - `relocalizing`: 이 상태에서 미션 제출을 막는다. 기존 `localization_lost` 와 따로 둔다.
- 콘솔: 후보 층을 지도에 그린다(번호·점수). 고르기 버튼과 다시 시도 버튼을 둔다. 문구는 `results.js` 표에 더한다.
- 계약 문서(`docs/interfaces/2026-10-13-operator-console-contract-draft.md`)의 명령표·상태 메시지·거부 사유를 같은 PR 에서 고친다.

## 4. 사전 등록 (새 검증 결과 전에 고정)

### 4.1 안전(주 판정)

- **틀린 출발**: 세션이 `running`(자동 주행 열림)에 들어간 순간의 추정 자세(base)가 참값에서 > 0.3 m 또는 > 0.1 rad 인 경우다.
- **부정확 출발**: 0.10–0.30 m 또는 0.05–0.10 rad 다.
- 통과: 유효 세션 ≥ 60 에서 틀린 출발 0, 부정확 출발 0 이다.
  - 60 곳에서 0 건이면 단측 95 % 상한은 4.87 % 다(독립 가정). 총괄 조건 5 % 이하를 맞춘다.
- 사람이 고른 출발은 판정 표본에서 뺀다. 검증 실행은 사람이 없는 무인 실행이고, 확정 못 하면 사람 요청으로 셈하고 끝낸다.
- 브리지 대조(`slam_not_localized`) 실패는 출발이 아니다. 안전 쪽으로 거부한 것으로 따로 센다.

### 4.2 성공률 하한(B-P2 끝단)

- **성공**: 사람 없이 재시도 포함 3 번 안에 확정하고, 브리지 bootstrap 을 통과해 `running` 에 들어가고, 그 자세가 성공 허용 오차(≤ 0.10 m·0.05 rad) 안인 경우다.
- **하한: 유효 세션의 70 % 이상.**
  - 근거는 운용 요구다. 무인 출발이 쓸 만하려면 셋 가운데 둘보다 많이 사람 없이 떠야 한다. 70 % 아래면 운용자가 세 번에 한 번 꼴 이상 불려 간다.
  - B-P1b 의 시도당 82 % 를 근거로 쓰지 않는다(총괄: 같은 표본으로 문턱을 정하면 순환이다). 시도당 성공은 참고로만 적는다.
  - 재스캔은 잡음만 바꾸므로 시도당 성공보다 크게 오르지 않을 것으로 본다. 그래서 하한을 시도당 참고값보다 낮게 둔다.
- 관측 성공률과 Clopper-Pearson 단측 95 % 하한을 함께 적는다. 통과는 관측값 ≥ 70 % 다.

### 4.3 시간 상한

- **정합 단계**(4–7 단계의 자동 부분, 모든 시도): 마감 30 s 하나를 나눠 쓴다. 그래서 30 s 를 넘겨 나오는 확정은 없다(B-P1b 의 `relocalize()` 마감).
  - 통과: 마감에 걸린 세션 ≤ 10 %, 반환 32 s 초과 0(허용 초과 2 s).
- **브리지 단계**(8–11 단계): `reloc_pose.json` 부터 `running` 까지다.
  - 상한은 개발에서 잰 뒤 1 차 동결 전에 정한다. 개발 최대의 2 배를 올림한 값으로 한다.
- 수치 표기:
  - **ws1 1 스레드**: 잰 값이다.
  - **Jetson Orin Nano**: 재지 않았다. 추정으로만 적는다(예: 정합 단계 × 3, 근거 없는 배율). 실차 단계에서 잰다(총괄).
  - Jetson 에서 정합이 30 s 를 넘으면 마감이 사람 요청으로 바꾼다. 안전은 그대로이고, 성공률만 떨어진다.

### 4.4 판정 표본

- 새 세계: 공장 배치 seed 5.
  - 결과 전 규칙: 앞선 두 세계(seed 0, seed 4)와의 차이 가운데 작은 쪽이 가장 큰 seed 를 고른다. 차이는 LiDAR 높이 짐(꼭대기 ≥ 1.15 m) 바닥 자리의 합집합 대비 다른 칸 비율이다.
  - 오프라인 계산 결과(seed 1·2·3·5·6 의 (seed 0 대비, seed 4 대비)):
    - seed 1: 65.4 %, 66.8 %
    - seed 2: 68.5 %, 60.0 %
    - seed 3: 62.1 %, 66.3 %
    - seed 5: 68.0 %, 66.8 %
    - seed 6: 57.8 %, 73.5 %
  - 작은 쪽의 최대는 seed 5(66.8 %)다. 처음 초안은 seed 0 대비만 보고 seed 2 를 골랐다. 그러나 seed 2 는 seed 4 와 60.0 % 만 달라서, 재계산 검토(①)에서 바꿨다.
  - 자이로 조사, V2′(정확도·덮개), 잡음 seed 0 → 1 → 2 대체. 순회는 seed 5 기록으로 보완 계획한다(B4b 와 같은 방식).
- 시작: 그 지도에서 층 A A B C, 추출 seed 1030, laser 3 m 로 소진까지 뽑는다. 유효 세션이 60 미만이면 판정하지 않고 보고한다.
- 실행: 시작마다 무인 재위치 세션 하나다(사람 고르기 없음). 탐침은 세션이 `running` 또는 사람 요청(`awaiting_pick`)에 닿으면 끝낸다.
- 겹침 지표(정합 입력 기준, 개발 전부 대비)를 기록한다. 결론 범위는 "같은 홀 조건부" 로 적는다.

### 4.5 동결

- 1 차 동결(개발 뒤, 새 조사 전):
  - 코드 커밋
  - 정합기 설정과 문턱(B-P1b 동결 그대로)
  - 재시도 수, 마감, 브리지 단계 상한
  - 판정 스크립트
- 2 차 동결(수집 전): 지도 ID, keep-out, 시작 목록 sha256.

## 5. 위험과 한계

- 같은 홀이다. 결론은 "같은 홀, seed 5 배치에서의 조건부 확인" 이다.
- 사람 고르기의 안전은 사람에게 기댄다. 끝점 비율 검증만 한다. 이 판정에 넣지 않는다.
- 재스캔은 기하를 바꾸지 못한다. 관측이 모호한 자리는 B 의 추가 관측 이동(S-P1 뒤)이 다룬다.
- 브리지가 추정 자세를 받아들여도, 그것이 맞는지는 SLAM 이 판단하지 못할 수 있다. 정합기가 틀리게 확정하고 SLAM 도 그 자리에서 맞아 보이면 대조를 통과한다. 그래서 안전의 근거는 정합기의 경쟁·반복 구조 검사다. 브리지 대조는 덧붙인 확인이다.
- 실차 LiDAR 잡음·반사·바닥 기울기는 범위 밖이다.
