# 매끄러운 텔레옵 확인 실행 2 — 운용 기본 확인과 최대 배속 (등록, 2026-11-13, 결과 전 고정 — 초안: Codex 검토 전)

배경:
- [1차 결과](../validation/2026-11-12-teleop-smooth.md): L04(f 0.4, catch-up 0) 통과 3/3, K09(f 0.9, catch-up 6) 불통과 3/3(후진 hold).
- 1차는 층 지연 예산 off·캐시 없음이었고, L04 의 창 여유가 약 2 % 였다.

총괄 결정(2026-11-12):
- 1순위: 운용 기본(예산 on + 캐시)에서 L04 확인.
- 2순위: 같은 조건에서 끊기지 않는 최대 배속(L 0.5, K 0.6·0.7, 필요하면 0.8).
- K09 재실행은 K08 이 통과할 때만 한다. 후진 비용 진단은 K 가 무너질 때 같은 기록으로 한다(새 실행 없이).
- 이 실행은 캐시 PR 과 #473(#442 결함 수정)이 main 에 들어간 뒤의 main 으로 낸다.

- K08 을 처음부터 넣는다. 결과를 보고 팔을 더하지 않도록, 1.5 시간 안에서 미리 고정한다.
- 어느 팔이 다른 팔의 결과로 중단되는 일은 없다.

## 2. 판정 (1차 등록 3절과 같은 규칙, 결과 전 고정)

- 팔마다 1차 등록 3절의 규칙·판정 가능 조건·자리 규칙·같은 계정 겹침 규칙을 그대로 쓴다. 도구는 `tools/teleop_realtime_report.py --verdict --factor F --slots <그 팔의 셋> [--overlapped ...]` 이다. 팔별 자리:
  - L04: `t01_l04_r1,t10_l04_r2,t11_l04_r3`(F 0.4)
  - L05: `t02_l05_r1,t09_l05_r2,t12_l05_r3`(F 0.5)
  - K06: `t03_k06_r1,t08_k06_r2,t13_k06_r3`(F 0.6)
  - K07: `t04_k07_r1,t07_k07_r2,t14_k07_r3`(F 0.7)
  - K08: `t05_k08_r1,t06_k08_r2,t15_k08_r3`(F 0.8)
- 같은 계정 겹침은 sacct 원출력을 결과와 함께 보관한다(1차 결과 검토 P3).
- **최대 배속 정의.** 통과한 팔 가운데 f 가 가장 큰 팔이다(L 과 K 는 따로 말한다). 통과 팔의 f 가 끊기지 않고 이어지지 않아도(예: K06 불통과, K07 통과) 각 팔의 판정을 그대로 적고, '이 값까지 단조롭다'고 말하지 않는다.
- 1차와 비교해 보고만 하는 것:
  - L04 의 1차(예산 off·캐시 없음) 대비 TELEOP 배율·창 최솟값 차이. 예산 on 과 캐시가 함께 바뀌어 둘의 몫은 가르지 않는다.
  - 각 팔의 TELEOP 허가 비용(벽 1 s 당 `teleop.permit`·`core.permission_watch`)과 후진 hold 의 출력.

## 3. 결과에 따른 처리

- L04 가 통과하면, 도움말의 "콘솔 기본(0.4)에서 끊기지 않음"이 운용 기본(예산 on·캐시)에서도 확인됐다고 결과 문서에 적는다. 도움말 문구는 그대로다.
- L04 가 불통과하면 도움말 문구를 내리고 총괄에 올린다.
- 최대 배속 팔이 L05·K06·K07·K08 가운데 있으면, 그 설정만 결과 문서에 적는다. 도움말과 런처 기본 변경은 총괄 결정이다.
- K08 이 통과하면 K09 재실행을 등록한다(총괄 3).
- K 팔이 하나라도 후진 hold 로 무너지면, 같은 기록으로 후진 허가 비용을 진단한다(총괄 3, 새 실행 없음).

## 4. 범위

- 1차 등록 4절과 같다: 한 장면·seed·짧은 hold 열, 직접 조작 다섯 종류와 승강, 넓은 공간의 안전.
- 같은 날 다른 시간 측정과 겹치지 않게 단독으로 돈다(ws1 순서는 총괄).
- 결과는 예산 on·캐시 포함 main 에 한정된다. 실행 기록의 `layer_latency_budget` 인자와 스냅숏의 캐시 코드를 결과 문서에서 확인해 적는다.
