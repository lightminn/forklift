# 좁은 칸의 운반 출발 정지 — 탈출 전 조향 맞춤과 출발 띠 0.03 (2026-10-27, 계획 1 판)

지시: 총괄(2026-10-27) — 코드 수정 안으로 간다. riib 에서 출발 띠 해제를 켜고 띠를 0.03 m 로, 탈출 평가 전에 조향을 맞춘다(장면 재계획의 presteer 를 탈출에도). 런처 기본은 riib 에서만 켠다. 계획서에는 0.02 → 0.03 의 안전 근거와 조향을 실제로 맞춘 뒤에만 그 원호로 평가하는 조건을 적는다. 독립 검토 3 회, 시험 먼저, Isaac 비교는 사전 등록한다.
정책(사용자 2026-10-24): 여유·안전 판정 규칙·런처 기본값·복구 로직은 사용자 결정 없이 정하고 문서·보고로 남긴다.
진단: `docs/validation/2026-10-27-transport-start-stall.md`, 도구 `tools/transport_start_stall.py`.
branch `feat/escape-presteer`(진단 브랜치 `diag/transport-start-stall` 위).

## 1. 문제와 근거

- 증상(진단 문서): 좁은 칸(aisle_rack 랙 기둥, trailer 벽)에서 꺼낸 직후 적재 외곽이 키 큰 소품의 LiDAR 표시 반경에서 0–0.027 m 떨어져 선다. 운반 허가가 occupied 로 0 이고, 운반 P6 재계획은 `invalid_start` 다. 탈출 후보 8 개가 모두 격자 검사에서 떨어져 운반 추종 시간 초과로 끝난다(T2 aisle 6 건, trx trailer 5 건).
- CPU 대입(11 실행, 실패 실행의 첫 운반 덤프):

| 변형 | 탈출 후보 격자 통과(실행) |
|---|---|
| 기본, #151 E2, 출발 띠 0.02·0.03 | 0 |
| 띠 0.02 + 조향 0 | 2 |
| 띠 0.03 + 조향 0 | 9 |
| 띠 0.03 + 조향 −0.02·−0.05 m⁻¹ | 4(aisle 의 같은 4) |
| 띠 0.03 + 조향 +0.02·+0.05 m⁻¹ | 5(trailer 5) |

- 걸림 둘:
  - ⓐ 서 있는 동안 남은 미세 조향(|κ| 0.002–0.009 m⁻¹)이 정지 원호에서 외곽 모서리를 해제된 칸 쪽으로 mm 단위로 돌린다. 출발 띠 해제는 해제된 칸에 가까워지는 움직임을 막으므로, 첫 자세에서 잘린다.
  - ⓑ 띠 폭 0.02 m 가 칸 거리(0.010–0.027 m)보다 좁다.
- 조향을 0 으로 맞추는 것은 측정 오차 안에서 부호가 정해지지 않는다. 기존 presteer 허용 오차는 앞바퀴 각 0.02 rad, 곡률로 약 0.03 m⁻¹ 이고, 실패 실행의 잔여 조향은 그보다 작다. 그래서 0 대신 막힌 칸에서 멀어지는 쪽으로 분명히 꺾는다(|κ| = 0.05 m⁻¹). 측정 오차가 있어도 부호가 유지되고, 위 표에서 그 부호의 0.02·0.05 가 모두 같은 실행을 푼다.

## 2. 설계

### D1 출발 띠 폭

- 러너 `--start-band-m M`(기본 없음 = 지금 공식 envelope + step/2). `--start-band-release on` 일 때만 쓴다. 근접 계약 POST_MEASUREMENT 에 등록한다(기본 None).
- riib 런처: `START_BAND` 기본 on, `START_BAND_M` 기본 0.03. `riib_defaults.txt` 에 기록한다.
- CT-1·콘솔 런처는 바꾸지 않는다.

### D2 탈출 전 조향 맞춤 (escape presteer)

- 러너 `--escape-presteer on|off`(기본 off, 근접 계약 off). riib 런처 `ESCAPE_PRESTEER` 기본 on.
- 장면 재계획 기기의 `wait_plan` 에서 재계획이 `invalid_start` 이고 탈출이 남았을 때:
  1. 켜져 있으면 먼저 지금 측정 조향으로 탈출을 평가한다(지금과 같다). 자격 있는 후보가 있으면 지금처럼 바로 탈출한다.
  2. 없으면 탈출 후보를 가정 조향 κs ∈ {+0.05, −0.05} m⁻¹ 로 평가한다. 정지 원호 셋(κs, κs/2, 0)과 경로·ramped·쓸림·끝 영역은 `escape.evaluate` 그대로다. 자격 있는 후보가 있는 κs 를 고른다. 둘 다 있으면 고른 후보의 끝 여유가 큰 쪽이다. 둘 다 없으면 지금처럼 `invalid_start` 로 끝난다.
  3. 새 상태 `escape_presteer`: 바퀴 0, 조향 목표 κs. 기존 presteer 와 같은 오차(앞바퀴마다 Ackermann 각 차이 ≤ 0.02 rad)와 시간 상한(1.0 s)을 쓴다.
  4. 맞춤이 끝나면(aligned 또는 timeout) **측정한 조향으로 탈출을 다시 평가한다.** `hooks.held_kappa()` 는 조향 관절에서 읽는다. 자격 있는 후보가 있을 때만 지금 경로로 설치한다(`escape_install`). 없으면 `scene_replan_failed:<trigger>:invalid_start` 로 끝난다(기록에 사유).
- 그래서 원호 판정은 언제나 실제로 잡힌 조향으로 한다. 가정 κs 는 어느 쪽으로 꺾을지 고르는 데만 쓴다.
- 탈출 주행은 지금과 같다. 곧은 후진 추종기가 κs 에서 0 으로 조향을 되돌리는 동안의 원호는 평가한 셋(κs, κs/2, 0) 사이다. 허가는 매 틱 작용한다(탈출은 운반 단계의 backoff 소유).
- 기록: 장면 재계획 줄에 `escape_presteer` = {후보 κs 별 자격 수, 고른 κs, aligned/timeout, 오차, 측정 κ, 재평가 결과}.
- 끄면 기기 상태도 기록도 지금과 같다.

### D3 기본값

riib 런처만 바꾼다: `START_BAND=on`, `START_BAND_M=0.03`, `ESCAPE_PRESTEER=on`. 러너 기본은 모두 off 다. 재생 게이트와 옛 기록은 그대로다.

## 3. 안전 근거

- 띠 0.02 → 0.03:
  - 출발 띠 해제는 출발할 때 외곽에서 띠 안에 있던 occupied 칸만 해제한다. 해제한 칸에는 외곽의 각 부분이 지금까지보다 가까워지지 않는 동안만 통과시킨다(`start_release.release_length`).
  - 띠 밖의 칸, 출발 뒤 새로 들어온 칸은 그대로 막는다.
  - 띠를 0.01 m 넓혀도 이 규칙은 그대로이고, 해제 대상이 외곽에서 0.03 m 이내의 칸까지 늘 뿐이다.
- 이번 실패의 막힌 칸은 키 큰 소품의 표시 반경이다. 실제 간격(truth)은 기둥 0.181–0.215 m, 벽 0.205–0.208 m 다. 허가 문턱(envelope 0.01 + 정지 여유 0.05 = 0.06 m)의 3 배 이상이다. 통과하는 탈출은 모두 꺼낸 방향 그대로의 곧은 후진이다.
- 지난 비교의 실제 짐 겹침(`docs/validation/2026-10-24-start-band-release.md`, 해제 켬 aisle_rack s4)은 LiDAR 면 아래 낮은 블록 소품과의 겹침이었다. 같은 종류가 끈 팔에서도 났다. 그 뒤 들어온 저상 감시(#133, riib 기본 on)가 낮은 소품을 장면 사각형으로 따로 본다. 이 계획은 저상 감시를 바꾸지 않고, 탈출도 운반 단계라 저상 감시가 계속 작용한다.
- 조향 맞춤: 원호 판정은 측정한 조향으로 한다(D2-4). 맞춤이 시간 상한에 걸려도 측정 조향이 자격을 못 주면 탈출하지 않는다.

## 4. 확인

- C1 단위 시험(먼저 쓴다):
  - 기기 상태 기계: 끔이면 같다. 켬이면 측정 조향으로 먼저 평가하고, 자격이 없으면 κs 를 고르고 → `escape_presteer`(목표 κs, 오차·시간 상한) → 측정 조향으로 재평가 → 설치하거나 끝낸다. 맞춤 중 움직이면 wait_stop 으로 간다. 시간 상한, 둘 다 자격 없음, 재평가 실패, 정지(pause) 시간 이동(`shift_time`)도 본다.
  - core 포트: 가정 κ 평가가 같은 함수로 계산되고 설치하지 않는다.
  - 러너 인자, 근접 계약, 런처 기본값과 `riib_defaults.txt` 기록.
- C2 CPU: `tools/transport_start_stall.py` 를 구현의 평가 함수로 다시 돌려 11 실행에서 고른 κs 와 자격 수가 위 표와 같은지 본다.
- C3 회귀: 재생 게이트 runs29(끔), ws1 전체 pytest.
- C4 Isaac(사전 등록, 결과 전에 이 절을 고쳐 커밋한다):
  - 장면: aisle_rack 0–7, trailer 0–4(`--exit-clearance-m 0.30`, 장면 필수 인자). 리보틱스 3 슬롯 묶음, #181 사전 검사, 의존성 없음.
  - 두 팔: A = 지금 riib 기본, B = `START_BAND=on START_BAND_M=0.03 ESCAPE_PRESTEER=on`. 같은 seed 를 번갈아 돈다.
  - 센 것: 장면별 완주, 운반 P6 탈출의 시도·조향 맞춤·설치·완료, 실제 겹침·`unpermitted`, 새 실패 유형.
  - 기본값 판정 규칙: B 의 완주가 A 보다 많고, 실제 겹침 0, `unpermitted` 가 A 보다 늘지 않으며, 새 실패 유형이 없어야 riib 기본으로 둔다. 하나라도 못 넘으면 기능만 남기고 riib 기본은 끈다. 총괄에 보고하고 총괄이 정한다.

## 5. 남는 것

- 거리 0 인 두 실행(aisle b0 s2·c3 s4): 막힌 칸이 외곽에 닿아 출발 띠로는 풀 수 없다. 그 칸이 무엇을 표시한 것인지(기둥 반경 안의 실제 충돌 위험인지, 들린 팔레트나 포크의 자기 표시인지)를 따로 진단한다(총괄 지시).
- 꺼내기 띠를 빈 길로 보는 안(ii)은 원리는 단단하지만 이번 실패에는 거의 듣지 않아 넣지 않는다.
