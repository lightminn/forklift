## 1. 문제와 근거

- 증상(진단 문서): 좁은 칸(aisle_rack 랙 기둥, trailer 벽)에서 꺼낸 직후, 적재 외곽이 키 큰 소품의 LiDAR 표시 반경에서 0–0.027 m 떨어져 선다.
  - 운반 허가가 occupied 로 0 이다. 운반 P6 재계획은 `invalid_start` 다.
  - 탈출 후보 8 개가 모두 자격을 잃어 운반 추종 시간 초과로 끝난다.
  - 해당 실행: T2 aisle 6 건, trailer 10 건(trx 5, 둘째 진단 tra 3·trb 2).
- 전체 판정 재현(도구 `90019c46`, ws1 `tss_diag/tss_90019c46.{txt,json}`). 실패 실행의 첫 운반 덤프에서 러너 `escape_plan` 을 그대로 다시 계산했다.
  - 장면 소품에 실행의 KEEPOUT 을 적용했다. 트리거 사각형은 붙잡은 조향에서 구했다(`current_blocked_rectangles`). 띠를 켜면 트리거 사각형을 출발 띠로 가른다.
  - 쓸림·경로·경사 경로·정지 원호 셋·끝 영역(기록된 문턱)을 모두 본다. 그다음 선택하고, 측정 조향에서 설치 전 허가(`candidate_permit`)를 본다. 탈출 속도는 러너의 0.15 m/s 다.
  - 끈 팔의 후보별 첫 실패 검사는 14/16 실행에서 실행 기록과 같다. b0 s0 의 전진 두 후보와 c3 s4 는 다르다. 덤프가 기록보다 3 s 앞이라 트리거 사각형이 다른 것으로 본다.

| 변형 (조향은 원호 평가와 설치 허가의 측정값 둘 다) | 설치까지 가는 실행 |
|---|---|
| 기본(붙잡은 조향 \|κ\| 0.0005–0.0085 m⁻¹), 띠 0.02·0.03 | 0/16 |
| 조향 ±0.05 m⁻¹, 띠 없음 | 0/16 |
| 띠 0.03 + 조향 정확히 0 | 13/16 |
| 띠 0.03 + 조향 −0.02·−0.05 | 3/16(aisle b0 s0·c3 s1·c3 s2) |
| 띠 0.03 + 조향 +0.02·+0.05 | 10/16(trailer 10 건 전부) |

- 고른 탈출은 모두 꺼낸 방향 그대로의 곧은 후진이다. aisle 은 0.6 m, trailer 는 1.0 m(tra s1 만 0.6 m)다. 설치 허가는 모두 `ok` 다.
- 남는 3 건(aisle b0 s2·b0 s3·c3 s4)은 어느 변형에서도 8 후보가 모두 직사각형 쓸림에서 막힌다. 조향·띠로는 풀리지 않는다(5 절).
- 걸림 둘(둘 다 있어야 풀린다):
  - ⓐ 서 있는 동안 남은 미세 조향이 정지 원호에서 외곽 모서리를 막힌 칸 쪽으로 mm 단위로 돌린다. 출발 띠 해제는 해제된 칸에 가까워지는 움직임을 막으므로 첫 자세에서 잘린다. 부호는 장면에 따라 다르다. aisle 은 −, trailer 는 + 쪽만 통과한다.
  - ⓑ 띠 0.02 m 는 외곽–칸 거리(0.010–0.027 m)보다 좁다.
- 정확한 0 은 맞춤으로 만들 수 없다. 기존 presteer 허용 오차는 바퀴마다 Ackermann 각 0.02 rad 다. 위 실패 실행들의 잔여 조향을 측정 차체의 바퀴각으로 바꾸면 최대 0.0056 rad 이다(Codex 계산). 그래서 0 을 목표로 하면 명령 없이 바로 "맞춤 완료"가 된다.
  - 그래서 0 대신 통과하는 쪽으로 분명히 꺾는다(|κ| = 0.05 m⁻¹). 위 표에서 그 부호의 0.02·0.05 는 같은 실행을 푼다.

## 2. 설계

### D1 출발 띠 폭

- 러너 `--start-band-m M` 을 둔다. 기본은 없음이고, 지금 공식(envelope + step/2)을 쓴다. `--start-band-release on` 일 때만 쓴다. 근접 계약 POST_MEASUREMENT 에 등록한다(기본 None).
- riib 런처: `START_BAND` 기본 on, `START_BAND_M` 기본 0.03. `riib_defaults.txt` 에 기록한다.
- CT-1·콘솔 런처는 바꾸지 않는다.

### D2 탈출 전 조향 맞춤 (escape presteer)

러너 `--escape-presteer on|off` 를 둔다(기본 off, 근접 계약 off). riib 런처는 `ESCAPE_PRESTEER` 기본 on 이다. 끄면 기기 상태와 기록이 지금과 같다.

장면 재계획 기기(`scene_replan.py`)의 `wait_plan` 에서 재계획이 `invalid_start` 이고 탈출 예산이 남았을 때:

1. 먼저 지금처럼 `escape_plan` 으로 측정 조향에서 탈출을 평가한다. 설치되면 지금과 같다.
2. 설치되지 않고 켜져 있으면, 새 포트 `escape_probe(extra, clearance_m, kappa)` 로 κs ∈ {+0.05, −0.05} m⁻¹ 각각을 평가한다.
   - `escape_plan` 과 같은 함수로 계산하되 설치하지 않는다. 원호 셋은 κs, κs/2, 0 이고, 설치 허가의 측정 조향도 κs 로 둔다(agy 지적 3: 허가까지 통과하는 쪽만 고른다).
   - 둘 다 되면 고른 후보의 끝 여유가 큰 쪽으로 한다. 둘 다 안 되면 지금처럼 `invalid_start` 로 끝난다(standing-safe 그대로).
   - 기록: `scene_escape_candidates` 에 `probe_kappa` 를 단 줄로 남긴다.
3. 새 상태 `escape_presteer` 로 간다. 출력은 바퀴 0, 조향 목표 κs(기존 `presteer` 출력과 같은 형식)다. 아무것도 설치하지 않으므로 `changed` 는 그대로 False 다. 매 틱:
   - `stopped()` 가 아니면 `wait_stop` 으로 간다(agy 지적 1). 그 경우 요청은 처음 계획부터 다시 하고, 탈출 예산은 쓰지 않은 채다.
   - 바퀴마다의 오차가 0.02 rad 이하이면 aligned, 1.0 s 가 지나면 timeout 이다. 시작 시각은 `presteer_since` 에 둬서 정지(pause) 시간 이동(`shift_time`)이 그대로 적용된다(agy 지적 7).
4. aligned 또는 timeout 이면 다시 `escape_plan` 을 부른다. 측정 조향(`hooks.held_kappa()`, 조향 관절)과 지금 자세로 평가하므로, 원호 판정은 언제나 실제로 잡힌 조향으로 한다.
   - 자격 있는 후보가 있고 설치 허가가 ok 일 때만 설치한다(`escape_install`, `changed = True`).
   - 없으면 `scene_replan_failed:<trigger>:invalid_start` 로 끝난다. `changed` 가 False 라 지금처럼 standing-safe 로 서서 돌려준다.
   - 다시 고른 후보가 탐침 때와 달라도 된다. 기록에 같은지 적는다.
5. 출발 띠 해제의 앵커: `escape_plan` 은 첫머리에서 `_note_release_standing(rear, stopped())` 를 부른다. 앵커는 서 있는 동안 버전이 같으면 다시 잡지 않는다.
   - 그러므로 맞춤 중 조향 마찰로 자세가 mm 단위 움직여도 앵커의 "가까워지지 않음" 기준은 처음 선 자세에서 잰다. 다시 잡으면 그 사이 가까워진 만큼이 기준에 들어가 버린다.
   - 보정 버전이 바뀌어 앵커가 떨어졌으면 지금 자세에서 다시 잡는다(지금 규칙).
   - 맞춤 동안의 자세 이동(위치·방향)을 기록한다.
  - 한계: 맞춤 중 속도가 잠깐 0.01 m/s 를 넘으면(`stopped()` False) 허가 쪽 `note_standing` 이 새 정지로 보고 다음 정지 자세에서 앵커를 다시 잡는다. 이것은 모든 서서 출발에 있는 지금 규칙이고, 기기는 그때 `wait_stop` 으로 돌아가 처음부터 다시 계획한다.

### D3 탈출 주행의 조향 범위

- 탈출 추종기는 곧은 경로의 측면 오차를 줄이려고 반대 부호 곡률을 명령할 수 있다(agy 지적 2).
- 평가한 원호는 κs, κs/2, 0 뿐이다. 반대 부호 쪽 정지 원호는 막힌 칸 쪽이라 허가가 0 을 낸다. 허가가 서 있는 채 1 s 0 이면 탈출이 `stopped` 가 되고, `changed` 가 True 라 미션이 끝난다.
- 그래서 조향 맞춤으로 시작한 탈출에서는 기기가 내보내는 곡률을 [min(κs, 0), max(κs, 0)] 로 자른다(`scene_replan_tick` 의 escape 출력). 조향은 κs 에서 0 쪽으로만 움직이고, 그 사이의 정지 원호는 평가한 셋의 범위 안이다. 허가는 매 틱 그대로 작용한다.
- 맞춤 없이 시작한 탈출(1 단계에서 바로 설치)은 지금과 같다.
- 기록: 자른 틱 수와 자르기 전 곡률의 최소·최대.

### D4 기본값

riib 런처만 바꾼다: `START_BAND=on`, `START_BAND_M=0.03`, `ESCAPE_PRESTEER=on`. 러너 기본은 모두 off 다. 재생 게이트와 옛 기록은 그대로다.

## 3. 안전 근거

- 띠 0.02 → 0.03:
  - 출발 띠 해제는 서서 출발할 때 외곽에서 띠 안에 있던 occupied 칸만 해제한다. 해제한 칸에는 외곽의 각 부분이 앵커 때보다 가까워지지 않는 동안만 통과시킨다(`start_release`).
  - 띠 밖의 칸, 출발 뒤 새로 들어온 칸은 그대로 막는다. 허가의 나머지(정지 거리, 증거 나이, 센서 끊김)는 그대로다.
  - 띠를 0.01 m 넓히면 해제 대상이 외곽에서 0.03 m 이내의 칸까지 늘 뿐, 규칙은 같다.
- 이번 실패의 막힌 칸은 키 큰 소품의 표시 반경이다. 출발 자세에서 외곽과 실제 면(truth)의 간격은 기둥 0.181–0.215 m, 벽 0.190–0.208 m 다.
  - 허가의 고정 여유는 envelope 0.01 + 정지 여유 0.05 m 이고, 여기에 속도 항이 더해진다. 탈출 속도 0.15 m/s 의 정지 거리는 0.08 m 다(Codex 지적 5: 앞 판의 "문턱 0.06 m" 는 속도 항을 뺀 값이었다).
  - 이 간격은 출발 자세 한 점의 값이다. 탈출 전체의 최소 간격이나 안전 검증을 대신하지 않는다.
  - 고른 탈출은 꺼낸 방향 그대로의 곧은 후진이라 그 면에서 멀어지거나 평행하게 간다. 탈출 중에도 허가가 매 틱 판정한다.
- 출발 띠는 riib 의 모든 단계, 모든 서서 출발에 걸린다(agy 지적 4). 탈출만이 아니다.
  - 지난 비교(`docs/validation/2026-10-24-start-band-release.md`, 띠 0.02)에서 해제 켬 실행은 운반 중 해제 걷기가 수천–수만 번 "다가감으로 잘림(capped)"이 되며 조금씩 움직이다 시간 초과로 끝났다. 허가가 0 보다 커서 P6 의 3 s 영점 계수가 다시 시작되기 때문이다.
  - 그 비교의 운반 통과는 같은 배치 3 에서 켬 2/8, 끔 4/7 이었다. 띠를 넓히면 이 기전이 더 잦아질 수 있다. C4 에서 따로 센다(4 절).
- 실제 짐 겹침: 지난 비교의 겹침(해제 켬 aisle_rack s4)은 LiDAR 면 아래 낮은 블록 소품이었고, 같은 종류가 끈 팔에서도 났다.
  - 그 뒤 저상 감시(#133, riib 기본 on)가 낮은 소품을 장면 사각형으로 따로 본다. 이 계획은 저상 감시를 바꾸지 않는다. 탈출도 운반 단계라 저상 감시가 계속 작용한다.
  - 저상 감시가 탈출 중 세우면 그 탈출은 `stopped` 로 끝나고 미션이 끝난다(agy 지적 5). 지금 탈출과 같은 결과다. C4 에서 센다.
- 조향 맞춤: 원호 판정과 설치 허가는 측정한 조향으로 한다(D2-4). 맞춤이 시간 상한에 걸려도 측정 조향이 자격을 못 주면 탈출하지 않는다. 탈출 중 조향은 평가한 범위를 벗어나지 않는다(D3).

## 4. 확인

### C1 단위 시험 (먼저 쓴다)

기기 상태 기계(`tests/unit/mission/test_scene_replan.py`):
- 끄면 지금과 같다(상태 열, 기록 키).
- 켜면 측정 조향 평가가 먼저다. 설치되면 탐침을 부르지 않는다.
- 자격 없음 → 두 κs 를 탐침하고 고른다(둘 다 되면 끝 여유가 큰 쪽, 하나만 되면 그쪽). 둘 다 안 되면 `invalid_start` standing-safe 로 끝난다.
- `escape_presteer` 의 출력은 presteer, 바퀴 0, 목표 κs 다.
- **[agy High 1]** 맞춤 중 `stopped()` 가 False 가 되면 그 틱에 `wait_stop` 으로 가고 조향·설치를 하지 않는다. 탈출 예산과 `changed` 는 그대로다.
- **[agy High 1]** 맞춤 중 보정 버전이 바뀌면 재평가에서 앵커를 지금 자세로 다시 잡는다. 버전이 같으면 다시 잡지 않는다. 맞춤 동안 자세가 움직였다면 기준은 처음 자세다.
- aligned 와 timeout 은 둘 다 측정 조향으로 재평가한다. timeout 에서 조향이 그대로(또는 반대)라 재평가가 실패하면 standing-safe 로 끝나고 미션은 끝나지 않는다.
- 재평가 후보가 탐침과 달라도 설치한다(기록에 표시).
- `shift_time` 이 맞춤 시작 시각을 민다.

core 포트(`tests/unit/mission/`):
- `escape_probe` 는 `escape_plan` 과 같은 계산(같은 후보·같은 판정)이고 설치하지 않으며 트래커·허가 상태를 바꾸지 않는다.
- **[agy High 2]** 맞춤으로 시작한 탈출에서 추종기가 반대 부호 곡률을 내면 출력이 [min(κs,0), max(κs,0)] 로 잘린다. 맞춤 없이 시작한 탈출은 자르지 않는다. 자른 틱 수가 기록된다.

러너·런처:
- `--start-band-m`·`--escape-presteer` 인자, 근접 계약 등록.
