# 계획 여유와 장애물 층 표시 반경의 불일치 — 원인과 설계안 (계획 v1)

작성일: 2026-10-23 · 지시: 총괄 세션(사용자 결정 2026-10-22, "계획기가 장애물 층의 표시 반경을 모르는 문제를 별도 작업으로") ·
범위: 원인 분석과 설계안 비교까지. **방향은 사용자 결정**으로 올리고 구현은 결정 뒤에 한다. 독립 검토 3 회(7 장).
관련: PR #106(좁은 통로 rack 사본), PR #91·#96(트레일러 출구 접두), `docs/plans/2026-10-04-lidar-obstacle-map.md`(장애물 층, P0a 고정값, 복구–허가 정합 4 판).

## 1. 문제

경로 계획기와 실행 중 주행 허가가 같은 장애물을 서로 다른 크기로 본다.

- **계획기**는 사전 지도의 소품 사각형을 실제 크기로 두고 여유를 더한다. 여유는 `planning_clearance_m` 0.10 m(`config/isaac_transport*.yaml`, `pallet_mission.py` 34 행)이다.
  접근 탐색·접근 직선은 `min(여유, 접근 틈/2)` = 0.05 m(1673–1675 행)이다. 점유 격자가 있으면 꺼내기 직선은 0 m(1736–1739 행)이고, 재계획은 여유 0 으로 다시 시도한다(`core.py` 1328·1384–1405 행).
  `--layout scene`(리보틱스 장면)은 `--grid-planning` 을 막는다(`run_transport.py` 972–975 행: 1.05 m 면 아래 바닥 팔레트를 격자가 못 본다). 그래서 계획기는 실행 중 격자를 전혀 보지 않는다.
- **장애물 층**(`perception/obstacle_grid.py`)은 LiDAR 점마다 반경 r 의 원을 OCCUPIED 로 칠한다.
  - r = e(나이) + 0.06 + 2ρ·sin(ψ(나이)/2)(`radius_m` 356–363 행, `_marks` 473–490 행). ρ 는 후축에서 점까지 거리, 0.06 은 거리 잡음 한계 `sensor_bound_m` 이다.
  - e·ψ 는 `config/obstacle_odometry_age.json` 의 나이별 오도메트리 누적 오차다(러너는 `cumulative_position_m`·`cumulative_yaw_rad` 를 읽는다, `run_transport.py` 3349 행).
    이 표는 Isaac 실행의 휠 오도메트리(보고 바퀴 속도 + 조향, 잡음 모형)에서 잰 값이다. P0a 재측정(2026-10-06) + 측정 차체 게이트(2026-10-08)이며 고정값이다
    (`2026-10-04-lidar-obstacle-map.md` 2261 행 "P0a 결과와 고정값").
  - 칠할 때 반경을 0.0125 m 단위로 올리고, 칸(0.05 m) 정사각형이 원에 닿으면 칠한다(`_mark_disks` 587–603 행).
  - 표시는 `occupied_max_age_s` 0.3 s 동안 남는다.
- **주행 허가**(`control/drive_permission.py`)는 앞으로 갈 경로의 외곽(`hull_forward`)을 0.01 m(정지 포락선) + 쓸림 패드(0.02 m 표본 사이 이동의 절반, 약 0.01–0.025 m)만큼 넓힌다(`_margin` 399–405 행).
  그 외곽이 OCCUPIED 칸과 겹치면 그 앞에서 멈출 속도로 묶는다(442–445 행). `margin_m` 0.05 는 정지거리 항이지 공간 여유가 아니다(46–48 행).
  허가가 적용되는 단계는 관측·접근·운반·귀환 등이다(`core.py` `permission_acting` 1043–1069 행). 접근 직선 끝 0.80 m 와 하역 직선 끝 0.70 m 는 면제되고, 꺼내기는 아예 대상이 아니다.
  삽입은 포켓 단계에서 다시 켜진다(1143–1148 행).

### 1.1 계획기가 표면에서 비워야 할 거리 (원자료에서 계산)

허가가 막지 않으려면 경로 외곽이 표면에서 r + 칸 도달(반경 올림 + 칸 대각선 반 0.035 m) + 0.01 + 쓸림(약 0.025 m)보다 떨어져 있어야 한다.
나이 표별로 계산했다(나이 0.1–0.3 s, ρ 0.5–5 m, 러너가 읽는 누적 키).

| 오차 표 | e (0.1 / 0.3 s) | ψ (0.1 / 0.3 s) | r | 필요 거리 |
|---|---|---|---|---|
| 보고 오도메트리(지금 Isaac 기본, `obstacle_odometry_age.json`) | 0.0241 / 0.0421 m | 0.0144 / 0.0260 rad | 0.091–0.232 m | **0.17–0.31 m** |
| 팀 규격 엔코더, 새 표(feat/team-spec-age-table 8c80683a, sha256 b853b34a…, PR 전) | 0.0193 / 0.0257 m | 0.0080 / 0.0142 rad | 0.083–0.157 m | **0.158–0.233 m** |
| (참고) main 의 옛 팀 규격 표 / 팀 규격 + 자이로 표 | 0.0077 / 0.0065 m(0.1 s, `position_max_m`) | 0.0024 / 0.0006 rad | 0.067–0.086 m | 0.145–0.158 m |

새 팀 규격 표는 모든 보고 Isaac 임무에서 다시 잰 것이다. 짧은 나이 yaw 가 0.2 s 에서 0.0029 → 0.0137 rad 로 커졌다(적재 선회 중 다리 끝 급정지 구간, rk3_aisle_out_s0 — 그 세션의 확인).
옛 팀 규격·자이로 표는 그 방식으로 다시 재지 않았다. 관절각 오도메트리를 기본으로 올리면 표시 반경이 옛 팀 규격 값이 아니라 새 표 수준이 된다는 뜻이다.
계획기 여유는 0.10 m(접근 0.05 m)라서 어느 표에서도 모자라다. 오차 표와 무관한 상수 몫이 약 0.13 m 다 — 거리 잡음 한계 0.06, 칸 도달 약 0.035, 정지 포락선 + 쓸림 약 0.035.
그래서 오도메트리를 좋게 해도 불일치는 남는다.
기록과도 맞는다. rack 기둥 하나(0.052 m 각)가 x 0.40 m 폭 덩어리로 칠해졌고(PR #106 결과, `rkt_aisle` 덤프), 트레일러 벽 띠는 면에서 0.178 m 까지였다(`2026-10-22-riibotics-trailer-exit.md` 1 장).

## 3. 설계안

### P1. 계획 여유를 장애물 층에 맞춘다

LiDAR 면(1.05 m)을 지나는 사전 지도 구조(소품 높이 > 1.05 m, 벽 경계)를 계획기가 G 만큼 더 키워서 본다. 안전 여유를 줄이지 않고 늘리는 쪽이다.

**정량화(UBAI CPU, main 47d653ae, 잡 1035987·1036281).** 리보틱스 장면은 `riibotics_isaac_scenes.plan_scene`(Isaac 임무 설정 그대로)으로, factory 는 `bay_planning_sweep --layout factory`(seed 0–49,
`--min-obstacle-height-m 1.15` 라 남은 소품은 모두 LiDAR 높이)로 계획만 했다. 추종·인식·허가는 없다. aisle 계열은 랙 뒤 경계도 G 만큼 당겼다. rack 사본은 금지 구역 없이(기둥 실제 크기) 썼다.

- **P1a — 모든 계획 구간에 G**

  | 장면 | G = 0 | 0.05 | 0.10 | 0.15 |
  |---|---|---|---|---|
  | factory seed 0–49 | 49/50(seed 47 운반 탐색 시간 초과) | 50/50 | 50/50 | 50/50 |
  | aisle(원래) | ✓ | ✗ | ✗ | ✗ |
  | aisle_rack · aisle_out_rack · trailer | ✓ | ✓ | ✗ | ✗ |
  | random_1–3_m | ✓ | ✓ | ✓ | ✗ |
  | line_1–3_m · conveyor | ✓ | ✓ | ✓ | ✓ |

  실패는 모두 `straight_in_collision` — 칸 사이로 들어가는 삽입·꺼내기·하역 직선과 트레일러 안 직선이다. 이 직선들은 구조에 붙어서 지나가도록 정해진 구간이다.
  필요 G 는 보고 표로 0.07–0.21 m, 새 팀 규격 표로 0.06–0.13 m(옛 팀 규격 표로는 약 0.05 m)다. 어느 표로도 P1a 는 좁은 장면 경로를 없앤다.
- **P1b — 탐색 구간(관측·접근·운반·귀환 탐색)에만 G, 고정 직선(접근·삽입·꺼내기·하역·빼내기)은 지금 여유로 실제 크기 소품을 검사.**
  출발 자세가 키운 구조 안쪽이면 탐색이 `invalid_start` 로 거부된다. 꺼낸 자리가 칸 앞 기둥 사이이고, 트레일러는 입구 안이다.
- **P1c — P1b + 운반 앞 출구 접두.** 트레일러 접두(PR #91 `ExitPrefix`)를 일반화한다. 실제 크기의 LiDAR 높이 구조에서 1.5·(G + 0.10) + 0.01 m 떨어질 때까지 0.05 m 씩 직진 후진하며, 상한은 1.0 m 다.
  1.5 배인 이유: 접두의 이격은 유클리드 거리로 재는데 탐색 검사는 여유를 차체 축 방향으로 붙인다. 모서리 근처에서는 √2 배까지 차이 나서, G + 0.10 으로는 접두 끝이 다시 거부됐다.

  | 장면 | P1b G = 0.05 | 0.10 | 0.15 | 0.20 | 0.25 | P1c G = 0.05 | 0.10 | 0.15 | 0.20 | 0.25 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | aisle(원래) · random_1–3_m · line_1–3_m | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
  | aisle_rack | ✓ | 운반 출발 거부 | 〃 | 〃 | 〃 | ✓ | ✓ | ✓ | 복귀 경로 없음 | 운반 출발 거부 |
  | aisle_out_rack | ✓ | 운반 경로 없음 | 운반 출발 거부 | 〃 | 〃 | ✓ | ✓ | ✓ | 복귀 경로 없음 | 복귀 출발 거부 |
  | trailer | ✓ | ✓ | 운반 출발 거부 | 〃 | 〃 | ✓ | ✓ | ✓ | ✓ | ✓ |

  (UBAI 잡 1036340. P1b·P1c 는 `pallet_mission._straight_plan` 을 실제 크기 소품으로 검사하도록 바꿔 끼운 스크립트로 쟀다. 저장소 코드가 아니다.)
  P1c 는 G = 0.15 m 까지 모든 좁은 장면을 통과한다. 새 팀 규격 표의 필요 G(0.06–0.13 m)는 이 범위 안이다. 보고 표의 필요 G(0.07–0.21 m)는 가장 나쁜 쪽(ρ 5 m·나이 0.3 s)이 넘는다.
  rack 사본이 0.20 m 에서 막히는 곳은 복귀다. 빼낸 자리가 키운 기둥 안쪽이고, 복귀 앞에는 접두가 없다. 같은 접두를 복귀에 붙이는 것은 재지 않았다.
- 남는 불일치: P1b·P1c 의 고정 직선은 지금 여유이고, 그중 허가가 적용되는 구간(접근 직선의 면제 전 부분, 포켓 단계의 삽입)은 그대로 어긋난다.
  rack 사본 Isaac 의 삽입은 `insert:occupied` 집계가 있어도 통과했다(칸 축 정렬이라 옆 기둥 덩어리까지 측면 약 0.13 m). 좁은 칸 틈에서는 확인이 필요하다.
- 안전 영향: 여유를 늘리기만 한다. 실차 SLAM 오차와는 무관하다. 사전 지도가 실제와 SLAM 오차만큼 어긋나도, 허가는 지도가 아니라 LiDAR 로 판정하므로 그 오차를 이미 다루지 않는다.
  남는 위험은 경로가 없어지는 것(좁은 장면)과, 고정 직선 구간(P1b)에서는 불일치가 그대로 남는 것이다.
- 실차 적용: 사전 지도에 "LiDAR 높이 구조" 표시(높이 또는 분류)가 필요하다. 지금 장면 형식에는 소품 높이가 있다.

### P2. 지도에 있는 정적 구조를 장애물 층에서 덜 키운다

사전 지도의 구조와 맞는 LiDAR 점은 r 대신 더 작은 반경(예: 최신 스캔만, 또는 표면에 붙인 사각형)으로 칠한다. **안전 판정 규칙을 바꾸는 안**이다.

- 근거로 쓸 수 있는 것: 정적 구조는 매 스캔 다시 보이므로, 나이 0.3 s 의 큰 원은 같은 면을 덮는 중복이다(최신 0.1 s 스캔이면 보고 표에서도 r 0.091–0.156 m).
- 위험:
  - 맞춤 판정이 지도 위치에 기대면 SLAM 오차가 들어온다. 지금 허가는 트럭 기준 LiDAR 만 쓰므로 SLAM 오차(이 문서가 쓰는 0.14–0.16 m)와 무관하다.
    지도 기준 표시는 그 오차 이상을 덮어야 하므로 지금보다 작아지지 않는다.
  - 맞춤을 LiDAR 점끼리(같은 면이 반복 관측됨)로만 하면 지도 오차는 피하지만, 구조 옆에 붙은 사람·물체가 같은 면으로 묶일 위험이 있다.
    `close_gap` 0.25 m 메우기가 이미 가까운 점을 잇는다.
  - 기존 known_pallets(지도 사각형을 허가에 넣는 장치)는 사각형 반경이 인식 0.3 s 뒤 상한 0.20 m 를 넘어 트럭을 세워서 꺼져 있다(D8 까지, 사용자 2026-10-08).
    덜 키우는 방향과는 반대 문제지만, 지도 사각형을 허가에 들이는 규칙이 아직 검증되지 않았다는 근거다.
- 정량 근거가 부족하다. 이 안을 고르려면 위험 시나리오(구조 옆 사람·지도 어긋남) 시험을 먼저 설계해야 한다.

### P3. 오차 모형을 실측으로 줄인다 (P1·P2 와 함께 쓰는 안)

지금 표는 Isaac 보고 오도메트리의 오차다. 새 팀 규격 표(1.1)로 바꾸면 r 이 0.083–0.157 m, 필요 거리가 0.158–0.233 m 로 준다 — 보고 표(0.17–0.31 m)보다 작지만 줄어드는 폭이 크지 않다.
옛 팀 규격·자이로 표 수준(0.145–0.158 m)은 같은 방식으로 다시 재야 확인된다. 실차 엔코더·자이로 측정이 최종 근거다.

- 규칙은 그대로 두고 값만 측정으로 바꾸는 안이다. P0a 고정값을 다시 정하는 것이라 사용자 결정 사항이다.
- 실차 측정이 필요하다. 관절각 오도메트리(PR #92)는 머지됐지만 승격이 보류됐다 — 팀 규격 나이 표의 범위가 부족하다.
- 이것만으로는 상수 몫(약 0.13 m)이 남아 계획기 0.10 m 와 여전히 어긋난다. P1 의 G 를 새 팀 규격 표로 0.06–0.13 m 까지 줄여 줄 뿐이다.

### P4. 국소 처리 (지금 방식)

구조마다 경로를 고친다 — 트레일러 출구 접두(PR #91), rack 장면 우회(PR #106). 일반 규칙이 아니라 장면마다 새로 만들어야 하고, rack 은 작업 칸 회전에서 실패했다.

### P5. 계획기가 실행 중 격자를 본다 (격자 계획)

`--grid-planning` 은 이미 있다(관측 칸 + 계획 기억). 보이는 것은 허가와 같은 칸이라 일치하지만, 리보틱스 장면은 1.05 m 아래 바닥 팔레트를 격자가 못 봐서 막혀 있다.
사전 지도 소품과 격자를 합치는 변경과, 2382 류의 재계획–허가 쓸림 차(복구–허가 정합 4 판)를 함께 다뤄야 한다. 변경이 가장 크다.

## 4. 기존 결정과의 관계

- **PALLET_KEEP_M 0.3 보류(fleet, 2026-10-20):** 바닥 팔레트는 LiDAR 면 아래라 이 불일치와 다른 문제다. 그대로 둔다. 근거로 쓴 SLAM 0.14–0.16 m 는 Isaac 리보틱스 장면 임무 전체의 최대 오차이고 실차 측정이 아니다.
- **CT-1 D1 0.25 m(`prior_grow_m`, 2026-10-22):** 인식 안 된 이웃 팔레트를 명목 외곽 + 0.25 m 로 허가에 넣는 임시값이다. 사전 정보를 키워서 넣는다는 점에서 P1 과 같은 방향이다. 그대로 둔다.
- **트레일러 출구 접두(X = 0.30 m):** P4 의 한 사례다. P1b 가 운반 탐색에 G 를 주면 접두가 없어도 될 수 있지만, 접두는 그대로 두고 P1 결과로 다시 본다.
- **known_pallets 꺼짐(D8 까지):** P2 와 같은 종류의 장치다. P2 를 고르면 D8 조건과 함께 다룬다.
- **P0a 고정값:** P3 은 이 값을 바꾼다. P1 은 바꾸지 않는다.

## 5. 결정 항목 (사용자)

- 방향: P1(a/b) · P2 · P3 · P5 중 무엇을, 어떤 조합으로 할지.
- 권고: **P1c(G 는 쓰는 나이 표에서 계산, 지금 새 팀 규격 표 기준 0.13 m · 보고 표 기준 0.15 m 상한) + P3(실차 측정으로 표를 확정)**.
  - P1c 는 안전 여유를 줄이지 않고 탐색 경로를 허가와 맞추며, 트레일러 접두를 일반 규칙으로 흡수한다.
  - 보고 표의 최악값(0.21 m)까지 덮으려면 복귀 앞 접두를 더하고 다시 재야 한다.
  - P3 은 실차 측정으로 G 를 줄인다. 다만 새 팀 규격 표로는 줄어드는 폭이 작다(1.1).
  - P2 는 위험 근거가 부족해 지금 권하지 않는다.
  - P5 는 범위가 커서 P1c 로 부족할 때 다시 본다.
