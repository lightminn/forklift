# 취소 뒤 다른 대상 임무 실패 — 재현 배치 사전 등록 초안 (2026-11-09, 결과 전)

- 근거: [생명주기 4 확인 실행 결과](../validation/2026-11-09-live-riib-v2-lifecycle4-confirmation.md)(#377). 확인 실행에서 m2(P-5 → D-2)가 두 세션(B seed 1, A seed 0)에서 운반 단계, D-2 입구 앞에서 `occupied` 로 끝났다. 본배치의 정상 m2 는 9 세션 모두 done 이었다.
- 총괄 결정(2026-11-09): 콘솔이 조사한다. ④⑤ 승격과 ② 는 이 조사의 결론 뒤다. 코드 수정은 결론과 총괄 결정 뒤에 한다. 2026-10-27 trailer 계열과 같은 원인으로 확인되면 그 백로그와 합친다.
- 설계: Codex 상의(2026-11-09)를 거쳐 2×2 를 H1D0 대 H0D0 두 팔로 줄였다(1.2).

## 0. 이 배치가 답하는 것과 답하지 않는 것

- **첫 질문**: 그 실패가 '취소·회복 이력을 가진 상태'에서만 나는지, 아니면 운반 입구의 일시적 `occupied` 가 드물게 굳어지는 일반 계열인지. 두 설명은 서로 배타적이지 않다. 일반 계열이 있고, 그 위에서 이력이 발생률을 높일 수도 있다. 그래서 판정에는 '둘 다'와 '미결'이 있다.
- **이 배치는 원인을 좁히는 재현 배치다. 인과 판정이 아니다.** 아래 H0 는 '같은 자세에서 새로 시작한 세션'이다. H1 과의 차이에는 취소 전환 자체 말고도 다음이 함께 들어간다.
  - 주행으로 쌓인 SLAM·장애물 메모리·P-4 인식 정보.
  - H0 에만 있는 시작 재위치.
  - H0 에만 있는 운전자 배치 시작(`F1_AUTONOMY=allow`).
  - 그래서 차이가 나도 '취소 상태 누수 확인'으로 쓰지 않는다. 취소 전환의 인과효과가 필요하면, 같은 checkpoint 에서 의심하는 상태만 바꾸는 별도 개입이 필요하다(이 배치 범위 밖).
- D(D-1 의 P-4 유무)는 이번에 고정한다(D-1 비움). 세 가지 만드는 법이 모두 다른 변수를 함께 바꾸기 때문이다.
  - 정상 m1 완료: 귀환 자세·주행·지도·인식 이력·슬롯 앵커가 함께 달라진다.
  - P-4 참값만 D-1 로 옮김: `delivered` 상태와 슬롯 앵커가 생기지 않는다.
  - 다른 팔레트 취소 추가: H 요인 자체가 달라진다.
  - D 의 관여는 기록 기반 선행 검사(3 절)로만 본다.

## 1. 팔과 조건

### 1.1 공통

- 팔 A(라이브 현재 기본, ④⑤ 끔), 장면 random_m(`scenes_ct1_a770031/random_m_session.json`).
- 지도: registry 의 random_m 행이고, `MAP_BUNDLE=registry` 로 행이 없으면 시작하지 않는다.
- 같은 스냅숏(계측 보강 PR 머지 뒤 main), 같은 인식 모델·배속 0.3·따라잡기 6, `MAX_EPOCHS=1`.
- 진단 계측 `--occupied-dumps` 켬(EXTRA_ARGS).
- 래퍼는 v2 의 `riib_session_v2.sh` 를 바탕으로 한다. 계측 켬과 H0 의 시작 자세만 더한 사본을 쓰고, 해시를 남긴다.

### 1.2 두 팔

| 팔 | 구성 |
|---|---|
| H1(취소 이력 있음) | `cycle P-4:D-1,P-5:D-2 --stop-wait-at approach:5 --stop-wait-sim-s 5 --manual-recovery --end-session` — 확인 실행과 같은 연쇄 |
| H0(이력 없음) | `queue P-5:D-2 --end-session`. 시작은 `START_POSE` 로 맞춘 자세(1.3), `RELOC_UNATTENDED=1`, `F1_AUTONOMY=allow`. P-4 는 원래 자리 그대로 |

- 판정 대상 임무는 순번이 아니라 (P-5, D-2, mission_id)로 찾는다. H0 에서는 P-5 임무가 m1 이다.

### 1.3 H0 의 시작 자세

- 목표: 확인 실행 네 세션(성공·실패 모두)의 P-5 제출 시점(`transitions` 의 m2 진입) 참값 뒷차축(spool `slam.control` 4–6 열)의 중앙값 (−1.2691, 0.8528, 0.1706)이다. 네 값의 범위는 x −1.2718 ~ −1.2669, y 0.842 ~ 0.858, yaw 0.168 ~ 0.172 다.
- `START_POSE` 는 world 의 base_link 참값 배치라서 뒷차축에서 변환한다. base = rear + d·(cos yaw, sin yaw), d = 0.34 m(실행 URDF 의 `read_chassis_reference_m`: 뒷차축 x −0.34). 그래서 `START_POSE="-0.9340,0.9106,0.1706"` 이다.
- 맞춤 확인: 배치 뒤 정착한 참값 뒷차축이 목표에서 위치 0.02 m·yaw 0.02 rad 안이어야 그 세션을 센다(제안값, 기존 검증값 아님). 밖이면 판정 불가로 남기고, 다시 배치하지 않는다. 시작 속도·조향각·포크 높이·적재 없음을 함께 기록한다.
- 자세는 위 고정값이다. 새 H1 결과를 보고 고르지 않는다.

### 1.4 seed 와 실행

- 새 seed 쌍 {2, …, N+1}(N 은 총괄 결정, 권고 24 — 4 절). 각 seed 에서 H1·H0 한 세션씩 짝짓는다.
- 확인 실행의 seed 0·1 H1 기록은 재현 앵커로 보고만 하고, 주 분석에서 뺀다.
- 묶음: 한 잡, 슬롯 2, 목록은 seed 순서다. seed 마다 두 팔이 이웃한다. 홀수 seed 는 H1 을 먼저, 짝수 seed 는 H0 를 먼저 둔다. 실행기는 빈 슬롯을 바로 채우므로 짝이 늘 함께 돈다는 보장은 없다. 실제로 겹친 짝은 기록한다.
- 자원은 확인 실행과 같다(shard 4·CPU 8·19G). 텔레옵(수동 회복)이 있어서 실행 중 ws1 에 다른 잡을 두지 않는다.
- 다시 내는 규칙: 기반 실패(Isaac 기동 실패·`startup_silent`·`startup_viewport`·탐침 전 래퍼 종료)만, 세션마다 1 회 다시 낸다. 재위치 불확정·STOP 창 놓침·회복 미완료·자세 불일치는 관측 결과로 남기고 다시 내지 않는다.

## 2. 판정 (결과 전 고정)

### 2.1 실패 F

같은 임무(P-5 → D-2)의 운반 단계에서, **참값 뒷차축이 D-2 중심에서 3.0 m 안**인 구간(입구)에서 다음 중 하나로 임무가 끝나면 F 다.
- **Fₚ(허가 정지형)**: 최종 허가 0·`occupied` 가 연속 5 시뮬 s 이상이고, 해소되지 않아 운반 실패로 끝난다. 증거는 그 hold 의 5 s 덤프(`hold_dump`, `hold_age_s` ≥ 5)와 임무 결과다. `permit_stop → invalid_start → timeout` 사슬은 따로 표기한다.
- **F꜀(후보 거부형)**: 같은 입구의 cusp 재계획이 후보 대기(3 s)를 거쳐 `blocked:occupied` 로 끝난다. 허가 `occupied` 틱이 0 이어도 포함한다. 증거는 `scene_replans` 의 결과와 `candidate_dump` 다.

3.0 m·5 s 는 이 등록의 값이다. 정상 일시 사건과 비교하려고, 연속 hold 길이·최종 허가·막힌 칸을 함께 보고한다.

### 2.2 세션을 세는 조건

- 공통: 설정·코드·모델·장면·지도·브리지 이미지 해시, 실제 런처·탐침 인자, `slam_choice`, 시작 모드, 요청·응답·결과, spool 완결, 덤프 목록(`state["occupied_dumps"]`). 목록에 '예산 소진' 이 있으면 그 사실을 보고한다.
- H1: 확인 실행 판정과 같은 STOP 유효·정지 유지·대상 일치·회복 연쇄.
- H0: 1.3 의 자세 맞춤과 재위치 확정.
- P-5 임무가 운반에 닿지 못했거나 위 기록이 빠진 세션은 성공으로도 실패로도 세지 않는다. 미결로 남긴다. 진단 기록만 빠진 F 는 실패로 세고, 기전만 미결로 둔다.

### 2.3 주 검정과 결론

- seed 쌍마다 b = H1 만 F, c = H0 만 F 다.
- 주 검정은 단측 정확 McNemar(H1 쪽 초과), α = 0.05 다. H1 쪽 초과로 판정하는 최소 b 는 다음과 같다.

| c | 최소 b |
|---|---|
| 0 | 5 |
| 1 | 7 |
| 2 | 9 |
| 3 | 10 |

| 관측 | 결론 |
|---|---|
| 주 검정 통과 | **H1(이력) 조건에서 실패 초과.** 취소의 인과효과까지는 확정하지 않는다. |
| H0 의 서로 다른 seed 에서 같은 하위 유형·기전의 F 가 2 회 이상 | **이력 없이도 그 계열 재현**(일반 계열). 2 회는 재현 기준이고, 실패율이 같다는 기준은 아니다. |
| 둘 다 | 일반 계열이 있고, H1 조건에서 더 자주 난다. |
| 두 팔 모두 F 0 | 이번 범위에서 재현하지 못했다. |
| 그 밖 | 미결 또는 다른 실패 계열. |

- H0 의 F 하나라도 완전한 증거가 있으면, '취소 이력이 반드시 필요하다' 는 명제를 반박하는 데 쓴다. 다만 그것이 H0 의 새 재위치가 만든 별개 실패가 아닌지를 확인한 뒤에만 일반 계열로 잇는다.
- 미결 세션을 가능한 어느 방향으로 배정해도 결론이 그대로일 때만 결론을 낸다. 아니면 그 결론은 미결이다.

### 2.4 정지 규칙

- 예정한 N 쌍을 다 돌면 끝낸다. 실패 수나 p 값을 보고 늘리거나 줄이지 않는다.
- 필수 기록 결손을 발견하면 뒤 실행을 멈추고 계측을 고친다. 고치기 전후 결과는 합치지 않는다.
- 금지 접촉이나 장면 손상이 나오면 배치를 멈추고, 그때까지의 결과를 보존한다.

### 2.5 검정력(참고, 판정에 안 씀)

- 가정은 seed 쌍 사이 독립, 팔 사이 독립 Bernoulli 다(Codex 계산).
- H1/H0 실패율이 50 %/5 % 이면 검정력은 16 쌍 83 %·24 쌍 97 %, 50 %/10 % 이면 67 %·88 %, 25 %/5 % 이면 21 %·43 % 다.
- 24 쌍은 큰 차이를 찾는 진단 배치다. 작은 차이는 가르지 못한다.
- H0 가 0/24 이면 단측 95 % 정확 상한은 11.7 % 다.

## 3. 기록 기반 선행 검사 (D 의 관여, Isaac 없이)

1. 정상 m2(본배치 9 세션)와 실패 m2(확인 실행 2 세션)에서 P-4 의 추정 외곽·불확실도·슬롯 앵커를 비교한다.
2. B seed 1 의 막힌 칸, 원래 운반 경로, 재계획 입력이 서로 겹치는지 본다.
3. 가능하면 저장된 입력의 사본에서 이웃 팔레트 표현만 바꿔, 계획·허가 검사를 다시 한다.

- 이 검사는 직접적인 기하 관여 가능성만 가른다. 막힌 칸이 P-4 외곽 밖이라는 사실만으로, 경로 선택을 통한 D 의 영향을 배제하지는 못한다.
- known-pallet 처리는 이미 있는 `OCCUPIED` 를 지우지 않는다. 그래서 '알려진 팔레트가 있었다면 그 칸이 풀렸을 것' 이라는 해석은 성립하지 않는다.
