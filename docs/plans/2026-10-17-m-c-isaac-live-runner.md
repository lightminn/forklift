# M-c Isaac 실시간 실행기 계획

작성: 2026-10-17 · 상태: **4판 — Codex 3회차까지 반영, 재검토 중** · 근거: [운용 콘솔 설계](../design/2026-10-13-operator-console.md) 5.3·5.4·6·7.2·7.3·9절, [콘솔 계약 초안](../interfaces/2026-10-13-operator-console-contract-draft.md) 1–7·9절, [M-b 계획](2026-10-16-m-b-arbiter.md), [C2a 관찰 게이트웨이 설계](../design/2026-10-15-console-gateway-monitor.md)

## 1. 범위

**목표.** Isaac 안의 지게차를 웹 콘솔(`console/web`)로 실시간 조종·관찰한다. 판정 배치 실행기와 같은 미션 코어·중재기를 쓰되, 벽시계 1배속으로 돌고, 콘솔의 요청을 중재기(M-b)가 처리한다. 설계 6절의 M-c 정의와 계약 9절의 M-c 분담을 이번 판의 할 일로 삼는다.

- 포함
  - 실시간 페이싱: 물리 스텝을 벽시계에 맞춘다. 건너뛰거나 밀린 만큼 몰아서 돌지 않는다. 배속·지연을 재고 미달이면 상태에 싣고 수동 조종을 막는다.
  - 실행기의 실시간 모드(`run_transport.py --live`): 중재기를 주기마다 돌리고(M-b B3 순서), 출력(AUTO 후보, TELEOP 명령, 선점 0)을 바퀴·조향에 넣는다. 판정 배치(`--live` 없음)는 바뀌지 않는다.
  - 콘솔 서버: 같은 프로세스의 별도 스레드에서 console/1(제어·미디어 두 WebSocket)을 연다. 전송 규칙은 `console/wire.py` 를 그대로 쓴다. 노드·포트·`session_epoch` 를 파일로 남긴다(설계 7.2).
  - 미디어: 전방(마스트) 카메라 JPEG(촬영 단위 `frame_id`, 렌더 결과를 받은 차량 단조 시각), LiDAR 스캔, 장애물 격자. 대상 목록(`targets`).
  - `camera_latency_bound_s` 측정: 렌더 요청부터 영상 버퍼를 받기까지의 차량 단조 시각 분포를 실시간·미디어 부하 조건에서 잰다.
  - 잡마다 새 `session_epoch`(예측할 수 없는 값). 같은 잡 안에서 장면을 다시 시작하는 기능은 두지 않는다 — 새 장면은 새 잡이고 새 epoch 다.
- 제외
  - ROS 2 msg/action 과 게이트웨이 노드(C2b, 콘솔 쪽). 이번 콘솔 서버는 실행기 안의 직접 연결이다. C2b 가 생기면 같은 중재기 입출력을 ROS 로 옮긴다.
  - 비동기 포트와 늦은 결과 폐기(M-a 계획 D5 의 "M-c 전 별건"). 이번 판은 동기 포트 그대로 둔다: 계획이 도는 동안 sim 시각이 멈추고 페이싱이 미달로 표시된다(캡처는 sim 을 멈추지 않는다 — 안에서 물리 스텝을 돌린다). 만료·lease 는 차량 단조 시계로 계속 흐르므로(설계 5.2) 그 사이 텔레옵은 만료로 멈춘다.
  - 복구 동작 `withdraw_straight`, 수동 승강(M-b 와 같음).
  - 실차(C4)·H3.

**완료 조건.**
1. CPU 시험: 페이싱(몰아 돌기 없음, 이력), 연결부(통로 상한·최신값·STOP 통로, 물리 스텝 `gate`, 연결 소유권), 콘솔 서버(가짜 연결부, 실제 WebSocket, 종료 순서·포트 파일)의 단위·통합 시험.
2. ws1 Isaac 기능 시험(설계 9절 C3 범위의 메인 쪽 몫, 안전 검증 아님). 스크립트 클라이언트로 한 실행 안에서 다음을 거치고, **기록(C4)으로** 판정한다. 검토에서 나온 반례(틱 안 STOP 뒤 AUTO 승격 없음, welcome 직후 STOP, 연결 교체 때 lease 박탈, 틱 안 STOP 뒤 승강·단계 정지)는 CPU 회귀 시험으로도 둔다.
   - lease → 작업 지시(AUTO) → 일시정지 → TELEOP 진입·무장 → 30 s 연속 주행(속도·곡률·방향 반전 포함) 동안 페이싱 `ok` 유지와 의도하지 않은 만료 없음(agy G3), 조향 응답 기록
   - 명령 끊김 → 만료 뒤 **첫 물리 스텝부터** 바퀴 0
   - 계획(동기 호출) 중 STOP → 그 호출 안의 다음 물리 스텝부터 바퀴 0(설계 C3)
   - STOP 뒤 정지까지의 거리·시간 기록(agy G4)
   - 제어 연결 끊김·재연결(유예 안 재획득, 새 `lease_id`), 영상 정지(카메라 구독은 살아 있는데 렌더를 멈춤) → 영상 조종 명령 거부·무장 해제(설계 C3)
   - 재무장 → 재개 → 완료
   - 미디어: JPEG 디코딩 성공, `frame_id` 단조 증가, `acquired_mono` 단조, 프레임 간격이 구독 상한 근처(agy G1). 최대 구독에서의 페이싱(agy G5)
   - 제어 왕복 지연: 텔레옵 명령을 보낸 시각부터 그 명령이 적용된 `state` 를 받은 시각까지(같은 클라이언트 시계) 분포를 남긴다(agy G2 — 이번 판은 합격 문턱 없이 기록)
   - 잡을 다시 띄우면 이전 `lease_id`·세대가 `stale_epoch` 로 거부
   - 페이싱을 일부러 늦춘 실행에서 텔레옵 주행이 막힘
   - 정상 종료: close frame, 포트 파일 `ended`, 종료 코드 0(agy G6)
3. 판정 배치 불변: 재생 29건, ws1 전체 시험(실패 = 알려진 10건).
4. `camera_latency_bound_s` 측정값과 그 조건을 증거 문서에 남긴다.
5. M-b 가 M-c 에 넘긴 확인(조향 전환의 원호 다발 근사, 증거 노화, 방향 반전)을 위 실행의 기록으로 확인하고, 근사가 부족하면 그 사실을 적는다.

## 2. 결정

**C1 페이싱(순수, `forklift_core/live/pacing.py`).** `Pacer(target_factor, dt, window_s=1.0, min_ratio=0.9, ok_hold_s=1.0)`.

- **스텝 사이 최소 벽시간.** 물리 스텝마다 `wait_s(now)` 만큼 잔 뒤 **깨어난 실제 시각**으로 `started(now)` 를 부르고, 스텝을 마치면 `after_step(now)` 를 부른다. 다음 스텝은 직전 스텝의 실제 시작에서 `dt / target_factor` 뒤에야 시작한다(늦게 깬 잠이 다음 스텝 간격을 줄이지 않는다 — Codex 3회차 P2). 밀린 시간을 따라잡으려고 이 간격보다 빨리 도는 일은 없다 — 한 번 늦은 스텝 뒤에도 다음 스텝은 정해진 간격을 지킨다(Codex 1회차 P2: 기준점 방식은 200 ms 지연 뒤 27 스텝을 27 ms 에 몰아 돌렸다). 목표보다 빠르게 도는 일도 없다.
- 배속: 최근 `window_s` 벽시간 동안의 `Δsim/Δwall`. 지연(`lag_s`)은 마지막 스텝 간격이 목표 간격을 넘은 양.
- `ok` 는 이력을 둔다: 거짓 → 참은 배속 ≥ `min_ratio × target_factor` 가 `ok_hold_s` 동안 이어질 때, 참 → 거짓은 창 평균이 문턱 밑으로 내려가거나 한 스텝 간격이 `0.25 s` 를 넘을 때(동기 호출). 렌더 스텝마다의 짧은 출렁임으로 뒤집히지 않는다(agy T3).
- **목표 배속은 설정값이다**(`--live-factor`, 기본 1.0). 실측(검토 ①): 지금 배치 실행 전체의 배속은 0.61 이다(`ma3b_p_obs` 시뮬레이션 223.5 s / 벽시계 368.4 s, 장면 준비·계획·캡처·SLAM 동기 대기 포함). 정상 주행 구간의 배속은 M-c1 의 첫 Isaac 실측으로 정한다. 1.0 을 유지하지 못하면 목표를 낮춰 선언한다. 목표보다 느린 sim 은 같은 벽시간에 덜 움직이므로 조종 지연과 만료(벽시계)에 대해 안전한 쪽이다. 상태에는 목표와 실측을 함께 싣고(`pacing.target_factor`·`realtime_factor`), `ok` 는 선언한 목표 기준이다.

**C2 중재기 연결부(`sim/isaac/live_link.py`, Isaac 없이 시험 가능).** 중재기는 실행기 제어 스레드에서만 돈다(캡처 안의 물리 스텝도 같은 스레드다). 콘솔 서버 스레드와는 아래 통로로만 주고받는다.

- **들어오는 통로 넷**(서버 스레드가 넣고 제어 스레드가 꺼냄, 모두 잠금 하나로 보호):
  - 연결 통로: 연결·끊김. 상한 없이 받고 **STOP 보다 먼저** 처리한다 — welcome 직후 보낸 STOP 이 등록 전의 클라이언트로 버려지지 않게(Codex 2회차 P1). 그래도 모르는 클라이언트의 STOP 은 정지를 실행한다(답할 곳은 없다).
  - STOP 통로: STOP 요청(`conn_id`, `request_id`). 상한 없이 받되 같은 연결의 같은 `request_id` 는 하나로 합친다. 어떤 경우에도 버리지 않는다.
  - 순서 통로: 신뢰 요청(STOP 제외)을 도착 순서대로. 상한 256. 넘으면 서버 스레드가 그 요청에 `reject(busy)` 를 바로 답한다(저장하지 않는다 — 계약 1절의 `busy` 와 같은 뜻: 받지 않았다).
  - 최신값 칸: `teleop`·`echo`·`input_state` 는 연결별·종류별로 마지막 것 하나만 남긴다(계약 1절 "최신값만").
- **나가는 통로**: `(conn_id 또는 broadcast, message)`. 서버 스레드가 `call_soon_threadsafe` 로 꺼내 해당 연결의 송신 큐(`wire.py`)에 넣는다. 끊긴 연결로 가는 답은 버린다(재전송하면 저장된 결과를 받는다).
- **주기 순서**(M-b B3 + 물리 스텝 경계):
  1. 주기 첫머리: `observe(now, feedback)` → STOP 통로 → 순서 통로 → 최신값 칸 → `mission_context` → `core.commands.apply(t, Context(stop_kind, near_tracker))`.
  2. 코어 틱(계획·캡처 같은 동기 호출이 이 안에서 물리 스텝을 돌릴 수 있다).
  3. `resolve` → `step(now)`(머리에서 명령·lease 만료를 다시 본다 — 코어 틱이 오래 걸린 뒤 낡은 명령을 내지 않게, Codex 1회차 P1) → 출력 적용.
  - **모든 물리 스텝 직전(`step_world`, 캡처 안 포함)에 `gate(now)`** 를 부른다: 연결 통로와 STOP 통로를 비워 정지를 실행하고(STOP 의 효과는 순서와 무관하다 — 좁히기만 한다), 명령·lease 만료를 본다. 정지(`STOPPED`·선점 래치)면:
    - 그 스텝부터 바퀴 0, 조향 유지, **승강 목표를 최초 선점 스텝의 실측 승강 위치로 한 번 래치**하고 정지 동안 그 값을 유지한다(이미 내린 관절 목표를 향한 운동을 멈춘다 — Codex 2회차 P1). 매 스텝 실측으로 다시 맞추지 않는다 — 짐을 든 승강의 처짐이 래칫이 된다(M-a3 의 낙하 반례).
    - **그 코어 틱의 남은 미션 작업을 하지 않는다**: 캡처에서 돌아온 뒤의 인식 후속 처리(단계 전이 포함)·승강·시간 전이·추종·허가를 건너뛰고 그 틱을 일시정지 틱으로 끝낸다(실행기는 `gate` 가 정지를 낸 틱을 표시하고 캡처 반환 직후와 각 후속 단계 앞에서 확인한다). 미션은 다음 주기 첫머리에 `preempt` 를 받아 `paused` 가 된다.
    - `resolve` 는 `mission_context` 뒤에 경계가 있었으면 AUTO 로 올리지 않는다 — 틱 머리에서 수락된 제출이 그 틱 안의 STOP 을 덮지 않게(Codex 2회차 P1, 구현됨).
- **시계.** 중재기의 `now_mono` 는 `time.monotonic()`. 미션 코어에는 sim 시각 `t`. 둘을 빼지 않는다(계약 1절).
- **피드백의 시각은 표본을 만든 물리 스텝의 단조 시각이다.** 실행기는 오도메트리 속도·요 각속도를 계산하는 물리 스텝에서 `time.monotonic()` 을 함께 남기고, 중재기에는 그 값을 준다(Codex 1회차 P1: 읽는 순간 다시 찍으면 동기 대기 동안의 공백이 사라진다). 그래서 sim 이 멈춘 동안 피드백은 낡고, 정지 확인은 새 표본이 올 때까지 거짓이다.
- **장애물 증거의 신선도는 sim 시각으로 둔다(AUTO·TELEOP 허가 공통).** 근거: Isaac 안의 장애물·센서는 sim 시각으로만 움직이고 측정된다. sim 이 멈추면 세계도 멈추므로, 증거가 세계에 비해 얼마나 낡았는지는 sim 시각의 차이다. 벽시계로 재면 계획 중 sim 이 멈췄을 뿐 세계는 그대로인데 증거를 낡았다고 판정한다. 계약의 '차량 단조 시계' 규칙은 사람·네트워크가 끼는 명령·영상·lease 의 신선도이며 이번 판에서 그대로 지킨다(중재기). 실차는 센서 시각과 차량 시계가 같은 영역이라 이 구분이 없다.
- **입력 검증.** 중재기 입구(`safety/validate.py`)에서 계약 형식을 본다: 정수 필드, 문자열 필드, 비율 범위, `deadman` 은 bool, `echo`·`frame_echo` 는 객체. 어긋나면 신뢰 요청은 `invalid`, 최신값은 버린다(Codex 3회차 P1: `deadman: "false"` 가 주행했다). 연결부는 처리 중 예외를 기록하고 `invalid` 로 답한다 — 메시지 하나가 실행기를 끝내지 않는다.
- **미션 답의 연결.** 미션 요청은 요청한 연결을 기억하고, 판정 때 그 연결이 그 클라이언트의 현재 연결이 아니면 답을 버린다(저장은 한다 — 재전송하면 받는다, Codex 3회차 P2).
- **연결 소유권.** 중재기가 `conn_id` 를 안다(M-b 의 작은 확장): `connect(client_id, now, conn_id=)` 는 그 클라이언트의 현재 연결을 바꾸고, `disconnect`·메시지는 현재 연결의 것만 효과가 있다(STOP 은 예외 — 늘 정지를 실행한다). 같은 `client_id` 의 이전 연결이 늦게 끊겨도 새 연결은 남는다(Codex 1회차 P1). **lease 보유자의 새 연결은 lease 를 승계하지 않는다**: 기존 lease 를 잃고(유예 예약), TELEOP 이면 선점·무장 해제·`PAUSED`, 새 연결이 `lease_request` 로 새 `lease_id` 를 받는다(계약 2절, Codex 2회차 P1, 구현됨).
- 피드백·출력 적용·미션 제출·페이싱 미달 처리는 1판과 같다: TELEOP 출력은 코어와 같은 뒷단(Ackermann·조향 속도 제한)에 넣고 결과를 `applied` 로 싣고 코어 명령 상태 셋에 되쓴다. 실시간 모드는 스스로 제출하지 않는다. 페이싱 미달이면 TELEOP 주행 거부(사유 `pacing`). AUTO 는 막지 않는다.

**C3 콘솔 서버(`console/live/`).** 가짜 차량 서버의 `Handle` 구조와 `console/wire.py` 를 쓰고, 차량 자리에 `LiveVehicle`(C2 의 통로에 넣고 바로 돌아오는 대리자)을 둔다.

- `welcome` 은 서버가 바로 만든다(`session_epoch`, `backend: "isaac"`, `capabilities`): `control: true`, `mission: true`, `teleop_direct`·`teleop_video: true`, `lift: false`, `recovery_actions: []`, `feedback`(바퀴 속도·조향·승강 높이 `true`, 적재 `false`), 미디어 상한(카메라 10 Hz·640×400, 스캔 10 Hz, 격자 1 Hz), `provisional_limits: true`.
- **미디어 저장소**: 종류별로 `(seq, 내용)` 묶음을 잠금 아래 한 번에 바꾼다. 읽는 쪽은 묶음을 통째로 가져간다(agy T1: 영상과 `frame_id` 가 어긋나지 않게). JPEG 인코딩은 서버 쪽 작업 스레드에서 한 번만 한다.
- **포트 파일**: 임시 파일에 쓴 뒤 이름을 바꿔 원자적으로 남긴다(agy A5). `{"host", "port", "session_epoch", "pid", "started", "state": "running"}`. 끝날 때 `"state": "ended"` 로 다시 쓴다.
- **종료 순서**(agy A4·T6): 실행기의 `finally` 에서 서버 스레드에 닫기를 요청(`call_soon_threadsafe`) → 모든 연결에 동시에 close frame(1001), 공통 예산 1.5 s, 남은 것은 끊음 → 루프 정지 → 스레드 `join`(제한 5 s). `stop()` 은 스레드가 끝났는지를 돌려주고, 끝나지 않았으면 포트 파일을 `ended` 가 아니라 `stop_failed` 로 쓴다(Codex 3회차 P2).

**C4 실행기 통합(`--live`).**

- `--live` 는 `--mission-commands` 와 함께 쓸 수 없다. `--max-sim-seconds` 는 그대로 상한이다.
- 렌더: 카메라 프레임이 필요한 물리 스텝(10 Hz 이면 12 스텝마다)에만 `render=True`.
- **촬영 식별과 지연**(Codex 1회차 P1). 렌더 결과에는 그 픽셀이 그려진 sim 시각(렌더 메타데이터 시각)이 붙는다 — `perception_adapter.py` 가 적어 둔 대로 이 시각은 물리 시각보다 1–4 렌더 늦을 수 있다. 그래서:
  - `frame_id` 는 **메타데이터 sim 시각** 하나에 하나다. 같은 시각의 버퍼를 다시 받으면 새 번호를 주지 않고, `acquired_mono` 는 처음 받은 시각을 지킨다(계약 4.2).
  - 물리 스텝마다 `(그 스텝을 마친 sim 시각 → 그 스텝을 **시작한** 단조 시각)` 을 짧게 보관한다. 지연 = `acquired_mono − 시작 mono(메타데이터 sim 시각의 스텝)`. 그 스텝 안의 렌더 시간까지 들어가는 보수적인 값이다(Codex 2회차 P1).
  - **픽셀과 메타데이터 시각의 대응은 따로 잰다**(C5). 메타데이터 시각이 나아가도 픽셀이 옛것일 수 있다는 점은 메타데이터만으로 증명되지 않는다(어댑터 주석). 그래서 C5 의 대응 시험으로 픽셀이 메타데이터보다 몇 렌더 늦는지 재고, 그 지연을 상한에 더한다.
- 격자는 장애물 층 스냅숏(코드 0·1·2, `origin_m`), 스캔은 실행기의 2D LiDAR 스캔(미측정 NaN).
- `state` 의 `pose` 는 제어 자세(뒤 차축, SLAM 이 있으면 `map`·보정 버전), `freshness`, `pacing`.
- **기록**(Codex 1회차 P2): `live_log.jsonl` 에 메시지마다 수신 단조 시각·처리한 주기·물리 스텝 번호와 결과, 주기마다 중재기 출력과 적용 직전의 명령 만료 시각, 물리 스텝마다(정지 중이면) 바퀴 0 적용 여부, 페이싱 표본, 카메라 지연 표본. 그래서 "만료 뒤 첫 물리 스텝이 0 이었는가"를 기록으로 판정할 수 있다. 실시간 실행은 재생 대상이 아니다 — 경계 기록기를 켜지 않는다.

**C4a 실행 비용에 맞춘 두 조정(2026-10-17, 첫 Isaac 실행들에서).**
- 원호 다발 허가(M-b B8)는 매 주기 원호마다 경로 검사를 새로 설치하면 2개 원호 32 ms·8개 150 ms 로 실시간 물리 스텝(배속 0.25 에서 33 ms)을 넘었다. 그래서 `BundlePermit` 은 배치의 장애물 층과 같은 방식으로, 격자가 바뀌거나 다발의 양 끝·방향이 바뀌거나 0.25 m 를 달렸을 때만 다시 설치하고, 그 사이에는 달린 거리만큼 각 원호의 확인 거리를 줄인다(`advance`). 매 주기 양 끝은 **현재** 실측·출력 곡률로 정지 호·센서 침묵·증거 나이까지 다 묻고, 가운데 원호는 줄어든 경로 거리와 FREE 증거 나이로 본다. 캐시는 방향마다 따로 두고(반전 구간에 매 주기 재설치하지 않게), 달린 거리는 오도메트리 자세가 실제로 움직인 sim 거리다(Codex 10회차).
- 카메라 주기는 sim 시각이 아니라 벽시계 기준이다(기본 5 Hz). sim 기준 10 Hz 는 배속 0.25 에서 벽시계 2.2 Hz 라 프레임 간격만으로 영상 나이 한도 0.5 s 를 넘었다.

**C5 카메라 지연 측정.**
- 메타데이터 기준: C4 의 정의로 실시간·미디어 구독 조건에서 분포(중앙값·p99·최댓값)를 잰다.
- **픽셀 대응 시험**: 시험 장면에 카메라 시야 안에서 sim 시각에 따라 정해진 대로 움직이는 표지(예: 물리 스텝마다 x 가 정해진 만큼 나아가는 작은 판)를 두고, 받은 각 영상에서 표지의 위치로 그 픽셀이 그려진 sim 시각을 되읽어 메타데이터 시각과 비교한다. 렌더 수 단위의 픽셀 지연 분포를 얻는다. 같은 버퍼를 다시 받거나(픽셀 고정·메타 전진) 렌더를 멈췄을 때 영상 나이가 커지는지도 이 장면으로 본다.
- `camera_latency_bound_s` 잠정값 = 메타데이터 기준 최댓값 + 픽셀 지연 최댓값(시간) + 여유. 증거 문서에 조건(해상도·구독 상한·GPU 공유)과 남는 한계(이 장면·이 설정에서의 측정)를 적는다.

**C6 ws1 실행.** Slurm GPU 잡(`--gres=shard:1`). 판정 배치와 같은 GPU 를 동시에 쓰지 않는다. 스크립트 클라이언트(`tools/live_console_probe.py`)는 같은 잡 안에서 포트 파일을 읽고 시나리오를 돈다.

## 5. 위험

- 동기 계획 동안 sim 이 멈춰 텔레옵이 만료로 끊긴다. 이번 판의 의도된 동작이고 화면에 페이싱 미달로 보인다. 근본 해결은 비동기 포트(별건). TELEOP 는 미션이 `held` 인 동안이라 미션의 계획이 돌지 않는다 — 텔레옵 중 끊김은 캡처·미디어 부하 쪽에서 온다.
- 캡처는 sim 을 멈추지 않는다 — 내부에서 물리 스텝을 돌린다(`SensorCapture`). 그래서 정지는 주기가 아니라 물리 스텝 경계(`gate`)에서 보장한다.
- Isaac 이 1배속을 못 낼 수 있다(배치 전체 0.61). 목표 배속을 낮춰 선언하는 길을 C1 에 두었다. 렌더가 10 Hz 에서도 목표를 깨면 카메라 상한을 낮춘다. 측정으로 정한다.
- 콘솔 서버 스레드가 GIL 을 오래 잡으면 제어 주기가 밀린다. Pillow 의 인코더가 GIL 을 놓는다는 것은 가정이다 — 최대 구독에서의 페이싱(완료 조건 2)으로 확인하고, 깨지면 인코딩을 별도 프로세스로 옮긴다(agy A1).
- ws1 터널이 Slurm 실행 노드까지 닿는지(설계 7.2)는 사람이 붙는 시연에서만 필요하다 — 기능 시험은 같은 잡 안 클라이언트로 한다.

## 6. 열린 질문과 계약 델타

- 계약 1절의 "신선도 판정은 차량 단조 시계로만"에 Isaac 예외를 적는다: 장애물 증거(격자 FREE 나이, 센서 침묵)는 sim 시각으로 잰다 — Isaac 안의 세계·센서는 sim 시각으로만 움직인다(Codex 2회차가 받아들임). 명령·영상·lease 는 그대로 단조 시계.

- 페이싱 기준값(0.9·0.25 s)은 잠정이다. 기능 시험의 배속 분포를 보고 정한다.
- C2b(ROS 게이트웨이)가 생기면 이 직접 연결을 남길지(개발용) 없앨지.
