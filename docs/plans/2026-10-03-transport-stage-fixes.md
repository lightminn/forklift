## T1 — 운반 cusp 에서 방향이 어긋나면 그 자리에서 다시 계획

**지금:** 추종기는 cusp 8 mm 앞(제동 창)에서 위치가 30 mm 안이어도 yaw 가 50 mrad 를 넘으면 실패를 확정하고, 실행기는 임무를 끝낸다.

**바꿈:** 실행기가 **운반 단계**에서 다음을 모두 만족할 때만 다시 계획한다.

- 추종기의 첫 실패 원인이 **cusp 의 방향 불일치**(`failure == "endpoint_heading"`, `at_cusp`)다.
- 지금 경로 위에 있다(`off_path` 가 거짓 — 추종기는 첫 원인을 유지하므로, 그 뒤 경로를 벗어나면 따로 알린다).
- 재계획 횟수가 2 회 미만이다(실패한 재계획도 센다).

절차:

1. **정지를 확인한다.** 실패한 추종기는 이미 0 을 명령한다. 명령 속도가 0 이고, 평면 속도 크기 ≤ `stop_speed_mps`(운반 추종기 0.012 m/s), yaw 각속도
   ≤ 0.02 rad/s 인 상태가 연속 12 틱(0.1 s) 이어져야 정지로 본다 — 전진축 속도만으로는 옆 미끄러짐·회전을 놓친다(검토 ②).
2. 정지한 실측 후축 자세에서 **운반 구간만**(`plan_transport_leg`: `plan_transport` 의 운반 탐색 + 마지막 직선과 같은 코드) **같은 planner 설정·같은
   clearance 0.10 m** 로 다시 계획한다. 계획기는 출발 자세를 그 여유로 검사하고(어기면 `invalid_start`), 쓸고 지나가는 구간도 각 동작·해석 연결을
   clearance + ds/2·(1 + r|κ|) 로 검사한다 — 새 경로도 같은 여유 검사를 통과한다.
3. 성공하면 운반 경로·추종기(설정 그대로)를 새 것으로 바꾸고, **결과의 활성 경로(`state["paths"]`)·`paths.json`·렌더의 운반 계획선**도 새 경로로
   갱신하며, 재계획 시간을 `planning_wall_s` 에 더한다. 바뀐 경로는 `cusp_replans[].replaced_path` 로 남긴다. 실패하면 지금처럼 끝낸다.

경로 이탈·최종 목표의 방향 불일치·다른 단계의 실패는 지금 그대로 끝낸다.

오프라인 확인: 실패 순간의 자세에서 3003 은 112 확장(탐색 구간 2.54 m, 전환 1·남은 원래 경로 1.68 m), 4007 은 272 확장(탐색 3.57 m, 꼬리 직선 포함
4.27 m, 전환 6–7·남은 원래 경로 3.63 m 에 cusp 3 개)으로 즉시 계획된다. **재계획 경로는 cusp 가 더 많다**(4007 은 3 → 7, 3003 은 0 → 2) — 원인인 적재
상태 곡선 진입의 yaw 지연은 그대로이므로 같은 실패가 다시 나올 수 있고, 그래서 횟수를 제한한다.

**적히지 않은 전제(검토 ③):** 실패 뒤 정지할 때까지 조향이 풀리며 움직이는 짧은 구간은 계획되지 않는다(이때는 실행기의 접촉 검사만 작동). 새 추종기는
남은 조향각·잔여 속도에서 출발한다. 출발 자세는 시뮬레이터 정답 자세이고, Isaac 에서는 계획하는 동안 물리가 멈춘다 — 실물에서는 추정 자세와 계획 중
움직임이 문제가 된다.

**구현:** `TrackingCommand` 에 `failure`(`cross_track`·`endpoint_heading`·None, 첫 원인), `at_cusp`, `off_path`(지금 이탈 여부)를 덧붙인다(기본값이
있어 기존 사용처 불변). `pallet_mission.plan_transport_leg`. 실행기는 `state["cusp_replans"]` 에 시각·자세·오차·계획 상태·탐색 기록·새 경로·바뀐
경로를 남긴다.

## T2 — 확장 사다리: 기존 사다리 **뒤에** 세밀 격자 예산 ×4, 그리고 0.10 m 동작

**지금의 사다리:** 기본 격자(0.2 m/10°, 간격 8) → 세밀 격자(0.1 m/5°, 같은 예산 30,000) → 간격 4·2·1(기본 격자). 갇힌 출발이면 충돌 간격 0.01 m 로 사다리를
다시.

**바꿈:** 기존 사다리가 모두 실패한 **뒤에만** 두 시도를 더한다: 세밀 격자를 호출자 예산의 4 배(30,000 → 120,000; 세밀 격자는 칸이 8 배)로 다시, 그다음
세밀 격자 + 기본 동작 0.10 m. 기존 사다리의 순서·설정은 그대로라서 **기존 사다리가 구한 탐색은 같은 경로를 낸다**(초안은 새 시도를 간격 4·2·1 앞에 넣어
1020 의 접근 경로가 바뀌었다 — 검토 ②·③). 앞에서 같은 격자·동작으로 대기열이 닫힌(`no_path`) 탐색은 예산만 늘려 다시 하지 않는다. 예산은 배수라서 호출자가
일부러 작게 준 예산은 작게 남는다(이 규칙을 시험 `test_seed_seven_..._bounded_failure` 가 잡았다). 0.10 m 동작을 기본 격자에 쓰면 같은 칸에 겹쳐 208 확장에서
닫히므로 세밀 격자에서만 쓴다. `search_attempts` 에 동작 길이·예산을 덧붙인다(7·8 번째 칸).

**관측 구간은 두 번에 나눈다.** 확장 사다리를 관측 후보마다 쓰면, 예전에 실패하던 앞 번호 후보가 이제 계획되어 실행기가 다른 관측점을 고른다(검토 ③: 1008·7·
4006·3003 이 바뀜). 그래서 첫 관측의 후보 탐색은 **모든 후보를 기존 사다리로 먼저** 시도하고, 하나도 계획되지 않을 때만 모든 후보를 확장 사다리로 다시
시도한다(4020). 재관측은 기존 사다리만 쓴다. 접근·운반·복귀(목표가 하나인 탐색)는 확장 사다리를 쓴다 — 기존 사다리가 구한 것은 그대로다.

clearance·충돌 간격·곡률은 바꾸지 않는다.
