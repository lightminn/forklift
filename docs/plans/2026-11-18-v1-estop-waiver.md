# V1.0 로 바닥 주행 — 비상정지 입력 없는 정상 빌드 (계획, 간단판)

작성일: 2026-11-18 · 상태: **계획, 사용자 승인(2026-11-18 "이대로 진행")** · 관련: [도착일 절차서](2026-11-12-arrival-day-procedure.md) 0·8·9·12절, [실차 이식 계획](2026-11-11-sim-to-real-bringup.md) 3.4·5절, [모터 출력 설계](../design/2026-11-12-weact-h743-motor-output.md) 2절

## 0. 전제 (사용자 2026-11-18)

- 메인보드 V1.0 이 끝까지 쓰는 유일한 PCB 다.
- 별도 비상정지 회로나 배선은 하지 않는다.
- 지금 규칙 Q3(비상정지 입력이 없는 정상 빌드는 출력을 열 수 없고 `ARM` 을 거부)를 그대로 두면 바닥 주행(S4 step, S5 정상 빌드 시나리오, S6 텔레옵, M1–M3, 자율)이 열리지 않는다.
- 이 계획은 Q3 를 **사용자 기록이 있을 때만** 펌웨어에서 푼다.

## 1. 사용자 기록 (결정은 사용자, 채팅에서 결정을 분명히 말하면 에이전트가 쓰고 커밋·PR·머지할 수 있음 — 사용자 2026-11-18)

- 파일: `docs/validation/<날짜>-estop-waiver-record.md`.
- 표지 줄: `E-stop waiver record: confirmed-by=<이름>; date=<YYYY-MM-DD>; evidence=<근거>`
- 문구 초안(사용자가 고쳐 쓴다):
  > E-stop waiver record: confirmed-by=김광민; date=2026-11-2X; evidence=회로도 V1.0 에 비상정지 입력이 없고 개선판도 없음, 12 V 배터리. 정지 수단은 명령 만료·통신 끊김·DISARM·콘솔 STOP·게임패드 놓음, 마지막 수단은 주 전원 스위치나 배터리 커넥터 뽑기. 첫 바닥 주행은 0.05 m/s. MCU 와 무관한 하드웨어 차단이 없음을 알고 정상 빌드의 출력 열기를 허용함.
- 넘기는 방식: 이번 기록은 에이전트가 준비한 스크립트를 사용자가 `!` 로 실행해 편집·커밋했다(PR #582). 이후로는 사용자가 채팅에서 결정을 말하면 에이전트가 기록을 쓰고 커밋·PR·머지해도 된다(사용자 2026-11-18). 그때 evidence 에 '채팅 결정을 에이전트가 기록'과 결정 원문을 적는다.

## 2. 펌웨어 (기록 검사는 여기 한 곳)

- 빌드 구성: `FW_BUILD=normal` 에 `FW_MOTOR_OUTPUT=1` 이면 IPROPI 기록에 더해 `FW_ESTOP_WAIVER_RECORD=<경로>` 가 있어야 한다.
  - 검사는 지금의 IPROPI 기록 검사(`check_protection_record.cmake`)를 그대로 쓴다: 저장소 안의 일반 파일, HEAD 에 커밋됨, 작업 트리 내용 일치, 표지 줄 형식, 매 빌드 재검사.
  - 없으면 지금처럼 구성 단계에서 거부한다.
- 코어: `drive_config.estop_waived` 를 더한다. 그러면 `ARM` 을 받는다.
  - STATE bit7(`estop_unwired`)은 그대로 켠다(입력이 없다는 사실은 그대로). 계약 버전도 그대로다.
- 정체 문자열: `forklift-mcu normal OPEN <git> rec=<IPROPI 해시> waiver=<기록 해시>`(USB 제품 문자열·ELF).
- 시운전·HIL·IWDG 정지 빌드는 바뀌지 않는다.
- **크기**: CMake 약 25 줄, 코어·보드 약 15 줄, 시험 약 100 줄.
- **시험**:
  - 코어: 기록 없는 정상 빌드는 `ARM` 을 거부하고, `estop_waived` 면 받는다. bit7 은 켜진 채다.
  - 크로스(로컬): 임시 git 저장소의 가짜 기록으로, 기록 없음·커밋 안 됨은 거부되고, 기록이 있으면 `waiver=` 로 빌드된다.

## 3. 호스트 — 가장 작은 변경 (콘솔 몫)

- 지금 bit7 로 거부하는 곳은 두 군데다:
  - 실차 실행기·브리지의 `build_policy.drive_refusal` → `estop_unwired`
  - `bringup.py --floor` 의 확인(242 행 근처)
- 바꿈: 연결한 장치의 USB 제품 문자열에 `waiver=` 가 있으면, 두 곳 모두 bit7 을 **경고로만** 보고 거부하지 않는다.
  - 제품 문자열은 **링크를 열 때 그 열린 tty 와 같은 USB 장치**의 sysfs 에서 읽어 호스트에 넘긴다. 연결이 끊기면 지우고, 다시 연결할 때마다 다시 읽는다. `/dev/forklift-mcu` 경로를 따로 조회하지 않는다(재연결·보드 교체 때 다른 장치의 값을 쓸 수 있다, Codex). 읽지 못하면 거부한다.
  - 기록 자체는 다시 검사하지 않는다(펌웨어가 이미 검사함). 펌웨어의 `ARM` 게이트가 남으므로, 호스트만으로는 면제되지 않은 보드의 출력을 열 수 없다.
  - Jetson 에서 sysfs 로 읽히는지는 첫 연결 때 확인한다.
- waiver 가 없는 보드는 제품 문자열에 `waiver=` 가 없으므로 지금처럼 거부된다. UART7 링크도 제품 문자열이 없어 거부된다.
- `bringup.py` 의 속도 상한 계산에 바퀴 반경을 넣는다. 지금은 반경을 넘기지 않아 상한이 1.0 rad/s 이고, 0.132 m/s(1.06 rad/s) 시험이 거부된다(Codex).
- 크기: 약 40 줄과 시험.

## 4. 순서 (V1.0)

1. **11-20 당일**: S0–S3 그대로. IWDG ①·②(S5 9.1)도 이미 있는 그대로 한다.
2. **기록 커밋 뒤**: 펌웨어·호스트 PR 을 머지하고 `normal OPEN … waiver=` 이미지를 굽는다(절차서 3.1, 제품 문자열 확인). IWDG 시험 때 다른 이미지를 구웠으면 이 이미지로 다시 굽는다.
3. **S4 축별 폐루프**(받침대): 절차서 8절 그대로(폐루프 응답, 엔코더 고장 주입).
4. **받침대(바퀴 띄움), S4 의 최종 게인·정지 설정으로 각 1 회**: 출력이 멈추는지 보고 기록한다.
   - 명령 만료: `bringup.py scenario --kind expiry`
   - 통신 끊김: `bringup.py scenario --kind tx_cut`
   - `DISARM`: `bringup.py scenario --kind disarm`
   - 콘솔 STOP
   - 게임패드 놓음(0 목표 명령으로 감속하는지)
   - 하나라도 멈추지 않으면 바닥으로 가지 않는다.
5. **바닥 0.05 m/s**:
   - `--floor --rate 0.4`(0.05 m/s ÷ 잠정 반경 0.125 m)로 **통신 끊김 한 번, `DISARM` 한 번**을 한다. 두 경로는 서는 방식이 다르다: 만료는 300 ms 동안 출력을 켠 채 감속하고, `DISARM`·콘솔 STOP 은 곧바로 정지 출력(바퀴 `safe_brake=false` 면 굴러감)으로 간다(Codex).
   - 바퀴가 서는 거리는 줄자로, 시간은 영상으로 잰다.
   - 문턱(계획 3.4 잠정)은 0.5 s·0.10 m 다. 펌웨어는 만료 150 ms 와 정지 대기 300 ms 뒤 출력을 끄고, 그 뒤는 굴러서 선다. 그래서 굴러가는 구간까지 포함해 잰다.
   - 넘으면 바퀴 채널을 `safe_brake=true` 로 바꾸는 근거로 쓴다.
   - 통과하면 S6 텔레옵을 0.05 m/s 로 한다.
6. **0.132 m/s 로 올리기**: 그 속도(`--rate 1.06`)에서 통신 끊김·`DISARM` 을 한 번씩 더 잰다. 도구는 목표의 50 % 만 넘으면 사건을 시작하므로, 사건 직전 바퀴 속도가 목표 근처였는지 기록의 STATE 로 확인한다. 문턱 안이면 텔레옵 상한을 0.132 m/s 로 올린다.
7. **M1–M3**(절차서 12절), 그 뒤 자율.

**손작업**: S4 는 절차서 8절 그대로, 받침대 다섯 가지 약 10 분, 바닥 0.05 두 번 약 10 분, 0.132 두 번 약 10 분. 마지막 수단(주 전원 스위치나 배터리 커넥터)은 출력이 열린 모든 실행에서 손 닿는 곳에 둔다(절차서 0절에 한 줄).

## 5. 줄인 탓에 늘어나는 위험

정지 확인을 한두 번만 하므로 정지 성능의 흩어짐은 모른다. 또 호스트 쪽 기록 검사를 빼서, waiver 이미지가 꽂혀 있으면 호스트는 따로 확인하지 않고 바닥 주행을 연다. MCU 와 무관한 차단은 사람의 전원 차단뿐이다.

## 6. 자체 검토

- 앞선 판(호스트 기록 검사·확인 목록 열 가지)에 대한 Codex 3라운드의 지적 가운데 남긴 것: 정지 시간 계산의 한계(만료 150 ms + 정지 대기 300 ms 뒤 굴러감), `--floor` 속도 상한, 0.132 재측정의 실제 속도 확인, IWDG 시험 뒤 정상 이미지 다시 굽기.
- 간단판 Codex 확인 1차(P1 없음, P2 4), 모두 반영:
  - 제품 문자열을 열린 tty 의 장치에서 읽고 연결 수명을 따르게(3절).
  - 0.132 시험을 위해 `bringup.py` 상한에 반경 반영(3절).
  - 바닥에서 `DISARM` 도 한 번 잼 — 만료와 서는 방식이 다르다(4절 5·6).
  - 빠졌던 S4 를 되살리고, 받침대 다섯 가지는 S4 의 최종 설정으로(4절 3·4).
- 간단판 Codex 확인 2차: 새 P1/P2 없음(계획 수준, 구현·Jetson 연결·실물 시험은 별도).
