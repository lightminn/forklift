# 기존 포켓 인식기와 Isaac 접근 주행 연결

`계획.md` 2순위를 진행한다. 이전 대규모 검증 결과 집계는 사용자 요청에 따라
이번 작업에서 건너뛰며, 성공으로 간주하거나 완료 표시하지 않는다.

## 입력과 완료 범위

- 잠정 지게차에 합성 고정 RGB-D 카메라를 배치한다. 이는 실물 D435i 보정이 아니다.
- Isaac의 광축 Z 깊이(m), 같은 렌더의 RGB, 내부 파라미터, 촬영 시각과
  `base_link <- camera_optical_frame` 변환을 기존 `SceneInput`으로 전달한다.
- 기존 `detect_pockets()`와 EPAL 6 prior를 사용한다. 팔레트 정답을 검출기에
  넣거나 검출 실패 시 정답으로 대체하지 않는다.
- 정지 상태에서 취득한 관측을 같은 시각의 `world <- base_link`로 변환한다.
  포켓 전면 중심과 팔레트 중심의 깊이 절반 차이를 반영해 후륜축 정렬 목표를 만든다.
- Hybrid A*와 기존 바퀴·조향 추종기로 정렬 지점까지 이동하고 정지한다.
  삽입·승강은 다음 단계의 연속 포켓 추적이 준비된 뒤 수행한다.
- 차체 자기 위치와 장애물 지도는 시뮬레이터 값이다. 팔레트 정답은 별도 오차
  평가에만 사용한다. 무효·미검출·지연·좌표 또는 시각 불일치에는 주행하지 않는다.

## 구현 순서

1. RGB-D 스냅샷 계약 어댑터와 버퍼 복사·단위·좌표·미지 깊이 시험.
2. 관측 시각 변환 및 정렬 목표 계산과 잘못된 관측·시간·방향 시험.
3. Isaac 카메라 취득, 독립적인 접근 실행기, 재현 가능한 새 장면 구성.
4. 실제 렌더 → 기존 검출 → 계획 → 물리 바퀴 주행 및 정지 확인.
5. 미검출 시 정지 확인, 회귀 시험, 결과·제한과 원본 산출물 기록.

코어 변경은 병렬 구현하되 파일 소유권을 나누며, 통합 후 별도로 검토한다.
검출기의 파라미터나 알고리즘은 실제 실패 증거가 있을 때만 변경한다.
