# 출발 띠 해제 — 이미 바짝 붙어 선 자리에서 멀어지는 움직임 (2026-10-24)

배경 계획: `docs/plans/2026-10-23-planner-permission-clearance.md`(P6 까지), 결과 `docs/validation/2026-10-24-p6-permit-stop.md`.
정책(총괄 전달, 사용자 2026-10-24):
- 리보틱스 기준·실측 물리값이 아닌 여유·안전 판정 규칙·런처 기본값 변경은 사용자 결정 없이 진행하고, 문서와 보고로 남긴다.
- 이 작업은 그 정책에 따라 P6 결과 문서의 "남은 결정" (가)를 진행한다.
- 장면 재계획 장치 소유자(sw-연속이송-재관측)와 범위를 맞춘다.

## 1. 문제

트레일러 출구와 rack 통로의 운반 정지는 실기록 덤프 6 건에서 이렇게 생긴다.
- 꺼내기를 마친 적재 외곽이 벽·기둥 표시 띠의 칸 몇 개에서 0.008–0.019 m 떨어져 서 있다.
- 허가의 걷기(`DrivePermission._walk`)는 시작부터 여유를 적용한다. 그 여유는 외곽 여유 `envelope_m` 0.01 에 표본 사이 쓸림 패드(첫 구간 중간점에서 표본 간격 0.02 의 절반 0.01)를 더한 0.02 m 다.
- 그래서 그 칸이 첫 구간부터 걸린다. 그 칸에서 곧게 멀어지는 후진도, 경로 검사와 정지 원호 검사 모두에서 0 m 다.
- 같은 이유로 P6 재계획도 회복하지 못했다(invalid_start → 곧은 후진 탈출도 허가 0 m).

덤프에서 잰 값(①, `snapshots/esc_wip`, `start_release.start_band_cells` 의 정확 거리):

| 덤프 | 출발 띠 칸 수 | 출발 거리 d0 (m) | 해제 끔: 앞 다리 경로/정지 원호 | 해제 켬: 앞 다리 경로/정지 원호 |
|---|---|---|---|---|
| pc4_off_trailer_s2 #7 | 5 | 0.0093–0.0150 | 0 / 0 | 3.00 / 0.10(전 길이) |
| pc4_off_trailer_s1 #5 | 6 | 0.0107–0.0175 | 3.00 / 0 | 3.00 / 0.10 |
| p6b_off_trailer_s0 #5 | 3 | 0.0159–0.0192 | 3.00 / 0 | 3.00 / 0.10 |
| pc3t_aisle #6(rack) | 4 | 0.0079–0.0130 | 0 / 0 | 2.10(전 길이) / 0.10 |
| pc3_aisle_s0 #6(rack) | 2 | 0.0142–0.0164 | 0 / 0 | 2.10 / 0.10 |
| rk3_aisle_s1 #6(rack) | 0 | — | 0.02 / 0.10 | 0.02 / 0.10(변화 없음: 0.02 m 앞의 새 칸) |

- 앞으로(벽 쪽으로) 0.5·1.0 m 곧게 가거나 벽 쪽으로 도는 원호는 켬에서도 0–0.02 m 로 막힌다. 다가가는 움직임은 그대로 막는다.
- d0 는 0.0079–0.0192 m 다. 총괄 지시의 "0.01 m 안 칸"으로 띠를 잡으면 6 건 중 대부분의 칸이 빠진다. 그래서 띠는 걷기의 실제 시작 여유(0.02 m)로 둔다(2.1).

## 2. 설계

### 2.1 허가 쪽 — 출발 띠 해제 (`forklift_core.control.start_release`, `DrivePermission`)

- **출발 띠 칸**: 스냅숏의 OCCUPIED 칸 가운데, 걷는 모양(그 방향의 footprint, 부품 전부)의 지금 자세 외곽과 겹치지 않으면서 정확 거리 `d0 ≤ start_band_m` 인 칸.
  - `start_band_m` 은 걷기의 시작 여유와 같다: `envelope_offset_m + step_m / 2` = 0.01 + 0.01 = 0.02 m.
  - 외곽과 겹치는 칸은 지금까지처럼 자기 칸 규칙(완전히 안이면 제외, 걸치면 바깥 부분만 검사)을 따른다.
  - 거리는 칸(축 정렬 정사각형)과 각 부품(뒤 축 기준 직사각형) 사이의 정확한 볼록 다각형 거리다. 꼭짓점 대 상대 다각형 거리의 최솟값이고, 겹치면 0 이다.
- **멀어지는 동안 통과**: 걷기의 표본을 2 mm·0.001 rad 이하 간격으로 촘촘히 나눈 자세마다 외곽과 그 칸의 정확 거리를 잰다.
  - 처음으로 `d < d0` 가 되는 호 길이를 그 칸의 한계 `s*` 로 둔다.
  - 촘촘한 자세 사이에서 연속 쓸림이 더 다가갈 수 있는 최대량은 `0.001 + R × 0.0005` m 다(R = 모양의 가장 먼 모서리 반경, 적재 1.6 m → 1.8 mm). 이 값은 판정에 더하지 않고 한계로 적는다(4 장).
  - 이것은 경로 표본점이 아니라 외곽 전체(회전 중 모서리 포함)가 쓸고 가는 영역으로 판정하는 것이다(총괄 조건).
- **걷기**: 출발 띠 칸을 FREE(그 스냅숏 시각에 본 것으로)로 읽은 사본 위에서 지금 걷기를 그대로 돈다.
  - 그 결과를 `min(verified, min s*)` 로 자른다. 잘리면 `blocked = "occupied"` 이고 막힌 칸은 그 칸들이다.
  - 띠 밖의 칸은 앞쪽의 새 칸을 포함해 지금 여유(0.02 m, 정지 거리 여유 0.05 m 포함) 그대로다.
- **어디에 적용하나**: `check_path`(경로 검사)와 `check_arc`(정지 원호, `allowed_speed` 가 부르는 것) 둘 다.
  - 총괄 지시는 "정지 원호 검사는 그대로"였다. 하지만 위 표의 trailer s1·s0 은 경로가 통과해도 정지 원호(곡률 0)가 같은 띠 칸에 0 m 로 막혀, 원호에 적용하지 않으면 해제가 효과가 없다.
  - 그래서 원호의 정지 거리 모형(지연 0.15 s, 감속 1.5 m/s², 여유 0.05 m)·길이·방향 규칙은 바꾸지 않고, 원호의 걷기에도 같은 띠 칸 규칙만 적용한다. 이 해석은 보고에 따로 적는다.
  - 후보 허가(`candidate_permit`)·원격 조종 허가는 같은 설정을 복사해 쓰므로 같이 적용된다.
- **스위치**: `PermissionConfig.start_band_m`(기본 0 = 끔). 러너 `--start-band-release on|off` 가 켜면 0.02 m 를 넣는다.
  - 옛 기록에는 이 인자가 없으므로 off 로 재생된다(`getattr` 기본값). 근접 계약값은 off 다.

### 2.2 계획 쪽 — 탈출 쓸림 검사 (`escape.rectangles_sweep_free`, 장치의 `escape_plan` 포트)

- 장치의 곧은 후진 탈출은 사각형 검사(장면 소품 + 트리거의 추가 사각형, 표본마다 패드 0.01 m)를 통과해야 한다. 정지 자세가 추가 사각형에서 0.01 m 안이면 출발 표본부터 막힌다.
- 해제를 켜면 이렇게 한다.
  - 추가 사각형(트리거의 막힌 칸 사각형) 가운데 출발 외곽에서 `0 < d ≤ 0.01 m`(쓸림 패드)인 것만 사각형 검사에서 빼고, 출발 띠 규칙(촘촘한 쓸림 거리가 출발 거리 아래로 내려가지 않음)으로 따로 본다.
  - 출발 외곽과 겹치는 사각형은 풀지 않는다.
  - 장면 소품은 계획기의 정답이므로 지금 규칙 그대로 둔다(장치 소유자 제안).
  - 탈출 끝의 여유 검사(`end_clearance`)는 모든 사각형으로 지금처럼 한다.
- 계획기의 출발 검사(`invalid_start`)는 바꾸지 않는다. 이것이 탈출을 부르는 신호다. 탈출 뒤 자리에서 다시 계획한다.
- 같은 스위치로 묶는다. 계획 쪽만 풀면 허가가 첫 틱에 다시 막는다(P6 결과 문서).

### 2.3 바꾸지 않는 것

- 앞쪽 새 칸의 여유, 정지 거리 모형, 증거 나이 한계(풀린 칸은 그 스냅숏 시각으로 읽어 증거를 낡게 만들지 않는다), 센서 침묵, UNKNOWN 규칙, 그림자 띠.
- 리보틱스 기준·실측 물리값·센서 규격은 바꾸지 않는다.

## 3. 검증 계획

1. **단위 시험**:
   - 정확 거리(겹침·꼭짓점·회전)
   - 띠 칸 선택(겹치는 칸 제외, d0 > 띠 제외)
   - 멀어지는 곧은 후진은 통과, 평행 이동은 통과, 다가가는 전진·회전은 `s*` 에서 막힘
   - 띠 밖 새 칸은 지금처럼 막힘
   - 끔이면 걷기 결과가 비트 단위로 같음
   - 탈출 사각형 검사의 근접·겹침·끔
   - 스위치·근접 계약
2. **CPU 덤프**: 1 장의 표를 저장소 시험으로 고정한다(덤프를 고정 자료로 잘라 넣는다).
3. **재생 게이트** runs29: 꺼진 설정의 옛 기록이 그대로 재생된다.
4. **ws1 전체 pytest**.
5. **Isaac**(같은 시간대에 섞고, seed 여러 개). 팔은 셋이다.
   - A: 해제 끔, KEEPOUT 0
   - B: 해제 켬, KEEPOUT 0
   - C: 해제 켬, KEEPOUT 0.15
   - 장면: trailer(`--exit-clearance-m 0.30`) seed 0–4, aisle_rack seed 0–2, line_2_m seed 0–2. 모두 P6 켬(기본).
   - B 대 A 로 해제 효과를, C 대 B 로 KEEPOUT 효과를 본다.
6. **기본값 판정**(총괄 지시: 내 판단으로 정해 보고):
   - B 가 각 장면 완주 수에서 A 이상이고,
   - 허가 아래 실제 접촉(`obstacle_layer.unpermitted`, 충돌 실패)이 늘지 않고,
   - 새 실패 유형이 없으면 기본값을 켬으로 바꾼다.
   - KEEPOUT 은 C 가 B 보다 나을 때만 0.15 로 되돌린다.

## 4. 위험과 한계

- **쓸림의 이산화**: 촘촘한 자세 사이에서 외곽이 칸에 다가갈 수 있는 양은 최대 약 1.8 mm 다(적재). 띠 칸은 이미 실제 표면 위에 그려진 표시다(표시 반경 = 오도메트리 나이 오차 + 거리 잡음 한계 0.06 m + 각 오차 몫). 그래서 표시 띠 안쪽 1.8 mm 는 물리 접촉이 아니다. 숫자는 결과 문서에 다시 적는다.
- **표시 띠 칸 = 실제 물체 가장자리일 때**: 평행하게 0.008 m 옆을 지나가는 것을 허용하게 된다. 표시 자체가 위 반경만큼 부풀려져 있어 실제 표면과는 그만큼 떨어져 있다. 다만 오도메트리·SLAM 오차가 표시 반경을 넘으면 그 여유가 줄어든다. 이 위험은 지금 0.02 m 여유가 있을 때와 같은 종류이고, 그 차이(최대 0.02 m)가 줄어든 것이다.
- **새로 다가가는 칸은 지금 여유 그대로**다. 해제는 출발 자리의 칸에만 걸린다.
- **이 규칙이 풀지 못하는 정지**(rk3_aisle_s1 처럼 띠 밖 앞쪽 칸)는 P6 가 맡는다.
