## 3. 읽는 법 (탐색, 문턱 없음)

- **언제 나타나는가:** D1 에서 두 팔의 잔여 오차(보정 직후) 차이가 빈차 접근에서는 없고 적재 운반에서 생기는지, 추출 구간에서 이미 생기는지를 본다. 이것은 오차가 나타나는 시점이지 원인이 아니다.
- **보정이 무엇을 했는가:** D1 의 직전 오차와 직후 잔여(보정 뒤에도 남는가)를 팔별로 본다. 직전 오차에는 그 전 보정의 잔여도 섞여 있으므로, 오도메트리 몫은 D2 의 구간 상대 운동 오차로만 말한다. 보정의 방향이나 절댓값 감소만으로 H1 을 지지하거나 약화하지 않는다(+10 → +1 cm 도, +10 → −4 cm 도 일관된 음의 보정이다).
- **H2 와 맞지 않는 경우:** D2·D3·D8 에서 같은 조건(방향·회전 크기·속도가 비슷한 구간)끼리 비교해도 두 팔의 오도메트리 상대 운동 오차가 같다면, 적재 운반의 상류 오차가 두 팔에서 다르다는 기록은 없다고 쓴다. 다르다면 '상류 오차가 다르다는 기록이 있다'고 쓰고 기여도는 말하지 않는다. 조건이 겹치지 않는 구간은 비교 불가로 남긴다.
- **H1:** D4 에서 자세 요약통계(평균·변동·최대)의 팔별 차이가 없으면 '자세 요약통계의 팔별 차이는 관측되지 않았다'까지만 쓴다. 같은 자세라도 서로 다른 장소·관측 기하에서 나타나면 스캔에 주는 영향이 다르므로, 이것으로 H1 경로를 배제하지 않는다. 자세가 다르더라도 그것이 정합을 얼마나 움직이는지는 이 기록으로 알 수 없다(4 장).
- **H3:** D6 은 서술만 한다. D5 의 성분과 D6 의 동반을 H2·H3 의 기여로 나누지 않는다.

## 4. 가를 수 없는 것

- **H2 와 H3 의 기여도:** 키프레임 선택이 오도메트리 누적 거리·회전으로 정해지고 두 팔은 다른 곡선·방향·속도·정지를 겪으므로, 같은 운동에서의 오도메트리 차이로 읽을 수 없다. 기록으로는 상류 오차가 있는지만 볼 수 있다.
- **스캔 정합의 내부 상태:** 정합 잔차·공분산·지도 일치도는 기록에 없다. 그래서 '지도 기준으로는 맞게 보정했지만 지도가 어긋났다'(지도에 남은 H2·H3)와 '그 스캔의 정합이 치우쳤다'(H1)를 D1 로 떼지 못한다.
- **자세가 정합을 움직이는 양:** 유한 높이의 벽·랙·모서리에서는 작은 높이 변화가 적중면을 바꾸고, 정합의 약한 방향에서는 작은 스캔 차이가 커질 수 있다. 민감도 계산이나 스캔 재정합 없이 D4 의 크기만으로 H1 의 상한을 말하지 않는다.
- **미끄럼 대 유효 반경:** D8 은 측정 모델 몫과 '관절 회전 대비 참 이동' 몫을 나눌 뿐, 그 안의 미끄럼과 유효 반경을 따로 정하지 못한다.
- **지도 자체의 오차:** `bridge/maps.npz` 와 장면의 참 점유를 맞대는 정합은 범위 밖이다.
- **스캔 재정합:** 기록된 `scan_ranges_m` 은 잡음을 넣기 전 거리다. 그대로 재생하면 당시 SLAM 입력의 정확한 재현이 아니다. 재정합은 다음 진단 후보로만 둔다.

## 7. 자체 검토

### Codex 1 회차 (새 스레드, 1 판 대상 — P1 0·P2 6·P3 다수)

- P2 D1 의 직전 적용 보정을 이전 스캔 기록에서 가져오면 해제 몫을 잘못 센다, 멈춤 중 처리와 추적 중 처리를 가려야 한다, 후축 기준이어야 한다 → #319 의 추적기 재생과 `rear_of` 를 쓴다(2 장 D1).
- P2 D3 의 '두 앞바퀴 평균각'은 실제 오도메트리 모델과 다르고(평균각으로 tan/L 을 쓰면 정상 Ackermann 에서도 15° 에서 약 0.9 % 잔차), 후진 부호와 참 곡률 기준 제외가 틀렸다 → 실구현 식, 실행별 `odometry_geometry`, 부호 있는 Δs, 기구학 곡률로 창 선택, 주 지표를 잔차로 했다.
- P2 D4 의 수직 벽 계산은 센서 원점의 수평 이동(1 mrad 당 약 1.05 mm)을 빠뜨렸고, 1 mrad 를 약화 기준으로 쓸 근거가 없다 → 원점 이동을 넣고 분포로 보며, 기준이 아니라 눈금으로 낮췄다(2 장 D4, 4 장).
