# 오도메트리를 바퀴 관절각 기반으로 (3판)

브랜치 `feat/joint-angle-odometry`(main `1ea3c16` 에서).

**사용자 결정(2026-10-22, 총괄 세션 경유):** 오도메트리를 바퀴 관절각 기반으로 바꾼다. 실차 MT6701 이 각도를 세기 때문이다(4체배 4096). 이 일을 재작도 B 검증보다 먼저 한다.

## 1. 사실 (원자료에서 다시 계산)

- **지금의 기준선:** 배치·라이브 실행의 오도메트리는 `--encoder-model reported`(기본값)다. Isaac 이 보고하는 뒤 바퀴 관절 각속도에 가우스 잡음을 더해 적분한다(`run_transport.py` 5670행 부근).
  - 접근 중 큰 과대계상(최대 +22 mm / 2.5 m)은 이 보고 각속도 때문이다. 관절각 기반으로 센 거리는 truth 경로와 0.04–0.11 % 차이다(`docs/validation/2026-10-21-odometry-overcount.md`).
- **오른쪽 뒤 바퀴만 튀는 원인(짧은 확인, 2026-10-22):** 원인을 확정하지 못했다.
  - 확인한 바퀴 파라미터는 좌우가 같다. URDF 관절 형식·축·한계, 바퀴 질량·관성·충돌 실린더, 구동 이득(강성 0, 감쇠 1145.9), 최대 토크 3, 접촉 재질(정지 0.8 / 운동 0.7)이 같고, 차체 무게중심도 y = 0 이다.
  - 그런데 튐(|보고 − 관절각 미분| > 0.3 rad/s)은 슬램 로그가 있는 실행 35 개를 합쳐 오른쪽이 좌회전 234.5, 우회전 176.3, 직진 42.8 회(1,000 샘플당)였다. 왼쪽은 32.8, 27.2, 11.2 회였다. 선회 방향과 무관하게 오른쪽이 4–7 배다.
  - 관절 속도 보고 쪽(관절 순서·해 계산)의 문제로 보이지만 증명하지 않았다. 관절각 기반 오도메트리는 이 경로를 쓰지 않으므로 결정에는 영향이 없다.
- **관절각 기반 경로는 이미 있다:** `--encoder-model team_spec_quantized`(2026-10-15).
  - 매 물리 틱마다 관절각에서 팀 부품을 흉내 내 센다. 뒤 바퀴는 MT6701 4 체배 4,096 계수/회전, ABZ 히스테리시스 0.088° 다. 조향은 KTH7801-C 12 bit 다.
  - 그 증분을 `IncrementalWheelOdometry.update_increments` 로 적분한다. 이때 가우스 바퀴·조향 잡음은 더하지 않는다.
  - `team_spec_typical_inl` 은 여기에 데이터시트 전형 INL 을 더한 것이다.
  - 분해능은 2π/4096 × 0.125 m = 0.19 mm/계수다.
- **이미 짝이 맞는 것:** 팀 규격 오도메트리 나이 표 `config/obstacle_odometry_age_team_spec.json`(encoder_model team_spec_quantized, 반지름 0.125)이 있다. 이것을 쓰는 장애물 층 설정 `config/obstacle_layer_single_team_spec.yaml` 도 있다. 러너의 나이 표 검사(`age_table_problem`)가 둘의 짝을 강제한다.
- **막히는 조합:**
  - `--pocket-check` 는 팀 규격 엔코더와 함께 쓸 수 없다(러너 983행, 속도 경계·재생 규칙 미정).
  - 근접 추적 측정 조건은 `encoder_model: reported` 다(`near_tracking.py` POST_MEASUREMENT). 근접 추적 실행은 reported 로 남아야 한다.

## 2. 범위와 방안

**러너 기본값은 바꾸지 않는다.** 대신 관절각 기반을 쓰는 실행 설정(기준선)을 바꾼다.
- 기본값을 바꾸면 새로 내는 포켓 검사·근접 추적 실행과 `--record-slam` 없는 호출이 인자 없이는 거부된다. 저장된 기록을 읽는 d5 재생은 영향을 받지 않는다.
- 그런 실행은 지금처럼 reported 로 둔다.

1. **배치 기준선**(ws1 `test_runs/bd_isaac/bd.sbatch`, 저장소 밖)
   - `--encoder-model team_spec_quantized --obstacle-layer config/obstacle_layer_single_team_spec.yaml` 을 기본으로 한다.
   - 환경 변수 `ENCODER_MODEL=reported` 로 옛 기준선을 고를 수 있게 한다.
2. **콘솔 스크립트(`deploy/console/*.sbatch`)는 이번에 바꾸지 않는다.**
   - 라이브 수동주행 허가 검사(`teleop_drive`)는 한 틱 오도메트리 속도(`interval_speed`)로 움직이는 방향을 판단한다. 계수 하나는 120 Hz 에서 0.023 m/s 이므로, 0.020 m/s 전진 중에도 증분 0 인 틱이 나온다. 그 틱에 후진 요청이 들어오면 전방 검사가 빠진다(Codex CPU 반례).
   - 속도 불확실성을 넣은 방향·제동거리 계약을 정한 뒤 별도로 바꾼다(후속).
   - 미션의 정지 판정(`StopDetector`, 12 틱 평균 + 명령 유지)과 경로 추종은 이 반례에 해당하지 않는다.
3. **진단 도구:** `tools/odom_drift_terms.py` 가 팀 규격 실행도 다시 만들게 넓힌다(배치 기록 전용, live spool 은 범위 밖).
   - 기록 입력은 기존 `encoder_odometry_inputs()` 로 읽는다. `update_increments` 로 적분하고 기록 `odom_base` 와 완전 일치를 확인한다.
   - 항은 `quantize`(계수 − 관절각, 히스테리시스·조향 양자화 포함)와 `angle_truth` 다.
   - **구간 분류:** 지금 `phase_window()` 는 삽입에서 나가는 전이가 없으면 삽입 시작을 끝으로 잡는다. 실행을 정상 완료 / 중도 실패 / 구간 미도달 / 재현 실패로 나누고, 지표마다 유효 실행 수를 남긴다. 재현 실패·누락은 통과로 치지 않는다.
   - hold 구간(근접 촬영 → 삽입 끝)의 드리프트를 따로 보고한다.
4. **새 러너 인자:** 없다. 있으면 `near_tracking.py` 계약에 등록한다.
5. **시험 실행 1 회:** 팀 규격 + 팀 규격 장애물 층으로 EPAL 6 검사 끔 seed 0 을 처음부터 끝까지 돌린다. 막히는 곳이 없는지, 정지·저속 구간(근접 정지, 삽입 끝, 들기 전)에 명령 속도가 떨리지 않는지 본다.
6. **전후 비교(같은 snapshot·seed):** EPAL 6, 0.3725 m, `--bottom-deck-check` 끔·켬 × seed 0–5 를 reported 와 team_spec_quantized 로 각각 돌린다(24 회).
   - 보고 항목: 사이클 결과, 포크가 중심을 넘은 깊이, hold 구간과 접근~삽입 끝의 오도메트리 전진 드리프트, 각 촬영의 SLAM 오차, 들기 기울기.
   - 정지 상태에서 정지 감지기(`StopDetector`)에 들어가는 오도메트리 속도 잡음: 원시 σ 와 0.1 s 평균 σ, 0.012 m/s 문턱을 넘는 틱 비율(곁 세션 요청 2026-10-22, cusp 정지 복구 결함이 이 입력에서 난다). 측정 범위는 truth 후륜축 0.1 s 평균 속도 < 1 mm/s 이고 속도 명령이 0 인 틱이다.
   - 해석: 이 비교는 엔코더만이 아니라 조합의 전후다(바퀴 입력, 조향 양자화, 가우스 잡음 제거, 장애물 나이 표). seed 별 대응 결과를 보존한다.
   - 기록: snapshot 에 저장소 밖 `bd.sbatch`, 실제 argv, scene·URDF·설정·나이 표 식별자를 남긴다.
   - **기준선 승격 조건:**
     1. team_spec 쪽 hold 구간 전진 드리프트의 |중앙값|과 `max(|드리프트|)`(부호 무관 최악값)가 reported 보다 작다. 유효 실행 수가 같아야 비교한다.
     2. 검사 끔·켬 각각에서 사이클 실패 횟수가 늘지 않고, 실패 유형이 새로 생기지 않는다.
     3. 같은 seed 에서 reported 성공 → team_spec 실패로 바뀐 쌍은 하나씩 원인을 적는다. 원인이 오도메트리 조합(입력·양자화·나이 표)이면 승격을 멈춘다.
     4. 나이 표 초과 0 건(아래).
   - **나이 표 확인:** 24 회 원로그에서 실제 쓰인 나이 구간(전후진·선회·정지·적재)의 오도메트리 위치·yaw 오차가 팀 규격 표 안인지 본다. 지금 두 표로 계산하면 나이 0.2 s·거리 4 m 의 오차 반경이 179.1 mm 에서 79.6 mm 로 줄어, 장애물 FREE 영역이 달라진다. 표를 넘는 경우가 나오면 승격을 멈추고 표와 함께 다시 본다.

## 3. 영향 받는 것(기준선 변경)

- **오도메트리 나이 표:** 팀 규격 표가 이미 있다. 다만 reported 실행의 관절각에서 다시 센 표다. 팀 규격 실행에서 새로 재는 것은 범위 밖으로 둔다.
- **기존 배치 기준선과의 비교:** 2026-10-22 이전 결과(밑판 검사 EPAL 6·얕은 T11 등)는 reported 기준이다. 비교 문서에는 엔코더 모형을 함께 적는다.
- **근접 추적·포켓 검사·d5 재생:** reported 로 남는다(계약 그대로).
- **곁 세션:** "sw-연속이송-재관측"(근접 재관측 Isaac 재평가 예정)과 "v-g2 조사 잡 재개"(기록 비교)에는 머지 때 기준선 변경과 고르는 법을 알린다.
- **SLAM 쪽:** 팀 규격에는 가우스 바퀴 잡음이 없고, 양자화·히스테리시스가 대신 들어간다. SLAM 보정 결과가 달라질 수 있어 전후 비교에 넣는다.

## 4. 위험

- **재계수한 나이 표:** 팀 규격 표는 reported 조사 실행(r6/r7)의 물리 궤적을 팀 규격으로 다시 읽은 것이다. 계수 방식은 맞지만, 새 피드백이 만드는 궤적의 오차가 표 안에 드는지는 러너 검사가 보지 않는다. 그래서 위 6 의 나이 표 확인이 승격 조건이다.
- **기본값 분기:** 러너 기본값이 reported 로 남아, 스크립트 밖 실행(직접 CLI, 시험)은 옛 오도메트리다. 기록의 `encoder_model` 로 어느 쪽인지 남는다. 기본값 전환은 포켓 검사·근접 추적의 팀 규격 계약이 생긴 뒤 다시 본다.
- 팀 규격 엔코더로 배치 미션을 돌린 적이 있는지 아직 확인하지 않았다(P0a 측정·자이로 조사에서는 썼다). 미션 전체에서 막히는 곳이 나오면 고친다.
- "관절각 기반" 이 시뮬에서 정확한 것은 관절각이 truth 와 맞기 때문이다. 실차 미끄럼·타이어 변형은 따로다.

## 5. 자체 검토

- **직접 재계산(1판):**
  - 튐 집계는 `spikes_by_turn.py` 로 35 실행에서 다시 셌다.
  - 분해능은 2π/4096 × 0.125 = 0.000192 m 다.
  - 나이 표 두 개의 `noise.encoder_model`(team_spec_quantized), 반지름(0.125), 장애물 층 설정의 표 경로는 파일에서 확인했다.
  - 러너의 포켓 검사 금지(983행)와 `--record-slam` 요구(988행), 근접 추적 측정 조건의 `encoder_model: reported` 는 소스에서 확인했다.

## 6. 검토 기록

### 2판 → 3판

- **② Codex 재검토(2차): P1 없음, P2 2.** 1차 P2 3건의 대응은 확인됐다. 둘 다 받아들였다.
  - P2: '새 실패 유형 없음'만으로는 같은 유형의 실패가 늘어도 통과한다 → 조건별 실패 횟수 비증가와 seed 쌍의 성공→실패 원인 기록을 넣었다.
  - P2: 부호 있는 드리프트의 '최댓값'은 음수 쪽 악화를 놓친다(합성 반례: 최댓값 9→0 mm 인데 최악 절댓값 9→15 mm) → `max(|드리프트|)` 로 바꿨다.

### 1판 → 2판

- **② Codex 적대적 검토(1차): P1 없음, P2 3·P3 4.** 모두 받아들였다.
  - P2: 콘솔 수동주행 허가가 한 틱 계수 속도로 방향을 놓친다 → 콘솔 스크립트 전환을 이번 범위에서 뺐다.
  - P2: 재계수 나이 표는 실제 미션 궤적 오차를 검사하지 않는다 → 24 회 원로그의 나이 표 확인을 승격 조건으로 넣었다.
  - P2: `phase_window()` 가 삽입 실패 실행의 구간을 잘못 잡는다 → 구간 분류·유효 수·재현 실패 처리, hold 구간 드리프트를 넣었다.
  - P3: d5 재생은 기본값 전환과 무관하다는 정정, 비교가 조합의 전후라는 해석, 기록 식별자, 도구 범위(배치 전용)·`encoder_odometry_inputs` 재사용, 오른쪽 바퀴 문장 좁힘.
  - 기본값 유지와 오른쪽 바퀴 원인 미확정 결론에는 동의했다.
- **③ 독립 검토(agy, Gemini 3.8 Flash Medium — Argon 은 일할 한도 보류).** ①·② 결론을 보이지 않고 1판만 주었다.
  - 반영: 본 비교 전 시험 실행, 정지·저속 구간 명령 떨림 점검, 수치 승격 조건, 나이 표 교란을 해석·위험에 명시, 기본값 분기의 위험.
  - 반영하지 않은 것: 기본값 미지정 시 실행 중단·경고. 기록의 `encoder_model` 이 남고, 경고만 늘리면 기존 실행 기록이 달라진다.
